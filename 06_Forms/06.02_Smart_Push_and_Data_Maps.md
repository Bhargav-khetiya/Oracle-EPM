# 06.02 Smart Push and Data Maps

> **Module:** 06_Forms  
> **Topic:** 02 - Smart Push  
> **Target Audience:** Consultant to Architect

## 1. Learning Objectives
- Understand how to move data instantaneously between cubes (BSO to ASO).
- Differentiate between Data Maps and Smart Push.
- Configure Smart Push on a Data Form.

## 3. Introduction
In standard EPM architecture, users enter data into a BSO cube for calculation, but they run their massive, cross-dimensional reports out of an ASO cube. The critical question is: *How does the data get from BSO to ASO instantly so the user can see their updated report?* The answer is Smart Push.

## 7. Core Concepts

### 1. Data Maps
- **Definition:** The foundational mapping layer. A Data Map defines how dimensions in Cube A map to dimensions in Cube B.
- **Example:** You map the `OEP_FS` (Financials BSO) cube to the `OEP_REP` (Reporting ASO) cube. You define that the Account dimension in BSO maps exactly to the Account dimension in ASO.
- **Execution:** Admins can manually run a Data Map from the Data Exchange UI. It moves all the data in bulk.

### 2. Smart Push
- **Definition:** The UI mechanism that executes a Data Map *dynamically* from a Web Form.
- **How it works:** When a user clicks "Save" on a form, Smart Push captures the exact POV and Page members the user was looking at (e.g., `Entity: New York`, `Period: Jan`), and it *only* pushes that specific slice of data to the ASO cube.
- **Benefit:** Instead of taking 10 minutes to copy the whole database, it takes 2 seconds to copy the exact numbers the user just changed. 

## 13. Configuration: Setting up Smart Push
1. Go to Data Exchange -> Data Maps. Create the map between BSO and ASO.
2. Open your Data Form in edit mode.
3. Go to the **Smart Push** tab.
4. Attach the Data Map.
5. Check the box **"Run After Save"**.
6. Check the box **"Use Form Context"** (CRITICAL). This tells the system to only push the data visible on the form.

## 18. Architect Notes: Over-Pushing
If you do not check "Use Form Context", clicking Save on a form will trigger the entire Data Map to run in the background. If 50 users click Save at the same time, the server will attempt to copy the entire database 50 times simultaneously, causing a total system crash.

## 25. Interview Questions

### Intermediate
**Q: What is the difference between a Data Map and Smart Push?**
> A: A Data Map is the backend definition of how two cubes align (source to target). Smart Push is the frontend action attached to a form that executes the Data Map dynamically, usually restricted to the context of what the user is currently editing.

### Architect
**Q: A user clicks Save on a form. The data saves to the BSO cube successfully, but the Smart Push to the ASO cube fails with a "Member not found" error. What is the root cause?**
> A: The metadata between the two cubes is out of sync. An admin likely added a new Account or Entity to the BSO cube, but forgot to refresh the database or synchronize the ASO cube, meaning the target member does not physically exist in the ASO outline yet.

## 27. Summary
Smart Push is the glue that holds the BSO/ASO dual-cube architecture together. It provides the illusion to the end-user that they are working in a single, lightning-fast database.
