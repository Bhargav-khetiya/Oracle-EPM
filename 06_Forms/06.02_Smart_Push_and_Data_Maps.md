# 06.02 — Smart Push and Data Maps: Complete Guide

> **Module:** 06_Forms | **Topic:** Cross-Cube Data Movement
> **Audience:** Service Administrator / Power User

---

## 1. WHY — What Real-World Problem Does This Solve?

**The problem:** Hotel Pvt Ltd has 3 cubes: FinPlan (OEP_FS) for P&L, Workforce (OEP_WFP) for headcount/salary, and CapEx (OEP_CP) for capital projects. An HR manager enters salary data in the Workforce cube. But the CFO's P&L form in FinPlan needs to show "Salary Expense." Without Smart Push, the admin would have to manually export data from one cube and import it to another — daily, for every data change.

**The solution:** Smart Push automatically copies data between cubes when a user saves a form. Data Maps define *what* to push and *how* to map dimensions between cubes.

---

## 2. WHAT — Plain English Definition

### Smart Push
A **form-level automation** that triggers a cross-cube data copy whenever a user saves the form. It runs in the background — the user doesn't even know it's happening.

### Data Map
A **blueprint** that defines: Source cube → Target cube, which members to push, and how dimensions map between the two cubes.

```
                    Smart Push Trigger (On Save)
                              │
User saves form ──────────────┤
in Workforce Cube             │
                              ▼
                    ┌─────────────────────┐
                    │     DATA MAP        │
                    │                     │
                    │ Source: OEP_WFP     │
                    │ Target: OEP_FS     │
                    │                     │
                    │ Account Mapping:    │
                    │ Basic_Salary →      │
                    │   Salary_Expense    │
                    │                     │
                    │ Entity: Same        │
                    │ Employee: Aggregate │
                    └─────────┬───────────┘
                              │
                              ▼
                    Data appears in
                    FinPlan P&L form
```

## 3. HOW — Step-by-Step Mechanics

### Step 1: Create a Data Map

```
Navigator → Create and Manage → Data Maps → Create

Map Name: WF_to_FinPlan_Salary
Source Cube: OEP_WFP
Target Cube: OEP_FS
```

### Step 2: Configure Dimension Mappings

For each dimension, choose a mapping type:

| Source Dim (WFP) | Target Dim (FS) | Mapping Type | Details |
|-----------------|-----------------|-------------|---------|
| Account | Account | **Member-to-Member** | Basic_Salary → Salary_Expense |
| Entity | Entity | **Same** | Shared dimension — identical members |
| Scenario | Scenario | **Same** | Budget → Budget, Actual → Actual |
| Version | Version | **Same** | Working → Working |
| Year | Year | **Same** | FY2026 → FY2026 |
| Period | Period | **Same** | Jan → Jan, Feb → Feb |
| Employee | *(none in target)* | **Aggregate** | Sum all employees → single total |
| *(none in source)* | Department | **Fixed** | Always push to "HR_Department" |

### Step 3: Attach Smart Push to a Form

```
Form Designer → Open "Salary_Entry" form
→ Click "Smart Push" tab (or "Other Options")

  ☑ Enable Smart Push
  Data Map: [WF_to_FinPlan_Salary ▾]
  Trigger: [On Save ▾]
  Scope: [Changed Data Only ▾]

→ Save Form
```

### Step 4: User Experience (Transparent)

```
1. HR Manager opens "Salary_Entry" form (Workforce cube)
2. Enters salary: Mumbai_Hotel → Emp001 → Jan = ₹80,000
3. Clicks Save
4. Behind the scenes:
   - Data saves to OEP_WFP (normal save)
   - Smart Push fires automatically
   - Data Map copies: ₹80,000 → OEP_FS → Salary_Expense → Mumbai_Hotel → Jan
   - All employees aggregated: total salary for Mumbai = sum of all employees
5. CFO opens P&L form (FinPlan cube) → sees updated Salary_Expense
```

## 4. FIVE DIMENSION MAPPING TYPES

| Type | When to Use | Example |
|------|------------|---------|
| **Same** | Dimension exists in both cubes with identical members | Entity, Scenario, Year, Period |
| **Member-to-Member** | Different member names between cubes | WFP:Basic_Salary → FS:Salary_Expense |
| **Fixed** | Target dimension has no matching source dim — use a constant | Always push to Department="HR" |
| **Aggregate** | Source dimension doesn't exist in target — sum all members | Employee dim → aggregated total |
| **Unmapped** | Dimension ignored — data aggregated across it | Custom dims unique to source |

### Visual: How Each Type Works

```
SAME:        Source: Mumbai_Hotel  ──→  Target: Mumbai_Hotel (1:1)
MEMBER-MAP:  Source: Basic_Salary  ──→  Target: Salary_Expense (renamed)
FIXED:       Source: (no dim)      ──→  Target: Department = "HR" (constant)
AGGREGATE:   Source: [Emp1, Emp2]  ──→  Target: (summed = total) 
UNMAPPED:    Source: Custom_Dim    ──→  Target: (ignored/aggregated)
```

## 5. SMART PUSH CONFIGURATION OPTIONS

| Option | Values | Description |
|--------|--------|-------------|
| **Enable Smart Push** | ☑/☐ | Turn Smart Push on/off for this form |
| **Data Map** | Select from list | Which Data Map to use |
| **Trigger** | On Save / Manual | When to push data |
| **Scope** | Changed Data Only / All Data | Push only modified cells or entire form |

### Trigger Options

| Trigger | Behavior | Best For |
|---------|----------|----------|
| **On Save** | Pushes automatically when user clicks Save | Real-time cross-cube sync (most common) |
| **Manual** | User clicks Actions → Smart Push to trigger | Large forms where auto-push is too slow |

### Scope Options

| Scope | Behavior | Performance |
|-------|----------|-------------|
| **Changed Data Only** | Pushes only cells the user modified | ✅ Fast — minimal data transfer |
| **All Data on Form** | Pushes every cell visible on the form | ⚠️ Slower — use for full sync |

---

## 6. DATA MAP vs SMART PUSH vs MANUAL PUSH

| Feature | Data Map (Manual Run) | Smart Push (Auto) | Manual Copy |
|---------|----------------------|-------------------|-------------|
| **Trigger** | Admin runs from Jobs Console | Auto on form save | Admin runs manually |
| **Speed** | Bulk — processes all matching data | Fast — only changed cells | Bulk |
| **Use case** | Nightly batch processing | Real-time during data entry | One-time migration |
| **User visibility** | Admin-only | Transparent to users | Admin-only |
| **Navigation** | Navigator → Data Maps → Run | Form → Smart Push tab | Jobs Console |

## 7. SHOW ME — Hotel Pvt Ltd Complete Example

### Three Data Maps Needed

```
Data Map 1: "WF_to_FinPlan_Salary"
  Source: OEP_WFP (Workforce)
  Target: OEP_FS (FinPlan)
  Pushes: Basic_Salary, Benefits, Bonus → Salary_Expense, Benefits_Exp, Bonus_Exp
  Employee dim: Aggregated (sum all employees)
  
Data Map 2: "CapEx_to_FinPlan_Depreciation"
  Source: OEP_CP (Capital)
  Target: OEP_FS (FinPlan)
  Pushes: Depreciation_Amount → Depreciation_Expense
  Asset dim: Aggregated (sum all assets)
  
Data Map 3: "FinPlan_to_Reporting"
  Source: OEP_FS (FinPlan)
  Target: OEP_REP (Reporting/ASO)
  Pushes: All accounts → Same accounts
  All dims: Same (1:1 mapping)
  Run: Nightly batch (not Smart Push — too much data)
```

### Smart Push on Forms

```
Form: "Salary_Entry" (Workforce cube)
  Smart Push: ☑ Enabled
  Data Map: WF_to_FinPlan_Salary
  Trigger: On Save
  Scope: Changed Data Only
  
Form: "CapEx_Budget" (CapEx cube)
  Smart Push: ☑ Enabled
  Data Map: CapEx_to_FinPlan_Depreciation
  Trigger: On Save
  Scope: Changed Data Only

Form: "Revenue_Entry" (FinPlan cube)
  Smart Push: ☐ Disabled (no cross-cube push needed)
```

## 8. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Circular Smart Push (A→B and B→A) | Infinite loop, data corruption | Remove one direction; use one-way push only |
| "All Data" scope on a large form | Form save takes 2+ minutes | Switch to "Changed Data Only" |
| Unmapped dimension with data | Data gets aggregated unexpectedly | Add explicit mapping or Fixed value |
| Smart Push on every form | Performance degradation across app | Only enable on forms that genuinely need cross-cube sync |
| Forgot to create member in target cube | Smart Push silently fails | Validate Data Map before enabling |
| On Save trigger with slow target cube | Users wait during save | Switch to Manual trigger |

## 9. INTERVIEW QUESTIONS

### Beginner
**Q: What is the difference between Smart Push and a Data Map?**
> A Data Map is the **blueprint** defining how data moves between cubes — which members map to which. Smart Push is the **trigger mechanism** that automatically executes a Data Map when a user saves a form. Think of it as: Data Map = the recipe, Smart Push = the oven timer that starts cooking automatically.

### Intermediate
**Q: Hotel Pvt Ltd has 500 employees in the Workforce cube. When salary pushes to FinPlan, should each employee appear separately?**
> No — the Employee dimension should be mapped as "Aggregate." The FinPlan cube has no Employee dimension, so all 500 employees' salaries sum into one "Salary_Expense" total per entity. If FinPlan needed employee-level detail, you'd need to add an Employee dimension to FinPlan (massively increasing cube size). The standard pattern is: detailed data in the operational cube, aggregated totals in the financial cube.

### Architect
**Q: Design the Smart Push strategy for a multi-cube application with FinPlan, Workforce, CapEx, and an ASO Reporting cube. What pushes where, and when?**
> **Real-time pushes (Smart Push on forms):** (1) Workforce → FinPlan: salary, benefits, headcount. Trigger: On Save, Scope: Changed Data Only. (2) CapEx → FinPlan: depreciation, amortization. Trigger: On Save. **Nightly batch pushes (Data Map via Jobs):** (3) FinPlan → ASO Reporting: all data. Run as scheduled job at 2 AM — too much data for real-time push. ASO cubes don't support write-back, so this is always a batch operation. **Never push:** ASO → BSO (ASO is read-only aggregation). **Key design decision:** Keep Smart Push scope as "Changed Data Only" and avoid enabling it on reporting/summary forms.
