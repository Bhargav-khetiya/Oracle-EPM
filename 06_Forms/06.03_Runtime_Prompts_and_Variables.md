# 06.03 Runtime Prompts and Variables

> **Module:** 06_Forms  
> **Topic:** 03 - Runtime Prompts (RTP)  
> **Target Audience:** Consultant  

---

## 1. Learning Objectives
- Define User Variables vs Substitution Variables.
- Understand how Runtime Prompts bridge the gap between Forms and Business Rules.

## 7. Core Concepts: The Variables

To make forms and rules dynamic, EPM uses three types of variables:

### 1. Substitution Variables (Global)
- **Owned by:** Admin.
- **Scope:** Applies to the entire application.
- **Example:** `&CurYr = FY24`. If a form uses `&CurYr` in the column, every user sees FY24.

### 2. User Variables (Personal)
- **Owned by:** End User.
- **Scope:** Unique to the specific person logged in.
- **Example:** `My_Cost_Center`. User A sets their variable to `IT`. User B sets theirs to `HR`. They both open the exact same form. User A sees IT data. User B sees HR data.
- **Benefit:** You only have to build one form, rather than 50 different forms for 50 different managers.

### 3. Runtime Prompts (RTPs)
- **Owned by:** The Business Rule.
- **Scope:** Executes exactly when the rule is run.
- **Example:** You build a "Copy Budget" rule. Instead of hardcoding what to copy, you create an RTP. When the user clicks "Run Rule", a popup box asks: "Copy FROM which version?" and "Copy TO which version?". 

## 9. Internal Processing: Hidden RTPs on Forms
RTPs are usually pop-ups. However, a massive usability feature is the **Hidden RTP**.
- You attach a Business Rule to a Form (e.g., "Calculate Depreciation").
- The rule requires an Entity RTP (e.g., `[Entity_Prompt]`).
- On the form's Business Rule tab, you map the `[Entity_Prompt]` to the **Form Context**.
- **Result:** When the user clicks Save, the popup does *not* appear. The system invisibly grabs the Entity the user is currently looking at on the Page drop-down, feeds it into the RTP, and calculates the rule perfectly in the background.

## 25. Interview Questions

### Intermediate
**Q: A client has 100 department managers. They want each manager to only see their specific department when they open the "Expense Entry" form. How many forms do you need to build?**
> A: Exactly one form. You place a **User Variable** (e.g., `UV_Department`) in the POV or Page of the form. Each manager goes to their user preferences and selects their specific department. The form dynamically updates for whoever is logged in.

### Advanced
**Q: You write a Business Rule with a Runtime Prompt for `Entity`. A user runs the rule and selects `Total Geography` (a parent member). The rule takes 2 hours and crashes the system. How do you prevent this?**
> A: You must restrict the Runtime Prompt. When defining the RTP variable in Calculation Manager, you set the **Member Limits** property (e.g., `@RELATIVE("Total Geography", 0)`). This physically prevents the user from selecting a parent member, forcing them to select a level-0 base member, which runs in seconds.

## 27. Summary
Variables and RTPs turn static, rigid systems into dynamic, user-friendly applications. Master the art of passing the Form Context invisibly into Business Rules for the best user experience.
