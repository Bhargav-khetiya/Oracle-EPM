# 06.06 Form Grid Properties: Every Checkbox

> **Module:** 06_Forms  
> **Topic:** 06 - The Grid Properties Screen  
> **Target Audience:** Administrator / Consultant  

---

## Navigation
**Navigator -> Forms -> [Edit Form] -> Grid Properties**

## Overview
The Grid Properties tab controls the physical rendering, mathematical behavior, and user experience of the Web Form. Every checkbox has a specific architectural consequence.

## Section 1: Display Properties

### "Suppress Missing Blocks"
- **What it does:** If a row has no physical data blocks in Essbase, the row is hidden.
- **Architect Note:** **CRITICAL.** This must be checked on almost every single form. If you put `ILvl0Descendants(Product)` on the rows (10,000 products), and leave this unchecked, the Web Server will attempt to render 10,000 rows of blank data. The browser will crash. Checking this forces Essbase to only send rows that actually contain data.

### "Suppress Missing Data"
- **What it does:** Similar to Missing Blocks, but operates at the cell level.
- **Architect Note:** If you want a user to enter data into a *new* intersection (where no block currently exists), you MUST uncheck these suppression settings, or provide them a "Right Click -> Add Row" Action Menu. Otherwise, they cannot see the blank row to type into it.

### "Enable Grid Spread"
- **What it does:** Allows a user to type a value (e.g., 12,000) into a Parent Time Period (e.g., `YearTotal`) and the system will automatically spread it evenly across the children (1,000 per month).
- **Architect Note:** Disable this for Headcount or Balance Sheet forms. You cannot "spread" 10 employees across 12 months (resulting in 0.83 employees per month). It only makes mathematical sense for Flow accounts (Revenue/Expense).

### "Enable Cell-Level Document Attachments"
- **What it does:** Allows a user to right-click a cell and attach a PDF or Word document justifying their budget number.
- **Architect Note:** **DANGER.** Do not enable this globally. The EPM relational repository has a strict size limit (usually 150GB). If 500 users start attaching 10MB PDFs to individual cells, the relational database will fill up in 3 months, crashing the environment.

## Section 2: Calculation Properties

### "Run Form Rules on Save"
- **What it does:** Executes any Business Rules attached to the form when the user clicks the Save button.
- **Architect Note:** If you attach a 10-minute calculation script to the Save button, the user's browser will freeze with an hourglass for 10 minutes. They will think the system crashed and close the browser. Always use **Run in Background** for heavy rules, or rewrite them in Groovy for sub-second execution.

### "Calculate Form"
- **What it does:** Runs basic dynamic calculations on the form without calling Essbase.
- **Architect Note:** Highly useful for instantaneous subtotals, but cannot replace physical Essbase math.

## Section 3: Smart View / Excel Properties

### "Enable Flex Form"
- **What it does:** Converts a rigid web form into a dynamic Excel sandbox in Smart View. Users can insert blank rows, use native Excel filters, and type `#Missing` to clear data, then click Submit to send it all back to Essbase.
- **Architect Note:** This is the greatest feature Oracle has added in the last 5 years. It eliminates the need for users to build offline Excel models. However, it bypasses some strict Web Validation rules, so ensure your Essbase calc scripts have heavy data protection limits built in.

### "Show Row/Column Headers"
- **What it does:** Displays the raw Member Names (e.g., `Acct_1001`) instead of just the Aliases (`Salary`).
- **Architect Note:** Highly recommended for Admin-only maintenance forms, but confusing for end-users.

## Section 4: Precision and Formatting

### "Minimum / Maximum Precision"
- **What it does:** Controls decimal places.
- **Architect Note:** Set Headcount precision to `2` (e.g., 1.5 FTEs). Set Revenue precision to `0` (Whole dollars). Calculating and storing 8 decimal places for a $5B revenue line wastes RAM and creates rounding errors.

### "Read-Only"
- **What it does:** Locks the entire grid.
- **Architect Note:** Use this for Variance Analysis dashboards where you absolutely do not want a user accidentally overwriting the `Actuals` scenario.
