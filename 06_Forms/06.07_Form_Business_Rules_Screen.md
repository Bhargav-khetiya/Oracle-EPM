# 06.07 Form Business Rules Screen

> **Module:** 06_Forms  
> **Topic:** 07 - Attaching Logic to the UI  
> **Target Audience:** Consultant / Architect  

---

## Navigation
**Navigator -> Forms -> [Edit Form] -> Business Rules Tab**

## Overview
A Web Form without Business Rules is just a dumb grid. Business Rules attached to the form are what calculate the taxes, roll up the aggregations, and push the data to reporting cubes. The timing of *when* these rules fire is critical to performance.

## The Configuration Properties

### 1. Selected Business Rules
You move a rule from the left column (Available) to the right column (Selected). Once selected, you have four highly sensitive checkboxes.

### 2. "Run Before Load" (Checkbox)
- **What it does:** The rule executes the millisecond the user clicks the icon to open the form. The form will not render on the screen until the rule finishes.
- **When to apply:** Almost never. If the rule takes 10 seconds, the user stares at a white screen for 10 seconds every time they open the form. Use this ONLY for lightning-fast Groovy scripts that dynamically calculate the current month string.

### 3. "Run After Load" (Checkbox)
- **What it does:** The form renders on the screen instantly, and then the rule runs in the background.
- **When to apply:** Rarely used. Sometimes used to trigger a background data sync that the user doesn't need to wait for.

### 4. "Run On Save" (Checkbox)
- **What it does:** The most common trigger. The user types data, clicks Save, and the rule executes immediately to calculate the impact (e.g., `Revenue = Volume * Price`).
- **The Danger:** The rule executes *Synchronously*. The browser is frozen until the Essbase math is finished. 
- **Architect Rule:** If a rule takes longer than 5 seconds, DO NOT attach it to "Run On Save". The user will think the system crashed. Move it to an Action Menu.

### 5. "Use Members on Form" (Checkbox)
- **What it does:** This is the magic checkbox. If you check this, EPBCS automatically reads the exact POV, Page, and Rows the user is currently looking at, and silently passes those exact members into the Business Rule as hidden Runtime Prompts.
- **Architect Rule:** **ALWAYS check this.** If a user is looking at `New York`, this checkbox ensures the Business Rule only calculates `New York`. If you uncheck this, the Business Rule might calculate the entire `Total Company`, destroying performance.

### 6. "Hide Prompt" (Checkbox)
- **What it does:** If a Business Rule has Runtime Prompts (RTPs), a popup box normally appears asking the user to answer the prompt. Checking this box hides the popup.
- **Architect Rule:** You must use this in conjunction with "Use Members on Form". EPBCS will grab the POV (e.g., `New York`), silently feed it into the hidden RTP, and calculate instantly without ever bothering the user with a popup box. This creates a seamless, app-like user experience.

## 25. Interview Questions

### Intermediate
**Q: A user opens a form, changes a driver, and clicks Save. The form saves instantly, but the Subtotal row doesn't update. Why?**
> A: The Business Rule that calculates the subtotal is attached to the form, but the "Run On Save" checkbox was left unchecked. The user must manually click the "Action" gear icon and trigger the rule manually, which is a terrible user experience. Check the box to automate it.
