# Advanced Form Templates and Dashboards

Based on EPM Cloud Form Design tutorials (including Financials and FreeForm), building effective forms goes beyond just creating a grid. 

## 1. Action Menus (Including Ad Hoc Grids)

Action menus are right-click contextual menus that guide the user workflow.

### Setup and Enablement
*   **Form Level:** You can attach an Action Menu to a specific form. When a user right-clicks a cell, they see options like "Calculate Year Total", "Copy Prior Year", or "Navigate to Details".
*   **Ad Hoc Grids:** *Newer Feature:* You can now enable Action Menus on Ad Hoc grids in Smart View. This is massive because users often prefer Excel ad hoc over web forms. To enable this, the Action Menu must be assigned to the Cube itself, not just a form.
*   **Passing Context:** The most powerful feature of Action Menus is passing context. If a user right-clicks on "Cost Center 100", the action menu can pass "Cost Center 100" as a runtime prompt to a Business Rule, ensuring the rule only calculates that specific entity.

## 2. Trend-Based Planning in Financials

The standard Financials module heavily utilizes Trend-Based Planning. This is a specific form design pattern.

### How it Works
1.  **Trend Drivers:** Instead of typing dollar amounts, users select a "Trend Driver" from a Smart List (e.g., "Current Year Actual Average", "Prior Year Actual", "Monthly Growth %").
2.  **Rate Input:** Users input a rate or percentage based on the selected driver.
3.  **Calculation:** A business rule runs (often via an Action Menu or on save) that looks at the Driver, grabs the historical data (using `@PRIOR` or `Cross-Dims`), applies the rate, and calculates the future forecast.

### Form Design for Trend Planning
These forms require a very specific layout:
*   **Columns:** Historical Periods (Read-Only) next to Forecast Periods (Input).
*   **Rows:** Account, followed by the Trend Driver Smart List column, followed by the Rate column.
*   **Validation:** Use Cell-Level Security or Valid Intersections to lock the Trend Driver column for accounts that don't support trend planning.

## 3. FCCS vs. Planning Form Management

While the form builder looks identical across EPM Cloud, managing forms in Financial Consolidation and Close (FCCS) has unique constraints:
*   **FCCS Built-in Logic:** FCCS relies on specific custom dimensions (Movement, Data Source, Consolidation). Your forms *must* put these dimensions in the correct context.
    *   *Example:* You cannot allow data entry into `FCCS_Entity Total` or `FCCS_Proportion` in the Consolidation dimension. Forms should strictly point to `FCCS_Entity Input`.
*   **Journals:** In FCCS, data is often entered via Journals, not just forms. Forms are typically used for supplemental data entry (e.g., Headcount) or overriding specific automated calculations.

## 4. Dashboards 2.0

As discussed in earlier guides, Dashboards 2.0 should replace Composite Forms. 
*   **Master-Detail linking:** You can have a summary grid at the top. When a user clicks a row (e.g., "North America"), the detailed grid below it dynamically filters to show only North American entities.
*   **Visualizations:** Use gauge charts for KPIs, waterfall charts for P&L variances, and bar charts for trend analysis directly alongside the input grids.
