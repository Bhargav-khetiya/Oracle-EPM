# FreeForm Forms Administration

Oracle EPM FreeForm provides a massive amount of flexibility compared to standard Planning applications, as it doesn't force the standard required dimensions (like Scenario, Version, Entity, etc.). This flexibility directly impacts how you administer and build Forms.

## 1. What is FreeForm?
FreeForm allows you to build an EPM Cloud application with a completely custom dimensional structure. You can have a cube with just 3 dimensions or up to 29 dimensions, none of which have to be the "standard" Planning dimensions. 

Because of this, Forms in FreeForm behave slightly differently. You cannot rely on built-in logic for "Scenario" or "Version" unless you explicitly build dimensions to serve those purposes.

## 2. Administering Simple Forms
A simple form is a grid with a single Point of View (POV), a set of rows, and a set of columns.

### Creating Simple Forms in FreeForm
1.  **Layout:** You define the layout by dragging and dropping your custom dimensions to the Page, Row, or Column axes.
2.  **Point of View (POV):** Dimensions that are not on the rows, columns, or page axes *must* be in the POV. 
    *   *FreeForm Specifics:* Since FreeForm doesn't mandate a "Scenario" or "Version" dimension, your POV will look entirely different than a standard Planning app. You must ensure the user has context for what data they are entering.
3.  **Member Selection:** You can use functions (like `@Children(Member)`) or explicitly select members for the grid.

### Key Considerations for FreeForm Data Entry
*   **Valid Intersections:** Since the dimensionality is completely open, you must heavily rely on Valid Intersections to prevent users from entering data where it doesn't belong (e.g., entering Sales data against a Headcount metric if you combined those into a single custom dimension).
*   **Security:** Form security dictates who can open the form, but Data Security (applied to the custom dimensions) dictates what they can actually type into the cells.

## 3. Composite Forms vs. Dashboards
While you can build Composite Forms (combining multiple simple forms into one screen), Oracle strongly recommends using **Dashboards 2.0** instead.

### Why Dashboards Over Composite Forms?
*   **Performance:** Dashboards render much faster than traditional composite forms.
*   **Visualization:** Dashboards allow you to embed charts, graphs, and external URLs alongside your data grids.
*   **Interactivity:** You can link the POV of a grid in a dashboard to drive the data shown in a chart dynamically.

## 4. Working with Form Components

To make forms user-friendly, utilize form components:
*   **Action Menus:** Right-click menus that allow users to launch Business Rules, navigate to other forms, or open URLs. These are critical in FreeForm to guide the user workflow since the standard "Planning" process flows might not exist.
*   **Smart Push (Data Maps):** If your FreeForm app has multiple cubes (e.g., an Input cube and a Reporting ASO cube), attach a Smart Push to the form. When the user hits "Save", the data is instantly pushed to the reporting cube so they can see their aggregated results immediately.
