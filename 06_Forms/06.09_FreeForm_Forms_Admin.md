# 06.09 — FreeForm Forms: Complete Guide

> **Module:** 06_Forms | **Topic:** FreeForm Application Forms
> **Audience:** Service Administrator / Architect

---

## 1. WHY — What Real-World Problem Does This Solve?

**The problem:** Pre-built Oracle Planning modules (Financials, Workforce, CapEx) come with predefined dimensions, accounts, and forms. But some clients have unique requirements that don't fit any module — custom KPI tracking, hotel room inventory, project costing, or ad hoc data collection. Building on top of a module's rigid structure causes more problems than it solves.

**The solution:** FreeForm applications give you a **blank canvas** — no predefined dimensions, no predefined accounts, no predefined forms. You design everything from scratch. FreeForm is the "custom build" option in EPBCS.

---

## 2. WHAT — FreeForm vs Module-Based Applications

```
MODULE-BASED APPLICATION:               FREEFORM APPLICATION:
┌─────────────────────────────┐        ┌─────────────────────────────┐
│ Oracle Financials Module    │        │ Custom Application          │
│                             │        │                             │
│ Predefined dims:            │        │ You define ALL dims:        │
│  Account (fixed structure)  │        │  Account (your design)      │
│  Entity (fixed structure)   │        │  Entity (your design)       │
│  Scenario (predefined)      │        │  Scenario (your design)     │
│  Version (predefined)       │        │  Custom dims (unlimited)    │
│  Period/Year (predefined)   │        │  Period/Year (your design)  │
│                             │        │                             │
│ Pre-built forms, rules      │        │ No pre-built artifacts      │
│ Pre-built dashboards        │        │ Build everything yourself   │
│ OOTB planning modules       │        │ Maximum flexibility         │
└─────────────────────────────┘        └─────────────────────────────┘
```

## 3. WHEN TO USE FREEFORM

| Use FreeForm When | Use Modules When |
|-------------------|-----------------|
| Requirements don't fit any OOTB module | Standard financial planning |
| Client wants complete control | Client wants quick deployment |
| Unique KPIs/metrics not in modules | Standard workforce planning |
| Legacy Hyperion migration | Capital expenditure planning |
| Custom data collection | Revenue/sales planning |
| Prototype/POC development | Strategic/long-range planning |

```

```

## 4. CREATING A FREEFORM APPLICATION

```
Step 1: Navigator → Application → Create Application
Step 2: Select "FreeForm" as Application Type
Step 3: Configure:
  Application Name: HotelOps
  Cube Name: HotelOps_BSO  (BSO = Block Storage)
  Description: Hotel Operations Tracking
  
Step 4: Define dimensions:
  Required: Account, Period, Year, Scenario, Version, Entity
  Optional: Add custom dimensions (Room_Type, Floor, Status, etc.)
  
Step 5: Set dense/sparse:
  Dense: Account, Period
  Sparse: Entity, Room_Type, Year, Scenario, Version
  
Step 6: Create members, forms, rules
Step 7: Refresh Database
```

### FreeForm Cube Types

| Cube Type | Storage | Use Case |
|-----------|---------|----------|
| **BSO (Block Storage)** | Write-back, data entry | Data collection, budgeting |
| **ASO (Aggregate Storage)** | Read-only, fast aggregation | Reporting, large datasets |
| **Hybrid BSO** | BSO + dynamic calc | Most common — best of both |

## 5. FREEFORM FORM DESIGN — KEY DIFFERENCES

| Feature | Module Forms | FreeForm Forms |
|---------|-------------|----------------|
| **Account structure** | Predefined (Revenue, Expense, etc.) | You design from scratch |
| **Smart Lists** | Some pre-built (Account Type, etc.) | Create all Smart Lists yourself |
| **Business rules** | Some OOTB rules (Rollup, Copy, etc.) | Write all rules yourself |
| **Currency** | Pre-configured multicurrency | Set up manually if needed |
| **Period hierarchy** | Standard (Month→Quarter→Year) | Design your own time hierarchy |
| **Approval workflow** | Pre-configured | Set up manually |
| **Data entry forms** | Templates available | Design from blank canvas |

## 7. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Too many sparse dimensions | Block explosion, slow performance | Limit to 5-7 sparse dims |
| Not setting dense/sparse correctly | Extremely slow calculations | Account and Period = Dense; everything else = Sparse |
| No Two Pass on ratio members | Occupancy% wrong at parent levels | Enable Two Pass on all calculated ratio members |
| Missing Hybrid Mode | Unnecessary block creation for parents | Enable Hybrid BSO at app creation |
| Not planning dimension hierarchy | Flat lists, no aggregation | Design parent-child hierarchies before building |
| Creating too many cubes | Complexity explosion | Most FreeForm apps need just 1-2 cubes |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: When would you choose a FreeForm application over a Planning Module?**
> Choose FreeForm when the client's requirements don't fit any Oracle OOTB module (Financials, Workforce, CapEx, Revenue, Strategic). Examples: custom KPI tracking, operational metrics, industry-specific data collection (hotel room inventory, manufacturing yield tracking). Choose Modules when standard financial/workforce planning is needed — modules provide pre-built dimensions, forms, rules, and reports that accelerate deployment by weeks.

### Architect
**Q: Hotel Pvt Ltd needs to track daily room status across 500 rooms, 5 hotels, for 365 days. Should this be a FreeForm app or part of the existing FinPlan module?**
> **Separate FreeForm app.** Reasons: (1) The room-level granularity (500 rooms × 365 days = 182,500 data points per metric) would bloat the FinPlan cube. (2) Room inventory tracking has different dimensions (Room_Type, Floor) that don't belong in financial planning. (3) The data collection workflow is different — daily operational entry vs monthly budgeting. (4) Use a Data Map/Smart Push to aggregate key metrics (Occupancy_Rate, RevPAR) from the FreeForm app to the FinPlan cube for P&L reporting. This keeps both cubes lean and purpose-specific.
