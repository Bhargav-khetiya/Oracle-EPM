# 06.11 — Form Precision and Other Options: Complete Guide

> **Module:** 06_Forms | **Topic:** Precision Settings, Context Menus, Dynamic User Variables
> **Audience:** Service Administrator / Power User

---

## 1. WHY — What Real-World Problem Does This Solve?

**The problem:** A hotel's revenue form shows ₹8,523,456.789012 — too many decimals. An expense form shows ₹0.00 for everything because data is in thousands. The admin needs control over how numbers display, what right-click options users see, and how dynamic member selection works.

**The solution:** The "Other Options" tab (Step 3 in form creation) controls precision (decimal places), context menu associations, and dynamic user variable behavior per form.

---

## 2. PRECISION SETTINGS — COMPLETE REFERENCE

### What Is Precision?
Precision controls the **number of decimal places** displayed in form cells. It does NOT change the stored value — only the display.

```
Stored value in Essbase: 8523456.789012

Display with different precision:
  Precision 0: 8,523,457        (rounded, no decimals)
  Precision 2: 8,523,456.79     (standard currency display)
  Precision 4: 8,523,456.7890   (high precision)
  Min Precision 2: 8,523,456.79 (at least 2 decimals always shown)
```

### Precision Options

| Setting | Options | Description |
|---------|---------|-------------|
| **Minimum Precision** | 0-10 | Minimum decimal places always shown |
| **Maximum Precision** | 0-10 | Maximum decimal places displayed |
| **Scope** | Currency, Non-Currency, Percentage | Apply different precision per data type |

### Setting Precision

```
Form Designer → Other Options tab (Step 3)

Currency Values:
  Minimum Precision: [2]  ← always show at least 2 decimals
  Maximum Precision: [2]  ← never show more than 2

Non-Currency Values:
  Minimum Precision: [0]
  Maximum Precision: [0]  ← headcount = whole numbers

Percentage Values:
  Minimum Precision: [1]
  Maximum Precision: [1]  ← show 84.0% not 84.0000%
```

### Hotel Pvt Ltd Precision Settings

| Form | Data Type | Min | Max | Display |
|------|-----------|-----|-----|---------|
| Revenue Entry | Currency | 0 | 0 | ₹8,523,457 (no decimals — amounts in INR) |
| P&L Summary | Currency | 2 | 2 | ₹85,23,456.79 |
| Headcount Entry | Non-Currency | 0 | 0 | 45 (whole people) |
| Occupancy% Form | Percentage | 1 | 1 | 84.0% |
| Exchange Rate Form | Non-Currency | 4 | 6 | 0.01198 (high precision needed) |
| ADR Form | Currency | 0 | 0 | ₹8,500 |

## 3. CONTEXT MENU ASSOCIATIONS

### What Are Context Menus?
Right-click menus (Action Menus) that appear when a user right-clicks a cell. You can associate different Action Menus with different forms.

```
Form Designer → Other Options tab

Context Menu: [Hotel_Revenue_Actions ▾]

When user right-clicks a cell on this form:
  ├── Adjust Data...
  ├── Supporting Details...
  ├── ──────────────
  ├── Open Room Revenue Detail (custom form link)
  ├── Run Revenue Forecast Rule (custom rule link)
  └── View RevPAR Dashboard (custom URL)
```

### Associating Context Menus

```
Step 1: Create an Action Menu (Navigator → Create and Manage → Action Menus)
Step 2: Add menu items (Form links, Rule links, URLs)
Step 3: In Form Designer → Other Options → Context Menu → Select the Action Menu
```

## 4. DYNAMIC USER VARIABLES

### What Is This Option?
"Enable Dynamic User Variables" allows the form to use user variables that change the form's content based on the logged-in user — without the variable being locked in the POV.

```
Other Options → ☑ Enable Dynamic User Variables

Effect:
  The form evaluates User Variables at load time
  Each user sees personalized data automatically
  
  Mumbai GM: UserEntity = Mumbai_Hotel → sees Mumbai data
  Delhi GM: UserEntity = Delhi_Hotel → sees Delhi data
```

## 6. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Precision too high for currency | Form shows ₹8,523,456.789012 | Set Max Precision = 0 or 2 |
| Precision 0 for exchange rates | Rates show as 0 (0.012 rounds to 0) | Set Min Precision = 4 for exchange rate forms |
| No context menu associated | Users miss quick actions | Create and assign Action Menu |
| Different precision on similar forms | Inconsistent user experience | Standardize precision across related forms |
| Instructions too long | Users ignore them | Keep instructions under 5 lines |

## 7. INTERVIEW QUESTIONS

### Beginner
**Q: What does Precision control on a form?**
> Precision controls the **number of decimal places** displayed in cells. Minimum Precision ensures at least N decimals always show (e.g., 100.00). Maximum Precision caps the decimals shown (e.g., 100.79 not 100.7893). It's display-only — the actual stored value in Essbase is unchanged. You can set different precision for Currency, Non-Currency, and Percentage data types.

### Intermediate
**Q: Exchange rates are entered as 0.01198 but the form shows 0.01. What's wrong?**
> The form's Maximum Precision for Non-Currency values is set too low (probably 2). Exchange rates need higher precision — set Minimum Precision = 4 and Maximum Precision = 6 for the exchange rate form. This ensures the rate displays as 0.01198 instead of being rounded to 0.01.
