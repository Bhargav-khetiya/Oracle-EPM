# Form Security and Folder Design

Security in EPM operates on two primary layers: Data Security (what you can see in the database) and Artifact Security (what forms you can open).

## 1. The Inheritance Model
Forms are organized in Folders. Security assigned to a Folder cascades down to all forms inside it.
*   **The Architect's Rule:** Never assign security directly to an individual Form. 
*   **Why?** If you have 50 forms and assign security to each one manually, when a new group is created, an admin must click through 50 separate forms to add them. This guarantees human error.
*   **The Solution:** Create a strict folder hierarchy (e.g., `1_Input_Forms`, `2_Review_Forms`, `3_Admin_Only`). Assign the IDCS groups to the Folders.

## 2. Artifact Security vs. Data Security

*   **Artifact Security:** Determines if the user can click the Form icon in the navigation tree.
*   **Data Security:** Determines if they see data *after* the form opens.
*   **The Trap:** If you give a user "Read" access to the `HR_Input_Form` (Artifact), but they do not have "Read" access to the `HR_Dept` entity in the dimension (Data), the form will open but it will be entirely blank (or throw a data access error). Both layers must align.

## 3. The "Assign Access" Permissions
When applying security to a Form Folder, you have three levels:
*   **Read:** User can open the form and view data.
*   **Write:** User can open the form and input data (assuming Data Security also allows Write).
*   **None:** Explicitly denies access. Useful for locking down a specific form inside a folder that otherwise has Read access.
