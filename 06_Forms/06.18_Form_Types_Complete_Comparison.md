## Introduction

Oracle EPM Cloud offers **6 distinct form types**, each designed for different use cases. Choosing the wrong form type is one of the most common architectural mistakes — it leads to poor user experience, performance issues, and unnecessary complexity.

## 1. Simple Form

### What It Is
A single 2D grid connected to one cube. The most common and performant form type.

### Architecture
```
┌─────────────────────────────────────────┐
│ POV: Year=FY24  Scenario=Budget         │
│ Page: [Entity Dropdown ▼]               │
│                                         │
│ ┌─────────┬──────┬──────┬──────┬──────┐ │
│ │ Account │ Jan  │ Feb  │ Mar  │ Q1   │ │
│ ├─────────┼──────┼──────┼──────┼──────┤ │
│ │ Revenue │ 100  │ 120  │ 110  │ 330  │ │
│ │ COGS    │  40  │  48  │  44  │ 132  │ │
│ │ Margin  │  60  │  72  │  66  │ 198  │ │
│ └─────────┴──────┴──────┴──────┴──────┘ │
└─────────────────────────────────────────┘
```

### When to Use
- Standard data entry (budget input, forecast updates)
- Simple reporting (single-cube views)
- 90% of all forms in a typical EPM application

### When NOT to Use
- Need to show data from 2+ cubes side by side
- Need charts or visual elements
- Need Excel-like flexibility

## 2. Composite Form

### What It Is
Multiple simple form grids displayed on a single page. Each grid can connect to a **different cube**.

### Architecture
```
┌─────────────────────────────────────────┐
│ ┌─────────────────────────────────────┐ │
│ │ Grid 1: OEP_FS (Finance)           │ │
│ │ Revenue, COGS, Margin              │ │
│ └─────────────────────────────────────┘ │
│ ┌─────────────────────────────────────┐ │
│ │ Grid 2: OEP_WFP (Workforce)        │ │
│ │ Headcount, Salary, Benefits        │ │
│ └─────────────────────────────────────┘ │
│ ┌─────────────────────────────────────┐ │
│ │ Grid 3: OEP_CAPEX (Capital)        │ │
│ │ CapEx Budget, Depreciation         │ │
│ └─────────────────────────────────────┘ │
└─────────────────────────────────────────┘
```

### Properties
| Property | Description | Options |
|----------|-------------|---------|
| **Number of Grids** | How many sub-forms | 2–4 |
| **Layout** | Grid arrangement | Vertical stack, Horizontal, 2×2 grid |
| **Shared Dimensions** | Dimensions synced across grids | Select dimensions that share context |
| **Independent Save** | Each grid saves independently or together | ☑️ / ☐ |

### When to Use
- Cross-cube data review (Finance + Workforce on same page)
- Executive summary views
- P&L + KPIs combined view

### Limitations
- Maximum 4 grids per composite form
- Each grid adds a separate Essbase query (slower than a single form)
- Business rules apply per grid, not across grids

## 3. Dashboard

### What It Is
A rich visual page combining data grids, charts, tiles, and other visual components.

### Architecture
```
┌─────────────────────────────────────────────────┐
│ ┌────────────┐ ┌────────────────────────────────┐│
│ │  Revenue   │ │ Revenue Trend (Line Chart)     ││
│ │  $12.5M    │ │ ┌───────────────────────┐      ││
│ │  ▲ 5.2%    │ │ │                       │      ││
│ │  (KPI Tile)│ │ │   /\    /\            │      ││
│ │            │ │ │  /  \  /  \           │      ││
│ └────────────┘ │ └───────────────────────┘      ││
│ ┌────────────┐ └────────────────────────────────┘│
│ │  Expenses  │ ┌────────────────────────────────┐│
│ │  $8.3M     │ │ Department Breakdown (Bar)     ││
│ │  ▼ 2.1%    │ │ ┌───┐ ┌───┐ ┌───┐ ┌───┐     ││
│ │  (KPI Tile)│ │ │   │ │   │ │   │ │   │     ││
│ └────────────┘ │ │ F │ │ S │ │ I │ │ O │     ││
│                │ └───┘ └───┘ └───┘ └───┘     ││
│                └────────────────────────────────┘│
└─────────────────────────────────────────────────┘
```

### Dashboard Components
| Component | Description | Data Entry? |
|-----------|-------------|-------------|
| **Data Grid** | Standard form grid | ✅ Yes |
| **Chart** | Bar, Line, Pie, Donut, Area, Combo | ❌ No (read-only) |
| **KPI Tile** | Single-value highlight with trend indicator | ❌ No |
| **Text Box** | Static text or dynamic content | ❌ No |
| **URL Component** | Embedded web page | N/A |
| **Action Button** | Triggers business rules or navigation | N/A |

### When to Use
- Executive dashboards
- Variance analysis with visual highlights
- KPI monitoring
- Any scenario requiring charts

### Limitations
- More complex to build than simple forms
- Charts are read-only (no data entry in chart)
- Performance can degrade with many components

## 4. FreeForm

### What It Is
A simplified form where the admin selects members freely without the structured Layout tab. It's faster to build but offers less control.

### When to Use
- Quick ad-hoc forms for admin use
- Temporary forms during development
- When the standard Layout tab is too restrictive

### Differences from Simple Form
| Feature | Simple Form | FreeForm |
|---------|------------|---------|
| Layout Tab | Full structured layout with axes | Simplified drag-and-drop |
| Asymmetric support | ✅ Yes | ❌ Limited |
| Grid Properties | Full control | Basic options |
| Build Speed | Medium | Fast |

---

## 5. Flex Form (Smart View Only)

### What It Is
A web form opened in Smart View (Excel) that allows the user to modify the layout dynamically — add rows, use Excel formulas, apply native Excel formatting.

### Enabling
```
Form Properties → Smart View Properties → Enable Flex Form ☑️
```

### What Users Can Do in Flex Form
| Action | Supported? | Notes |
|--------|-----------|-------|
| Add blank rows | ✅ Yes | User inserts rows, selects members |
| Delete rows | ✅ Yes | Only user-added rows |
| Use Excel formulas | ✅ Yes | Client-side only (not saved to Essbase) |
| Use Excel filtering | ✅ Yes | Sort and filter natively |
| Change column members | ✅ Yes | Add/remove periods |
| Submit data to Essbase | ✅ Yes | Click "Submit Data" in Smart View |
| Use Excel conditional formatting | ✅ Yes | Native Excel features |
| Trigger business rules | ✅ Yes | Via Smart View Rules menu |

### When to Use
- Power users who live in Excel
- Large data entry tasks (1000+ rows)
- When users need to compare data not on the form
- When native Excel analysis is needed alongside data entry

### Risks
- Bypasses some web form validation rules
- Users may submit invalid data if Essbase-side validation is missing
- Cell-level security from web forms may not fully apply

---

## 6. Ad Hoc Grid (Smart View Only)

### What It Is
A completely user-driven grid in Smart View. The user starts with a blank Excel sheet, connects to a cube, and builds their own analysis by zooming in/out on dimensions.

### How It Works
1. Open Smart View → Connect to cube
2. See top-level members of all dimensions
3. Double-click a member to "Zoom In" (see children)
4. Right-click → "Keep Only" or "Remove Only" to filter
5. Submit data directly to Essbase

### When to Use
- Data exploration and analysis
- Users who need complete flexibility
- Power user data entry for non-standard intersections

### Limitations
- No admin control over layout
- No business rules association
- No validation rules
- No conditional formatting (web-form based)

# DECISION MATRIX: WHICH FORM TYPE TO USE

| Requirement | Recommended Form Type |
|------------|----------------------|
| Standard data entry (budget/forecast) | **Simple Form** |
| Cross-cube data review (Finance + Workforce) | **Composite Form** |
| Executive dashboard with charts | **Dashboard** |
| Quick admin form for testing | **FreeForm** |
| Power user Excel-based data entry | **Flex Form** |
| Ad-hoc data exploration | **Ad Hoc Grid** |
| Variance analysis with visuals | **Dashboard** |
| Large-volume data entry (1000+ rows) | **Flex Form** |
| Minimal IT involvement in form design | **Ad Hoc Grid** |
| Strict data validation required | **Simple Form** (with Groovy validation) |

## Interview Questions

### Intermediate
**Q: When would you use a Composite Form vs a Dashboard?**
> A: Use a Composite Form when you need data entry across multiple cubes on a single page (e.g., entering Finance data and Workforce data simultaneously). Use a Dashboard when you need visual elements like charts, KPI tiles, and formatted analytics. Dashboards support charts; Composite Forms do not. Composite Forms support full data entry; Dashboards support limited data entry.

### Architect
**Q: A CFO wants a single page showing Revenue trends (chart), Budget vs Actual (grid), and KPI tiles for Margin % and Cash Flow. Which form type do you use and why?**
> A: **Dashboard.** Only Dashboards support the combination of data grids, charts, and KPI tiles on a single page. Configure: (1) KPI tile for Margin % (linked to a specific intersection), (2) KPI tile for Cash Flow, (3) Line chart for Revenue trends (12-month history), (4) Data grid showing Budget vs Actual with variance columns. All components share the same Page dimension (Entity) so the CFO can toggle between departments.
