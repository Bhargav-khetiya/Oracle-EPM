## 🏢 Overview
Flex Forms allow users to modify the form layout at runtime, similar to ad-hoc analysis in Smart View but within the web interface.

### 💡 Logic & Purpose
Historically, if a user wanted to add an extra row for a new project on a standard data form, they couldn't. Standard forms are rigid, locked structures defined by administrators. Flex Forms were introduced to give users the freedom of Excel-based Ad-Hoc analysis (inserting rows, typing member names, filtering) while maintaining the security, business rules, and UI framework of a standard web form.

### 🌀 Confusion Resolution
> **Misconception:** "I turned on Flex Forms, so now users can just drag and drop dimensions to the columns and rows however they want."
> **Reality:** No! Flex Forms allow users to modify the *members* on the rows (or columns depending on setup) by keeping, removing, or inserting them. They do NOT allow the user to pivot the dimensions themselves. If Account is on the row and Period is on the column, it stays that way. For full dimension pivoting, the user must use Smart View Ad-Hoc, not Flex Forms.

### 😈 Twisted Interview Question
**Question:** A user is using a Flex Form in Smart View. They type an invalid account code "123456" into a new row and press Submit. Does it save the data? What happens?
> **Answer:** It does not save. Because Flex Forms enforce the strict data validation of standard forms, EPBCS will instantly reject the submission, flag the row as invalid, and refuse to commit any data to the database until the member name is corrected to a valid member that exists in the application outline.
