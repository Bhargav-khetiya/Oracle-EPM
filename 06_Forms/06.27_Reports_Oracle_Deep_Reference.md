## 📌 EPM Reports (Cloud-Native) — Complete Reference

### What is EPM Reports?

EPM Reports is Oracle's **modern, cloud-native** reporting tool. It replaced Financial Reporting as the go-forward solution. Built directly into EPM Cloud — no separate installation.

### 💡 Logic & Purpose
EPM Reports was designed to provide a lightweight, purely web-based reporting experience. It moves away from heavy client installations (like FR Web Studio) and provides a unified interface across all EPM Cloud business processes.

### ⚙️ Effect & When to Use
- **Effect:** Generates interactive, web-based reports and highly formatted PDF/Excel outputs directly from the cloud browser.
- **When to Use:** This should be your default choice for all new reporting requirements (variance reports, P&L statements, balance sheets).

### ⚖️ Comparison / Difference
**EPM Reports vs Smart View**
- **EPM Reports:** Pixel-perfect, static layouts designed for consumption (executives reading a PDF).
- **Smart View:** Ad-hoc, flexible grids designed for analysis (analysts slicing and dicing data in Excel).

### 🌀 Confusion Resolution
> **Misconception:** "I can export an EPM Report to Excel and use it as a data entry form."
> **Reality:** EPM Reports exported to Excel are purely static data dumps. They do not retain a live connection to the cube for write-back. If you need data entry in Excel, you must use Smart View forms.

### 😈 Twisted Interview Question
**Question:** You create an EPM Report for the Income Statement. The CEO wants to click on "Total Revenue" in the PDF and drill down to see the underlying accounts. How do you build this?
> **Answer:** You cannot drill down in a static PDF output. However, you can enable "Zoom" properties on the grid row for "Total Revenue". When viewed in HTML (web) format, the CEO can click the row to expand it dynamically.

```
Navigation: Home → Reports (Springboard cluster)
OR: Navigator → Reports
```

### Report Components

| Component | Description |
|-----------|-------------|
| **Grid** | Data table — connects to Essbase cube, rows/columns of members |
| **Chart** | Bar, Line, Pie, Area, Combo — linked to grid data |
| **Text Box** | Static text, headers, footers, notes |
| **Image** | Company logos, icons |
| **Page** | Multi-page reports |

### Creating a Report — Step by Step

```
Step 1: Navigator → Reports → Create
Step 2: Set Page Size (Letter, A4, Legal)
Step 3: Add a Grid component
Step 4: Connect to Data Source:
   - Select Application (e.g., FinPlan)
   - Select Cube (e.g., FinPlan BSO)
Step 5: Design Grid Layout:
   - Rows: Account members (or dimension)
   - Columns: Period members
   - POV: Scenario, Version, Year, Entity, Currency
Step 6: Add formatting (fonts, colors, borders)
Step 7: Add Charts (optional)
Step 8: Save and Run
```

### Grid Properties — Every Option

| Property | Description |
|----------|-------------|
| **Data Source** | Application and cube connection |
| **Rows** | Dimension(s) on Y axis |
| **Columns** | Dimension(s) on X axis |
| **POV** | Fixed dimension members |
| **Page Dimension** | Switchable dimension (dropdown) |
| **Suppress Missing Rows** | Hide rows with all #Missing |
| **Suppress Zero Rows** | Hide rows with all zeros |
| **Member Selection** | Static list, function (IChildren), or prompt |
| **Formatting** | Conditional, cell-level, alternate row coloring |
| **Drill-Through** | Enable drill to source data |

### Member Selection in Reports

| Method | Example | Use Case |
|--------|---------|----------|
| **Static** | Jan, Feb, Mar | Fixed columns |
| **Function** | IChildren(Year) → Q1,Q2,Q3,Q4 | Dynamic based on hierarchy |
| **ILvl0Descendants** | All leaf periods | Complete detail |
| **Range** | @RANGE(Period, &ForecastStart, Dec) | Substitution variable driven |
| **Prompt** | User selects at runtime | Interactive reports |

### Formatting & Conditional Formatting

```
Conditional Format Rules:
1. If Revenue > 1,000,000 → Green background + Bold
2. If Variance < 0 → Red text
3. If row is Level 0 → Normal font
4. If row is parent → Bold + Gray background
5. If cell = #Missing → Display as "–" (dash)
```

### Chart Types

| Type | Best For |
|------|----------|
| **Bar (Vertical)** | Comparing values across categories (Revenue by Entity) |
| **Bar (Horizontal)** | Long category names (department comparisons) |
| **Line** | Trends over time (monthly Revenue/Expenses) |
| **Pie** | Proportions (Revenue mix by product) |
| **Area** | Stacked trends (cost components over time) |
| **Combo** | Two measures with different scales (Revenue bars + Margin % line) |
| **Waterfall** | Bridge analysis (Budget → Actual variance breakdown) |

### 🎯 Hands-On: Build 5 EPM Reports

```
Exercise 1: Simple P&L Report
1. Create report → add Grid
2. Connect to FinPlan cube
3. Rows: IDescendants(Total_PnL) — full P&L hierarchy
4. Columns: IChildren(Year) → Q1, Q2, Q3, Q4, YearTotal
5. POV: Scenario=Actual, Version=Final, Year=FY26, Entity=Total Company
6. Format: Bold parents, indent children, currency format
7. Add conditional: Negative values in Red
8. Save as "P&L Summary Report"

Exercise 2: Variance Report with Charts
1. Create report → add Grid + Chart
2. Grid Rows: Top 10 P&L accounts
3. Grid Columns: Actual | Budget | Variance | Variance %
4. Variance = Actual - Budget (formula column)
5. Variance % = Variance / Budget × 100 (formula column)
6. Add Bar Chart: Revenue Actual vs Budget by Entity
7. Add Line Chart: Monthly Revenue trend
8. Format: Green = favorable, Red = unfavorable

Exercise 3: Multi-Page Executive Report
1. Page 1: Revenue Summary (grid + bar chart)
2. Page 2: Expense Detail (grid with all expense accounts)
3. Page 3: KPI Dashboard (grid with Margin %, Growth %, Efficiency)
4. Add company logo as header image
5. Add page numbers as footer
6. Add Date stamp
7. Export as PDF → email to executive team

Exercise 4: Report with Prompts (Interactive)
1. Create report with Page Dimension = Entity
2. Add Runtime Prompt: "Select Scenario" (Actual/Budget/Forecast)
3. Add Runtime Prompt: "Select Year" (FY25/FY26/FY27)
4. User selects values → report regenerates
5. Test: Run report → select different combinations → verify data changes

Exercise 5: Report Book (Multiple Reports)
1. Create 3 individual reports:
   - Revenue Summary
   - Expense Detail
   - Cash Flow Statement
2. Create a Report Book combining all 3
3. Set common POV: Scenario=Actual, Year=FY26
4. Generate as single PDF → one document with all 3 reports
5. Schedule for monthly distribution
```

## 📌 Financial Reporting (FR) — Legacy Reference

### Why You Still Need to Know FR

Even though Oracle replaced FR with EPM Reports, you will still encounter it:
1. Legacy implementations (pre-2021) still use it.
2. Many older clients haven't migrated their reports yet.
3. FR Web Studio is still supported.

### 💡 Logic & Purpose
Financial Reporting (FR) was the gold standard for pixel-perfect reporting in the hyperion on-premises era. It uses a heavy Java-based architecture to render highly complex, printable financial books.

### ⚙️ Effect & When to Use
- **Effect:** Renders legacy reports.
- **When to Use:** When maintaining an older application or when tasked with migrating FR reports to the new EPM Reports platform. Do not build new reports in FR.

### ⚖️ Comparison / Difference
**FR vs EPM Reports**
- **FR:** Legacy, heavy, requires separate Web Studio launch, being deprecated.
- **EPM Reports:** Modern, fast, integrated directly into the EPM Cloud UI, future-proof.

### 🌀 Confusion Resolution
> **Misconception:** "I have to manually rebuild hundreds of FR reports in the new EPM Reports tool."
> **Reality:** Oracle provides an automatic migration tool in the cloud that converts most FR reports to EPM Reports with one click, though complex formatting sometimes requires manual cleanup.

### 😈 Twisted Interview Question
**Question:** A client asks you to fix a formatting issue in an FR report, but when you look for FR Web Studio in the Navigator, it's missing. Why?
> **Answer:** Oracle has begun deprecating and hiding FR Web Studio in newer EPM Cloud pods. You may need to access it via a direct URL hack or inform the client it is time to migrate to EPM Reports.

## 📌 Report Bursting (Entity-Specific Reports)

Bursting is the process of generating a single report multiple times for different members (e.g., generating 50 different P&L PDFs for 50 different departments) and automatically emailing them to the respective managers.

### 💡 Logic & Purpose
Instead of an administrator manually changing the POV to "New York", printing to PDF, and emailing it to the NY manager, bursting automates the mass distribution of personalized data.

### ⚙️ Effect & When to Use
- **Effect:** Runs a batch job that cycles through a specified dimension, generates unique outputs, and distributes them via email or saves them to the Library.
- **When to Use:** Month-end reporting packages where hundreds of cost center managers need their specific budget vs actuals report.

### ⚖️ Comparison / Difference
**Bursting vs Scheduling**
- **Scheduling:** Runs a report at a specific time and sends the *exact same report* to everyone.
- **Bursting:** Runs a report at a specific time but slices it into *different views* based on the bursting definition, sending personalized data to each recipient.

### 🌀 Confusion Resolution
> **Misconception:** "Bursting bypasses security, so if I burst a report, everyone sees everything."
> **Reality:** Bursting can be configured to execute using the recipient's security profile, meaning they will only see the data they are authorized to see, even if the bursting definition includes members they don't have access to.

### 😈 Twisted Interview Question
**Question:** You set up a Bursting job for 100 entities. Manager A receives their email with a PDF attached. Manager B receives an email, but the PDF is completely blank. Why?
> **Answer:** Manager B lacks data access security to their assigned entity in the underlying Essbase cube. The bursting job ran, but returned #Missing for all intersections, resulting in a blank report.

```
Example:
Report Template: "Monthly P&L Report"
Burst on: Entity dimension
Result:
├── Monthly_PnL_Mumbai.pdf (only Mumbai data)
├── Monthly_PnL_Delhi.pdf (only Delhi data)
└── Monthly_PnL_Factory.pdf (only Factory data)
```

```

1. Create a P&L report template
2. Set Entity as Page dimension
3. Enable bursting on Entity
4. Run burst → verify separate PDF per entity
5. Each PDF should show ONLY that entity's data
```

## 🎓 Interview Questions (Oracle Official Level)

**Q: What are the 3 reporting options in EPM Cloud?**
> (1) EPM Reports — cloud-native, Oracle's go-forward direction, real-time data, grid+chart+text. (2) Financial Reporting (FR) — legacy Java-based, pixel-perfect control, being deprecated. (3) Smart View / Excel — ad-hoc analysis and free-form Excel reports with HsGetValue.

**Q: When would you use EPM Reports vs Financial Reporting vs Smart View?**
> EPM Reports: Standard formatted reports with grids and charts, new implementations. FR: When pixel-perfect PDF formatting is required or migrating from existing Hyperion FR. Smart View: When users want Excel flexibility, ad-hoc analysis, or custom dashboards with Excel formulas.

**Q: What is report bursting and when do you use it?**
> Bursting automatically generates separate reports for each member of a dimension (usually Entity). Each entity manager receives a PDF with only their data. Use it for monthly P&L distribution — Mumbai manager gets Mumbai report, Delhi manager gets Delhi report.

**Q: Oracle is deprecating Financial Reporting. What should you tell a client?**
> (1) New implementations should use EPM Reports only. (2) Existing FR reports should be migrated to EPM Reports during the next upgrade cycle. (3) FR still works and is supported, but no new features are being added. (4) Plan migration proactively — don't wait for forced removal.

**Q: How do you create a variance report with favorable/unfavorable formatting?**
> Create a report grid with columns: Actual, Budget. Add formula columns for Variance (=Actual-Budget) and Variance% (=Variance/Budget×100). Apply conditional formatting: If Account Type = Revenue and Variance > 0 → Green (favorable). If Account Type = Expense and Variance > 0 → Red (unfavorable, spent more). Reverse for negative values.
