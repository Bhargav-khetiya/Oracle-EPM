# SECTION 1: WHAT IS A BUSINESS RULE

---

## The Problem

You have a form where 200 hotel managers type budget numbers. But some numbers need to be **calculated**, not typed.

```
                    Jan         Feb         Mar
Revenue            ₹1.2Cr      ₹1.3Cr      ₹1.5Cr    ← Manager types this
Expense            ₹0.8Cr      ₹0.85Cr     ₹0.9Cr    ← Manager types this
Net Income           ???          ???          ???     ← WHO calculates this?
```

**Answer: A Business Rule.**

## What Is a Business Rule?

A **Business Rule** is a set of instructions that tells the Essbase database to calculate data.

```
Think of it like this:

Excel Formula:   =B2-B3        (calculates ONE cell)
Business Rule:   "Net_Income" = "Revenue" - "Expense"  
                 (calculates EVERY intersection in the cube — thousands of cells at once!)
```

## Types of Rules

| Type | Language | When to Use |
|------|----------|-------------|
| **Calc Script** | Essbase native | Standard math, aggregation, data copy — 90% of rules |
| **Groovy** | Java-based | Validation, dynamic logic, API calls — 10% of rules |
| **MDX Script** | MDX | ASO cube calculations — rare |

---

## Step 1: Open Calc Manager

```
Navigator → Calculation Manager
  OR
Navigator → Tools → Calculation Manager

The object tree appears:
  Application: HotelBudget
  └── Plan Type: Plan1 (BSO)
      ├── Rules (empty — we'll create one)
      ├── Rule Sets
      ├── Templates
      └── Variables
```

## Step 2: Create a New Rule

```
Right-click "Rules" under Plan1 → New Rule

  Name: BR_FIN_Calc_Net_Income
  Plan Type: Plan1
  Type: Script  ← (NOT Groovy — we want a Calc Script)
  
Click OK
```

## Step 3: Write the Calc Script

```essbase
/* BR_FIN_Calc_Net_Income */
/* Calculates Net Income for all Budget entities */

FIX("Budget", "Working", @LEVMBRS("Entity", 0), &CurrYear, @CHILDREN("YearTotal"))
    "Net_Income" = "Revenue" - "Expense";
ENDFIX
```

## Step 4: Understand Each Line

```essbase
/* Line 1: Comment — describes what the rule does */
/* BR_FIN_Calc_Net_Income */

/* Line 2: FIX — limits WHICH cells to calculate */
FIX(
    "Budget",                    /* Only Scenario = Budget */
    "Working",                   /* Only Version = Working */
    @LEVMBRS("Entity", 0),      /* Only Level-0 entities (Hotel India, London, NYC) */
    &CurrYear,                   /* Only the current year (substitution variable) */
    @CHILDREN("YearTotal")       /* Only months Jan-Dec (not YearTotal itself) */
)

/* Line 3: The actual calculation */
    "Net_Income" = "Revenue" - "Expense";
    /* For EVERY cell within the FIX scope:
       Set Net_Income = Revenue minus Expense */

/* Line 4: Close the FIX */
ENDFIX
```

## Step 5: Validate

```
Click [Validate] button in the toolbar

If successful: "Validation completed successfully"
If error: "Member [Net_Incomee] not found" ← fix the typo
```

## Step 6: Deploy

```
Click [Deploy] → Makes the rule available to users

States:
  ❌ Not Deployed → Users cannot run it
  ✅ Deployed → Users can run it, forms can trigger it
```

## Step 7: Run It

```
Method 1: Run manually
  Navigator → Rules → BR_FIN_Calc_Net_Income → Launch

Method 2: Attach to a form (runs when user clicks Save)
  Form Designer → Business Rules tab → Add BR_FIN_Calc_Net_Income
```

# SECTION 3: ANATOMY OF A CALC SCRIPT

---

```essbase
/* ANATOMY OF A COMPLETE CALC SCRIPT */

/* ──────── SECTION 1: SET Commands (optional) ──────── */
SET UPDATECALC OFF;          /* Disable incremental calc */
SET CREATEBLOCKONEQ ON;      /* Allow new block creation */

/* ──────── SECTION 2: FIX Statement ──────── */
FIX("Budget", "Working", &CurrYear, @LEVMBRS("Entity", 0))
    
    /* ──────── SECTION 3: Calculations ──────── */
    FIX(@CHILDREN("YearTotal"))
        "Net_Income" = "Revenue" - "Expense";
        "Margin_Pct" = "Net_Income" % "Revenue";
    ENDFIX
    
    /* ──────── SECTION 4: Aggregation ──────── */
    CALC DIM("Account");
    AGG("Entity");

ENDFIX

/* ──────── SECTION 5: Cleanup ──────── */
SET CREATEBLOCKONEQ OFF;
```

### The Rule of Thumb

```
EVERY calc script follows this pattern:
  1. SET     → Configure calculation behavior
  2. FIX     → Define WHICH cells to process
  3. CALC    → Do the math
  4. AGG     → Roll up to parents
  5. CLEANUP → Reset SET commands
```

# SECTION 4: FIX — THE MOST IMPORTANT COMMAND

---

## Why FIX Matters

```
Without FIX:
  "Net_Income" = "Revenue" - "Expense";
  → Essbase processes EVERY SINGLE INTERSECTION in the entire database
  → Millions of cells → Takes 30 minutes → May time out

With FIX:
  FIX("Budget", "Hotel India", "FY26")
      "Net_Income" = "Revenue" - "Expense";
  ENDFIX
  → Essbase processes ONLY Budget + Hotel India + FY26
  → Thousands of cells → Takes 2 seconds
```

## FIX Rules

| Rule | Explanation | Example |
|------|------------|---------|
| **Always use FIX** | Never calculate without scope | `FIX("Budget") ... ENDFIX` |
| **FIX on Sparse dimensions** | Sparse dims filter at block level (fast) | `FIX(@LEVMBRS("Entity", 0))` |
| **Don't FIX on Dense** | Dense dims don't filter blocks | ❌ `FIX("Revenue")` — use IF instead |
| **Nest FIX for clarity** | Separate sparse and period scopes | See example below |

```essbase
/* Good: Nested FIX */
FIX("Budget", "Working", @LEVMBRS("Entity", 0))    /* Sparse scope */
    FIX(@CHILDREN("YearTotal"))                       /* Period scope */
        "Net_Income" = "Revenue" - "Expense";
    ENDFIX
ENDFIX
```

## @Functions for Member Selection in FIX

| Function | What It Returns | Example |
|----------|----------------|---------|
| `@LEVMBRS("Dim", 0)` | All level-0 (leaf) members | All input-level entities |
| `@CHILDREN("Parent")` | Direct children of Parent | Jan, Feb, ..., Dec from YearTotal |
| `@DESCENDANTS("Parent")` | All descendants (all levels) | Every member under Revenue |
| `@ICHILDREN("Parent")` | Parent + direct children | Q1, Jan, Feb, Mar |
| `@IDESCENDANTS("Parent")` | Parent + all descendants | Revenue and everything below it |

# SECTION 5: ASSIGNMENTS AND FORMULAS

---

## Basic Assignment

```essbase
/* Simple formula */
"Net_Income" = "Revenue" - "Expense";

/* Multi-step calculation */
"Gross_Margin" = "Revenue" - "COGS";
"Operating_Income" = "Gross_Margin" - "Operating_Expense";
"Net_Income" = "Operating_Income" - "Tax";
```

## Key Syntax Rules

```essbase
/* ✅ CORRECT: Every statement ends with semicolon */
"Net_Income" = "Revenue" - "Expense";

/* ❌ WRONG: Missing semicolon */
"Net_Income" = "Revenue" - "Expense"

/* ✅ CORRECT: Member names in quotes */
"Net_Income" = "Revenue" - "Expense";

/* ⚠️ RISKY: Unquoted names might work but can break */
Net_Income = Revenue - Expense;

/* ✅ CORRECT: Comments with /* */ 
/* This is a comment */

/* ❌ WRONG: // does NOT work for comments */
// This will cause an error
```

# SECTION 6: IF/ELSE LOGIC

---

```essbase
/* Conditional calculation */
FIX("Budget", "Working", @LEVMBRS("Entity", 0), &CurrYear, @CHILDREN("YearTotal"))
    
    /* Only calculate margin if revenue is not zero */
    IF("Revenue" <> 0 AND "Revenue" <> #Missing)
        "Margin_Pct" = "Net_Income" / "Revenue" * 100;
    ELSE
        "Margin_Pct" = #Missing;
    ENDIF
    
ENDFIX
```

## IF with @ISMBR (Check Current Member)

```essbase
/* Different tax rates for different entities */
FIX("Budget", @LEVMBRS("Entity", 0), &CurrYear, @CHILDREN("YearTotal"))
    IF(@ISMBR("Hotel India"))
        "Tax" = "PBT" * 25.168 / 100;     /* Indian tax rate */
    ELSEIF(@ISMBR("Hotel London"))
        "Tax" = "PBT" * 19 / 100;          /* UK tax rate */
    ELSEIF(@ISMBR("Hotel NYC"))
        "Tax" = "PBT" * 21 / 100;          /* US tax rate */
    ENDIF
ENDFIX
```

# SECTION 7: CROSS-DIMENSIONAL REFERENCES

---

## The `->` Operator

```essbase
/* Read a value from a DIFFERENT member */
"Variance" = "Revenue" -> "Actual" - "Revenue" -> "Budget";

/* Translation:
   Variance = (Revenue where Scenario=Actual) - (Revenue where Scenario=Budget)
   
   The -> operator says "go to this member instead of the current one"
*/
```

## Common Cross-Dim Patterns

```essbase
/* Prior month */
"MoM_Growth" = "Revenue" - "Revenue" -> @PRIOR("Period");

/* Prior year */
"YoY_Growth" = "Revenue" - "Revenue" -> @PRIOR("Year");

/* Different entity */
"Corp_Rate" = "Tax_Rate" -> "Corporate";

/* Multiple cross-dims */
"Budget_Rev_Last_Year" = "Revenue" -> "Budget" -> @PRIOR("Year");
```

# SECTION 8: DATACOPY

---

```essbase
/* Copy data from one sparse member to another */
FIX(@LEVMBRS("Entity", 0), "Working", &CurrYear)
    DATACOPY "Actual" TO "Forecast";
ENDFIX

/* This copies ALL data from Scenario=Actual to Scenario=Forecast
   for every entity, every account, every period */
```

## DATACOPY Rules

```
1. DATACOPY works on SPARSE dimensions only
   ✅ DATACOPY "Actual" TO "Forecast"     (Scenario is Sparse)
   ❌ DATACOPY "Revenue" TO "Expense"     (Account is Dense — won't work)

2. Must create target blocks first (or use SET CREATEBLOCKONEQ ON)
   
3. DATACOPY is FAST — it copies entire blocks at once
```

# SECTION 9: AGGREGATION

---

## Three Ways to Roll Up Data

```essbase
/* AGG — Aggregation only (fastest) */
AGG("Entity");
/* Sums level-0 entities to parent entities:
   Hotel India + Hotel London + Hotel NYC → Hotel Group */

/* CALC DIM — Formulas + Aggregation */
CALC DIM("Account");
/* Runs member formulas AND aggregates:
   Revenue + Expense → runs formula for Net_Income → rolls up */

/* CALC ALL — Everything (slowest) */
CALC ALL;
/* Runs formulas and aggregates ALL dimensions — almost never use this */
```

## When to Use Which

| Command | Speed | What It Does | Use When |
|---------|-------|-------------|----------|
| `AGG("Entity")` | ⚡ Fastest | Sum children to parents | Simple rollup, no formulas |
| `CALC DIM("Account")` | 🟡 Medium | Formulas + aggregation | Account has member formulas |
| `CALC ALL` | 🔴 Slowest | Everything everywhere | Almost never — initial load only |

## Correct Order

```essbase
/* Always: Dense calcs first, then Sparse aggregation */
FIX("Budget", @LEVMBRS("Entity", 0))
    CALC DIM("Account");     /* Dense — calculate within each block */
    CALC DIM("Period");      /* Dense — calculate within each block */
ENDFIX

AGG("Entity");               /* Sparse — create parent blocks */
AGG("Department");            /* Sparse — create parent blocks */
```

# SECTION 10: SET COMMANDS

---

| Command | Purpose | Default | When to Change |
|---------|---------|---------|---------------|
| `SET CREATEBLOCKONEQ ON` | Create new blocks when assigning data | OFF | When DATACOPY or cross-dim creates new intersections |
| `SET UPDATECALC OFF` | Disable incremental calc tracking | ON | Always set OFF for better control |
| `SET MSG DETAIL` | Verbose logging for debugging | SUMMARY | When debugging — see every line processed |
| `SET LOCKBLOCK OFF` | Allow block compression after calc | ON | After large calculations to save memory |

```essbase
/* Typical production rule structure */
SET UPDATECALC OFF;
SET CREATEBLOCKONEQ ON;

FIX("Budget", @LEVMBRS("Entity", 0), &CurrYear)
    DATACOPY "Actual" TO "Budget";
ENDFIX

SET CREATEBLOCKONEQ OFF;
```

| **Manual** | User clicks Rules → selects rule → Launch | Navigator → Rules |
| **On Form Save** | Rule runs automatically when user saves the form | Form Designer → Business Rules tab |

## Attaching a Rule to a Form

```
Step 1: Open Form Designer
  Navigator → Forms → select form → Edit

Step 2: Go to Business Rules tab
  Click "Business Rules" tab

Step 3: Add the rule
  Select Plan Type: Plan1
  Available Rules: BR_FIN_Calc_Net_Income → Add (→ button)
  
Step 4: Configure
  Run On Save: ✅ (runs when user clicks Save)
  Run Before Save: ❌ (this is for Groovy validation)
  
Step 5: Save the form
```

### What Happens at Runtime

```
1. User opens form → sees Revenue and Expense cells
2. User types ₹1.5Cr in Revenue, ₹0.9Cr in Expense
3. User clicks SAVE
4. Planning writes Revenue and Expense to the cube
5. Business Rule fires: "Net_Income" = "Revenue" - "Expense" = ₹0.6Cr
6. Form refreshes → user sees Net Income = ₹0.6Cr
```

# SECTION 12: 10 BEGINNER-FRIENDLY RULES

---

```essbase
/* Rule 1: Calculate Net Income */
FIX("Budget", "Working", @LEVMBRS("Entity", 0), &CurrYear, @CHILDREN("YearTotal"))
    "Net_Income" = "Revenue" - "Expense";
ENDFIX

/* Rule 2: Apply 10% Growth to Revenue */
FIX("Budget", "Working", @LEVMBRS("Entity", 0), &CurrYear, @CHILDREN("YearTotal"))
    "Revenue" = "Revenue" * 1.10;
ENDFIX

/* Rule 3: Copy Actuals to Budget (Seed) */
SET CREATEBLOCKONEQ ON;
FIX(@LEVMBRS("Entity", 0), "Working", &CurrYear)
    DATACOPY "Actual" TO "Budget";
ENDFIX
SET CREATEBLOCKONEQ OFF;

/* Rule 4: Clear Budget Data */
FIX("Budget", @LEVMBRS("Entity", 0), "Working", &CurrYear)
    CLEARDATA @IDESCENDANTS("Net_Income");
ENDFIX

/* Rule 5: Calculate Margin % (with zero-check) */
FIX("Budget", "Working", @LEVMBRS("Entity", 0), &CurrYear, @CHILDREN("YearTotal"))
    IF("Revenue" <> 0 AND "Revenue" <> #Missing)
        "Margin_Pct" = "Net_Income" / "Revenue" * 100;
    ELSE
        "Margin_Pct" = #Missing;
    ENDIF
ENDFIX

/* Rule 6: Salary = Headcount × Average Salary */
FIX("Budget", "Working", @LEVMBRS("Entity", 0), &CurrYear, @CHILDREN("YearTotal"))
    "Salary_Expense" = "Headcount" * "Avg_Salary";
ENDFIX

/* Rule 7: Aggregate All Entities */
FIX("Budget", "Working", &CurrYear)
    AGG("Entity");
ENDFIX

/* Rule 8: Calculate Full P&L */
FIX("Budget", "Working", @LEVMBRS("Entity", 0), &CurrYear, @CHILDREN("YearTotal"))
    "Gross_Margin" = "Revenue" - "COGS";
    "EBITDA" = "Gross_Margin" - "Operating_Expense";
    "EBIT" = "EBITDA" - "Depreciation";
    "PBT" = "EBIT" - "Interest_Expense";
    IF("PBT" > 0)
        "Tax" = "PBT" * 25 / 100;
    ELSE
        "Tax" = 0;
    ENDIF
    "Net_Income" = "PBT" - "Tax";
ENDFIX

/* Rule 9: Variance = Actual - Budget */
FIX("Actual", "Working", @LEVMBRS("Entity", 0), &CurrYear, @CHILDREN("YearTotal"))
    "Variance_Amt" = "Revenue" - "Revenue" -> "Budget";
ENDFIX

/* Rule 10: Full Month-End (Clear → Seed → Calc → Agg) */
/* Phase 1 */ FIX("Forecast",@LEVMBRS("Entity",0),"Working",&CurrYear) CLEARDATA "Revenue"; ENDFIX
/* Phase 2 */ SET CREATEBLOCKONEQ ON;
              FIX(@LEVMBRS("Entity",0),"Working",&CurrYear) DATACOPY "Actual" TO "Forecast"; ENDFIX
              SET CREATEBLOCKONEQ OFF;
/* Phase 3 */ FIX("Forecast","Working",@LEVMBRS("Entity",0),&CurrYear,@CHILDREN("YearTotal"))
              "Net_Income"="Revenue"-"Expense"; ENDFIX
/* Phase 4 */ FIX("Forecast","Working",&CurrYear) AGG("Entity"); ENDFIX
```

# SECTION 13: COMMON MISTAKES

---

| Mistake | What Happens | Fix |
|---------|-------------|-----|
| No FIX statement | Processes entire database → takes forever | Always wrap in FIX |
| Missing semicolon | Syntax error on validation | End every statement with `;` |
| FIXing on Dense dimension | FIX is ignored → processes everything | Use IF(@ISMBR()) for Dense |
| Dividing without zero-check | #Missing results everywhere | `IF("Revenue" <> 0 AND "Revenue" <> #Missing)` |
| DATACOPY on Dense dimension | Error or unexpected behavior | DATACOPY only works on Sparse dims |
| AGG before CALC DIM | Parent values calculated before children | Always: CALC DIM first, then AGG |
| Forgetting SET CREATEBLOCKONEQ OFF | Blocks created everywhere | Turn it OFF right after DATACOPY |
| Using `=` for Store members on Dynamic Calc | "Member is Dynamic Calc" error | Can't assign to Dynamic Calc members |

# SECTION 14: INTERVIEW QUESTIONS

---

### Beginner

**Q1: What is a Business Rule?**
> A set of instructions (calc script) that tells Essbase to calculate data. Example: Net Income = Revenue - Expense. Unlike Excel where each cell has its own formula, a business rule calculates thousands of cells at once.

**Q2: What does the FIX statement do?**
> FIX limits which cells are processed by the rule. Without FIX, the rule processes the entire database. With FIX, you specify exactly which scenarios, entities, and periods to calculate — making it 100x faster.

**Q3: What is the difference between AGG and CALC DIM?**
> AGG only aggregates (sums children to parents). CALC DIM runs member formulas AND aggregates. CALC DIM is needed when an Account has a formula (like Net Income = Revenue - Expense). AGG is faster when you only need to sum up.

### Intermediate

**Q4: Why should you never FIX on a Dense dimension?**
> Dense dimensions exist inside every block. FIX is a block-level filter — it selects or excludes entire blocks. Since Dense members are inside blocks, FIXing on Dense cannot filter them out. Use IF(@ISMBR()) instead for Dense dimension conditions.

**Q5: What is SET CREATEBLOCKONEQ and when do you use it?**
> It tells Essbase to create new data blocks when a cross-dimensional assignment results in a new sparse intersection. Without it, writing to a non-existent block silently fails. Use it before DATACOPY and cross-dim assignments, then turn it OFF immediately after.

### Architect

**Q6: Describe the correct calculation order for a month-end close.**
> 1) Clear target data (CLEARDATA), 2) Copy actuals (DATACOPY with CREATEBLOCKONEQ ON), 3) Calculate Dense dimensions (CALC DIM Account, Period), 4) Aggregate Sparse dimensions (AGG Entity, Department). Dense before Sparse ensures correct parent values.

| Concept | Key Takeaway |
|---------|-------------|
| **Business Rule** | Instructions for Essbase to calculate data |
| **FIX** | Limits scope — ALWAYS use it |
| **Semicolons** | Every statement must end with `;` |
| **FIX on Sparse** | Fast — filters at block level |
| **IF for Dense** | Use IF(@ISMBR()) instead of FIX |
| **DATACOPY** | Fast bulk copy — Sparse dims only |
| **AGG** | Sum children to parents — fastest rollup |
