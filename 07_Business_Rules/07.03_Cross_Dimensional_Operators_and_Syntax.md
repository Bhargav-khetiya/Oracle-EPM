# 07.03 Cross-Dimensional Operators and Syntax

> **Target Audience:** Architect

## 1. Learning Objectives
- Master the `->` operator.
- Understand how to move data across isolated blocks safely.
- Identify the performance dangers of cross-dimensional targeting on the left side of an equation.

## 3. Introduction
A basic Calc Script calculates data within a single block: `Taxes = Salary * 0.20`. 
But what if the `Tax_Rate` is not stored in Cost Center 100? What if `Tax_Rate` is stored centrally in `No_Cost_Center`? Cost Center 100 must look outside its own block to grab the rate. You do this using the Cross-Dimensional operator: `->`.

## 7. Core Concepts: The `->` Operator

### Pulling Data (Right Side of Equation)
This is the most common and safest use of the operator. 
You tell the current block to look at a different block to grab a number.

```essbase
FIX("Cost_Center_100", "Working", "FY24")
    "Taxes" = "Salary" * "Tax_Rate" -> "No_Cost_Center";
ENDFIX
```
- **Execution:** Essbase opens the `Cost_Center_100` block. It calculates Taxes by taking the local Salary, then momentarily looking at the `No_Cost_Center` block, reading the `Tax_Rate`, and bringing that value back to calculate the math. 
- **Performance:** Very fast. Essbase remains in Bottom-Up mode.

### Pushing Data (Left Side of Equation)
You can use `->` to force data into a different block. This is highly dangerous.

```essbase
FIX("Cost_Center_100", "Working", "FY24")
    "Corporate_Tax_Pool" -> "No_Cost_Center" = "Taxes";
ENDFIX
```
- **Execution:** Essbase takes the local `Taxes` from Cost Center 100, and physically writes it into the `Corporate_Tax_Pool` account inside the `No_Cost_Center` block.
- **The Danger:** If `No_Cost_Center` is Sparse, and you target it on the left side of the equation, you force Essbase to evaluate the logic from a **Top-Down** perspective, massively slowing down calculation times and potentially causing block explosion if you aren't careful. 

## 18. Architect Notes: The Golden Rule of `->`
Never put a cross-dimensional operator (`->`) pointing to a Sparse dimension on the left side of an equation if you can avoid it.
Instead of pushing the data out, change your `FIX` statement to sit on the target block, and pull the data in.

*Bad (Pushing out - Slow):*
```essbase
FIX("Cost_Center_100")
    "Target_Account" -> "Cost_Center_200" = "Source_Account";
ENDFIX
```

*Good (Pulling in - Fast):*
```essbase
FIX("Cost_Center_200")
    "Target_Account" = "Source_Account" -> "Cost_Center_100";
ENDFIX
```

## 25. Interview Questions

### Intermediate
**Q: What does the `->` operator do in an Essbase calc script?**
> A: It is the Cross-Dimensional operator. It allows a calculation to reference or target data at a specific intersection that is outside the current scope of the `FIX` statement.

### Architect
**Q: A script uses `"Account_A" -> "Entity_B" = "Account_C";`. The script takes 2 hours. How do you optimize it?**
> A: Targeting a Sparse dimension (`Entity_B`) on the left side of an equation breaks Bottom-Up calculation. I would rewrite the script to `FIX` on `Entity_B` and pull the data: `FIX("Entity_B") "Account_A" = "Account_C" -> "Entity_A"; ENDFIX`. This restores Bottom-Up calculation and executes in seconds.

## 27. Summary
The cross-dimensional operator is necessary for allocations and global drivers, but it must be used strictly on the right side of the equation whenever possible to protect the engine's speed.
