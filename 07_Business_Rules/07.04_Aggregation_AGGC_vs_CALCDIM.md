# 07.04 Aggregation: AGGC vs CALC DIM

> **Module:** 07_Business_Rules  
> **Topic:** 04 - Aggregation Mechanics  
> **Target Audience:** Architect  

---

## 1. Learning Objectives
- Differentiate between `@IDESCENDANTS`, `CALC DIM`, and `AGG`.
- Understand the extreme performance penalty of calculating Dense vs Sparse dimensions.
- Optimize aggregation scripts for standard BSO.

## 3. Introduction
Users enter data at the bottom (e.g., `Jan`, `New York`, `Travel Expense`). Executives want to see the data at the top (`Q1`, `Total NA`, `Total OpEx`). Pushing the data from the bottom to the top is called Aggregation. If you write the aggregation script incorrectly, it will take 8 hours.

## 7. Core Concepts: The Commands

### 1. `CALC DIM`
- **What it does:** Calculates the ENTIRE dimension, executing every single mathematical formula attached to every member, and rolling up the hierarchy.
- **Syntax:** `CALC DIM("Entity", "Product");`

### 2. `AGG`
- **What it does:** ONLY performs hierarchical rollup (Addition, Subtraction, Ignore). It completely ignores member formulas (like `Margin = Profit / Sales`).
- **Syntax:** `AGG("Entity", "Product");`
- **Architect Note:** `AGG` is drastically faster than `CALC DIM` because it doesn't have to invoke the formula parser. Use `AGG` for standard rollup dimensions (like Entity) that don't contain complex custom math.

## 8. Architecture Overview: Dense vs Sparse Aggregation

This is the most critical rule in Essbase performance tuning.

### Dense Dimensions (The Inside of the Block)
- Remember: `Account` and `Period` are usually Dense.
- Dense data lives *inside* a single block.
- Calculating a Dense dimension is incredibly fast because Essbase just does the math in RAM without having to fetch new blocks from the hard drive.
- **The Rule:** You MUST use `CALC DIM` for Dense dimensions (e.g., `CALC DIM(Account, Period);`) because they contain heavy member formulas (like Variance and Ratios).

### Sparse Dimensions (The Outside of the Block)
- Remember: `Entity` and `Product` are usually Sparse.
- Sparse aggregation forces Essbase to read Block A, read Block B, add them together, and physically create a brand new Block C on the hard drive. This is heavy disk I/O.
- **The Rule:** You MUST use `AGG` for Sparse dimensions (e.g., `AGG(Entity, Product);`). If you use `CALC DIM` on a Sparse dimension, Essbase will evaluate every empty block Top-Down, causing a massive performance crash.

## 9. Internal Processing: The Execution Order
You cannot just aggregate everything at once. The order matters mathematically.

**The Golden Sequence (Standard BSO):**
1. **Calculate the Dense Drivers:** `CALC DIM("Account");` (Calculates base-level math like `Revenue = Price * Volume`).
2. **Aggregate the Sparse:** `AGG("Entity", "Product");` (Rolls the base-level Revenue up the physical geographic tree).
3. **Re-Calculate the Dense (Two-Pass):** `CALC DIM("Account");` (Why do it again? Because `Margin %` at the `Total Geography` level is mathematically wrong if you just add up the base-level percentages. You must re-calculate the `Margin %` formula *after* the raw dollars have rolled up).

## 25. Interview Questions

### Intermediate
**Q: You write a script: `AGG("Account");`. The script runs instantly, but all the Variance and Ratio accounts are completely blank. Why?**
> A: The `AGG` command only performs hierarchical rollups (+, -, ~). It explicitly ignores Member Formulas. Because Variance and Ratios are calculated via formulas, `AGG` skips them entirely. You must use `CALC DIM("Account");` to force the engine to execute the formulas.

### Architect
**Q: An application has Hybrid BSO enabled. You review a junior developer's Business Rule and see `AGG("Entity", "Product");`. What should you do?**
> A: Delete the code. In a properly configured Hybrid BSO application, the upper-level Sparse members (Entity, Product) are set to `Dynamic Calc`. They do not physically store data on the hard drive; they calculate in RAM instantly when queried. Therefore, running a physical `AGG` command on them is completely useless and wastes CPU cycles. Hybrid eliminates the need for Sparse aggregation scripts.

## 27. Summary
Know the difference between `AGG` (Hierarchical) and `CALC DIM` (Formulas). Respect the Dense/Sparse boundary. And if you are on modern Cloud EPM, use Hybrid to delete these scripts forever.
