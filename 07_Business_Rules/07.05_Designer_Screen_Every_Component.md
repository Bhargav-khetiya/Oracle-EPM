# 07.05 Designer Screen: Every Component

> **Target Audience:** Architect / Developer

## Navigation
**Navigator -> Rules -> Open Rule -> Designer View**

## Overview
Calculation Manager allows you to write scripts via a visual drag-and-drop UI (Designer) or raw text (Edit Script). While Architects prefer raw text, understanding the Designer palette components is crucial for building automated templates.

## Every Configuration Property in the Palette

### 1. Formula Component
- **What it does:** The most common component. You drag it onto the canvas to perform basic math.
- **Properties:**
  - **Member:** The target intersection you are writing to (e.g., `"Taxes"`).
  - **Equation:** The math (e.g., `"Salary" * 0.20`).
- **Behind the Scenes:** The engine translates this into `Target = Equation;`.

### 2. Condition Component (The IF Statement)
- **What it does:** Splits the logical flow based on a criteria.
- **Properties:**
  - **Condition:** e.g., `"Revenue" > 1000000`
- **Visuals:** It creates two paths on the canvas: a True path and a False path. You drag Formula components into each path.
- **Architect Note:** Avoid wrapping IF statements around Sparse dimensions. It forces a Top-Down evaluation that destroys performance. IF statements should primarily evaluate Dense dimensions.

### 3. Range Component (The FIX Statement)
- **What it does:** The bounding box. It isolates the engine to only calculate a specific slice of data.
- **Properties:**
  - **Dimensions:** You select which members to include (e.g., `Entity = "New York"`, `Year = "FY24"`).
- **Visuals:** It draws a massive gray box on the canvas. Any Formula components you drag *inside* the box are restricted by the FIX.
- **Architect Note:** If you leave a dimension out of the Range component, Essbase defaults to calculating every single member of that dimension. This is the #1 cause of rule timeouts.

### 4. Loop Component
- **What it does:** Executes the logic multiple times.
- **Properties:**
  - **Variable:** A counter (e.g., `i`).
  - **Start / End:** (e.g., 1 to 12).
- **Architect Note:** Loops in native Essbase are notoriously slow. Do not write a loop that iterates 10,000 times. If you need complex looping, you should rewrite the rule in Groovy, which handles Java loops instantly in RAM before passing the final string to Essbase.

### 5. System Templates (The Goldmine)
- **What it does:** Oracle pre-built macros for the hardest Essbase functions.
- **Example: `Allocate` Template**
  - **Properties:** You fill out a wizard: "What is the Source Pool?", "What is the Driver?", "What is the Target?". 
  - **Behind the Scenes:** The wizard automatically generates 20 lines of flawless, highly-optimized `@ALLOCATE` syntax that would take a developer 3 hours to write and debug manually.
- **Architect Note:** Never write Allocations or Currency Conversions from scratch in raw text. Drag the Oracle System Template onto the canvas and fill out the wizard.

## 25. Interview Questions

### Intermediate
**Q: You drag a Formula component onto the canvas and write `"Margin" = "Profit" / "Revenue"`. You validate the rule, and it passes. You run it, and it fails with a Division by Zero error. How do you fix this in the Designer?**
> A: You must drag a **Condition** component onto the canvas *before* the Formula. Set the Condition to `"Revenue" <> 0`. Then, drag the Formula component onto the `True` path of the Condition. This ensures the division only occurs if Revenue exists.
