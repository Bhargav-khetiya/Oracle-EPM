# 08.01 Calc Manager Architecture and Designer

> **Module:** 08_Calculation_Manager  
> **Topic:** 01 - Architecture and Designer  
> **Target Audience:** Consultant

## 1. Learning Objectives
- Navigate the Calculation Manager interface.
- Differentiate between the System View and the Designer View.
- Understand how graphical rules are compiled into Essbase code.

## 3. Introduction
Historically, writing Essbase scripts required opening a text editor, memorizing the proprietary syntax, and praying you didn't miss a semicolon. Oracle created **Calculation Manager** to provide a graphical, drag-and-drop interface for building business logic, making the system accessible to functional finance admins, not just hardcore programmers.

## 8. Architecture Overview
Calculation Manager is not the calculation engine. It is just the UI.
1. **The UI Layer:** You drag a "Formula Component" onto the screen.
2. **The Compile Layer:** When you click "Save", Calc Manager translates your graphical flow chart into native Essbase `.csc` syntax.
3. **The Deployment Layer:** When you click "Deploy", the compiled `.csc` file is pushed to the Essbase server, ready to be executed.

## 10. Navigation: System View vs Designer View

### System View
- The main file explorer.
- Displays all Applications, Cubes, Rules, Scripts, Templates, and Variables.
- **Architect Note:** Never organize rules randomly. Always create folders (e.g., `Financials_Rules`, `Workforce_Rules`) to maintain enterprise order.

### Designer View
- The canvas where you build the rule.
- Contains a Palette on the left (with components like `Formula`, `Condition`, `Loop`, `Script`).
- **The Flowchart:** The rule executes from the Start icon to the End icon. 

## 14. Examples: Drag and Drop Components

### 1. The Point of View (POV) Component
- Equates to the Essbase `FIX` statement.
- You drag a POV onto the canvas and select `Budget`, `FY24`, `Working`. Everything inside this box will only calculate for that intersection.

### 2. The Formula Component
- The actual math.
- E.g., `[Taxes] = [Salary] * 0.20;`
- **Important:** Even in the graphical UI, the syntax inside the formula box must follow Essbase rules (e.g., members must be enclosed in quotes if they contain spaces, and statements must end with semicolons).

### 3. The Condition Component
- Equates to an `IF` statement.
- Creates a split in the flowchart (True / False). 
- E.g., `If ([Department] == "IT") -> Route to Formula A. Else -> Route to Formula B.`

### 4. The Script Component
- For architects who hate the flowchart UI. 
- You drag the Script component onto the canvas and just type raw Essbase code. Many senior developers prefer this because it is faster to type code than to click through dozens of graphical popup windows.

## 19. Production Support: Validating and Compiling
Before deploying a rule, you must click the **Validate** button.
- Calculation Manager checks the syntax against the Essbase outline.
- If you typed `"Taxes" = "Salary" * 0.20;`, but the member `Salary` does not exist in the Account dimension, the validator will throw an error and prevent deployment.

## 25. Interview Questions

### Beginner
**Q: What is the difference between Calculation Manager and Essbase?**
> A: Calculation Manager is the front-end graphical tool used to design, manage, and compile business rules. Essbase is the back-end database engine that actually executes the compiled math.

### Intermediate
**Q: You write a rule in Calculation Manager, validate it, and attach it to a Web Form. The user clicks Save, but the form throws an error saying "Rule cannot be found." What did you forget to do?**
> A: You forgot to **Deploy** the rule. Validating and saving a rule only updates the Calculation Manager repository. It must be explicitly deployed to push the executable file to the Essbase server.

## 27. Summary
Calculation Manager democratizes Essbase scripting. While senior architects often bypass the UI to write raw code, the graphical interface is essential for managing the sheer volume of rules in an enterprise application.
