## 1. Learning Objectives
- Define the purpose of a Template in Calculation Manager.
- Differentiate between Design-Time Prompts (DTPs) and Runtime Prompts (RTPs).
- Architect a modular, reusable code base.

## 3. Introduction
If you are building an application with 50 Business Rules, and 45 of those rules require the exact same logic to clear out empty blocks at the end of the script, you should not type `CLEARBLOCK EMPTY;` 45 times. If you ever need to change that logic, you have to edit 45 files. 

An Enterprise Architect builds **Templates**. 

## 7. Core Concepts: Templates

A Template is a reusable snippet of code or a reusable flowchart that can be embedded into multiple Business Rules.

### 1. Script Templates
- You write a raw Essbase script (e.g., standard database optimization settings like `SET UPDATECALC OFF;`).
- You save it as a Template named `T_Opt_Settings`.
- In your 50 Business Rules, you simply drag the `T_Opt_Settings` template onto the canvas. 
- **The Benefit:** If Oracle releases a new best-practice optimization setting, you edit the Template *once*, and all 50 rules are automatically updated.

### 2. Graphical Templates
- You can create a complex flowchart (e.g., calculating Depreciation based on 5 different asset classes) and save the entire flowchart as a Template. 

## 9. Internal Processing: DTPs vs RTPs

When building Templates, you must understand the difference in prompt timing.

### Runtime Prompts (RTP)
- Execute when the **End-User** clicks "Run Rule" on a Web Form.
- Used to gather business data (e.g., "Which Cost Center are you calculating?").

### Design-Time Prompts (DTP)
- Execute when the **Developer** drags the Template into a Business Rule.
- **Example:** You build a generic "Clear Data" template. When Developer A drags it into the `Financials` rule, a DTP popup asks the *developer*: "Which cube is this for?" The developer types `OEP_FS`. When Developer B drags it into the `Workforce` rule, they type `OEP_WFS`. 
- **The Benefit:** DTPs allow you to write a single, highly generic template that adapts its code based on developer input during the design phase.

## 13. Configuration: Rule Sets
Sometimes you don't want to embed code; you just want to run multiple rules in a specific order.
- **Definition:** A Rule Set is a collection of Business Rules grouped together.
- **Execution:** When a user launches a Rule Set, it runs Rule 1. When Rule 1 finishes, it runs Rule 2, etc.
- **Use Case:** The "Month End Close" process. You bundle the `Calculate_Depreciation`, `Calculate_Taxes`, and `Consolidate_Entity` rules into a single Rule Set, so the admin only has to click one button at 11:59 PM on the last day of the month.

## 24. Common Mistakes
- **The Copy/Paste Developer:** A junior consultant builds 10 identical allocation rules, changing only the target entity in each script by copying and pasting the code 10 times. When a bug is found in the allocation logic, they forget to fix it in Rule #7, causing millions of dollars in calculation errors. *Always use Templates for repeated logic.*

## 25. Interview Questions

### Intermediate
**Q: What is the main advantage of using a Template over writing code directly in a Business Rule?**
> A: Centralized maintenance and code reusability. Updating a logic flaw in a single Template automatically propagates the fix to every Business Rule that references it.

### Architect
**Q: Can you pass a Design-Time Prompt (DTP) variable into a Runtime Prompt (RTP) constraint?**
> A: Yes. This is a highly advanced technique. You can build a template that asks the developer for a parent member (DTP), and then uses that DTP value to dynamically set the `@RELATIVE` boundaries of an RTP that the end-user will see later. This allows the architect to create universally adaptable templates across multiple applications.

## 27. Summary
Templates are the difference between "coding" and "architecting." Treat Calculation Manager like an object-oriented programming environment. Build modular, reusable components.
