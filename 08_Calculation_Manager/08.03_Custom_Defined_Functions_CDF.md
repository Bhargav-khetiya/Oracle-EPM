# 08.03 Custom Defined Functions (CDF)

## 1. Learning Objectives
- Understand the limits of native Essbase functions.
- Define what a Custom Defined Function (CDF) is.
- Explain the transition of CDFs from On-Premise to Cloud.

## 3. Introduction
Essbase comes with hundreds of native functions (`@SUM`, `@AVG`, `@PRIOR`). But occasionally, an enterprise requires bizarre, highly specific math (like a proprietary Black-Scholes options pricing algorithm). You cannot write that in standard calc script syntax. You need a CDF.

## 7. Core Concepts: What is a CDF?

A **Custom Defined Function** is a Java program written outside of Essbase, registered inside Essbase, and called from a Calc Script just like a native `@` function.

### On-Premise Architecture
In the old days (Hyperion 11.1.2.4), a Java developer would:
1. Write a `.jar` file containing the math logic.
2. Put the `.jar` file physically on the Essbase server's hard drive.
3. Open MaxL and run a `CREATE FUNCTION` command to link the `.jar` to the cube.
4. The consultant would then write: `"Bonus" = @MyCustomCalc("Salary");`

## 8. Cloud Evolution: The Death of Custom CDFs

**CRITICAL WARNING:** You cannot upload custom `.jar` files to Oracle Cloud EPM. 

Because EPBCS is a multi-tenant SaaS environment, Oracle cannot allow you to run random, unvetted Java bytecode on their Essbase servers. It is a massive security risk. Therefore, **custom user-created CDFs are dead in the Cloud.**

### The Cloud Replacement: Groovy
If you need to execute complex math that cannot be handled by native Essbase functions, you must write a **Groovy Rule**. 
Because Groovy is Java-based, you can write your complex Black-Scholes algorithm directly into the Groovy script within the Calculation Manager UI, utilizing the Oracle-approved Groovy Sandbox. 

### Oracle OOTB CDFs
While you cannot create *new* CDFs, Oracle pre-packaged a library of extremely useful CDFs into the Cloud that you can call in your standard Calc Scripts. 
- Example: `@CalcMgrExcel` functions. Oracle converted many standard Excel functions (like PMT for loan payments) into pre-packaged CDFs available in Calculation Manager.

## 25. Interview Questions

### Intermediate
**Q: A client migrating from On-Premise Hyperion has a custom Java CDF (`@CalcTaxCustom`) they use in their calc scripts. Can you migrate this to EPBCS?**
> A: No. Oracle Cloud EPM does not allow the uploading of custom `.jar` files for security reasons. The custom Java logic must be rewritten as a Groovy Business Rule or reconstructed using native Essbase functions.

### Architect
**Q: You need to calculate a complex Loan Payment (PMT) in a calc script, exactly how Excel calculates it. Essbase doesn't have a native `@PMT` function. How do you achieve this?**
> A: Oracle provides a suite of pre-built Financial CDFs in Calculation Manager. I would use the `@CalcMgrExcelPMT` function within the calc script, which natively mimics the Excel formula behavior without requiring any custom Java uploads.

## 27. Summary
Do not waste time trying to hack Java into the Cloud. If the math is too complex for standard Calc Manager functions or the pre-built Oracle CDFs, Groovy is your only supported architectural path.
