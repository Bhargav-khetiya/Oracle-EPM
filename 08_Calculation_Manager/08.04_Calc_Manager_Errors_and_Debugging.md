# 08.04 Calc Manager Errors and Debugging

> **Module:** 08_Calculation_Manager  
> **Topic:** 04 - Errors and Debugging  
> **Target Audience:** Architect  

---

## 1. Learning Objectives
- Identify common Calculation Manager compilation errors.
- Troubleshoot Essbase runtime errors.
- Master the `SET MSG` debugging command.

## 3. Introduction
When a Business Rule fails, it fails in one of two places: during Compilation (in Calculation Manager) or during Execution (in Essbase). Understanding how to read the error logs is the only way to survive as an EPM Architect.

## 7. Core Concepts: The Two Types of Errors

### 1. Compilation Errors (Design Time)
- **Where it happens:** When you click "Validate" or "Deploy" in Calc Manager.
- **What it means:** You broke the rules of syntax. You forgot a semicolon, you referenced a member that doesn't exist, or you misspelled an Essbase command.
- **The Log:** The error pops up immediately in the UI. 
- **Example:** `Error: Member "Revenue" not found in database.` (Fix: You either misspelled Revenue, or the member hasn't been refreshed into the cube yet).

### 2. Runtime Errors (Execution Time)
- **Where it happens:** When the user clicks "Run Rule" on a form.
- **What it means:** The syntax was perfect, but the logic physically crashed the Essbase engine (e.g., Block Explosion, Out of Memory, Division by Zero).
- **The Log:** The UI just says "Rule Failed." You must dig into the **Jobs** console or the Essbase Application Logs to see the real error.

## 13. Configuration: Debugging with SET MSG
If your script is running, but calculating the wrong numbers, you cannot easily "step through" the code like a Python debugger. You must use the Essbase message logger.

```essbase
SET MSG DETAIL;
```
If you place this at the top of your Calc Script, Essbase will print an incredibly detailed log of exactly which blocks it opened, which intersections it calculated, and how long each block took. 
- **Architect Note:** NEVER leave `SET MSG DETAIL;` in a production script. It generates so much text in the log file that the logging process itself will slow the calculation down by 50%. Always change it back to `SET MSG SUMMARY;` or `SET MSG ERROR;` before deployment.

## 16. Real Client Scenarios: The "Divide by Zero" Ghost
A rule that ran perfectly for 6 months suddenly fails. 
- You check the logs: `Error: Division by zero`. 
- **The Cause:** The script contains `Margin = Profit / Sales`. In January, Sales was $10,000. The rule worked. In February, a new Cost Center had Profit, but $0 in Sales. The math crashed the block calculation.
- **The Fix:** ALWAYS wrap division in an `IF` statement or use the `@CalcMgrDivide` function.
```essbase
IF("Sales" <> 0 AND "Sales" <> #MISSING)
    "Margin" = "Profit" / "Sales";
ENDIF
```

## 25. Interview Questions

### Intermediate
**Q: A user runs a Business Rule and it fails. You open Calculation Manager, validate the rule, and it says "Passed with no errors." Why did it fail for the user?**
> A: Validation only checks syntax (Compilation). The user experienced a Runtime error. This could be caused by bad data (Division by Zero), a Runtime Prompt (RTP) where the user selected an invalid combination, or a memory timeout on the Essbase server.

### Architect
**Q: You deploy a rule containing `SET CREATENONMISSINGBLK ON`. The rule times out after 1 hour. You check the Application Statistics and see the block count went from 100,000 to 15,000,000. How do you recover the database?**
> A: You have caused a massive Block Explosion. 
> 1. You must immediately kill the active calculation job from the Jobs console to stop the explosion.
> 2. You must remove the `SET CREATENONMISSINGBLK` command or fix the `FIX` statement in the rule.
> 3. To fix the database, you must write a cleanup script using `CLEARBLOCK EMPTY;` across the exploded dimensions to purge the 14,900,000 garbage blocks from the index and hard drive, restoring performance.

## 27. Summary
An architect anticipates failure. Build logging, handle `#MISSING` data gracefully, and know how to read the Essbase logs.
