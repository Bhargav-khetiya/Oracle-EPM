# 08.04 System Settings and Variables Screen

> **Module:** 08_Calculation_Manager  
> **Topic:** 04 - Variables and Settings  
> **Target Audience:** Architect  

---

## Navigation
**Navigator -> Rules -> Actions -> Variable Designer**

## Overview
Calculation Manager relies heavily on Variables. If you hardcode a Year (e.g., `"FY24"`) into 500 Business Rules, you will have to manually open and edit 500 scripts next year. Variables decouple the logic from the time horizon.

## 1. Execution Variables (Runtime Prompts - RTPs)

### What is an RTP?
An RTP pauses the script execution and asks the user a question: "Which Entity do you want to calculate?"

### The Configuration Screen
- **Name:** e.g., `rtp_Entity`
- **Type:** `Member` (The user selects a member from the dimension tree).
- **Dimension:** `Entity` (Restricts the popup to only show Entity members).
- **Default Value:** `"Total Geography"`
- **RTP Text:** "Please select the target Cost Center."

### Architect Note: The "Limits" Property
The most dangerous thing you can do is leave the **Limits** property blank.
If you leave it blank, a user can select `Total Company`. If the script uses the RTP inside a `FIX` statement, it will attempt to calculate the entire company simultaneously, crashing the server.
**The Fix:** You MUST set the RTP Limit to `@RELATIVE("Total Company", 0)`. This physically prevents the user from selecting parent members, forcing the script to only execute on safe, level-0 leaf nodes.

## 2. Global Variables (Substitution Variables)

### What is a Sub Var?
A variable managed by the Administrator that updates the entire system instantly.

### The Configuration Screen
- **Name:** `CurYr`
- **Value:** `FY24`
- **Cube:** `OEP_FS` (or Global)

### Architect Note: Scope (Global vs Application vs Plan Type)
1. **Global (All Applications):** Set at the server level. If you change it, it changes for every single application on the Pod. (Rarely used).
2. **Application Level (EPBCS):** Set for the entire application. If you change `CurYr` to `FY25`, every Web Form and Business Rule in all cubes updates instantly.
3. **Plan Type Level (OEP_FS):** Set for a specific cube. 
**The Conflict:** If you have an Application variable `CurYr = FY24` and a Cube variable `CurYr = FY25`, the **Cube variable wins**. Essbase always respects the narrowest scope. This is a massive trap for junior admins who update the Application variable and wonder why the Financials cube forms are still showing the old year.

## 3. System Settings (Calculation Manager)

**Navigator -> Rules -> System Settings**

### "Compile on Save"
- **What it does:** Every time you click Save on a Business Rule, it automatically checks the syntax and compiles it for Essbase.
- **Architect Note:** Keep this ON.

### "Enable Background Processing"
- **What it does:** Allows rules to execute asynchronously.
- **Architect Note:** Essential for user experience. If a user runs a 5-minute aggregation, they shouldn't have to stare at a frozen screen.

### "Max Errors/Warnings"
- **What it does:** Stops the compilation process if the script generates too many errors.
- **Architect Note:** Default is usually 100. If you have 100 errors in a 50-line script, you should rethink your career path.
