# 08.05 Script Editor Screen and Validation

> **Module:** 08_Calculation_Manager  
> **Topic:** 05 - The Raw Text Editor  
> **Target Audience:** Architect / Developer  

---

## Navigation
**Navigator -> Rules -> Open Rule -> Edit Script View**

## Overview
While the Designer palette is great for beginners and System Templates, true Architects write raw Essbase syntax and Groovy code. The Script Editor is where the actual physics of the engine are commanded.

## Every Configuration Property

### 1. The Script Canvas
This is the raw text area.
- **Architect Note:** EPM Cloud has no auto-complete for native Essbase `@` functions. You must memorize the syntax. If you type `@IDESCENDENTS` instead of `@IDESCENDANTS`, the script will fail validation.

### 2. The Validation Button (The Green Checkmark)
- **What it does:** Parses the raw text against the Essbase `.otl` file to ensure every member name exists and every function is spelled correctly.
- **The Trap:** Validation DOES NOT check mathematical logic.
  - If you write `FIX("Account")`, the validation will PASS because "Account" is a valid dimension.
  - However, when you run the rule, it will crash the server because you cannot put an entire Dense dimension into a FIX statement without triggering a block explosion.
  - **Conclusion:** A validated rule does not mean a safe rule.

### 3. The "Analyze" Button
- **What it does:** This is a hidden gem. It evaluates the script and provides an estimated block count.
- **Architect Note:** If the Analyzer says "This script will evaluate 5,000 blocks," you are safe. If it says "This script will evaluate 2,000,000,000 blocks," DO NOT DEPLOY IT. You have written a Top-Down sparse evaluation that will crash the Pod.

### 4. Variables Tab (Bottom Pane)
- **What it does:** If you type `{My_Prompt}` in the script canvas, Calc Manager automatically registers it in the Variables tab below.
- **The Configuration:** You must click the Variables tab, check the "Is Runtime Prompt" box, and define the limit (e.g., `"Total Geography"`).

### 5. Script Type Dropdown
- **Options:** `Calc Script` | `Groovy Script`
- **What it does:** Tells the compiler which engine to use.
- **Architect Note:** If you select `Groovy Script`, you can no longer write native Essbase `FIX` statements directly on the canvas. You must wrap them in Java strings (e.g., `String script = "FIX... ENDFIX";`).

## 25. Interview Questions

### Architect
**Q: You write a Business Rule in the Script Editor. You use a Substitution Variable `&CurYr`. You validate the rule, and it throws an error: "Variable &CurYr does not exist." You go to the Variables screen, and `CurYr` definitely exists. Why is the script editor throwing an error?**
> A: The Substitution Variable is likely created at the **Cube (Plan Type) Level** (e.g., `OEP_FS`), but the Business Rule properties in Calc Manager are currently set to evaluate against a different cube (e.g., `OEP_WFS`) or the Global application level. Calc Manager validates the script against the specific cube the rule is attached to. Ensure the rule is deployed to the correct cube where the variable physically exists.
