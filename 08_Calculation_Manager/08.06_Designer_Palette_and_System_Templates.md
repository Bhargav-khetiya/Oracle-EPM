## 3. Introduction
When you double-click a Business Rule in the System View, you enter the **Designer View**. This is the graphical flowchart canvas. On the left side of the screen is the Palette, split into two sections: `New Objects` and `Existing Objects`. This is your toolbox.

## 7. Core Concepts: The New Objects Palette

The top half of the palette allows you to drag fresh logical components onto the canvas.

1. **Formula:** A box where you type mathematical equations (e.g., `A = B + C;`).
2. **Script:** A box where you type raw Essbase commands (e.g., `SET UPDATECALC OFF;`).
3. **Condition:** Creates a visual diamond (IF / ELSE split).
4. **Member Block:** Equates to a standard `FIX` statement in Essbase, isolating the calculation to specific members.
5. **Member Range:** Equates to an `@ANCESTORS` or `@DESCENDANTS` function block.
6. **Fixed Loop:** Executes a set of commands multiple times.

## 8. Architecture Overview: Existing Objects & System Templates

The bottom half of the palette contains `Existing Objects`. This is where the true power of Calculation Manager lies, particularly the **System Templates** provided by Oracle out-of-the-box.

### Why Use System Templates?
If a client asks you to build a rule that copies `Budget -> V1` to `Budget -> V2`, you *could* write a manual cross-dimensional script. But it is much safer and faster to drag the Oracle **Copy Data** template onto the canvas. 

### Key System Templates
1. **Clear Data:** Safely wipes data from a specified intersection, automatically handling the backend `CLEARDATA` syntax.
2. **Copy Data:** Moves data from Source to Target. A pop-up asks you for the dimensions (e.g., Source Version, Target Version).
3. **Amount-Unit-Rate:** A pre-built logic flow that perfectly handles driver-based math (Volume * Price = Revenue), ensuring zero-division errors are bypassed.
4. **Allocate - Level to Level:** A massive time-saver. If you need to push IT Overhead from a generic corporate cost center down to 500 base-level cost centers based on Headcount, this template builds the complex `@ALLOCATE` Essbase syntax for you through a simple wizard interface.
5. **Aggregation:** Generates the `CALC DIM()` commands to roll up sparse dimensions.
6. **SET Commands:** Automatically injects best-practice optimization settings (like `SET AGGMISSG ON;`).

## 14. Examples: Building an Allocation
Instead of writing 50 lines of complex Essbase code, an admin drags the **Allocation** System Template onto the canvas.
- A Design-Time Prompt (wizard) pops up.
- **Source:** The admin selects `Account: IT_Pool`.
- **Target:** The admin selects `@RELATIVE(Total Cost Centers, 0)`.
- **Driver:** The admin selects `Account: Headcount`.
- Calculation Manager automatically generates perfectly optimized, error-free Essbase code to perform the allocation.

## 25. Interview Questions

### Beginner
**Q: In the Calculation Manager Designer, where do you find the pre-built logic for copying data or clearing data?**
> A: You find it on the left-hand palette under **Existing Objects -> System Templates**.

### Architect
**Q: A junior developer drags the "Aggregation" System Template onto the canvas, targets all 10 sparse dimensions, and deploys it. The rule takes 4 hours to run. Why is the System Template "slow"?**
> A: The System Template is not slow; the architecture is flawed. The Aggregation template simply generates a `CALC DIM()` command for whatever dimensions you select. By selecting all 10 sparse dimensions simultaneously, the developer forced a full database restructure/aggregation, which calculates billions of empty intersections. System Templates are tools, not magic. You must still apply architectural intelligence by only aggregating the specific dimensions that changed, or better yet, enabling Hybrid BSO to eliminate the need for the Aggregation template entirely.

## 27. Summary
Do not reinvent the wheel. Before writing raw Essbase scripts for standard financial tasks (Copy, Clear, Allocate), check the System Templates folder. Oracle has already written the optimal code for you.
