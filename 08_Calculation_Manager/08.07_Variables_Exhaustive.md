# Variables Exhaustive (SubVars, UserVars, RTPs)

Variables provide flexibility in EPM Cloud, allowing you to update a value in one place and have it cascade across hundreds of forms, rules, and reports.

## 1. Substitution Variables (SubVars)

Substitution Variables are global (or cube-level) placeholders, primarily used to roll the application forward in time.

*   **Syntax:** Always prefixed with an ampersand (`&`). Example: `&CurYr`.
*   **Scope:** Can be defined at the Application level (applies to all cubes) or the Cube level.
*   **Primary Use Case:** Every month-end, an admin changes `&CurMo` from "Jan" to "Feb". Every form, report, and calculation script that references `&CurMo` instantly shifts to February without any code changes.
*   **Limitation:** They are static across all users. If `&CurMo` is February, it is February for everyone.

## 2. User Variables (UserVars)

User Variables are specific to the *logged-in user*.

*   **Syntax:** No special prefix in forms, but in Calc Manager, they are referenced differently depending on the context.
*   **Scope:** User-level.
*   **Primary Use Case:** If a manager only oversees Cost Center 100, they set their `MyCostCenter` User Variable to "CC_100". Any form they open that uses that variable will automatically filter to "CC_100". Another manager can set theirs to "CC_200" and use the exact same form.
*   **Limitation:** The user *must* set their variable in User Preferences before opening a form, otherwise the form throws an error.

## 3. Runtime Prompts (RTPs)

RTPs are dynamic variables used exclusively in Business Rules to ask the user for input *at the moment of execution*.

*   **Syntax:** Always wrapped in braces (`{}`). Example: `{rtp_Scenario}`.
*   **Scope:** Execution-level (lasts only for the duration of the calculation).
*   **Integration with Forms:** When a rule is attached to a form (via "Run on Save" or an Action Menu), the form will attempt to pass its current POV directly to the RTPs.
    *   *If the form's Scenario is "Actual" and the rule has `{rtp_Scenario}`, the rule runs for "Actual" silently.*
    *   *If the rule asks for a member not on the form's POV (e.g., asking for a Percentage Rate), a pop-up dialog appears asking the user to type it in.*
*   **Limits and Security:** You can restrict RTPs using "Member Limits" (e.g., `@RELATIVE("Total Entities", 0)`) to prevent a user from selecting a parent member and accidentally blowing up the database size during an allocation.
