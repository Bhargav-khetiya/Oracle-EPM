## 1. Learning Objectives
- Differentiate between the 3 core variable scopes: Global, Application, and Plan Type.
- Understand the physical limitations of Substitution Variables.
- Master the UI configuration of Variables.

## 3. Introduction
Hardcoding is the enemy of maintenance. If you hardcode `FY24` into 100 Business Rules, 50 Forms, and 200 Reports, you will spend exactly 40 hours on January 1st changing `FY24` to `FY25` manually. To prevent this, architects use **Variables**.

## 7. Core Concepts: Substitution Variables

A Substitution Variable (Sub Var) is a text placeholder that is resolved globally by the Essbase engine before a query or script executes.

### Syntax
Sub Vars are always prefixed with an ampersand: `&`
- `&CurYr`
- `&CurPeriod`

### The Three Scopes (Limits)
When you create a Substitution Variable (Navigator -> Variables), you must define its scope. This is a critical architectural decision.

1. **Global Scope:** 
   - The variable applies to *every application* on the entire Pod (e.g., both EPBCS and FCCS if hosted together).
   - **Limit:** Highly dangerous. If EPBCS is ready to roll over to `FY25`, but FCCS is still closing `FY24`, changing a Global variable will instantly break FCCS reporting.
2. **Application Scope:**
   - The variable applies to all cubes *within* EPBCS (e.g., `FinPlan`, `Manpower`).
   - **Best Practice:** This is the standard scope for Time variables (`&CurYr`).
3. **Plan Type (Cube) Scope:**
   - The variable only applies to a single specific cube (e.g., just `Manpower`).
   - **Use Case:** You have a variable called `&NextCalcStep` that directs a specific Workforce calculation, but is irrelevant to Financials.

## 9. Internal Processing: How Essbase Reads Variables

When Essbase sees a script with `FIX(&CurYr)`, it halts compilation. It queries the relational repository: "What is the string value for `&CurYr` in this Application?" 
The repository returns `"FY24"`. 
Essbase physically rewrites the script in memory to `FIX("FY24")` and then executes it.

## 14. Examples: The Rolling Forecast Challenge
A client wants a 12-month rolling forecast. In January, the form should show `Feb-Dec` (Forecast) and `Jan` (Actual). In February, it should show `Mar-Dec` (Forecast) and `Jan-Feb` (Actual).
- **The Bad Way:** The Admin manually edits the Web Form columns on the 1st of every month.
- **The Architect Way:** The Admin creates 12 Substitution Variables: `&M1`, `&M2` ... `&M12`. The Web Form columns are hardcoded to the variables. On the 1st of the month, the Admin (or an EPM Automate script) updates the 12 variables centrally. The form instantly dynamically shifts.

## 25. Interview Questions

### Intermediate
**Q: An admin creates a Substitution Variable `&CurMonth = Jan`. A user opens a form that has `&CurMonth` in the column, but the column says `#Missing` or throws an error. The admin checks the database, and `Jan` definitely has data. What is wrong with the variable?**
> A: Check the scope. If the admin created the variable at the `Manpower` cube scope, but the user is opening a form connected to the `FinPlan` cube, the `FinPlan` cube cannot see the variable. The admin must change the scope to Application level.

### Architect
**Q: Can you use a Substitution Variable in a member formula (e.g., defining the logic for `Gross Margin %` in the Account dimension)?**
> A: Yes, but with extreme caution. If you use a Sub Var in a member formula, you are baking that variable into the Essbase Outline. When you change the value of the variable next month, Essbase may not immediately recognize the change in dynamic calculations until you perform a Database Refresh or explicitly clear the calculator cache. It is highly recommended to use Sub Vars in Calc Scripts and Forms, but limit their use in permanent Outline member formulas to avoid caching issues.

## 27. Summary
Variables decouple logic from time. A perfectly architected application should have zero hardcoded years or periods in its codebase.
