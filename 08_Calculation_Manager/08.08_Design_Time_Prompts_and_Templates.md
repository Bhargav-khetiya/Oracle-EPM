# Design Time Prompts (DTPs) and Templates

In Calculation Manager, a Template is a reusable block of code. Instead of copying and pasting the same 50 lines of complex allocation math into 10 different Business Rules, you put it in a Template.

## 1. The Power of DTPs (Design Time Prompts)

Templates are useless if they are hardcoded. To make them dynamic, you use DTPs.

*   **What is a DTP?** It is a variable that is populated *when a developer adds the Template to a Business Rule*. 
*   **Contrast with RTP:** An RTP (Runtime Prompt) asks the *end-user* for input when they run the rule. A DTP asks the *developer* for input when they build the rule.

### Example Scenario
You build an "Allocate Expenses" template.
*   It has DTPs for `[Source_Entity]`, `[Target_Entity]`, and `[Driver_Account]`.
*   Developer A drags the template into Rule 1, and fills the DTPs with "Corporate", "Subsidiaries", and "Headcount".
*   Developer B drags the exact same template into Rule 2, and fills the DTPs with "IT", "Marketing", and "Square Footage".

## 2. Syntax inside the Template

Inside the Calculation Manager Template, you reference the DTPs using brackets `[]`.

```essbase
/* This is inside the Template */
FIX( [Target_Entity] )
    "Allocated_Overhead" = [Source_Entity] * [Driver_Account];
ENDFIX
```

## 3. DTP Step-by-Step Configuration

When creating a DTP in Calc Manager, you must define its type to ensure the developer passes the correct string.
1.  **Type:** Member, Members, Dimension, String, Numeric. (If you select "Member", the developer gets a hierarchy picker when they use the template).
2.  **Validation:** You can write logic to validate the DTP input. (e.g., Ensure the developer didn't select a Parent member for a Level 0 input).
3.  **Dependencies:** You can make DTPs dependent on each other. If DTP_1 is "Entity", DTP_2 will only show members from the Entity dimension.

## 4. The Compilation Process

When a Business Rule is validated and deployed, Calculation Manager reads the DTP values provided by the developer, injects them into the Template's brackets, and compiles the final, raw Essbase Calc Script. The Essbase server never sees a "Template"—it only sees the fully expanded, hardcoded script.
