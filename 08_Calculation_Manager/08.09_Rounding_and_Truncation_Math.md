# Rounding and Truncation Math (Calc Manager)

When Essbase calculates data, it uses the raw double-precision floating-point numbers. If you do not explicitly round the data during calculation, reports will show "penny rounding" discrepancies.

## 1. The "Penny Off" Problem

*   **Scenario:** 
    *   Cost = $100.334
    *   Units = 3
    *   Total = Cost * Units = $301.002
*   **Display:** If the form is set to 2 decimal places, the user sees Cost: $100.33, Units: 3, Total: $301.00. 
*   **The User's Complaint:** "Your system is broken. 100.33 * 3 is 300.99, but your total says 301.00. The math is wrong by a penny."
*   **The Reality:** The math is mathematically perfect based on the floating-point numbers, but visually incorrect based on the display precision.

## 2. The @ROUND Function

To solve the penny off problem, you must physically round the data during the calculation script *before* the math rolls up.

```essbase
/* Syntax: @ROUND (Value, DecimalPlaces) */

FIX ("Actual", "FY24")
    "Cost" = @ROUND("Cost_Input" * "FX_Rate", 2);
ENDFIX
```
By forcing the Cost to be stored exactly as `100.33`, the subsequent multiplication (`100.33 * 3`) will yield exactly `300.99`, matching the user's manual calculator.

## 3. The @TRUNCATE Function

Truncation is different from rounding. Rounding looks at the next digit to determine if it should round up or down (e.g., `100.556` rounds to `100.56`). Truncation simply chops off the decimals without looking.

```essbase
/* Syntax: @TRUNCATE (Value) */

/* 100.556 becomes 100.000 */
"Whole_Units" = @TRUNCATE("Calculated_Units");
```
*   **Use Case:** Truncation is heavily used in Workforce Planning. You cannot have 0.5 of an employee for tax calculations. You must truncate the calculated FTE (Full Time Equivalent) to a whole number before calculating head-tax limits.

## 4. Avoiding Division by Zero (The Precision Killer)

While discussed in the interview questions section, it is worth repeating that division by zero or division by `#MISSING` will pollute the database with mathematical infinity errors that break higher-level aggregations. Always wrap division in an `IF` statement.

```essbase
IF ("Units" <> 0 AND "Units" <> #MISSING)
    "Price" = @ROUND("Revenue" / "Units", 2);
ENDIF
```
