# Exhaustive List: All Calc Manager Templates

Calculation Manager includes pre-built "System Templates" out of the box, as well as the ability to create Custom Templates. This is an exhaustive list of the primary template types.

## 1. System Templates (Pre-Built by Oracle)

Oracle provides these to accelerate development without writing code.

### Allocation Templates
*   **Allocate:** The standard top-down allocation template. Allows you to define Source, Target, and Driver. (Under the hood, it generates an `@ALLOCATE` function).
*   **Amount-Unit-Rate:** Calculates Amount = Unit * Rate, or solves for whichever variable is missing based on the others.

### Aggregation Templates
*   **Aggregate:** A GUI wrapper around the `CALC DIM` command. Allows you to select which dimensions to aggregate and in what order.
*   **Clear Data:** A GUI wrapper around the `CLEARDATA` command. Erases a specific slice of the database before running new calculations.

### Currency Templates
*   **Calculate Currency:** (Used primarily in Planning modules). Applies the exchange rates stored in the `HSP_Rates` dimension to local data.

### Workforce/Capital Templates (Module Specific)
If you enable modules, Oracle injects dozens of hidden templates:
*   `OEP_WFSC`: Workforce calculate salary.
*   `OEP_CPDP`: Capital calculate depreciation.

## 2. Custom Templates (User-Defined)

Architects build Custom Templates for reusable logic. When building a Custom Template, you define its "Type".

### Standard Custom Templates
*   **Formula Template:** The most common. Contains a raw block of Essbase script math (e.g., `A = B * C`).
*   **Script Template:** A larger block containing `FIX` statements, `SET` commands, and multiple formulas.
*   **Condition Template:** A reusable `IF/ELSE` logic block (e.g., `IF (Scenario == "Actual")`).

### DTP (Design Time Prompt) Components
Every custom template can utilize DTPs to make it dynamic.
*   **Member DTP:** Prompts the developer to pick a member.
*   **Members DTP:** Prompts the developer to pick a cross-dimensional comma-separated list of members.
*   **Dimension DTP:** Prompts the developer to pick an entire dimension.
*   **String/Numeric DTP:** Prompts for raw text or a static number.
*   **Boolean DTP:** A True/False checkbox for the developer.

## 3. Template Execution Flow

When a template is dragged into a Business Rule, it follows this lifecycle:
1.  **Design Time:** The developer fills out the DTPs.
2.  **Validation:** Calc Manager checks if the DTP inputs are valid (e.g., didn't put a string in a numeric DTP).
3.  **Compilation:** Calc Manager replaces the `[DTP_Name]` tags inside the template with the actual inputs provided by the developer.
4.  **Deployment:** The fully expanded Essbase script is saved to the Essbase server.
5.  **Runtime:** The Essbase engine executes the script block by block. It has no awareness that a "Template" was ever used.
