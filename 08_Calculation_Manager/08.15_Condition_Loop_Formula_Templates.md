# 08.15 Condition, Loop & Formula Templates — Exhaustive Deep Dive

> **Module:** 08_Calculation_Manager  
> **Topic:** 15 — Flow-Control Templates (Condition / Loop / Formula)  
> **Target Audience:** Administrator / Architect / Developer  

---

## Introduction

While the System Templates (Clear Data, Copy Data, Allocation, etc.) generate pre-built logic, the **flow-control templates** — Condition, Loop, and Formula — are the building blocks that give you programmatic control over your business rules. These are the Calc Manager equivalents of `IF/ELSE`, `FOR/EACH`, and raw mathematical expressions.

Every business rule of any complexity uses at least one of these three objects. Mastering every property, option, and combination is what separates a developer from an architect.

---

# PART 1: THE CONDITION TEMPLATE (IF / ELSEIF / ELSE)

---

## 1. What is the Condition Template?

The Condition template generates an `IF ... ELSEIF ... ELSE ... ENDIF` block in the compiled Essbase calc script. It allows you to execute different calculation logic based on whether a condition evaluates to `TRUE` or `FALSE`.

### Where to Find It
- **Graphical Designer:** In the New Objects palette → drag **Condition** onto the canvas between Begin and End (or inside a Loop/Member Range)
- **Script Mode:** You type `IF` / `ELSEIF` / `ELSE` / `ENDIF` directly

---

## 2. Graphical Designer — Every Click, Every Property

When you drag a Condition block onto the Graphical Designer canvas, it creates a **diamond-shaped decision node** with two branches: `True` (green arrow) and `False` (red arrow).

### Step-by-Step: Adding a Condition

1. **Drag** the Condition object from the New Objects palette
2. **Drop** it onto the canvas at the desired position in the flow
3. **Double-click** the diamond to open the **Condition Properties dialog**

### Condition Properties Dialog — Every Field

| Property | Description | Options / Values | Default |
|----------|-------------|------------------|---------|
| **Condition Name** | Display label on the canvas | Free text (e.g., `Check_Department`) | `Condition1` |
| **Condition Type** | How the condition is structured | `Member`, `Data Value`, `Variable`, `Custom` | `Member` |
| **Left Operand** | The value/member on the left side of the comparison | Member name, variable, `@` function, numeric value | (empty) |
| **Operator** | Comparison operator | `==`, `!=`, `<`, `>`, `<=`, `>=` | `==` |
| **Right Operand** | The value/member on the right side of the comparison | Member name, variable, `@` function, numeric value, `#Missing` | (empty) |
| **Boolean Connector** | Combine multiple conditions | `AND`, `OR` | (none — single condition) |
| **Add Condition** | Button to add another condition row (creates compound conditions) | Click to add row | — |
| **Negate (NOT)** | Checkbox to negate the entire condition | `TRUE` / `FALSE` | `FALSE` |

---

## 3. Condition Type Deep Dive — All 4 Types

### Type 1: Member Condition
Tests whether the current calculation context is on a specific member.

**What it generates:**
```essbase
IF(@ISMBR("IT_Department"))
    /* True branch */
ENDIF
```

**Properties when "Member" is selected:**
| Field | Description |
|-------|-------------|
| Dimension | Dropdown — select which dimension to test |
| Member | Member selector — pick the member(s) to test |
| Function | Optional — use `@ISMBR`, `@ISDESC`, `@ISANC`, `@ISLEV`, `@ISGEN`, `@ISUDA`, `@ISACCTYPE`, `@ISCHILD`, `@ISPARENT`, `@ISSAMEGEN`, `@ISSAMELEV` |

**All Available @IS Functions for Conditions:**

| Function | Syntax | What It Tests | Example |
|----------|--------|---------------|---------|
| `@ISMBR` | `@ISMBR("member")` | Is the current member exactly this? | `@ISMBR("Jan")` |
| `@ISDESC` | `@ISDESC("parent")` | Is the current member a descendant of this parent? | `@ISDESC("Total_Entity")` |
| `@ISANC` | `@ISANC("child")` | Is the current member an ancestor of this child? | `@ISANC("P_100")` |
| `@ISLEV` | `@ISLEV(n)` | Is the current member at level n? (0 = bottom) | `@ISLEV(0)` |
| `@ISGEN` | `@ISGEN(n)` | Is the current member at generation n? (1 = top) | `@ISGEN(3)` |
| `@ISUDA` | `@ISUDA("uda_value")` | Does the current member have this UDA tag? | `@ISUDA("Allocatable")` |
| `@ISACCTYPE` | `@ISACCTYPE("type")` | Is the account type Revenue/Expense/Asset/Liability/Equity? | `@ISACCTYPE("Revenue")` |
| `@ISCHILD` | `@ISCHILD("parent")` | Is the current member a direct child? | `@ISCHILD("Q1")` |
| `@ISPARENT` | `@ISPARENT("child")` | Is the current member the parent of this child? | `@ISPARENT("Jan")` |
| `@ISSAMEGEN` | `@ISSAMEGEN("member")` | Is the current member at the same generation? | `@ISSAMEGEN("East")` |
| `@ISSAMELEV` | `@ISSAMELEV("member")` | Is the current member at the same level? | `@ISSAMELEV("P_100")` |

### Type 2: Data Value Condition
Tests the actual numeric value in a cell.

**What it generates:**
```essbase
IF("Revenue" > 0 AND "Revenue" <> #Missing)
    "Tax" = "Revenue" * 0.25;
ENDIF
```

**Properties when "Data Value" is selected:**
| Field | Description |
|-------|-------------|
| Left Member | The member/intersection whose value to test (e.g., `"Revenue"`) |
| Operator | `==`, `!=`, `<`, `>`, `<=`, `>=` |
| Right Value | A number, `#Missing`, another member name, or a variable |
| Cross-Dim | Optional cross-dimensional reference (e.g., `"Revenue" -> "Budget"`) |

### Type 3: Variable Condition
Tests the value of a Runtime Prompt or substitution variable.

**What it generates:**
```essbase
IF({RTP_Scenario} == "Budget")
    /* Budget-specific logic */
ENDIF
```

**Properties when "Variable" is selected:**
| Field | Description |
|-------|-------------|
| Variable Name | Dropdown — select from defined RTPs, substitution vars, or global/local vars |
| Operator | `==`, `!=`, `<`, `>`, `<=`, `>=` |
| Compare To | A literal value, another variable, or a member name |

### Type 4: Custom Condition
Raw free-text entry — you type whatever Essbase syntax you want.

**What it generates:** Exactly what you type.

**Properties when "Custom" is selected:**
| Field | Description |
|-------|-------------|
| Custom Expression | Free-text box — enter any valid Essbase Boolean expression |

**Use Case:** When none of the pre-built types support your condition (e.g., complex nested `@` functions like `@ISLEV(0) AND @ISUDA("CapEx") AND "Amount" -> @PARENT("Period") > 1000`)

---

## 4. Compound Conditions — AND / OR / NOT Combinations

You can combine multiple conditions using Boolean connectors.

### Adding Multiple Conditions
Click **"Add Condition"** in the Condition Properties dialog to add additional rows.

| Row | Left Operand | Operator | Right Operand | Connector to Next |
|-----|-------------|----------|---------------|-------------------|
| 1 | `@ISMBR("IT")` | `==` | `TRUE` | `AND` |
| 2 | `"Revenue"` | `>` | `0` | `OR` |
| 3 | `@ISUDA("Active")` | `==` | `TRUE` | (none — last row) |

**Generated Script:**
```essbase
IF(@ISMBR("IT") AND "Revenue" > 0 OR @ISUDA("Active"))
```

> **⚠️ CRITICAL: Operator Precedence Trap**
> Essbase evaluates `AND` before `OR` (just like math evaluates `*` before `+`). The expression above is NOT `(A AND B) OR C` — it is `A AND (B OR C)` due to precedence rules. To force grouping, use the Custom condition type and add parentheses manually:
> ```essbase
> IF((@ISMBR("IT") AND "Revenue" > 0) OR @ISUDA("Active"))
> ```

### Negation (NOT)
Checking the **Negate** checkbox wraps the entire condition in a `NOT()`:
```essbase
IF(NOT(@ISMBR("IT")))
```

---

## 5. ELSEIF and ELSE Branches

### Adding ELSEIF
In the Graphical Designer:
1. Right-click the Condition diamond
2. Select **"Add Else If"**
3. A new condition diamond appears on the `False` branch
4. Configure its properties identically to the original condition

### Adding ELSE
1. Right-click the Condition diamond (or the last ELSEIF diamond)
2. Select **"Add Else"**
3. A simple pass-through block appears for the default case

### Generated Script Example (IF / ELSEIF / ELSE / ENDIF)
```essbase
IF(@ISUDA("Premium"))
    "Discount_Rate" = 0.15;
ELSEIF(@ISUDA("Standard"))
    "Discount_Rate" = 0.10;
ELSEIF(@ISUDA("Basic"))
    "Discount_Rate" = 0.05;
ELSE
    "Discount_Rate" = 0;
ENDIF
```

### Nesting Conditions
You can drag a Condition inside the True or False branch of another Condition to create nested IF statements.

**Generated Script:**
```essbase
IF(@ISMBR("US_Entity"))
    IF(@ISACCTYPE("Revenue"))
        "Tax" = "Revenue" * 0.21;
    ELSE
        "Tax" = "Revenue" * 0.25;
    ENDIF
ENDIF
```

> **⚠️ Performance Warning: Nested IF Statements**
> Every `IF` statement forces Essbase to evaluate conditions at the **cell level** (inside the block). A three-level nested IF inside a large FIX can be 10x slower than the equivalent three separate FIX statements. 
> 
> **Best Practice:** Replace nested IFs with tighter FIX statements wherever possible:
> ```essbase
> /* SLOW: Nested IF */
> FIX("Budget")
>     IF(@ISMBR("US_Entity"))
>         IF(@ISACCTYPE("Revenue"))
>             "Tax" = "Revenue" * 0.21;
>         ENDIF
>     ENDIF
> ENDFIX
> 
> /* FAST: Tight FIX */
> FIX("Budget", "US_Entity", @RELATIVE("Revenue_Accounts", 0))
>     "Tax" = "Revenue" * 0.21;
> ENDFIX
> ```

---

## 6. Condition Template — Best Practices

| # | Best Practice | Why |
|---|--------------|-----|
| 1 | Always protect division with `IF(denominator <> 0 AND denominator <> #Missing)` | Prevents #DIV/0 errors and #Missing propagation |
| 2 | Use `@ISUDA` over `@ISMBR` when possible | UDAs make rules dynamic — adding a new member with the UDA auto-includes it without editing the rule |
| 3 | Limit IF nesting to 2 levels maximum | Performance degrades exponentially with each nesting level |
| 4 | Replace IF with FIX when testing sparse dimension members | FIX operates at block level (fast); IF operates at cell level (slow) |
| 5 | Use ELSEIF instead of separate IF blocks | Separate IFs evaluate ALL conditions; ELSEIF short-circuits after the first match |
| 6 | Always include an ELSE branch for safety | Catches unexpected edge cases; prevents silent data corruption |

---

## 7. Common Errors & Troubleshooting

| Error | Cause | Fix |
|-------|-------|-----|
| `"Syntax error near ENDIF"` | Missing `IF` for a dangling `ENDIF` | Check graphical flow — ensure every Condition diamond has matching begin/end |
| `"Cannot use IF outside of a member block"` | IF used at top-level without a FIX or member formula context | Wrap in `FIX()...ENDFIX` or use inside a member formula block `"Member"( IF... ENDIF )` |
| `"ELSEIF without matching IF"` | ELSEIF placed outside the Condition's branch in graphical mode | Re-drag the ELSEIF inside the Condition's False branch |
| Condition always evaluates FALSE | Comparing a numeric cell value to a string literal | Ensure right operand is numeric (no quotes around numbers) |

# PART 2: THE LOOP TEMPLATE (FOR EACH / ITERATION)

---

## 1. What is the Loop Template?

The Loop template generates iterative processing in the compiled script. In Essbase Calc Manager, loops are primarily implemented through **FIX-based iteration** over member lists, not traditional `for(i=0; i<n; i++)` programming loops.

### Where to Find It
- **Graphical Designer:** New Objects palette → drag **Loop** onto the canvas
- **Script Mode:** FIX on a member function that returns a list (e.g., `@CHILDREN`, `@RELATIVE`)

---

## 2. Loop Properties Dialog — Every Field

When you double-click a Loop block on the Graphical Designer canvas:

| Property | Description | Options / Values | Default |
|----------|-------------|------------------|---------|
| **Loop Name** | Display label on canvas | Free text (e.g., `Loop_Entities`) | `Loop1` |
| **Loop Type** | What type of iteration | `Fixed Member List`, `Member Function`, `Range`, `Variable` | `Fixed Member List` |
| **Dimension** | Which dimension to loop over | Dropdown of all dimensions | (first dimension) |
| **Members** | Which members to iterate through | Member selector (pick specific members) | (empty) |
| **Function** | Member function for dynamic list | `@CHILDREN`, `@DESCENDANTS`, `@IDESCENDANTS`, `@RELATIVE`, `@SIBLINGS`, `@ISIBLINGS`, `@UDA` | (none) |
| **Level/Generation** | For `@RELATIVE` — target level or generation | Number (0 = bottom level) | `0` |
| **Variable** | Use an RTP/variable as the member list | Variable selector | (none) |

---

## 3. Loop Type Deep Dive — All 4 Types

### Type 1: Fixed Member List
You manually select specific members to loop over.

**Generated Script:**
```essbase
FIX("Entity_A")
    /* loop body */
ENDFIX
FIX("Entity_B")
    /* loop body */
ENDFIX
FIX("Entity_C")
    /* loop body */
ENDFIX
```

**Use Case:** When you need to apply different logic per member, or when the member list is small and static.

> **Architect Note:** This does NOT generate a single `FIX("Entity_A", "Entity_B", "Entity_C")`. Each member gets its own FIX block. This matters because each FIX is processed sequentially, which can be slower than a single FIX with all members but allows unique logic per iteration.

### Type 2: Member Function
Uses an `@` function to dynamically generate the member list at runtime.

**Properties when "Member Function" is selected:**
| Field | Options |
|-------|---------|
| Function | `@CHILDREN("parent")`, `@DESCENDANTS("parent")`, `@IDESCENDANTS("parent")`, `@RELATIVE("parent", level)`, `@SIBLINGS("member")`, `@ISIBLINGS("member")` |
| Parent Member | The anchor member for the function |
| Level/Generation | For `@RELATIVE` only — specifies the target level |

**Generated Script (example: @CHILDREN):**
```essbase
/* If "Total_Product" has children P_100, P_200, P_300 */
FIX("P_100")
    /* loop body */
ENDFIX
FIX("P_200")
    /* loop body */
ENDFIX
FIX("P_300")
    /* loop body */
ENDFIX
```

**Use Case:** Dynamic rules that automatically adapt when new members are added to the hierarchy. If P_400 is added next month, the loop automatically includes it without editing the rule.

### Type 3: Range
Loops over a sequential range (primarily used with Period/Year dimensions).

**Generated Script:**
```essbase
FIX("Jan")
    /* loop body */
ENDFIX
FIX("Feb")
    /* loop body */
ENDFIX
/* ... through Dec */
```

### Type 4: Variable
Uses a Runtime Prompt variable as the member list. The user selects which members to loop over at execution time.

**Generated Script:**
```essbase
FIX({RTP_Entity_Selection})
    /* loop body */
ENDFIX
```

---

## 4. Loop Body — What Goes Inside

Inside the loop block on the graphical canvas, you can place any other object:
- **Formula** blocks (calculations)
- **Condition** blocks (IF/ELSE)
- **Script** blocks (raw script)
- **System Templates** (Clear Data, Copy Data, etc.)
- **Nested Loops** (loop inside a loop)

### Nested Loop Example
Outer loop: Entities. Inner loop: Periods.

**Generated Script:**
```essbase
FIX("Entity_A")
    FIX("Jan")
        "Tax" = "Revenue" * 0.25;
    ENDFIX
    FIX("Feb")
        "Tax" = "Revenue" * 0.25;
    ENDFIX
ENDFIX
FIX("Entity_B")
    FIX("Jan")
        "Tax" = "Revenue" * 0.25;
    ENDFIX
    FIX("Feb")
        "Tax" = "Revenue" * 0.25;
    ENDFIX
ENDFIX
```

> **⚠️ Performance Warning: Nested Loops**
> Nested loops multiply the number of FIX blocks exponentially. 100 Entities × 12 Periods = 1,200 separate FIX blocks. This is almost always slower than a single `FIX("Entity_A", "Entity_B", ..., "Jan", "Feb", ...)`.
>
> **When nested loops ARE justified:** When the loop body contains unique logic per iteration (e.g., different tax rates per entity-period combination).

---

## 5. Loop vs FIX — Critical Architecture Decision

| Scenario | Use Loop | Use Single FIX |
|----------|---------|----------------|
| Same math for all members | ❌ | ✅ Single FIX is faster |
| Different math per member | ✅ (with Condition inside) | ❌ |
| Need to reference current loop member in formula | ✅ | ❌ |
| Processing order matters (Entity A must calc before Entity B) | ✅ (sequential) | ❌ (parallel/unordered) |
| Maximum performance | ❌ | ✅ |

---

## 6. Loop Best Practices

| # | Best Practice | Why |
|---|--------------|-----|
| 1 | Use `@RELATIVE(parent, 0)` instead of `@DESCENDANTS` when only targeting Level 0 | `@DESCENDANTS` includes upper-level members which create unnecessary iterations |
| 2 | Avoid nested loops unless logic truly varies per combination | Exponential FIX block multiplication kills performance |
| 3 | Use `@UDA` for dynamic member lists instead of hard-coded names | Auto-adapts to metadata changes |
| 4 | Place SET commands OUTSIDE the loop, not inside | SET commands reset per FIX block; placing them inside means they execute N times needlessly |
| 5 | For sequential processing, use loops; for parallel, use a single FIX with `SET CALCPARALLEL` | Essbase can parallelize within a single FIX but not across sequential FIX blocks |

# PART 3: THE FORMULA TEMPLATE

---

## 1. What is the Formula Template?

The Formula template is the most basic building block — it generates raw mathematical expressions in the compiled calc script. Any time you need to assign a value to a member, you use a Formula.

### Where to Find It
- **Graphical Designer:** New Objects palette → drag **Formula** onto the canvas
- **Script Mode:** Type the formula directly (e.g., `"Tax" = "Revenue" * 0.25;`)

---

## 2. Formula Properties Dialog — Every Field

| Property | Description | Options / Values | Default |
|----------|-------------|------------------|---------|
| **Formula Name** | Display label on canvas | Free text (e.g., `Calc_Tax`) | `Formula1` |
| **Target Member** | The member receiving the calculated value (left side of `=`) | Member selector or type member name | (empty) |
| **Formula Expression** | The mathematical expression (right side of `=`) | Free text — any valid Essbase expression | (empty) |
| **Formula Type** | How the formula is structured | `Simple Assignment`, `Member Formula Block`, `Multi-Line Script` | `Simple Assignment` |
| **Use Cross-Dimensional Operator** | Button to insert `->` references | Opens cross-dim builder | — |
| **Use Function** | Button to insert `@` functions | Opens function picker | — |
| **Use Variable** | Button to insert variables/RTPs | Opens variable picker | — |

---

## 3. Formula Type Deep Dive — All 3 Types

### Type 1: Simple Assignment
A single line: `Target = Expression;`

**Generated Script:**
```essbase
"Tax" = "Revenue" * 0.25;
```

**Properties:**
| Field | Description |
|-------|-------------|
| Target Member | Single member (e.g., `"Tax"`) |
| Expression | Any math expression (e.g., `"Revenue" * 0.25`) |

### Type 2: Member Formula Block
Wraps the formula inside a member block syntax — required when using IF/ELSE within a formula.

**Generated Script:**
```essbase
"Tax"(
    IF("Revenue" > 0)
        "Tax" = "Revenue" * 0.25;
    ELSE
        "Tax" = 0;
    ENDIF
)
```

**Properties:**
| Field | Description |
|-------|-------------|
| Target Member | The member that owns the formula block |
| Block Content | Multi-line expression area — can contain IF/ELSE, multiple assignments |

> **Architect Note:** The `"Member"( ... )` syntax is called a **Member Block**. It tells Essbase: "For every occurrence of this member in the current scope, execute the logic inside the parentheses." This is fundamentally different from a bare `"Tax" = ...;` assignment because it changes the calculation context to be anchored on that member.

### Type 3: Multi-Line Script
A free-text area where you can type multiple lines of raw Essbase script.

**Generated Script:** Exactly what you type.

**Use Case:** Complex formulas with multiple intermediate calculations:
```essbase
"Gross_Revenue" = "Units" * "Price";
"Net_Revenue" = "Gross_Revenue" - "Discounts" - "Returns";
"Tax" = "Net_Revenue" * 0.25;
"Net_Income" = "Net_Revenue" - "Tax" - "Operating_Expenses";
```

---

## 4. Cross-Dimensional Operator (`->`) in Formulas

The `->` operator lets you pull values from different dimension intersections.

### Syntax
```essbase
"Target" = "Source_Member" -> "Other_Dim_Member";
```

### Cross-Dim Builder Dialog
When you click **"Use Cross-Dimensional Operator"**:

| Field | Description |
|-------|-------------|
| Source Member | The data member (e.g., `"Revenue"`) |
| Cross-Dim Dimension | Which dimension to cross into |
| Cross-Dim Member | The specific member in that dimension (e.g., `"Prior_Year"`) |
| Add Another | Button to chain multiple `->` references |

### Chaining Multiple Cross-Dims
```essbase
"Variance" = "Revenue" -> "Actual" -> "FY24" - "Revenue" -> "Budget" -> "FY24";
```

> **⚠️ Performance Warning:** Every `->` operator forces Essbase to look up a different block. A formula with 5 cross-dim references is 5x more expensive than a formula without any. Always FIX on the dimensions you're crossing into instead of using `->` when possible.

---

## 5. Using `@` Functions in Formulas

The Function picker provides access to all Essbase calculation functions:

### Most Common Functions Used in Formulas

| Category | Function | Example |
|----------|----------|---------|
| Math | `@SUM` | `"Total" = @SUM("Product", @CHILDREN("All_Products"));` |
| Math | `@AVG` | `"Avg_Price" = @AVG("Price", @CHILDREN("All_Regions"));` |
| Math | `@ROUND` | `"Rounded" = @ROUND("Tax", 2);` |
| Math | `@ABS` | `"Positive" = @ABS("Variance");` |
| Hierarchy | `@PARENTVAL` | `"Parent_Rev" = @PARENTVAL("Account", "Revenue");` |
| Time | `@PRIOR` | `"Prior_Month" = @PRIOR("Revenue", 1);` |
| Time | `@NEXT` | `"Next_Month" = @NEXT("Revenue", 1);` |
| Cross-Cube | `@XREF` | `"Rate" = @XREF("FX_Cube", "USD_Rate");` |
| Allocation | `@ALLOCATE` | (complex — use the Allocation System Template instead) |

---

## 6. Formula Best Practices

| # | Best Practice | Why |
|---|--------------|-----|
| 1 | Always end every formula with a semicolon `;` | Missing semicolons cause cryptic syntax errors |
| 2 | Protect all divisions: `IF(denom <> 0 AND denom <> #Missing)` | #Missing division returns garbage data or errors |
| 3 | Use the Member Block syntax `"Member"( ... )` for conditional formulas | Ensures the calculation context is properly anchored |
| 4 | Minimize cross-dimensional references (`->`) | Each `->` is an additional block lookup — use FIX to pre-scope instead |
| 5 | Order formulas from dependent to independent | If B depends on A, calculate A first. Essbase processes top-to-bottom |
| 6 | Use `@ROUND` at the end of complex math chains | Prevents floating-point rounding errors from accumulating |
| 7 | Place formulas INSIDE the tightest possible FIX | Reduces the number of blocks Essbase opens and processes |

## 7. Complete Examples — Combining All Three Templates

### Example 1: Monthly Revenue Allocation by Department
```
Flow: Begin → Loop(Departments) → Condition(Has Revenue?) → Formula(Allocate) → End
```

**Generated Script:**
```essbase
SET UPDATECALC OFF;
SET CREATEBLOCKONEQ ON;

/* Loop over all departments */
FIX("Dept_A", "Budget", "Working", "FY24")
    /* Condition: Check if Revenue exists */
    "Allocated_Cost"(
        IF("Revenue" <> #Missing AND "Revenue" > 0)
            "Allocated_Cost" = "Total_Overhead" * ("Revenue" / "Revenue" -> "Total_Departments");
        ELSE
            "Allocated_Cost" = 0;
        ENDIF
    )
ENDFIX
FIX("Dept_B", "Budget", "Working", "FY24")
    "Allocated_Cost"(
        IF("Revenue" <> #Missing AND "Revenue" > 0)
            "Allocated_Cost" = "Total_Overhead" * ("Revenue" / "Revenue" -> "Total_Departments");
        ELSE
            "Allocated_Cost" = 0;
        ENDIF
    )
ENDFIX
/* ... repeated for each department */
```

### Example 2: Tax Calculation with Tiered Rates by Entity Type
```
Flow: Begin → FIX(Budget) → Condition(US Entity?) → [True: Formula(21%)] → [False: Condition(EU Entity?)] → [True: Formula(25%)] → [False: Formula(30%)] → End
```

**Generated Script:**
```essbase
FIX("Budget", "Working", "FY24", @RELATIVE("Total_Entity", 0))
    "Tax"(
        IF(@ISUDA("US_Entity"))
            "Tax" = "Pre_Tax_Income" * 0.21;
        ELSEIF(@ISUDA("EU_Entity"))
            "Tax" = "Pre_Tax_Income" * 0.25;
        ELSE
            "Tax" = "Pre_Tax_Income" * 0.30;
        ENDIF
    )
ENDFIX
```

## Interview Questions

### Intermediate
**Q: In the graphical designer, what is the difference between dragging a Condition inside a Loop vs. placing a Condition after a Loop?**
> A: Inside the Loop, the Condition is evaluated once per iteration (per member). After the Loop, it evaluates once for the entire rule. Placing it inside means each department can have different logic; placing it after means the condition applies globally to the output of all loop iterations combined.

### Architect
**Q: A developer has a rule with 3 nested IF statements inside a FIX on 50,000 entities. The rule takes 45 minutes. How do you optimize it to under 5 minutes?**
> A: Replace nested IF statements with additional FIX constraints. Each IF evaluates at cell-level (slow). FIX evaluates at block-level (fast). For example, replace `IF(@ISMBR("US"))` with `FIX("US")`. Replace `IF(@ISACCTYPE("Revenue"))` with `FIX(@RELATIVE("Revenue_Parent", 0))`. This converts 3 layers of cell-level evaluation into 3 layers of block-level scoping, often achieving 10x–20x speedups.

### Trick Question
**Q: Can you place a Loop inside a Condition's True branch in the graphical designer?**
> A: Yes. This is valid and generates a FIX block wrapped inside an IF block. However, this is architecturally questionable because the IF (cell-level) runs first and then the FIX (block-level) runs inside it, which inverts the normal optimization pattern. It is almost always better to put the Condition (IF) inside the Loop (FIX), not the other way around.

---

## Summary

| Template | What It Generates | When to Use | Performance Impact |
|----------|-------------------|-------------|-------------------|
| **Condition** | `IF/ELSEIF/ELSE/ENDIF` | Different logic based on member/value/variable | Cell-level — slowest |
| **Loop** | Sequential `FIX/ENDFIX` blocks | Iterate over member lists with per-member logic | Block-level — medium |
| **Formula** | `"Target" = Expression;` | Any mathematical calculation | Depends on scope |

The golden rule: **Use FIX (Loop/Member Range) to reduce scope, then use Condition (IF) only for logic that cannot be expressed as a FIX constraint.**
