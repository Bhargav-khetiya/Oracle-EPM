## 🏢 Overview

**Calculation Manager** is the graphical design environment in Oracle EPBCS where you create, manage, validate, deploy, and launch business rules, rule sets, and templates. It replaces the old Hyperion Business Rules editor and provides a visual drag-and-drop interface alongside a script editor.

---

## 📌 Accessing Calculation Manager

```
Home → Navigator → Calculation Manager
OR
Home → Tools → Calculation Manager (in some versions)
```

## 📌 Key Components

### 1. Rules

A **Rule** is the fundamental calculation unit. It contains one or more components that execute in sequence.

| Rule Type | Description |
|-----------|-------------|
| **Plan Type Rule** | Associated with a specific cube (FinPlan, Manpower, Capital) |
| **Shared Rule** | Can be used across multiple cubes |
| **Template** | Reusable calculation component |

### 2. Components Within a Rule

Each rule can contain these component types arranged in a flow:

| Component | Icon | Purpose |
|-----------|------|---------|
| **Script** | 📝 | Raw Essbase calc script or Groovy code |
| **Member Range** | 🎯 | Graphical FIX statement — select members without code |
| **Condition** | ❓ | IF/ELSE logic — graphical branching |
| **Loop** | 🔄 | Iterate through member lists |
| **Data Map** | 🔀 | Smart Push — move data between cubes |
| **Formula** | ƒ | Graphical formula builder |
| **Comment** | 💬 | Add documentation within the rule flow |

### 3. Rule Sets

A **Rule Set** groups multiple rules that execute together.

```
Rule Set: "Monthly Close"
├── Run Sequentially:
│   ├── Rule: "01_Clear_Prior_Calcs"
│   ├── Rule: "02_Copy_Actuals"
│   ├── Rule: "03_Calculate_Revenue"
│   └── Rule: "04_Aggregate_Entity"
└── Properties:
    ├── Stop on Error: Yes
    └── Share Runtime Prompts: Yes
```

### Execution Modes

| **Conditional** | Rules run based on conditions | Different logic per scenario |

### 💡 Logic & Purpose
Rule Sets exist because administrators need to chain calculations together (e.g., Clear Data → Copy Actuals → Calculate Drivers → Aggregate). Execution modes determine how the server CPU handles this chain. "Sequential" runs them safely one by one. "Parallel" attempts to run them at the exact same time on different CPU threads to cut down execution time by 80%.

### 🌀 Confusion Resolution
> **Misconception:** "My Rule Set takes 10 minutes to run sequentially. If I just switch it to 'Parallel' mode, it will finish in 2 minutes."
> **Reality:** You cannot blindly switch a Rule Set to Parallel! If Rule 2 (Calculate Revenue) relies on the data copied by Rule 1 (Copy Actuals), running them in Parallel will cause Rule 2 to calculate based on *empty* or *old* data because Rule 1 hasn't finished yet. Parallel mode can ONLY be used for completely independent calculations (e.g., Calculating the NA region and the EMEA region simultaneously).

### 😈 Twisted Interview Question
**Question:** A developer places two rules into a Parallel Rule Set: `Rule A` (Calculates Expenses) and `Rule B` (Calculates Revenue). Both rules use `SET UPDATECALC OFF;` and execute a full `CALC ALL;` on the database. When the user launches the Rule Set, the system crashes and throws an Essbase error. Why?
> **Answer:** Block Locking contention! Both rules are trying to lock and calculate the exact same physical data blocks simultaneously on different threads. Essbase protects data integrity by locking blocks during write operations. If two parallel threads try to write to the same block, one will fail or the system will deadlock. Parallel rules must act on completely distinct slices of data (using strict `FIX` statements).

## 📌 Working with Variables

### Types of Variables

| Variable Type | Scope | Example |
|--------------|-------|---------|
| **Substitution Variable** | Application-wide | `&CurrentMonth`, `&BudgetYear` |
| **Runtime Prompt (RTP)** | User provides at execution | Entity selection, growth rate |
| **Global Variable** | Across all applications | Shared configuration values |

### Creating Runtime Prompts

1. In Calc Manager → Right-click **Variables** → **New Variable**
2. Set properties:

| Property | Options |
|----------|---------|
| **Name** | `RTP_Entity` |
| **Type** | Member |
| **Dimension** | Entity |
| **Default Value** | E10001 |
| **Required** | Yes |
| **Allow Multi-Select** | Yes/No |
| **Choice List** | Show only Level 0 |

## 📌 Templates

Templates are reusable calculation components. They allow you to create a calculation once and use it across multiple rules.

### Creating a Template

```
Template: "Standard_Allocation"
├── Input Variables:
│   ├── SourceMember (Account)
│   ├── TargetLevel (Number)
│   └── AllocationBasis (Account)
├── Logic:
│   FIX(@RELATIVE("Entity", {TargetLevel}))
│       {SourceMember} = {SourceMember}->"All Entities" * 
│           {AllocationBasis} / {AllocationBasis}->"All Entities";
│   ENDFIX
└── Output: Allocated values at target level
```

### Using a Template in a Rule

1. Drag template into rule designer
2. Map template variables to actual members
3. Template expands into full calc script on deployment

## 📌 Workflow: Create → Validate → Deploy → Launch

### Step 1: Create the Rule
1. Right-click cube → **New Rule**
2. Name it with a consistent convention: `XX_Action_Target` (e.g., `01_Calculate_Revenue`)
3. Add components using the designer or script editor
4. Save frequently

### Step 2: Validate
- Click **Validate** (checkmark icon)
- Checks: member names, syntax, dimension references
- ⚠️ Validation does NOT run the rule — it only checks syntax

### Step 3: Deploy
- Click **Deploy** (rocket icon)
- Makes the rule available in the Planning web interface
- Deploys to the specific cube (FinPlan, Manpower, etc.)
- ⚠️ Undeployed rules cannot be launched from forms or task lists

### Step 4: Launch
- From Planning: **Tools → Business Rules → Select Rule → Launch**
- Or: Attach to a form (runs on save or button click)
- Or: Include in a task list
- Or: Schedule via EPM Automate / Job Console

## 📌 Attaching Rules to Forms

### Methods to Attach

| Method | When It Runs |
|--------|-------------|
| **Run on Save** | Every time user clicks Save on the form |
| **Run on Load** | Every time the form opens |
| **Business Rule Button** | When user clicks a specific button |
| **Right-click Menu** | When user right-clicks → Run Rule |

### Configuration Steps

1. **Navigate:** Home → Forms → Select Form → Edit
2. **Business Rules tab** → Add Rule
3. Set execution trigger (Save, Load, or both)
4. Map any runtime prompts to form dimensions

## ⭐ Best Practices

| Practice | Reason |
|----------|--------|
| Name rules with numbering prefix | `01_`, `02_` keeps execution order clear |
| Use descriptions | Every rule should explain WHAT and WHY |
| Create templates for repeated logic | DRY principle — Don't Repeat Yourself |
| Version your rules | Before major changes, copy the rule as backup |
| Test in DEV first | Never test new rules in Production |
| Log rule duration | Use SET MSG DETAIL for performance tracking |
| Group related rules in Rule Sets | Easier management and scheduling |

## ⚠️ Common Errors

| Error | Cause | Fix |
|-------|-------|-----|
| "Member not found" | Typo or member removed from outline | Check member name in dimension |
| "Rule not deployed" | Forgot to deploy after changes | Click Deploy in Calc Manager |
| "Cannot run — no permission" | User lacks role | Grant Calc Manager access in provisioning |
| Rule runs but no data changes | Wrong FIX scope or missing CREATEBLOCKONEQ | Add SET CREATEBLOCKONEQ ON |
| "Rule set failed" | One rule in the set errored | Check individual rule logs |

## 🎓 Interview Questions

**Q: What is Calculation Manager and why do we need it?**
> A: Calc Manager is the IDE for creating business rules in EPBCS. It provides a visual designer, script editor, validation, deployment, and version management. Without it, you'd be writing raw Essbase scripts with no UI.

**Q: What is the difference between Validate, Deploy, and Launch?**
> A: Validate checks syntax (no execution). Deploy makes the rule available in Planning (no execution). Launch actually RUNS the rule against data.

**Q: What is a Template and when would you use one?**
> A: A Template is a reusable calculation component with input variables. Use it when you have the same calculation logic applied to different members — e.g., allocation logic that runs for 20 different cost centers.

**Q: How do you attach a business rule to a form?**
> A: Edit the form → Business Rules tab → Add the rule → Choose trigger (On Save, On Load, or Button). Map any runtime prompts to form dimensions.
