## Introduction

# SECTION 1: RULE ENTRY POINT — `Rule` and `Operation`

Every Groovy rule starts with access to the `operation` object, which is the entry point to the entire API.

---

## 1.1 `operation` Object

| Property / Method | Returns | Description |
|-------------------|---------|-------------|
| `operation.application` | `Application` | Access to the application object |
| `operation.grid` | `DataGrid` | Access to the form grid that triggered the rule (only available in form-context rules) |
| `operation.user` | `User` | The currently logged-in user |
| `operation.planType` | `String` | The plan type (cube) name |
| `operation.cube` | `Cube` | The cube object |
| `operation.getSubstitutionVariable("name")` | `String` | Value of a substitution variable |
| `operation.setSubstitutionVariable("name", "value")` | `void` | Set a substitution variable value |

---

## 1.2 `Application` Object

| Method | Returns | Description |
|--------|---------|-------------|
| `application.getCube(name)` | `Cube` | Get a specific cube by name |
| `application.getCubes()` | `List<Cube>` | All cubes in the application |

---

## 1.3 `User` Object

# SECTION 2: DATA GRID — `DataGrid` and `DataCell`

The DataGrid is the form grid object. It is the primary interface for reading data the user has on screen, validating edits, and throwing errors.

---

## 2.1 `DataGrid` Object (from `operation.grid`)

| Method | Returns | Description |
|--------|---------|-------------|
| `grid.getCellIterator()` | `Iterator<DataCell>` | Iterate through ALL cells on the form |
| `grid.dataCellIterator()` | `Iterator<DataCell>` | Same — iterate all data cells |
| `grid.dataCellIterator(String... filters)` | `Iterator<DataCell>` | Iterate cells matching specific members |
| `grid.getDataCell(rowIndex, colIndex)` | `DataCell` | Get a specific cell by row/column index |
| `grid.getPov()` | `Map<String, String>` | Get the form's Point of View as a dimension→member map |
| `grid.getPage()` | `Map<String, String>` | Get the Page selections |
| `grid.getSmartPush()` | `SmartPush` | Access Smart Push configuration for the form |
| `grid.getRows()` | `List` | Row member details |
| `grid.getColumns()` | `List` | Column member details |
| `grid.isCellEdited()` | `boolean` | Whether any cell on the grid was modified |

### Filtering dataCellIterator:
```groovy
// Iterate only cells where Account = "Revenue"
grid.dataCellIterator("Revenue").each { DataCell cell ->
    println "Revenue value: ${cell.data}"
}

// Iterate cells where Account = "Revenue" AND Period = "Jan"
grid.dataCellIterator("Revenue", "Jan").each { DataCell cell ->
    println "Jan Revenue: ${cell.data}"
}
```

# SECTION 3: DATA GRID DEFINITION BUILDER — Programmatic Data Access

When you need to read/write data outside of the form context (e.g., read from a different cube, write to a different intersection), use `DataGridDefinitionBuilder`.

---

## 3.1 `DataGridDefinitionBuilder`

| Method | Returns | Description |
|--------|---------|-------------|
| `new DataGridDefinitionBuilder()` | `Builder` | Create a new builder |
| `.addPov(String... members)` | `Builder` | Set POV members |
| `.addRow(String dimension, String... members)` | `Builder` | Add row dimension and members |
| `.addColumn(String dimension, String... members)` | `Builder` | Add column dimension and members |
| `.setSuppressMissing(boolean)` | `Builder` | Suppress #Missing cells |
| `.build()` | `DataGridDefinition` | Build the definition |

### Complete Example: Read Data
```groovy
// Build a grid definition to read Revenue for Jan-Mar
DataGridDefinitionBuilder builder = new DataGridDefinitionBuilder()
builder.addPov("Budget", "Working", "FY24", "Entity_US")
builder.addRow("Account", "Revenue", "COGS")
builder.addColumn("Period", "Jan", "Feb", "Mar")
builder.setSuppressMissing(false)
DataGridDefinition dgDef = builder.build()

// Execute the query
Cube cube = operation.application.getCube("Plan1")
DataGrid dg = cube.loadGrid(dgDef, false)  // false = don't lock

// Read values
dg.dataCellIterator().each { DataCell cell ->
    println "${cell.getAccountName()} / ${cell.getPeriodName()} = ${cell.data}"
}
```

### Complete Example: Write Data
```groovy
DataGridDefinitionBuilder builder = new DataGridDefinitionBuilder()
builder.addPov("Forecast", "Working", "FY24", "Entity_US")
builder.addRow("Account", "Tax")
builder.addColumn("Period", "Jan", "Feb", "Mar")
DataGridDefinition dgDef = builder.build()

Cube cube = operation.application.getCube("Plan1")
DataGrid dg = cube.loadGrid(dgDef, true)  // true = lock for writing

dg.dataCellIterator().each { DataCell cell ->
    // Calculate Tax = 25% of Revenue (you'd read Revenue separately)
    cell.setCellValue(1000 * 0.25)  // Example
}

cube.saveGrid(dg)  // Save to Essbase
```

# SECTION 4: CALCULATION LAUNCHING

---

## 4.1 Launching Essbase Calc Scripts from Groovy

```groovy
// Method 1: Execute a pre-built business rule
operation.application.getRule("Rule_Name").execute()

// Method 2: Execute a dynamic calc script string
String script = """
SET UPDATECALC OFF;
FIX("Budget", "Working", "FY24", "${entity}")
    "Tax" = "Revenue" * 0.25;
ENDFIX
"""
Cube cube = operation.application.getCube("Plan1")
cube.executeCalcScript(script)
```

### Dynamic Script Generation Pattern (Most Powerful Use of Groovy):
```groovy
// Read the entity from the form's POV
String entity = operation.grid.getPov().get("Entity")
String year = operation.grid.getPov().get("Year")

// Build a hyper-targeted calc script
String calcScript = """
SET UPDATECALC OFF;
SET MSG SUMMARY;
FIX("Budget", "Working", "${year}", "${entity}")
    "Tax" = "Revenue" * 0.25;
    "Benefits" = "Salary" * 0.30;
    "Total_Compensation" = "Salary" + "Benefits";
ENDFIX
"""

// Execute
operation.application.getCube("Plan1").executeCalcScript(calcScript)

println "Calculation completed for ${entity} / ${year}"
```

# SECTION 8: VALIDATION & ERROR HANDLING

---

## 8.1 Stopping a Save with Custom Error

```groovy
// Veto (cancel) the save operation with an error message
operation.grid.dataCellIterator().each { DataCell cell ->
    if (cell.isEdited() && cell.data < 0) {
        cell.addValidationError(0xFF0000, "Negative values not allowed!")
        throwVetoException("Save cancelled: Negative values detected.")
    }
}
```

## 8.2 Try/Catch Error Handling

```groovy
try {
    Cube cube = operation.application.getCube("NonExistentCube")
    cube.executeCalcScript("CALC ALL;")
} catch (Exception e) {
    println "ERROR: ${e.message}"
    throwVetoException("Calculation failed: ${e.message}")
}
```

## 8.3 Logging

# SECTION 9: COMMON GROOVY PATTERNS — PRODUCTION READY

---

## Pattern 1: Validate Before Save (No Negatives)
```groovy
boolean hasErrors = false
operation.grid.dataCellIterator().each { DataCell cell ->
    if (cell.isEdited() && !cell.isReadOnly()) {
        if (cell.data < 0 && cell.getAccountName() == "Revenue") {
            cell.addValidationError(0xFF0000, "Revenue cannot be negative")
            hasErrors = true
        }
    }
}
if (hasErrors) {
    throwVetoException("Validation failed: Please correct highlighted cells.")
}
```

## Pattern 2: Dynamic Calc Script Generation
```groovy
String entity = operation.grid.getPov().get("Entity")
String scenario = operation.grid.getPov().get("Scenario")
String year = operation.grid.getPov().get("Year")

String script = """
SET UPDATECALC OFF;
SET CALCPARALLEL 4;
FIX("${scenario}", "Working", "${year}", "${entity}")
    "Tax" = "Revenue" * 0.25;
    "Net_Income" = "Revenue" - "COGS" - "OpEx" - "Tax";
ENDFIX
"""
operation.application.getCube("Plan1").executeCalcScript(script)
```

## Pattern 3: Cross-Cube Data Copy via DataGrid
```groovy
// Read from Workforce cube
DataGridDefinitionBuilder readBuilder = new DataGridDefinitionBuilder()
readBuilder.addPov("Budget", "Working", "FY24", "Entity_US")
readBuilder.addRow("Account", "WFP_Headcount")
readBuilder.addColumn("Period", "Jan", "Feb", "Mar")
DataGrid sourceGrid = operation.application.getCube("OEP_WFP").loadGrid(readBuilder.build(), false)

// Write to Finance cube
DataGridDefinitionBuilder writeBuilder = new DataGridDefinitionBuilder()
writeBuilder.addPov("Budget", "Working", "FY24", "Entity_US")
writeBuilder.addRow("Account", "FS_Headcount")
writeBuilder.addColumn("Period", "Jan", "Feb", "Mar")
DataGrid targetGrid = operation.application.getCube("OEP_FS").loadGrid(writeBuilder.build(), true)

// Copy values
def sourceValues = []
sourceGrid.dataCellIterator().each { sourceValues.add(it.data) }

int i = 0
targetGrid.dataCellIterator().each { DataCell cell ->
    if (i < sourceValues.size()) cell.setCellValue(sourceValues[i++])
}

operation.application.getCube("OEP_FS").saveGrid(targetGrid)
```

## Pattern 4: Conditional Cell Formatting
```groovy
operation.grid.dataCellIterator("Variance_Pct").each { DataCell cell ->
    if (!cell.isMissing()) {
        if (cell.data < -10) {
            cell.addValidationError(0xFF0000, "Critical: >10% unfavorable variance")
        } else if (cell.data < 0) {
            cell.addValidationError(0xFFA500, "Warning: Unfavorable variance")
        } else if (cell.data > 20) {
            cell.addValidationError(0x00FF00, "Exceptional: >20% favorable")
        }
    }
}
```


## Interview Questions

### Intermediate
**Q: What is the difference between `cell.data` and `cell.isEdited()` in a Groovy Save Data rule?**
> A: `cell.data` returns the current value of the cell (whether it was edited or not). `cell.isEdited()` returns TRUE only if the user changed that specific cell in the current save operation. This is critical for validation — you should only validate edited cells, not all cells on the form.

### Architect
**Q: A Groovy rule reads 200,000 cells from a DataGrid to apply a 10% increase and crashes with "Exceeded Memory Limit". How do you fix it?**
> A: Groovy runs in the web server JVM with ~50MB memory limit per rule. Loading 200K cells into a DataGrid object overwhelms memory. The fix: (1) Don't use Groovy for bulk calculations. (2) Use Groovy to generate a dynamic Essbase calc script (`"Revenue" = "Revenue" * 1.10;`) and pass it to `cube.executeCalcScript(script)`. Essbase handles bulk math in its own optimized engine without JVM memory constraints.
