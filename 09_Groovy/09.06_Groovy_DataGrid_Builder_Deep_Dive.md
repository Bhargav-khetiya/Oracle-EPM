# Groovy DataGridBuilder Deep Dive

The `DataGridBuilder` in Oracle EPM Groovy is arguably the most powerful API object available. It allows you to programmatically read, manipulate, and save data directly into the Essbase cube *without* using a calc script. This circumvents many Essbase calculation limitations.

## 1. Anatomy of a DataGrid

A DataGrid is essentially an in-memory representation of a web form or a Smart View retrieve. It consists of:
*   **POV (Point of View):** Dimensions that remain constant for the entire grid.
*   **Columns:** Dimensions that span the top of the grid (usually Time/Scenario).
*   **Rows:** Dimensions that go down the side (usually Account/Entity).

## 2. Reading Data: DataGridDefinitionBuilder

Before you can build a grid to *save* data, you often need to build a grid to *read* data.

### Deep Dive: Fetching Specific Data Intersections
```groovy
// 1. Create a definition builder
DataGridDefinitionBuilder builder = cube.dataGridDefinitionBuilder()

// 2. Define the axis
builder.addPov(['OEP_Working', 'USD', 'BaseData'])
builder.addColumn(['FY23', 'FY24'])
builder.addRow(['Account1', 'Account2'], ['Entity1', 'Entity2'])

// 3. Build and load the grid
DataGridDefinition definition = builder.build()
DataGrid grid = cube.loadGrid(definition, false) // false = don't include cell text/formatting to save memory
```

**Performance Trap:** Loading a massive grid into memory will crash the Groovy JVM (usually hitting the 50MB memory limit). Always make your `addRow` or `addColumn` scope as tight as possible. Do not query `@DESCENDANTS("Total_Entity")` if there are 10,000 entities.

## 3. Writing Data: DataGridBuilder

Once you have calculated data in Groovy (e.g., pulling exchange rates from an external REST API and multiplying them in Groovy arrays), you need to save it back.

### Deep Dive: The Save Pattern
```groovy
// 1. Initialize the builder
DataGridBuilder saveBuilder = cube.dataGridBuilder('MM/DD/YYYY')

// 2. Set the static POV
saveBuilder.addPov('OEP_Working', 'USD', 'BaseData', 'FY24', 'Jan')

// 3. Add column headers
saveBuilder.addColumn('Amount') 

// 4. Loop through your data and add rows
myCalculatedMap.each { entity, calcAmount ->
    // Add row headers (Entity) and the data values
    saveBuilder.addRow([entity], [calcAmount])
}

// 5. Build and Save
DataGrid saveGrid = saveBuilder.build()
cube.saveGrid(saveGrid)
```

### Notable Behaviors & Error Handling
*   **Read-Only Cells:** If you try to save data to a dynamic calc member, a parent member, or an intersection blocked by Valid Intersections/Security, the `saveGrid()` will throw a `VetoException`. 
*   **Status Check:** Always check the status of the save grid after execution:
    ```groovy
    cube.saveGrid(saveGrid)
    println "Successfully saved ${saveGrid.size()} cells."
    ```
*   **Batching:** If you are saving more than 50,000 cells, do not put them in a single DataGrid. Loop and `saveGrid()` in batches of 10,000 - 20,000 to prevent timeout errors.

## 4. Iterating Through an Existing Grid

Often, you want to trigger a Groovy rule from a Data Form, read the edited cells, and do something with them.

```groovy
// Iterate over only the cells the user edited on the form
operation.grid.dataCellIterator({DataCell cell -> cell.isEdited()}).each { DataCell cell ->
    String account = cell.getMemberName("Account")
    double val = cell.data
    
    // Custom validation logic
    if (account == "Salary" && val > 1000000) {
        cell.addValidationError(0xFF0000, "Salary cannot exceed 1M per month.")
        veto("Validation failed. Please review highlighted cells.")
    }
}
```
*   **The Power of `veto()`:** This instantly stops the save process on the form and returns a red error message to the user, preventing bad data from entering the cube. This is vastly superior to traditional Essbase calc script validation.
