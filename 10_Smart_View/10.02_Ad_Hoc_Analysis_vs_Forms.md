# 10.02 Ad-Hoc Analysis vs Forms

> **Module:** 10_Smart_View  
> **Topic:** 02 - Ad-Hoc Analysis  
> **Target Audience:** End User to Consultant  

---

## 1. Learning Objectives
- Differentiate between a structured Form and an Ad-Hoc Grid.
- Master the `Zoom In`, `Keep Only`, and `Pivot` functions.
- Understand the physical impact of a massive Ad-Hoc retrieve on the Essbase server.

## 3. Introduction
Web Forms (and Smart View Forms) are built by the IT department. They are rigid. If a user says, "I need to see Travel Expense by Cost Center, but I also want to cross-join it with Product and Vendor," the IT department might say, "We don't have a form for that." 
The user doesn't need IT. The user needs **Ad-Hoc Analysis**.

## 7. Core Concepts: The Freedom of Ad-Hoc

An Ad-Hoc Grid is a blank Excel canvas directly connected to the Essbase cube.

### How it Works
1. The user connects to the Cube via the Smart View panel.
2. They click "Ad-Hoc Analysis".
3. A default grid appears (usually with the top-level dimensions like `Year` and `Measures`).
4. **The Magic:** The user can type member names directly into the Excel cells (e.g., type `Jan` in cell C1, type `Travel` in cell A2) and click **Refresh**. Essbase instantly fetches that specific intersection.

### Core Navigation Buttons
- **Zoom In:** Double-click a parent (e.g., `Q1`) to instantly retrieve its children (`Jan`, `Feb`, `Mar`).
- **Keep Only:** Select a column, click Keep Only, and all other columns disappear from the query.
- **Pivot:** Move a dimension from the Row to the Column, or up into the POV header.

## 18. Architect Notes: The Danger of Ad-Hoc

Ad-Hoc gives end-users the power of a database administrator. This is dangerous.

- **The Cartesian Explosion:** A user puts `Total Product` (10,000 members) on the Rows. They Pivot `Total Cost Center` (500 members) to the Columns. They click Zoom In -> Bottom Level on both.
- **The Result:** They just asked the Essbase server to generate and send an XML file containing 5,000,000 cells. 
- **The Crash:** The Essbase server spikes to 100% CPU to calculate the data. Microsoft Excel hits its 2GB memory limit trying to render 5 million cells and crashes completely. 

### The Architect's Defense
You must protect the server from untrained users.
1. **Max Rows Limit:** In the EPM Cloud settings, the Administrator must set the "Maximum number of rows for Smart View" to a reasonable limit (e.g., 50,000). If a user requests 5 million rows, the server rejects the request immediately, saving the system from crashing.
2. **ASO vs BSO:** Train power users to perform massive Ad-Hoc queries ONLY against the ASO Reporting cube, never the BSO Planning cube.

## 25. Interview Questions

### Intermediate
**Q: A user types "Travel_Expense" into a cell in an Ad-Hoc grid and clicks Refresh. An error pops up saying "Member not found", but they swear the account exists. What happened?**
> A: The member name likely has a different spelling or an alias. By default, Smart View might be set to recognize "Member Names" (e.g., `60001_Travel`) but the user typed the "Alias" (`Travel_Expense`). The user must either go to Smart View Options and change the Member Name Display to "Alias", or use the Member Selection dialog box to pick the exact string Essbase expects.

### Architect
**Q: How do you prevent users from submitting bad data via Ad-Hoc?**
> A: While you can't physically stop them from building an Ad-Hoc grid, you can use **Valid Intersections** to lock down the intersections. Additionally, you should heavily restrict `Write` access in the Security groups so that users can only submit data to their specific Cost Center, and configure the Form-level logic to be the primary method of data entry, discouraging Ad-Hoc submission.

## 27. Summary
Ad-Hoc Analysis is the reason Finance departments love Essbase. Teach them how to Pivot and Zoom, but strictly enforce row limits to prevent them from accidentally taking down the server.
