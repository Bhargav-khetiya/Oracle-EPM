# EPM Integration Agent Setup (On-Premise SQL to Cloud)

The EPM Integration Agent is a lightweight Java program installed on an on-premise server. It solves the massive security problem of how a Cloud SaaS application (EPM) can pull data from an on-premise Oracle or SQL Server database without the company having to open inbound firewall ports.

## 1. How the Agent Works (The Polling Mechanism)

1.  **Installation:** The IT department installs the `.jar` agent on an internal server that has JDBC access to the internal SQL database.
2.  **No Inbound Ports:** The IT department does *not* need to allow EPM Cloud to talk to their server.
3.  **Outbound Polling:** The Agent wakes up every few minutes and makes an *outbound* HTTPS request to EPM Cloud asking, "Do you have any jobs for me?"
4.  **Execution:** If EPM Cloud says "Yes, run Data Load Rule X", the Agent executes the SQL query against the internal database, writes the results to a CSV file locally, and uploads that CSV securely over HTTPS to the EPM Cloud Inbox. EPM Cloud then loads the file normally.

## 2. Setting Up the Agent

### Step 1: Download and Configure
*   Download the Agent ZIP file from the Data Integration UI.
*   Edit the `agentparams.ini` file. You must provide the EPM Cloud URL, an encrypted EPM admin password, and the specific folder paths for local processing.

### Step 2: Configure the Database Connection
*   In the EPM Cloud UI (Data Integration -> Actions -> Agent), define the SQL connection (e.g., `jdbc:oracle:thin:@internaldb:1521:PROD`).
*   The Agent must have the specific JDBC driver `.jar` file (e.g., `ojdbc8.jar` or `mssql-jdbc.jar`) placed in its `lib` folder.

### Step 3: Write the SQL Query
*   When creating the Source system in Data Integration, you actually paste the SQL `SELECT` statement into the cloud UI. 
*   *Trap:* The column headers in your `SELECT` statement (e.g., `SELECT ACCOUNT as ACCOUNT, AMOUNT as AMOUNT`) must exactly match the expected dimensions in the Target application.

### Step 4: Run the Agent
*   Start the agent using the provided `.bat` or `.sh` script. It will run continuously in a command prompt (or as a Windows Service). If the agent goes down, all SQL integrations will fail with a timeout error in the cloud.
