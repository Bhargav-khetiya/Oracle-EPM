## 1. Learning Objectives
- Differentiate between Identity Domain roles and Application roles.
- Understand how to secure specific slices of data in Essbase.
- Architect a security model using Groups.

## 3. Introduction
EPM data is highly sensitive. The application contains the exact salaries of every employee and the unreleased revenue forecasts for the entire corporation. If you give a Junior Financial Analyst access to the CEO's compensation data, you have caused a major corporate incident. Security in EPM is multi-layered and absolute.

## 7. Core Concepts: The Four Identity Domain Roles

Before a user even touches the EPBCS Application, they must be assigned a role in the Identity Domain (IDCS / OCI IAM). 

### 1. Service Administrator
- **The God Role.** Can do everything. Create cubes, delete data, run data maps, clear the database.
- *Architect Rule:* Only 2-3 people in the company should have this role in Production.

### 2. Power User
- **The Department Head.** Can create forms, design reports, and manage data for their specific slice of the business. Cannot delete the cube or change the physical outline.

### 3. User
- **The Data Entry Clerk.** Can open forms and enter data into the intersections they are granted access to. Cannot create forms or rules.

### 4. Viewer
- **The Executive.** Can only view reports and forms (Read Only). Cannot save data.

## 9. Internal Processing: Access Control (Data Security)
Giving someone the "User" role just gets them into the building. It doesn't tell them which rooms they can enter. You must configure **Access Control**.

- You assign security on dimensions. Usually, this is done on the **Entity** dimension.
- **Example:** User JSMITH is granted `Write` access to the member `Cost Center 100`. 
- When JSMITH opens a form, if the form is pointing to Cost Center 100, they can type data. If they try to change the POV to Cost Center 200, the form will throw an error or display `#NoAccess`.

## 13. Configuration: Groups vs Users (The Golden Rule)
Never, ever assign security to a specific user. 
- **The Bad Way:** Assigning `Write` access to Cost Center 100 directly to `JSMITH`. When JSMITH quits, you have to manually find every security assignment linked to his name and remove it, then add the new guy `BJOHNSON`. 
- **The Good Way (Groups):** Create a Group called `Grp_CC100_Planners`. Assign `Write` access to the Group. Add `JSMITH` to the Group. When he quits, simply remove him from the Group and add `BJOHNSON`. 

## 16. Real Client Scenarios: The "All Data" Conflict
Security conflicts occur when a user is in multiple groups.
- Group A has `Read` access to `North America`.
- Group B has `Write` access to `North America`.
- If a user is in both groups, the **highest level of access wins**. The user will have `Write` access. 

## 25. Interview Questions

### Intermediate
**Q: A user with the "Service Administrator" role logs in and complains they cannot see the Salary account data on a form; it says #NoAccess. You check the security on the Account dimension and see that no groups have been assigned access to the Salary account. Why can't the Admin see it?**
> A: Service Administrators bypass all standard data access security. However, if a dimension has the **"Apply Security"** property checked, the Admin still needs to explicitly grant themselves (or the Admin group) access to those members. Otherwise, the system enforces the default security (which is No Access) even against Admins to protect highly sensitive data like compensation.

### Architect
**Q: How do you implement a security model where a manager can see all Cost Centers rolling up to "Total Finance", but they cannot see the "Exec_Bonus" account within those cost centers?**
> A: EPM Cloud security evaluates the intersection of all secured dimensions. You must check "Apply Security" on BOTH the Entity dimension and the Account dimension. 
> 1. Grant the manager `Read` access to `Total Finance (Descendants)` in the Entity dimension.
> 2. Grant the manager `None` (No Access) to the `Exec_Bonus` member in the Account dimension. 
> When the manager queries the intersection of Finance and Exec_Bonus, Essbase combines the security and restricts the cell.

## 27. Summary
Security is not an afterthought; it must be designed into the architecture from Day 1. Always use Groups, restrict Service Admin access, and secure data at the intersection level.
