# Valid Intersections Exhaustive Guide

Valid Intersections are a global EPM Cloud feature designed to prevent users from entering data or running calculations on combinations of dimension members that do not make business sense. 

*They do not delete data or blocks; they merely lock the cells in the UI (Forms, Smart View) and restrict Calculation Manager runtime prompts.*

## 1. Core Mechanics

A Valid Intersection rule consists of an "Anchor" dimension and one or more "Non-Anchor" dimensions.

*   **Anchor Dimension:** The primary driver (usually Entity or Department).
*   **Non-Anchor Dimensions:** The dimensions being restricted (usually Account, Product, or Project).

### Example Scenario
*   *Anchor:* `Entity: IT Department`
*   *Non-Anchor:* `Account: Software Expenses` (Valid), `Account: Manufacturing Expenses` (Invalid)

When a user opens a form for the IT Department, the "Manufacturing Expenses" row will be completely grayed out (read-only), even if the user has full Security write access to the Manufacturing Expenses account.

## 2. Unselected Members (The Global Trap)

The most critical and often misunderstood setting in Valid Intersections is **"Unselected Members are Valid"** vs. **"Unselected Members are Invalid"**.

*   **Unselected Members are Valid:** If you create a rule anchoring "IT Department", what happens to the "HR Department" (which you didn't select in the rule)? The HR Department ignores this rule completely. All accounts remain valid for HR.
*   **Unselected Members are Invalid:** What happens to HR now? Because it wasn't explicitly mapped in the rule, *every single account* becomes invalid for HR.
    *   *Trap:* Changing this setting without realizing its global impact is the #1 cause of users suddenly reporting that their entire application became read-only.

## 3. Impact on Forms and Smart View

*   **Forms:** By default, forms will still display invalid intersections (grayed out). Form designers should check the **"Suppress Invalid Data"** option in the form layout. This completely hides the rows/columns that are invalid, drastically improving the user experience and form loading time.
*   **Smart View:** Users will see gray cells. If they try to submit data to them, Smart View will throw a Veto error.

## 4. Impact on Calculation Manager

Valid Intersections apply to Runtime Prompts (RTPs). 
*   If a rule asks a user to select an Entity and an Account, the system will prevent them from selecting `IT Department` and `Manufacturing Expenses` in the prompt window. 
*   However, Valid Intersections **do not** stop backend calculation scripts. If your calc script explicitly says `FIX("IT Department") "Manufacturing Expenses" = 100; ENDFIX`, Essbase *will* calculate it and write the data, bypassing the Valid Intersection UI block. Valid Intersections are UI filters, not database-level security.
