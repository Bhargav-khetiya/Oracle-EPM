# REST API Integration

Oracle EPM Cloud provides a comprehensive REST API. In fact, EPM Automate, Smart View, and the web interface itself all use the REST API under the hood.

## 1. Authentication Options

To call an EPM REST endpoint, you must authenticate.
*   **Basic Authentication:** Passing a base64 encoded string of `domain.user:password` in the header. This is the simplest method but least secure.
*   **OAuth 2.0 (OAUTH):** The modern, secure standard. You configure a confidential application in IDCS (Identity Cloud Service) to generate a client ID and secret. You use these to request a bearer token, which is then passed in the header of your REST calls. This prevents passing raw credentials.

## 2. Asynchronous Job Execution

A critical concept in the EPM REST API is that almost all long-running actions (rules, data loads, cube refreshes) are **asynchronous**.

### The API Flow:
1.  **POST Request:** You send a `POST` request to start a Business Rule (passing RTPs in the JSON body).
2.  **Immediate Response (202 Accepted):** The server does *not* wait for the rule to finish. It immediately returns a `202 Accepted` status along with a `jobId` and a `status URL`.
3.  **Polling:** Your custom integration script must enter a loop, sending a `GET` request to the `status URL` every few seconds to check the status.
4.  **Final Response:** Eventually, the status URL returns `status: 0` (Success) or `status: 1` (Error).

*This differs from EPM Automate, which automatically handles the polling loop for you and just waits to give you the final success/failure.*

## 3. Key Use Cases for REST over EPM Automate

While EPM Automate is easier for simple batch scripts, the REST API is required for:
*   **Webhooks & Callbacks:** Triggering an EPM rule from an external cloud service (e.g., Salesforce, Workday) when an event occurs.
*   **Granular Data Extraction:** The REST API can execute MDX queries or data slice queries and return the results directly as JSON, rather than having to export a CSV file and parse it.
*   **Custom UIs:** Building a completely custom web portal that interacts with EPM data.
