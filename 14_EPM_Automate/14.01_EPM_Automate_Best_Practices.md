# EPM Automate Best Practices

EPM Automate is a command-line utility used by administrators to schedule and orchestrate tasks in Oracle EPM Cloud. It acts as a wrapper around the REST API.

## 1. Core Commands

*   `login`: Authenticates the session. Always use encrypted password files (`.epw`) rather than clear text passwords in scripts.
*   `runBusinessRule`: Executes a calculation script. You can pass runtime prompts (RTPs) as parameters.
*   `runDataRule`: Executes a Data Integration load rule.
*   `exportSnapshot` / `downloadFile`: The critical sequence for daily backups. You export the environment to a snapshot, then download it to a local secure server.
*   `uploadFile` / `importSnapshot`: The inverse, used for migrating applications.
*   `clearCube`: Wipes specific data regions.

## 2. Batch Scripting Best Practices (Windows/Linux)

EPM Automate is usually called from within a Windows Batch (`.bat`) or Linux bash script.

### Error Handling (The Return Code)
Every EPM Automate command returns a status code (0 = Success, non-zero = Failure). You *must* check the `%ERRORLEVEL%` in Windows (or `$?` in Linux) after every command.

```bat
epmautomate runBusinessRule "Nightly_Aggr"
IF %ERRORLEVEL% NEQ 0 (
    echo "Aggregation failed! Aborting."
    epmautomate logout
    exit /b %ERRORLEVEL%
)
```
If you do not check the error level, your script will blindly proceed. For example, if a metadata import fails but the script continues and runs a database refresh, it could corrupt the cube.

### Logging
Always redirect the output of your batch script to a log file (`>> nightly_log.txt`). Include timestamps using standard OS commands so you can debug when a specific command failed.

## 3. Limits and Constraints

*   **Concurrency:** You can run multiple EPM Automate sessions concurrently, but do not run conflicting jobs (e.g., trying to run a Database Refresh while a Data Load is running).
*   **Timeouts:** EPM Automate will wait for the server to finish the job. If a business rule takes 4 hours, the EPM Automate window will remain open and wait for the HTTP response. If network connectivity drops during those 4 hours, the job will continue on the Oracle server, but your local script will fail with a connection timeout.
*   **Updates:** EPM Automate requires periodic upgrades. If your utility version falls too far behind the Cloud environment version, commands will begin to fail.
