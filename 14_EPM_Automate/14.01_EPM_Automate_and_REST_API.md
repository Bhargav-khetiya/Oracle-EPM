## 1. Learning Objectives

## 3. Introduction
An EPM system that requires a human to log in every morning at 6:00 AM, click "Run Data Load", wait 10 minutes, click "Run Business Rule", and wait 5 minutes is a broken system. You must automate the routine maintenance and data integration pipelines.

## 7. Core Concepts: EPM Automate
EPM Automate is a command-line utility provided by Oracle. 
- You install it on a local Windows or Linux server.
- You write batch scripts (`.bat` or `.sh`) calling EPM Automate commands.
- You schedule the batch scripts using Windows Task Scheduler, Control-M, or AutoSys.

### Basic Workflow
Every script follows the exact same 3-step paradigm:
1. `epmautomate login`
2. `epmautomate [do something]`
3. `epmautomate logout`

## 14. Examples: The Daily Snapshot Backup Script
As covered in the Architecture module, Oracle only keeps one daily backup (Artifact Snapshot). An architect must write a script to download it every day.

```bat
REM Login to the Cloud Pod using an encrypted password file
epmautomate login ServiceAdmin EPM_Prod_URL my_encrypted_password.epw

REM Rename the snapshot so it has today's date (e.g., Backup_20241028)
epmautomate copySnapshotFromInstance "Artifact Snapshot" "Backup_%date%"

REM Download the renamed file to the local server
epmautomate downloadfile "Backup_%date%"

REM Clean up the cloud storage to prevent running out of space
epmautomate deletefile "Backup_%date%"

REM Logout
epmautomate logout
```

## 8. Architecture Overview: EPM Automate vs REST API
EPM Automate is extremely powerful, but it is a "wrapper" created by Oracle around their own REST API. 

**EPM Automate:**
- Easy to use. Just type a command.
- Requires installing a utility on a local machine.
- Limited to the specific commands Oracle has programmed into the utility.

**REST API:**
- Hard to use. Requires programming (Python, Groovy, or cURL) to construct HTTP JSON payloads.
- Does *not* require local installation. Any system on earth that can send an HTTPS request can talk to EPM Cloud.
- Extremely flexible. You can query detailed job statuses or extract specific metadata properties that EPM Automate cannot reach.

## 18. Architect Notes: Integration Pipelines
Do not just string commands together blindly. A good automation script has error handling.
If the `epmautomate runDataRule` command fails (e.g., the source ERP system was down and no file was generated), the script MUST catch the error code, terminate immediately, and send an email alert to the IT team. If it doesn't catch the error, it will blindly proceed to run the Business Rules on empty data, potentially wiping out the forecast.

## 25. Interview Questions

### Intermediate
**Q: You write a script containing the command `epmautomate login JSMITH Password123`. A security auditor flags your script as a critical vulnerability. Why?**
> A: You hardcoded a plaintext password into a batch file. Anyone with access to the server can read the file and gain Service Administrator access to the EPM Cloud environment. You must use the `epmautomate encrypt` command to generate an `.epw` encrypted password file and reference the file in the script.

### Architect
**Q: A client uses an enterprise scheduling tool (like Control-M) to trigger their EPM jobs. Their corporate security policy strictly forbids installing the EPM Automate executable on the Control-M server. How do you automate the data loads?**
> A: I would bypass EPM Automate entirely and use the **REST API**. Control-M natively supports triggering REST API calls via HTTPS. I would configure Control-M to send a `POST` request with the JSON payload to the EPM Cloud Data Integration endpoint to trigger the data load rule, utilizing OAuth 2.0 or Basic Auth for security.

## 27. Summary
An architect builds systems that run themselves. Master EPM Automate for file manipulation and routine jobs, and master the REST API for enterprise orchestration.
