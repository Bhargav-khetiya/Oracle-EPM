# 14.01 Jobs: Types and Scheduling

> **Module:** 14_Administration  
> **Topic:** 01 - Jobs and Automation UI  
> **Target Audience:** Consultant  

---

## 1. Learning Objectives
- Identify the types of Jobs available in EPBCS.
- Schedule recurring backend processes.
- Monitor the Job Console for system failures.

## 3. Introduction
EPM is a batch-processing engine. While users run Business Rules on-demand via web forms, the heavy lifting (copying a budget version, importing 5 million rows from ERP, restructuring the database) must happen in the background. The central command center for this is the **Jobs** console.

## 7. Core Concepts: Job Types

When you go to Navigator -> Jobs -> Schedule, you can automate almost anything.

1. **Rules:** Run a Business Rule or Rule Set (e.g., `Calculate_Global_Depreciation`).
2. **Data Map / Smart Push:** Synchronize data between BSO and ASO in bulk (e.g., `Push_Financials_to_Reporting`).
3. **Import Data / Export Data:** Move flat files in and out of the cube.
4. **Import Metadata:** Update the dimension tree (e.g., add new cost centers from a file).
5. **Clear Cube:** Wipe out a specific slice of data (e.g., clear the `Working` version before starting the new budget cycle).
6. **Restructure Cube:** Force Essbase to defragment the index and page files to restore performance.

## 9. Internal Processing: The Job Console

The Job Console is the heartbeat monitor of the application. 
- It tracks the status of every single job (Completed, Processing, Error).
- **The Log File:** This is critical. If a rule fails, the Job Console provides a hyperlink to a text file. Clicking it reveals the raw Essbase engine error (e.g., `Error: Division by zero at block [Cost Center 100]`).

## 13. Configuration: Scheduling

You can schedule a job directly in the web UI.
1. Click **Schedule**.
2. Select the Job Type (e.g., Rule).
3. Select the specific rule.
4. Define the **Runtime Prompts (RTPs)**. *Architect Note:* A scheduled job has no human to answer pop-up questions. You must hardcode the RTPs (e.g., `Entity = Total Geography`) into the job definition.
5. Set the cadence (e.g., Daily at 2:00 AM).

## 18. Architect Notes: EPM Automate vs UI Scheduling

While scheduling via the Web UI is easy, Enterprise Architects rarely use it for critical pipelines.
- **The Limitation of UI Scheduling:** The web UI cannot easily sequence complex, conditional dependencies. You cannot say: "Run the ERP Data Load. If it fails, email the CFO and stop. If it succeeds, run the Business Rule. If the rule succeeds, run the Data Map."
- **The Architect Standard:** Architects use **EPM Automate** or **REST APIs** orchestrated by a dedicated enterprise scheduler (like Control-M, AutoSys, or Windows Task Scheduler) to build resilient, error-handling pipelines. The Web UI scheduler is mostly used for simple, internal tasks like daily cube restructures.

## 25. Interview Questions

### Intermediate
**Q: An admin schedules a Business Rule to run nightly at 3:00 AM. In the morning, they check the Job Console and see the job failed instantly with the error: "Missing required prompts." What was configured incorrectly?**
> A: The Business Rule contains Runtime Prompts (RTPs) that do not have default values. Because a scheduled job runs unattended in the background, there is no user interface for the system to ask for the prompt. The admin must edit the Job definition and physically hardcode the answers to the RTPs in the job settings.

### Architect
**Q: A client schedules a massive "Clear Cube" job for 2:00 AM, and an "Import Data" job for 2:05 AM. On Monday, the data is loaded perfectly. On Tuesday, the cube is completely empty when users log in. What architectural flaw caused this?**
> A: The architect relied on time-based guessing rather than sequential dependency. On Tuesday, the "Clear Cube" job might have taken 10 minutes to run instead of 4 minutes. Because the jobs were merely scheduled by time, the "Import Data" job started at 2:05 AM and finished at 2:08 AM, loading the data. Then, the "Clear Cube" job finally finished at 2:10 AM, instantly wiping out the data that was just loaded. Jobs must be chained sequentially (using EPM Automate or REST API) so that Job B only starts after Job A returns a success code.

## 27. Summary
The Job Console tells you what the engine is doing. Check it daily. Move complex scheduling out of the UI and into EPM Automate to build resilient pipelines.
