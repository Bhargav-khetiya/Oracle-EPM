# LCM (Lifecycle Management) Migration Best Practices

Lifecycle Management (LCM) is the Oracle EPM framework for migrating applications, dimensions, forms, rules, and data between environments (e.g., from Test to Production). 

## 1. The Snapshot Architecture

*   An LCM "Snapshot" is essentially a `.zip` file containing thousands of XML files (representing forms/rules), CSV files (representing dimension members), and TXT files (representing data).
*   **Export:** Extracts current artifacts to a Snapshot folder.
*   **Download:** Pulls the Snapshot from the Cloud server to your local machine (using EPM Automate `downloadfile`).
*   **Upload:** Pushes a local Snapshot to a target Cloud environment.
*   **Import:** Overwrites the target environment's artifacts with the contents of the Snapshot.

## 2. Full vs. Incremental Migrations

### Full Migration (The "Lift and Shift")
*   You export *everything* in the application. 
*   **Use Case:** Initial go-live, or performing a massive environment clone.
*   **Risk:** It overwrites the target completely. If users were entering data in Prod, a full migration from Test will wipe out their prod data and replace it with test data unless you explicitly exclude the `Data` artifact.

### Incremental Migration
*   You selectively export only the pieces that changed (e.g., 3 new Forms, 1 updated Business Rule).
*   **Use Case:** Daily/Weekly code deployments.
*   **Best Practice:** Always maintain a manual log (or Jira ticket) of exactly which artifacts a developer touched. LCM does not have a "git diff" to automatically show you what changed.

## 3. The "Missing Dependency" Trap

The #1 cause of failed LCM imports is missing dependencies. 

*   **Scenario:** You built a new Form (`Form_A`) that uses a new Smart List (`SL_Priority`). You export `Form_A` in an incremental snapshot and import it to Prod.
*   **Result:** The import fails with "Object Not Found". 
*   **Why:** LCM does *not* automatically package dependencies. You must manually select both `Form_A` and `SL_Priority` in your export. This applies heavily to Action Menus, Navigation Flows, and composite Forms.

## 4. Renaming Artifacts

**Warning:** Do not rename an artifact (like a Form or Business Rule) and expect LCM to handle it gracefully. 

If you rename `Form_Old` to `Form_New` in Test and migrate it to Prod:
1. Prod will receive `Form_New`.
2. Prod will **keep** `Form_Old`. LCM is an "upsert" (update/insert) process. It does not delete artifacts in the target environment that are missing from the source snapshot. You must manually delete the old form in Prod to keep the environment clean.
