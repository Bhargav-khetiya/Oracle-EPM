# 14.02 Daily Maintenance and Audit

> **Module:** 14_Administration  
> **Topic:** 02 - Maintenance, AMW, and Auditing  
> **Target Audience:** Architect  

---

## 1. Learning Objectives
- Master the Automated Maintenance Window (AMW).
- Configure the Audit log to track user activity.
- Understand how to restore the environment from a catastrophic failure.

## 3. Introduction
EPM systems do not break slowly; they break instantly. A user accidentally deletes a dense dimension member, or a bad Groovy script creates a block explosion that consumes 100% of the server RAM. When the CFO calls you in a panic, you need two things: The Audit log (to find out who did it) and the Maintenance Snapshot (to fix it).

## 7. Core Concepts: The AMW (Automated Maintenance Window)

Every day, Oracle takes your application offline for exactly 1 hour. This is the AMW.
During this hour, Oracle performs backend database compaction, restarts WebLogic services, and most importantly, takes a full backup of the environment.

### The Artifact Snapshot
- This is the holy grail. It contains the data, the metadata, the forms, the rules, and the security as it existed at the exact moment the AMW started.
- **The Physical Limit:** Oracle only keeps **ONE** snapshot. Tonight's snapshot overwrites last night's snapshot. 
- **The Architect's Duty:** You MUST write an EPM Automate script to download this snapshot every single day and store it on a local company server or an AWS S3 bucket. If you do not do this, and a user corrupts the system on Friday, but you don't notice until Monday, Oracle cannot help you. The clean Friday backup was overwritten by the corrupt Saturday and Sunday backups.

## 9. Internal Processing: Auditing

If a form is deleted, or a million dollars goes missing from a budget, the Admin will be blamed. To prove what happened, you must enable **Auditing**.

### Configuration
1. Go to Tools -> Audit.
2. By default, Oracle does *not* audit everything because it causes database bloat.
3. **What to Enable:**
   - **Data (Crucial):** Tracks every single number typed into a form. Shows the Old Value, the New Value, the User, and the Timestamp.
   - **Metadata:** Tracks who added or deleted members from the dimensions.
   - **Security:** Tracks who added users to groups.
   - **Form Design:** Tracks who changed a web form layout.

### The Performance Cost
Tracking every single data change is heavy. If you load 5 million rows of data from the ERP nightly, and Data Auditing is turned on, the system will try to write 5 million audit logs simultaneously, doubling the load time and crashing the table. 
- **Best Practice:** Only enable Data Auditing on highly sensitive manual entry scenarios, or aggressively purge the Audit log (via EPM Automate `clearAudit`) every 30 days to prevent the application repository from exceeding its size limits.

## 16. Real Client Scenarios: The Metadata Disaster
A junior admin logs in, goes to the Account dimension, and accidentally deletes the `Total Revenue` parent member. They click "Refresh Database". 
Because Essbase drops the data for any member that is deleted, all revenue data for the entire history of the company is instantly wiped from the hard drive. 

**The Recovery Plan:**
1. Do not panic.
2. Check the Audit log to confirm who deleted the member and exactly when it happened.
3. Locate yesterday's downloaded **Artifact Snapshot** zip file.
4. Go to Tools -> Migration.
5. Upload the Snapshot.
6. Select *only* the Account dimension and the Essbase Data to import.
7. Click Import. The system restores the member and the data to the state it was in yesterday at 2:00 AM. 
*(Any data entered by users today between 2:00 AM and the crash is permanently lost).*

## 25. Interview Questions

### Intermediate
**Q: A user claims they typed $50,000 into the Travel budget yesterday, but today the cell says $10,000. How do you investigate this?**
> A: You navigate to Tools -> Audit. Assuming Data Auditing is enabled, you filter the audit log by the specific intersection (`Cost Center` -> `Travel`). The log will display a chronological history of that cell, showing that User A entered $50,000 at 9:00 AM, but User B (or a scheduled Business Rule) overwrote it with $10,000 at 4:00 PM.

### Architect
**Q: The application runs perfectly for a year. Suddenly, nightly data loads go from taking 10 minutes to taking 3 hours. The Essbase cube size is normal. What administrative setting likely caused this repository bloat?**
> A: The most common cause is an unmanaged Audit Log. If Data Auditing and Task Auditing are enabled but never cleared, the relational repository database (which handles the web UI and staging tables) fills up with millions of log rows. Querying the staging tables for a data load requires scanning past millions of audit records, severely degrading performance. The Architect must implement an EPM Automate script to run the `clearAudit` command periodically (e.g., retaining only 90 days of logs) to keep the repository optimized.

## 27. Summary
Paranoia is the hallmark of a great EPM Architect. Audit everything users do, and download your backups daily.
