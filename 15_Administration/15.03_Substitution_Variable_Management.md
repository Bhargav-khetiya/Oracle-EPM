# 15.03 — Substitution Variable Management: Complete Guide

> **Module:** 15_Administration | **Topic:** SubVars, User Variables, Runtime Prompts
> **Audience:** Service Administrator

---

## 1. WHY — What Real-World Problem Does This Solve?

**The problem:** A business rule has `FIX("Jan")` hardcoded. Every month, someone must edit the rule, change "Jan" to "Feb", validate, deploy. 12 months × 50 rules = 600 manual edits per year. One typo = broken month-end close.

**The solution:** Substitution Variables replace hardcoded member names with dynamic placeholders. Change the variable once → all 50 rules automatically use the new value.

---

## 2. ALL THREE VARIABLE TYPES

| Type | Symbol | Managed By | Scope | Used In |
|------|--------|-----------|-------|---------|
| **Substitution Variable** | `&VarName` | Service Admin | All users | Rules + Forms |
| **User Variable** | `#VarName` | Each user individually | Per user | Forms only |
| **Runtime Prompt (RTP)** | `{RTP_Name}` | User at runtime | Per execution | Rules only |

## 3. SUBSTITUTION VARIABLES — DETAILED

### Creating SubVars

```
Navigator → Administration → Variables → Substitution Variables

Name          │ Value    │ Plan Type    │ Description
──────────────┼──────────┼──────────────┼─────────────────────────
CurrMonth     │ Sep      │ ALL          │ Current reporting month
PriorMonth    │ Aug      │ ALL          │ Previous month
CurrYear      │ FY2026   │ ALL          │ Current fiscal year
PriorYear     │ FY2025   │ ALL          │ Previous fiscal year
ForecastStart │ Oct      │ OEP_FS       │ First open forecast month
BudgetYear    │ FY2027   │ OEP_FS       │ Active budget year
CurrQtr       │ Q3       │ ALL          │ Current quarter
```

### Using in Business Rules

```essbase
/* Instead of hardcoded months: */
FIX("Sep")  /* ❌ Must edit every month */
  "Total" = "A" + "B";
ENDFIX

/* Use substitution variable: */
FIX(&CurrMonth)  /* ✅ Admin updates variable once */
  "Total" = "A" + "B";
ENDFIX

/* Multiple SubVars */
FIX(&CurrMonth, &CurrYear, "Budget", "Working")
  FIX(@RELATIVE("All_Hotels", 0))
    "Net_Income" = "Total_Revenue" - "Total_Expenses";
  ENDFIX
ENDFIX
```

### Using on Forms

```
Form Designer → Rows/Columns/Page/POV:
  
  POV: Scenario, Version
  Page: Entity (User Variable)
  Columns: &CurrYear (Substitution Variable)
  
  Column member selection: &CurrYear
  → Automatically shows data for FY2026
  → When admin changes &CurrYear to FY2027, form updates

  Column with SubVar range:
  @RANGE("Period", &ForecastStart, "Dec")
  → Shows Oct, Nov, Dec (open forecast months)
  → Next month: admin changes &ForecastStart to "Nov"
  → Form shows Nov, Dec (only open months)
```

### Updating via EPM Automate

```bash
# Update single variable
epmautomate setsubstvars "ALL" "CurrMonth=Oct"

# Update multiple variables at once
epmautomate setsubstvars "ALL" "CurrMonth=Oct" "PriorMonth=Sep" "ForecastStart=Nov"

# Update for specific cube only
epmautomate setsubstvars "OEP_FS" "BudgetYear=FY2028"
```

## 4. USER VARIABLES — DETAILED

### What They Are

User Variables let each user set their own default member for a dimension. On forms, User Variables filter the data to the user's preferred context.

### Creating User Variables

```
Navigator → Administration → Variables → User Variables

Name          │ Dimension │ Default Value  │ Description
──────────────┼───────────┼────────────────┼──────────────────
UserEntity    │ Entity    │ All_Hotels     │ User's default hotel
UserDepartment│ Department│ All_Departments│ User's default dept
UserCurrency  │ Currency  │ Local          │ User's preferred currency
```

### How Users Set Their Variable

```
User: Ramesh (Mumbai planner)
  Navigator → Preferences → Variables
  UserEntity: [Mumbai_Hotel ▾]

User: Priya (Delhi planner)
  Navigator → Preferences → Variables
  UserEntity: [Delhi_Hotel ▾]

Form: Revenue_Entry
  Page axis: Entity = #UserEntity
  
  Ramesh opens form → sees Mumbai data
  Priya opens form → sees Delhi data
  Same form, different data!
```

## 5. RUNTIME PROMPTS — DETAILED

### Creating RTPs in Calc Manager

```
Calc Manager → Variables → New Variable

Name: RTP_Scenario
Type: Member
Dimension: Scenario
Default: Budget
Prompt: "Select Scenario:"

Name: RTP_Year
Type: Member
Dimension: Year
Default: &CurrYear (can reference SubVar!)
Prompt: "Select Year:"

Name: RTP_GrowthRate
Type: Numeric
Default: 5
Prompt: "Enter Growth Rate (%):"
```

### Using RTPs in Rules

```essbase
/* Rule uses RTPs to make it dynamic */
FIX({RTP_Scenario}, "Working", {RTP_Year})
  FIX(@RELATIVE("All_Hotels", 0))
    "Total_Revenue" = "Total_Revenue" * (1 + {RTP_GrowthRate} / 100);
  ENDFIX
ENDFIX

/* When user launches the rule, they see: */
┌── Runtime Prompts ──────────────────────────┐
│                                              │
│  Select Scenario: [Budget ▾]                │
│  Select Year:     [FY2026 ▾]                │
│  Enter Growth Rate (%): [5____]             │
│                                              │
│  [Run]  [Cancel]                            │
└──────────────────────────────────────────────┘
```

## 6. SHOW ME — Hotel Pvt Ltd Variable Strategy

```
Substitution Variables:
  &CurrMonth     = Sep        (updated monthly by admin)
  &PriorMonth    = Aug
  &CurrYear      = FY2026
  &PriorYear     = FY2025
  &ForecastStart = Oct        (first open forecast month)
  &BudgetYear    = FY2027
  &CurrQtr       = Q3

User Variables:
  #UserEntity    = per user (Mumbai_Hotel, Delhi_Hotel, etc.)
  #UserDept      = per user (Front_Office, Kitchen, etc.)

Runtime Prompts:
  {RTP_Scenario} = user selects at rule launch
  {RTP_Year}     = user selects (default: &CurrYear)
  {RTP_Entity}   = user selects or auto from form context

Monthly Update Script (EPM Automate):
  #!/bin/bash
  # Run on 1st of each month
  MONTH="Oct"
  PRIOR="Sep"
  FCAST="Nov"
  
  epmautomate login admin@hotelpvtltd.com pass.epw $URL $DOMAIN
  epmautomate setsubstvars "ALL" \
    "CurrMonth=${MONTH}" \
    "PriorMonth=${PRIOR}" \
    "ForecastStart=${FCAST}"
  epmautomate logout
```

## 7. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Forgetting to update SubVar monthly | Rules process wrong month | Automate with EPM Automate script |
| Hardcoding months in rules | Must edit rules every month | Replace with &CurrMonth |
| User Variable not set by new user | Form shows All_Hotels (too much data) | Set default and train users |
| RTP default = hardcoded member | Fails when member changes | Default = &SubVar |
| &VarName typo in rule | Rule fails: "variable not found" | Match exact variable name |
| SubVar value doesn't match member name | Rule fails: "member not found" | Value must be exact member name |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: What is a Substitution Variable and why use one?**
> A Substitution Variable is a named placeholder (prefixed with &) that holds a member name. Instead of hardcoding `FIX("Sep")` in 50 rules, you write `FIX(&CurrMonth)` and set `&CurrMonth = Sep`. When October arrives, the admin changes the variable once, and all 50 rules automatically process October data. It eliminates manual rule editing and prevents typos. Updated via: UI (Navigator → Variables) or CLI (`epmautomate setsubstvars`).

### Architect
**Q: Design the complete variable strategy for Hotel Pvt Ltd.**
> **SubVars (7):** CurrMonth, PriorMonth, CurrYear, PriorYear, ForecastStart, BudgetYear, CurrQtr — all set to ALL cubes. Automated monthly update via EPM Automate script scheduled on the 1st at 8 AM. **User Variables (2):** UserEntity (per user → filters forms to their hotel), UserDept (per user → optional department filter). Defaults set during user onboarding. **RTPs (3):** RTP_Scenario (member selector, default=Budget), RTP_Year (member selector, default=&CurrYear), RTP_GrowthRate (numeric, default=5). Used in manual rules like Budget Seed and Copy Version. Key principle: SubVars for system-wide time context, User Variables for per-user data filtering, RTPs for per-execution user input.
