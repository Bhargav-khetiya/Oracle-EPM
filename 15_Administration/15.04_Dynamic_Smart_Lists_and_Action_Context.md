# Dynamic Smart Lists and Action Context

This ultra-deep dive covers the intersection of Smart Lists, Action Menus, and runtime context passing.

## 1. Dynamic Smart Lists (The Metadata Trick)

Standard Smart Lists require you to type out IDs and Labels manually (1=High, 2=Medium). This is a maintenance nightmare if the list changes frequently.

*   **The Hack:** You can build a Smart List dynamically from a Dimension.
*   **How:** In the Smart List properties, select **"Create from members"** and pick a dimension (e.g., `Projects`).
*   **Result:** Every time you add a new member to the `Projects` dimension and refresh the database, EPM automatically adds that member as a dropdown option in the Smart List.
*   **The ID Generation:** EPM automatically generates a numerical ID for the Smart List based on the internal Essbase Member ID. You do not control this number.

## 2. Action Menus: Passing Context (The POV)

When a user right-clicks a cell on a Form and selects an Action Menu item (like a Business Rule), EPM passes the "Context" of that cell to the rule's Runtime Prompts (RTPs).

### The Exact Matching Rule
For context passing to work, the RTP name in the Business Rule *must* map to the Dimension Name on the form.
*   If the user right-clicks on a cell for the `IT_Dept` (Entity dimension), and the Business Rule has an RTP named `{rtp_Entity}`, the rule will run silently for `IT_Dept`.
*   If the RTP is named `{myDepartment}`, the system will not map it. It will pop up a box and force the user to manually type in `IT_Dept`.

## 3. The Cross-Module Context Trap

Passing context gets extremely complex when using an Action Menu to jump from one Form to another Form, especially if they are in different modules (e.g., jumping from Workforce to Financials).

*   **The Problem:** Workforce has a dimension called `Job`. Financials does not have a `Job` dimension.
*   **The Error:** If you create an Action Menu on a Workforce form that opens a Financials form, EPM tries to pass the `Job` member (e.g., "Software Engineer") to the Financials form. Financials rejects it because it doesn't know what a `Job` is. The target form crashes or fails to open.
*   **The Fix:** You must use the **"Pass Page/POV"** settings carefully in the Action Menu definition, explicitly excluding dimensions that do not exist in the target cube.
