# Conditional Action Menus

In a previous section (`14.04`), we discussed passing context via Action Menus. However, what if an action shouldn't be available to everyone all the time?

## 1. The Requirement
A user opens a form containing rows for "Travel Expense" and "Capital Purchase". 
*   If they right-click "Travel Expense", they should see an Action Menu to "Run Travel Allocation".
*   If they right-click "Capital Purchase", they should see an Action Menu to "Calculate Depreciation".
*   *Crucially: They should not see both options on both rows.*

## 2. Building Conditional Menus

Action Menus support dynamic display logic based on the user's Point of View (POV).

*   **Dimension-Based Conditions:** In the Action Menu setup, you can add a condition: `Show this menu item ONLY IF the row member is a descendant of "Capital_Accounts"`.
    *   When the user right-clicks the Travel row, EPM evaluates the row. Since Travel is not a descendant of Capital, the "Calculate Depreciation" menu item is hidden entirely.

*   **Data-Based Conditions:** You can go deeper than metadata. You can show/hide menus based on the actual *data value* in the cell.
    *   *Example:* `Show this menu item ONLY IF the Cell Value > 1000000`. 
    *   If a user inputs a $2 million expense, they can right-click it and a special "Submit for Board Approval" menu item appears. If they type $50, the menu item remains hidden.

## 3. Performance Impact

Conditional Action Menus are evaluated by the Web Server (WebLogic) the exact millisecond a user right-clicks a cell.

*   **Warning:** If you build an Action Menu with 50 different items, and every single item has a complex nested IF condition checking multiple dimensions and data values, the user will right-click a cell and experience a 2-3 second delay before the menu even appears. 
*   **Best Practice:** Keep conditions simple. Rely on Dimension/Member checks rather than complex data-value checks whenever possible.
