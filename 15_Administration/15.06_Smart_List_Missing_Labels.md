# Smart List Missing Labels (The Obscure Trap)

Smart Lists map numerical IDs to text labels (e.g., `1 = High`, `2 = Medium`). But what happens when the cell has no data (`#MISSING`)?

## 1. The Missing Label Property
By default, if a cell is `#MISSING`, the Smart List dropdown will show nothing (a blank cell). 

*   **The Trap:** Users often interpret a blank cell as an error, or they think the form is broken.
*   **The Fix:** In the Smart List configuration screen, there is a specific property called **"Missing Label"**. 
*   If you type `"Unassigned"` or `"Select Priority..."` into the Missing Label property, the web form will display that text instead of a blank cell for any `#MISSING` block.

## 2. The Calculation Implication
While the form displays "Unassigned", you must remember that Essbase still sees `#MISSING`.
*   If you write a calculation script that says:
    ```essbase
    IF ("Priority_SmartList" == "Unassigned") 
       // This will FAIL. "Unassigned" is a text label, not an ID.
    ```
*   You must write:
    ```essbase
    IF ("Priority_SmartList" == #MISSING)
       // This will work.
    ```

## 3. ID 0 vs #MISSING
Never create a Smart List entry with an ID of `0`. 
*   While technically possible in some older versions, EPM struggles to differentiate between a physical `0` input and a `#MISSING` block depending on the Form properties (as discussed in `06.11`).
*   Always start your Smart List IDs at `1` or `10`.
