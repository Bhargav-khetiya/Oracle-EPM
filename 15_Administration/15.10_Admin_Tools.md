## 🏢 1. EPM Automate

**EPM Automate** is a command-line utility used by administrators to automate repeatable tasks.

If an admin has to log into the web interface every night at midnight to import a file from ERP, that's inefficient. Instead, they use EPM Automate.

### What EPM Automate Can Do:
- Automatically import/export data or metadata.
- Trigger Data Management load rules.
- Execute Business Rules (e.g., run the "Consolidate" rule at 2 AM).
- Create daily backups (Snapshots) of the entire application and download them to a local server.

*Technical Consultants write batch scripts (Windows `.bat`) or shell scripts that contain EPM Automate commands, and schedule them using Windows Task Scheduler or a tool like Control-M.*

## 💡 2. Navigation Flows

**Navigation Flows** allow you to customize the EPM web interface based on the user's role.

### Why it's useful:
- The **System Admin** sees all 50 menus, settings, and forms.
- A **Department Manager** logging in should NOT see settings. They should only see three icons: "My Tasks", "Expense Forms", and "Dashboards".

By setting up Navigation Flows, you create a simplified, focused user experience that prevents users from getting lost or clicking things they shouldn't.

## 🛠 3. Task Lists

**Task Lists** are step-by-step guides for users.

Instead of telling a user "Go find the 5 forms you need to fill out," you assign them a Task List.
1. **Task 1:** Review Prior Year Actuals (Opens a specific read-only form).
2. **Task 2:** Enter Headcount Plan (Opens the Manpower form).
3. **Task 3:** Calculate Expenses (Runs a business rule).
4. **Task 4:** Submit for Approval (Changes the status of the Approval Unit).

Users just log in, click their Task List, and follow the instructions 1 by 1.

### 💡 Logic & Purpose
Task Lists and Navigation Flows seem to do the same thing (guide users to forms), but their architectural purpose is different. Navigation Flows dictate *what* a user is allowed to click on (UI restriction). Task Lists dictate the *chronological order* in which a user must perform a business process (Workflow enforcement). You use Navigation flows to hide the 'Setup' menu; you use Task Lists to enforce that 'Salary Planning' must happen before 'Expense Planning'.

### 🌀 Confusion Resolution
> **Misconception:** "I want to prevent the Sales team from seeing the HR forms. I'll just remove the HR forms from the Sales Task List."
> **Reality:** Removing a form from a Task List does NOT secure the form! If the Sales team knows how to click the "Forms" folder, they can still open the HR forms. Task Lists are merely shortcuts, not security walls. If you want to prevent access, you MUST apply Artifact Security directly on the HR form folder, or restrict access via Navigation Flows.

### 😈 Twisted Interview Question
**Question:** A user complains that their Task List says "Complete", but the Finance Director cannot see their submitted data in the consolidated report. The admin verifies the user checked off all items on the Task List. Why is the data missing?
> **Answer:** Task Lists are fundamentally just checklist UIs. Checking a box on a Task List does NOT automatically run calculations, consolidate data, or physically push data unless that specific checkbox was explicitly linked to a Business Rule. The user likely manually checked the boxes without actually opening the forms and saving the data, or a 'Consolidate' rule was missing from the end of the list.

## 🔒 4. Security: Users, Roles, and Groups

Security in EPM is layered. You must ensure people only see what they are legally allowed to see (e.g., HR data is highly confidential).

### A. Predefined Roles (System Level Access)
Granted in the Oracle Cloud Console.
- **Service Administrator:** Full access to build and manage the system.
- **Power User:** Can create forms and rules, but can't change core system settings.
- **User:** Can enter data into forms and run reports.
- **Viewer:** Read-only access to reports and forms.

### B. Artifact Security
Who can open a specific Form, Rule, or Dashboard?
- *Example:* Only the "Finance Team" group can open the "Revenue Planning" form.

### C. Data Access (Cell-Level Security)
Who can see specific dimension members?
- *Example:* The HR Manager has "User" role, but their Data Access is restricted to `Department = HR`. If they open a form, the `IT Department` cells will show up as `#NoAccess` or just be hidden entirely.
