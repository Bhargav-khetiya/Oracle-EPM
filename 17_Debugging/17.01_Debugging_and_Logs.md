# Debugging and Logs

Troubleshooting Oracle EPM requires knowing where to look when things go wrong, as the front-end UI errors are often generic.

## 1. Calculation Script Debugging

When a calc script fails or produces the wrong numbers, you must debug it.

*   **SET MSG DETAIL:** Add this to the top of your script. It forces Essbase to write exactly which blocks it is pulling into memory, how long the calculation took, and how many blocks were updated. It is the single most important command for finding bottlenecks.
*   **The "Zero" Test:** If a cross-dim formula isn't working, try writing a hardcoded `1` to the intersection. If `1` doesn't write, the block doesn't exist, or you have a Dense/Sparse `FIX` issue. If `1` writes, but your formula doesn't, the right side of your formula is evaluating to `#MISSING`.
*   **Block Creation:** Essbase does not calculate a sparse intersection unless a block already exists there. (Top-Down calc exception applies). If you assign data to a cross-dim target and the block doesn't exist, it won't write. Use `SET CREATENONMISSINGBLK ON;` (with extreme caution, as it can explode database size) to force block creation.

## 2. Groovy Logging

Groovy rules offer infinitely better debugging than standard calc scripts.

*   **`println()`:** You can print variables, data grid sizes, and strings directly to the Job Console log.
    ```groovy
    def myVar = 100
    println "The value of myVar is: $myVar"
    ```
*   **Vetoes:** Use `veto("Error message")` to instantly stop execution and throw a custom error to the user on the screen.

## 3. Key Log Files

While EPM Cloud obscures access to raw server logs, you can still download diagnostic files.

*   **Job Console Logs:** Always the first stop for Rule, Data Load, or Metadata failures.
*   **Provide Feedback (Diagnostic Logs):** If an error throws a generic UUID (e.g., "Error: [1A2B3C]"), you must use the "Provide Feedback" utility. This packages the hidden server logs (Essbase server logs, WebLogic logs) and sends them to Oracle Support. You cannot read these specific logs yourself in the cloud; you must open a Service Request (SR) and provide the reference number.
*   **Data Integration Process Logs:** Essential for mapping failures. It will tell you exactly which source row failed to map and why.
