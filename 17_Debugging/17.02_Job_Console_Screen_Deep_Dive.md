# 17.02 Job Console Screen Deep Dive

## Navigation

## Overview
The Job Console is the flight recorder of the EPM system. Every Business Rule, Data Load, Database Refresh, and Smart Push executed by any user is logged here. 

## Every Configuration Property

### 1. The Filtering Mechanics
If you have 500 users, the Job Console will generate thousands of entries a day. You must know how to filter.
- **Job Type:** Filter by `Rules`, `Data Rule`, `Restructure Cube`, or `Clear Cube`.
- **Status:** Filter by `Completed`, `Error`, or `Processing`.
- **Architect Note:** If a user complains the system is locked, immediately filter by `Status: Processing`. This will show you exactly which massive rule or data load is currently holding the database hostage.

### 2. The Job Details Pop-Up
When you click on a specific job in the list, you get the diagnostic payload.

#### "Run Time"
- **What it is:** The exact duration.
- **Architect Note:** Monitor this over months. If a rule takes 12 seconds in January, 45 seconds in June, and 3 minutes in December, you have a cumulative data volume problem. The blocks are bloating, and you need to optimize the script or purge old data.

#### "Parameters" (Runtime Prompts)
- **What it is:** Displays exactly what the user typed into the popup box before the rule ran.
- **Architect Note:** Users lie. A user will say, "I ran the rule for New York and it crashed!" You open the Job Console, check the Parameters, and see they actually selected `"Total Company"`. This screen is your ultimate proof in a support dispute.

#### "Error Log Attachment" (The Paperclip)
- **What it is:** If a job fails, a small paperclip icon appears. Clicking it downloads the raw Essbase `.txt` log.
- **Architect Note:** For Data Management jobs, the paperclip downloads the Process Details log, which tells you exactly which row in the flat file failed the mapping validation.

### 3. Action Menu: "Cancel Job"
- **What it does:** Sends a kill signal to the Essbase engine to abort the running calculation.
- **The Danger:** Essbase is a transactional database. If a rule is halfway through calculating 10,000 blocks and you kill it, Essbase must execute a "Rollback". The Rollback deletes the 5,000 blocks it just created to return the database to a clean state. 
- **Architect Note:** The Rollback can take just as long as the calculation itself. If you kill a rule, and the job status changes to `Cancelling...`, DO NOT panic and try to restart the server. The engine is frantically cleaning up the corrupted blocks. Let it finish.

## 25. Interview Questions

### Architect
**Q: You schedule an EPM Automate script to run a critical Data Rule every night at 2:00 AM. For three days, the data hasn't loaded. You check the Job Console for the last three days at 2:00 AM, but there is absolutely no record of the job—no Success, no Error, nothing. What happened?**
> A: If the job doesn't appear in the Job Console *at all*, it means the request never reached the EPM Cloud server. The failure occurred outside of Oracle. You must check the local Windows Task Scheduler logs or the external CI/CD pipeline (e.g., Jenkins) that triggers the EPM Automate script. The local server likely lost internet connection or the EPM Automate password expired.
