## 🏢 Overview

Debugging in Oracle EPBCS involves diagnosing issues across multiple layers: **data issues** (wrong values), **calculation errors** (rules failing), **form problems** (rendering/performance), **integration failures** (data loads), and **infrastructure issues** (connectivity/performance). This guide covers systematic approaches to each.

## 🐛 Debugging Tools

### 1. Job Console

```
Navigation: Home → Tools → Job Console
```

Shows all executed jobs with status, duration, and error details.

| Column | What to Check |
|--------|--------------|
| **Status** | Completed with Errors → inspect details |
| **Duration** | Unusually long → performance issue |
| **Type** | Rules, Data Import, Metadata Import, etc. |
| **Details** | Click for full error message and log |

### 2. Activity Reports

```
Navigation: Home → Tools → Activity Reports
```

| Report | What It Shows |
|--------|--------------|
| **Form Performance** | Slow forms with load times |
| **Rule Performance** | Slow rules with execution times |
| **User Activity** | Login patterns, session counts |
| **Data Load** | Import/export times and errors |

### 3. Smart View Diagnostics

```
In Smart View: Help → Health Check
OR: Smart View → Options → Advanced → Diagnostics
```

### 4. Calc Script Logging

```
/* Add to your calc script for debugging */
SET MSG DETAIL;      /* Maximum logging */
SET NOTICE LOW;      /* Show all notice messages */

/* Or for production */
SET MSG SUMMARY;     /* Minimal logging */
```

## 📌 Common Issues & Solutions

### Data Issues

| Problem | Symptoms | Diagnosis | Solution |
|---------|----------|-----------|----------|
| **Data not showing on form** | Empty cells, #Missing | Check POV, check if data exists at that intersection | Verify data was loaded, check member selection |
| **Wrong totals** | Parent shows incorrect sum | Check consolidation operators, check Dynamic Calc | Verify +/-/~ operators on children |
| **Data disappeared** | Values were there yesterday | Check if someone ran a CLEARDATA rule | Review Job Console for rule executions |
| **Duplicate data** | Values doubled | Data loaded twice | Check data management mappings, clear and reload |
| **Actuals don't match ERP** | EPM total ≠ ERP total | Mapping mismatch in data integration | Check unmapped accounts in Data Management |

### Calculation Errors

| Error | Cause | Fix |
|-------|-------|-----|
| "Member not found in database" | Typo or deleted member | Check member name in outline, update rule |
| "Cannot lock object" | Another user/rule running | Wait or kill the other session |
| "Insufficient privileges" | User lacks calc permissions | Check role provisioning |
| "Maximum cell limit exceeded" | Grid too large | Narrow FIX scope |
| "Script completed with errors" | Syntax or logic error | Check Job Console details, enable MSG DETAIL |

### 💡 Logic & Purpose
Calculation debugging is the most complex task for an architect. The Essbase engine processes commands at a microscopic level (cell by cell). When a calculation fails, the engine is usually protecting the server from a runaway process (like an infinite loop or a 100GB block generation request). Tools like `SET MSG DETAIL` force the engine to narrate its thought process, exposing exactly which block crashed the server.

### 🌀 Confusion Resolution
> **Misconception:** "My Business Rule failed with a syntax error, so I'll just check the Job Console to see exactly which line of code is broken."
> **Reality:** The Job Console is terrible for syntax debugging! It often just says "Script completed with errors". To debug syntax, you must validate the rule inside **Calculation Manager** during design time. The Job Console is for *runtime* errors (e.g., trying to divide by zero on a specific intersection, or hitting a lock contention limit), not syntax errors.

### 😈 Twisted Interview Question
**Question:** A developer writes a Business Rule with a massive FIX statement targeting 5,000 entities. They launch the rule. The Job Console immediately (within 1 second) says "Completed successfully." However, when the developer checks the data, absolutely nothing has changed. Why did it "succeed" instantly without calculating?
> **Answer:** This is a classic "Silent Failure". The FIX statement likely resulted in an **Empty Set**. For example, the developer fixed on `FIX("Budget", "Actual")` (two members from the SAME dimension). Essbase evaluates the cross-dimensional intersection of `Budget AND Actual`, finds it mathematically impossible, evaluates to an empty block set, and instantly exits the script successfully because it technically calculated all (zero) targeted blocks perfectly.

### Form Issues

| Problem | Cause | Fix |
|---------|-------|-----|
| Form takes > 30 seconds to load | Too many cells, no suppression | Enable Suppress Missing, reduce rows/columns |
| Form shows #NoAccess | User lacks security access | Check dimension security for the user/group |
| Form shows stale data | Data changed but not refreshed | Refresh the form, check if calc rule ran |
| Validation rule blocking save | Data fails validation criteria | Check validation rule conditions |
| Business rule not running on save | Rule not attached or not deployed | Check form properties → Business Rules tab |

### Data Integration Errors

| Error | Cause | Fix |
|-------|-------|-----|
| "Target member not found" | Account in source not mapped | Add mapping in Data Management |
| "Invalid data value" | Non-numeric data in numeric field | Clean source data |
| "Load rule not found" | Rule name mismatch | Verify load rule name in Data Management |
| Data loads but doesn't appear | Loaded to wrong intersection | Check dimension mappings carefully |
| Partial load — some rows rejected | Mapping issues for specific members | Check Data Management error log |

### Smart View Issues

| Problem | Cause | Fix |
|---------|-------|-----|
| "Unable to connect" | Wrong URL, network, or session | Verify URL, check VPN, clear cache |
| "Session expired" | Idle timeout | Re-login |
| HsGetValue returns #NoData | Missing dimension in function | Ensure ALL dimensions are specified |
| Extremely slow refresh | Large grid or network latency | Reduce grid size, check network |
| Add-in not appearing in Excel | Installation issue | Repair install, check COM add-in settings |

## 🐛 Systematic Debugging Approach

### The DRILL Method

```
D — Define the problem precisely
    "Form X shows wrong revenue total for Entity E10001 in Budget FY26"

R — Reproduce the issue
    Open the exact form, select the exact POV, verify the problem exists

I — Isolate the layer
    Is it a Data issue? Calc issue? Form issue? Security issue?
    → Check same intersection in Smart View Ad-Hoc
    → If Ad-Hoc shows correct data → Form configuration problem
    → If Ad-Hoc shows wrong data → Calc or Data problem

L — Locate the root cause
    → Check Job Console for recent rule/load runs
    → Check dimension outline for member properties
    → Check data load logs for errors

L — Log and resolve
    → Document the issue, root cause, and fix
    → Update troubleshooting runbook
```

### Data Verification via Smart View

```
Step 1: Open Smart View → Ad-Hoc on the cube
Step 2: Set POV to the exact intersection reported
Step 3: Drill down to Level 0 members
Step 4: Check if individual values are correct
Step 5: Check if parent aggregation is correct
Step 6: Compare with source data (ERP/file)
```

## 🐛 Debugging Best Practices

| Practice | Reason |
|----------|--------|
| Always check Job Console first | Most recent errors are logged there |
| Use Smart View ad-hoc to verify data | Bypass form configuration to see raw data |
| Enable MSG DETAIL for debugging | See exactly what the calc script does |
| Test in DEV, never in PROD | Avoid impacting production users |
| Keep a debugging journal | Track recurring issues and solutions |
| Document all fixes | Build a team knowledge base |

## 🎓 Interview Questions

**Q: A user reports that their form shows wrong totals. How do you debug this?**
> A: (1) Reproduce the issue on the exact form/POV. (2) Open Smart View ad-hoc on the same intersection to check if data is correct at the Essbase level. (3) If ad-hoc is correct, it's a form config issue. (4) If ad-hoc is wrong, check consolidation operators, check if a calc rule was missed, verify data load mappings.

**Q: A business rule is taking 30 minutes. How do you optimize?**
> A: (1) Check the FIX scope — is it too broad? (2) Add SET MSG DETAIL to see block-by-block processing. (3) Check if CALC ALL is being used. (4) Verify SET UPDATECALC ON for incremental updates. (5) Check for unnecessary cross-dimensional references.

**Q: Data was loaded but isn't showing on the form. What do you check?**
> A: (1) Verify the POV on the form matches the loaded intersection. (2) Check if the form has Suppress Missing enabled and data is actually missing. (3) Check Data Management load log for rejected records. (4) Verify dimension mappings point to the correct members. (5) Check if a refresh cube is needed after metadata changes.
