# Common EPM Production Support Tickets

After an EPM application goes live, administrators spend significant time resolving standard user issues. Understanding these common tickets is critical for architects building sustainable systems.

## 1. "I can't see the Data / The Form is Read-Only"

This is the most common support ticket. The resolution is always a checklist:

1.  **Check Approval Status:** Is the Approval Unit for that Entity locked or promoted to the user's manager? (If yes, it's read-only).
2.  **Check Valid Intersections:** Is the specific combination of Entity/Cost Center and Account disabled globally? (If yes, the cell is greyed out).
3.  **Check Security Groups:** Did the user get removed from their IDCS group, or did someone change the Access Control on the form/dimension?
4.  **Check Dynamic Calc:** Is the user trying to type data into a Parent member or a Dynamic Calc member? Essbase only accepts input at Level 0 Stored members.

## 2. "The Numbers don't tie to the ERP"

A data discrepancy ticket.

1.  **Check the Data Load Rule:** Did the overnight Data Management job fail? Check the Job Console.
2.  **Check the Mappings:** If the job succeeded, did a new account get added in the ERP that is unmapped in EPM? (It will be stuck in the TDATASEG staging table).
3.  **Check Aggregation:** Did the data load successfully, but the overnight aggregation script failed? Level 0 data will be correct, but the Parent levels will be blank or stale.

## 3. "Smart View is Crashing / Freezing Excel"

A performance ticket usually caused by user behavior.

1.  **Suppress Missing Blocks:** Ensure the user has "Suppress Missing Blocks" checked in their Smart View options. If unchecked on a sparse form, Essbase will try to return millions of empty cells, causing Excel to run out of memory.
2.  **Zooming in on Parents:** If a user zooms in on "Total Product" (which has 50,000 children) in an Ad Hoc grid, it will crash. Train users to use the Member Selection box for large dimensions.

## 4. "My Business Rule is taking 2 Hours to run"

A performance ticket requiring code optimization.

1.  **Check the FIX Statement:** Is the rule calculating the entire database (`FIX(@DESCENDANTS("Entity"))`) when it only needs to calculate the current entity being viewed (`FIX({rtp_Entity})`)?
2.  **Check for Dynamic Calcs in FIX:** Are there Dynamic Calc members inside the dense `FIX` block? This forces Essbase to materialize those calculations in memory block-by-block, causing massive slowdowns.
