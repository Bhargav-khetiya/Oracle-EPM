# 18.02 — Incident Management and L3 Support: Complete Guide

> **Module:** 18_Production_Support | **Topic:** L1/L2/L3 Support, Oracle SR, Escalation
> **Audience:** Support Lead / Service Administrator

---

## 1. WHY — Structured Incident Management

Without a tiered support model, every ticket goes to the most senior person. The architect spends 3 hours fixing "Smart View won't connect" (a 5-minute VPN issue). Tiered support ensures the right person handles the right issue.

---

## 2. THE 3-TIER SUPPORT MODEL

```
┌── L1: Self-Service / Help Desk (70% of tickets) ──────────────┐
│  Who: End users + basic IT help desk                           │
│  Scope: Documented issues with known fixes                     │
│  Tools: Knowledge base, Quick Reference Guide, FAQ             │
│  SLA: 4 hours                                                  │
│  Examples:                                                     │
│    → "Smart View won't connect" → check VPN                   │
│    → "Form is blank" → check User Variable                    │
│    → "Can't edit" → check if Final version                    │
│    → "Session expired" → re-login                             │
│    → "Password reset" → Identity Domain admin                  │
└────────────────────────────────────────────────────────────────┘
       │ Escalate if: L1 can't resolve in 30 minutes
       ▼
┌── L2: Application Support (25% of tickets) ───────────────────┐
│  Who: EPBCS Admin / Power User                                 │
│  Scope: Configuration changes, data issues, security           │
│  Tools: EPBCS Admin console, Jobs Console, Calc Manager        │
│  SLA: 8 hours                                                  │
│  Examples:                                                     │
│    → "Rule failed" → check Jobs Console, fix member name      │
│    → "Data doubled" → fix import mode, reload                 │
│    → "New user setup" → provision + security + training       │
│    → "Form slow" → suppress missing, reduce cells             │
│    → "SubVar wrong" → update variables                        │
│    → "Security issue" → adjust dimension security             │
└────────────────────────────────────────────────────────────────┘
       │ Escalate if: requires rule logic change, performance tuning,
       │              or Oracle cloud infrastructure issue
       ▼
┌── L3: Expert / Architect (5% of tickets) ─────────────────────┐
│  Who: EPBCS Architect / Consultant / Oracle Support (SR)       │
│  Scope: Rule development, architecture, Oracle cloud issues    │
│  Tools: Calc Manager, Groovy, REST API, Oracle SR portal       │
│  SLA: 24-48 hours                                              │
│  Examples:                                                     │
│    → Rule logic wrong → debug and fix calc script              │
│    → Performance degradation → block analysis, cache tuning    │
│    → Cloud service issue → raise Oracle SR                     │
│    → Architecture change → design review                       │
│    → Custom Groovy development → code + test + deploy          │
└────────────────────────────────────────────────────────────────┘
```

## 3. RAISING AN ORACLE SERVICE REQUEST (SR)

```
When to raise an SR:
  ☐ Cloud service is down (instance unreachable)
  ☐ Maintenance window overrun (instance not available after 8 hours)
  ☐ Bug: EPBCS feature not working as documented
  ☐ Performance issue you've optimized but can't resolve
  ☐ Feature request

How to raise:
  1. Log into My Oracle Support (support.oracle.com)
  2. Create SR → Select Product: Oracle EPM Cloud
  3. Severity:
     Sev 1: Production down (24/7 response)
     Sev 2: Major functionality impacted (4-hour response)
     Sev 3: Minor issue (1 business day response)
     Sev 4: Question/enhancement (2 business day response)
  4. Include:
     - Instance URL
     - Error message (exact text)
     - Steps to reproduce
     - Screenshots
     - Jobs Console log (if rule failure)
     - Impact description
  5. Monitor and respond to Oracle's questions promptly

Tips:
  ✅ Always include exact error messages
  ✅ Include "Steps to reproduce" — Oracle needs this
  ✅ Respond within 24 hours to keep SR active
  ✅ Request phone call for Sev 1/2
  ❌ Don't raise Sev 1 for non-production issues
```

## 4. SHOW ME — Hotel Pvt Ltd Support Matrix

```
Support Team:
  L1: IT Help Desk (2 people) — handles VPN, login, basic questions
  L2: EPBCS Admin (Bhargav) — handles config, security, data, rules
  L3: Architect (Consultant, on-call) — handles complex rule fixes

Monthly Ticket Volume:
  L1: 20 tickets/month (avg resolution: 15 minutes)
  L2: 8 tickets/month (avg resolution: 45 minutes)
  L3: 1-2 tickets/month (avg resolution: 4 hours)
  Oracle SR: 0-1 per quarter

Escalation Rules:
  L1 → L2: If not resolved in 30 minutes
  L2 → L3: If requires code change or architecture decision
  L2 → Oracle: If cloud infrastructure issue
  Any → Sev 1: If production down for all users
```
