**Q1: When would you use Groovy instead of Calc Scripts?**
> Use Groovy for: REST API calls, email notifications, complex conditional logic, string manipulation, metadata access, data movement between cubes with complex transformations, and any logic beyond simple math. Use Calc Scripts for straightforward calculations where performance is critical.

**Q2: What is DataGridBuilder?**
> DataGridBuilder is the Groovy API class used to WRITE data to an Essbase cube. You define POV, columns, and add rows with values, then call `saveGrid()` to push data. Equivalent to submitting a form programmatically.

**Q3: What is DataGridDefinitionBuilder?**
> DataGridDefinitionBuilder is used to READ data from a cube. You define what intersection to retrieve, call `loadGrid()`, then iterate over cells with `dataCellIterator()`.

**Q4: How do you access substitution variables in Groovy?**
> `String month = operation.application.getSubstitutionVariable("CurrentMonth")`. To set: `operation.application.setSubstitutionVariable("CurrentMonth", "Jul")`.

**Q5: How do you iterate over dimension members?**
> `def dim = operation.application.getDimension("Entity", "FinPlan")` then `def members = dim.getEvaluatedMembers("ILvl0Descendants(Entity)", "FinPlan")` then `members.each { m -> println m.name }`.

**Q6: How do you handle errors in Groovy?**
> Use try/catch/finally blocks. Log with `println` (visible in Job Console). Re-throw exceptions to mark the rule as failed. Always validate inputs before processing.

**Q7: Can you call external REST APIs from Groovy?**
> Yes. Use `HttpURLConnection` and `URL` classes. Parse responses with `groovy.json.JsonSlurper`. Common use: fetch live exchange rates, send notifications to Slack/Teams, integrate with external systems.

**Q8: How do you send emails from Groovy?**
> Use `operation.application.getMailDefinition()`. Set to/subject/body, then `operation.application.sendMail(mailDef)`. Used for notifications after calc completion, error alerts, etc.

**Q9: What is the performance consideration for DataGridBuilder?**
> Always batch writes into a single `saveGrid()` call. Multiple small saves are slow because each creates a separate server round-trip. Also use `setSuppressMissing(true)` when reading to avoid processing empty cells.

### 😈 Twisted Interview Question
**Question:** A Groovy script loops through 10,000 employees to calculate bonuses. For each employee, it builds a grid, writes the bonus, and calls `saveGrid()`. The script takes 25 minutes to run. How do you optimize it to run in 10 seconds?
> **Answer:** The developer committed the cardinal sin of putting `saveGrid()` INSIDE the `each` loop! This causes 10,000 separate network API calls to the Essbase kernel. To fix it, instantiate ONE `DataGridBuilder` *outside* the loop, add all 10,000 rows to that single grid builder inside the loop, and then call `saveGrid()` EXACTLY ONCE *after* the loop closes.

**Q10: How do you read a cell value at a specific intersection?**
> Load a grid definition, then: `cell.data` returns the numeric value. Use `cell.getMemberName("Dimension")` to get which member the cell belongs to. Use `cell.crossDimCell("Period": "Feb")` to navigate to a different member.

**Q11: What is the Operation class?**
> `operation` is the entry point to the EPM Groovy API. Through it you access: `operation.application` (app-level methods), `operation.grid` (current form's grid), `operation.application.getCube("name")` (cube access).

**Q12: How would you implement a data copy from Actual to Budget using Groovy?**
> Read Actual data using DataGridDefinitionBuilder → iterate over cells → build Budget grid using DataGridBuilder with different POV (Scenario=Budget) → save. This gives you control to transform data during copy (e.g., apply growth rate).

**Q13: What are the limits of Groovy in EPM Cloud?**
> Maximum execution time: 30 minutes. Maximum grid size: ~500K cells. Network calls may be restricted by Oracle's cloud firewall. No file system access (cloud sandboxed). Limited Java libraries available.

**Q14: How do you debug Groovy rules?**
> Use `println` extensively — output appears in Job Console log. Check return values. Use try/catch to capture and log errors. Test with small data sets first. Enable SET MSG DETAIL for underlying calc visibility.

**Q15: When would you use Groovy Smart Push vs Calc Script DATACOPY?**
> Groovy Smart Push: For cross-cube data movement with complex transformations, conditional logic, or when you need to call it programmatically. Calc Script DATACOPY: For simple within-cube data copy between Sparse members. DATACOPY is faster for simple copies.
