# 23.04 — Case Study: Migration from On-Premise Hyperion

> **Module:** 23_Case_Studies | **Topic:** On-Prem to Cloud Migration
> **Audience:** Architect / Migration Lead

---

## 1. THE PROBLEM

```
Hotel Pvt Ltd — Legacy Environment:

Current: Hyperion Planning 11.2.x on-premise
  - Server: 2 physical servers (aging, 7 years old)
  - Maintenance: 1 DBA + 1 middleware admin
  - Patches: 6 months behind Oracle releases
  - Uptime: 97% (3% = 11 days downtime/year)
  - Smart View: Version 11.1 (outdated)
  - Backup: Manual nightly scripts (fail silently)
  - Cost: ₹35L/year (hardware + licenses + admin labor)

Pain Points:
  ❌ Server hardware end-of-life in 12 months
  ❌ On-prem team retiring (knowledge drain)
  ❌ No Groovy support (11.2 doesn't have it)
  ❌ No dashboards (old UI)
  ❌ Patch cycle: 3-6 months behind
  ❌ Disaster recovery: untested, manual
```

---

## 2. MIGRATION APPROACH

### Phase 1: Assessment (Week 1-2)

```
Inventory:
  ☐ Applications: 1 (HotelPlan)
  ☐ Cubes: 2 (FinPlan BSO, Reporting ASO)
  ☐ Dimensions: 8
  ☐ Members: ~400 total
  ☐ Forms: 25
  ☐ Business Rules: 12 (calc scripts only — no Groovy)
  ☐ Security: 3 groups, 45 users
  ☐ Data: 3 years of actuals + current year budget
  ☐ Integrations: 1 flat file feed from PMS

Decision: Lift-and-Shift OR Redesign?
  → REDESIGN (move to EPBCS with pre-built modules)
  → Reason: Take advantage of Hybrid BSO, Groovy, dashboards
```

### Phase 2: Cloud Setup (Week 3-4)

```
☐ Provision EPBCS instance
☐ Create application using EPBCS Enterprise modules
☐ Enable FinPlan, Workforce modules
☐ Map on-prem dimensions to EPBCS standard dims:
    On-Prem "Measures" → EPBCS "Account" (with Account Type mapping)
    On-Prem "Entities" → EPBCS "Entity"
    On-Prem "Periods" → EPBCS "Period" (standard time dim)
    On-Prem "Years" → EPBCS "Year"
    On-Prem "Scenario" → EPBCS "Scenario"
    On-Prem "Version" → EPBCS "Version"
    Custom "Dept" → EPBCS Custom Dimension
```

### Phase 3: Metadata Migration (Week 5-6)

```
☐ Export on-prem outline to flat file
☐ Transform member names to EPBCS standards:
    On-prem: "101_Mumbai" → Cloud: "Mumbai_Hotel"
    On-prem: "Rev_Room" → Cloud: "Room_Revenue"
☐ Import metadata via flat file load
☐ Set member properties (Account Type, Data Storage, Time Balance)
☐ Validate dimension structure matches on-prem
☐ Refresh database
```

### Phase 4: Rule Migration (Week 7-8)

```
On-Prem Rules (Calc Scripts):           Cloud Rules (Hybrid):
  CALC_Revenue.csc          →           CALC_Revenue_Totals (Calc Script)
  CALC_Expenses.csc         →           CALC_Expense_Totals (Calc Script)
  CALC_PNL.csc              →           CALC_PnL_Complete (Calc Script)
  COPY_SEED.csc             →           COPY_Actual_to_Budget (Calc Script)
  CALC_CURRENCY.csc         →           CALC_Currency_Conversion (Calc Script)
  AGG_ALL.csc               →           AGG_Entity (simplified — Hybrid = no full AGG)

NEW rules (not possible on-prem):
  VAL_Revenue_PreSave (Groovy — validation!)
  RPT_Close_Email (Groovy — email notification!)

Rulesets (new concept — didn't exist on-prem):
  RS_OnSave_Revenue (3 rules)
  RS_Monthly_Close (8 rules)
```

### Phase 5: Data Migration (Week 9)

```
☐ Export on-prem data:
    essbase.bat> export database HotelPlan.FinPlan
    → data file: FinPlan_export.txt (~50MB)

☐ Transform data format:
    On-prem:  "101_Mumbai" "Rev_Room" 8500000
    Cloud:    Mumbai_Hotel,Room_Revenue,Actual,Final,FY2024,Jan,8500000

☐ Upload and load to EPBCS:
    epmautomate uploadfile FinPlan_data.csv
    epmautomate importdata "DL_Migration" "FinPlan_data.csv"

☐ Validate: Compare on-prem totals vs cloud totals
    On-prem All_Hotels Total_Revenue FY2024: ₹23,45,00,000
    Cloud   All_Hotels Total_Revenue FY2024: ₹23,45,00,000 ✅
```

### Phase 6: Forms + Security + UAT (Week 10-11)

```
☐ Rebuild 25 forms (enhanced with dashboards + KPIs)
☐ Migrate security groups (3 groups, 45 users)
☐ Set dimension security + form permissions
☐ Smart View: Update connection URLs for all 45 users
☐ UAT: Each hotel GM validates their data
☐ UAT: Finance team runs month-end close simulation
☐ UAT: CFO validates consolidated reports
```

### Phase 7: Go-Live + Cutover (Week 12)

```
Cutover Plan (Friday evening):
  6:00 PM — Freeze on-prem (read-only)
  6:30 PM — Final data export from on-prem
  7:00 PM — Load final data to cloud
  7:30 PM — Run AGG + validation
  8:00 PM — Switch DNS / update Smart View URLs
  8:30 PM — Send go-live email to all users
  
Monday 9:00 AM — Users log into EPBCS Cloud ✅
Monday-Friday — Hyperdesk support for questions (war room)
```

## 3. THE RESULTS

```
BEFORE (On-Prem)              AFTER (EPBCS Cloud)
────────────────────────────────────────────────────
₹35L/year TCO                → ₹25L/year (license only)
2 servers + DBA/admin         → Zero infrastructure
97% uptime                    → 99.9% uptime (Oracle SLA)
6 months behind patches       → Always current
No Groovy                     → Full Groovy support
No dashboards                 → Executive dashboards
Manual backups                → Automatic daily backups
No disaster recovery         → Built-in DR
Smart View 11.1               → Latest Smart View
3-month budget cycle          → 4-week cycle
5-day close                   → 6-minute close (automated)
```

---

## 4. RISKS AND MITIGATIONS

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|-----------|
| Data mismatch after migration | Medium | High | Cell-by-cell comparison on 50 key intersections |
| Users resist new UI | High | Medium | 2 training sessions + Quick Reference Guide |
| Smart View version mismatch | Medium | Low | Bundle new SV in migration package |
| Rule logic differs slightly | Low | High | Parallel run for 1 month (on-prem + cloud) |
| Network/VPN issues | Medium | Medium | Pre-test VPN from all 5 hotel locations |
