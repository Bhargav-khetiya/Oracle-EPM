# 25.02 Smart View Options Screen

> **Module:** 25_CheatSheets  
> **Topic:** 02 - Smart View Options Configuration  
> **Target Audience:** Power User / Consultant  

---

## Navigation
**Excel -> Smart View Ribbon -> Options**

## Overview
A user complains that "Smart View looks broken" or "The numbers have too many decimals." 99% of the time, the server is fine, and the user's local Smart View Options are misconfigured. 

## Every Configuration Property

### 1. Advanced Tab (The Engine)

#### "Number of Undo Actions"
- **What it does:** Allows the user to click Undo after an Ad-Hoc pivot.
- **Default:** 0. 
- **Architect Note:** Increase this to `5`. Do not set it to 100, or Excel will consume 10GB of local RAM tracking every single pivot history, crashing the user's laptop.

#### "Route message to files"
- **What it does:** Generates a local diagnostic log of all HTTP traffic between Excel and Oracle.
- **When to use:** Turn this on ONLY when Oracle Support demands a trace file to debug a network timeout. Leave it off otherwise to save hard drive space.

### 2. Formatting Tab (The Aesthetics)

#### "Use Excel Formatting" vs "Cell Styles"
- **What it does:** 
  - `Cell Styles` applies Oracle's hardcoded colors (e.g., Dirty cells turn Yellow).
  - `Excel Formatting` allows the user to paint a cell bright pink, click Refresh, and the cell stays bright pink.
- **Architect Note:** If a user complains that their custom formatting disappears every time they refresh the data, tell them to check `Use Excel Formatting` and uncheck `Move Formatting on Operations`.

#### "Scale"
- **What it does:** Divides the data by a factor (e.g., Thousands, Millions).
- **Architect Note:** **MASSIVE DANGER.** If a user sets Scale to `Thousands`, and they type `5` into the grid and click Submit, Smart View multiplies it by 1,000 before sending it to the database, saving `$5,000`. If they forget they have Scaling turned on, they will destroy the budget data.

### 3. Data Options Tab (The Mechanics)

#### "Suppress Rows: #Missing / Zero"
- **What it does:** Hides rows that have no data.
- **Architect Note:** If a user complains, "I zoomed in on the Entity dimension and nothing happened, all the rows disappeared!" It is because they zoomed into a slice of the database with no data, and this checkbox hid all the empty rows. Tell them to uncheck it to see the blank grid.

#### "Replacement: #NoAccess / #Missing"
- **What it does:** Changes the text displayed in the grid.
- **Architect Note:** Power users hate seeing `#Missing` printed in 5,000 cells; it makes the Excel sheet unreadable. Change the `#Missing` replacement label to a blank space or a dash (`-`). 
- *Warning:* Do not change the `#NoAccess` label. Users need to know exactly which cells they are locked out of due to Security constraints.

## 25. Interview Questions

### Intermediate
**Q: A user builds an Ad-Hoc grid. They change a number, click Submit, and Excel throws an error: "Cannot submit data to a dynamic calc member." The user is confused because all the members in their grid look identical, they don't know which one is dynamic. How do they fix their UI?**
> A: Go to Smart View Options -> Formatting Tab. Enable **Cell Styles**. Expand the Member styles and set a distinct color (e.g., Gray) for `Dynamic Calc` members, and White for `Data (Store)` members. Click Refresh. The grid will instantly color-code itself, showing the user exactly which cells are read-only formulas and which cells accept data entry.
