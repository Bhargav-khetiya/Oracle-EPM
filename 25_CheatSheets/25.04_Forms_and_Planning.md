## 📌 Form Layout
| Area | Purpose | Example |
|---|---|---|
| **POV** | Fixed filters (rarely changed) | Scenario=Budget, Year=FY26 |
| **Pages** | Switchable filters (frequent) | Entity, Department |
| **Rows** | Left-side headers | Account members |
| **Columns** | Top headers | Period (Jan-Dec) |
| **Anchor** | Primary dim in multi-dim rows/cols | Controls nesting |

## 🎛️ Key Form Properties
| Property | What It Does |
|---|---|
| Suppress Missing Data | Hides rows with all #MISSING |
| Suppress Missing Blocks | Performance optimization (test first!) |
| Display Missing as Blank | Shows empty cells instead of #MISSING |
| Read-Only | Prevents data entry |
| Enable Grid Spread | Allow value distribution |
| Calc On the Fly | Real-time formula preview |

### 💡 Pro Tip: Suppress Missing Blocks vs Data
> **Misconception:** You should always turn on "Suppress Missing Blocks" on large forms to make them fast.
> **Reality:** Suppress Missing Blocks stops Essbase from scanning the index for empty blocks. If the form's query is highly sparse (e.g. querying millions of possible intersections where only 5 have data), it's a lifesaver. However, if the query is mostly dense (e.g. looking at all accounts for one entity), checking for blocks first actually adds overhead and *slows down* the form! Test both ways before defaulting.
