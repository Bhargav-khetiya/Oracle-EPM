## 📌 Functional Consultant
| Aspect | Detail |
|---|---|
| **Focus** | Business & finance language |
| **Does** | Gathers requirements, writes documentation, designs solution |
| **Tests** | Against business needs and user acceptance |
| **Skills** | Finance knowledge, process understanding, communication |

## 📌 Technical Consultant (Your Role)
| Aspect | Detail |
|---|---|
| **Focus** | System & code language |
| **Does** | Configures cubes, writes rules (Groovy), builds forms, manages metadata |
| **Tests** | System functionality, performance, integrations |
| **Skills** | Essbase, Groovy, Calc Scripts, REST API, Smart View |

### 💡 Pro Tip: The Architect's Mindset
> **Misconception:** A technical consultant's job is just to write the code the functional consultant asks for.
> **Reality:** You are the guardian of the system's physics. If a functional consultant asks you to build a business rule that calculates every department against every project across every entity, you must push back! That creates an impossibly huge calculation scope. A true architect translates business desires into *system-optimized* realities, often suggesting alternate approaches (like Data Maps) rather than blindly coding bad design.
