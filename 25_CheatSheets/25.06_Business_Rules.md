## 📌 FIX Statement
```
FIX("Sparse_Member1", "Sparse_Member2")
    /* calc goes here */
ENDFIX
```
- Only Sparse dimensions in FIX
- Use IF for Dense dimensions inside FIX

## 📌 Essential SET Commands
```
SET UPDATECALC ON;         -- Only recalc dirty blocks
SET CREATEBLOCKONEQ ON;    -- Create blocks on assignment
SET AGGMISSG OFF;          -- Skip missing in aggregation
SET MSG SUMMARY;           -- Production logging
SET MSG DETAIL;            -- Debug logging
```

## 📌 Common Operations
| Operation | Command |
|-----------|---------|
| Aggregate | `AGG("Entity");` |
| Calculate dimension | `CALC DIM("Account");` |
| Copy data | `DATACOPY "Actual" TO "Budget";` |
| Clear data | `CLEARDATA "Budget";` |
| Cross-dim reference | `"Revenue"->"Actual"->"FY26"` |

## 📌 Design Patterns
1. **Copy:** DATACOPY src TO tgt (with CREATEBLOCKONEQ ON)
2. **Allocate:** Target = Total × (basis / total_basis)
3. **Translate:** USD = Local × Rate
4. **Clear+Calc:** CLEARDATA → then calculate
5. **Rolling Forecast:** @RANGE up to &CurrentMonth = Actuals

### 💡 Pro Tip: The Empty Set Silent Failure
> **Misconception:** If a business rule runs in 1 second and the Job Console says "Completed", it worked perfectly.
> **Reality:** Essbase will return a successful "Completed" status even if it calculated absolutely nothing! If your `FIX` statement accidentally targets a combination of members that has no data (e.g. an empty block), Essbase quickly checks the index, finds nothing, and finishes. Always add `SET MSG DETAIL;` and check the logs to verify blocks were actually read and updated!
