## 📌 Core API Classes
| Class | Purpose |
|-------|---------|
| `operation.application` | App-level access |
| `DataGridDefinitionBuilder` | READ data |
| `DataGridBuilder` | WRITE data |
| `getDimension("Dim","Cube")` | Dimension access |
| `getSubstitutionVariable("name")` | Read sub var |

## 📌 Read Data Pattern
```groovy
def grid = new DataGridDefinitionBuilder()
grid.setSuppressMissing(true)
grid.addPov(["Year":"FY26","Scenario":"Actual"])
grid.addColumn(["Period":["Jan","Feb","Mar"]])
grid.addRow(["Account":"Revenue"])
def data = cube.loadGrid(grid.build(), false)
data.dataCellIterator().each { cell ->
    println "${cell.getMemberName('Account')} = ${cell.data}"
}
```

## 📌 Write Data Pattern
```groovy
DataGridBuilder grid = new DataGridBuilder(cube)
grid.addPov(["Year":"FY26","Scenario":"Budget"])
grid.addColumn(["Period":["Jan","Feb","Mar"]])
grid.addRow(["Account":"Revenue","Entity":"E10001"], [1000,1100,1200])
cube.saveGrid(grid.build())
```

## 📌 Key Tips
- Always `setSuppressMissing(true)` when reading
- Batch all writes in ONE `saveGrid()` call
- Use `cell.data ?: 0.0` for null safety
- Use `try/catch` for error handling
- `println` output → Job Console log

### 💡 Pro Tip: Smart Push vs DataGridBuilder
> **Misconception:** You should use `DataGridBuilder` to push large amounts of data between cubes.
> **Reality:** `DataGridBuilder` is slow for massive data movement because it parses data cell-by-cell in the JVM. If you are moving thousands of records from the FinPlan cube to the Reporting cube, you should execute a `Smart Push` via Groovy instead (`operation.application.getDataMap("MapName").execute()`). Let the native C++ engine handle the heavy lifting!
