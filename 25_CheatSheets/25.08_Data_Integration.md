## 📌 Data Load Methods
| Method | Use Case |
|--------|----------|
| Data Management (FDMEE) | Complex mapping + transformation |
| Data Exchange | Simple file-based load |
| EPM Automate | Scheduled/scripted loads |
| REST API | Programmatic loads |
| Smart View Submit | Manual user entry |
| Groovy DataGridBuilder | Rule-based writes |

## 📌 Data Flow
```
ERP → Export CSV → Upload to Inbox → Data Management → Map → Load → Cube
```

## 📌 Data Management Components
1. **Import Format** — file structure (columns, delimiters)
2. **Location** — links format to target cube
3. **Mapping** — source member → target member
4. **Load Rule** — execution definition

## 📌 Smart Push / Data Maps
- Data Map: Defines cube-to-cube mapping
- Smart Push: Triggers Data Map on form save
- Both move data WITHIN the application (between cubes)

## 📌 EPM Automate Data Commands
```bash
epmautomate uploadFile data.csv        # Upload
epmautomate importData LoadRule        # Import
epmautomate exportData ExportRule      # Export
epmautomate downloadFile report.csv    # Download
```

## 📌 Common Load Errors
| Error | Fix |
|-------|-----|
| Target member not found | Add mapping in Data Mgmt |
| Invalid data value | Clean source data (non-numeric) |
| Partial load | Check rejected records in DM log |
| Data doesn't appear | Check POV, security, refresh cube |

### 💡 Pro Tip: The "Success" Status Trap
> **Misconception:** When calling the REST API to run a Data Management load rule, if you receive a `status: 0` JSON response, the data was loaded successfully.
> **Reality:** Data loads are asynchronous. `status: 0` just means the EPM server *accepted* your request to start the job. The job could fail 5 seconds later due to mapping errors. You must extract the `jobId` from the response and write a loop that continuously polls the Job Status endpoint until it returns a final completion status (like `-1` for complete).
