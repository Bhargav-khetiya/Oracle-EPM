# 27.01 Application Overview Screen

> **Module:** 27_Screen_Encyclopedia  
> **Topic:** 01 - The Application Overview  
> **Target Audience:** Administrator  

---

## Navigation
**Navigator -> Application -> Overview**

## Purpose
This screen is the central dashboard for the physical architecture of the EPM Application. It tells you what modules are enabled, the size of the database, the number of dimensions, and allows you to trigger database refreshes.

## Screen Sections

### 1. The Header Strip
- **Application Name:** The 8-character ID of the app (e.g., `EPBCS`).
- **Application Type:** `Enterprise` or `Custom`.
- **Status:** Should be `Active`.

### 2. Cubes Tab
Displays every physical Essbase cube in the application.
- **Cube Name:** e.g., `OEP_FS` (Financials), `OEP_REP` (Reporting).
- **Type:** `BSO` (Block Storage) or `ASO` (Aggregate Storage).
- **Size:** Very important. If your BSO cube says 50GB, you have a massive architectural problem.
- **Action Menu (Gear Icon) -> Clear Cube:** Used to wipe out specific slices of data.

### 3. Dimensions Tab
Lists every dimension in the application.
- **Cube Column:** Checkmarks indicate which cubes share this dimension. (If `Entity` is checked for `OEP_FS` and `OEP_WFS`, it is a shared dimension).
- **Import / Export Buttons:** Used to manually load metadata CSV files into the dimensions without using Data Integration.

### 4. Actions Menu (Top Right)
This is the most dangerous and important menu on the screen.

- **Refresh Database:** 
  - *Purpose:* When you add a new member (e.g., `Cost Center 999`) in the Dimension Editor, it does not actually exist in Essbase yet. You MUST run a Database Refresh to push the relational metadata changes into the physical Essbase `.otl` file.
  - *Danger:* A full refresh can take anywhere from 2 minutes to 2 hours. If a user tries to run a calculation or save data during a refresh, the system is locked, and they will get an error.

- **Remove Application:**
  - *Purpose:* Deletes the entire application. There is no undo button. Do this only in DEV/TEST when starting over from scratch.

## Interview Questions

### Beginner
**Q: You added a new Account to the dimension editor, but when you open a Web Form, the account is missing. Why?**
> A: You forgot to click "Refresh Database" on the Application Overview screen. The metadata change is stuck in the relational repository and hasn't been pushed to the Essbase outline yet.

### Architect
**Q: You click "Refresh Database". The process runs for 5 minutes and then fails with the error: "Cube restructuring failed. Cannot lock database." What happened?**
> A: Another process currently has an exclusive lock on the database. This usually means a massive Business Rule is running, or a Data Load is currently executing. You cannot restructure the database outline while the engine is actively writing data to blocks. The Admin must go to the Jobs console, identify the running job, wait for it to finish (or kill it), and then retry the Database Refresh.
