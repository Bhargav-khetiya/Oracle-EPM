## Navigation
**Navigator -> Access Control**

## Overview
Access Control is the central nervous system for security. If configured incorrectly, a junior analyst in Marketing could accidentally overwrite the global Board of Directors' finalized budget. Security in EPBCS is managed via **Groups**, not individual users.

## Every Configuration Property

### 1. Manage Groups Tab

#### "Create Group"
- **Architect Rule:** NEVER assign dimensional security directly to a User (e.g., John Smith). John will quit in 6 months, and you will have orphan security profiles. 
- You MUST create a Group (e.g., `Grp_Marketing_Planners`). You assign security to the Group. When John quits, you simply remove him from the Group and add his replacement.

### 2. Assign Application Roles Tab

This screen maps IDCS (Identity Domain) privileges to Application abilities.

#### The Core Roles:
- **Service Administrator:** God Mode. Overrides all explicit Deny filters on dimensions. Can delete the application.
- **Power User:** Can build Web Forms, write Business Rules, and load data. Cannot delete the application.
- **User:** The standard planner. Can only enter data into forms built by Power Users.
- **Viewer:** Completely Read-Only. Even if you give them "Write" access to a specific Cost Center later on, the Viewer role acts as a hard ceiling. They can never save data.

### 3. Assign Access (Dimensional Security)

**Navigator -> Dimensions -> [Click the Key Icon]**

This is where the actual data matrix is built.
- **Target:** You select `Cost Center 100`.
- **Assignee:** You select `Grp_Marketing_Planners`.
- **Type of Access:** `Read`, `Write`, or `None`.

#### The Inheritance Properties (Crucial)
When you assign access to a Parent member (e.g., `Total Europe`), you must define how it cascades down to the children (`France`, `Germany`).

- **Member:** Access ONLY applies to `Total Europe`. The user cannot see `France`.
- **Children:** Access applies to `France` and `Germany`, but NOT `Total Europe`.
- **Descendants:** Access applies to all children, grandchildren, and great-grandchildren down the tree. (The most common setting).
- **Member & Descendants:** Access applies to `Total Europe` AND all children down the tree.

## The Architect's Conflict Resolution Rules

If a user belongs to multiple groups with conflicting security, Essbase uses a strict order of operations to resolve the conflict:

1. **Rule 1:** Explicit assignment overrides Inherited assignment. (If Group A has Inherited `Write` to Europe, but Group B has Explicit `Read` to France, France becomes `Read`).
2. **Rule 2:** `None` (Deny) ALWAYS overrides `Read` or `Write`. Deny is absolute.
3. **Rule 3:** `Write` ALWAYS overrides `Read`.

## 25. Interview Questions

### Architect
**Q: A user is in `Group_A` which gives them `Write` access to `Total North America (Member & Descendants)`. The user is also in `Group_B` which gives them `None` (Deny) access to the `USA` (a child of North America). What can the user edit?**
> A: The user can edit `Canada` and `Mexico`, but they are completely blocked from `USA`. Because `None` (Deny) is the absolute highest priority in the Essbase security matrix, the specific Deny on the `USA` overrides the inherited `Write` access cascading down from `North America`.
