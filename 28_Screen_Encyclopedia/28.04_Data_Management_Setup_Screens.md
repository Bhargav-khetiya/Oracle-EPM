# 27.04 Data Management Setup Screens

> **Module:** 27_Screen_Encyclopedia  
> **Topic:** 04 - The FDMEE Pipeline Screens  
> **Target Audience:** Administrator

## Navigation
**Navigator -> Integration -> Data Management -> Setup Tab**

## Overview
Data Management (formerly FDMEE) is the ETL (Extract, Transform, Load) engine built directly into EPM. It is a strictly linear pipeline. You must configure the screens in exact sequential order, or the pipeline breaks.

## The Sequential Configuration Screens

### 1. Target Application
- **What it is:** Tells the ETL engine where the data is going.
- **The Configuration:** You click **Add -> Local**. This registers your physical EPBCS cubes (e.g., `OEP_FS`) into Data Management.
- **Architect Note:** If you add a new Custom Dimension to EPBCS, you MUST come to this screen and click **Refresh Metadata**. Otherwise, Data Management will not know the new dimension exists and mappings will fail.

### 2. Import Format
- **What it is:** Tells the ETL engine how to read the flat file (or SQL table).
- **The Configuration:** 
  - **File Type:** `Delimited - Numeric Data` (The standard CSV format).
  - **Delimiter:** Comma `,` or Pipe `|`.
  - **Column Mappings:** You explicitly define the columns. "Account is in Column 1. Entity is in Column 2. Amount is in Column 5."
- **Architect Note:** If your source file has a header row, you must type `1` in the "Skip Rows" property, otherwise the system will try to load the word "Entity" into the database as a data value, crashing the import.

### 3. Location
- **What it is:** The central hub that links the Import Format to the Target Application.
- **The Configuration:** You name the Location (e.g., `Loc_SAP_GL`) and assign the Import Format and Target App to it. Security is applied at the Location level (e.g., allowing the UK Admin to only run the UK Location).

### 4. Period Mapping
- **What it is:** Translates the Source ERP calendar into the EPBCS calendar.
- **The Configuration:** 
  - **Global Mapping:** Maps `Jan-24` (Source) to `Jan` (Target Period) and `FY24` (Target Year).
  - **Application Mapping:** Overrides the Global mapping for specific cubes.
- **Architect Note:** If a user gets a "No Period Mapped" error during a data load, it means you forgot to add the new Fiscal Year to this screen.

### 5. Category Mapping
- **What it is:** Translates the Source Ledger Type into the EPBCS Scenario.
- **The Configuration:** Maps `Actual_Ledger` to the `Actual` Scenario in EPBCS.

## 25. Interview Questions

### Intermediate
**Q: You build the entire pipeline. When you try to run the Data Load Rule, the system immediately fails and says "Invalid Import Format." You check the Import Format screen, and everything looks perfect. What is the architectural relationship you forgot to configure?**
> A: You forgot to assign the Import Format to the **Location**. The Data Load Rule executes against a Location. If the Location is blank or pointing to the wrong Import Format, the rule has no idea how to parse the file. You must follow the strict sequence: Source -> Target -> Import Format -> Location -> Data Rule.
