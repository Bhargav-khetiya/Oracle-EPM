# Job Console, Scheduling, and Calculation Launch

In EPM Cloud, executing processes is handled through the Job Console, Rules screen, or automated scheduling screens. 

## 1. Launching Calculation Manager Rules

As referenced in the Calculation Manager Launch guide, there are multiple ways to execute a rule, each with different implications.

*   **From a Form:** The most common. Rules can be set to "Run on Save". The critical benefit here is that the Form's POV is automatically passed to the rule's runtime prompts, drastically reducing the calculation scope and preventing the user from accidentally calculating the entire database.
*   **From the Rules Screen (Job Console):** Users can launch rules manually. If the rule requires runtime prompts (RTPs), the user must explicitly enter them. 
    *   *Risk:* If RTP limits (Valid Intersections) are not configured properly, a user might leave a prompt blank or select "Total Geography", causing a massive calculation that locks the system.
*   **From EPM Automate / REST API:** Used for overnight batch jobs.
*   **From Action Menus:** Attached to Ad Hoc grids or forms, allowing contextual execution.

## 2. The Job Console Screen

The Job Console is the primary diagnostic screen for administrators.

### Analyzing Job Statuses
*   **Processing:** The rule or data load is currently executing. You can click on the job to see which specific steps are running.
*   **Completed:** Successful execution.
*   **Completed with Errors:** Common in data loads (e.g., some rows were unmapped and failed, but the rest loaded). You must check the log file attached to the job.
*   **Error:** The job failed completely (e.g., syntax error in a calc script, or a timeout).

### Canceling Jobs
Administrators can cancel stuck jobs from this screen. However, if a massive Essbase calc script is deep in execution, clicking "Cancel" sends a kill signal, but the Essbase engine might take time to safely roll back the block updates. Never force-kill the service unless absolutely necessary, as it can corrupt the cube outline.

## 3. The Scheduling Screen

EPM Cloud provides a built-in scheduler, replacing the need for external tools (like Windows Task Scheduler + EPM Automate) for basic tasks.

### What Can Be Scheduled?
*   **Business Rules / RuleSets:** Run overnight aggregations.
*   **Data Integration (Data Load Rules):** Schedule automated pulls from ERP systems or flat file drops.
*   **Database Refreshes:** Schedule the cube refresh after metadata updates.
*   **Clear Cubes:** Wipe data before a new load.

### Limitations of the Built-in Scheduler
*   **Dependencies:** The native scheduler is somewhat basic. If you have a complex chain where Job C *must* only run if Job B succeeds, and Job B relies on Job A, you are better off using EPM Automate orchestrated by an enterprise scheduling tool (like Control-M, AutoSys, or Jenkins).
*   **Timezones:** Ensure the scheduler timezone aligns with your global maintenance window.
