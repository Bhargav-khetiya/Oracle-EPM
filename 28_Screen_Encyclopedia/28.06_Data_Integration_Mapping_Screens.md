# Data Integration Mapping Screens

Based on the Data Management (FDMEE) and Data Integration documentation, mapping members is the most critical activity in the data load process.

## 1. Defining Members in Maps

When mapping source system data (e.g., from an ERP) to the EPM Cloud target application, you use the Data Integration Mapping screens.

### Map Types
*   **Explicit Mapping:** Maps a specific source value directly to a target value (e.g., `Account 1000` -> `A_Sales`). This is the fastest mapping type to process.
*   **Between Mapping:** Maps a range of source values to a single target (e.g., `Accounts 1000 to 1999` -> `A_Revenue`).
*   **In Mapping:** Maps a comma-separated list of values to a target.
*   **Multi-Dimensional Mapping:** The most complex but powerful type. It changes the target member based on *multiple* source columns (e.g., IF Account = `1000` AND Cost Center = `IT`, target is `A_Software`).
*   **Like Mapping:** Uses wildcards (`*` or `?`) to map patterns (e.g., `1*` -> `A_Assets`). This is the slowest mapping to process and evaluates last.

## 2. Using `#SCRIPT` in Mappings

For advanced mapping requirements where standard mapping types fail, Data Management allows you to write Jython or SQL scripts directly in the target member field.

*   **Syntax:** You define the target as `#SCRIPT` and then provide the script logic in the mapping rule details.
*   **Performance Impact:** Using Python/Jython scripts in data load mappings significantly slows down the import process because the script has to evaluate row-by-row. Where possible, use SQL mapping scripts, as they execute a single batch `UPDATE` statement on the staging table, making them infinitely faster.

## 3. Ignore Mappings

Often, your source file contains data you do not want to load to EPM (e.g., statistical accounts or empty rows).

*   You must map these to a specific target called `IGNORE`.
*   If you do not map them to `IGNORE`, the data load will fail with an "Unmapped Dimension" error.

## 4. The Processing Order
The system always processes maps in a specific order, which is critical to understand when troubleshooting:
1.  Explicit
2.  Between
3.  In
4.  Multi-Dimensional
5.  Like

If an explicit map exists, the system uses it and completely ignores a "Like" map that might also apply to that same data row.
