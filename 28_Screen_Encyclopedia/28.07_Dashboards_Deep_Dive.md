## WHY — What Real-World Problem Does This Solve?

Without dashboards, EPM is just a spreadsheet replacement. A planner opens a form, types numbers, saves. The CFO opens a different form, sees numbers. Nobody connects the dots.

**Dashboards transform EPM from "data entry" into "decision-making."**

Hotel Pvt Ltd CFO's problem: "I open EPM and I see 15 different forms. I have to click into each one. It takes 20 minutes to get a picture of how the company is performing. I want to log in and SEE everything at once."

**Dashboard 2.0 = ONE screen with forms + charts + tiles + KPIs, all interactive.**

---

## WHAT — Plain English Definition

A **Dashboard 2.0** is a customizable canvas (like a PowerPoint slide) where you drag and drop:
- **Forms (Grids)** — data tables from the Essbase cube
- **Charts** — bar, line, pie, combo, waterfall, gauge, and more
- **Tiles** — large KPI number boxes with conditional coloring
- **External URLs** — embed a website inside the dashboard
- **Commentary** — text boxes for narrative input

Everything on the canvas is interactive: clicking a member in one component can filter data in another (Master-Detail linking).

### Every Object Type You Can Place

| Object | Description | Data Source | Interaction |
|--------|-------------|-------------|-------------|
| **Form (Grid)** | Data table from Essbase cube | Saved Planning Form | Read + Write (if not read-only) |
| **Bar Chart** | Vertical/horizontal bars | Linked to a Form | Click bar → apply context |
| **Line Chart** | Trend lines over time | Linked to a Form | Hover for tooltips |
| **Pie / Doughnut** | Proportional breakdown | Linked to a Form | Click slice → filter |
| **Combo Chart** | Bar + Line overlaid | Linked to a Form | Dual Y-axis support |
| **Waterfall** | Bridge/walk analysis | Linked to a Form | Budget → Forecast walk |
| **Scatter / Bubble** | Correlation analysis | Linked to a Form | Multi-variable view |
| **Funnel** | Conversion pipeline | Linked to a Form | Staged analysis |
| **Radar / Polar** | Multi-KPI comparison | Linked to a Form | Spider chart |
| **Geo Map** | Geographic data | Linked to a Form | Region coloring |
| **Tile** | Large KPI number box | Linked to a Form | Conditional coloring |
| **Gauge** | Dial/bar vs target | Linked to a Form | Red/Yellow/Green zones |
| **URL** | External website | URL string | Iframe embedding |
| **Commentary** | Text input | User-typed | Narrative reporting |

### Dashboard Properties — Every Configuration Option

| Property | Location | Options | Default |
|----------|----------|---------|---------|
| **Name** | General Tab | Free text | "Untitled" |
| **Folder** | General Tab | Library path | /Dashboards |
| **Instructions** | General Tab | Rich text or URL | None |
| **Global POV** | General Tab | Enable/Disable | Enabled |
| **Layout** | Canvas | Drag-resize | Auto |
| **Component Count** | Canvas | Max 12 | 0 |
| **Height %** | Per component | 10-100% | Auto |
| **Width** | Per component | 1-4 columns | Auto |
| **Edit Without Data** | Toolbar | Yes/No | No |
| **Master-Detail** | Component Settings | Tag as Master | Not set |

### Limits and Constraints — Complete List

| Constraint | Limit | Impact |
|-----------|-------|--------|
| **Max components per dashboard** | 12 (recommended 4-6) | Beyond 6 → browser lag |
| **Max tiles per tile component** | 10 | Each = 1 Essbase intersection |
| **Max total cells across all forms** | ~50,000 | Beyond → timeout/crash |
| **Recommended load time** | < 3 seconds | Users abandon at 5+ seconds |
| **Simultaneous Essbase queries** | = component count | 6 components = 6 parallel queries |
| **External URL protocol** | HTTPS only | HTTP blocked by browsers |
| **External URL CORS** | Target must allow iframe | Google, Salesforce etc. blocked |
| **Image size** | Max 2MB | Large images slow rendering |
| **Dashboard per form** | No hard limit | Check via "Show Usage" |

### Master-Detail Linking — Step-by-Step

```
1. CREATE MASTER FORM:
   "Hotel_Summary" → Entity on Rows, Revenue+Expenses on Columns
   
2. CREATE DETAIL FORM:
   "Hotel_Monthly" → Account on Rows, Jan-Dec on Columns, Entity on POV

3. ADD BOTH TO DASHBOARD

4. SELECT "Hotel_Summary" → Properties → "Tag as Master"

5. DIMENSION MAP:
   Master Entity (Rows) → Detail Entity (POV)

6. USER EXPERIENCE:
   Right-click "Mumbai_Taj" in Master → "Apply Context"
   → Detail form's Entity POV changes to Mumbai_Taj
   → Detail refreshes showing Mumbai data only

7. LINKED CHARTS AUTO-REFRESH TOO:
   Any chart linked to the Detail form also updates
```

### Global POV Behavior

```
GLOBAL POV BAR (Top of Dashboard):
┌──────────────────────────────────────────────────────┐
│ Scenario: [Actual ▼]  Year: [FY26 ▼]  Version: [Final ▼] │
└──────────────────────────────────────────────────────┘

BEHAVIOR:
   → Changing "Scenario" in the Global POV changes it
     for ALL components on the dashboard simultaneously
   → All forms, charts, tiles re-query with new scenario
   → Single point of control for the entire dashboard

OVERRIDE:
   → Individual forms can have "Fixed POV" that ignores
     the Global POV for specific dimensions
   → Example: Tile always shows "Actual" even when user
     switches Global POV to "Budget"
```

## MISTAKES — Common Errors & Fixes

| # | Mistake | Symptom | Fix |
|---|---------|---------|-----|
| 1 | Too many components | Dashboard timeout | Reduce to 4-6, enable suppression on all forms |
| 2 | Master-Detail not tagged | Click does nothing | Select form → Properties → "Tag as Master" |
| 3 | Form deleted/modified | Dashboard shows error | Check "Show Usage" before modifying forms |
| 4 | Tile shows ₹0 | Hidden columns in source form | Remove hidden columns, verify first visible column |
| 5 | Chart not refreshing after save | BSO/ASO sync issue | Enable Smart Push "Run After Save" on data entry form |
| 6 | External URL blank | CORS policy | Target site must allow iframe; use HTTPS only |
| 7 | Gauge shows wrong color | Boundary range issue | Set exclusive upper bounds (74.99, not 75) |

## TEST ME — Interview Questions

### 🟢 Beginner
**Q: What objects can you place on a Dashboard 2.0?**
> Forms (grids), Charts (bar/line/pie/combo/waterfall/scatter/gauge/geo), Tiles (KPI boxes), External URLs, and Commentary (text). Maximum recommended: 4-6 components.

### 🟡 Intermediate
**Q: A dashboard with a data entry form and a pie chart powered by the ASO reporting cube. User saves data, but chart doesn't update. Why?**
> The data entry form writes to BSO. The chart reads from ASO. Saving BSO data doesn't automatically push to ASO. Fix: Configure Smart Push on the data entry form with "Run After Save" enabled, targeting the ASO cube. Then enable dashboard component refresh on save.

### 🔴 Architect
**Q: Design a role-based dashboard strategy for a 500-entity global company.**
> Create 3 dashboard tiers: (1) **C-Suite Dashboard** — 3 KPI tiles + trend chart + global summary grid with master-detail by Region → Entity drill-down. Read-only, powered by ASO cube. (2) **Regional Manager Dashboard** — Region-filtered P&L grid (editable for adjustments) + variance waterfall chart + staff cost gauge. BSO cube with Smart Push. (3) **Analyst Dashboard** — Full data entry forms + action buttons (run business rules) + ad-hoc grids. BSO cube. Each tier assigned via Navigation Flow with role-based visibility. Dashboard count: ~10 total (3 global + 5 regional + 2 operational). Forms per dashboard: max 4. Total cell count per dashboard: under 50K.

## Back End Architecture

```
STORAGE:
   Dashboards are stored in: Relational Data → Dashboards
   They do NOT store data — they render underlying Forms

LCM MIGRATION:
   Export: Relational Data → Dashboards (artifact type)
   Must migrate WITH dependent forms:
   ├── Dashboard "Revenue_Dash" depends on:
   │   ├── Form "KPI_Summary"
   │   ├── Form "Revenue_Trend"
   │   └── Form "Revenue_Mix"
   └── If forms are missing in target environment → Dashboard breaks

DEPENDENCY CHAIN:
   Dashboard → Form → Cube → Dimensions → Members
   Delete any link in this chain → Dashboard fails
```
