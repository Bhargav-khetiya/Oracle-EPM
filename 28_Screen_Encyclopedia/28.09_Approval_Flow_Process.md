# Approval Flow Process

The Approvals functionality in EPM Cloud dictates the formal budget approval process. It enforces data locking and routing based on an organizational hierarchy.

## 1. The Core Concept: Approval Units

An "Approval Unit" is a specific slice of data that is moving through the approval process. It is almost always defined by the **Entity** dimension (e.g., Cost Center 100), combined with Scenario and Version (e.g., Budget -> Working).

*   **Ownership:** An Approval Unit has an "Owner" and "Reviewers". Only the current Owner can edit data in that slice.
*   **Data Locking:** When a unit is submitted to the next level, it becomes read-only for the previous owner.

## 2. End-to-End Budget Approval Process

The standard state transition (front end flow) is:

1.  **Start:** The Administrator clicks "Start" on the Approval hierarchy. All entities are unlocked. Ownership drops to the lowest level planners.
2.  **Under Review (Promote):** A planner finishes their budget for Cost Center 100. They click **Promote**. The ownership transfers to their manager. Cost Center 100 is now read-only for the planner.
3.  **Approve / Reject:** The manager reviews the data. 
    *   If they click **Approve**, the unit is locked entirely.
    *   If they click **Reject**, ownership transfers back to the planner, and the data unlocks for them to fix.
4.  **Sign Off:** A final state for auditors or executives who don't approve but need to lock the record.

## 3. Back End Configuration

Setting up Approvals requires defining a specific hierarchy.

*   **Approval Hierarchy:** You select a parent in the Entity dimension (e.g., "Total Company"). The system automatically creates an approval routing path based on the dimension tree.
*   **Secondary Dimensions:** You can optionally add a secondary dimension to the approval unit. For example, if "Product" is added, the approval unit becomes Entity + Product. A manager could approve "Cost Center 100 -> Software Sales" while leaving "Cost Center 100 -> Hardware Sales" open. *Warning: This makes the approval process exponentially more complex.*
*   **Validation Rules:** You can attach Data Validation rules to the promotion process. If Cost Center 100 has a negative Net Income, the system can block the user from clicking "Promote" until they fix it.

## 4. Notable Roles

*   **Owner:** Has write access.
*   **Reviewer:** Has read access while someone else owns it; gains write access when promoted to them.
*   **Viewers:** Always read-only.
*   **Administrator:** Can force-promote, force-reject, or take ownership of any unit at any time to fix bottlenecks.
