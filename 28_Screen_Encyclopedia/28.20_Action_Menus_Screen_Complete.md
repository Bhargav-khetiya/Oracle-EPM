## 1. WHY — What Problem Do Action Menus Solve?

**The problem:** When a user is in a form and right-clicks on a cell, row, or column, by default nothing useful happens. But users often want to quickly:
- Jump to a related form with the current context (entity, period)
- Launch a business rule directly from the form
- Navigate to the approval workflow for the current data
- Open a dashboard showing the data they just entered

**The solution:** Action Menus (also called right-click menus or context menus) let Service Administrators define custom right-click options that appear when users interact with forms, performing actions based on the current form context (POV, page, row, column selection).

**Hotel Pvt Ltd use case:** A planner enters room revenue for Mumbai hotel. They right-click → "Calculate Hotel P&L" (launches the rollup business rule). Or they right-click → "View Dashboard" (opens the Hotel Performance dashboard with the same POV). This is a high-value consultant skill — it significantly improves user experience.

---

## 2. WHAT — Plain English Definition

Action Menus are **administrator-configured right-click context menus** that attach to:
- Data input forms
- Ad hoc grids

When a user right-clicks in a form, the configured menu options appear. Each option can:
1. **Open a URL** (with optional form context passed in)
2. **Navigate to another form** (carrying the current POV/page context)
3. **Launch a business rule** (with or without runtime prompts)
4. **Open the Approvals workflow** (for a specific scenario/version)
5. **Open a Dashboard**
6. **Act as a header** (for grouping menu items with a separator)

## 5. MENU ITEM TYPES — COMPLETE REFERENCE

### Type 1: URL
```
Configuration:
  URL: https://your-url.com/page?entity=<Entity>&scenario=<Scenario>
  
  Use Form Context: ☑ (replaces <Entity>, <Scenario> etc. with actual member names)
    Example URL with context: https://yoursite.com/?E=<Entity>&S=<Scenario>
    Result at runtime: https://yoursite.com/?E=Mumbai_Hotel&S=Budget
  
  Behavior: Always opens in a new browser tab
```

**Allowed URL types:**
```
✅ https:// only
✅ Your company's internal portals (with SSO)
✅ Oracle Analytics Cloud (with SSO)
✅ Public web pages
❌ http:// (insecure)
❌ Another full EPBCS instance embedded
```

### Type 2: Form
```
Configuration:
  Form Folder: [Hotel Forms/Revenue]
  Form: [Hotel Room Revenue Entry]
  
  Behavior: Opens form in web browser context
             In Smart View: Opens the form in Smart View
             Flex forms: Open as flex forms in Smart View, simple in web
  Context passing: Current POV + Page members are set in the target form
                   if those dimensions exist on the target form's Page
```

### Type 3: Business Rule
```
Configuration:
  Cube: [OEP_FS]
  Business Rule: [Calculate_P&L]
  View Type: Classic View OR Streamline View
  Window Title: [Run P&L Calculation]  (optional)
  OK Button Label: [Launch]  (optional)
  Cancel Button Label: [Cancel]  (optional)
  Launch Confirmation Message: [This will recalculate all P&L. Continue?]  (optional)
```

**Streamline View** vs **Classic View:**
```
Classic View: 
  All runtime prompts on one screen, standard layout
  
Streamline View:
  Each runtime prompt on its own line, cleaner layout
  Better for prompts with long dropdown lists
```

### Type 4: Manage Approvals
```
Configuration:
  Scenario: [Budget]
  Version: [Working]
  
  Behavior: Opens Manage Approvals pre-filtered to that Scenario/Version
  Use case: Quick access to approve/reject the data just entered
```

### Type 5: Dashboard
```
Configuration:
  Dashboard: [Hotel Performance Dashboard]
  
  Behavior: Opens dashboard in a new dynamic tab
             Cell context is retained from the source form
```

### Type 6: Menu Header
```
Configuration:
  Label: [Analysis Tools]  OR  Label: [-]  (for separator bar)
  
  Behavior: Creates a non-clickable group header or separator bar
             Can have child items added below it (Add Child option)
```

## 6. REQUIRED PARAMETERS — WHERE MENU SHOWS

The "Required Parameters" setting controls WHEN a menu item appears (which right-click context activates it):

| Setting | When Menu Item Shows |
|---------|---------------------|
| **None** | Always shows when user right-clicks anywhere in the form |
| **Row** | Shows when user right-clicks a row |
| **Column** | Shows when user right-clicks a column |
| **Point of View** | Shows when user right-clicks the POV area |
| **Page** | Shows when user right-clicks the Page selector |
| **Members Only** | Shows only when user right-clicks a member label cell (not a data cell) |
| **Cell Only** | Shows only when user right-clicks a data cell |
| **[Specific Dimension]** | Shows only when user right-clicks a member of that dimension |

**Examples:**
```
Required = Account    → Menu shows only when right-clicking Account members
Required = Row        → Menu shows when right-clicking any row
Required = None       → Menu always shows (in the form's context menu)
```

> ⚠️ **Smart View limitation:** For action menus attached to forms (simple or flex), the Page and POV options are NOT supported in Smart View.

## 7. AD HOC MENUS — GLOBAL RIGHT-CLICK MENUS

An **ad hoc menu** is a special type of action menu that is NOT attached to a specific form. Instead, it is **enabled for all ad hoc grids** within selected cubes.

**Creating an ad hoc menu:**
```
1. Navigator → Create and Manage → Action Menus
2. Actions → Create Menu
3. Enter Menu Name
4. Check: Enable for Ad Hoc ☑
5. Select Cubes: All Cubes OR specific cubes
6. Click OK
7. Add menu items (URL, Form, Business Rule, etc.)
8. Save
```

**Where ad hoc menus appear:**
- Any ad hoc grid using the selected cube(s)
- Smart View ad hoc grids using those cubes

**Use case at Hotel Pvt Ltd:**
Create an ad hoc menu on the OEP_FS cube with:
- "Run Calculate Form" → Business Rule: Calculate_Form
- "View Hotel Summary" → Dashboard: Hotel_Summary_Dashboard

Now any analyst doing ad hoc analysis on OEP_FS gets these options.

## 8. ATTACHING MENUS TO FORMS

After creating an action menu, it must be ATTACHED to specific forms.

**How to attach:**
```
Path: Home → Data → [open a form] → Form Actions → Manage Properties → Other Options

Or in Form Designer:
Other Options tab → Action Menu → [Select from list]
```

Once attached, users see the right-click options when working in that form.

**Multiple forms, one menu:** You can attach the same menu to multiple forms.
**Multiple menus, one form:** You can attach multiple menus to one form.
**Can't delete if attached:** If a menu is in use by a form, you must first remove it from the form, then delete the menu.

## 10. DO's AND DON'Ts

### ✅ DO
- **DO** use the Launch Confirmation Message for business rules that take >30 seconds — set user expectations
- **DO** use Form Context in URL action menus to pass the current selection (Entity, Scenario, Version) to the URL
- **DO** use Menu Header separators to organize menus with >4 items
- **DO** test menus in the web AND Smart View — behavior differs
- **DO** use Required Parameters = Row to avoid confusing menus showing in wrong contexts

### ❌ DON'T
- **DON'T** delete an action menu while it's still attached to forms — detach first
- **DON'T** use HTTP URLs — HTTPS only
- **DON'T** use spaces or special characters in the Menu Item name (only alphanumeric + underscore)
- **DON'T** use Page/POV context in Smart View — not supported
- **DON'T** create menus with >10 items without using headers/separators — overwhelming for users

## 11. INTERVIEW QUESTIONS

### Beginner
**Q: A user wants to right-click in a form and run a business rule. What do you need to configure?**
> **A:** You need to: (1) Create an action menu (Navigator → Action Menus → Create Menu). (2) Add a menu item of type "Business Rule", selecting the cube and business rule. Set the Required Parameters appropriately. (3) Attach the action menu to the form via the form's Other Options tab → Action Menu. Now when the user right-clicks in the form, the business rule option appears.

### Intermediate
**Q: You want to create a URL action menu that opens a SharePoint page specific to the entity and scenario the user is currently viewing. How do you configure this?**
> **A:** Create an action menu with a URL item. In the URL field, use dimension names in angle brackets: `https://company.sharepoint.com/hotel/<Entity>/budget/<Scenario>`. Enable the "Use Form Context" checkbox. At runtime, EPBCS replaces `<Entity>` with the actual entity member name (e.g., "Mumbai_Hotel") and `<Scenario>` with the actual scenario (e.g., "Budget"). The URL becomes: `https://company.sharepoint.com/hotel/Mumbai_Hotel/budget/Budget`. Note: SharePoint must be configured to allow oraclecloud.com in its Content Security Policy for this to work in an IFrame, or it will open in a new tab.

### Architect
**Q: You are designing a Hotel Pvt Ltd implementation where 5 different hotel entities all use the same "Revenue Entry" form but need different right-click menu options based on the entity. Hotel A has a special "Calculate Room Type Revenue" rule that Hotel B doesn't have. How do you handle this with action menus?**
> **A:** Action menus can't be filtered by dimension member (only by required dimension). The cleanest architectural solution is: (1) Create separate forms for each hotel entity (Hotel_A_Revenue, Hotel_B_Revenue) — this is good practice anyway for entity-specific configurations. (2) Create entity-specific action menus (Hotel_A_Menu with the special rule, Hotel_B_Menu without). (3) Attach Hotel_A_Menu to Hotel_A_Revenue form, and Hotel_B_Menu to Hotel_B_Revenue form. Alternatively, if forms must be shared, use the "Required Parameters" dimension filter: create the "Calculate Room Type Revenue" menu item with Required Parameters = Entity, then the menu only shows when the user right-clicks an Entity member cell — more a workaround than a clean solution. The cleanest is always entity-specific forms with entity-specific menus.
