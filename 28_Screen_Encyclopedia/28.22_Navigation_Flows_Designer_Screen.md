## 1. WHY — What Problem Does Navigation Flows Solve?

**The problem:** EPBCS has one fixed navigation structure by default. But different users (Finance Controllers, HR Planners, Mumbai Hotel managers, Service Admins) need completely different experiences. A planner shouldn't see admin screens; an admin needs everything.

**The solution:** Navigation Flows let you create **completely customized Home pages** for different user groups/roles — controlling exactly which cards are visible, in what order, with what icons and labels.

**Real consultant use:** On every EPBCS project, you will be asked to configure navigation flows to present a clean, role-appropriate interface to business users. This is often one of the first configuration tasks after the core application is built.

---

## 2. WHAT — Plain English Definition

A Navigation Flow is a **configuration template** that defines:
- Which cards (icons) appear on the Home page
- What order they appear in
- What labels/icons they use
- Which tabs appear inside each card
- Whether those tabs show forms, dashboards, reports, or external URLs

Think of it like a **menu system designer** for the EPBCS home page.

## 5. EVERY ELEMENT — COMPLETE PROPERTY REFERENCE

### Navigation Flow Level Properties

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| **Name** | Text | Yes | Unique name — max characters, no special chars (&<>"\\+) |
| **Assign To** | Dropdown | No | Assign to a role OR a group (not both) |
| **Description** | Text | No | Free-text description |
| **Active toggle** | Toggle | — | Only one per category (global/role/group) can be active |

### Card-Level Properties (Add Card dialog / Edit Card page)

| Property | Options | Impact |
|----------|---------|--------|
| **Name** | Text (max 25 chars) | Label shown on Home page icon |
| **Visible** | ☑ / ☐ | Controls if card appears on Home page |
| **Cluster** | None / existing cluster name | Assigns card to a cluster (group) |
| **Icon** | Oracle icon library | Graphic shown on the card tile |
| **Page Type** | Single Page / Tabular Page | Single: opens one form/URL. Tabular: shows tabs |
| **Content Source** (Single) | Artifact / URL | Select a form/dashboard/report OR enter HTTPS URL |
| **Orientation** (Tabular) | Vertical / Horizontal | Tab layout style |

### Tab-Level Properties (within a Tabular Page card)

| Property | Options | Impact |
|----------|---------|--------|
| **Name** | Text | Tab label (max 30 chars shown; hover reveals full) |
| **Visible** | ☑ / ☐ | Show/hide the tab |
| **Content Source** | Artifact / URL | What the tab shows |
| **Sub Tabs** | Yes/No (Page Type = Tabular) | Tabs can have their own horizontal sub-tabs |

### Cluster-Level Properties

| Property | Options | Impact |
|----------|---------|--------|
| **Name** | Text | Label for cluster "parent" icon |
| **Icon** | Oracle icon library | Graphic for cluster icon |
| **Visible** | ☑ / ☐ | Show/hide the cluster |
| **Cards in cluster** | Multi-select | Which cards live inside this cluster |

## 6. NAVIGATION FLOW CATEGORIES

| Category | One Active Flow Allowed | Description |
|----------|------------------------|-------------|
| **Global** | Yes | Default for all users with no other matching flow |
| **Role-based** | Yes per role | Overrides Global for users with that role |
| **Group-based** | Yes per group | Most specific — overrides role and global |

**Priority Order (most specific wins):**
```
Group-based  >  Role-based  >  Global
```

## 7. DESIGN LIMITS (Oracle Guidelines)

| Element | Maximum Visible | If Exceeded |
|---------|----------------|-------------|
| Top-level cards/clusters | 20 | Warning message shown |
| Cards within a cluster | 16 | Warning message shown |
| Vertical tabs within a card | 10 | Warning message shown |
| Horizontal sub-tabs within a vertical tab | 20 | Warning message shown |
| Card label characters | 25 | Truncated |
| Sub-tab label (horizontal) | 30 chars shown at runtime | Hover reveals full label |

## 8. WHAT CANNOT BE CHANGED OR REMOVED

| Element | Restriction |
|---------|-------------|
| **Default** navigation flow | Cannot delete, cannot edit (only view/duplicate/activate) |
| **Active** navigation flow | Cannot rename or delete (must deactivate first) |
| **Application cluster** | Cannot remove from navigation flow |
| **Settings icon** (inside Application) | Cannot remove |
| **Tools cluster** | Cannot remove |
| **Access Control** (inside Tools) | Cannot remove |
| **Navigation Flows** (inside Tools) | Cannot remove |
| **Daily Maintenance** (inside Tools) | Cannot remove |
| **Migration** (inside Tools) | Cannot remove |

## 9. SPECIAL FEATURES

### User Access View (Preview Mode)
Navigate: Navigation Flows → select flow → Actions → User Access View
- Select any user from the group assigned to the flow
- See EXACTLY what they see on their Home page
- Icons show which nodes they can't access:
  - 🚫 Red icon = No Access at all
  - ⚠️ Yellow icon = Partial Access (some tabs inaccessible)
- Great for UAT and troubleshooting "why can't I see X?"

### Validate Option
Navigate: Select flow → Actions → Validate
- Finds all navigation flow nodes pointing to **deleted or renamed artifacts**
- Shows error icons next to broken nodes
- Must fix by reassigning the artifact (Choose Artifact button)
- Best practice: Run Validate before setting any flow to Active

### Reloading a Navigation Flow
After making design changes, to see them immediately (without logging out):
- Click your username → Settings and Actions → **Reload Navigation Flow**
- OR on the Home page: click the Navigation Flow icon → **Reload**

### Import/Export via Snapshots (LCM)
Navigation flows are included in LCM (Migration) snapshots. When importing:
- If an active flow of the same category exists, the imported flow becomes **Inactive**
- Must manually activate after import (to avoid accidental cutover mid-cycle)

## 10. URL EMBEDDING — RULES AND GOTCHAS

You can embed third-party URLs in cards/tabs. Rules:
```
✅ Allowed:
   • HTTPS URLs only (no HTTP)
   • External sites with CSP headers allowing oraclecloud.com
   • Public domain pages (Wikipedia, etc.)
   • Google Sheets / Google Drive files (with share link)
   • Microsoft Office 365 files
   
❌ NOT Allowed:
   • HTTP (insecure) URLs
   • Internal/relative URLs
   • Third-party sites that don't consent to embedding
   • Full other Cloud EPM environments (e.g., don't embed Narrative Reporting)
```

**IFrame Requirement:** The third-party site must add `oraclecloud.com` to its Content Security Policy. For Oracle Analytics Cloud embedding, SSO must be enabled.

**Workaround for auth-required pages:** Log in to the third-party site in another browser tab first, then the embedded IFrame may show the authenticated page.

## 11. HOTEL PVT LTD EXAMPLE

### Hotel Pvt Ltd — Navigation Flow Design

**Requirement:** 
- Planners (Mumbai, Delhi, Bangalore hotels) should see only their hotel's planning forms
- Finance Controllers see all financial forms + reports
- HR sees only Workforce forms
- Service Admins see everything

**Design:**

```
Navigation Flow: Hotel_Planner_Mumbai
├── Assign To: Mumbai_Planners_Group
├── Cards:
│   ├── My Hotel Forms (Tabular, Vertical tabs)
│   │   ├── Revenue Entry [Mumbai Revenue Form]
│   │   ├── Expense Entry [Mumbai Expense Form]  
│   │   └── Capital Request [Mumbai CAPEX Form]
│   ├── Approvals [Approval Workflow]
│   └── Task List [Mumbai Planning Tasks]
└── Hidden: Application, Tools, Dashboards (admin), Rules

Navigation Flow: Hotel_Finance
├── Assign To: Finance_Controllers_Group
├── Cards:
│   ├── Financial Forms (cluster)
│   │   ├── All Revenue Forms
│   │   └── Expense Summary
│   ├── Dashboards [Hotel Portfolio Dashboard]
│   ├── Reports [P&L Report, Variance Report]
│   └── Approvals [Final Approval Step]
└── Hidden: Application, Tools (admin)

Navigation Flow: Hotel_Admin
├── Assign To: Service_Administrator role
├── Cards: ALL (including Application and Tools)
└── Active: Yes
```

## 12. DO's AND DON'Ts

### ✅ DO
- **DO** create separate navigation flows per group/role (avoid one global flow for all)
- **DO** run Validate before activating a navigation flow
- **DO** use User Access View to test what users see before go-live
- **DO** keep card labels to ≤20 characters (even though 25 is allowed — looks better on Home page)
- **DO** use clusters to group related cards when you have more than 8-10 items
- **DO** use Reload Navigation Flow (not log out/log in) during design testing

### ❌ DON'T
- **DON'T** edit the Default navigation flow (it's read-only)
- **DON'T** activate a navigation flow mid-business-cycle without UAT
- **DON'T** exceed the visibility limits (20 top-level, 16 per cluster, 10 tabs, 20 sub-tabs)
- **DON'T** use special characters (&<>"\\+) in navigation flow/card/tab names
- **DON'T** use HTTP URLs — HTTPS only
- **DON'T** embed a full other Cloud EPM instance inside a card
- **DON'T** confuse importing navigation flows from LCM — they always import as Inactive

## 13. NAMING RESTRICTIONS

The following special characters are **BANNED** from navigation flow/card/cluster/tab names:
- `&` (ampersand)
- `<` (less than)
- `>` (greater than)
- `"` (quotation mark)
- `\` (backslash)
- `+` (plus sign)

## 14. INTERVIEW QUESTIONS

### Beginner
**Q: What is the difference between a Card and a Cluster in Navigation Flows?**
> **A:** A Card is a single icon on the Home page that links to a specific area (Single Page) or displays multiple tabs (Tabular Page). A Cluster is a "group" of cards — when you click a cluster icon, it expands to show the cards inside it. Clusters are used to organize many cards into logical groupings without cluttering the Home page. For example, you might have an "EPBCS Planning" cluster that contains Revenue, Expense, and Headcount cards.

### Intermediate
**Q: You made changes to a navigation flow in the designer, but the Home page still shows the old layout. What do you do?**
> **A:** You need to reload the navigation flow without logging out. Click your username in the top-right → Settings and Actions → **Reload Navigation Flow**. Design changes are not reflected in real-time; they only take effect after a reload (which is equivalent to refreshing the navigation flow cache for your session).

### Architect
**Q: You import a migration snapshot from TEST to PROD. The snapshot contains an active global navigation flow "Hotel_Custom_NF". After import, users in PROD still see the old Default navigation flow. Why and how do you fix it?**
> **A:** When importing a snapshot, if an active navigation flow of the same category (global) already exists in PROD, the imported navigation flow becomes Inactive automatically. This is by design — Oracle doesn't want an import to accidentally activate a flow in PROD during a migration that might happen before the target go-live date. The fix: go to Tools → Navigation Flows → find "Hotel_Custom_NF" (now showing Inactive) → click the Active column to set it to Active. The old Default or any other active global flow will then automatically become Inactive. No downtime needed, but expect a brief layout change for users.
