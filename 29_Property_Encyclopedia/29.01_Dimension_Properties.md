## 1. Learning Objectives

## 3. Introduction
When you add a member to a dimension (e.g., `Revenue`), you don't just give it a name. You configure properties that dictate exactly how the Essbase engine calculates, stores, and displays that member. A single wrong property choice can break the entire balance sheet.

## The Properties

### 1. Data Storage
Dictates how the member interacts with the hard drive.
- **Store:** The default for level-0 members. The data is physically saved to the `.pag` file on the hard drive.
- **Dynamic Calc:** The default for upper-level ASO members, and Hybrid BSO parents. The data is NEVER saved to the hard drive. When a user queries this member, the Essbase engine calculates the math on the fly in RAM and returns the answer.
- **Dynamic Calc & Store:** Rarely used. Calculates in RAM the first time, then saves it to disk for the second query. 
- **Shared:** Used in Alternate Hierarchies. Points to the original stored member so data is not physically duplicated.
- **Never Share:** Overrides the "Implied Sharing" feature of Essbase, ensuring the parent is physically calculated and stored independently of a single child.

### 2. Consolidation Operator
Dictates how this member rolls up to its parent.
- **(+) Addition:** Default. Adds to parent.
- **(-) Subtraction:** Used for Contra-Accounts (e.g., `Returns and Allowances` rolls up to `Net Sales` with a minus sign).
- **(*) Multiplication / (/) Division / (%) Percent:** Used for complex custom rollups.
- **(~) Ignore:** Crucial. The member does NOT roll up to the parent. *Architect Rule:* Always use `~` for Rates (e.g., `Tax Rate = 20%`), Prices, and Smart List IDs. Adding two 20% tax rates together to get 40% at the parent level is mathematically invalid.

### 3. Time Balance (Account Dimension Only)
Dictates how parent time periods (e.g., `Q1`) aggregate their children (`Jan`, `Feb`, `Mar`).
- **Flow:** Default. `Q1 = Jan + Feb + Mar`. Used for Income Statement accounts (Revenue, Expense).
- **First:** `Q1 = Jan`. 
- **Last:** `Q1 = Mar`. Crucial for Balance Sheet accounts (e.g., `Cash on Hand`). Your Q1 Cash is not the sum of Jan + Feb + Mar; it is whatever the balance was on the last day of March.
- **Average:** `Q1 = (Jan + Feb + Mar) / 3`. Used for Headcount reporting.

### 4. Skip Options (Used with Time Balance)
What happens if the Time Balance is set to `Last`, but `Mar` has no data (`#Missing`)?
- **None:** `Q1 = #Missing`.
- **Missing:** If `Mar` is missing, the engine skips backward and uses `Feb`. If `Feb` is missing, it uses `Jan`. This is the standard best practice for Balance Sheets to ensure a balance carries forward until changed.

## Interview Questions

### Architect
**Q: You have an Account called `Inventory_Balance`. It is set to Time Balance: Last, Skip: Missing. In Jan it is 100. In Feb it is 0. In Mar it is `#Missing`. What is the value of Q1?**
> A: The value of Q1 is **0**. Essbase looks at Mar, sees `#Missing`, triggers the "Skip Missing" rule, and goes to Feb. Feb has a value of `0`. (0 is a real number, not missing). It accepts `0` and returns it as the Q1 balance.
