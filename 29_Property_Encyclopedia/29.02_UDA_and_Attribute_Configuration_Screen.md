# 28.02 UDA and Attribute Configuration Screen

> **Module:** 28_Property_Encyclopedia  
> **Topic:** 02 - Attributes and UDAs  
> **Target Audience:** Administrator  

---

## Navigation
**Navigator -> Dimensions -> [Dimension Name] -> Custom Attributes / UDA Tab**

## Overview
When the primary hierarchy is not enough, you must tag members with metadata. 
- A **UDA (User Defined Attribute)** is a simple text tag (e.g., `New_Store`).
- An **Attribute Dimension** is a structured, hierarchical tag that physically alters the Essbase index (e.g., `Store_Size: 5000_sqft`).

## Section 1: UDA Configuration (The Simple Tag)

### Creating a UDA
1. Select the Dimension (e.g., `Entity`).
2. Click the **UDA** tab.
3. Click the **+** icon.
4. Type the name: e.g., `Same_Store_Sales`.

### Applying a UDA
1. Edit a member (e.g., `Store_101`).
2. Go to the UDA tab on the member properties.
3. Move `Same_Store_Sales` from the Available box to the Selected box.

### Architectural Impact of UDAs
- **Storage:** UDAs take up ZERO physical space in the Essbase block.
- **Speed:** Extremely fast for Business Rules. You can write `FIX(@UDA("Entity", "Same_Store_Sales"))` and Essbase will instantly find every store with that tag.
- **Reporting:** Terrible for reporting. You cannot easily put a UDA on the Rows of a Web Form to say "Show me Total Revenue for all Same_Store_Sales." UDAs are filters, not aggregators.

## Section 2: Attribute Dimension Configuration (The Structured Tag)

### Creating an Attribute Dimension
1. Go to the classic Dimension Editor.
2. Click the **+** icon to create a brand new dimension.
3. Set the Type to **Attribute**.
4. Set the Data Type: `Text`, `Numeric`, `Boolean`, or `Date`.
5. Name it: e.g., `Store_Square_Footage`.

### Attaching the Attribute to a Base Dimension
1. Edit the base dimension (e.g., `Entity`).
2. Go to the Custom Attributes tab.
3. Link the `Store_Square_Footage` dimension to the `Entity` dimension.

### Applying an Attribute to a Member
1. Edit `Store_101`.
2. Go to the Attribute Values tab.
3. Select `5000_sqft` from the dropdown.

### Architectural Impact of Attribute Dimensions
- **Storage:** Creates a secondary index in the Essbase `.ind` file. It increases the index size but does not explode the block size.
- **Speed:** Slower than UDAs for calculation scripts, because the engine has to cross-reference the secondary index.
- **Reporting:** Phenomenal. You can put `Store_Square_Footage` on the Rows of a Web Form, and `Account` on the Columns, and Essbase will dynamically calculate (in RAM) the Total Revenue for all 5000 sqft stores.

## 25. Interview Questions

### Intermediate
**Q: A user wants to tag a list of Employees with their "Hire Date". They want to be able to write a calculation script that says "If Hire Date > Jan 1 2024, calculate bonus." Should you use a UDA or an Attribute?**
> A: You must use an **Attribute**. UDAs are simple text strings; they cannot handle mathematical operators like Greater Than (`>`). An Attribute dimension can be configured with a Data Type of `Date`, allowing the Essbase engine to evaluate chronological logic.

### Architect
**Q: You attach an Attribute dimension to the `Entity` dimension. You then try to assign the attribute to the parent member `Total North America`. The system throws an error. Why?**
> A: By the laws of Essbase physics, Attribute dimensions can ONLY be assigned to Level-0 (leaf) members of a Sparse dimension. You cannot assign an attribute to a Parent member. If `North America` is a parent, you must assign the attribute to the child stores beneath it, and the attribute engine will handle the dynamic rollup.
