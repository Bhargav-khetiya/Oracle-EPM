# 28.03 Currency and Exchange Rate Properties

> **Module:** 28_Property_Encyclopedia  
> **Topic:** 03 - Multi-Currency Configuration  
> **Target Audience:** Solution Architect  

---

## Navigation
**Navigator -> Application -> Settings -> [Currency Tab]** (If Multi-Currency is enabled).

## Overview
Global companies do business in 50 currencies. The Board of Directors only wants to see the final report in USD. Oracle EPBCS handles this via a dedicated Currency dimension and Exchange Rate tables.

## The Architecture of Multi-Currency

If you enable "Multi-Currency" during application creation, Oracle creates a hidden, locked dimension called `Currency`.

### The Currency Dimension Properties

#### 1. Input Currencies (Local)
- **Examples:** `GBP`, `EUR`, `JPY`.
- **What it does:** This is the currency the local manager types their budget into. The London manager opens a form, the POV defaults to `GBP`, and they type £1,000.

#### 2. Reporting Currencies (Converted)
- **Examples:** `USD_Reporting`, `EUR_Reporting`.
- **What it does:** These are read-only members. The system takes the `GBP` input, multiplies it by the exchange rate, and stores the answer in `USD_Reporting`.

## The Exchange Rate Table Screen

**Navigator -> Data -> Exchange Rates**

### Every Configuration Property

#### 1. Average Rate vs Ending Rate
You cannot use the same exchange rate for the entire Income Statement and Balance Sheet. That violates GAAP accounting.

- **Average Rate:** 
  - **Where to apply:** Income Statement (Revenue, Expense).
  - **Why:** Revenue is earned evenly throughout the month, so you use the average exchange rate for that month.
- **Ending Rate:** 
  - **Where to apply:** Balance Sheet (Cash, Inventory).
  - **Why:** Cash is a snapshot on the absolute last day of the month. You must use the exchange rate active on 11:59 PM of that final day.

#### 2. The Rate Data Grid
- **Rows:** The Input Currencies (`GBP`, `JPY`).
- **Columns:** The Periods (`Jan`, `Feb`).
- **Intersection:** You type the exact rate (e.g., `1.25`).

### The Hidden Essbase Math (Architect Knowledge)
When you run the "Calculate Currencies" Business Rule, what is Essbase physically doing?
It is running a massive script that says:
`USD_Reporting = GBP * [Average_Rate];`

**The Block Explosion Danger:**
If you have 50 currencies, the Currency calculation script has to read every single sparse block in the database, multiply it by the rate, and physically create a brand new block for `USD_Reporting` on the hard drive. 
- In standard BSO, this takes 4 hours.
- **The Architect's Fix:** Enable **ASO Reporting**. Push the local `GBP` data to the ASO reporting cube. The ASO cube has built-in dynamic currency conversion that multiplies the rate in RAM the exact second the CEO opens the dashboard, completely eliminating the 4-hour BSO script.

## 25. Interview Questions

### Architect
**Q: A user types $1,000 into a Revenue account in USD. The Exchange Rate to EUR is 0.90. The user runs the Currency Conversion script. They look at `EUR_Reporting`, but the cell is empty (`#Missing`). Why?**
> A: Check the `Account` dimension properties. Every account has a property called "Exchange Rate Type". If the "Exchange Rate Type" for the Revenue account was accidentally left blank (instead of being assigned to "Average"), the Currency calculation script will explicitly skip that account, because it doesn't know which rate table to multiply it against.
