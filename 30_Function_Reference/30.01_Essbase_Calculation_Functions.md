# 29.01 Essbase Calculation Functions

> **Module:** 29_Function_Reference  
> **Topic:** 01 - Essbase Core Functions  
> **Target Audience:** Architect / Developer

## The `@` Functions

Every native Essbase function begins with the `@` symbol. They are used in Business Rules and Member Formulas.

### `@SUM`
- **Purpose:** Adds a range of members together.
- **Syntax:** `@SUM(SKIPMISSING, "Jan":"Mar")`
- **Architect Note:** Faster than writing `Jan + Feb + Mar`, especially when dealing with `#Missing` data.

### `@AVG`
- **Purpose:** Averages a range of members.
- **Syntax:** `@AVG(SKIPMISSING, "Jan":"Mar")`
- **Architect Note:** Always use `SKIPMISSING`. If Jan is 100, Feb is 200, and Mar is `#Missing`, `SKIPMISSING` divides by 2 (Result: 150). If you use `INCZERO`, it divides by 3 (Result: 100).

### `@PRIOR`
- **Purpose:** Fetches data from a previous member in the dimension (usually Time).
- **Syntax:** `@PRIOR("Account_Name", 1, "Period")`
- **Use Case:** Calculating variance against prior month, or carrying forward a balance sheet amount.

### `@ANCESTORS` / `@DESCENDANTS` / `@CHILDREN` / `@SIBLINGS`
- **Purpose:** Relative dimensional targeting.
- **Syntax:** `@DESCENDANTS("Total Geography")`
- **Architect Note:** Never hardcode a list of 50 states in a `FIX` statement. Use `@IDESCENDANTS("USA")` (Inclusive Descendants). If the client adds a new state next month, the script dynamically picks it up without requiring code maintenance.

### `@UDA`
- **Purpose:** Filters a dimension by a User Defined Attribute.
- **Syntax:** `@UDA("Product", "Red")`
- **Architect Note:** Highly optimized for `FIX` statements.

### `@CALCMODE`
- **Purpose:** Forces the engine to evaluate math in a specific way.
- **Syntax:** `@CALCMODE(BOTTOMUP)` or `@CALCMODE(TOPDOWN)`
- **Architect Note:** Use with extreme caution. Forcing Bottom-Up on a formula that targets missing sparse blocks will result in the formula simply ignoring the blocks and failing to calculate.

### `@ALLOCATE`
- **Purpose:** Pushes a pool of money down to children based on a driver.
- **Syntax:** `@ALLOCATE("Overhead_Pool", @DESCENDANTS("Cost Centers"), "Headcount", , share)`
- **Architect Note:** This function is historically difficult to write from scratch due to its 8 complex parameters. Always use the Calculation Manager "System Template" wizard to generate `@ALLOCATE` syntax for you.

## System Settings (SET Commands)
These are not functions, but global directives for the script.

### `SET UPDATECALC OFF;`
- **Purpose:** Forces Essbase to calculate every block in the `FIX`, regardless of whether the block is marked as "dirty" or "clean".
- **Rule:** Always put this at the top of your Business Rules in EPM Cloud. 

### `SET AGGMISSG ON;`
- **Purpose:** Tells the aggregation engine to aggregate `#Missing` values just like real numbers.
- **Rule:** This drastically speeds up ASO and BSO aggregations because the engine doesn't have to pause and evaluate the block to see if it contains missing data; it just blindly sweeps the blocks up the hierarchy.

### `SET CREATENONMISSINGBLK ON;`
- **Purpose:** Forces Essbase to generate a physical block on the hard drive if a formula requires it, even if no data previously existed there.
- **Rule:** The most dangerous command in EPM. Use only on very tight `FIX` statements, or you will cause a block explosion.
