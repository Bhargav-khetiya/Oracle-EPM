## The Groovy API Toolkit

While native Essbase uses `@` functions, Groovy in Oracle EPM utilizes a massive Java-based object library. Below are the most critical objects and methods an Architect must memorize.

### 1. Context and Operation (`operation.application`)
The entry point to the EPM application.

**Get the current application:**
`def app = operation.application`

**Get a specific cube:**
`def cube = app.getCube("OEP_FS")`

### 2. The Data Grid (`DataGridBuilder` / `DataGridDefinition`)
The most powerful feature of Groovy is intercepting the data a user just typed into a Web Form *before* it hits the database.

**Get the current Web Form grid (Run Before Save):**
`DataGrid grid = operation.grid`

**Iterate through the rows the user edited:**
```groovy
grid.dataCellIterator({DataCell cell -> cell.isEdited()}).each { DataCell cell ->
    println("User changed ${cell.getMemberName("Account")} to ${cell.data}")
}
```
*Use Case:* High-speed data validation. Check if the cell value > 1,000,000 and throw a `VetoException` instantly.

### 3. Veto Exceptions (Blocking Actions)
If a user does something illegal, you must stop the HTTP request dead in its tracks.

**Syntax:**
```groovy
throw new VetoException("Error: You cannot increase salaries by more than 10%.")
```
*Effect:* The save action is aborted. The data does not reach Essbase. The user sees a red popup box with your exact error message.

### 4. Executing Calc Scripts (`evaluateCalcScript`)
Groovy is terrible at heavy multidimensional math. Essbase is incredible at it. The standard pattern is to use Groovy to figure out *what* needs to be calculated (e.g., finding exactly which Cost Center the user edited), building a dynamic string of Essbase code, and handing it to the Essbase engine.

**Syntax:**
```groovy
String script = """
FIX("Working", "FY24", "${editedCostCenter}")
    "Taxes" = "Salary" * 0.20;
ENDFIX
"""
cube.evaluateCalcScript(script)
```

### 5. Smart Push / Data Maps (`DataMap`)
Triggering asynchronous data movement.

**Syntax:**
```groovy
def myMap = operation.application.getDataMap("Push_Financials")
// Execute asynchronously (false) so the user doesn't wait
myMap.execute(false) 
```

### 6. REST API Connections (`HttpResponse`)
Reaching out to external systems (or calling EPM Automate jobs internally).

**Syntax:**
```groovy
def conn = operation.application.getConnection("My_ERP_Connection")
HttpResponse<String> response = conn.get("/api/v1/rates")
if(response.status == 200) {
    // parse JSON
}
```

## Architect Notes: The `println` Debugger
Groovy does not have an interactive step-through debugger in the Cloud. You must use `println`.
When you write `println("The value is ${myVar}");`, it prints that text directly to the **Jobs Console** log file. This is the only way to figure out why your variables aren't resolving correctly. Always check the Job Console when building Groovy rules.
