# 30.01 Common Essbase Errors

> **Module:** 30_Error_Encyclopedia  
> **Topic:** 01 - The Core Essbase Errors  
> **Target Audience:** Support / Admin / Architect  

---

## The Encyclopedia of Failure

### ERROR: 1042017 - Network error: The client or server timed out
- **What it means:** The Smart View query or Business Rule took too long, and the WebLogic server severed the connection.
- **The Cause:** You likely ran an Ad-Hoc query that requested 2 million rows, or a Business Rule triggered a Block Explosion.
- **Resolution:** Limit Smart View row returns in the application settings. Optimize the Calc Script `FIX` statement to target fewer blocks.

### ERROR: 1200315 - Error parsing formula. Member [X] not found.
- **What it means:** Calculation Manager or Essbase cannot find a string of text in the outline.
- **The Cause:** 
  1. A typo in the script.
  2. You added a new member but forgot to run "Refresh Database".
  3. You are referencing an Alias instead of a Member Name, and your script editor is not configured to accept aliases.
- **Resolution:** Run a DB Refresh, check your spelling, and always use Member Names in scripts.

### ERROR: 1200324 - Error executing formula: Division by Zero
- **What it means:** The script tried to divide a number by 0 or `#Missing`.
- **The Cause:** `Margin = Profit / Revenue`. If Revenue is 0, the block crashes.
- **Resolution:** Wrap the division in a conditional check:
  ```essbase
  IF("Revenue" <> 0)
      "Margin" = "Profit" / "Revenue";
  ENDIF
  ```

### ERROR: 1020043 - Outline has errors, cannot restructure
- **What it means:** You clicked "Refresh Database" and it failed instantly.
- **The Cause:** You broke an architectural rule in the Dimension Editor. Examples:
  1. You set a Parent member to `Store` instead of `Dynamic Calc` in a Hybrid application.
  2. You created two members with the exact same name (Duplicate Member violation).
  3. You created a Shared Member, but the original Primary Member doesn't exist.
- **Resolution:** Review the Job Console log; it will usually tell you exactly which member name violated the outline rules. Fix it in the Dimension Editor and refresh again.

### ERROR: 1013295 - Server is in read-only mode
- **What it means:** Users cannot save data.
- **The Cause:** An Administrator manually placed the application in Maintenance Mode via EPM Automate, or a massive database restructure crashed halfway through, leaving the database locked.
- **Resolution:** An Admin must run `epmautomate resetService` to restart the Pod, or manually unlock the database via the Application Overview settings.

### The Silent Error: Data Disappears After Aggregation
- **What it means:** A user enters data at Level-0. An Admin runs an aggregation script. The user refreshes the form, and the Level-0 data is completely gone.
- **The Cause:** The parent member was set to `Store`, and the aggregation script ran. However, a sibling of the Level-0 member had a `#Missing` block, and the aggregation engine overwrote the parent with `#Missing`, which then corrupted the calculation. Or, more likely, a `CLEARBLOCK` command was accidentally triggered before the data was pushed.
- **Resolution:** Never use `Store` parents if you can use Hybrid `Dynamic Calc`. It eliminates aggregation errors entirely.
