## The Integration Error Dictionary

When data fails to load from the ERP into EPM, the business panics. You must be able to diagnose Data Integration (FDMEE) errors in seconds.

### ERROR: "No data to load" (or 0 rows extracted)
- **What it means:** The Import step finished successfully, but it found zero rows of data in the source file or SQL query.
- **The Cause:** 
  1. The Source Period mapping is wrong (e.g., trying to pull Jan-24 data using a Dec-23 parameter).
  2. The flat file was uploaded, but it is completely empty.
  3. The ERP Source system returned a blank result set due to an aggressive SQL filter.
- **Resolution:** Check the Process Details log. Download the source file from the Inbox to verify it actually contains data.

### ERROR: "Data row ignored / Invalid Member"
- **What it means:** Data Management tried to push the data into Essbase (The Export Step), but Essbase rejected it.
- **The Cause:** 
  1. The data file contains a Cost Center (e.g., `CC_999`) that does not exist in the Essbase Dimension outline.
  2. The data file mapped a value to a parent member that is set to `Dynamic Calc` (you can only load data to `Store` level-0 members).
- **Resolution:** Open the Data Integration **Workbench**. Look for the rows highlighted in Red or Gray. The Workbench will explicitly tell you which member name was rejected. Add the missing metadata to Essbase, Refresh the Database, and re-export the data.

### ERROR: "Mapping Error (Unmapped Data)"
- **What it means:** The data made it into the staging table, but the translation engine doesn't know what to do with it (The Validate Step failed).
- **The Cause:** The Source ERP file has an account called `Acct_1001`, but nobody created a Data Mapping to translate `Acct_1001` into the target EPM account `Salary_Expense`.
- **Resolution:** Open the **Workbench**. Filter for Validation Errors (the orange icon). The system will show you the exact source strings that are unmapped. Go to the Data Mapping screen, add the explicit or wildcard mappings, and click re-validate.

### ERROR: "Staging Table Timeout / Hanging at 10%"
- **What it means:** The process starts but never gets past the initial Import stage.
- **The Cause:** The relational repository is bloated with millions of old records, causing the SQL insert statements to time out.
- **Resolution:** You must run the EPM Automate `maintainDataManagement` command to truncate the staging tables (e.g., purging data older than 30 days). 

### The Silent Error: Overwriting Data with Zeros
- **What it means:** The data load ran successfully. But when users log in, the numbers are completely wrong or wiped out.
- **The Cause:** The Export Mode in the Data Load Rule was set to **Replace** instead of **Merge**, but the data file only contained a partial subset of the data. The "Replace" mode cleared the entire target slice in Essbase before loading the tiny partial file, effectively deleting all other data in that slice.
- **Resolution:** Always use "Merge" (or "Store Data") for partial/incremental loads. Only use "Replace" for full month-end total re-loads.
