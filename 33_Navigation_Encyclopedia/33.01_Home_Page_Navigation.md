## 1. WHY â€” What Problem Does the Home Page Solve?

**The problem:** EPBCS has 100s of screens, admin functions, reports, forms, and rules. Without a central launchpad, every user would need to memorize deep URLs or multi-step navigation paths.

**The solution:** The Home Page is a **personalized launchpad** â€” a card-based interface that shows each user ONLY the areas they're permitted to access, in a way that can be customized by the Service Administrator using Navigation Flows.

**Consultant Use Case:** When you join a new client project, the Home Page immediately tells you:
- What modules are enabled (FinPlan, Workforce, Capital cards = EPBCS)
- What the admin has customized (custom cards, branding, clusters)
- What your role has access to (missing cards = no permission)

## 2. WHAT â€” Plain English Definition

The Home Page is the **first screen** you see after logging in to EPBCS. It contains:
1. A **Global Header** (top bar) â€” navigation icons + user menu
2. A **Work Area** â€” grid of cards/icons linking to functional areas
3. An **Announcements Panel** (right side) â€” personal activity feed
4. **Infolet dots** (optional) â€” swipeable dashboard summaries

The appearance is called **Redwood Experience** (Oracle's modern UI framework). You can switch between:
- **Oracle theme** (default light)
- **Custom Light**
- **Custom Dark**

## 9. NAVIGATION FLOW CUSTOMIZATION â€” How Admins Control the Home Page

The cards on the Home page are controlled by **Navigation Flows**. The Service Administrator can:

| Action | Result |
|--------|--------|
| **Hide a card** | Card disappears for that user group |
| **Rename a card** | Card shows custom label (e.g., "Planning" instead of "Financials") |
| **Change card icon** | Custom icon from Oracle's icon library |
| **Add a card cluster** | Group multiple cards under one "parent" icon |
| **Add a URL card** | Embed any HTTPS URL (e.g., Oracle Analytics Cloud dashboard) |
| **Reorder cards** | Up/down arrows in Navigation Flow designer |

**What CANNOT be hidden (mandatory items):**
- The Application cluster and Settings icon inside it
- The Tools cluster and: Access Control, Navigation Flows, Daily Maintenance, Migration

## 13. INTERVIEW QUESTIONS

### Beginner
**Q: A new user logs in but can't see the Forms icon on the Home page. What are the two possible causes?**
> **A:** (1) The user's group doesn't have the Forms card visible in their Navigation Flow â€” the Service Admin needs to check Tools â†’ Navigation Flows and ensure the "Data" card is visible for that group. (2) The user has not been granted permission to any forms â€” even if the card is visible, clicking it would show an empty list.

### Intermediate
**Q: Your client wants the Home page to say "Hotel Budget System" instead of showing the Oracle EPM name, and use their company logo. How do you set this up?**
> **A:** Go to Home â†’ Application â†’ Settings â†’ Appearance tab. (1) Upload the company logo under "Logo Image." (2) The "Display Business Process Name" option controls whether the EPM app name shows â€” setting it to No hides it. Note: you can't set a completely custom text name here; hiding/showing is the control. For a "Hotel Budget System" title, you'd need to use a custom card label in the Navigation Flow or use a custom background image with the text embedded.

### Architect
**Q: You have 5 user groups at Hotel Pvt Ltd: Mumbai Planners, Delhi Planners, HR, Finance Controllers, and Service Admins. Each group should see a different Home page. How do you design this?**
> **A:** Create 5 custom navigation flows (duplicate the Default for each). Assign each navigation flow to its corresponding group (Tools â†’ Navigation Flows â†’ Assign To). Configure each navigation flow to show only the relevant cards:
> - Mumbai/Delhi Planners: Forms specific to their entity, Approvals, Task Lists
> - HR: Workforce forms only
> - Finance Controllers: All finance forms + Reports + Approvals
> - Service Admins: Everything including Application, Tools
> Remember: Only ONE navigation flow per category (global/role/group) can be active at a time. Each group gets their own navigation flow in the "group" category.
