### Q1: The Multi-Grid Worksheet Architecture
**Question:**
"Can a single Excel worksheet contain two separate Smart View grids connected to two completely different cubes (e.g., Grid 1 connected to `OEP_FS` BSO, and Grid 2 connected to `OEP_REP` ASO)? How does Smart View manage this, and what setting is required?"

**Consultant Model Answer:**
> "Yes, Smart View fully supports **Multiple Grids on a Single Sheet**:
>
> 1. **How It Works:** Smart View treats each grid as an independent data range with its own dedicated connection, dimensional POV, and query context.
> 2. **Mandatory Configuration Setting:**
>    - In Smart View Options $\rightarrow$ **Advanced**, check the option:
>      ```
>      [X] Enable Multiple Grids on a Worksheet
>      ```
> 3. **The Architectural Limitations:**
>    - You cannot submit data to both grids in a single atomic transaction; data submissions are executed grid-by-grid based on active cursor focus.
>    - You cannot use Zoom In/Out across both grids simultaneously.
>    - If the user moves rows or deletes cells that cause the two grids to overlap, Smart View raises an error: `Grids cannot intersect on the same worksheet`."

### Q2: Smart View Free-Form Mode vs Form Mode Write-Back
**Question:**
"A user opens a standard Planning Web form in Smart View and submits data successfully. Then, the user creates a free-form ad-hoc grid containing the exact same members. When they click 'Submit Data' on the ad-hoc grid, the submission fails with: `Cannot submit data on a calculated or dynamic member`. Why did it succeed on the form but fail on the ad-hoc grid?"

**Consultant Model Answer:**
> "This failure highlights the difference between **Planning Form Mode** and **Free-Form Ad-Hoc Mode**:
>
> 1. **On the Planning Form:** The user was viewing an upper-level parent cell or an account with a dynamic formula where **Grid Spread** was enabled. The Planning ADF middle tier intercepted the input, performed the spreading calculation down to Level 0 stored cells, and submitted the valid Level 0 payload to Essbase.
> 2. **On the Ad-Hoc Grid:** Ad-hoc mode communicates directly with the Essbase query provider. Essbase has no middle-tier spreading logic for ad-hoc grids. When the user attempts to submit data directly to an upper-level parent or dynamic calc member, Essbase strictly rejects the write because it cannot physically store a number in a dynamic calculation cell."

### Q3: The Excel COM Add-In Disablement Crash
**Question:**
"After an Excel crash, the Smart View ribbon completely disappears. The user restarts Excel, but Smart View does not load. Checking Excel Options shows Smart View is listed under 'Disabled Application Add-ins'. Why did Excel disable it, and what is the exact recovery procedure?"

**Consultant Model Answer:**
> "When Excel crashes while a COM add-in is executing an operation:
> 1. Microsoft Excel's crash detection mechanism flags the add-in DLL (`HsAddin.dll`) as the potential cause of the crash.
> 2. To prevent Excel from crashing on subsequent launches, Excel automatically places the add-in on the **Hard Disabled List** in the Windows Registry (`HKEY_CURRENT_USER\Software\Microsoft\Office\16.0\Excel\Resiliency\DisabledItems`).
>
> **The Recovery Procedure:**
> 1. In Excel, go to **File** $\rightarrow$ **Options** $\rightarrow$ **Add-ins**.
> 2. In the **Manage** drop-down at the bottom, select **Disabled Items** and click **Go**.
> 3. Select `Oracle Smart View for Office (HsAddin.dll)` and click **Enable**.
> 4. Return to the Manage drop-down, select **COM Add-ins**, click **Go**, and ensure the checkbox for `Oracle Smart View for Office` is checked with Load Behavior set to `Load at Startup`."

### Q4: Missing Suppression Breaking Excel Lookups
**Question:**
"A financial reporting template has Excel `=VLOOKUP` formulas referencing a Smart View data sheet. An administrator enables 'Suppress Missing Rows' in Smart View options. Immediately, the entire reporting package breaks, displaying `#N/A` errors across hundreds of cells. Why did suppressing missing rows break the workbook?"

**Consultant Model Answer:**
> "Enabling 'Suppress Missing Rows' causes the rows returned by Smart View to **shift dynamically**:
>
> 1. When missing suppression is enabled, any row with `#Missing` data is completely omitted from the retrieved grid.
> 2. As data changes from month to month, the physical row position of specific accounts changes (e.g., `Marketing_Expense` might be at row 45 in January, but shifts to row 38 in February because earlier accounts had no data).
> 3. Static Excel formulas referencing fixed cell coordinates (e.g., `=VLOOKUP("Marketing", Sheet1!A10:D100, 4, FALSE)`) fail or point to the wrong row because the underlying row offsets shifted.
>
> **The Fix:**
> - Disable row suppression on sheets intended for automated formula referencing.
> - Alternatively, check **'Repeated Members'** and use dynamic `INDEX/MATCH` or `XLOOKUP` functions searching for member name keys rather than relying on fixed row positions."

### Q5: Smart View Diagnostic Tool for HTTP Tracing
**Question:**
"A client reports that a specific ad-hoc retrieval in Smart View takes 90 seconds, but running the same query via a web form takes 2 seconds. How do you use the Smart View Diagnostic Tool to capture network timings and isolate the bottleneck?"

**Consultant Model Answer:**
> "The **Smart View Diagnostic Tool** allows consultants to record detailed client-side HTTP network traces without installing third-party packet sniffers:
>
> 1. In Excel, navigate to the **Smart View** ribbon $\rightarrow$ **Help** $\rightarrow$ **Diagnostics** $\rightarrow$ click **Start Diagnostics**.
> 2. Perform the slow 90-second ad-hoc retrieval operation.
> 3. Click **Stop Diagnostics** $\rightarrow$ **Save Diagnostic Folder**.
> 4. Open the generated log files (`SmartView.log` and XML payload traces).
> 5. **Analysis:**
>    - Check the timestamp deltas between `Request Sent` and `Response Received`.
>    - If the server response time was 88 seconds: The bottleneck is an unoptimized MDX query or missing block indexing in Essbase.
>    - If the server response time was 2 seconds, but the client processing time was 88 seconds: The bottleneck is **client-side Excel rendering** (e.g., Excel attempting to evaluate thousands of conditional formatting rules or massive cell styles across 100,000 cells)."

### Q6: Drill-Through to Source ERP Mechanics
**Question:**
"A user right-clicks an Actual expense cell in a Smart View grid and selects 'Drill-Through'. What is the underlying architecture that enables the user to view the original GL transaction in Oracle ERP Cloud?"

**Consultant Model Answer:**
> "Drill-Through operates via a federated data integration link:
>
> 1. When data was originally loaded from Oracle ERP Cloud (Fusion GL) into Planning via **Data Management / Data Integration**, the integration engine stored the **lineage mapping** in relational tables on the OCI backplane.
> 2. The loaded Essbase cell is tagged with a metadata drill-through flag.
> 3. When the user clicks **Drill-Through** in Smart View:
>    - Smart View opens a browser session passing the cell's dimensional coordinates to the Cloud EPM Data Integration server.
>    - The server matches the coordinates against the stored staging tables to display the detailed drill-through landing page.
>    - If configured, the landing page provides a deep link (`Drill to Source`) that passes single-sign-on tokens directly to Oracle ERP Cloud, opening the original Fusion General Ledger journal entry."

### Q8: Dynamic Link Library (`HsAddin.dll`) Registry Conflicts
**Question:**
"A user installs a 64-bit version of Smart View on a machine running 32-bit Microsoft Excel. What error occurs, and why?"

**Consultant Model Answer:**
> "The installation will result in a **bitness architecture collision**:
>
> 1. A 32-bit application process (`EXCEL.EXE *32`) **cannot load a 64-bit Dynamic Link Library (`HsAddin.dll`)** into its memory space.
> 2. When Excel starts, it attempts to load the DLL and throws an unhandled Windows exception:
>    ```
>    Error: The file HsAddin.dll is not a valid Office Add-in (or Error 0x800700c1: %1 is not a valid Win32 application).
>    ```
> 3. The Smart View ribbon will fail to appear.
>
> **The Golden Rule:** The bitness of Smart View **must always match the bitness of Microsoft Office**, NOT the bitness of the Windows Operating System! (e.g., 32-bit Office requires 32-bit Smart View, even on 64-bit Windows 11)."

### Q9: Alias Table Switching Failures
**Question:**
"A user changes the active Alias Table in Smart View from 'Default' to 'Long Names'. Some account names change to their descriptive aliases, while other accounts still display alphanumeric codes (e.g., `Acct_5100`). Why did only part of the grid change?"

**Consultant Model Answer:**
> "This occurs because of **incomplete alias definitions in metadata**:
>
> 1. In Oracle Planning, each member can have aliases defined across multiple alias tables (e.g., 'Default', 'English', 'Long Names', 'Spanish').
> 2. If a developer imported metadata for `Acct_5100` and entered an alias in the 'Default' table but **left the 'Long Names' alias table field blank**:
> 3. When Smart View switches to 'Long Names', Essbase finds no alias for that member in that specific table.
> 4. **Engine Fallback:** Essbase automatically falls back to displaying the raw **Member Name** (`Acct_5100`) rather than leaving the cell blank.
>
> **The Fix:** Export dimension metadata and ensure every member has corresponding entries populated across all configured alias tables."

"How can you construct an external URL to open a specific Dashboard 2.0 in Cloud EPM with the POV pre-filtered to a specific Entity and Year?"

**Consultant Model Answer:**

>
> ```
> https://epm-instance.oraclecloud.com/HyperionPlanning/faces/epm/dashboard2?dashboard=Executive_Overview&Entity=US_Corp&Years=FY24

### Q11: Infolet Security Restrictions (Blank Card Trap)
**Question:**
"An administrator designs an executive Infolet showing Total Company Cash. When an executive logs in, the Infolet displays as a completely blank white tile with no numbers. What security layer is causing this?"

**Consultant Model Answer:**
> "This is caused by **Form or Dimension Security Restrictions**:
>
> 1. An Infolet is fed by an underlying Planning Form.
> 2. For an Infolet to render data:
>    - The user must have **Access Rights to the underlying Form** (assigned via Form Security).
>    - The user must have **READ access to all dimensional members** present in the form's POV, rows, and columns.
> 3. If the user has access to the Infolet page, but the administrator forgot to grant the user's role access to the underlying feeding form (or if Cell-Level Security blocks the intersection), the Infolet cannot retrieve data and gracefully renders as a blank card."

### Q12: Waterfall Chart Subtotal Anchor Errors
**Question:**
"In a Dashboard 2.0 Waterfall chart, the final bar representing 'Ending Cash' is treated as a delta variance and floats in the air rather than anchoring to the baseline. How do you configure a member as a subtotal/total in Dashboards 2.0?"

**Consultant Model Answer:**
> "By default, a Waterfall chart treats every sequential column as an incremental addition or subtraction.
>
> To anchor a bar as a summary total:
> 1. In the Dashboard 2.0 designer, select the Waterfall chart widget.
> 2. Navigate to **Chart Properties** $\rightarrow$ **Series**.
> 3. Identify the member representing Ending Cash.
> 4. Toggle the property **'Is Subtotal'** or **'Is Total'** to **TRUE**.
> 5. The engine will render that bar starting from the zero baseline on the Y-axis rather than floating from the previous bar's height, completing the bridge."

### Q13: Smart View Cell Formatting Inflation (Sheet Bloat)
**Question:**
"A user's Excel workbook containing Smart View sheets grew from 2 MB to 150 MB, causing Excel to freeze during save. What caused this massive file bloat, and how do you remediate it?"

**Consultant Model Answer:**
> "This is caused by **Excel Style Accumulation & Unconstrained Cell Formatting**:
>
> 1. When users perform ad-hoc operations (Zoom In, Pivot, Keep Only) with 'Use Excel Formatting' enabled:
>    - Excel duplicates XML style definitions inside the workbook file for every operation.
>    - If formatting was applied to entire columns (A:XFD) or entire rows (1:1048576) rather than strictly the data range, Excel stores formatting metadata for over 1 million blank cells!
> 2. **The Remediation:**
>    - Clear formatting on all empty cells beyond the active data grid.
>    - Use Excel's 'Inquire' add-in to clean excess formatting.
>    - In Smart View Options, ensure **'Move formatting on operations'** is checked, and avoid formatting entire Excel sheet columns."

### Q14: Dashboard 2.0 User Grid Spread Validation
**Question:**
"If a user modifies an aggregate cell on a Dashboard 2.0 form widget, how does the dashboard validate whether the spread is permissible before submitting?"

**Consultant Model Answer:**
> "1. The dashboard widget evaluates whether the underlying form layout has **'Enable Grid Spread'** enabled.
> 2. When the user enters a number in a parent cell and presses Enter, the Redwood ADF middle tier inspects the descendant Level 0 cells.
> 3. If any child cells are locked via approval status or Cell-Level Security, the client computes the spread using the locked-exclusion algorithm.
> 4. If all children are read-only, or if the parent has an un-spreadable dynamic member formula, the dashboard immediately highlights the cell in red and displays an interactive toast notification: `Operation not permitted: Cell is read-only or contains non-writable children`."

### Q15: Smart View "Member Name Display" Settings
**Question:**
"In Smart View ad-hoc analysis, what are the three options for 'Member Name Display', and why is 'Member Name and Alias' preferred for financial auditing?"

**Consultant Model Answer:**
> "The three options in Smart View Options $\rightarrow$ **Member Options** $\rightarrow$ **Member Name Display** are:
> 1. **Member Name Only:** Displays the raw technical code (e.g., `E101`).
> 2. **Alias Only:** Displays the business description (e.g., `New York Office`).
> 3. **Member Name and Alias:** Displays both in the cell (e.g., `E101 - New York Office`).
>
> **Why 'Member Name and Alias' Is Preferred for Auditing:**
> - In enterprise applications, different departments or entities often have similar business aliases (e.g., two different sub-departments both named 'Administration').
> - Displaying both the unique system member name and the human-readable alias prevents ambiguity during financial audits, ensuring users know the exact database coordinate they are analyzing."
