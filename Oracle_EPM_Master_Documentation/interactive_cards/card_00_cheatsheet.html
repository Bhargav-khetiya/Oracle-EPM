Top 10 Golden Laws
Law 1: Implied Sharing Single-Child Trap Storage

Single child parent = memory pointer. Adding child 2 mid-year breaks implied share, causing historical Q1 reports to display #Missing until re-calculated. Fix: Modern Hybrid Dynamic Calc (~).

Law 2: Evaluation Order vs Solve Order Classic Trap

Evaluation Order = UI display precedence (fixes Smart List displaying as $1.00). Solve Order = Essbase math priority (0-127; highest calculates LAST and wins).

Law 3: Block Size Formula (8 KB – 100 KB) Tuning

Block Size = ∏(Stored Dense Members) × 8 bytes. Shared dense members add ZERO bytes to block size. Oversized blocks (>100 KB) trigger 25,000x write amplification.

Law 4: Groovy Surgical Calculation Next-Gen

Inspects cell.edited in HTTP payload; builds dynamic FIX targeting strictly edited blocks. Drops form save calculation from 45s to 0.15s. Validates via throwVetoException.

Law 5: ASO Slice Compaction & Zero Cells ASO

Repeated ERP loads create hundreds of incremental slices, causing query lag. Merge Incremental preserves views. Merge All + Drop Zero Cells compacts and purges deleted rows.

Law 6: Block-Level Locking Queues Concurrency

Essbase locks ENTIRE BLOCKS, not cells. Editing different accounts in the same sparse entity queues up. Writing to a shared Corporate timestamp inside form save rules locks all users.
