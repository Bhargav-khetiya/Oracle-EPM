# CATEGORY 1: CORE PLATFORM TERMS

---

### 1. EPM (Enterprise Performance Management)
**What It Is:** The umbrella term for software that helps companies plan, budget, forecast, consolidate, and report on financial performance.  
**Analogy:** Like a GPS for a company's money — it shows where you are, where you're going, and if you're off course.  
**EPM Context:** Oracle EPM Cloud is Oracle's SaaS offering for EPM.

### 2. PBCS (Planning and Budgeting Cloud Service)
**What It Is:** The original name for Oracle's cloud-based planning application. Single-module only.  
**Analogy:** Like buying a single-room apartment — you get one space (planning), that's it.  
**EPM Context:** PBCS was the first cloud planning product. Now largely replaced by EPBCS.

### 3. EPBCS (Enterprise Planning and Budgeting Cloud Service)
**What It Is:** The enhanced version of PBCS that includes pre-built modules (Financials, Workforce, Capital, Projects, Strategic Modeling).  
**Analogy:** Like buying a fully furnished apartment — you get rooms for everything (planning + workforce + capex + projects).  
**EPM Context:** EPBCS is what most new customers use. When someone says "PBCS" today, they usually mean EPBCS.

### 4. Essbase
**What It Is:** Extended Spread Sheet Database — the multidimensional OLAP database engine that stores all EPM data.  
**Analogy:** Like the engine inside a car — users never see it, but nothing works without it.  
**EPM Context:** Every number you see in a form is stored in an Essbase cube.

### 5. Hyperion
**What It Is:** The company Oracle acquired in 2007 ($3.3B) to get Essbase and all the planning/reporting tools.  
**Analogy:** Like Google buying YouTube — Oracle bought Hyperion to get the EPM technology.  
**EPM Context:** "Hyperion" is the on-premise predecessor. "Oracle EPM Cloud" is the cloud successor.

### 6. FCCS (Financial Consolidation and Close Cloud Service)
**What It Is:** Oracle's cloud module for financial consolidation, close, and reporting (replacing HFM/Hyperion Financial Management).  
**Analogy:** Like the final exam — after all hotels submit their budgets, FCCS combines them all, translates currencies, and eliminates intercompany transactions to create ONE consolidated report.  
**EPM Context:** FCCS is a separate module from EPBCS but often deployed together.

### 7. OCI (Oracle Cloud Infrastructure)
**What It Is:** Oracle's cloud computing platform — the physical data centers, servers, and networking that host EPM Cloud.  
**Analogy:** Like the electricity grid that powers your house — you don't see it, but without it, nothing turns on.  
**EPM Context:** EPM runs on OCI. Your data physically lives in an OCI data center.

### 8. SaaS (Software as a Service)
**What It Is:** Software delivered over the internet — you don't install anything, you just log into a web browser.  
**Analogy:** Like Netflix — you don't buy DVDs, you just stream. Like EPM Cloud — you don't install servers, you just log in.  
**EPM Context:** Oracle EPM Cloud is SaaS. Oracle manages all infrastructure, patches, and upgrades.

### 9. On-Premise (On-Prem)
**What It Is:** Software installed on your own company's servers, in your own data center.  
**Analogy:** Like owning a house vs. renting an apartment. On-prem = you own the servers. Cloud = Oracle owns them.  
**EPM Context:** Hyperion Planning was on-premise. Oracle is moving all customers to EPM Cloud (EOL approaching).

### 10. Smart View
**What It Is:** An Excel add-in that connects Microsoft Excel to Essbase. Users can retrieve and submit data from Excel.  
**Analogy:** Like a phone charger connecting your phone to a wall outlet — Smart View connects Excel to Essbase.  
**EPM Context:** Many finance users prefer Excel over web forms. Smart View is how they access EPM data in Excel.

# CATEGORY 2: ESSBASE / DATABASE TERMS

---

### 11. Cube
**What It Is:** A multidimensional database — like a Rubik's Cube where each axis is a different business dimension (Account, Entity, Period, etc.).  
**Analogy:** A spreadsheet has 2 dimensions (rows and columns). A cube has 5-15 dimensions. Imagine a 15-dimensional Rubik's Cube.  
**EPM Context:** In EPBCS, cubes are called "Plan Types" — Plan1, Plan2, Plan3, Reporting.

### 12. Plan Type
**What It Is:** Oracle's name for an Essbase cube within a Planning application.  
**Analogy:** Like different rooms in a house — Plan1 is the kitchen (Revenue), Plan2 is the bedroom (Workforce).  
**EPM Context:** Enterprise apps support up to 6 BSO plan types + 1 ASO plan type.

### 13. BSO (Block Storage Option)
**What It Is:** Essbase's primary storage method — data is organized into "blocks" based on dense dimension intersections.  
**Analogy:** Like a filing cabinet — each drawer (block) holds data for one combination of sparse members.  
**EPM Context:** All input cubes in EPBCS use BSO (or Hybrid BSO).

### 14. ASO (Aggregate Storage Option)
**What It Is:** Essbase's alternative storage method — optimized for read-heavy, reporting-only workloads.  
**Analogy:** Like a read-only library — you can read any book instantly, but you can't write new ones.  
**EPM Context:** The "Reporting" plan type in EPBCS is ASO. Used for large dashboards and executive reports.

### 15. Hybrid BSO
**What It Is:** A mix of BSO and ASO — parent members are Dynamic Calc (ASO-like) while leaf data is stored (BSO-like).  
**Analogy:** Like a self-checkout store — items are scanned on-the-fly (dynamic calc) instead of pre-totaled.  
**EPM Context:** Hybrid BSO is the default in EPBCS. It reduces storage and improves performance.

### 16. Dense Dimension
**What It Is:** A dimension where most members have data for most combinations. Dense dimensions form the DATA BLOCK.  
**Analogy:** Like rows and columns in a spreadsheet — every cell is likely to have a value.  
**EPM Context:** Account and Period are almost always Dense. Block size = Product of all Dense member counts.

### 17. Sparse Dimension
**What It Is:** A dimension where most members do NOT have data for most combinations. Sparse dimensions form the INDEX.  
**Analogy:** Like a hotel registry — only rooms with guests checked in have data. Empty rooms have no record.  
**EPM Context:** Entity, Scenario, Version, Year, Custom dims are typically Sparse.

### 18. Data Block
**What It Is:** The fundamental unit of data storage in BSO. One block = all Dense dimension values for one unique Sparse combination.  
**Analogy:** Like a single page in a filing cabinet. The page has all accounts × all periods for ONE entity + ONE scenario.  
**EPM Context:** Block exists only when at least one cell in the block has data (or is calculated).

### 19. Index File (.ind)
**What It Is:** The lookup table that tells Essbase WHERE each data block is stored on disk.  
**Analogy:** Like the table of contents in a book — it tells you which page to go to, not the actual content.  
**EPM Context:** When you retrieve data, Essbase first checks the index, then reads the block from the page file.

### 20. Page File (.pag)
**What It Is:** The file that physically stores all data blocks on disk.  
**Analogy:** Like the actual pages of a book — this is where the numbers live.  
**EPM Context:** Large applications can have multi-GB page files.

### 21. Outline (.otl)
**What It Is:** The metadata structure of an Essbase cube — all dimensions, members, hierarchies, and properties.  
**Analogy:** Like the blueprint of a building — it defines the structure but doesn't contain the data.  
**EPM Context:** In EPBCS Cloud, the outline is managed via the Dimensions UI (not a file you download).

### 22. #Missing
**What It Is:** Essbase's representation of "no data" — not zero, but EMPTY.  
**Analogy:** Like an empty hotel room vs. a room with 0 guests. #Missing = room doesn't exist in the system. 0 = room exists but has zero guests.  
**EPM Context:** #Missing cells don't consume storage. Zero cells DO consume storage.

### 23. Restructure
**What It Is:** The process of rebuilding the Essbase outline and data blocks when dimension structure changes.  
**Analogy:** Like renovating a building — you can't add a new floor without restructuring the foundation.  
**EPM Context:** Adding/removing members triggers a restructure. Large restructures can take minutes to hours.

### 24. OLAP (Online Analytical Processing)
**What It Is:** A category of database designed for complex analytical queries (aggregation, slicing, dicing).  
**Analogy:** Like a chef's kitchen (designed for cooking) vs. a warehouse (designed for storage). OLAP = analysis-optimized.  
**EPM Context:** Essbase is an OLAP database. SQL databases are OLTP (transaction-optimized).

### 25. MDX (Multi-Dimensional Expressions)
**What It Is:** A query language for OLAP databases (like SQL is for relational databases).  
**Analogy:** SQL is the language to talk to SQL databases. MDX is the language to talk to Essbase.  
**EPM Context:** ASO cubes only support MDX (not calc scripts). Smart View ad hoc queries use MDX behind the scenes.

# CATEGORY 3: DIMENSIONS AND METADATA TERMS

---

### 26. Dimension
**What It Is:** A category of data — like a "column header" but in multiple directions.  
**Analogy:** A spreadsheet has 2 dimensions (rows = one category, columns = another). EPM has 10-15 categories (Account, Entity, Period, etc.).  
**EPM Context:** Standard dims: Account, Entity, Period, Year, Scenario, Version, Currency. Plus Custom dims.

### 27. Member
**What It Is:** An individual item within a dimension.  
**Analogy:** If Dimension = "Months", Members = "January, February, March..."  
**EPM Context:** Members can be parents (with children) or leaves (no children, also called level-0).

### 28. Hierarchy
**What It Is:** The parent-child tree structure within a dimension.  
**Analogy:** Like a family tree — grandparent → parent → child. Data aggregates from children UP to parents.  
**EPM Context:** Entity: Total Company → India → Mumbai, Delhi, Hyderabad.

### 29. Generation
**What It Is:** The depth level counting from the TOP (root). Gen1 = root, Gen2 = first children, etc.  
**Analogy:** Like counting floors from the penthouse DOWN. Penthouse = Gen1, next floor down = Gen2.  
**EPM Context:** Used in calc scripts: `@GEN("Entity",2)` = all Gen2 Entity members.

### 30. Level
**What It Is:** The depth level counting from the BOTTOM (leaves). Level0 = leaves, Level1 = their parents, etc.  
**Analogy:** Like counting floors from the ground UP. Ground floor = Level0, next floor up = Level1.  
**EPM Context:** Level-0 members are where data is entered. Parents aggregate from children.

### 31. Data Storage Property
**What It Is:** How a member's data is handled — Store, Dynamic Calc, Shared, Label Only, Never Share.  
**Analogy:** Like storage options for a file — save to disk (Store), calculate when needed (Dynamic Calc), shortcut to another file (Shared).  
**EPM Context:** The MOST important property decision in dimension design.

### 32. Store
**What It Is:** Data is physically saved to the Essbase database.  
**Analogy:** Like saving a Word document to your hard drive — it's permanently there.  
**EPM Context:** Level-0 input members are typically "Store".

### 33. Dynamic Calc
**What It Is:** Data is calculated on-the-fly when retrieved, NOT stored in the database.  
**Analogy:** Like a calculator — it doesn't store the answer, it recalculates every time you press "=".  
**EPM Context:** Parent members and KPIs are usually Dynamic Calc. Saves storage space but adds retrieval time.

### 34. Shared Member
**What It Is:** A member that appears in multiple locations in the hierarchy but stores data in only ONE place.  
**Analogy:** Like a shortcut on your desktop — it points to the original file, not a copy.  
**EPM Context:** Used for alternate hierarchies. Example: "Mumbai" appears under both "India" and "West Region".

### 35. Label Only
**What It Is:** A member that stores no data — used purely as a grouping header.  
**Analogy:** Like a folder name on your computer — it organizes files but doesn't contain data itself.  
**EPM Context:** Used for statistical groupings. Example: "Revenue_Drivers" is Label Only, its children are Store.

### 36. Consolidation Operator
**What It Is:** The math symbol (+, -, *, /, ~) that determines how a child rolls up to its parent.  
**Analogy:** Like an instruction tag on each ingredient — "add this," "subtract this," "ignore this."  
**EPM Context:** Revenue children use `+`. Expense children use `+`. Revenue parent uses `~` because it has a formula.

### 37. Time Balance
**What It Is:** A property on Account members that controls how data aggregates ACROSS TIME (periods to quarters to years).  
**Analogy:** Your bank balance on Jan 31 is ₹10L. Feb 28 is ₹12L. Q1 balance is NOT ₹22L — it's ₹12L (the ending balance).  
**EPM Context:** Flow = sum over time (Revenue). Balance/Ending = last period value (Cash). First = first period value.

### 38. Variance Reporting
**What It Is:** A property that controls how favorable/unfavorable variance is displayed.  
**Analogy:** Revenue up ₹5L = good (Non-Expense). Expenses up ₹5L = bad (Expense). The sign logic flips.  
**EPM Context:** Revenue accounts = Non-Expense. Expense accounts = Expense. This affects variance calculations.

### 39. Account Type
**What It Is:** Categorization of an account — Revenue, Expense, Asset, Liability, Equity, Saved Assumption.  
**Analogy:** Like tagging food as "protein," "carbs," or "fat" — it changes how the system handles the number.  
**EPM Context:** Account Type drives sign-flipping and reporting behavior.

### 40. Alias
**What It Is:** An alternate display name for a member.  
**Analogy:** Your username is "emp_12345" but your display name is "Rajesh Sharma." The alias is the friendly name.  
**EPM Context:** Member name = "Rev_Room" (system). Alias = "Room Revenue" (user-facing). Multiple alias tables for languages.

### 41. UDA (User-Defined Attribute)
**What It Is:** A text tag you can attach to any member for filtering and grouping.  
**Analogy:** Like a hashtag on social media — #Revenue, #Expense, #KPI — you can filter by tag.  
**EPM Context:** Used in calc scripts: `@UDA("Account", "KPI")` = process only KPI accounts.

### 42. Attribute Dimension
**What It Is:** A special dimension that classifies members of another dimension by a characteristic.  
**Analogy:** Like filtering products by "Color" — Color is an attribute of the Product dimension.  
**EPM Context:** Region (attribute of Entity), Account_Type (attribute of Account). Used for reporting slicing.

### 43. Smart List
**What It Is:** A dropdown list attached to a cell in a form — converts text choices to numeric IDs.  
**Analogy:** Like a dropdown in Google Forms — user sees "Approved/Pending/Rejected" but the system stores 1/2/3.  
**EPM Context:** Used for approval status, risk ratings, yes/no flags in planning forms.

# CATEGORY 4: PLANNING AND APPLICATION TERMS

---

### 44. Scenario
**What It Is:** A dimension that represents different versions of reality — Budget, Actual, Forecast.  
**Analogy:** Like "What if?" scenarios in life — "What if I get a raise?" (Optimistic) vs. "What if I get fired?" (Pessimistic).  
**EPM Context:** Standard Scenarios: Budget, Actual, Forecast. Each has Start Year, End Year properties.

### 45. Version
**What It Is:** A dimension for tracking iterations of the same scenario — Working, Final, Submitted.  
**Analogy:** Like document versions — Draft v1, Draft v2, Final. You iterate until it's approved.  
**EPM Context:** Bottom-Up = data enters at leaves. Target = top-down targets distributed to leaves.

### 46. Substitution Variable
**What It Is:** A server-side variable that acts as a placeholder for a value that changes over time.  
**Analogy:** Like a speed limit sign that can change — the sign says "&SpeedLimit" and the government sets it to "60" or "80".  
**EPM Context:** `&CurMonth = "Jan"`, `&CurYear = "FY26"`. Updated monthly by admin. Used in calc scripts and forms.

### 47. Valid Intersection
**What It Is:** A rule that prevents users from entering data at certain dimension combinations.  
**Analogy:** Like a vending machine that only accepts ₹10 coins — it rejects invalid inputs.  
**EPM Context:** Example: Hotel Mumbai ONLY has Room_Revenue, FnB_Revenue — not Manufacturing_Revenue.

### 48. Approval Flow (Process Management)
**What It Is:** A workflow that tracks who has submitted, promoted, approved, or rejected a budget unit.  
**Analogy:** Like a leave approval process — Employee submits → Manager reviews → HR approves → Done.  
**EPM Context:** States: Not Started → First Pass → Under Review → Approved → Published. Based on Scenario/Version/Entity.

### 49. Task List
**What It Is:** A guided checklist that tells users what steps to complete in what order.  
**Analogy:** Like a recipe — "Step 1: Enter Revenue. Step 2: Enter Expenses. Step 3: Submit for approval."  
**EPM Context:** Task Lists can auto-launch forms, business rules, URLs. Users check off completed tasks.

### 50. Navigation Flow
**What It Is:** A customizable menu system that replaces the default EPBCS hamburger menu.  
**Analogy:** Like a custom home screen on your phone — you choose which apps (forms, dashboards) appear and in what order.  
**EPM Context:** Cards, Tabs, Clusters — create a branded experience for users. Assigned by role/security.

# CATEGORY 5: FORM AND UI TERMS

---

### 51. Data Input Form (Web Form)
**What It Is:** A grid-based interface where users enter budget/forecast data.  
**Analogy:** Like an Excel spreadsheet, but connected to a database — when you type a number and hit Save, it goes into Essbase.  
**EPM Context:** The PRIMARY way users interact with EPBCS.

### 52. POV (Point of View)
**What It Is:** The "filter bar" at the top of a form that shows which members are selected for dimensions not on rows/columns.  
**Analogy:** Like the "viewing angle" of a camera — the POV tells you "you're looking at Budget, FY26, Working version."  
**EPM Context:** Dimensions not in rows/columns go to the POV. Users can change POV to see different slices.

### 53. Runtime Prompt (RTP)
**What It Is:** A popup that asks the user to select a member value before a business rule runs.  
**Analogy:** Like a waiter asking "Which size? Small, Medium, Large?" before preparing your order.  
**EPM Context:** `{RTP_Entity}` in calc scripts. Types: Member, Cross-Dimensional, String, Number.

### 54. Smart Push
**What It Is:** An automatic data movement from one plan type (cube) to another, triggered when a user saves data on a form.  
**Analogy:** Like auto-forwarding an email — when data lands in Plan1, it automatically copies to Plan2.  
**EPM Context:** Configure on the form's "Other Options" tab. Pushes only changed data.

### 55. Data Map
**What It Is:** A mapping definition that controls HOW data moves between plan types (including member-to-member mapping).  
**Analogy:** Like a translation dictionary — "Revenue in Plan1 maps to Income in Plan2."  
**EPM Context:** More flexible than Smart Push. Supports member mapping, not just direct copy.

### 56. Composite Form
**What It Is:** A form that displays multiple grids (potentially from different plan types) on one screen.  
**Analogy:** Like a split-screen TV — left side shows revenue, right side shows headcount.  
**EPM Context:** Up to 4 grids on one form. Each grid can reference a different cube.

### 57. Dashboard
**What It Is:** A visual display with charts, tiles, and KPIs — for executives who want pictures, not numbers.  
**Analogy:** Like the dashboard of a car — speedometer, fuel gauge, temperature — quick visual health check.  
**EPM Context:** EPBCS dashboards support bar charts, pie charts, tiles, gauges. Limited customization compared to OBIEE.

### 58. Flex Form
**What It Is:** A Smart View-only form that supports asymmetric layouts (different members on different rows).  
**Analogy:** Like a custom-shaped puzzle — not a uniform grid. Row 1 has Revenue for Mumbai, Row 2 has Expenses for Delhi.  
**EPM Context:** Only accessible through Smart View (Excel), not the web UI.

# CATEGORY 6: CALCULATION AND BUSINESS RULE TERMS

---

### 59. Business Rule
**What It Is:** A named calculation object in Calc Manager that can be launched from forms, task lists, or EPM Automate.  
**Analogy:** Like a macro in Excel — you click "Run" and it performs a sequence of calculations.  
**EPM Context:** Business Rules wrap calc scripts. They can have Runtime Prompts.

### 60. Calc Script (Calculation Script)
**What It Is:** The actual Essbase calculation code inside a Business Rule — written in Essbase's proprietary language.  
**Analogy:** Like the recipe instructions inside a cookbook — the step-by-step math.  
**EPM Context:** Uses FIX, IF/ELSE, @functions, AGG, CALC DIM, DATACOPY, etc.

### 61. FIX Statement
**What It Is:** A command that narrows the scope of a calculation to specific members.  
**Analogy:** Like a spotlight on a stage — it illuminates ONLY the area you want to calculate, ignoring everything else.  
**EPM Context:** `FIX("Budget", "FY26", @IDESCENDANTS("Hotel_India")) ... ENDFIX` — calculates ONLY Budget FY26 for India hotels.

### 62. AGG (Aggregation)
**What It Is:** A command that rolls up data from children to parents across ALL sparse dimensions at once.  
**Analogy:** Like totaling all the rows in a spreadsheet column — sum everything up.  
**EPM Context:** `AGG("Entity");` aggregates ALL Entity members (Mumbai, Delhi → India → Total).

### 63. CALC DIM
**What It Is:** A command that aggregates ONE specific dimension AND executes member formulas.  
**Analogy:** Like AGG but smarter — it also runs any custom formulas on calculated members.  
**EPM Context:** `CALC DIM("Account");` aggregates Account AND runs formulas like RevPAR = Revenue / Rooms.

### 64. DATACOPY
**What It Is:** A command that copies data from one member/set to another.  
**Analogy:** Like Ctrl+C, Ctrl+V — copies Budget data to Forecast.  
**EPM Context:** `DATACOPY "Budget" TO "Forecast";` inside a FIX statement.

### 65. Cross-Dimensional Operator (->)
**What It Is:** A syntax to reference a specific member in another dimension.  
**Analogy:** Like a cell reference in Excel — A1 vs. Sheet2!A1. The `->` tells Essbase "go to THIS dimension member."  
**EPM Context:** `"Revenue"->"Jan"` = the Revenue value for January specifically.

### 66. @IDESCENDANTS
**What It Is:** A function that returns a member AND all of its descendants (children, grandchildren, etc.).  
**Analogy:** "Give me India AND ALL cities under India."  
**EPM Context:** `@IDESCENDANTS("Hotel_India")` = Hotel_India + Mumbai + Delhi + Hyderabad.

### 67. @DESCENDANTS
**What It Is:** A function that returns only the descendants (NOT including the member itself).  
**Analogy:** "Give me all cities under India, but NOT India itself."  
**EPM Context:** `@DESCENDANTS("Hotel_India")` = Mumbai + Delhi + Hyderabad (no India).

### 68. Rule Set
**What It Is:** A container that runs multiple business rules in sequence (or parallel).  
**Analogy:** Like a playlist — plays Rule 1, then Rule 2, then Rule 3, in order.  
**EPM Context:** Rule Sets can run rules sequentially or in parallel. They can also have conditional logic.

### 69. Groovy
**What It Is:** A Java-based scripting language embedded in EPBCS for advanced logic that calc scripts can't do.  
**Analogy:** Like upgrading from a basic calculator (calc scripts) to a smartphone (Groovy) — it can do everything plus call APIs, read forms, send emails.  
**EPM Context:** Groovy runs on the web server JVM (not Essbase). Memory limited to ~50MB per rule.

### 70. Member Formula
**What It Is:** A formula embedded directly on a dimension member (not in a business rule).  
**Analogy:** Like a formula in an Excel cell — it's attached to that specific cell permanently.  
**EPM Context:** Dynamic Calc members have formulas. Example: `RevPAR = "Room_Revenue" / "Rooms_Available";`

# CATEGORY 7: INTEGRATION AND DATA TERMS

---

### 71. Data Integration (DI)
**What It Is:** The newer, guided-wizard approach to loading data into EPBCS from files or databases.  
**Analogy:** Like a setup wizard when installing software — "Step 1: Select source. Step 2: Map fields. Step 3: Load."  
**EPM Context:** Replaces the older Data Management/FDMEE approach.

### 72. Data Management (DM / FDMEE)
**What It Is:** The older, more complex approach to data loading — with mapping tables, validation scripts, and drill-through.  
**Analogy:** Like manually filing taxes with paper forms vs. using TurboTax (Data Integration).  
**EPM Context:** Still available in EPBCS but being gradually deprecated in favor of Data Integration.

### 73. EPM Integration Agent
**What It Is:** A lightweight Java application installed on-premise that creates a secure tunnel to Oracle Cloud.  
**Analogy:** Like a VPN tunnel — it lets cloud talk to your on-premise database without opening firewall ports.  
**EPM Context:** Required when loading data from SQL Server, Oracle DB, or other on-premise databases.

### 74. EPM Automate
**What It Is:** A command-line tool for automating EPBCS administrative tasks.  
**Analogy:** Like a script that runs chores automatically — "Every night at 11 PM, backup the database and refresh the cube."  
**EPM Context:** Commands: `login`, `runBusinessRule`, `importData`, `exportData`, `runDataRule`, `recreate`.

### 75. REST API
**What It Is:** A standard web interface for programmatic access to EPBCS — read data, write data, run rules, manage metadata.  
**Analogy:** Like a waiter in a restaurant — you send a request (order), the API processes it, and returns a response (food).  
**EPM Context:** URL: `https://<server>/HyperionPlanning/rest/v3/...`. Authentication via Basic Auth or OAuth.

### 76. LCM (Life Cycle Management)
**What It Is:** The mechanism to migrate EPBCS artifacts (dimensions, forms, rules) between environments.  
**Analogy:** Like moving house — you pack everything into boxes (snapshot), transport them, and unpack at the new place.  
**EPM Context:** Export → Download ZIP → Upload to target → Import. Used for Dev → Test → Prod migration.

### 77. Snapshot
**What It Is:** A ZIP file containing selected EPBCS artifacts exported via LCM.  
**Analogy:** Like a backup of your phone — contains all your apps, photos, settings.  
**EPM Context:** Snapshots can include: dimensions, forms, rules, security, data, variables, etc.

# CATEGORY 8: SECURITY AND ADMINISTRATION TERMS

---

### 78. IDCS (Identity Cloud Service) / OCI IAM
**What It Is:** Oracle's identity management system — manages users, passwords, MFA, and SSO.  
**Analogy:** Like a building's security desk — checks your ID before letting you in.  
**EPM Context:** All EPBCS users are created/managed in IDCS. Roles are assigned here.

### 79. Service Administrator
**What It Is:** The highest-level role in EPBCS — full access to everything.  
**Analogy:** Like the building owner — has keys to every room, can change any lock.  
**EPM Context:** Can create apps, manage dimensions, write rules, provision users. Usually 2-3 people.

### 80. Power User
**What It Is:** A role that can create forms, business rules, and reports — but cannot manage the application.  
**Analogy:** Like a department head — can arrange furniture in their department but can't renovate the building.  
**EPM Context:** Typically assigned to super users and EPM developers.

### 81. Planner
**What It Is:** A role that can enter data on assigned forms — but cannot create or modify forms/rules.  
**Analogy:** Like a hotel guest — can use the room but can't remodel it.  
**EPM Context:** Most end users are Planners. They see only forms assigned to them.

### 82. Viewer
**What It Is:** Read-only access — can see data but cannot change it.  
**Analogy:** Like a museum visitor — look but don't touch.  
**EPM Context:** Used for executives who review data but don't enter budgets.

### 83. Access Control
**What It Is:** Dimension-level security — controlling which members a user can Read, Write, or Not See.  
**Analogy:** Like room access in a hotel — your keycard works for Room 305 but not Room 410.  
**EPM Context:** Assign per Entity: "Mumbai Hotel GM can write to Mumbai, read India total, no access to Delhi."

### 84. Security Filter (Essbase)
**What It Is:** A row-level filter on the Essbase database that restricts which data blocks a user can access.  
**Analogy:** Like a spam filter for email — blocks certain data from reaching the user.  
**EPM Context:** Created automatically by Planning when you set up Access Control.

# CATEGORY 9: FINANCE AND BUSINESS TERMS

---

### 85. P&L (Profit and Loss Statement / Income Statement)
**What It Is:** A financial report showing Revenue - Expenses = Net Income over a PERIOD of time.  
**Analogy:** Like your monthly bank statement — "You earned ₹1L, spent ₹80K, saved ₹20K."  
**EPM Context:** The most common report in EPBCS. P&L accounts have Time Balance = Flow.

### 86. Balance Sheet
**What It Is:** A financial report showing Assets = Liabilities + Equity at a POINT in time.  
**Analogy:** Like a snapshot of your net worth TODAY — house value, car value, minus mortgage, minus loans.  
**EPM Context:** Balance Sheet accounts have Time Balance = Balance (Ending). Q1 = March value, not sum.

### 87. Cash Flow Statement
**What It Is:** A report showing how cash actually moved in and out of the bank account.  
**Analogy:** Your P&L says you're profitable (₹20K saved). But your cash flow says your bank account is empty because the client hasn't paid you yet (Accounts Receivable).  
**EPM Context:** Modeled in the OOTB Financials module. Complex: requires DSO calculations.

### 88. Budget
**What It Is:** The annual financial plan — "How much do we plan to earn and spend next year?"  
**Analogy:** Like planning a wedding — "We'll spend ₹5L on food, ₹2L on venue, ₹1L on decoration."  
**EPM Context:** Scenario = "Budget" in EPBCS. Typically done once per year (September-December for next year).

### 89. Forecast
**What It Is:** An updated prediction of financial results based on current actuals.  
**Analogy:** Like re-estimating your wedding budget AFTER you've booked the venue — "The venue cost ₹3L not ₹2L, so we need to cut food to ₹4L."  
**EPM Context:** Scenario = "Forecast" in EPBCS. Updated monthly or quarterly.

### 90. Variance
**What It Is:** The difference between two values — typically Budget vs. Actual.  
**Analogy:** Like weighing yourself — your goal was 70kg (Budget), you're 73kg (Actual), variance = 3kg unfavorable.  
**EPM Context:** Variance = Actual - Budget. Favorable = revenue up or expenses down. Unfavorable = opposite.

### 91. Allocation
**What It Is:** Distributing a cost from one source to multiple targets based on a driver.  
**Analogy:** Like splitting a restaurant bill — Total = ₹3,000, split by what each person ordered.  
**EPM Context:** "Allocate HQ Rent ₹50L to all hotels based on square footage." Requires calc scripts.

### 92. Intercompany Elimination
**What It Is:** Removing transactions between subsidiaries of the same parent company during consolidation.  
**Analogy:** If your left hand pays ₹100 to your right hand, your total wealth hasn't changed. Eliminate the internal transfer.  
**EPM Context:** Handled in FCCS. Also possible in EPBCS with custom logic.

### 93. Currency Translation
**What It Is:** Converting financial data from local currency to reporting currency using exchange rates.  
**Analogy:** Hotel Mumbai reports in ₹. Hotel London reports in £. CFO needs everything in $ for the US parent company.  
**EPM Context:** EPBCS has built-in currency translation. Requires exchange rate tables (Average, Ending, Historical).

### 94. Driver-Based Planning
**What It Is:** Instead of typing final numbers, users input assumptions (volume, rate, %) and the system calculates results.  
**Analogy:** Instead of guessing "Revenue = ₹2Cr," you input: Rooms=200, Occupancy=75%, Rate=₹3,200 → system calculates Revenue.  
**EPM Context:** Core design pattern in EPBCS. Uses member formulas and Dynamic Calc members.

### 95. Rolling Forecast
**What It Is:** A forecast that always looks X months ahead — as one month completes, a new month is added.  
**Analogy:** Like a car's headlights — they always illuminate the next 100 meters, no matter how far you've driven.  
**EPM Context:** 3+9 = 3 months Actual + 9 months Forecast = 12 months. Next month: 4+8.

# CATEGORY 10: ARCHITECTURE AND INFRASTRUCTURE TERMS

---

### 96. Pod
**What It Is:** A cluster of servers in an OCI data center that hosts multiple EPM tenants.  
**Analogy:** Like an apartment building — multiple tenants (companies) share the building infrastructure.  
**EPM Context:** Performance can be affected by "noisy neighbors" on the same pod (rare).

### 97. Tenant
**What It Is:** Your company's isolated instance within the shared EPM Cloud platform.  
**Analogy:** Like your apartment in the building — your space is private, even though you share the building.  
**EPM Context:** Each tenant has its own Essbase instances, data, and configuration.

### 98. Maintenance Window
**What It Is:** A daily 1-hour period when Oracle may apply patches. System is unavailable.  
**Analogy:** Like a building's elevator maintenance — unavailable for 1 hour each night.  
**EPM Context:** Usually 2:00-3:00 AM local time. Monthly updates also happen during extended windows.

### 99. Environment
**What It Is:** A separate instance of EPBCS — Dev, Test, or Prod.  
**Analogy:** Like having 3 copies of a document — Draft (Dev), Review (Test), Final (Prod).  
**EPM Context:** Standard subscription = 2 environments. Enterprise = 3.

### 100. EPM Cloud Modules
**What It Is:** Pre-built, industry-standard templates within EPBCS.  
**Analogy:** Like pre-built rooms in a house — Financials (kitchen), Workforce (bedroom), Capital (garage). Pre-furnished.  
**EPM Context:** Available only in Enterprise applications: Financials, Workforce, Capital, Projects, Strategic Modeling.

### 101. EDMCS (Enterprise Data Management Cloud Service)
**What It Is:** A separate Oracle Cloud module for managing metadata (dimension members) across multiple EPM applications.  
**Analogy:** Like a central HR system that manages employee records across all departments.  
**EPM Context:** When you have 5+ EPM applications and need consistent metadata governance across all.

### 102. OAC (Oracle Analytics Cloud)
**What It Is:** Oracle's cloud BI and analytics platform for advanced visualizations and dashboards.  
**Analogy:** Like upgrading from a basic TV (EPBCS dashboards) to a home theater (OAC) — much more powerful visualization.  
**EPM Context:** Connects to Essbase via Smart View or REST API for enterprise-grade dashboards.

### 103. Two-Pass
**What It Is:** A member property that forces Essbase to recalculate a member AFTER the initial aggregation pass.  
**Analogy:** Like proofreading an essay AFTER writing it — the first pass writes, the second pass corrects.  
**EPM Context:** Used for percentage calculations that depend on aggregated values. Example: EBITDA% = EBITDA / Revenue (needs Revenue to be aggregated first).

### 104. Implied Sharing
**What It Is:** Automatic data sharing that occurs when a parent has only ONE child.  
**Analogy:** If you have only one child, that child inherits everything — no splitting needed.  
**EPM Context:** If parent "India_Revenue" has only one child "Revenue_INR", they automatically share the same data value. Can cause unexpected behavior if not understood.

### 105. Block Creation
**What It Is:** The process of Essbase creating a new data block when data is first written to a new sparse intersection.  
**Analogy:** Like opening a new file folder — it only exists once you put something in it.  
**EPM Context:** Blocks are created by: data loads, calc scripts with `SET CREATEBLOCKONEQ ON`, or form data entry.
