## What Is EPM?

**EPM = Software that helps big companies plan, budget, forecast, and report their finances.**

```
Think of it like this:

Excel     = Calculator for ONE person
EPM       = Calculator for an ENTIRE company

Excel     = You type numbers and formulas
EPM       = 200 people type numbers â†’ system calculates automatically
             â†’ converts currencies â†’ rolls up to group totals
```

## What Does an EPM Consultant Do?

An EPM Consultant is the person who **sets up and configures** the EPM system for a company.

```
Client: "We're a hotel chain. We need a budgeting system."

EPM Consultant:
  1. UNDERSTAND the client's business (hotel revenue, expenses, KPIs)
  2. DESIGN the database structure (what dimensions, what hierarchies)
  3. BUILD the application (create forms, write calculation rules)
  4. LOAD data (connect to ERP systems like Oracle EBS, SAP)
  5. TEST everything (enter data, run calculations, verify reports)
  6. TRAIN users (teach 200 managers how to enter budgets)
  7. SUPPORT the system (fix bugs, add new features)
```

## The Building Blocks â€” What You'll Learn

Here's every major concept you'll study, explained in one sentence:

### 1. Essbase (The Database Engine)
**What:** The calculation engine that stores and computes all the numbers.  
**Analogy:** If EPM is a car, Essbase is the engine.

### 2. Dimensions (The Structure)
**What:** Categories that organize data â€” like Account, Entity, Period, Scenario.  
**Analogy:** If Essbase is a Rubik's cube, Dimensions are the sides (colors).

```
Example:
  Account Dimension:  Revenue, Expense, Net Income
  Entity Dimension:   Hotel India, Hotel London, Hotel NYC
  Period Dimension:   Jan, Feb, Mar, ..., Dec
  Scenario Dimension: Budget, Actual, Forecast
  Year Dimension:     FY25, FY26, FY27
```

### 3. Forms (The Data Entry Screens)
**What:** Web pages where users type their budget numbers.  
**Analogy:** Like a Google Sheet, but connected to the database.

```
A form looks like this:

                 Jan      Feb      Mar      Q1 Total
Revenue         â‚¹1.5Cr   â‚¹1.6Cr   â‚¹1.8Cr   â‚¹4.9Cr
  Room Revenue  â‚¹1.0Cr   â‚¹1.1Cr   â‚¹1.2Cr   â‚¹3.3Cr

```

### 4. Business Rules (The Calculations)
**What:** Formulas that run on the database â€” like Excel formulas but for millions of cells.  
**Analogy:** "When user clicks Save, multiply Revenue by 1.10 for all hotels"

```essbase
/* This is a Business Rule (Calc Script) */
FIX("Budget", @LEVMBRS("Entity", 0))
    "Revenue" = "Revenue" * 1.10;
ENDFIX
/* Translation: For every hotel, increase Budget Revenue by 10% */
```

### 5. Calc Manager (The Rule Builder)
**What:** The tool where you create and manage Business Rules.  
**Analogy:** Calc Manager is the workshop. Business Rules are what you build in it.

### 6. Member Formulas (Embedded Calculations)
**What:** Formulas attached directly to a member â€” they calculate automatically.  
**Analogy:** `Net Income = Revenue - Expense` â€” this formula is attached to "Net Income" and runs every time someone opens a form.

### 7. Smart View (Excel Add-in)
**What:** An Excel plugin that connects Excel to the EPM database.  
**Analogy:** Instead of opening a web form, you open Excel and pull live data.

### 8. Data Integration (Loading Data)
**What:** How you get data INTO the EPM system from ERP systems.  
**Analogy:** "Every night at 2am, actual data from SAP is loaded into EPM automatically."

### 9. Groovy (Programming Language)
**What:** A Java-based scripting language that extends EPM's capabilities.  
**Analogy:** If Business Rules are a hammer, Groovy is a Swiss Army knife.

### 10. EPM Automate (Command Line Tool)
**What:** A tool to automate EPM tasks â€” like scheduling data loads, backups, etc.  
**Analogy:** Like writing a batch script that runs EPM tasks automatically.
