# 05.08 Account Dimension — Exhaustive Property Reference

> **Module:** 05_Metadata  
> **Topic:** 08 — Every Property of the Account Dimension  
> **Target Audience:** Developer / Architect  

---

## Introduction

The **Account** dimension is the most property-rich dimension in Oracle EPM Planning. Every member has ~15+ configurable properties that control how values are stored, aggregated, displayed, and converted across currencies. A single wrong property choice (e.g., `Time Balance: Flow` on a Balance Sheet account) can corrupt an entire financial statement.

This document covers **every single property** with every option, use case, and common pitfall.

# EVERY ACCOUNT MEMBER PROPERTY

---

## 1. Member Name

| Field | Description | Rules |
|-------|-------------|-------|
| **Member Name** | The unique internal identifier | Must be unique across ALL dimensions. No duplicates allowed even across different dimensions. |

**Best Practices:**
- Use prefixes: `Rev_`, `Exp_`, `Ast_`, `Liab_` for quick identification
- No spaces (use underscores): `Rev_Product_Sales` not `Rev Product Sales`
- Keep under 80 characters (Essbase limit = 80; Planning limit varies)

---

## 2. Alias

| Field | Description | Rules |
|-------|-------------|-------|
| **Alias** | User-friendly display name | Can contain spaces, special characters |
| **Alias Table** | Which alias table stores this alias | `Default`, or custom alias tables |

**Example:**
| Member Name | Alias (Default) |
|------------|----------------|
| `Rev_Product_Sales` | `Product Sales Revenue` |
| `Exp_Salary` | `Salary & Wages` |

---

## 3. Data Storage

| Option | Description | When to Use |
|--------|-------------|-------------|
| **Store** | Value is physically saved to disk | Level 0 input accounts (Revenue, Expense line items) |
| **Dynamic Calc** | Value is calculated in real-time on every query | Parent/rollup accounts (Total Revenue, Gross Margin), ratios, percentages |
| **Dynamic Calc & Store** | Calculates on first query, caches result | Rarely used — complex historical calculations |
| **Shared** | Points to another member's stored value | Alternate hierarchies (e.g., Revenue in both "By Product" and "By Region" hierarchies) |
| **Never Share** | Prevents Implied Sharing | When a parent has only one child but must store independently |
| **Label Only** | Holds no data — visual label only | Section headers (e.g., "--- Income Statement ---") |

### Implied Sharing Rule:
If a parent has **exactly one child**, Essbase automatically shares the child's data with the parent (Implied Sharing). To prevent this:
- Tag the parent as `Never Share`
- OR add a dummy child (e.g., `Unused_Placeholder`)

## 4. Account Type

| Type | Description | Impact on Consolidation | Impact on Currency | Impact on Variance Reporting |
|------|-------------|------------------------|--------------------|------------------------------|
| **Revenue** | Income/Sales accounts | + (Adds to parent) | Uses Average FX rate | Favorable = Positive (Actual > Budget) |
| **Expense** | Cost/Expense accounts | + (Adds to parent) | Uses Average FX rate | Favorable = Positive (Budget > Actual) |
| **Asset** | Balance sheet — Assets | + (Adds to parent) | Uses Ending FX rate | Favorable = Positive (Actual > Budget) |
| **Liability** | Balance sheet — Liabilities | + (Adds to parent) | Uses Ending FX rate | Favorable = Positive (Budget > Actual) |
| **Equity** | Balance sheet — Equity | + (Adds to parent) | Uses Ending FX rate | Favorable = Positive |
| **Saved Assumption** | Driver/rate accounts (not financial) | Depends on consolidation operator | No currency conversion | N/A |

### Account Type Impact Summary:

| Feature | Revenue | Expense | Asset | Liability | Equity | Saved Assumption |
|---------|---------|---------|-------|-----------|--------|-----------------|
| Time Balance Default | Flow | Flow | Last | Last | Last | None |
| FX Rate Type | Average | Average | Ending | Ending | Ending | None |
| Variance Sign | Act - Bud | Bud - Act | Act - Bud | Bud - Act | N/A | N/A |
| In Financial Reports | Income Statement | Income Statement | Balance Sheet | Balance Sheet | Balance Sheet | Supporting Schedules |

## 5. Time Balance

Controls how child periods aggregate to parent periods (e.g., Jan+Feb+Mar → Q1).

| Option | Formula | Example | When to Use |
|--------|---------|---------|-------------|
| **Flow** | `Q1 = Jan + Feb + Mar` | Revenue, Expenses (income statement) | P&L accounts — values accumulate over time |
| **First** | `Q1 = Jan` | Opening Balance | When the parent should show the starting value |
| **Last** | `Q1 = Mar` | Ending Cash Balance, Headcount at month-end | Balance Sheet accounts — snapshot at end of period |
| **Average** | `Q1 = (Jan + Feb + Mar) / 3` | Average Headcount, Average Price | Statistical accounts where the average is meaningful |
| **Fill** | `Q1 = Jan = Feb = Mar` (propagates) | Annual rates applied monthly | When the same value should fill all children |
| **Weighted Average (First/Last)** | Weighted calculation | Weighted Average Interest Rate | Complex financial instruments |

### Time Balance Decision Matrix:

| Account | Time Balance | Why |
|---------|-------------|-----|
| Revenue | Flow | Revenue accumulates (Jan Rev + Feb Rev = YTD Rev) |
| Salary Expense | Flow | Expenses accumulate |
| Cash on Hand | Last | Cash balance is a snapshot at end of period |
| Inventory Balance | Last | Inventory is a point-in-time balance |
| Headcount (FTE) | Last or Average | Last = month-end headcount; Average = average during quarter |
| Tax Rate | None or Fill | A rate doesn't aggregate — it stays constant |
| Interest Rate | None | Cannot sum rates |
| Number of Transactions | Flow | Transactions accumulate |
| Revenue per Employee | Average | A ratio — must be averaged, not summed |
| Accounts Receivable | Last | A/R is a balance at a point in time |

---

## 6. Skip Option

Controls behavior when child periods contain `#Missing` values during Time Balance aggregation.

| Option | Behavior | Example (Time Balance = Last, Jan=100, Feb=#Missing, Mar=#Missing) |
|--------|----------|------------------------------------------------------------------|
| **None** | If the last child is #Missing, the parent is #Missing | Q1 = #Missing |
| **Missing** | Skip #Missing children, use the last non-missing value | Q1 = 100 (Feb and Mar are skipped, Jan is used) |
| **Zeros** | Skip zero-valued children, use the last non-zero value | Q1 = uses last non-zero child |
| **Missing and Zeros** | Skip both #Missing and zero children | Q1 = uses last child that is non-missing AND non-zero |

### Skip Option Decision Matrix:

| Account Type | Time Balance | Skip Option | Why |
|-------------|-------------|-------------|-----|
| Cash Balance | Last | Missing | Cash carries forward — if no new data, the balance remains |
| Headcount | Last | Missing | If no update in March, headcount is same as February |
| Revenue | Flow | None | Missing revenue means $0 — don't skip |
| Inventory | Last | Missing | Inventory carries forward until updated |
| Tax Rate | None | None | Rates don't aggregate — Skip is irrelevant |

### The Classic Trap:
**Q: Jan=100, Feb=0, Mar=#Missing. Time Balance=Last, Skip=Missing. What is Q1?**

**A: Q1 = 0.** Essbase checks Mar → #Missing → skips. Checks Feb → 0 → this is a REAL VALUE (not #Missing). Returns 0. Many people incorrectly think it returns 100, but 0 is not #Missing.

## 7. Variance Reporting

Controls the sign convention for variance analysis.

| Option | Formula | When Account Type is... |
|--------|---------|------------------------|
| **Non-Expense** | `Variance = Actual - Budget` | Revenue, Asset — positive variance = favorable |
| **Expense** | `Variance = Budget - Actual` | Expense, Liability — under-budget = favorable |

### Impact on Reports:
In a variance report, a **positive** number is always **green** (favorable) and a **negative** number is always **red** (unfavorable).

| Account | Actual | Budget | Variance (Non-Expense) | Variance (Expense) |
|---------|--------|--------|----------------------|-------------------|
| Revenue | 1,200 | 1,000 | +200 (Favorable ✅) | N/A |
| Salary | 800 | 1,000 | N/A | +200 (Under budget ✅) |
| Rent | 550 | 500 | N/A | -50 (Over budget ❌) |

---

## 8. Exchange Rate Type

Controls which exchange rate is used for currency conversion.

| Option | Rate Used | When to Use |
|--------|----------|-------------|
| **Average** | Average FX rate for the period | P&L accounts (Revenue, Expenses) — activity over time |
| **Ending** | End-of-period FX rate | Balance Sheet accounts (Assets, Liabilities) — point-in-time |
| **Historical** | A specific historical FX rate | Equity accounts (e.g., retained earnings at original FX rate) |
| **None** | No currency conversion applied | Non-currency accounts (Headcount, Units, Rates) |

---

## 9. Data Type

Controls what kind of data the member can hold.

| Option | What It Stores | Example |
|--------|---------------|---------|
| **Currency** | Monetary values (with currency symbol) | Revenue = $1,000,000 |
| **Non-Currency** | Numbers without currency formatting | Headcount = 150 |
| **Percentage** | Values displayed as percentages | Margin % = 25% |
| **Smart List** | Values mapped to a Smart List dropdown | Status = "Approved" (stored as integer ID) |
| **Date** | Date values | Start Date = 01/15/2024 |
| **Text** | Free-text values (stored in relational DB, not Essbase) | Comment = "Pending CFO review" |

### Data Type Impact:
| Feature | Currency | Non-Currency | Smart List | Text |
|---------|----------|-------------|------------|------|
| Stored in Essbase | ✅ | ✅ | ✅ (as number) | ❌ (relational only) |
| Aggregatable | ✅ | ✅ | ❌ | ❌ |
| Currency conversion | ✅ | ❌ | ❌ | ❌ |
| Form display | `$1,000` | `150` | Dropdown | Text box |

## 10. Source Plan Type

| Field | Description | Options |
|-------|-------------|---------|
| **Source Plan Type** | Which cube is the "master" source of data for this account | Plan1, Plan2, Plan3, or specific cube name |

**Impact:** When data exists in multiple cubes, the Source Plan Type determines which cube's data is considered the "official" value for reporting.

## 11. Plan Type Association

| Field | Description | Options |
|-------|-------------|---------|
| **Plan Type 1 (Plan1)** | Is this account enabled in Plan Type 1? | ☑️ / ☐ |
| **Plan Type 2 (Plan2)** | Enabled in Plan Type 2? | ☑️ / ☐ |
| **Plan Type 3 (Plan3)** | Enabled in Plan Type 3? | ☑️ / ☐ |
| **Custom cubes** | Enabled in any custom cube? | ☑️ / ☐ per cube |

**Impact:** A member can exist in multiple cubes or be restricted to one. If disabled for a cube, the member is invisible in that cube's forms and rules.

---

## 12. Consolidation Operator

| Operator | Effect | Example |
|----------|--------|---------|
| `+` (Addition) | Adds to parent | Revenue + COGS = Gross Margin |
| `-` (Subtraction) | Subtracts from parent | Returns and Allowances (contra-revenue) |
| `*` (Multiplication) | Multiplies into parent | Rare |
| `/` (Division) | Divides into parent | Rare |
| `%` (Percentage) | Percentage of parent | Rare |
| `~` (Ignore) | Does NOT roll up to parent | **Critical for rates, percentages, KPIs** |

### The `~` Ignore Trap:
If a member like `Tax_Rate = 25%` has consolidation operator `+`, Essbase will add 25% to the parent total, corrupting the financials. **Always use `~` for non-additive accounts** (Rates, Prices, Percentages, Headcount-derived metrics, Smart List accounts).

## 13. Solve Order (0–127)

| Value Range | Use For |
|------------|---------|
| 0 (default) | Standard aggregation (sums) |
| 10–20 | Custom aggregation |
| 30–40 | Variance calculations |
| 50–60 | Ratios and percentages |
| 70–80 | Complex KPIs |
| 90–127 | Exception overrides |

**Rule:** Higher Solve Order = calculates LAST = wins at conflict intersections.

## Interview Questions

### Intermediate
**Q: An account called `Headcount_FTE` is configured with Account Type = Revenue, Time Balance = Flow, Consolidation = +, Data Type = Currency. List everything wrong.**
> A: **4 errors:** (1) Account Type should be `Saved Assumption` (Headcount is not revenue). (2) Time Balance should be `Last` or `Average` (you don't sum monthly headcounts — 10 employees in Jan + 10 in Feb ≠ 20 for Q1). (3) Consolidation should be `~` (Ignore) or `+` depending on hierarchy design (summing FTEs across entities is valid, but summing with Revenue is not). (4) Data Type should be `Non-Currency` (Headcount is not monetary).

### Architect
**Q: Design the Account Type, Time Balance, Skip Option, Consolidation, and Exchange Rate properties for these 5 accounts: Revenue, Salary Expense, Cash Balance, Headcount, and Gross Margin %.**

| Account | Type | Time Balance | Skip | Consolidation | FX Rate |
|---------|------|-------------|------|---------------|---------|
| Revenue | Revenue | Flow | None | + | Average |
| Salary Expense | Expense | Flow | None | + | Average |
| Cash Balance | Asset | Last | Missing | + | Ending |
| Headcount | Saved Assumption | Last | Missing | ~ | None |
| Gross Margin % | Saved Assumption | None | None | ~ | None |

> **Additional:** Gross Margin % should be Dynamic Calc with Two-Pass enabled and Solve Order = 50.

---

## Summary

The Account dimension has **17+ properties per member**. The 5 most critical are:
1. **Account Type** — Drives currency conversion and variance sign
2. **Time Balance** — Flow vs Last vs Average — #1 cause of wrong quarterly totals
3. **Skip Option** — Determines carry-forward behavior for Balance Sheet
4. **Consolidation Operator** — `~` for rates/percentages, `+` for financial values
5. **Data Type** — Currency vs Non-Currency vs Smart List
