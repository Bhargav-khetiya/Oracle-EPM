# 06.03 — Runtime Prompts and Variables on Forms: Complete Guide

> **Module:** 06_Forms | **Topic:** Runtime Prompts, Substitution Variables, User Variables
> **Audience:** Service Administrator / Power User

---

## 1. WHY — What Real-World Problem Does This Solve?

**The problem:** A single business rule like "Calculate P&L" should work for ANY scenario, ANY year, ANY entity — not just hardcoded ones. If you hardcode `FIX("Budget", "FY2026")`, you'd need 10 copies of the same rule for 10 scenarios. Similarly, a form should let each hotel GM see their own hotel without the admin creating 5 identical forms.

**The solution:** Variables make forms and rules **dynamic and reusable**:
- **Runtime Prompts (RTPs):** Pop-up dialogs asking the user "Which scenario? Which year?" before a rule runs
- **Substitution Variables:** Global admin-managed placeholders (`&CurrMonth = "Jan"`) that change centrally
- **User Variables:** Per-user settings (`UserEntity = "Mumbai_Hotel"`) that personalize forms

## 3. RUNTIME PROMPTS (RTPs) — DEEP DIVE

### What They Are
When a business rule is launched, a dialog pops up asking the user to select members. These selections are injected into the calc script at runtime.

### Creating RTPs in Calc Manager

```
Calculation Manager → Open Rule → Variables tab

Variable Name: RTP_Scenario
Type: Member
Dimension: Scenario
Default: Budget
Prompt Text: "Select Scenario"
Required: ☑

Variable Name: RTP_Year
Type: Member
Dimension: Year
Default: &CurrYear  (can use substitution variable as default!)
Prompt Text: "Select Year"
Required: ☑
```

### All RTP Types

| RTP Type | User Sees | Stored As | Use Case |
|----------|-----------|-----------|----------|
| **Member** | Member selector (single) | Member name | "Pick a Scenario" |
| **Members** | Member selector (multi) | Member list | "Pick entities to clear" |
| **Numeric** | Number input box | Double | "Adjustment amount: 50000" |
| **String** | Text input box | String | "Comment: Q1 adjustment" |
| **Integer** | Integer input | Integer | "Number of months: 6" |
| **Percent** | Percentage input | Double (0-100) | "Growth rate: 10%" |
| **Date** | Date picker | Date value | "Effective date" |
| **Smart List** | Smart List dropdown | Smart List ID | "Status: Approved" |
| **Boolean** | Yes/No checkbox | Boolean | "Include children? Yes" |
| **Cross Dimension** | Member pair selector | CrossDim | "Account->Entity" |
| **Member Range** | From/To member | Range | "From Jan To Jun" |
| **Dimension** | Dimension selector | Dim name | "Aggregate which dimension?" |

### RTP in Calc Script

```essbase
/* RTP Variables are referenced with curly braces: {RTP_VarName} */

FIX({RTP_Scenario}, {RTP_Version}, {RTP_Year})
  FIX(@CHILDREN("All_Hotels"))
    "Net_Income" = "Total_Revenue" - "Total_Expenses";
  ENDFIX
ENDFIX

/* At runtime, if user selects Budget, Working, FY2026: */
/* Generated script becomes: */
FIX("Budget", "Working", "FY2026")
  FIX(@CHILDREN("All_Hotels"))
    "Net_Income" = "Total_Revenue" - "Total_Expenses";
  ENDFIX
ENDFIX
```

### RTP in Groovy

```groovy
/* RTPS: {RTP_Scenario} {RTP_Year} */

String scenario = rtps.RTP_Scenario.toString()
String year = rtps.RTP_Year.toString()

println "Running for: ${scenario} / ${year}"

operation.grid.dataCellIterator().each { cell ->
  // process cells
}
```

## 4. SUBSTITUTION VARIABLES — DEEP DIVE

### What They Are
Global named variables set by admins, referenced with `&` prefix. They're like environment variables — one central place changes the value everywhere.

### Creating Substitution Variables

```
Navigator → Create and Manage → Variables → Substitution Variables

Name: CurrMonth      Value: Aug       Cube: All Cubes
Name: CurrYear       Value: FY2026    Cube: All Cubes
Name: PriorYear      Value: FY2025    Cube: All Cubes
Name: ForecastStart   Value: Sep       Cube: OEP_FS
Name: BudgetVersion   Value: Working   Cube: OEP_FS
```

### Using in Forms

```
Form Designer → Layout tab → Row/Column member selection:

  Column members: &CurrMonth  (shows current month dynamically)
  
  OR in member selection formula:
  @CHILDREN("All_Hotels") → filtered by &ForecastStart

When admin changes CurrMonth from "Aug" to "Sep":
  → ALL forms using &CurrMonth automatically update
  → No form redesign needed
```

### Using in Business Rules

```essbase
/* Reference with & prefix */
FIX("Budget", "Working", &CurrYear)
  FIX(@RANGE("Period", &ForecastStart, "Dec"))
    "Forecast" = "Actual" * 1.05;
  ENDFIX
ENDFIX

/* When admin sets: CurrYear=FY2026, ForecastStart=Sep */
/* Generated script: */
FIX("Budget", "Working", "FY2026")
  FIX(@RANGE("Period", "Sep", "Dec"))
    "Forecast" = "Actual" * 1.05;
  ENDFIX
ENDFIX
```

## 5. USER VARIABLES — DEEP DIVE

### What They Are
Per-user personalization settings. Each user sets their own value. Forms use these to filter which data each user sees.

### Creating User Variables (Admin)

```
Navigator → Create and Manage → Variables → User Variables

Name: UserEntity      Dimension: Entity     Default: All_Hotels
Name: UserDepartment  Dimension: Department  Default: All_Departments
Name: UserScenario    Dimension: Scenario    Default: Budget
```

### Users Setting Their Values

```
Settings Gear (⚙) → User Preferences → User Variables tab

UserEntity: [Mumbai_Hotel ▾]  ← Mumbai GM selects their hotel
UserDepartment: [All_Departments ▾]
UserScenario: [Budget ▾]
```

### Using in Form Design

```
Form Designer → Layout tab → Page axis:
  Entity dimension → Member Selection → Variables tab → UserEntity

Result:
  - Mumbai GM sees: Form shows Mumbai_Hotel data
  - Delhi GM sees: Form shows Delhi_Hotel data
  - CFO sees: Form shows All_Hotels data
  
  Same form, different data per user!
```

## 7. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Forgot to update SubVar monthly | Forms show last month's data | Create monthly admin checklist |
| User Variable not created before form | Form shows "Invalid Variable" | Create User Variable first, then add to form |
| RTP with no default value | Users confused by empty prompt | Always set a sensible default |
| Using SubVar where User Variable needed | All users see same entity | Use User Variable for per-user filtering |
| Using User Variable in rules | Not supported — rules use RTPs | Use Runtime Prompts in rules |
| Typo in `&VarName` | Rule fails with "variable not found" | Case-sensitive — verify exact name |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: What are the three types of variables in EPBCS and when do you use each?**
> **Substitution Variables** (`&CurrMonth`): Admin sets globally, used in forms and rules for dynamic time references. Change monthly/quarterly. **User Variables** (`UserEntity`): Each user sets their own value, used in forms to personalize which data they see. Set once, rarely changed. **Runtime Prompts** (`{RTP_Scenario}`): Pop-up dialog when launching a rule — user picks members at execution time. Used only in business rules.

### Intermediate
**Q: A form uses `&CurrMonth` in the column. The admin updates CurrMonth from "Jul" to "Aug." Do users need to do anything?**
> No — substitution variables are resolved server-side when the form loads. The next time any user opens the form, it automatically shows "Aug" instead of "Jul." No form redesign, no user action. This is the key advantage of substitution variables — one admin change propagates everywhere instantly.

### Architect
**Q: Design the complete variable strategy for Hotel Pvt Ltd's monthly forecasting process.**
> **Substitution Variables (6):** `&CurrMonth`, `&CurrYear`, `&PriorMonth`, `&PriorYear`, `&ForecastStart`, `&ActualThrough`. Admin updates all 6 on the 1st of each month. These drive form columns (showing actual months vs forecast months) and rule FIX statements. **User Variables (3):** `UserEntity` (each GM's hotel), `UserDepartment` (department managers), `UserScenario` (defaults to Budget). **RTPs (3 per rule):** Each calculation rule prompts for Scenario, Version, Year — with defaults from substitution variables. The monthly admin workflow: (1) Update 6 SubVars, (2) Post announcement, (3) Users open forms — automatically see new month.
