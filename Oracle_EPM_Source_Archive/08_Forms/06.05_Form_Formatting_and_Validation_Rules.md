# 06.05 — Form Formatting and Validation Rules: Complete Guide

> **Module:** 06_Forms | **Topic:** Conditional Formatting, Data Validation Rules, Format Rules
> **Audience:** Service Administrator / Power User

---

## 1. WHY — What Real-World Problem Does This Solve—

**The problem:** A plain white grid with black numbers is useless for decision-making. The CFO opens a P&L form and sees 200 rows of numbers — which ones are important— Which expenses exceeded budget— Which hotels are underperforming— Without visual cues, critical data is buried in noise.

**The solution:** Format Rules and Data Validation Rules make forms **visually intelligent**:
- **Format Rules:** Conditional formatting — change cell colors, fonts, and styles based on data values
- **Data Validation Rules:** Block invalid data entry — prevent users from entering negative revenue or unrealistic numbers

---

## 2. WHAT — Two Distinct Rule Types

```
Form Rules (Layout tab → Format/Validation section)
│
├── FORMAT RULES (visual only — don't block data entry)
│   ├── Conditional formatting based on cell values
│   ├── Change background color, font color, font style
│   └── Example: Red background when Variance < 0
│
└── DATA VALIDATION RULES (block/warn on invalid data)
    ├── Prevent entry of values outside valid range
    ├── Show error/warning messages to users
    └── Example: Block if Revenue < 0
```

## 3. FORMAT RULES — COMPLETE REFERENCE

### Creating a Format Rule

```
Form Designer → Layout tab → Format/Validation Rules section → Add Rule

Rule Name: [Highlight_Negative_Variance______]
Rule Type: Format Rule

Condition:
  IF [Cell Value] [Is Less Than] [0]

Format:
  Background Color: [🔴 Red]
  Font Color: [⬜ White]
  Font Style: [Bold]
```

### All Condition Operators

| Operator | Description | Example |
|----------|-------------|---------|
| **Equals** | Exact match | Cell = 0 → grey out |
| **Not Equal To** | Anything except | Cell ≠ #MISSING → show data |
| **Greater Than** | Above threshold | Cell > 1000000 → highlight |
| **Less Than** | Below threshold | Cell < 0 → red |
| **Greater Than or Equal** | At or above | Cell ≥ 100 → green |
| **Less Than or Equal** | At or below | Cell ≤ -10000 → dark red |
| **Between** | Range check | 0 < Cell < 100 → yellow |
| **Is Missing** | #MISSING check | Cell = #MISSING → grey |
| **Is Not Missing** | Has data | Cell ≠ #MISSING → normal |

### All Format Options

| Property | Options | Description |
|----------|---------|-------------|
| **Background Color** | Color picker | Cell background |
| **Font Color** | Color picker | Text color |
| **Font Style** | Normal, Bold, Italic, Bold Italic | Text weight |
| **Number Format** | Override precision | Custom number formatting |

### Multiple Conditions (AND/OR)

```
Rule: "Traffic Light Variance"

Condition 1: IF Variance% > 5  → Background: 🟢 Green (favorable)
Condition 2: IF Variance% BETWEEN -5 AND 5 → Background: 🟡 Yellow (on target)
Condition 3: IF Variance% < -5 → Background: 🔴 Red (unfavorable)
```

### Applying to Specific Members

```
Format rules can target specific dimension members:

Rule: "Highlight Revenue Totals"
Apply To:
  Account: Total_Revenue, Total_Expenses, Net_Income (specific members)
  Entity: All (apply to all entities)
  
Condition: Always (no condition — always format these rows)
Format: Font = Bold, Background = Light Blue
```

## 4. DATA VALIDATION RULES — COMPLETE REFERENCE

### Creating a Data Validation Rule

```
Form Designer → Layout tab → Format/Validation Rules → Add Rule

Rule Name: [Block_Negative_Revenue________]
Rule Type: Data Validation Rule

Condition:
  IF [Cell Value] [Is Less Than] [0]

Action:
  ○ Error (blocks save — user MUST fix)
  ● Warning (shows warning but allows save)
  
Message: "Revenue cannot be negative. Please enter a positive value."

Apply To:
  Account: Room_Revenue, F&B_Revenue, Spa_Revenue
```

### Validation Action Types

| Action | Behavior | When to Use |
|--------|----------|-------------|
| **Error** | Blocks form save entirely until fixed | Hard constraints: negative revenue, impossible values |
| **Warning** | Shows warning but allows save | Soft constraints: unusually high values, sanity checks |

### Common Validation Patterns

```
1. NEGATIVE PREVENTION:
   IF Cell < 0 → Error: "This value cannot be negative"
   Apply to: Revenue accounts

2. UPPER LIMIT CHECK:
   IF Cell > 10000000 → Warning: "Value exceeds ₹1Cr — please verify"
   Apply to: All expense accounts

3. PERCENTAGE RANGE:
   IF Cell > 100 OR Cell < 0 → Error: "Percentage must be 0-100"
   Apply to: Occupancy_Rate, Profit_Margin

4. MANDATORY ENTRY:
   IF Cell IS MISSING → Warning: "Please enter a value"
   Apply to: Required KPIs (Revenue, Headcount)

5. YEAR-OVER-YEAR VARIANCE:
   IF ABS(Cell - PriorYear) > Cell * 0.50 → Warning: "Change exceeds 50%"
   Apply to: Budget accounts (sanity check)
```

---

## 5. EVALUATION ORDER

When multiple rules apply to the same cell, they execute in order (top to bottom in the rule list). Later rules can override earlier ones.

```
Rule 1: IF Cell IS MISSING → Background: Grey
Rule 2: IF Cell < 0 → Background: Red  ← overrides Rule 1 if cell is negative
Rule 3: IF Cell > 1000000 → Background: Green ← overrides Rules 1-2 if > 1M

Order matters! Drag rules up/down to control priority.
```

## 7. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Too many format rules on one form | Form loads slowly (rules evaluated per cell) | Limit to 10-15 rules per form |
| Error validation on calculated cells | Users can't fix dynamic calc cells | Apply validation only to input (Store) members |
| Forgot to specify "Apply To" | Rule applies to ALL cells (performance hit) | Always target specific accounts/members |
| Rule order wrong | Green overrides red for negative values | Drag "negative=red" rule AFTER "positive=green" |
| Validation on historical months | Users get errors on locked past data | Apply validation only to editable periods |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: What is the difference between a Format Rule and a Data Validation Rule—**
> A **Format Rule** changes the visual appearance of cells (colors, fonts) based on conditions but never blocks data entry. A **Data Validation Rule** can actually prevent the user from saving the form if invalid data is entered (Error action) or show a warning while still allowing save (Warning action). Use format rules for visual intelligence; use validation rules for data integrity.

### Intermediate
**Q: A form has 5,000 cells and 20 format rules. Users complain it's slow. How do you optimize—**
> (1) Reduce rules to essential ones (5-8 max). (2) Use "Apply To" to target specific members instead of all cells. (3) Move complex conditional logic to business rules that set a "Status" Smart List member, then format based on the Smart List value (1 rule instead of 5). (4) Consider using member formulas for variance calculations instead of format rule conditions. (5) If the form is read-only (P&L summary), format rules are fine — the performance impact is mainly on load, not interaction.
