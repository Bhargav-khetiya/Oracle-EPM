# 06.06 — Flex Forms in Smart View: Complete Guide

> **Module:** 06_Forms | **Topic:** Flex Forms — Dynamic Grid Extension in Smart View
> **Audience:** Service Administrator / Power User / Smart View Users

---

## 1. WHY — What Real-World Problem Does This Solve—

**The problem:** Standard forms are fixed — the admin defines which members appear on rows and columns. If a user needs to see a member not on the form, they must ask the admin to redesign it. For ad hoc analysis, this is painfully slow. Users want Excel-like flexibility to add/remove members on the fly.

**The solution:** Flex Forms allow Smart View users to **dynamically add or remove members** from rows and columns without redesigning the form. The user types a member name in a new row/column in Excel, refreshes, and the data appears — while still respecting the form's security and validation rules.

---

## 2. WHAT — Plain English Definition

A Flex Form is a **regular form with flex mode enabled** that allows Smart View users to:
- Add new member rows/columns by typing member names directly in Excel
- Remove rows/columns by deleting the member name
- Submit data for members not originally in the form definition
- Maintain all form properties (formatting, validation, Smart Push)

```
Standard Form (Fixed):          Flex Form (Dynamic):
┌─────────────────────┐        ┌─────────────────────────────┐
│ Jan  Feb  Mar       │        │ Jan  Feb  Mar  Apr  May     │ ← user added Apr, May
│ Room_Rev   100  110 │        │ Room_Rev   100  110  120    │
│ F&B_Rev     50   55 │        │ F&B_Rev     50   55   60   │
│ Spa_Rev     20   22 │        │ Spa_Rev     20   22   25   │
│                     │        │ Gym_Rev     10   12   15   │ ← user added Gym_Rev
└─────────────────────┘        └─────────────────────────────┘
```

> ⚠️ **Key:** Flex Forms work ONLY in Smart View (Excel). They do NOT work in the web browser.

---

## 3. HOW — Enabling Flex Forms

### Step 1: Enable in Form Designer

```
Form Designer → Layout tab → Smart View Options section

  ☑ Enable flex form for rows
  ☑ Enable flex form for columns  (optional — usually just rows)
  ☑ Show invalid members for flex form  (highlights typos)
```

### Step 2: Per-Dimension Settings

```
Form Designer → Layout tab → Click row dimension → Dimension Properties

  ☑ Flex beyond form definition  (allows members outside form definition)
```

### Step 3: User Experience in Smart View

```
1. User opens the form in Smart View (Excel)
2. Form loads with standard members defined by admin
3. User types "Gym_Revenue" in an empty row below Spa_Revenue
4. User clicks Refresh
5. Smart View validates the member name against the dimension
6. If valid → data loads for Gym_Revenue
7. If invalid → cell highlighted in red (if "Show invalid members" enabled)
8. User enters data and clicks Submit → data saved to Essbase
```

## 4. FLEX FORM PROPERTIES — COMPLETE

| Property | Location | Description |
|----------|----------|-------------|
| **Enable flex form for rows** | Smart View Options | Allow adding/removing row members |
| **Enable flex form for columns** | Smart View Options | Allow adding/removing column members |
| **Show invalid members** | Smart View Options | Highlight invalid member names in red |
| **Flex beyond form definition** | Dimension Properties (per dim) | Allow members outside the form's member selection |
| **Repeat member labels** | Smart View Options | Auto-enabled for flex forms (required) |

---

## 5. FLEX FORM RULES AND RESTRICTIONS

| Rule | Description |
|------|-------------|
| **Smart View only** | Flex Forms do NOT work in the web browser |
| **Security applies** | Users can only add members they have access to |
| **Valid Intersections apply** | Invalid intersections are still blocked |
| **Form rules apply** | Format rules, validation rules still enforce |
| **Smart Push works** | Cross-cube push still fires on save |
| **Can't change POV** | Page and POV dimensions remain fixed |
| **Member must exist** | Can't create NEW members — only add existing ones |
| **Attribute members** | Can add attribute members if dimension is on the form |

## 6. USE CASES

| Scenario | How Flex Form Helps |
|----------|-------------------|
| **Ad hoc analysis** | User adds specific accounts to investigate variance |
| **New member data entry** | Admin adds a new hotel — user adds it to the form without redesign |

## 8. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| "Flex beyond form definition" not checked | Users can't add members outside form | Enable per-dimension in Dimension Properties |
| User types wrong member name | "Invalid member" error | Enable "Show invalid members" to highlight |
| Trying flex in web browser | No flex functionality visible | Explain: flex = Smart View only |
| Flex on both rows AND columns | Confusing grid, data entry errors | Usually enable flex on rows only |
| Not enabling "Repeat member labels" | Flex doesn't work | Auto-enabled — don't manually disable |

## 9. INTERVIEW QUESTIONS

### Beginner
**Q: What is a Flex Form and where does it work—**
> A Flex Form is a Planning form with "flex mode" enabled that allows users to dynamically add or remove dimension members from rows and columns in Smart View (Excel). It does NOT work in the web browser. The user types a member name in an empty row, refreshes, and the data loads — without needing admin to redesign the form.

### Intermediate
**Q: A Flex Form has Revenue accounts on rows with flex enabled. A user adds "Salary_Expense" (an expense account) to the form. What happens—**
> It works — the user can add any valid Account member, even if it's outside the form's original Account member selection, as long as "Flex beyond form definition" is enabled for the Account dimension and the user has Read/Write access to Salary_Expense. The cell values load normally. However, format rules defined for Revenue accounts won't apply to the added Expense row. Data validation rules that target specific accounts also won't apply unless they cover all accounts.
