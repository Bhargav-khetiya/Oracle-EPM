# 06.07 — Form Business Rules: Complete Guide

> **Module:** 06_Forms | **Topic:** Attaching Business Rules to Forms
> **Audience:** Service Administrator / Power User

---

## 1. WHY — What Real-World Problem Does This Solve—

**The problem:** A user enters revenue data in a form and clicks Save. But the P&L totals don't update because the aggregation rule hasn't run. The user has to navigate to Rules, find the right rule, fill in runtime prompts, and launch it manually. After every single save. Every time.

**The solution:** Attach business rules directly to forms so they run **automatically** on load, on save, or via a manual button — without the user leaving the form.

---

## 2. THREE RULE ATTACHMENT MODES

| Mode | When It Runs | User Action | Use Case |
|------|-------------|-------------|----------|
| **On Load (Before)** | Before the form data loads | None — automatic | Pre-populate calculated fields before display |
| **On Save (After)** | After the user clicks Save | None — automatic | Recalculate totals, aggregate, push data |
| **Manual (Ad Hoc)** | When user clicks Actions → Business Rules | User must click | Optional rules: Clear data, Copy version, Forecast |

```
Form Lifecycle:
  1. User opens form
  2. 🔄 ON LOAD rules execute (before data shown)
  3. Form data displays
  4. User enters/edits data
  5. User clicks Save
  6. Data saves to Essbase
  7. 🔄 ON SAVE rules execute (after save)
  8. Form refreshes with updated calculations
  9. User can also click Actions → Business Rules
  10. 🔄 MANUAL rules execute on demand
```

### Rule Properties on Forms

| Property | Description |
|----------|-------------|
| **Run on Load** | Execute before form data loads |
| **Run on Save** | Execute after data saves |
| **Manual** | Available in Actions → Business Rules menu |
| **Hide from user** | Rule runs but isn't visible in the rule list |
| **Use form members as context** | Pass POV/Page selections as runtime prompts |

## 4. RUNTIME PROMPT BEHAVIOR ON FORMS

When a rule with Runtime Prompts is attached to a form:

### On Save (Automatic)

```
RTPs are pre-filled from the form's POV/Page selections:
  Form POV: Scenario=Budget, Version=Working, Year=FY2026
  
  Rule RTP_Scenario → auto-fills with "Budget"
  Rule RTP_Version → auto-fills with "Working"
  Rule RTP_Year → auto-fills with "FY2026"
  
  User sees NO popup — rule runs silently with form context.
```

### Manual Launch

```
User clicks Actions → Business Rules → "Clear_Forecast"

If rule has RTPs not matchable from form:
  → RTP dialog pops up for user to fill remaining prompts
  
If ALL RTPs match form dimensions:
  → Option 1: Run silently (if "Use form members as context" = ☑)
  → Option 2: Show dialog with pre-filled values (user can override)
```

---

## 5. RULE EXECUTION ORDER

When multiple rules are attached:

```
On Save execution order:
  Rule 1: Hotel_Rollup      → runs first (aggregation)
  Rule 2: Currency_Conversion → runs second (after rollup)
  
  Order = order in the Selected Rules list (top to bottom)
  Drag rules up/down to change execution order.
```

> ⚠️ **CRITICAL:** If Rule 2 depends on Rule 1's output (e.g., currency conversion needs aggregated totals), ORDER MATTERS. Always test the execution sequence.

## 6. SHOW ME — Hotel Pvt Ltd Form-Rule Attachments

### Revenue Entry Form

```
Form: "Room_Revenue_Entry"
Attached Rules:
  1. "Calculate_Room_Totals" → On Save (auto-aggregate room revenue)
  2. "Calculate_KPIs" → On Save (calculate ADR, RevPAR, Occupancy%)
  
User experience:
  GM enters Jan room revenue = ₹85,00,000
  Clicks Save
  → Essbase saves the data
  → Rule 1 runs: aggregates Room_Revenue to Total_Revenue
  → Rule 2 runs: calculates ADR = Revenue / Occupied_Rooms
  → Form refreshes: user sees updated totals and KPIs instantly
```

### P&L Summary Form (Read-Only)

```
Form: "Hotel_P&L_Summary"
Attached Rules:
  1. "Full_Aggregation" → On Load (refresh aggregations before display)
  
User experience:
  CFO opens P&L form
  → Rule runs before data displays (2-3 second delay)
  → P&L shows fully aggregated, current numbers
  → No stale data ever displayed
```

### Forecast Entry Form

```
Form: "Revenue_Forecast_Entry"
Attached Rules:
  1. "Calculate_Forecast_Totals" → On Save
  2. "Copy_Actual_to_Forecast" → Manual (Actions → Business Rules)
  3. "Clear_Forecast_Data" → Manual (Actions → Business Rules)
  
User experience:
  GM enters forecast data → Save → totals calculate automatically
```

## 7. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Heavy rule on "On Load" | Form takes 30+ seconds to open | Move to "On Save" or reduce rule scope |
| Wrong rule order | Currency conversion runs before aggregation | Reorder: aggregate first, convert second |
| RTPs not matching form dimensions | Rule fails silently or shows unexpected popup | Ensure RTP variable names match form dimension names |
| Too many "On Save" rules | Save takes 30+ seconds | Consolidate into a single Ruleset |
| "On Save" rule fails | User doesn't know — data saved but calcs wrong | Add error logging; test rules thoroughly |
| Destructive rule as Manual | User accidentally runs "Clear Data" | Add confirmation prompt or remove from form |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: What's the difference between On Load and On Save rules on a form—**
> **On Load** rules run BEFORE the form data displays — useful for refreshing calculations so users always see current numbers. **On Save** rules run AFTER the user saves data — useful for recalculating totals, aggregating, and pushing data to other cubes. On Load adds a delay when opening the form; On Save adds a delay when saving.

### Intermediate
**Q: A form has 3 On Save rules and users complain the save takes 45 seconds. How do you optimize—**
> (1) Consolidate the 3 rules into a single Ruleset that runs them sequentially — reduces overhead of 3 separate rule invocations. (2) Optimize each rule's FIX statement — make sure they only process the intersection the user changed, not the entire cube. (3) Check if any rule is redundant (e.g., aggregation is unnecessary if parents are Dynamic Calc in Hybrid Mode). (4) Consider using "Smart Push" instead of a rule for cross-cube data movement. (5) If one rule is for reporting only, move it to a nightly batch job instead of On Save.
