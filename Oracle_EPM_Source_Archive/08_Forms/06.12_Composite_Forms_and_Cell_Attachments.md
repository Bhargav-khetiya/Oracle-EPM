# 06.12 — Composite Forms and Cell Attachments: Complete Guide

> **Module:** 06_Forms | **Topic:** Composite Forms, Cell-Level Documents
> **Audience:** Service Administrator / Power User

---

## 1. WHY — What Real-World Problem Does This Solve—

### Composite Forms Problem
A hotel GM needs to see Revenue data (FinPlan cube), Headcount data (Workforce cube), and CapEx data (Capital cube) on **one screen**. Without composite forms, they'd open 3 separate forms and mentally correlate the data.

### Cell Attachments Problem
A GM enters ₹15,00,000 for Renovation_CapEx. The CFO asks: "What's the justification— Without cell attachments, the GM has to send an email or write in a comment — disconnected from the data.

**The solutions:**
- **Composite Forms** display multiple forms from different cubes on a single page
- **Cell Attachments** (Cell-Level Documents) let users attach files/URLs/text to individual cells

---

## 2. COMPOSITE FORMS — DEEP DIVE

### What They Are
A Composite Form is a **container that holds 2-8 simple forms** on one page, arranged in a grid layout. Each sub-form can be from a **different cube**, enabling cross-cube visibility.

```
┌── Composite Form: "Hotel Executive Summary" ─────────────────────┐
│                                                                   │
│  ┌─── Sub-Form 1: Revenue (OEP_FS) ─────┐  ┌── Sub-Form 2: ───┐│
│  │ Account      │ Jan   │ Feb   │ Mar    │  │ Headcount (WFP)   ││
│  │──────────────┼───────┼───────┼────────│  │ Dept   │ HC │ Sal ││
│  │ Room Revenue │ 85L   │ 90L   │ 88L   │  │ F&B    │ 45 │ 12L ││
│  │ F&B Revenue  │ 22L   │ 24L   │ 21L   │  │ Rooms  │ 30 │ 8L  ││
│  │ Total Rev    │ 1.12Cr│ 1.18Cr│ 1.09Cr│  │ Admin  │ 15 │ 5L  ││
│  └──────────────────────────────────────┘  └───────────────────┘│
│                                                                   │
│  ┌─── Sub-Form 3: CapEx (OEP_CP) ───────────────────────────────┐│
│  │ Project          │ Budget    │ Actual    │ Variance          ││
│  │──────────────────┼───────────┼───────────┼───────────────────││
│  │ Room Renovation  │ ₹50,00,000│ ₹42,00,000│ ₹8,00,000 (16%) ││
│  │ Kitchen Upgrade  │ ₹20,00,000│ ₹22,00,000│ -₹2,00,000 (-10%)││
│  └──────────────────────────────────────────────────────────────┘│
└───────────────────────────────────────────────────────────────────┘
```

### Creating a Composite Form

```
Navigator → Create and Manage → Forms → Create → Composite Form

Step 1: Name: "Hotel_Executive_Summary"
Step 2: Layout Grid: [2 columns × 2 rows]
Step 3: Assign forms to grid positions:
  Position (1,1): Revenue_Summary (OEP_FS)
  Position (1,2): Headcount_Summary (OEP_WFP)
  Position (2,1): CapEx_Tracker (OEP_CP) — spans 2 columns
Step 4: Configure shared dimensions:
  ☑ Synchronize Entity across sub-forms
  ☑ Synchronize Scenario across sub-forms
Step 5: Save
```

### Dimension Synchronization

When multiple sub-forms share dimensions (Entity, Scenario, Year), you can **synchronize** them:

```
Synchronize Entity:
  When user changes Entity dropdown to "Mumbai_Hotel" on Form 1:
  → Form 2 automatically switches to Mumbai_Hotel
  → Form 3 automatically switches to Mumbai_Hotel
  
  All sub-forms stay in sync without the user changing each one!
```

| Synchronizable | Non-Synchronizable |
|---------------|-------------------|
| Entity | Account (different per cube) |
| Scenario | Custom dimensions |
| Version | Cube-specific dimensions |
| Year | Employee (WFP only) |
| Period | Asset (CP only) |

## 3. COMPOSITE FORM PROPERTIES

| Property | Description |
|----------|-------------|
| **Grid Layout** | Rows × Columns grid arrangement (1×2, 2×2, etc.) |
| **Sub-form assignment** | Which form goes in which grid position |
| **Column span** | A form can span multiple columns |
| **Row span** | A form can span multiple rows |
| **Synchronize dimensions** | Share dimension selections across forms |
| **Hide form borders** | Seamless look (forms blend together) |

## 4. CELL-LEVEL DOCUMENTS (ATTACHMENTS)

### What They Are
Users can attach files, URLs, or text notes to **individual cells** in a form. The attachment is linked to the specific data intersection (Scenario/Version/Entity/Account/Period).

### Enabling Cell Attachments

```
Form Designer → Display Properties:
  ☑ Enable cell-level document

After enabling:
  - A paperclip icon (📎) appears on cells with attachments
  - Users right-click a cell → "Cell-Level Documents" to add/view
```

### Attachment Types

| Type | Description | Example |
|------|-------------|---------|
| **File** | Upload a document (PDF, Excel, Word, image) | Renovation quote PDF |
| **URL** | Link to an external webpage | Link to vendor proposal |
| **Text** | Free-text note | "Approved by CFO on Aug 12" |

### User Workflow

```
1. User right-clicks a cell (e.g., CapEx → Renovation → Q3)
2. Selects "Attachments" or "Cell-Level Documents"
3. Dialog opens:
   ┌── Cell Documents ────────────────────────────┐
   │                                               │
   │  Intersection: CapEx / Renovation / Q3 / 2026│
   │                                               │
   │  Existing:                                    │
   │  📄 Vendor_Quote_Aug2026.pdf (uploaded Aug 5) │
   │  🔗 https://vendor.com/quote/123             │
   │  📝 "CFO approved ₹50L budget" (Aug 10)      │
   │                                               │
   │  [+ Add File]  [+ Add URL]  [+ Add Text]     │
   │  [Delete Selected]                            │
   └───────────────────────────────────────────────┘
4. Adds attachment → 📎 icon appears on the cell
```

## 5. CELL COMMENTS vs CELL ATTACHMENTS vs SUPPORTING DETAILS

| Feature | Cell Comments | Cell Attachments | Supporting Details |
|---------|-------------|-----------------|-------------------|
| **What** | Text notes | Files, URLs, text | Line-item breakdowns |
| **Storage** | Application DB | Application DB | Essbase |
| **Visible to** | All users with access | All users with access | All users with access |
| **Attached to** | Specific cell intersection | Specific cell intersection | Account member |
| **Enable** | Always available | Form property must be enabled | Always available |
| **Access** | Right-click → Comments | Right-click → Attachments | Right-click → Supporting Details |
| **Use case** | Quick notes | Supporting documents | Detail behind a total |

## 7. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Too many sub-forms (6+) | Composite form loads very slowly | Limit to 3-4 sub-forms |
| Not synchronizing dimensions | User changes entity on one form, others don't follow | Enable dimension synchronization |
| Cell attachments on every form | Storage fills up quickly | Enable only on forms where justification is needed |
| Composite form as data entry | Hard to navigate, confusing UX | Keep data entry on simple forms; composites for dashboards |
| Large file attachments | Upload limits, storage issues | Limit file size to 5-10MB; use URLs for large files |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: What is a Composite Form and why would you use one—**
> A Composite Form displays 2-8 simple forms on a single page, arranged in a grid. You use it when users need to see data from **multiple cubes** on one screen — like Revenue (FinPlan cube) alongside Headcount (Workforce cube). Dimensions can be synchronized so changing Entity on one form updates all others automatically.

### Intermediate
**Q: A Composite Form has 4 sub-forms from 3 different cubes. The form takes 30 seconds to load. How do you optimize—**
> (1) Reduce sub-forms to 3 (combine where possible). (2) Enable Suppress Missing Data and Suppress Missing Blocks on each sub-form. (3) Reduce member selections — use smaller member lists on rows/columns. (4) Make read-only sub-forms truly read-only (less processing). (5) Consider replacing the composite form with a Dashboard — dashboards are lighter and load components asynchronously. (6) Check if synchronization is causing cascading refreshes — simplify synchronized dimensions.
