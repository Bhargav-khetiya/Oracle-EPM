# 06.14 Form Properties Tab — Exhaustive Reference

> **Module:** 06_Forms  
> **Topic:** 14 — Every Option in the Form Properties Tab  
> **Target Audience:** Administrator / Consultant / Architect  

---

## Introduction

When you create or edit a form in Oracle EPM Cloud (`Navigator → Forms → [New/Edit Form]`), the Form Designer has multiple tabs. The **Properties** tab is the first tab and controls the form's identity, cube association, display settings, and fundamental behavior.

This document covers **every single field** on the Properties tab and every sub-section.

---

## Navigation Path
```
Navigator → Forms → [Create New Form] or [Edit Existing Form] → Properties Tab
```

---

# SECTION 1: FORM IDENTITY

| Field | Description | Options / Values | Default | Impact |
|-------|-------------|------------------|---------|--------|
| **Form Name** | Internal name (used in URLs, APIs, EPM Automate) | Alphanumeric, underscores, hyphens. No spaces in some contexts. | — | Must be unique within the folder |
| **Description** | Optional text describing the form's purpose | Free text (up to 255 chars) | (empty) | Shown in form listing and hover tooltips |
| **Instructions** | User-facing instructions displayed above the grid when the form opens | Free text with basic HTML formatting | (empty) | Visible to end users — use for guidance |
| **Folder** | The folder where the form is organized | Folder selector (browse hierarchy) | Root | Affects form listing and security inheritance |

### Form Naming Best Practices:
| Pattern | Example | Why |
|---------|---------|-----|
| `Module_Purpose_CubeShort` | `FIN_Revenue_Entry_FS` | Immediately identifies module, use case, and cube |
| `Process_Step_Number` | `Budget_01_Revenue` | Aligns forms to task list steps |
| Avoid spaces | `Rev_Entry` not `Rev Entry` | Spaces cause issues in URLs and EPM Automate |

---

# SECTION 2: CUBE (PLAN TYPE) SELECTION

| Field | Description | Options | Default | Impact |
|-------|-------------|---------|---------|--------|
| **Cube** | Which Essbase cube (Plan Type) this form reads/writes data from | Dropdown: All plan types (e.g., `Plan1`, `Plan2`, `Plan3`, `OEP_FS`, `OEP_WFP`, `Custom`) | First plan type | Determines which dimensions and members are available in the Layout tab |

### Multi-Cube Considerations:
- A single form can ONLY connect to **ONE cube**
- To show data from multiple cubes, use **Composite Forms** or **Dashboards**
- If you change the cube after building the layout, all member selections are cleared

# SECTION 3: GRID PROPERTIES — DISPLAY

## 3.1 Suppression Options

| Property | What It Does | Options | Default | When to Enable | When to Disable |
|----------|-------------|---------|---------|----------------|-----------------|
| **Suppress Missing Blocks** | Hides rows where the physical Essbase data block doesn't exist | ☑️ / ☐ | ☐ (Off) | ✅ ALWAYS on production forms with large dimensions on rows | When users need to enter data into brand-new intersections |
| **Suppress Missing Data** | Hides rows/columns where the block exists but cells are `#Missing` | ☑️ / ☐ | ☐ (Off) | Reporting-only forms (variance analysis) | Data entry forms (users need to see empty cells to type in) |
| **Suppress Missing Blocks on Columns** | Same as Suppress Missing Blocks but for columns | ☑️ / ☐ | ☐ (Off) | When columns have sparse dimensions with many empty intersections | Rare — columns usually have dense dimensions |
| **Suppress Missing Data on Columns** | Same as Suppress Missing Data but for columns | ☑️ / ☐ | ☐ (Off) | Reporting dashboards | Data entry forms |
| **Suppress Invalid Rows** | Hides rows with invalid intersections (as defined by Valid Intersections rules) | ☑️ / ☐ | ☐ (Off) | When Valid Intersections are configured | When debugging intersection issues |
| **Suppress Invalid Columns** | Same for columns | ☑️ / ☐ | ☐ (Off) | When Valid Intersections are configured | When debugging |

### The Critical Rule: Suppress Missing Blocks = THE Most Important Checkbox
```
SCENARIO: Account dimension has 500 members on rows. Entity on Page.
- User selects Entity = "New_Branch_Office" (just created, no data loaded)
- Suppress Missing Blocks = OFF:
  → Essbase queries 500 × all_sparse_combinations = potentially 50,000+ queries
  → Form loads in 3 minutes showing 500 empty rows
  → Browser may crash

- Suppress Missing Blocks = ON:
  → Essbase scans index, finds 0 blocks for New_Branch_Office
  → Form loads in 0.5 seconds showing "No Data Found"
```

## 3.2 Display Options

| Property | What It Does | Options | Default | Architect Note |
|----------|-------------|---------|---------|----------------|
| **Enable Grid Spread** | Allows users to type into parent periods (e.g., YearTotal) and spread to children | ☑️ / ☐ | ☐ (Off) | Enable for P&L data entry (Revenue/Expense). **Disable for Headcount** (0.83 employees per month is invalid) and Balance Sheet accounts. |
| **Enable Cell-Level Document Attachments** | Users can right-click cells and attach files (PDF, Excel) | ☑️ / ☐ | ☐ (Off) | **DANGER:** EPM relational DB has ~150GB limit. 500 users × 10MB PDFs = fills up fast. Use sparingly. |
| **Enable Mass Allocate** | Allows users to mass-spread values across children using the grid's Allocate feature | ☑️ / ☐ | ☐ (Off) | Enable for top-down planning where managers allocate targets to departments |
| **Show Currency** | Displays currency code next to values | ☑️ / ☐ | Based on app | Enable for multi-currency apps. Disable for single-currency to save screen space. |
| **Show Alias by Default** | Shows member aliases instead of member names | ☑️ / ☐ | ☑️ (On) | Almost always ON for end users. Turn OFF for admin/debugging forms. |
| **Display Member Names / Aliases in Row Headers** | What appears in the row labels | `Member Name Only`, `Alias Only`, `Member Name : Alias`, `Alias : Member Name` | `Alias Only` | Use `Member Name : Alias` for admin forms so you see both |
| **Display Member Names / Aliases in Column Headers** | Same for column labels | Same options | `Alias Only` | Same guidance as rows |

## 3.3 Precision and Formatting

| Property | What It Does | Options | Default | Architect Note |
|----------|-------------|---------|---------|----------------|
| **Minimum Precision** | Minimum decimal places shown | `0` to `10` | `0` | Set to `0` for currency (whole dollars). Set to `2` for FTE headcount. |
| **Maximum Precision** | Maximum decimal places shown | `0` to `10` | `0` | Match to Minimum for consistent display. Higher = more granular data. |
| **Cell Text** | Allow text comments on individual cells | ☑️ / ☐ | ☐ (Off) | Useful for budget justification but increases relational DB size |

# SECTION 4: GRID PROPERTIES — CALCULATION

| Property | What It Does | Options | Default | Impact |
|----------|-------------|---------|---------|--------|
| **Run Form Rules on Save** | Execute attached business rules when the user clicks Save | ☑️ / ☐ | ☐ (Off) | If enabled and a heavy rule is attached, user's browser freezes until the rule completes |
| **Calculate Form on Save** | Run basic dynamic calculations (subtotals) within the form grid without calling Essbase | ☑️ / ☐ | ☐ (Off) | Lightweight — doesn't call Essbase. Good for instant feedback on subtotals |
| **Run Formula on Save** | Execute member formulas on the form data | ☑️ / ☐ | ☐ (Off) | Triggers Dynamic Calc member formulas upon save |

### Run Form Rules on Save — Architecture Decision:

| Rule Weight | Recommendation |
|------------|---------------|
| Sub-second (simple formula) | ✅ Enable Run on Save — instant feedback |
| 1–10 seconds | ⚠️ Consider Groovy for faster execution |
| 10+ seconds | ❌ Disable Run on Save. Use "Run in Background" or schedule via job |

# SECTION 5: SMART VIEW / EXCEL PROPERTIES

| Property | What It Does | Options | Default | Impact |
|----------|-------------|---------|---------|--------|
| **Enable Flex Form** | Converts the web form into a dynamic Excel sandbox in Smart View | ☑️ / ☐ | ☐ (Off) | Users can add rows, use Excel filters, type #Missing. Most powerful feature for power users. |
| **Enable for Ad Hoc** | Allows users to open this form's intersection as a starting point for Ad Hoc analysis in Smart View | ☑️ / ☐ | ☐ (Off) | Gives power users flexibility to pivot, drill, and explore beyond the form layout |
| **Show Row/Column Headers in Smart View** | Display dimension headers in Smart View | ☑️ / ☐ | ☑️ (On) | Usually keep ON for clarity |

### Flex Form Deep Dive:
| Feature | Available in Flex Form— |
|---------|------------------------|
| Insert blank rows | ✅ Yes |
| Native Excel filtering | ✅ Yes |
| Excel formulas (SUMIF, VLOOKUP) | ✅ Yes (client-side only) |
| Submit modified data back to Essbase | ✅ Yes |
| Bypasses some web form validation rules | ⚠️ Yes — build Essbase-side validation |
| Groovy Save Data script triggers | ✅ Yes |
| Conditional formatting from web form | ❌ No (use Excel formatting) |

## Interview Questions

### Intermediate
**Q: A user says they cannot enter data into a new product that was just added to the outline. The form shows the product on rows but the cell is grayed out. What are the possible causes—**
> A: Multiple possibilities: (1) `Suppress Missing Blocks` or `Suppress Missing Data` is hiding the intersection, (2) The member's Data Storage is set to `Label Only` or `Dynamic Calc` (neither allows input), (3) The user doesn't have Write access to the member via Access Control, (4) The cell falls into a read-only intersection defined by Valid Intersections, (5) The member is not assigned to the form's Plan Type (cube), (6) A validation rule is rejecting the input.

### Architect
**Q: A finance team asks for a form where 200 employees enter their own expense data, and the form immediately recalculates total department expenses when any employee saves. The recalculation script takes 8 seconds. How do you architect this—**
> A: Do NOT enable "Run Form Rules on Save" — 200 users × 8 seconds = overlapping calculations, lock contention, and browser freezes. Instead: (1) Enable "Calculate Form on Save" for instant client-side subtotals (no server load), (2) Create a Groovy "Save Data" rule that only recalculates the specific department the user belongs to (narrow FIX scope → sub-second), (3) Schedule a background aggregation rule every 5 minutes or on-demand for the CFO's dashboard.

---

## Summary

The Form Properties tab contains **~30+ settings** that control everything from data display to calculation behavior to security. The two most impactful settings are:
1. **Suppress Missing Blocks** — Always ON (prevents form crashes)
2. **Run Form Rules on Save** — Use with extreme caution (can freeze user browsers)

Every other setting should be configured based on the form's specific purpose (data entry vs reporting) and the user audience (power users vs casual planners).
