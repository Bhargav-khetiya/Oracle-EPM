## 🏢 1. What is a Form—

A **Form** is a **data entry screen** (like an Excel sheet) where users enter budget, forecast, or actual numbers.

### Think of it Like This:
> A Form is a **structured view** of the Essbase cube. It shows specific dimensions on rows, columns, pages, and POV — and lets users enter or view data.

### Example Form Layout:

```
POV:  [Scenario: Budget]  [Version: Working]  [Year: FY26]  [Currency: INR]

Page: [Entity: E10001 - Hotel Pvt Ltd]  [Department: D10010 - Catering]

              Jan      Feb      Mar      Apr      May      Jun
Revenue      ₹18Cr    ₹19Cr   ₹20Cr    ₹21Cr   ₹22Cr    ₹23Cr
Expense      ₹12Cr    ₹13Cr   ₹14Cr    ₹14Cr   ₹15Cr    ₹16Cr
Net Profit    ₹6Cr     ₹6Cr    ₹6Cr     ₹7Cr    ₹7Cr     ₹7Cr
             ↑                                              ↑
           (Rows = Account)                    (Columns = Period)
```

## 💡 2. Form Layout — POV, Pages, Rows, Columns

Every form has 4 areas where you place dimensions:

### A. POV (Point of View)
| What It Is | Where It Shows | User Interaction |
|-----------|---------------|-----------------|
| Fixed dimension selections at the top | Dropdown menus above the grid | User selects ONE value per dimension |

**Example:** Scenario = Budget, Version = Working, Year = FY26

**Key Rule:** POV members act as **filters**. If POV says "Scenario = Budget", you will ONLY see Budget data.

### B. Pages
| What It Is | Where It Shows | User Interaction |
|-----------|---------------|-----------------|
| Dimensions that let users switch between "pages" of data | Dropdown menus below POV, above the grid | User selects a value, grid refreshes |

**Example:** Entity = E10001. User switches to E10002 — grid refreshes to show new entity's data.

**Difference from POV:**
- POV = very rarely changed (like Scenario, Version, Year)
- Page = frequently changed (like Entity, Department)

### 💡 Logic & Purpose
Separating the POV and Page drops-downs is a UI/UX optimization. Dimensions that define the overarching dataset (Budget, Working, FY26) sit quietly in the POV, filtering the entire experience. Dimensions that define the operational units (Department, Cost Center, Entity) sit in the Page drop-downs because users need to rapidly click through them to input data across multiple cost centers in a single sitting without reloading the entire form.

### 🌀 Confusion Resolution
> **Misconception:** "I want to see January through December on my columns, so I'll just put the Period dimension on the Page drop-down so users can select the month."
> **Reality:** If you put Period on the Page drop-down, the user can only see *one month at a time* in the grid. To see Jan-Dec side-by-side, Period MUST be on the Columns axis.

### 😈 Twisted Interview Question
**Question:** A form has Account on Rows and Period on Columns. Entity, Scenario, and Version are in the POV. The user opens the form, but it takes 45 seconds to load and crashes their browser. What design flaw caused this—
> **Answer:** The designer put Entity, Scenario, and Version in the POV, but failed to restrict the member selections. If the POV defaults to the top-level parent (e.g., "Total Entity", "All Scenarios", "All Versions"), the form attempts to load and aggregate millions of intersections simultaneously before rendering. POV/Page dimensions must always be restricted to `Level 0` (leaf) members, or dynamic user variables, to ensure fast rendering.

### C. Rows
| What It Is | Where It Shows | User Interaction |
|-----------|---------------|-----------------|
| Members displayed as row headers on the left side | Left side of the grid | Users see member names and enter data in cells |

**Example:** Account members (Revenue, Expense, Profit) shown as rows.

### D. Columns
| What It Is | Where It Shows | User Interaction |
|-----------|---------------|-----------------|
| Members displayed as column headers across the top | Top of the grid | Users enter data under each column |

**Example:** Period members (Jan, Feb, Mar...) shown as columns.

## 🛠 3. Anchor Dimension

### What is the Anchor Dimension—
The **Anchor Dimension** is the primary dimension on a row or column. When you have multiple dimensions on rows, the Anchor determines which one controls the layout.

### Example:
If you have **Account** and **Department** both on rows:
- Anchor = Account → Accounts are listed first, departments nested inside
- Anchor = Department → Departments are listed first, accounts nested inside

```
Anchor = Account:                    Anchor = Department:
┌───────────────────────────┐        ┌───────────────────────────┐
│ Revenue                   │        │ HR Department             │
│   → HR Dept               │        │   → Revenue               │
│   → IT Dept               │        │   → Expense               │
│ Expense                   │        │ IT Department             │
│   → HR Dept               │        │   → Revenue               │
│   → IT Dept               │        │   → Expense               │
└───────────────────────────┘        └───────────────────────────┘
```

## 🎛️ 4. Dimension Properties in Forms

When you add a dimension to a form, you can set these properties:

| Property | What It Does | Options |
|----------|-------------|---------|
| **Member Name** | Show the member's system name | 100110, E10001 |
| **Alias** | Show the member's friendly name | "Rooms Revenue", "Hotel Pvt Ltd" |
| **Member Formula** | Show the formula attached to the member | IF(Revenue > 0, Revenue * 0.3, 0) |
| **Hide dimension** | Completely hide the dimension from the form | Yes/No |
| **Show consolidation operators** | Show +, -, ~, etc. next to member names | Yes/No |
| **Start expanded** | Show the dimension's hierarchy expanded or collapsed | Yes/No |
| **Enable custom attributes** | Allow custom attribute columns | Yes/No |
| **Drill on Shared Members** | Allow drilling on shared members | Yes/No |
| **Show Currency** | Show currency code next to member (for multi-currency apps) | Yes/No |
| **Show Qualified Name** | Show as "Parent.Child" format | E.g., "Total Entity.E10001" |

### "Apply to All" Options:
| Setting | Meaning |
|---------|---------|
| **Apply to all row dimensions** | Same properties for all dimensions on rows |
| **Apply to all column dimensions** | Same properties for all dimensions on columns |
| **Apply to all page dimensions** | Same properties for all page dimensions |
| **Apply to all POV dimensions** | Same properties for all POV dimensions |

## 📊 5. Form Layout Options

These control how rows and columns appear:

| Option | What It Does |
|--------|-------------|
| **Apply to all rows/columns** | Apply same settings to all rows/columns |
| **Hide** | Hide a specific row or column |
| **Read-only** | Make a row/column non-editable |
| **Show separator** | Add a bold border before a segment for visual distinction |
| **Suppress hierarchy** | Don't indent children under parents |
| **Suppress missing data** | Hide rows/columns where all cells are #MISSING |
| **Column width / Row height** | Small, Medium, Large, Size-to-Fit, or Custom size |
| **Global Assumptions Form** | Enable transferring global assumptions between environments |

### Column Width Options:
| Option | Decimal Places Shown |
|--------|---------------------|
| Small | 7 decimal places |
| Medium | 10 decimal places |
| Large | 13 decimal places |
| Size-to-Fit | Auto-adjust to content |
| Custom | Up to 999 decimal places |

## 🎛️ 6. Grid Properties

Grid-level properties affect the entire data grid:

| Property | What It Does |
|----------|-------------|
| **Suppress missing blocks** | Don't show rows from data blocks that are entirely empty (improves performance) |
| **Suppress missing data** | Hide rows/columns without data (shows only rows with numbers) |
| **Suppress invalid data** | Hide rows/columns with invalid data |
| **Default row height** | Set default height: Medium, Size-to-Fit, or Custom |
| **Default column width** | Set default width: Small, Medium, Large, Size-to-Fit, or Custom |
| **Global Assumptions Form** | Enable for storing global assumptions like tax rates |
| **Suppress invalid Scenario/Time Periods** | Hide invalid combinations |
| **Suppress Missing also Suppresses Zero** | When enabled, both #MISSING AND zero values are hidden |
| **Remove Form Suppressions in Ad Hoc** | Allow Smart View users to do ad hoc analysis even with suppressions |
| **Enable Calc On the Fly** | See member formulas on hover and calculate without submitting |
| **Pivot Rows and Columns after load** | Transpose (swap) rows and columns |

### Important Edge Cases:

**"Suppress missing blocks" Edge Case:**
> This option can **degrade performance** if no or few rows are suppressed. Always test forms before and after enabling this setting.

**"Suppress missing data" with "also Suppresses Zero":**
> When selected, this overrides Smart View runtime suppression selections. Be careful — users in Smart View won't be able to change this.

## 🎛️ 7. Display Properties (Setting Display)

| Property | What It Does |
|----------|-------------|
| **Make form read-only** | Entire form becomes non-editable |
| **Hide form** | Hide the form from users (used for forms accessed from menus or task lists) |
| **Display missing values as blank** | Show empty cells instead of "#MISSING" text |
| **Enable Mass Allocate** | Allow bulk spreading of values across cells |
| **Enable Grid Spread** | Enable value spreading across the grid |
| **Enable cell-level document** | Allow users to attach documents to individual cells |
| **Message for forms with no data** | Custom message like "No data available for this selection" |

### Edge Case — Missing Values:
```
Without "Display missing values as blank":
    Revenue | Jan    | Feb     | Mar
    Rooms   | ₹18Cr | #MISSING | ₹20Cr   ← Looks messy!

With "Display missing values as blank":
    Revenue | Jan    | Feb     | Mar
    Rooms   | ₹18Cr |         | ₹20Cr   ← Looks clean!
```

## 📖 9. Data Validation Rules

Validation rules ensure data quality by checking user inputs.

| Option | What It Does |
|--------|-------------|
| **Add/Edit Format/Validation Rules** | Create or modify rules |
| **Copy Format/Validation Rules** | Copy rules to reuse them |
| **Paste Format/Validation Rules** | Paste copied rules to new location |
| **Validate only for users with access** | Skip validation for users who can't access the form |
| **Validate only for pages with existing blocks** | Only run validation where data blocks exist |
| **Validate only for cells/pages user has access to** | Run as the current user (apply their security) |
| **Validate with each possible value for user variables** | Run validation for every possible user variable value |
| **Validate with current approval unit members** | Use current approval unit member for validation |

### Example Validation Rule:
```
Rule: Revenue must be greater than 0
If Revenue <= 0 → Show error: "Revenue cannot be zero or negative"

Rule: Expense cannot exceed Budget
If Expense > Budget → Show warning: "Expense exceeds budgeted amount"
```

## 🔗 10. Menus in Forms

### What Are Form Menus—
Menus are **right-click options** or **toolbar buttons** that let users perform actions directly from a form.

### Common Menu Actions:
| Menu Action | What It Does |
|-------------|-------------|
| **Run Business Rule** | Execute a calculation (e.g., "Calculate Net Profit") |
| **Launch URL** | Open a link (e.g., link to a report or document) |
| **Launch Form** | Open another form |
| **Drill Through** | Drill down to see detail data |
| **Supporting Detail** | Open supporting detail for a cell |

### Menu Creation:
1. Navigate to **Navigation Flows** → **Form Menus**
2. Create a new menu
3. Add menu items (actions)
4. Attach the menu to a form

## 📝 11. Substitution Variables

### What Are They—
**Substitution Variables** are placeholders whose values can be changed without modifying the application.

### Example:
```
Variable Name:  CurrentMonth
Variable Value: Jun

Variable Name:  CurrentYear
Variable Value: FY26

Variable Name:  BudgetYear
Variable Value: FY27
```

### How They're Used in Forms:
Instead of hardcoding "FY26" in every form, you set the POV to use `&CurrentYear`. When the year changes, you update the variable ONCE — all forms automatically update.

### Real-World Edge Case:
> **Month-end process:** At the end of June, the admin changes:
> - `CurrentMonth` from "Jun" to "Jul"
> - All forms now show July as the current month
> - No need to edit 50 individual forms!

## ⚡ 12. UDA — User-Defined Attributes

### What Are They—
**UDA (User-Defined Attributes)** are custom text labels you attach to dimension members for **filtering and grouping**.

### Example:
```
Member: 200610 (Salary Expense)    → UDA: "ManpowerRelated"
Member: 200620 (Health Insurance)  → UDA: "ManpowerRelated"
Member: 200410 (Electricity)       → UDA: "AdminRelated"
Member: 200420 (Logistics)         → UDA: "AdminRelated"
```

### How They're Used:
In a form, you can say: *"Show me only accounts with UDA = ManpowerRelated"*  
Result: Only Salary and Health Insurance rows appear.

### Difference from Attributes:
| Feature | UDA | Attribute Dimension |
|---------|-----|-------------------|
| **Type** | Simple text tag | Full dimension with members |
| **Complexity** | Simple | More complex |
| **Use Case** | Quick filtering | Detailed attribute-based analysis |

## 📝 13. Summary — Form Design Checklist

When creating a form, decide:

| Decision | Options |
|----------|---------|
| **Which dimensions on Rows—** | Typically Account |
| **Which dimensions on Columns—** | Typically Period |
| **Which dimensions on Pages—** | Entity, Department (switchable) |
| **Which dimensions on POV—** | Scenario, Version, Year, Currency (fixed) |
| **Suppress missing data—** | Yes (for clean look) or No (to see gaps) |
| **Read-only or editable—** | Depends on user role |
| **Validation rules—** | Add rules for data quality |
| **Menus—** | Add right-click actions for business rules |
