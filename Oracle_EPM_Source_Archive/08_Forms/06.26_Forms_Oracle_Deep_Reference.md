## 📌 Form Types — Complete Reference

### Simple Form

```
One grid — Accounts on rows, Periods on columns
Most common for data entry
Example: Revenue Input form
```

### Composite Form

```
Multiple grids combined into one view
Each sub-grid can have different dimensions
Example: Executive Dashboard with Revenue + Expenses + KPIs
```

### Flex Form (Oracle 21.12+)

```
Same structure as Simple Form but allows Excel-like operations:
- Sort columns
- Add Excel formulas
- Filter rows
- Conditional formatting
- Still submits data back to EPM
```

### 💡 Logic & Purpose
Historically, if a user entered budget data into a BSO cube and wanted to view the consolidated results in an ASO reporting cube, they had to call an admin to run a manual "Data Copy" or "Export/Import" script. **Smart Push** changed the game. It allows the form to automatically take the data the user *just saved*, map it to the ASO cube, and push it in the background in seconds.

### 🌀 Confusion Resolution
> **Misconception:** "I attached a Smart Push to my form to trigger 'On Save', but the users are complaining it takes 3 minutes to save the form."
> **Reality:** By default, Smart Push tries to push data for the *entire* Data Map definition. To fix this, you must configure the Smart Push on the form to "Use Form Context." This forces the Smart Push to only push the specific Entity, Scenario, and Version that the user is currently looking at, dropping the save time from 3 minutes to 3 seconds.

### 😈 Twisted Interview Question
**Question:** A form has a Business Rule configured to "Run on Save" (which calculates taxes), and a Smart Push configured to "Run on Save" (which pushes the data to ASO). The user saves the form. However, the ASO cube does not show the calculated tax data, it only shows the base revenue data. Why—
> **Answer:** Execution Order! When a form is saved, EPBCS performs actions in a strict sequence: (1) Save entered data to Essbase, (2) Run Smart Push, (3) Run "Calc on Save" Business Rules. Because the Smart Push fired *before* the business rule calculated the taxes, only the base data was pushed. To fix this, the Smart Push must be moved *inside* the business rule (using Groovy or the 'Run Smart Push' component) so it executes *after* the tax calculation finishes.

## 📌 Advanced Form Features

### Conditional Formatting (Data Validation)

```
Navigation: Edit Form → Layout → Formatting → Conditional Format

Examples:
- If Revenue > 1,000,000 → Green background
- If Variance < 0 → Red text
- If Status = "Pending" → Yellow highlight
- If data = #Missing → Gray italics
```

### Cell-Level Security

```
Navigation: Edit Form → Layout → Properties per row/column

Options:
- Read Only → user cannot edit this row/column
- Hidden → this row/column is invisible
- Writable → user can edit (default for Store members)
```

### Dynamic Member Selection

```
Instead of hard-coding "Jan, Feb, Mar" on columns:
Use member function: ILvl0Descendants(Period)
→ Automatically shows all Level 0 periods

Use substitution variable: @RANGE(Period, &ForecastStart, Dec)
→ Changes when you update &ForecastStart
```

## ⚡ Form Performance Optimization

### The 3-Second Rule

```
Target: Every form should load in < 3 seconds
If it takes > 5 seconds, users will complain
If it takes > 10 seconds, users will stop using EPM
```

### Performance Checklist

| # | Check | Impact |
|---|-------|--------|
| 1 | Suppress Missing Data = ON | High — reduces retrieved cells |
| 2 | Suppress Missing Blocks = ON | High — skips empty blocks entirely |
| 3 | Cell count < 5,000 | High — fewer cells = faster |
| 4 | No heavy rules on Load | High — slows every form open |
| 5 | Dense dims on Rows/Columns | Medium — efficient retrieval |
| 6 | Sparse dims on POV/Pages | Medium — reduces block scans |
| 7 | Use member functions (ILvl0Desc) | Low — cleaner than static lists |
| 8 | Limit conditional formatting rules | Low — each rule adds processing |

```
   - Add 2 rules on Load
   - Disable all suppression

3. Optimize step by step:
   a. Enable Missing suppression → measure
   b. Enable Missing Blocks suppression → measure

   d. Reduce to 100 accounts → measure
   e. Reduce to 12 columns → measure
4. Document each improvement percentage
```

## 🎓 Interview Questions

**Q: A form takes 30 seconds to load. Walk me through your optimization approach.**
> (1) Check cell count — reduce if > 5000. (2) Enable Suppress Missing Data + Missing Blocks. (3) Check for Business Rules on Load — remove or optimize. (4) Verify Dense dimensions are on Rows/Columns. (5) Check if Dynamic Calc members are causing slow retrieval. (6) Split into smaller forms. (7) Use Activity Reports to identify the specific bottleneck.

**Q: What is the difference between a Composite Form and a regular form—**
> A Composite Form combines multiple sub-forms into a single view. Each sub-form can show different dimensions, cubes, or time ranges. Regular forms show one grid. Use Composite for dashboards where you need multiple perspectives (Revenue + Expenses + KPIs) on one screen.

**Q: When would you use a Flex Form vs a regular form—**
> Flex Forms when users need Excel-like operations (sorting, filtering, Excel formulas) while still submitting data to EPM. Regular forms when you want a controlled, standardized layout. Flex Forms are ideal for power users who love Excel but need EPM's data integrity.

**Q: How do you implement driver-based planning in forms—**
> Create driver accounts (Units, Rate, Occupancy) as input rows. Create calculated accounts (Revenue) as Dynamic Calc or with Business Rule on Save. User enters drivers → rule calculates results → all on the same form. This is more flexible than entering absolute numbers.
