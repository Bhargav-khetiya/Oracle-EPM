## 1. Reports Architecture — Narrative Reporting vs Cloud EPM <a name="1-architecture"></a>

### Two Deployment Models

Oracle EPM Reports exists in **two deployment contexts** — this confuses many people:

```
┌─────────────────────────────────────────────────────────────────────┐
│                     EPM REPORTS DEPLOYMENTS                         │
├─────────────────────────────┬───────────────────────────────────────┤
│  NARRATIVE REPORTING        │  CLOUD EPM (EPBCS/PBCS)              │
│  (Standalone Subscription)  │  (Embedded in Business Process)      │
├─────────────────────────────┼───────────────────────────────────────┤
│ ✅ Multi-source reports     │ ❌ Single instance only               │
│ ✅ Notes (commentary)       │ ❌ No Notes                           │
│ ✅ Generative AI (GenAI)    │ ❌ No GenAI                           │
│ ✅ Analytics Images (OAC)   │ ❌ No Analytics Images                │
│ ✅ Shared Reports/Objects   │ ❌ No Shared Reports                  │
│ ✅ Report Packages          │ ❌ No Report Packages                 │
│ ✅ Cross-cloud content      │ ❌ Cannot point to other instances    │
│ ✅ Library (artifacts)      │ ✅ Cloud EPM Repository               │
│ ✅ Export/Import             │ ✅ LCM Migration                     │
│ ✅ FR Migration via import  │ ✅ FR Migration via FR card           │
│ ✅ Remote Libraries         │ ✅ Remote Libraries                   │
│ ✅ Books & Bursting         │ ✅ Books & Bursting                   │
│ ✅ Tables (System Reports)  │ ✅ Tables (Enterprise license only)   │
│ ✅ Fonts: Library managed   │ ✅ Fonts: App Settings → Reporting    │
│ ✅ Scheduling: Job Console  │ ✅ Scheduling: EPM Job Scheduler      │
└─────────────────────────────┴───────────────────────────────────────┘
```

### Supported Data Sources (Narrative Reporting)

| Data Source Type | Example |
|-----------------|---------|
| **Oracle Fusion Cloud EPM** | Planning, FCCS, Tax, FreeForm, EPCM |
| **Oracle Essbase Cloud** | Standalone Essbase instances |
| **Oracle Essbase On-Premises** | Legacy Essbase servers |

### Cloud EPM Tables — System Reports (Enterprise License Only)

```
WHAT: Tables are relational data grids (not Essbase cubes)
WHERE: Cloud EPM business processes with Enterprise license
USE CASE: Embed Task Manager status, Supplemental Data, or
          Enterprise Journals data inside a formatted report

SUPPORTED FEATURES IN TABLES:
   ✅ Member selector
   ✅ Prompts and POV
   ✅ Formatting
   ✅ Sorting
   ✅ Drill to content
   ✅ Conditional formatting/suppression
   ✅ Formulas
   ✅ Grouping
   ✅ Charts linked to tables
   ✅ Books and Bursting
   ✅ Excel output

HOTEL EXAMPLE:
   Create a report that shows:
   Page 1: P&L from Planning cube (Grid)
   Page 2: Task Manager close status (Table)
   Page 3: Journal entries summary (Table)
   → Complete month-end reporting package
```

## 2. Connections and Data Sources — Complete Reference <a name="2-connections"></a>

### Connection vs Data Source

```
CONNECTION (Parent)          DATA SOURCE (Child)
┌───────────────────┐        ┌──────────────────┐
│ URL: epm.oracle.. │───────→│ Cube: FinPlan BSO│
│ User: admin@...   │        └──────────────────┘
│ Password: ****    │        ┌──────────────────┐
│                   │───────→│ Cube: FinPlan ASO│
│                   │        └──────────────────┘
│                   │        ┌──────────────────┐
│                   │───────→│ Cube: Capital BSO│
└───────────────────┘        └──────────────────┘

ONE Connection → MANY Data Sources (cubes)
```

### Creating a Connection (Narrative Reporting)

```
NAVIGATION: Library → Connections → Create

Step 1: Connection Name: "HotelPlan_Production"
Step 2: Connection Type: Oracle Fusion Cloud EPM
Step 3: Server URL: https://hotel-epm.oraclecloud.com
Step 4: Identity Domain: hotelepm
Step 5: Administrator User: admin@hotelpvtltd.com
        (MUST be native user, NOT SSO)
        (Multi-Factor Auth NOT supported)
Step 6: Password: ********
Step 7: Enable Library: ☐ (check only if using Remote Library)
Step 8: Select Cubes:
        ☑ HotelPlan BSO (Planning cube)
        ☑ HotelPlan ASO (Reporting cube)
        ☑ Capital BSO (CapEx cube)
Step 9: Save

CRITICAL RULES:
   → User creating Connection must be same as Admin ID in Connection
   → Both must be NATIVE users (not SSO)
   → Narrative Reporting version MUST match Cloud EPM version
   → Remote Libraries: Only enable when regularly used
   → Stale credentials in Remote Libraries = performance degradation
```

### Data Source Management

```
GLOBAL CHANGE:
   All reports using Connection1 → now use Connection2
   Effect: Every grid in every report pointing to Connection1 updates
   Use: When migrating between environments (DEV → PROD)

SELECTIVE CHANGE:
   Only specific reports change from DataSource1 → DataSource2
   Effect: Only selected grids update
   Use: When splitting reports across different cubes
```

### Cloud EPM Data Sources (Automatic)

```
In Cloud EPM deployments, data sources are AUTOMATIC:
   → System detects all application cubes on the instance
   → Creates data sources for each cube automatically
   → No manual connection setup needed
   → Cannot point to other EPM instances
   → Data sources appear when you add a Grid to a report

HOTEL EXAMPLE (Cloud EPM):
   Application: HotelPlan
   Auto-created data sources:
   ├── HotelPlan BSO (Planning cube)
   ├── HotelPlan ASO (Reporting cube)
   ├── Capital BSO (CapEx planning)
   └── Manpower BSO (Workforce planning)
```

### Print All Selections Sequence

This is an **advanced feature** that many people miss:

```
WHAT: When a report has multiple "page" dimensions (dimensions the
user can switch between), "Print All Selections" generates a page
for EVERY combination of those dimension members.

EXAMPLE:
   Report has Page Dimensions:
   ├── Entity: Mumbai, Delhi, Goa (3 members)
   └── Scenario: Actual, Budget (2 members)

   "Print All Selections" generates:
   Page 1: Mumbai + Actual
   Page 2: Mumbai + Budget
   Page 3: Delhi + Actual
   Page 4: Delhi + Budget
   Page 5: Goa + Actual
   Page 6: Goa + Budget
   → 3 × 2 = 6 pages total

   SEQUENCE CONFIGURATION:
   Controls which dimension iterates first:
   Sequence 1: Entity (outer loop)
   Sequence 2: Scenario (inner loop)
   
   Result Order:
   Mumbai-Actual, Mumbai-Budget,
   Delhi-Actual, Delhi-Budget,
   Goa-Actual, Goa-Budget

   If reversed (Scenario first, Entity second):
   Actual-Mumbai, Actual-Delhi, Actual-Goa,
   Budget-Mumbai, Budget-Delhi, Budget-Goa
```

**FORMAT HIERARCHY (Critical to understand):**

```
FORMATTING INHERITANCE:

Grid Format (lowest priority)
   ↓ overridden by
Row/Column Format
   ↓ overridden by
Cell Format (highest priority)

EXAMPLE:
   Grid: Font = Arial 10pt Black
   Row 3: Font = Arial 10pt Bold (parent row)
   Cell [3,2]: Font = Arial 10pt Bold RED (negative variance)
   
   → Cell [3,2] shows Bold RED (cell wins)
   → Rest of Row 3 shows Bold Black (row wins over grid)
   → All other cells show Normal Black (grid default)
```

## 5. Point of View (POV) — Complete Reference <a name="5-pov"></a>

### Global vs Local POV

```
GLOBAL POV:
   → One POV controls ALL grids in the report
   → Changing "Scenario" in Global POV updates every grid
   → Most common configuration

LOCAL POV:
   → Each grid has its own independent POV
   → Grid 1 shows "Actual", Grid 2 shows "Budget" simultaneously
   → Used for side-by-side comparison reports

CONFIGURATION:
   Report Properties → POV Type:
   ○ Global (default)
   ○ Local (per-grid)

HOTEL EXAMPLE — GLOBAL:
   Global POV: Scenario=Actual, Year=FY26, Version=Final
   Grid 1 (P&L): Shows Actual FY26 data
   Grid 2 (BS): Shows Actual FY26 data
   → Change Global POV to Budget → BOTH grids update

HOTEL EXAMPLE — LOCAL:
   Grid 1 POV: Scenario=Actual, Year=FY26
   Grid 2 POV: Scenario=Budget, Year=FY26
   → Shows Actual vs Budget side by side
   → Changing Grid 1's POV doesn't affect Grid 2
```

### POV Setup Options

```
FOR EACH DIMENSION IN THE POV:

OPTION 1: FIXED MEMBER
   Member: "Actual"
   → Always shows Actual, user cannot change
   → Use for: Production reports with fixed context

OPTION 2: PAGE SELECTOR (Dropdown)
   Members: Actual, Budget, Forecast
   Default: Actual
   → User can switch via dropdown
   → Use for: Interactive reports

OPTION 3: PROMPT (Runtime)
   Prompt Text: "Select Scenario"
   Type: Member selector
   → User MUST select before report runs
   → Use for: Reports embedded in books/bursting

OPTION 4: USER VARIABLE
   Variable: &UserEntity
   → Each user has a preset entity in their profile
   → Report auto-filters to user's entity
   → Use for: Personalized reports without bursting

OPTION 5: SUBSTITUTION VARIABLE
   Variable: &CurMonth
   → Server-level variable set by admin
   → All users see the same current month
   → Use for: Rolling period reports
```

### Displaying the Printable Page Member

```
WHAT: When a dimension is set as "Page" (dropdown), each member
generates a separate page when printing.

CONFIGURATION:
   Dimension "Entity" → Set as Page dimension
   Members: Mumbai, Delhi, Goa

   When user clicks "Print":
   Page 1: Entity = Mumbai (full P&L for Mumbai)
   Page 2: Entity = Delhi (full P&L for Delhi)
   Page 3: Entity = Goa (full P&L for Goa)

   When user clicks "Print All Selections":
   ALL combinations of all page dimensions print

HOTEL EXAMPLE:
   Page Dim 1: Entity (5 hotels)
   Page Dim 2: Scenario (Actual, Budget)
   "Print All" → 5 × 2 = 10 pages
   Each page = one hotel + one scenario
```

### Attribute Dimensions and POV

```
WHAT: Attribute dimensions can appear in the POV to filter data
by attribute values (e.g., Hotel Star Rating, Region Type).

SETUP:
   POV → Add Dimension → Select attribute dimension "Hotel_Type"
   Member: "5-Star"
   → Report only shows data for 5-Star hotels

HOTEL EXAMPLE:
   Attribute dimension: Hotel_Rating
   Members: 5-Star, 4-Star, 3-Star, Budget
   
   POV: Hotel_Rating = 5-Star
   → Grid only shows 5-Star properties
   → Mumbai Taj, Delhi Palace, Goa Beach (5-Star)
   → Jaipur Fort (4-Star) → EXCLUDED
   → Budget Inn (Budget) → EXCLUDED
```

## 6. Formula Rows & Columns — Complete Syntax <a name="6-formulas"></a>

### Formula Row/Column Basics

```
WHAT: A calculated row or column that doesn't exist in Essbase.
It's computed by the report engine at render time.

INSERT:
   Grid Designer → Right-click column/row header → "Insert Formula"
   → A new column/row appears with formula editor

TYPES:
   → Formula Column: Calculates across columns (e.g., Var = Col2 - Col3)
   → Formula Row: Calculates across rows (e.g., Total = Row2 + Row3)
   → Cell-Level Formula: Override formula for a specific cell
```

### Formula Syntax — Complete Reference

```
REFERENCING COLUMNS:
   [Column_Name]    → Reference by name
   [1], [2], [3]    → Reference by position (1-indexed)
   
REFERENCING ROWS:
   [Row_Name]       → Reference by name
   {1}, {2}, {3}    → Reference by position

REFERENCING CELLS IN OTHER GRIDS:
   Grid1.Cell[3,2]  → Row 3, Column 2 of Grid1
   Grid2.[Revenue]  → The "Revenue" row of Grid2

OPERATORS:
   +  Addition
   -  Subtraction
   *  Multiplication
   /  Division
   %  Percentage

FORMULA EXAMPLES:

1. Variance (Actual - Budget):
   =[Actual] - [Budget]

2. Variance % with division-by-zero handling:
   =IFThen([Budget] = 0, 0, ([Actual] - [Budget]) / [Budget] * 100)

3. Year-over-Year Growth:
   =IFThen([FY25] = 0, 0, ([FY26] - [FY25]) / [FY25] * 100)

4. Percentage of Total:
   =PercentofTotal([Actual])

5. Average excluding zeros:
   =AverageA([Q1], [Q2], [Q3], [Q4])

6. Cumulative Sum (YTD):
   =Sum([Jan]:[CurrentMonth])

7. Cross-Grid Reference:
   =Grid1.Cell[3,2] - Grid2.Cell[3,2]
   → Compares same cell across two grids
   → Useful for multi-cube reports (BSO vs ASO comparison)

HOTEL EXAMPLE — VARIANCE REPORT:
   Column A: Account (text labels)
   Column B: Actual (from Essbase)
   Column C: Budget (from Essbase)
   Column D: Variance = [B] - [C]                    ← Formula
   Column E: Var% = IFThen([C]=0, 0, [D]/[C]*100)   ← Formula
   Column F: Prior Year (from Essbase)
   Column G: YoY Growth = IFThen([F]=0, 0, ([B]-[F])/[F]*100) ← Formula
```

### Mathematical Functions Available in Formulas

| Function | Syntax | Description | Example |
|----------|--------|-------------|---------|
| **Absolute** | `Abs(value)` | Absolute value | `Abs([Variance])` → always positive |
| **Average** | `Average(v1, v2, ...)` | Average of values | `Average([Q1],[Q2],[Q3],[Q4])` |
| **AverageA** | `AverageA(v1, v2, ...)` | Average excluding #Missing/zero | `AverageA([Q1],[Q2],[Q3],[Q4])` |
| **Count** | `Count(v1, v2, ...)` | Count of values | `Count([Jan]:[Dec])` |
| **CountA** | `CountA(v1, v2, ...)` | Count excluding #Missing | `CountA([Jan]:[Dec])` |
| **Difference** | `Difference(v1, v2)` | v1 - v2 | `Difference([Actual],[Budget])` |
| **Eval** | `Eval(expression)` | Evaluate expression | `Eval([Revenue]/[Rooms])` |
| **IFThen** | `IFThen(cond, true, false)` | Conditional | `IFThen([Var]>0, "Fav", "Unfav")` |
| **Max** | `Max(v1, v2, ...)` | Maximum value | `Max([Q1],[Q2],[Q3],[Q4])` |
| **Min** | `Min(v1, v2, ...)` | Minimum value | `Min([Q1],[Q2],[Q3],[Q4])` |
| **PercentofTotal** | `PercentofTotal(value)` | % of column total | `PercentofTotal([Revenue])` |
| **Product** | `Product(v1, v2, ...)` | Multiply all values | `Product([Rooms],[Rate],[Days])` |
| **Rank** | `Rank(value, order)` | Ranking position | `Rank([Revenue], Descending)` |
| **Round** | `Round(value, decimals)` | Round to N decimals | `Round([Var%], 1)` → 8.6 |
| **Sum** | `Sum(v1, v2, ...)` | Add all values | `Sum([Jan]:[Dec])` |
| **SumV** | `SumV(v1, v2, ...)` | Sum excluding #Missing | `SumV([Jan]:[Jun])` |
| **Truncate** | `Truncate(value, decimals)` | Truncate (no round) | `Truncate(8.67, 1)` → 8.6 |
| **Variance** | `Variance(act, bud, type)` | Smart variance | `Variance([Actual],[Budget],"Revenue")` |
| **VariancePercent** | `VariancePercent(act, bud, type)` | Smart var % | `VariancePercent([Actual],[Budget],"Expense")` |

### Variance and VariancePercent — Smart Functions

```
THE PROBLEM:
   Revenue Variance = Actual - Budget (positive = favorable)
   Expense Variance = Budget - Actual (positive = favorable)
   → Different calculation logic for different account types!

THE SOLUTION: Variance() function handles this automatically

ESSBASE BEHAVIOR:
   Variance(Actual, Budget) = Actual - Budget
   → Revenue: 6.3Cr - 5.8Cr = +0.5Cr (favorable ✅)
   → Expense: 4.5Cr - 4.3Cr = +0.2Cr (unfavorable ❌ — should be negative!)

CLOUD EPM BEHAVIOR:
   Variance(Actual, Budget) respects Account Type property:
   → Revenue account: Actual - Budget (higher = good)
   → Expense account: Budget - Actual (lower = good)
   → Automatically adjusts sign based on Account Type!

IMPORTANT: The "Variance Behavior" depends on whether you're
using Essbase or Cloud EPM. In Cloud EPM, the Account Type
property drives the sign convention.

HOTEL EXAMPLE:
   Room Revenue (Account Type = Revenue):
   Variance(5.2Cr, 4.8Cr) = +0.4Cr (favorable ✅)
   
   Salary Expense (Account Type = Expense):
   Variance(2.1Cr, 2.0Cr) = -0.1Cr (unfavorable ❌)
   → Budget - Actual = 2.0 - 2.1 = -0.1Cr
```

## 9. Grouping in Reports <a name="9-grouping"></a>

### What is Grouping?

```
WHAT: Grouping organizes grid data by repeating a section for
each member of a grouping dimension.

WHY: Instead of creating 5 separate pages (one per hotel),
you define ONE grid layout and "group by Entity" — the report
engine repeats the grid for each entity automatically.

HOW IT DIFFERS FROM PAGE DIMENSION:
   Page Dimension: User selects via dropdown, one at a time
   Grouping: ALL members rendered at once, in sequence

HOTEL EXAMPLE:
   Grid: P&L accounts on rows, Months on columns
   Grouping Dimension: Entity
   
   Result:
   ┌─────────────────────────────────────────┐
   │ === MUMBAI TAJ ===                       │
   │ Revenue    | Jan | Feb | Mar | ...       │
   │ Expense    | ... | ... | ... | ...       │
   │ Net Income | ... | ... | ... | ...       │
   │                                          │
   │ === DELHI PALACE ===                      │
   │ Revenue    | Jan | Feb | Mar | ...       │
   │ Expense    | ... | ... | ... | ...       │
   │ Net Income | ... | ... | ... | ...       │
   │                                          │
   │ === GOA BEACH ===                         │
   │ Revenue    | Jan | Feb | Mar | ...       │
   │ Expense    | ... | ... | ... | ...       │
   │ Net Income | ... | ... | ... | ...       │
   └─────────────────────────────────────────┘
```

### Grouping and Page Breaks

```
OPTION: "Page Break After Each Group" = Yes
   → Each entity starts on a new page
   → Perfect for printing separate P&L sheets

HOTEL EXAMPLE:
   Page 1: Mumbai Taj P&L
   Page 2: Delhi Palace P&L
   Page 3: Goa Beach P&L
   Page 4: Jaipur Fort P&L
   Page 5: Udaipur Lake P&L
   → 5-page PDF, one per hotel
```

### Grouping and Formulas

```
IMPORTANT: Formula references in grouping scenarios must be
carefully managed.

BEHAVIOR:
   → Formulas within a grouped section calculate PER GROUP
   → Formula: Variance = [Actual] - [Budget]
   → For Mumbai group: uses Mumbai's Actual and Budget
   → For Delhi group: uses Delhi's Actual and Budget
   → Each group is independent

CROSS-GROUP FORMULAS:
   → Not directly supported within a single grid
   → To compare Mumbai vs Delhi, use two grids or a summary grid
```

### Grouping Considerations

```
LIMITS:
   → Multiple groupings can be nested (Group by Region, then Entity)
   → Each additional grouping multiplies the output pages
   → 5 Regions × 10 Entities = 50 sections
   → Performance impact with large member sets

SORTING WITHIN GROUPS:
   → Each group can be sorted independently
   → Sort by Revenue descending within each hotel group
   → Top revenue accounts appear first in each hotel section

CONDITIONAL FORMATTING WITH GROUPING:
   → Conditions apply PER GROUP
   → Red/Green formatting evaluates each hotel independently
   → Mumbai's "Red" threshold may show differently than Delhi's
```

## 11. Valid Intersections in Reports <a name="11-valid-intersections"></a>

```
WHAT: Valid Intersections define which member combinations are
allowed. Invalid combinations return #Missing or are blocked.

IN REPORTS:
   → If POV contains an invalid intersection, the grid returns
     #Missing for all cells (even if data exists)
   → Report designer must be aware of valid intersection rules

FROM THE POV:
   → When user selects Entity="Mumbai" and Department="IT_Shared"
   → If IT_Shared is only valid for Entity="Corporate"
   → Report returns #Missing for ALL accounts
   → This is NOT a data problem — it's a valid intersection block

ON GRID DATA:
   → Rows/columns with invalid intersections show #Missing
   → "Suppress Missing" will hide these rows
   → Can create confusing reports if users don't understand VIs

HOTEL EXAMPLE:
   Valid Intersection: Hotel entities only valid with Hotel departments
   Entity="Mumbai_Taj" + Department="Front_Desk" → VALID ✅
   Entity="Mumbai_Taj" + Department="Corporate_Finance" → INVALID ❌
   
   If report POV = Mumbai_Taj, Department = Corporate_Finance:
   → ALL cells return #Missing
   → Report appears "empty" even though Mumbai has data
   
   FIX: Ensure POV selections are valid combinations
```

## 17. Member Selection — Complete Reference <a name="17-members"></a>

### Member Selection Functions

| Function | What It Returns | Example |
|----------|----------------|---------|
| **Children** | Direct children of a member | Children(YearTotal) → Q1, Q2, Q3, Q4 |
| **IChildren** | Include parent + children | IChildren(YearTotal) → YearTotal, Q1, Q2, Q3, Q4 |
| **Descendants** | All descendants at all levels | Descendants(Revenue) → all accounts under Revenue |
| **IDescendants** | Include parent + all descendants | IDescendants(Revenue) → Revenue + all accounts |
| **Lvl0Descendants** | Only leaf (Level 0) members | Lvl0Descendants(Entity) → individual hotels only |
| **ILvl0Descendants** | Include parent + leaf members | ILvl0Descendants(Entity) → Total + individual hotels |
| **Ancestors** | All ancestors up to root | Ancestors(Mumbai) → West_Region, India, Total |
| **IAncestors** | Include member + ancestors | IAncestors(Mumbai) → Mumbai, West_Region, India, Total |
| **Siblings** | Members at same level under same parent | Siblings(Q1) → Q1, Q2, Q3, Q4 |
| **ISiblings** | Include parent + siblings | ISiblings(Q1) → YearTotal, Q1, Q2, Q3, Q4 |
| **Parent** | Direct parent | Parent(Mumbai) → West_Region |
| **Range** | Members between two points | Range(Period, Jan, Jun) → Jan through Jun |
| **Intersect** | Common members of two sets | Intersect(Children(A), Children(B)) |
| **Except** | Members in first set NOT in second | Except(Children(Revenue), {Service_Revenue}) |
| **Match** | Members matching a pattern | Match(Account, "*Revenue*") |
| **PeriodOffset** | Shift period by N | PeriodOffset(CurrentPOV, -3) → 3 months ago |
| **CurrentPOV** | Current POV member | CurrentPOV("Period") → Jul |
| **Top/Bottom** | Top/Bottom N by value | Top(5, Revenue) → top 5 revenue accounts |

### Range Function — Rolling Reports

```
HOTEL EXAMPLE — ROLLING 6-MONTH REPORT:

SubVar: &CurMonth = "Jul"

Column Members: Range(Period, PeriodOffset(&CurMonth, -5), &CurMonth)
Result: Feb, Mar, Apr, May, Jun, Jul

When &CurMonth changes to "Aug":
Result: Mar, Apr, May, Jun, Jul, Aug

→ Report automatically "rolls forward" every month
→ No manual member selection changes needed
```

### Match Function with CurrentPOV

```
HOTEL EXAMPLE — FILTER BY PATTERN:

Column Members: Match(Account, "*Revenue*")
Result: Room_Revenue, F&B_Revenue, Events_Revenue, Other_Revenue

Match(Entity, "Hotel_*")
Result: Hotel_Mumbai, Hotel_Delhi, Hotel_Goa (prefix match)

Match(Account, CurrentPOV("Department") & "*")
→ If POV Department = "Front", matches "Front_Desk_Revenue", "Front_Desk_Expense"
→ Dynamic filtering based on POV context
```

### PeriodOffset and Parent Functions

```
ROLLING QUARTERS EXAMPLE:

Current POV Period: Jul

Column 1: PeriodOffset(CurrentPOV("Period"), 0) → Jul
Column 2: PeriodOffset(CurrentPOV("Period"), -1) → Jun
Column 3: PeriodOffset(CurrentPOV("Period"), -2) → May
Column 4: Parent(CurrentPOV("Period")) → Q3 (parent of Jul)

RESULT: Shows current month, prior 2 months, and quarter parent
→ Automatically shifts when period advances
```

```
PROMPT TYPES:
   ├── Member Selector: User picks from dimension tree
   ├── Choice List: User picks from predefined list
   ├── Text Input: User types free text
   └── Date Input: User picks a date

CONFIGURATION:
   Grid Designer → Row/Column → Member Selection → Prompt
   Prompt Name: "Select Entity"
   Dimension: Entity
   Default: Total_Entity
   Required: Yes
   
   When report runs:
   ┌───────────────────────────────┐
   │ SELECT ENTITY:                │
   │ ┌───────────────────────────┐ │
   │ │ ○ Total_Entity            │ │
   │ │   ├── ○ Mumbai_Taj        │ │

SAVED MEMBER SELECTIONS:

### Book POV Management

```

   Scenario=Actual, Year=FY26

   Section "Q1 Analysis" → Period=Q1
   → Applies to all reports in this section only
   → Overrides report POVs for this section

3. REPORT POV (Lowest Priority):
   Report "P&L" has its own POV
   → Used only if NOT overridden by book/section

HOTEL EXAMPLE:

         │
         ▼

         │
    ┌────┴────┬────────┬────────┬────────┐
    ▼         ▼        ▼        ▼        ▼
 Mumbai    Delhi     Goa     Jaipur   Udaipur
    │         │        │        │        │
    ▼         ▼        ▼        ▼        ▼
┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐
│ PDF  │ │ PDF  │ │ PDF  │ │ PDF  │ │ PDF  │
│      │ │      │ │      │ │      │ │      │
│Email:│ │Email:│ │Email:│ │Email:│ │Email:│

└──────┘ └──────┘ └──────┘ └──────┘ └──────┘
```

### Prerequisites for Bursting

```
1. REPORT OR BOOK must already exist and work correctly
2. The BURST DIMENSION must be a Page or POV dimension in the report
3. A DISTRIBUTION FILE (CSV) must be created OR users managed manually
4. EMAIL SERVER must be configured (Cloud EPM handles this)
5. User creating bursting must have ADMIN or REPORT_ADMIN role
```

### Creating a Bursting Definition — Step-by-Step

```
NAVIGATION: Reports → Bursting → Create

Step 1: NAME
   └── Name: "Monthly_PnL_Burst"
   └── Description: "Monthly P&L distribution to hotel GMs"

Step 2: SELECT ARTIFACT (Report or Book)
   └── Type: Report
   └── Select: "Monthly_PnL_Report"

Step 3: SET BURSTING POV
   └── Burst Dimension: Entity
   └── Members: ILvl0Descendants("Total_Entity")
       → Mumbai_Taj, Delhi_Palace, Goa_Beach, Jaipur_Fort, Udaipur_Lake
   └── Other POV dimensions:
       Scenario: Actual (fixed for all bursts)
       Year: FY26 (fixed for all bursts)

Step 4: TARGETED DISTRIBUTION FILE (CSV)
   └── Upload CSV file:
   
   Entity_Member,Channel,Format,Email,Subject
   Mumbai_Taj,Email,PDF,gm.mumbai@hotel.com,Monthly P&L - Mumbai
   Delhi_Palace,Email,PDF,gm.delhi@hotel.com,Monthly P&L - Delhi
   Goa_Beach,Email,PDF,gm.goa@hotel.com,Monthly P&L - Goa
   Jaipur_Fort,Email,PDF,gm.jaipur@hotel.com,Monthly P&L - Jaipur
   Udaipur_Lake,Email,PDF,gm.udaipur@hotel.com,Monthly P&L - Udaipur

   ALTERNATIVE: Legacy Distribution (manual user mapping)
   └── Map Entity members to users directly in the UI

Step 5: DISTRIBUTION FORMAT
   └── PDF (most common)
   └── Excel (.xlsx)

Step 6: SUCCESS NOTIFICATIONS
   └── Send email to: admin@hotel.com
   └── Subject: "Bursting Complete — Monthly P&L"
   └── Body: "All 5 hotel P&L reports distributed successfully."

Step 7: FAILURE NOTIFICATIONS
   └── Send email to: admin@hotel.com
   └── Subject: "ALERT: Bursting Failed — Monthly P&L"
   └── Body: "Bursting failed. Check Job Console for details."

Step 8: EMAIL CHANNEL CONFIGURATION
   └── From: reports@hotelpvtltd.com
   └── Reply-To: fpa@hotelpvtltd.com
   └── Email Body: "Dear GM, please find attached your monthly
                    P&L report. Contact FP&A for questions."

Step 9: LIBRARY CHANNEL (Optional)
   └── Save output to Library: /Reports/Distributed/Monthly/
   └── File Name Pattern: "PnL_<<Entity>>_<<Year>>.pdf"

Step 10: SAVE BURSTING DEFINITION
```

### Multiple Data Sources in Bursting

```
WHAT: If the report/book contains multiple data sources,
the bursting definition can burst on ONE dimension that
exists across all data sources.

HOTEL EXAMPLE:

   Grid 1: HotelPlan BSO (Entity dimension)
   Grid 2: Capital BSO (Entity dimension)

SECURITY CONSIDERATION:

   → If creator has access to all entities, all PDFs have data

```

### Limitations for Bursting

```
   → Maximum burst members: No hard limit, but 500+ is slow
   → Email size limit: 25MB per email (PDF attachment)
   → Concurrent bursting jobs: Limited by EPM instance capacity

## 26. Best Practices & Troubleshooting <a name="26-best-practices"></a>

### Design Best Practices (from Oracle Appendix A)

```
1. PLAN BEFORE BUILDING
   → Define report purpose and audience
   → Sketch layout on paper first
   → Identify data sources and dimensions
   → Plan member selection strategy

2. USE EXPANDED SEGMENTS FOR SCALABILITY
   → Use functions (IChildren, IDescendants) instead of static members
   → When hierarchy changes, report auto-adapts
   → But: Use single segments for precise custom formatting

3. FORMATTING HIERARCHY
   → Cell > Row/Column > Grid (most specific wins)
   → Apply formatting at the most specific level needed
   → Avoid redundant formatting at multiple levels

4. PERFORMANCE OPTIMIZATION
   → Limit grid cells: <50,000 per report
   → Enable suppression (Missing Blocks, Missing Data, Zero Data)
   → Use ASO cubes for large reporting queries
   → Avoid "relational-style" reports with 10,000+ rows
   → Use hidden grids to power charts (avoid showing huge tables)

5. USE CONDITIONAL FORMATTING WISELY
   → Apply to specific rows/columns, not entire grid
   → Complex conditions slow rendering
   → Test with full data volume before deployment

6. STANDARDIZE LAYOUTS
   → Create shared components (Narrative Reporting)
   → Use consistent fonts, colors, and number formats
   → Document formatting standards for the team

7. TEST OUTPUT FORMATS
   → HTML, PDF, and Excel render differently
   → Test in ALL output formats during design
   → Column widths that work in HTML may truncate in PDF

8. FONT MANAGEMENT
   → Upload custom fonts before designing reports
   → Narrative Reporting: Library → Fonts
   → Cloud EPM: App Settings → Reporting Settings → Fonts
   → If font not available, system substitutes (may break layout)

9. USE SUBSTITUTION VARIABLES
   → &CurMonth, &CurYear for dynamic date context
   → Avoid hardcoding "FY26" — use &CurYear instead
   → Admin updates variable once → all reports update

10. SECURE ACCESS
    → Reports inherit cube-level security
    → User sees only the data they're authorized for
    → Test reports with different user roles
```

### FAQs and Troubleshooting

```
FAQ 1: "Report shows #Missing everywhere"
   → Check POV: Are all dimensions set to valid members?
   → Check Valid Intersections: Is the POV combination valid?
   → Check data: Does data exist for this intersection?
   → Check security: Does the user have read access?

FAQ 2: "PDF columns are misaligned"
   → Set explicit column widths (don't use Auto)
   → Reduce font size for narrow columns
   → Switch to Landscape orientation for wide reports
   → Enable "Wrap Text" in column formatting

FAQ 3: "Report takes 5+ minutes to generate"
   → Reduce grid size (fewer rows, fewer columns)
   → Enable "Suppress Missing Blocks"
   → Use ASO cube instead of BSO for reporting
   → Remove or simplify complex conditional formatting
   → Check cube aggregation status (run CalcAll before report)

FAQ 4: "Chart doesn't match grid data"
   → Verify chart is linked to correct grid
   → Check chart axis configuration (correct dimension)
   → Refresh chart after modifying grid member selection
   → Check if chart is using hidden grid (verify hidden grid data)

FAQ 5: "Bursting emails not received"
   → Check email addresses in distribution CSV
   → Check spam/junk folders
   → Verify email channel configuration in bursting definition
   → Check Job Console for error messages
   → Verify the user running burst has email send permissions

FAQ 6: "Book Table of Contents is wrong"
   → Regenerate book (TOC updates on generation)
   → Check section/report names (TOC uses these)
   → Verify TOC template (Word template) is correctly formatted
   → Check page break settings in reports
```

## TEST ME — Interview Questions <a name="test-me"></a>

### 🟢 Beginner

**Q: What's the difference between a Grid and a Table in Reports?**
> Grid connects to an Essbase multidimensional cube (OLAP data). Table connects to a Cloud EPM relational schema (Task Manager, Journals, Supplemental Data). Tables are Enterprise license only.

**Q: What are the 5 report objects you can place on a report canvas?**
> Grid, Chart, Text Box, Image, and Table. In Narrative Reporting, also: Notes, Analytics Image, and Shared Objects.

### 🟡 Intermediate

**Q: Explain the formatting hierarchy in EPM Reports.**
> Cell formatting overrides Row/Column formatting, which overrides Grid formatting. Most specific wins. To apply different formatting to one cell in a uniformly formatted row, use cell-level formatting.

**Q: What is Print All Selections Sequence and when would you use it?**
> When a report has multiple Page dimensions, "Print All Selections" generates pages for every combination of page dimension members. The Sequence controls which dimension iterates first (outer/inner loop). Use it for generating comprehensive board packs covering all entities and scenarios.

**Q: What are the two types of POV — Global vs Local? When use each?**
> Global POV applies one set of dimension selections to ALL grids in the report. Local POV gives each grid its own independent selections. Use Global for standard reports. Use Local when you need side-by-side comparison (Grid 1 = Actual, Grid 2 = Budget on the same page).

### 🔴 Architect

**Q: A client has 50 FR reports in legacy Hyperion. Design the migration strategy to Cloud EPM Reports.**
> 1. Export all FR reports as .zip from FR Workspace. 2. Import into Cloud EPM via the Financial Reporting migration card — auto-converts most objects. 3. Run validation report — categorize errors as: auto-fixable, manual fix required, rebuild required. 4. For each report: verify data source mapping, check formatting, test in PDF/HTML/Excel. 5. Create shared components (Narrative Reporting) for common elements (logo, header, footer) to reduce maintenance. 6. Build new reports using EPM Reports for any FR reports that can't migrate cleanly. 7. Parallel run: keep FR available for 2 months while users validate new Reports. 8. Decommission FR access after sign-off.

**Q: How do you architect a GenAI-powered narrative reporting solution?**
> 1. Enable GenAI in Narrative Reporting (Enterprise license). 2. Design reports with grids that produce clean, structured data. 3. Insert AutoTextSummary function in text boxes below key grids. 4. Configure Causality criteria for variance analysis and Compare criteria for period-over-period. 5. Customize ML template files to match company terminology. 6. Test narrative output with real data — verify accuracy. 7. Combine with Notes summarization for user-entered commentary. 8. Embed in Books for automated board pack generation with AI narratives.
