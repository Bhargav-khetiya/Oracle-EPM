# 08.01 — Calc Manager Overview and Navigation: Complete Guide

> **Module:** 08_Calculation_Manager | **Topic:** Architecture, Components, Navigation
> **Audience:** Service Administrator / Rule Developer

---

## 1. WHY — What Real-World Problem Does This Solve—

**The problem:** Business users enter revenue and expense data in forms. But totals, ratios, allocations, forecasts, and aggregations don't calculate themselves. Someone needs to write the logic that transforms raw data into meaningful financials. That "someone" uses Calculation Manager.

**The solution:** Calculation Manager is the **IDE (Integrated Development Environment)** for building all calculation logic in EPBCS. It's where you create, edit, validate, deploy, and manage business rules.

## 3. THE FIVE COMPONENT TYPES

| Component | Icon | What It Does | Example |
|-----------|------|-------------|---------|
| **Formula** | 📐 | Single assignment statement | `"Total" = "A" + "B";` |
| **Script** | 📜 | Multi-line calc script | FIX/ENDFIX blocks, AGG, SET commands |
| **Condition** | ❓ | IF/THEN/ELSE logic | IF Revenue > 0 → calculate margin |
| **Member Range** | 📊 | Loops over member ranges | Process each entity one by one |
| **Template** | 📋 | Reusable pre-built logic | Copy Version, Clear Cell Details |

### How Components Combine

```
Rule: "Calculate_PnL"
├── Script: SET LOCKBLOCK ON
├── Condition: IF Scenario = Budget
│   ├── Formula: "Total_Rev" = "Room" + "F&B" + "Spa"
│   ├── Formula: "Total_Exp" = "Labor" + "Maint" + "Utils"
│   └── Formula: "Net_Income" = "Total_Rev" - "Total_Exp"
├── Member Range: @CHILDREN("All_Hotels")
│   └── Formula: "Margin" = "Net_Income" / "Total_Rev" * 100
└── Script: AGG("Entity")

Components are dragged and connected in the graphical designer.
```

## 4. RULE LIFECYCLE

```
Step 1: CREATE
  New Rule → Name it → Assign to Plan Type (cube)

Step 2: DESIGN
  Drag components into the graphical flow
  OR: Write calc script directly in Script View

Step 3: VALIDATE ☑
  Click Validate → checks syntax, member names, functions
  Fix any errors

Step 4: SET AS DEPLOYABLE
  Right-click Rule → "Set as Deployable"
  (Only Deployable rules can be deployed)

Step 5: DEPLOY 🚀
  Deploy → makes the rule executable
  Rule is now available to run and attach to forms

Step 6: RUN ▶
  Run manually, attach to form (On Save/Load), or schedule

Step 7: MONITOR 📊
  Check Jobs Console for execution status and logs
```

```
Status Flow:
  Draft → Deployable → Deployed → Running → Completed/Error

  Draft:      Rule is being edited, cannot run
  Deployable: Ready for deployment
  Deployed:   Active — can be run, attached to forms
  Running:    Currently executing
  Completed:  Finished successfully
  Error:      Failed — check job log
```

## 5. GRAPHICAL VIEW vs SCRIPT VIEW

| Feature | Graphical View | Script View |
|---------|---------------|-------------|
| **Interface** | Drag-and-drop components | Raw text editor |
| **Best for** | Visual design, simple rules | Complex scripts, bulk editing |
| **Components** | Can use all 5 types | Script and Formula only |
| **Readability** | Excellent for non-developers | Requires calc script knowledge |
| **Portability** | Components are reusable | Copy-paste friendly |
| **Complex logic** | Possible but cumbersome | Preferred for complex rules |

### When to Use Which

```
Use GRAPHICAL when:
  ✅ Building simple formulas
  ✅ Teaching new developers
  ✅ Creating reusable component libraries
  ✅ Rules with clear IF/THEN logic

Use SCRIPT when:
  ✅ Complex multi-FIX calculations
  ✅ Performance-critical rules (SET commands)
  ✅ Migrating from Hyperion on-premise
  ✅ Rules with many variables
  ✅ Copy-pasting from documentation
```

## 6. RULESETS

### What They Are
A Ruleset groups multiple rules that execute sequentially in a defined order.

```
Ruleset: "Monthly_Close"
├── Rule 1: Clear_Prior_Calcs       (runs first)
├── Rule 2: Calculate_Revenue_Totals (runs second)
├── Rule 3: Calculate_Expense_Totals (runs third)
├── Rule 4: Calculate_PnL            (runs fourth)
├── Rule 5: Currency_Conversion      (runs fifth)
└── Rule 6: Aggregate_Entity         (runs last)
```

### Why Use Rulesets—

```
Without Ruleset: 6 separate "On Save" rules on a form
  → 6 separate Essbase sessions
  → 6 separate overhead costs
  → Total time: 18 seconds

With Ruleset: 1 Ruleset containing 6 rules
  → 1 Essbase session
  → Rules run within same context
  → Total time: 6 seconds (3× faster!)
```

## 8. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Forgot to Deploy after edit | Old version of rule runs | Re-deploy after every change |
| Rule not set as Deployable | Deploy button greyed out | Right-click → Set as Deployable |
| Wrong Plan Type assigned | Rule references wrong cube members | Assign rule to correct Plan Type |
| Too many individual On Save rules | Form save is slow | Group into a Ruleset |
| Editing a Deployed rule | Users see inconsistent behavior | Undeploy → Edit → Validate → Deploy |
| No validation before deploy | Members changed → rule fails | Always Validate before Deploy |

## 9. INTERVIEW QUESTIONS

### Beginner
**Q: What is the rule deployment lifecycle in Calculation Manager—**
> Create → Design (graphical or script) → **Validate** (check syntax/members) → **Set as Deployable** (mark ready) → **Deploy** (activate for execution) → Run (manually, on form, or scheduled). The key step most people forget: you must "Set as Deployable" before you can Deploy. After any edit, you must re-validate and re-deploy — the old deployed version stays active until you explicitly deploy the new one.

### Intermediate
**Q: When should you use a Ruleset vs individual rules on a form—**
> Use a Ruleset when 2+ rules must execute in sequence on the same form trigger (On Save or On Load). A Ruleset runs all rules within a single Essbase session, avoiding the overhead of multiple session starts. Performance improvement is typically 2-3× faster. Also, Rulesets guarantee execution order — individual On Save rules may not execute in the order you expect. Individual rules are fine when there's only one rule per form trigger or when rules are unrelated.
