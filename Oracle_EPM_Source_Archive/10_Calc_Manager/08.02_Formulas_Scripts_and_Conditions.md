# 08.02 — Formulas, Scripts, and Conditions: Component Deep Dive

> **Module:** 08_Calculation_Manager | **Topic:** Component Types in Detail
> **Audience:** Service Administrator / Rule Developer

---

## 1. WHY — Why Understand Component Types—

Each component type solves a different problem. Using the wrong type makes rules harder to maintain, slower to execute, and impossible for others to understand. A well-designed rule uses the right component for each job.

---

## 2. FORMULA COMPONENT — THE BUILDING BLOCK

### What It Is
A single mathematical assignment. The simplest unit of calculation.

### Syntax

```essbase
"Target_Member" = expression;
```

### Examples

```essbase
/* Simple sum */
"Total_Revenue" = "Room_Revenue" + "F&B_Revenue" + "Spa_Revenue";

/* Ratio */
"Profit_Margin" = "Net_Income" / "Total_Revenue" * 100;

/* Growth */
"Budget_Revenue" = "Actual_Revenue" * 1.05;

/* Reference another member */
"Variance" = "Actual" - "Budget";

/* Constant */
"Tax_Rate" = 0.30;
```

### Formula Properties

| Property | Options | Description |
|----------|---------|-------------|
| **Plan Type** | Cube name | Which cube this formula operates on |
| **Member** | Target member | The member being calculated |
| **Formula** | Expression | The calculation logic |
| **Comment** | Free text | Documentation |

## 3. SCRIPT COMPONENT — THE POWER TOOL

### What It Is
A multi-line Essbase calc script block. Can contain FIX/ENDFIX, SET commands, loops, multiple formulas, and data operations.

### When to Use Script vs Formula

```
Use FORMULA when:
  ✅ Single assignment: "A" = "B" + "C";
  ✅ Simple logic, no FIX needed

Use SCRIPT when:
  ✅ Multiple assignments in sequence
  ✅ FIX/ENDFIX blocks required
  ✅ SET commands needed (LOCKBLOCK, CALCPARALLEL)
  ✅ AGG, DATACOPY, CLEARDATA operations
  ✅ Variables (VAR declarations)
```

### Script Examples

```essbase
/* ===== Multi-formula script ===== */
SET LOCKBLOCK ON;
SET CALCPARALLEL 4;

FIX({RTP_Scenario}, {RTP_Version}, {RTP_Year})
  FIX(@RELATIVE("All_Hotels", 0))
    
    /* Revenue totals */
    "Total_Revenue" = "Room_Revenue" + "F&B_Revenue" + "Spa_Revenue";
    
    /* Expense totals */
    "Total_Expenses" = "Labor" + "Maintenance" + "Utilities" + "Amenities";
    
    /* P&L calculations */
    "EBITDA" = "Total_Revenue" - "Total_Expenses";
    "Net_Income" = "EBITDA" - "Depreciation" - "Interest" - "Tax";
    
    /* Ratios */
    IF("Total_Revenue" <> 0)
      "Profit_Margin" = "Net_Income" / "Total_Revenue" * 100;
      "Expense_Ratio" = "Total_Expenses" / "Total_Revenue" * 100;
    ELSE
      "Profit_Margin" = 0;
      "Expense_Ratio" = 0;
    ENDIF
    
  ENDFIX
ENDFIX

/* Aggregate */
FIX({RTP_Scenario}, {RTP_Version}, {RTP_Year})
  AGG("Entity");
ENDFIX

SET LOCKBLOCK OFF;
```

## 4. CONDITION COMPONENT — THE DECISION MAKER

### What It Is
An IF/THEN/ELSE container that executes different components based on a condition.

### Graphical View

```
┌── Condition: Is Budget— ─────────────────────────┐
│                                                    │
│  IF: @ISMBR("Budget")                             │
│  │                                                 │
│  ├── THEN: ──────────────────────────────────────┐│
│  │   ├── Formula: "Forecast" = "Actual" * 1.05   ││
│  │   └── Script: AGG("Entity")                   ││
│  │                                                ││
│  └── ELSE: ──────────────────────────────────────┐│
│      └── Formula: "Variance" = "Actual"-"Budget" ││
│                                                    │
└────────────────────────────────────────────────────┘
```

### Condition Types

| Condition | Syntax | Example |
|-----------|--------|---------|
| **Member check** | `@ISMBR("Member")` | Is current member "Budget"— |
| **Level check** | `@ISLEV("Dim", 0)` | Is level-0 (leaf) entity— |
| **Ancestor check** | `@ISANCEST("Parent")` | Is ancestor of "All_Hotels"— |
| **Value check** | `"Revenue" > 0` | Is Revenue positive— |
| **UDA check** | `@ISUDA("Entity", "LuxuryHotel")` | Has UDA "LuxuryHotel"— |

### Nested Conditions

```
Condition: Which Scenario—
├── IF @ISMBR("Budget")
│   └── Formula: Apply budget growth rates
├── ELSEIF @ISMBR("Forecast")
│   └── Formula: Apply forecast adjustments
└── ELSE (Actual)
    └── Formula: No calculation (actuals are loaded)
```

## 5. MEMBER RANGE COMPONENT — THE LOOP

### What It Is
Iterates over a set of dimension members, executing enclosed components for each member.

### Configuration

```
Member Range Properties:
  Dimension: Entity
  Function: @CHILDREN("All_Hotels")
  
  Result: The enclosed formulas execute once for each child:
    Iteration 1: Context = Mumbai_Hotel
    Iteration 2: Context = Delhi_Hotel
    Iteration 3: Context = Bangalore_Hotel
    Iteration 4: Context = Kolkata_Hotel
    Iteration 5: Context = Chennai_Hotel
```

### When to Use

```
Use Member Range when:
  ✅ Different logic per member (e.g., different growth rates per hotel)
  ✅ Need to reference the current member name in logic
  ✅ Processing members sequentially with dependencies

Don't use when:
  ❌ Same formula applies to all members (use FIX instead — faster)
  ❌ Simple aggregation (use AGG instead)
```

## 6. TEMPLATE COMPONENT — THE REUSABLE MODULE

### What It Is
A pre-built calculation pattern that can be parameterized and reused across multiple rules.

### System Templates (Pre-installed)

| Template | What It Does |
|----------|-------------|
| **Copy Version** | Copy data from one Version to another |
| **Copy Data** | Copy data across any dimension |
| **Clear Cell Details** | Remove supporting details |
| **Mass Allocate** | Distribute amounts across members |
| **Rolling Forecast** | Shift forecast periods forward |

### Using a Template

```
Rule: "Copy_Budget_to_Forecast"
├── Template: Copy Version
│   Parameters:
│     Source Version: Working
│     Target Version: Final
│     Scenario: Budget
│     Year: FY2026
│     Clear Target: ☑
```

### Custom Templates

```
Create your own templates for repeated patterns:

Template: "Apply_Growth_Rate"
  Parameters:
    Growth Rate: (numeric input)
    Source Scenario: (member selector)
    Target Scenario: (member selector)
  
  Logic:
    FIX({Target_Scenario}, "Working", &CurrYear)
      "Revenue" = "Revenue" -> {Source_Scenario} * {Growth_Rate};
    ENDFIX

Usage in rules:
  Rule 1: Apply_Growth_Rate(1.05, "Actual", "Budget")    → 5% growth
  Rule 2: Apply_Growth_Rate(1.03, "Budget", "Forecast")   → 3% growth
```

```
Rule: "Monthly_PnL_Calculation"

```

## 8. COMMON MISTAKES

| Mistake | Fix |
|---------|-----|
| Using Script for a single formula | Use Formula component — cleaner |
| Using Member Range when FIX works | FIX is 10× faster than Member Range loops |
| Complex nested Conditions | Simplify — move logic into a single Script component |
| Not documenting component purpose | Add comments to every component |
| Reinventing logic that a System Template handles | Check available templates first |

---

## 9. INTERVIEW QUESTIONS

### Beginner
**Q: Name the 5 component types in Calculation Manager and when to use each.**
> (1) **Formula** — single assignment like `"Total" = "A" + "B"`. (2) **Script** — multi-line calc scripts with FIX, SET, AGG. (3) **Condition** — IF/THEN/ELSE logic to branch based on members or values. (4) **Member Range** — loop over dimension members, executing logic for each. (5) **Template** — reusable, parameterized calculation patterns (Copy Version, Mass Allocate). Use Formula for simple calcs, Script for complex multi-step logic, Condition for branching, Member Range only when per-member logic differs, and Template for standard operations.
