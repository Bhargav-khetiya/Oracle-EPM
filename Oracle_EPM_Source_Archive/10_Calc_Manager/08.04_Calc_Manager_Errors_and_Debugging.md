# 08.04 — Calc Manager Errors and Debugging: Complete Guide

> **Module:** 08_Calculation_Manager | **Topic:** Error Messages, Debugging, Troubleshooting
> **Audience:** Service Administrator / Rule Developer

---

## 1. WHY — Why Master Debugging—

**The problem:** A business rule fails at 2 AM during month-end close. The Jobs Console shows "Error." The log has a cryptic message: `"Error: 1200585 - Unknown member name [Revnue] in formula"`. Without debugging skills, you're stuck until morning when the developer arrives.

**The solution:** Master the error codes, debugging techniques, and log analysis patterns. Most errors fall into 5 categories and can be fixed in minutes.

---

## 2. THE 5 ERROR CATEGORIES

```
1. SYNTAX ERRORS     → Wrong calc script syntax
2. MEMBER ERRORS     → Member doesn't exist or misspelled
3. RUNTIME ERRORS    → Divide by zero, overflow, timeout
4. DEPLOYMENT ERRORS → Rule not deployed, wrong cube
5. PERMISSION ERRORS → User can't run the rule
```

## 3. COMPLETE ERROR CODE REFERENCE

### Syntax Errors

| Error | Message | Cause | Fix |
|-------|---------|-------|-----|
| 1200480 | "Syntax error in formula" | Missing semicolon, bracket, ENDFIX | Check matching FIX/ENDFIX, IF/ENDIF pairs |
| 1200485 | "Unexpected token" | Wrong keyword or operator | Check for typos in keywords |
| 1200490 | "ENDFIX without matching FIX" | More ENDFIXes than FIXes | Count FIX/ENDFIX pairs |
| 1200495 | "FIX without ENDFIX" | Missing ENDFIX | Add the missing ENDFIX |

```essbase
/* Common syntax errors and fixes */

/* ERROR: Missing semicolon */
"Total" = "A" + "B"          /* ❌ No semicolon */
"Total" = "A" + "B";         /* ✅ Fixed */

/* ERROR: Mismatched FIX/ENDFIX */
FIX("Budget")
  FIX(@CHILDREN("All_Hotels"))
    "Total" = "A" + "B";
  ENDFIX
/* ❌ Missing second ENDFIX */
ENDFIX                        /* ✅ Added */

/* ERROR: Mismatched IF/ENDIF */
IF("Revenue" > 0)
  "Margin" = "Profit" / "Revenue";
/* ❌ Missing ENDIF */
ENDIF                         /* ✅ Added */
```

### Member Errors

| Error | Message | Cause | Fix |
|-------|---------|-------|-----|
| 1200585 | "Unknown member name" | Member doesn't exist or misspelled | Verify member name in dimension editor |
| 1200586 | "Duplicate member name" | Same member name in multiple dims | Use qualified name: [Dim].[Member] |
| 1200588 | "Member not found in dimension" | Member moved or deleted | Update rule after metadata change |

```essbase
/* ERROR: Unknown member name */
"Total" = "Revnue" + "Expenses";  /* ❌ Typo: "Revnue" */
"Total" = "Revenue" + "Expenses"; /* ✅ Correct spelling */

/* ERROR: Duplicate member name across dimensions */
FIX("Q1")                        /* ❌ Q1 exists in Period AND Custom dim */
FIX(@MEMBER("Period"."Q1"))      /* ✅ Qualified with dimension name */
```

### Runtime Errors

| Error | Message | Cause | Fix |
|-------|---------|-------|-----|
| 1200700 | "Divide by zero" | Division where denominator = 0 | Add IF(denom <> 0) check |
| 1200705 | "Numeric overflow" | Number exceeds max value | Check formula logic |
| 1013060 | "Timeout" | Rule exceeded time limit | Optimize rule or increase timeout |
| 1200800 | "Insufficient memory" | Cube too large for available memory | Optimize block size, cache |

```essbase
/* ERROR: Divide by zero */
"Margin" = "Profit" / "Revenue";          /* ❌ Crashes if Revenue = 0 */
IF("Revenue" <> 0)                        /* ✅ Protected */
  "Margin" = "Profit" / "Revenue" * 100;
ELSE
  "Margin" = 0;
ENDIF
```

### Deployment Errors

| Error | Message | Cause | Fix |
|-------|---------|-------|-----|
| — | "Rule not available" | Rule not deployed | Deploy in Calc Manager |
| — | "Rule modified since deployment" | Rule changed but not re-deployed | Re-deploy |
| — | "Cube mismatch" | Rule designed for different cube | Check cube association |

### Permission Errors

| Error | Message | Cause | Fix |
|-------|---------|-------|-----|
| — | "Access denied" | User lacks rule launch permission | Grant "Launch Rule" role |
| — | "Insufficient access to member" | Security prevents access | Check dimension security |

## 4. DEBUGGING TECHNIQUES

### Technique 1: Log Messages

```essbase
/* Add trace messages to identify where the rule fails */
@CalcMgrLogMessageTrace("=== Starting P&L Calculation ===");

FIX("Budget", "Working", &CurrYear)
  @CalcMgrLogMessageTrace("Step 1: Calculating Revenue totals");
  "Total_Revenue" = "Room_Rev" + "F&B_Rev";
  
  @CalcMgrLogMessageTrace("Step 2: Calculating Expenses");
  "Total_Expenses" = "Labor" + "Maintenance";
  
  @CalcMgrLogMessageTrace("Step 3: Calculating Net Income");
  "Net_Income" = "Total_Revenue" - "Total_Expenses";
  
  @CalcMgrLogMessageTrace("=== P&L Calculation Complete ===");
ENDFIX

/* In the job log, you'll see:
   [TRACE] === Starting P&L Calculation ===
   [TRACE] Step 1: Calculating Revenue totals
   [TRACE] Step 2: Calculating Expenses
   [ERROR] Unknown member name "Maintainence"  ← FOUND IT!
*/
```

### Technique 2: Validate Before Deploy

```
Calculation Manager → Open Rule → Click "Validate" button

Validation checks:
  ✅ Syntax (matching brackets, semicolons)
  ✅ Member names (all members exist in cube)
  ✅ Function names (all @functions are valid)
  ✅ Variable references (all RTPs defined)
  ❌ Logic (DOES NOT check if results are correct)
```

### Technique 3: Analyze Button

```
Calculation Manager → Open Rule → Click "Analyze"

Shows:
  - Which dimensions are in FIX
  - Which members are referenced
  - Estimated block count
  - Potential performance issues
  - Warnings about Top-Down triggers
```

### Technique 4: Compare Scripts

```
Calculation Manager → Tools → Compare Scripts

Compare:
  Rule Version 1 (working) vs Rule Version 2 (broken)
  
Shows:
  - Line-by-line diff
  - Added/removed/modified lines
  - Helps identify what change broke the rule
```

### Technique 5: Disable Components

```
In the graphical designer:
  Right-click a component → Disable

The component turns grey and is skipped during execution.
Use to isolate which component causes the error.

Test sequence:
  1. Disable all components except the first one → Run → Works—
  2. Enable second component → Run → Works—
  3. Enable third component → Run → ERROR! → Found the culprit
```

## 5. SHOW ME — Debugging a Hotel Pvt Ltd Rule

### The Error

```
Job Log:
  [INFO] Launching rule: Hotel_PnL_Calculation
  [INFO] Processing cube: OEP_FS
  [ERROR] Error: 1200585 - Unknown member name [Maintainence]
  [ERROR] Rule execution failed
```

### The Fix

```
Step 1: Search the rule for "Maintainence"
Step 2: Found on line 15: "Total_Expenses" = "Labor" + "Maintainence" + "Utilities";
Step 3: Fix the typo: "Maintenance" (not "Maintainence")
Step 4: Validate → ✅ No errors
Step 5: Deploy
Step 6: Re-run → ✅ Success
```

## 6. COMMON DEBUGGING PATTERNS

| Symptom | Likely Cause | Diagnostic Step |
|---------|-------------|-----------------|
| Rule worked yesterday, fails today | Member renamed/deleted | Check recent metadata changes |
| Rule runs but results are wrong | Logic error (not syntax) | Add trace messages, check values |
| Rule takes 10× longer than usual | Block explosion or Top-Down | Check block count before/after |
| Rule fails for one user, works for admin | Permission issue | Check user's dimension access |
| Rule fails on Forecast, works on Budget | Member missing in Forecast scenario | Check member intersections |
| "Timeout" error | Rule too slow | Optimize FIX scope, check algorithm |

## 7. INTERVIEW QUESTIONS

### Beginner
**Q: A rule fails with "Unknown member name." How do you fix it—**
> (1) Check the job log for the exact member name causing the error. (2) Open the Dimension Editor and search for that member — it's either misspelled in the rule, renamed, or deleted. (3) Fix the member name in the rule. (4) Validate the rule. (5) Re-deploy and re-run.

### Intermediate
**Q: A rule ran successfully for 6 months but suddenly fails after a metadata import. What happened—**
> The metadata import likely renamed, moved, or deleted a member that the rule references. Steps: (1) Check the error log for the exact error message. (2) If "Unknown member name" — the member was deleted or renamed. Check the metadata import file for changes. (3) If the rule references members by name (not by function like @CHILDREN), any member rename breaks the rule. (4) Best practice: Use member functions (@CHILDREN, @DESCENDANTS, @ICHILDREN) instead of hardcoded member names — they're resilient to hierarchy changes. (5) After fixing, validate and re-deploy the rule.
