# 08.05 — System Templates Deep Dive: Complete Guide

> **Module:** 08_Calculation_Manager | **Topic:** Pre-Built Templates, Copy Version, Mass Allocate
> **Audience:** Service Administrator / Rule Developer

---

## 1. WHY — What Real-World Problem Does This Solve—

**The problem:** Every EPBCS project needs the same 5-6 operations: Copy Version, Clear Data, Mass Allocate, Rolling Forecast. Writing these from scratch every time is wasteful and error-prone.

**The solution:** Oracle ships **System Templates** — pre-built, parameterized calculation components you can drag into rules and configure. Zero custom scripting needed.

---

## 2. ALL SYSTEM TEMPLATES

| Template | Purpose | When to Use |
|----------|---------|-------------|
| **Copy Version** | Copy data between Versions (Working → Final) | Budget lock/approval |
| **Copy Data** | Copy data between any two members of any dimension | Seed budget from actuals |
| **Clear Cell Details** | Remove supporting detail from cells | After data restructuring |
| **Mass Allocate** | Distribute amounts across members | Corporate cost allocation |
| **Rolling Forecast** | Copy actuals to forecast for closed periods | Monthly forecast refresh |
| **Grid Spread** | Enable user-initiated data spreading | Budget entry forms |

## 3. COPY VERSION TEMPLATE

### Configuration

```
Template: Copy Version
  Source Version: Working
  Target Version: Final
  
  Options:
    ☑ Clear Target Before Copy
    ☐ Copy Missing Values
    ☑ Copy Level-0 Blocks Only
    
  Scope:
    Scenario: Budget
    Year: FY2026
    Entity: All Hotels (Level-0)
```

### Generated Script

```essbase
/* The template generates this calc script behind the scenes */
FIX("Budget", "FY2026", @RELATIVE("All_Hotels", 0))
  CLEARDATA "Final";
ENDFIX
CLEARBLOCK ALL;
FIX("Budget", "FY2026", @RELATIVE("All_Hotels", 0))
  DATACOPY "Working" TO "Final";
ENDFIX
```

### Hotel Pvt Ltd Use Case

```
Budget Approval Process:
  1. Planners enter data in "Working" version
  2. GMs review and approve
  3. Admin runs "Copy Working → Final"
  4. Final version is locked (Read-only for planners)
  5. Any further changes go to Working
```

## 4. MASS ALLOCATE TEMPLATE

### Configuration

```
Template: Mass Allocate
  Source:
    Point of View: Corporate_HQ, Budget, Working, FY2026
    Source Account: Total_Corp_Overhead
    
  Target:
    Members: @CHILDREN("All_Hotels") (Mumbai, Delhi, etc.)
    Target Account: Allocated_Corp_Cost
    
  Allocation Basis:
    ○ Even Split
    ● Proportional to: Total_Revenue
    ○ Fill (same value everywhere)
    
  Options:
    ☑ Round to nearest integer
    ☐ Spread across periods
```

### What It Does

```
Total Corporate Overhead: ₹1,20,00,000

Allocation by Revenue Share:
  Mumbai:    ₹4.5Cr revenue (37.5%) → ₹45,00,000
  Delhi:     ₹3.0Cr revenue (25.0%) → ₹30,00,000
  Bangalore: ₹2.4Cr revenue (20.0%) → ₹24,00,000
  Kolkata:   ₹1.2Cr revenue (10.0%) → ₹12,00,000
  Chennai:   ₹0.9Cr revenue (7.5%)  → ₹9,00,000
  TOTAL:     ₹12.0Cr (100%)         → ₹1,20,00,000 ✅
```

## 5. ROLLING FORECAST TEMPLATE

### Configuration

```
Template: Rolling Forecast
  Current Period Variable: &CurrMonth
  
  Closed Periods (Jan → CurrMonth-1):
    Source: Actual
    Action: Copy to Forecast
    
  Open Periods (CurrMonth → Dec):
    Source: Keep existing Forecast
    Action: No change
```

### How It Works (If CurrMonth = Sep)

```
Month │ Source     │ Action
──────┼───────────┼──────────────────────
Jan   │ Actual    │ Copy Actual → Forecast (closed)
Feb   │ Actual    │ Copy Actual → Forecast (closed)
Mar   │ Actual    │ Copy Actual → Forecast (closed)
Apr   │ Actual    │ Copy Actual → Forecast (closed)
May   │ Actual    │ Copy Actual → Forecast (closed)
Jun   │ Actual    │ Copy Actual → Forecast (closed)
Jul   │ Actual    │ Copy Actual → Forecast (closed)
Aug   │ Actual    │ Copy Actual → Forecast (closed)
Sep   │ Forecast  │ Keep existing (open — user entered)
Oct   │ Forecast  │ Keep existing (open — user entered)
Nov   │ Forecast  │ Keep existing (open — user entered)
Dec   │ Forecast  │ Keep existing (open — user entered)

Result: Jan-Aug = Actuals, Sep-Dec = User Forecast
```

### Generated Script

```essbase
FIX("Forecast", "Working", &CurrYear, @RELATIVE("All_Hotels", 0))
  FIX(@RANGE("Period", "Jan", @PRIOR(@MEMBER(@CONCATENATE(&CurrMonth)))))
    DATACOPY "Actual" TO "Forecast";
  ENDFIX
ENDFIX
```

## 6. USING TEMPLATES IN RULES

### Drag-and-Drop in Graphical Designer

```
Rule: "Monthly_Forecast_Update"
├── Template: Rolling Forecast (configured for current month)
├── Script: P&L recalculations
├── Template: Mass Allocate (corporate overhead)
└── Script: AGG("Entity");

Deploy and attach to a form or schedule nightly.
```

### Template vs Custom Script

| Feature | System Template | Custom Script |
|---------|----------------|---------------|
| Setup time | 5 minutes (configure UI) | 30+ minutes (write code) |
| Maintenance | Oracle updates automatically | You maintain |
| Error handling | Built-in | Must write |
| Flexibility | Limited to template options | Unlimited |
| Performance | Optimized by Oracle | Depends on your code |
| Best for | Standard operations | Custom logic |

## 7. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Not clearing target in Copy Version | Old data persists | ☑ Clear Target Before Copy |
| Mass Allocate basis has zeros | Division by zero → no allocation | Validate basis data exists |
| Rolling Forecast wrong SubVar | Wrong periods locked as actual | Verify &CurrMonth is current |
| Using template when custom needed | Template limitations frustrate | Switch to Script component |
| Forgetting to deploy after config | Template doesn't execute | Always validate → deploy |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: What system templates does Calc Manager provide—**
> Copy Version (Working → Final), Copy Data (seed budget from actuals), Mass Allocate (distribute costs by driver), Rolling Forecast (blend actuals + forecast), Clear Cell Details (remove supporting detail), and Grid Spread. Templates are pre-built, parameterized components — drag into a rule, configure settings, deploy. No custom scripting needed for standard operations.

### Architect
**Q: When should you use a system template vs writing custom calc script—**
> Use templates when: the operation is standard (copy, allocate, clear) and the template's options cover your requirements. Use custom scripts when: you need custom logic (multi-driver allocation, conditional copying, complex transformations), performance optimization with SET commands, or integration with variables and cross-dimensional operations. Rule of thumb: start with a template. If it can't do what you need, then write custom script. Templates are maintained by Oracle and automatically optimized — custom scripts are your responsibility.
