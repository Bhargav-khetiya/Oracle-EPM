# 08.06 — Rulesets and Execution Flow: Complete Guide

> **Module:** 08_Calculation_Manager | **Topic:** Rulesets, Sequential Execution, Parallel Rules
> **Audience:** Service Administrator / Rule Developer

---

## 1. WHY — What Real-World Problem Does This Solve—

**The problem:** A form has 4 separate On Save rules: Revenue Totals, Expense Totals, P&L Calculation, and Aggregation. Each rule opens a separate Essbase session, causing overhead: 4 sessions × 2 second overhead = 8 seconds wasted. Users wait 12 seconds instead of 4.

**The solution:** A Ruleset groups multiple rules into a single execution unit, running them sequentially within one Essbase session. Result: 66% faster form saves.

---

## 2. WHAT — Ruleset Mechanics

```
WITHOUT Ruleset (4 individual On Save rules):
  Form Save → Rule 1 (open session → execute → close) → 3s
            → Rule 2 (open session → execute → close) → 3s
            → Rule 3 (open session → execute → close) → 3s
            → Rule 4 (open session → execute → close) → 3s
  Total: 12 seconds (4 sessions × 3s each)

WITH Ruleset (1 Ruleset containing 4 rules):
  Form Save → Ruleset (open session → Rule 1 → Rule 2 → Rule 3 → Rule 4 → close)
  Total: 4 seconds (1 session, rules share context)
```

---

## 3. CREATING A RULESET

```
Calculation Manager → New Ruleset

Name: Monthly_Close_Ruleset
Plan Type: OEP_FS

Rules (in execution order):
  1. Calculate_Revenue_Totals     → runs first
  2. Calculate_Expense_Totals     → runs second
  3. Calculate_PnL               → runs third (depends on 1 + 2)
  4. Calculate_KPIs              → runs fourth (depends on 3)
  5. Currency_Conversion         → runs fifth
  6. Aggregate_Entity            → runs last

Settings:
  ☑ Stop on error (if Rule 2 fails, don't run Rules 3-6)
  ☑ Run at server (execute on Essbase server)
```

### Ruleset Properties

| Property | Options | Description |
|----------|---------|-------------|
| **Stop on Error** | ☑ On / ☐ Off | Stop remaining rules if one fails |
| **Run at Server** | ☑ On / ☐ Off | Execute on Essbase server (faster) |
| **Validate** | Button | Validate all rules in the ruleset |
| **Deploy** | Button | Deploy the entire ruleset |

## 4. EXECUTION FLOW PATTERNS

### Pattern 1: Sequential (Default)

```
Ruleset: Monthly_Close
  Rule 1 → waits → Rule 2 → waits → Rule 3 → waits → Rule 4
  
  Each rule starts after the previous finishes.
  Data saved by Rule 1 is available to Rule 2.
```

### Pattern 2: Conditional Execution

```
Ruleset: Budget_Processing
  Rule 1: Calculate_Revenue (always runs)
  Rule 2: Calculate_Forex (condition: IF Currency <> "Local")
  Rule 3: Calculate_PnL (always runs)
  Rule 4: Send_Notification (condition: IF Scenario = "Budget")
  
  In the Ruleset designer:
    Rule 2 → Right-click → Set Condition → "Run only when..."
```

### Pattern 3: Ruleset Calling Ruleset

```
Master Ruleset: "Full_Month_End"
  ├── Ruleset 1: "Data_Preparation" (Clear + Load + Validate)
  ├── Ruleset 2: "Calculations" (Revenue + Expense + PnL + KPIs)
  ├── Ruleset 3: "Post_Processing" (Currency + Allocations)
  └── Ruleset 4: "Finalization" (Aggregate + Smart Push)
  
  Each sub-ruleset can be tested independently.
  The master ruleset chains them all together.
```

## 5. RULESETS ON FORMS

### Attaching to a Form

```
Form Designer → Business Rules tab:

On Save:
  ☐ Individual Rule: Calculate_Revenue
  ☐ Individual Rule: Calculate_PnL
  ☐ Individual Rule: Aggregate
  
  BETTER:
  ☑ Ruleset: Data_Entry_OnSave (contains all 3 rules)
  
Result: 1 Essbase session instead of 3.
  Save time: 9 seconds → 3 seconds.
```

### On Load vs On Save Rulesets

| Trigger | When Runs | Typical Rules |
|---------|-----------|---------------|
| **On Load** | Before form opens | Refresh dynamic calcs, currency conversion |
| **On Save** | After user saves | Totals, P&L, KPIs, aggregation |

```
Form: Revenue_Entry
  On Load Ruleset: "Refresh_Form_Data"
    Rule 1: Update_Exchange_Rates
    Rule 2: Calculate_Prior_Year_Variance
  
  On Save Ruleset: "Process_Revenue"
    Rule 1: Calculate_Revenue_Totals
    Rule 2: Calculate_PnL
    Rule 3: Aggregate_Entity
    Rule 4: Smart_Push_to_Reporting
```

## 7. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Not using Ruleset for multiple On Save rules | Slow form saves | Group into Ruleset |
| Wrong rule order in Ruleset | P&L calc before Revenue calc → wrong values | Order dependencies correctly |
| "Stop on Error" off | Downstream rules use bad data | Turn ON for production |
| Not deploying Ruleset after changes | Old version runs | Re-deploy after editing |
| Too many rules in On Load Ruleset | Form opens slowly | Move non-essential to On Save or batch |
| Ruleset not validated | Compilation error at runtime | Validate all rules before deploy |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: What is a Ruleset and why use one instead of individual rules—**
> A Ruleset groups multiple business rules into a single execution unit. Individual On Save rules each open separate Essbase sessions (2-3 second overhead each). A Ruleset runs all rules within one session — typically 2-3× faster. Also, Rulesets guarantee execution order (Rule 1 before Rule 2) and support "Stop on Error" to prevent downstream rules from running on bad data.

### Architect
**Q: Design the Ruleset architecture for Hotel Pvt Ltd's entire application.**
> Four Rulesets: (1) **Revenue_OnSave** — attached to Revenue form, runs totals + KPIs + entity aggregation. (2) **Expense_OnSave** — attached to Expense form, runs expense totals + P&L + aggregation. (3) **Monthly_Close** — scheduled at 2 AM on the 1st, runs the full sequence: SubVar update → all calcs → currency conversion → allocation → aggregation → Smart Push. (4) **Annual_Budget_Seed** — manual trigger once per year, runs clear → copy → growth → PnL → aggregate. Each Ruleset has "Stop on Error" enabled. Monthly_Close should be monitored via Jobs Console with email alerts on failure.
