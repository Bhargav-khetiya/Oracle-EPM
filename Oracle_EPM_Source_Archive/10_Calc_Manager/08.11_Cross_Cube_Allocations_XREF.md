# 08.11 — Cross-Cube Allocations (XREF): Complete Guide

> **Module:** 08_Calculation_Manager | **Topic:** Cross-Cube References, XREF, Smart Push
> **Audience:** Architect / Developer

---

## 1. WHY — Data Lives in Multiple Cubes

Hotel Pvt Ltd has salary data in OEP_WFP (Workforce) but needs the total labor cost in OEP_FS (FinPlan) for P&L calculations. Cross-cube operations move or reference data between cubes.

---

## 2. THREE METHODS FOR CROSS-CUBE ACCESS

| Method | Direction | Mechanism | Best For |
|--------|-----------|-----------|----------|
| **Smart Push** | Source → Target | Push on form save | Automated, real-time |
| **Data Map (Groovy)** | Source → Rule | Read in Groovy | Complex logic |
| **XREF (Calc Script)** | Source → Rule | Read in calc | Simple lookups |

---

## 3. SMART PUSH

```
Form Designer → Business Rules → Smart Push

Configuration:
  Source Cube: OEP_WFP (Workforce)
  Target Cube: OEP_FS (FinPlan)
  
  Data Mapping:
    Source Account: Total_Labor_Cost → Target Account: Labor
    Source Entity: (same)
    Source Period: (same)
    Source Scenario: (same)
  
  Trigger: On Save (when user saves Workforce form)
  
Result: When HR saves salary data, it auto-pushes to FinPlan cube
```

---

## 4. GROOVY DATA MAP

```groovy
/* Read from Workforce cube while in FinPlan rule */
DataMap wfpMap = operation.dataMap("WFP_to_FS")

operation.grid.dataCellIterator("Account#Labor").each { cell ->
    /* Read Total_Labor_Cost from Workforce cube */
    double laborCost = cell.crossDimCell(wfpMap, "Account#Total_Labor_Cost").data
    cell.data = laborCost
}
```

---

## 5. XREF IN CALC SCRIPTS

```essbase
/* @XREF — read from another cube in a calc script */
FIX("Budget", "Working", &CurrYear)
  FIX(@RELATIVE("All_Hotels", 0))
    /* Read Total_Labor_Cost from OEP_WFP cube */
    "Labor" = @XREF("OEP_WFP", "Total_Labor_Cost");
  ENDFIX
ENDFIX

/* @XREF syntax: @XREF("CubeName", "MemberInSourceCube") */
/* Unmapped dimensions use same member name across cubes */
/* Only works if dimension members have same names in both cubes */
```

### XREF Limitations

```
⚠️ @XREF is READ-ONLY (cannot write to other cube)
⚠️ @XREF is SLOW on large datasets (cell-by-cell retrieval)
⚠️ Dimension members must have same names in both cubes
⚠️ @XREF doesn't work in ASO cubes
⚠️ Smart Push is preferred for most use cases
```

---

## 6. COMPARISON

| Feature | Smart Push | Groovy DataMap | @XREF |
|---------|-----------|---------------|-------|
| Speed | ⚡ Fast (batch) | ⚡ Medium | 🐌 Slow (cell-by-cell) |
| Direction | Push (write) | Read | Read |
| Trigger | Form save/rule | Rule execution | Rule execution |
| Mapping flexibility | High | High | Low (same names) |
| Recommended | ✅ Primary | ✅ Complex logic | ⚠️ Simple lookups only |
