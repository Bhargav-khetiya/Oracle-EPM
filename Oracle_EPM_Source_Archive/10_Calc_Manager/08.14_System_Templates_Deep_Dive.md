## 1. Using the Clear Data Template

Use the Clear Data template to clear data from members in the cube.

To clear data, you specify the members whose values you want to clear. You can clear data for one member or for a block of members.

For example, you could use the Clear Data template to clear forecast data before copying data from "actual" to "forecast" and making changes.

### How to use the Clear Data template:

1. Create or open a business rule or a template.
2. Do one of the following:
   * **For a graphical rule or template:** Under New Objects, select Clear Data, and then drop it into the flow chart between Begin and End.
   * **For a script rule or template:** Expand System Templates, then select Clear Data, and then drop it into the desired area in the script.
3. Enter the requested information in the Clear Data Wizard.

### Clear Data Wizard Steps

#### Step 1: Data Selection
Define the data to clear by selecting one or more members for each dimension.

The following options are available:
* Click **Variable Selector** button next to Use Predefined Selection to select variables to populate all the dimensions with values.
* Click **Member Selector** button next to Member Selector to select members and functions for each dimension.
* Select a dimension, and then click **Select** button to select a variable, member, or function.

In **Select a Clearblock Option**, select an option to define how to clear the data:
* **All:** Clears all blocks of data.
* **Upper:** Clears only consolidated blocks of data.
* **Dynamic:** Clears blocks containing values derived from Dynamic Calc and Store member combinations.
* **Non-Input:** Clears data blocks containing derived values. This works only for blocks that are created completely by a calculation operation and not blocks into which any values are loaded.
* **N/A:** Clears data blocks and sets the members to #Missing.

#### Step 2: Settings
If you have a multi-currency application with `HSP_Rates` set to "sparse" or a single-currency application, Settings displays the members selected in Data Selection.

Click the drop-down, and select a dimension where a single member is selected, preferably a dense dimension.

> **Note:** Since the script uses the member from the dimension you select, if you cannot select a dimension where a single member is selected, then you cannot use this template.

### Deep Dive: Understanding Clearblock Options & Use Cases

When you select an option in the "Select a Clearblock Option" dropdown, the System Template generates specific Essbase syntax under the hood. Understanding the difference between these options is critical for performance and data integrity.

#### 1. All (Generates: `CLEARBLOCK ALL`)
* **What it does:** Completely deletes the physical data block from the database for the selected sparse intersection. 
* **Use Case:** Preparing a target scenario for a fresh copy. For example, before you copy Actuals to Forecast, you want to ensure there is no residual, obsolete forecast data sitting in blocks that Actuals won't overwrite.
* **Example:** `CLEARBLOCK "Forecast" ALL;` will physically remove all blocks associated with the Forecast scenario.

#### 2. Upper (Generates: `CLEARBLOCK UPPER`)
* **What it does:** Clears data only from blocks that contain consolidated (level 1 or higher) sparse members. It leaves base-level (level 0) input data untouched.
* **Use Case:** Resetting aggregations. If you have run a full database aggregation and want to "undo" it to save space before a backup, or if you need to force a clean re-aggregation from level 0 without deleting user inputs.
* **Example:** Wiping out all aggregated regional totals while preserving the specific data inputs from local branches.

#### 3. Dynamic (Generates: `CLEARBLOCK DYNAMIC`)
* **What it does:** Specifically clears blocks that are associated with members tagged as "Dynamic Calc and Store". 
* **Use Case:** "Dynamic Calc and Store" members calculate upon first retrieval and then save the result to disk to speed up subsequent queries. If the underlying data changes, you must clear these stored dynamic blocks so they recalculate correctly on the next retrieval.

#### 4. Non-Input (Generates: `CLEARBLOCK NONINPUT`)
* **What it does:** Clears data blocks that were generated entirely by calculations, leaving blocks alone if they contain at least one piece of data that was manually input or loaded via Data Integration.
* **Use Case:** Re-running allocations. If you allocate an IT overhead pool down to 100 departments, it creates new blocks. If the allocation rules change, you want to clear out the previous allocated amounts (Non-Input) without accidentally deleting a department's direct expenses (Input).

#### 5. N/A (Generates: `CLEARDATA`)
* **What it does:** Instead of deleting the physical data block from the disk, this option loops through the block and changes every single data cell to `#Missing` (null). The block itself remains on the disk.
* **Use Case:** You are targeting a dense dimension member (e.g., clearing a specific Account). You cannot delete a physical block based on a dense member, because the block contains *all* dense members. So, you must use `CLEARDATA` to simply empty the specific cells inside the block.
* **Example:** You need to clear the "Salaries" account, but keep "Taxes" and "Benefits" which are in the same dense block.

#### Performance Tip: CLEARBLOCK vs CLEARDATA
* **`CLEARBLOCK`** is extremely fast because it drops the file pointer to the block entirely. It reduces database size. It can only be used on **Sparse** dimensions.
* **`CLEARDATA`** is slower because it must load the block into memory, write `#Missing` to the cells, and save the block back to disk. Use this when targeting **Dense** dimensions.

## 2. Using the Copy Data Template

Use the Copy Data template to copy data from one location in the database to another.

For example, you could use the Copy Data template to create a budget for 2015 by copying the values for your accounts and entities from 2014. In this case, you would copy the 2014 actuals to the forecast for 2015. You could also use the Copy Data template to copy budget data from a "worst case" budget scenario to a "best case" scenario, where you can make changes.

### How to use the Copy Data template:

1. Create or open a business rule or a template.
2. Do one of the following:
   * **For a graphical rule or template:** Under New Objects, select Copy Data, and then drop it into the flow chart between Begin and End.
   * **For a script rule or template:** Expand System Templates, then select Copy Data, and then drop it into the desired area in the script.
3. Enter the requested information in the Copy Data Wizard.

### Copy Data Wizard Steps

#### Step 1: Point of View
Define the data to copy by selecting one or more members for each dimension. Leave the dimensions that vary for copy from and to empty. You specify these members in the following steps.

The following options are available:
* Click **Variable Selector** button next to Use Predefined Selection, to select variables to populate all the dimensions with values.
* Click **Member Selector** button next to Member Selector, to select members and functions for each dimension.
* Select a dimension, and then click **Select** button to select a variable, member, or function.

#### Step 2: Copy From
Select the members from which to copy data.
> **Note:** Select one member for each dimension. If you do not select a member for each dimension, a warning message is displayed.

#### Step 3: Copy To
Select the member to which to copy data.

#### Step 4: Options
*Optional:* Enter a percentage increase or decrease to apply to the destination range of data cells.
For example, to increase the target data by 10 percent, enter `10`, and to decrease the target data by 10 percent, enter `-10`.
To enter a variable, click the Select button. For example, you could define a run-time prompt variable, and then enter the value for this increase or decrease at runtime.

### Deep Dive: Copy Data Architecture & Best Practices

Under the hood, the Copy Data template generates a `DATACOPY` Essbase command. Understanding how `DATACOPY` works is vital for writing efficient rules.

#### 1. How DATACOPY works
Unlike basic mathematical assignments (e.g., `Target = Source;`), `DATACOPY` physically creates blocks for the target if they do not exist. It reads the source block, duplicates it, changes the target dimension member name in the header, and writes the new block to disk.
* **Syntax Generated:** `DATACOPY "Source_Member" TO "Target_Member";`
* **Performance:** Because it works at the block level rather than calculating cell-by-cell, `DATACOPY` is extremely fast and efficient for moving large swaths of data.

#### 2. Point of View vs Copy From/To
The wizard separates the POV from the Source/Target:
* **Point of View (The `FIX` statement):** The dimensions you set in the POV define the boundaries of the copy. This generates the `FIX (...)` statement around the `DATACOPY` command. It tells Essbase *what slice* of data to look at.
* **Copy From / To (The `DATACOPY` statement):** The dimensions you leave blank in the POV are the ones that are changing. You define these in the Source and Target tabs.

#### 3. Best Practices & Pitfalls
* **Always Clear Target First:** `DATACOPY` does not overwrite data if the source intersection is `#Missing` and the target is not; it adds/updates. If the target intersection already contains data that doesn't exist in the source, that target data will remain untouched, leading to an imperfect copy. **Always use a Clear Data template on the target region immediately before a Copy Data template** to ensure a perfect 1:1 match.
* **Block Creation:** Because `DATACOPY` explicitly creates blocks, it is widely used as a "Block Creator" tool. If you need to perform math on an empty dataset, you can first `DATACOPY` dummy data into it to ensure the blocks exist before running your custom formulas.
* **The Options Tab (Math during copy):** The percentage increase/decrease option is powerful. Instead of doing a `DATACOPY` and then a subsequent `Target = Target * 1.10;`, the template can handle this in one pass, reducing I/O and saving time.

## 3. Using the Amount-Unit-Rate Template

Use the Amount-Unit-Rate template to calculate one of three members that you input for amounts, units and rates.

For example, if you want to calculate product revenue and you know the quantity and price, you select Calculate Amounts, and enter the product revenue for amounts, the quantity for units, and the price for rates. This calculates product revenue by multiplying quantity and price.

### How to use the Amount-Unit-Rate template:

1. Create or open a business rule or a template.
2. Do one of the following:
   * **For a graphical rule or template:** Under New Objects, select Amount-Unit-Rate, and then drop it into the flow chart between Begin and End.
   * **For a script rule or template:** Expand System Templates, then select Amount-Unit-Rate, and then drop it into the desired area in the script.
3. Enter the requested information in the Amount-Unit-Rate Wizard.

### Amount-Unit-Rate Wizard Steps

#### Step 1: Select Calculation Method
Define a calculation method to use by selecting one of the following options from the drop-down list:
* **Calculate Amounts:** Amounts = Units * Rates
* **Calculate Units:** Units = Amounts / Rates
* **Calculate Rates:** Rates = Amounts / Units
* **Calculate All:** Select if the member with `#Missing` may vary or is unknown. This calculation method searches for the `#Missing` values and applies the appropriate calculation method to solve for these unknown values.

#### Step 2: Point of View
Define the members that do not vary in the calculation process.
* Click **Variable Selector** button next to Use Predefined Selection, to select variables to populate all the dimensions with values.
* Click **Member Selector** button next to Member Selector, to select members for each dimension.
* Select a dimension, and then click **Select** button to select a variable, member, or function.

#### Step 3: Calculate Amounts/ Calculate Units / Calculate Rates / Calculate All
This step varies depending on what you selected for the calculation method.
* **If you select Calculate Amounts:** enter a member or click Select button to select a member for Amounts, then click Next to enter members for Units, and then click Next to enter members for Rates. On the Units and Rates steps, you can enter members that vary from the Point of View.
* **If you selected to Calculate Units:** enter a member or click Select button to select a member for Units, then click Next to enter members for Amounts, and then click Next to enter members for Rates.
* **If you selected to Calculate Rates:** enter a member or click Select button to select a member for Rates, then click Next to enter members for Amounts, and then click Next to enter members for Units.
* **If you select Calculate All:** enter or select members for Amounts, Units, and Rates.

### Deep Dive: Driver-Based Math & Error Prevention

The Amount-Unit-Rate template is fundamental for Driver-Based Planning. While the math seems simple (`A = U * R`), writing it manually in a script often leads to errors and poor performance if not handled correctly.

#### 1. Zero-Division Protection (The `#Missing` Problem)
When you choose **Calculate Units (`U = A / R`)** or **Calculate Rates (`R = A / U`)**, dividing by zero or `#Missing` will cause Essbase to throw an error or write meaningless data. 
* **The Template Advantage:** Under the hood, this template wraps the division in a protective `IF` statement. It verifies that the denominator is not zero and not `#Missing` *before* attempting the math. This prevents calculation failures and keeps logs clean.

#### 2. The Power of "Calculate All"
"Calculate All" is extremely powerful for dynamic modeling where users might input any two of the three variables. 
* **How it works:** It generates a conditional block that checks which variables are `#Missing`. 
  * `IF(Units != #Missing AND Rates != #Missing) Amounts = Units * Rates;`
  * `ELSEIF(Amounts != #Missing AND Rates != #Missing) Units = Amounts / Rates;`
  * `ELSEIF(Amounts != #Missing AND Units != #Missing) Rates = Amounts / Units;`
* **Use Case:** A planner knows they need $1,000,000 in Revenue (Amount) and their product Price is $50 (Rate). They type in the Amount and Rate, and the system automatically solves for the required Volume (Units). Another planner inputs Volume and Price, and the system solves for Revenue.

#### 3. Block Creation Dynamics
Similar to other calculations, standard mathematical formulas (`Amounts = Units * Rates;`) require the target block to exist. 
* If you are calculating **Amounts** and the intersection for "Amount" doesn't have a block yet, the calculation won't happen unless you enable `#Missing` block creation (which is bad for performance) or use a `DATACOPY` to create the block first. 
* However, if Amounts and Units share the same dense dimensions, the formula will simply execute within the existing block, making it highly efficient.

 T_TP

     T_TP1

         P_110
         etc
     T_TP2
         P_200
         P_210
         etc
     T_TP3
         P_291
         P_292

In this example, you would use level/generation 3 for the start and level/generation 4 for the end in the Allocate - Level to Level template to allocate from the parent members (T_TP1, T_TP2, T_TP3) to their children (level 0) members.

### Deep Dive: Level-to-Level Allocation Architecture

The Allocate Level-to-Level template is a powerful wrapper for the Essbase `@ALLOCATE` and `@MDALLOCATE` functions. It is designed to take a pool of money sitting at a parent level and dynamically push it down to the descendants based on a specific driver.

#### 1. Why Level-to-Level is Powerful
Standard allocations often just push from one single source (e.g., `IT_Dept`) to a list of targets (e.g., `@RELATIVE("Total Departments", 0)`). 
**Level-to-Level** is different because it loops through the hierarchy. In the example provided (T_TP1, T_TP2), money sitting at T_TP1 is allocated ONLY to its direct children (P_100, P_110). Money sitting at T_TP2 is allocated ONLY to P_200, P_210. This creates a highly dynamic "waterfall" allocation without having to write hundreds of individual `FIX` statements.

#### 2. The Offset Concept
In standard accounting, when you allocate money out of a pool (Source) into a specific department (Target), the pool must be cleared out, otherwise, the balance sheet will double-count the money. 
* **Without Offset:** The source pool remains at $100, and the targets receive $100. (Total = $200. Bad for financials).
* **With Offset:** The system writes a negative entry (`-100`) to the defined Offset member. (Source = $100, Offset = -$100, Targets = $100. Total = $100. Perfectly balanced).

#### 3. Drivers and the "Basis"
The "Driver" is the mathematical basis for the allocation. If T_TP1 has $1,000 to allocate to P_100 and P_110, how does it know how much to give each—
* The driver defines this ratio. If the driver is "Headcount", and P_100 has 70 employees while P_110 has 30, the template automatically calculates the ratio: `70 / (70 + 30) = 70%`. P_100 gets $700, and P_110 gets $300.
* **Driver Aggregation:** The wizard asks if you want to update the driver's aggregations. If your Headcount data is loaded at Level 0 but hasn't been aggregated up to the parent (T_TP1), the calculation will fail (since it divides by the total). The template can automatically generate an `@SUM` or `CALC DIM` command to aggregate the driver *before* performing the allocation.

#### 4. Performance Considerations
Because this template generates `@ALLOCATE` or `@MDALLOCATE`, it executes in top-down mode. 
* It requires the underlying blocks to exist.
* If you are allocating across multiple sparse dimensions, it might generate a massive cross-dimensional block generation event. 
* Always test the output script to ensure the `FIX` statement is as tight as possible.

## 5. Using the Allocation Template

Use the Allocation template to allocate values from a source to a destination, either evenly or based on a specified driver.

For example, you could use the Allocation template to allocate administrative expenses to the level 0 members of the Product dimension, using Gross Sales as the basis.

### How to use the Allocation template:

1. Create or open a business rule or a template.
2. Do one of the following:
   * **For a graphical rule or template:** Under New Objects, select Allocation, and then drop it into the flow chart between Begin and End.
   * **For a script rule or template:** Expand System Templates, then select Allocation, and then drop it into the desired area in the script.
3. Enter the requested information in the Allocation Wizard.

### Allocation Wizard Steps

#### Step 1: Point of View
Define the members that do not vary in the allocation. You must select at least one member from one dimension.
* Click **Variable Selector** button next to Use Predefined Selection, to select variables to populate all the dimensions with values.
* Click **Member Selector** button next to Member Selector, to select members for each dimension.
* Select a dimension, and then click **Select** button to select a variable, member, or function.

#### Step 2: Source
For each dimension, select a member from which to allocate the data, and enter the percentage of the source to allocate.
* For example, to allocate 25% of the source value enter `25`.

#### Step 3: Allocation Range
Select the dimension to which to allocate the data, and the parent member for this dimension.
* The data is allocated to the **level 0 members** below the specified parent member in the database outline. (The level 0 member is the lowest member in the outline with no members beneath it.)

#### Step 4: Destination - Target
Specify a target member for each dimension defined in the source.

#### Step 5: Destination - Offset
*Optional.* Specify the offset to generate an offsetting calculation by entering a member for each dimension.
* An offsetting value can be calculated as either the same or opposite value of the source.
* For example, if you have $1000 in your source to allocate, you can use an offset so that you don't double your numbers. When you run the rule, $1000 will be allocated to level 0, and the offset will create the `-1000` in the members specified.
* Specify whether to clear the offset data before the allocation process begins.
* Specify whether the offset's value should be the opposite sign of the allocated data.

#### Step 6: Exclude
*Optional.* Select members to exclude from the allocation range.
* These members do not receive any allocated data, and their driver values are excluded from the driver percentage basis.

#### Step 7: Driver
Define whether to "allocate using a driver" or "allocate evenly".
* Select one member per dimension for each dimension that varies from the Point of View. Dimensions you leave empty are inherited from the Point of View and from the upper member ranges defined in the rule.

#### Step 8: Spread Method
If you selected "allocate evenly" in the Driver step, select an option to spread the data.

#### Step 9: Other Options (Rounding)
Answer the questions in the wizard. If you select a rounding method, there are additional steps depending on the rounding method you select. The following rounding methods are available:
* **Define Rounding Member:** If you select this option, then next step is *Rounding on Member*, where you enter the number of decimal places to use for the allocation and select a member on which to place the allocation rounding difference.
* **Use Biggest Value:** If you select this option, the next step is *Round on Biggest*, where you enter the number of decimal places to use for the allocation.
* **Use Smallest Value:** If you select this option, the next step is *Round on Smallest*, where you enter the number of decimal places to use for the allocation.
* **No Rounding:** If you select this option, there are no additional steps.

### Deep Dive: Standard Allocation Architecture

The standard Allocation template is one of the most frequently used components in Planning/Calculation Manager. It generates the `@ALLOCATE` function under the hood, but specifically targets Level 0 members.

#### 1. Level-to-Level vs. Standard Allocation
Unlike the Level-to-Level allocation (which cascades down the hierarchy step-by-step), the standard Allocation template is a direct "Top-Down" push. It takes a pool of money (Source) and pushes it directly to the lowest level (Level 0) descendants of the Allocation Range parent. It skips intermediate parents entirely.

#### 2. The Exclude Function
The Exclude tab is critical for edge-cases where a specific member within the target parent should NOT receive an allocation. 
* **The Math Impact:** It is important to note that excluding a member doesn't just stop it from receiving money; it also excludes that member's driver data from the total basis pool. 
* **Example:** If you allocate based on Headcount, and you exclude the "Exec_Dept" member, the calculation will remove "Exec_Dept" from the total Headcount denominator so that 100% of the money is distributed properly among the remaining departments.

#### 3. Rounding Differences
When dealing with percentages and fractions (e.g., allocating $100 across 3 departments based on 33.33% each), you often end up with a remainder (e.g., $99.99 allocated, $0.01 left over). This causes reconciliation issues in financial reports.
* **Define Rounding Member:** This allows you to select a specific "plug" account or department to absorb any leftover pennies, ensuring the final allocated sum perfectly matches the source.
* **Round on Biggest / Smallest:** Alternatively, Essbase can automatically find the department that received the largest (or smallest) allocation and simply stick the extra penny there.

#### 4. Allocate Evenly vs Driver-Based
* **Driver-Based:** Uses the proportional value of a driver member (e.g., Headcount, Square Footage) to calculate ratios.
* **Allocate Evenly:** If you have 5 level-0 targets in your Allocation Range, it simply divides the Source by 5 and pushes 20% to each. This is useful for flat distributions (e.g., distributing a flat software licensing fee equally among all users).

## 6. Using the Aggregation Template

Use the Aggregation template to aggregate data values of members you specify.

Using the Aggregation template, you can:
* Restrict the aggregation by entering members in the Point of View
* Specify whether to aggregate missing values
* Specify whether to aggregate values into the local currency (not supported for hybrid aggregation)

* `SET FRMLBOTTOMUP ON`: Optimize the calculation on a sparse dimension

For example, you could use the Aggregation template to aggregate dense or sparse dimensions using a parent member, and select a level of aggregation, such as Descendants, Children, or Ancestors(all).

Specify the settings on the step (e.g., SET commands for aggregation).

### Deep Dive: Aggregation Architecture & Hybrid Optimization

The Aggregation Template translates the wizard inputs into standard Essbase `CALC DIM()` or `AGG()` commands, combined with optimal `SET` settings. 

#### 1. Dense vs. Sparse Aggregation
Essbase handles Dense and Sparse aggregations completely differently:
* **Dense:** Dense dimensions are calculated *within* the block in memory. It is incredibly fast. That's why the wizard separates Dense and Sparse. If a Dense dimension has no stored upper-level members (e.g., everything is Dynamic Calc), the template is smart enough to generate *no script* for it, saving processing time.
* **Sparse:** Sparse dimensions create entirely new blocks when they aggregate. `AGG(Sparse_Dim)` is generally faster than `CALC DIM(Sparse_Dim)` because `AGG` just adds the numbers up, whereas `CALC DIM` also executes any member formulas on that dimension. The template asks if your sparse dimension has formulas so it knows whether to use `AGG` or `CALC DIM`.

#### 2. Full vs. Partial Aggregation
* **Full Aggregation:** Runs the command on the entire dimension (e.g., `AGG(Entity);`). This is simple but can be overkill if only a small portion of the dimension changed data.
* **Partial Aggregation:** Runs the aggregation on a specific subset (e.g., `@DESCENDANTS("North_America")`). This generates a `FIX` statement or uses specific functions to limit the block creation, which is a major performance tuning technique.

#### 3. The "Hybrid Aggregation" Note
You'll notice the Oracle documentation specifically calls out that certain SET commands (like `SET UPTOLOCAL ON` and `SET CACHE HIGH`) are "not supported for hybrid aggregation". 
* **What is Hybrid—** Hybrid BSO (Block Storage Option) allows sparse upper-level members to calculate dynamically in memory upon retrieval, just like dense members. 
* **The Impact:** If an application has Hybrid enabled, you generally *do not need to run Aggregation rules on sparse dimensions* anymore. The numbers roll up automatically when the user refreshes a report. Therefore, while this template is powerful for traditional BSO, its use is heavily minimized in modern Hybrid EPM applications.

#### 4. Important SET Commands
The template allows you to easily inject critical SET commands:
* **`SET AGGMISSG ON`:** If turned ON, Essbase treats `#Missing` as a value during aggregation. This can sometimes create empty upper-level blocks if you aren't careful, so it's often left OFF for performance unless specifically needed.
* **`SET FRMLBOTTOMUP ON`:** Forces the calculator engine to evaluate formulas from the bottom of the hierarchy up. This is a crucial setting for optimizing calculations on sparse dimensions to prevent the engine from doing unnecessary top-down passes.

## 7. Using the SET Commands Template

Use the SET Commands template to enter script commands that optimize the performance of calculation scripts.

You can include data volume, data handling, memory usage, threading, and logging script commands.

### How to use the SET Commands template:

1. Create or open a business rule or a template.
2. Do one of the following:
   * **For a graphical rule or template:** Under New Objects, select SET Commands and then drop it into the flow chart between Begin and End.
   * **For a script rule or template:** Expand System Templates, then select SET Commands, and then drop it into the desired area in the script.
3. Enter the requested information in the Set Commands Wizard.

### SET Commands Wizard Steps

The wizard includes the following steps:
1. **Data Volume**
2. **Data Handling**
3. **Memory Usage**
4. **Threading**
5. **Logging**

Each step has several questions that can be answered by selecting an option in the drop-down list next to the question. You can select one or more options in this template.

> **Note:** You do not need to answer every question in the Set Commands wizard. You can answer only the questions that are applicable to your situation.
> 
> **Note:** When the application is in Essbase Hybrid, only the Data Volume, Data Handling, and Threading tabs are displayed in the wizard.

### Deep Dive: Common SET Commands & Performance Tuning

The SET Commands template is essentially a GUI wrapper for inserting Essbase `SET` commands at the top of your script. These commands dictate how the Essbase calculator engine allocates memory, handles missing data, and utilizes CPU threads.

#### 1. Data Volume & Data Handling
These tabs control how the engine behaves when it encounters data vs. `#Missing` blocks.
* **`SET UPDATECALC OFF;`** (Intelligent Calc): This is one of the most critical commands to understand. If you know you are running a full calc on a fresh dataset, setting this to `OFF` forces Essbase to calculate everything, ignoring whether blocks are marked as "clean" or "dirty". 
* **`SET AGGMISSG ON/OFF;`**: Determines if Essbase should consider `#Missing` cells as values during aggregation. Usually kept `OFF` to prevent the unnecessary creation of empty upper-level blocks.
* **`SET CREATEBLOCKONEQ ON/OFF;`**: If `ON`, allows equations on sparse dimensions to create blocks even if the target is empty. This is notoriously dangerous for performance if misused (can cause block explosions).

#### 2. Memory Usage (Non-Hybrid Only)
In traditional BSO applications, you must manually tune how much RAM Essbase is allowed to use during complex calculations.
* **`SET CACHE HIGH;`**: Instructs Essbase to maximize calculator cache (RAM) for the duration of the script. This minimizes disk I/O, dramatically speeding up calculations at the expense of memory usage.
* **Why this disappears in Hybrid:** As the Oracle note mentions, if the app is Hybrid, this tab disappears. Hybrid Essbase manages memory dynamically and automatically. It does not require or allow manual `CACHE` tuning commands in scripts.

#### 3. Threading (`CALCPARALLEL`)
The Threading tab allows you to configure multi-processing.
* **`SET CALCPARALLEL n;`**: Where `n` is the number of CPU threads you want to allocate to the calculation (e.g., `SET CALCPARALLEL 4;`).
* **How it works:** Essbase will evaluate the `FIX` statement and attempt to break the calculation down into independent "tasks" that can run concurrently on multiple CPU threads. If you have a powerful server, this can cut calculation times by 50% or more.
* **Best Practice:** Never set this to the maximum number of cores on the server. If a server has 8 cores, setting `CALCPARALLEL 8` will consume 100% of the CPU, freezing out other users or integrations.

#### 4. Logging
* **`SET MSG SUMMARY / DETAIL / ERROR;`**: Controls how much information Essbase writes to the application log during the calc. For standard production rules, use `SUMMARY` or `ERROR` to prevent the log files from ballooning to gigabytes in size. Use `DETAIL` only for debugging.

You use the Currency Conversion template in Planning applications that are created with multiple currencies selected.

> **Note:** The Oracle documentation notes: "If the Planning application is created with multi-currencies, the Currency Conversion template does not display in the list of System Templates." 2. Do one of the following:
   * **For a graphical rule or template:** Under New Objects, select Currency Conversion, and then drop it into the flow chart between Begin and End.
   * **For a script rule or template:** Expand System Templates, then select Currency Conversion, and then drop it into the desired area in the script.

#### Step 1: Information - Currency
Describes the function of the template and what information you need to use the template.

#### Step 2: Exchange Rate Option
Answer the questions in the wizard about currency:

* **Select the reporting currency:** Select the reporting currency to which you want to convert.
* **Select the parent member that contains your currency members:** Select the parent member that is the parent for all of the currencies used in your application; for example, "Input Currencies."

* **Do you want to use the account types for currency conversion—** Select *Yes* to use account types for currency conversion. If you select Yes, Expense and Revenue accounts will use average exchange rates, and Liability and Equity accounts will use ending exchange rates. * **Do you want to calculate ending exchange rates—** Select whether to calculate ending rates.

Select the members to use in the conversion to the reporting currency.
* Click **Variable Selector** button next to Use Predefined Selection, to select variables to populate all the dimensions with values.

* Select a dimension, and then click **Select** button to select a variable, member, or function.

Enter the account(s) to use the average exchange rate to convert to the reporting currency.

Select the members that contain the ending exchange rates.
> **Note:** You only need to select the members that are different than the members in the Point of View.

### Deep Dive: Currency Translation Architecture

Currency conversion is one of the most complex tasks in EPM. The Currency Conversion template simplifies the process of joining financial data with exchange rates stored in a different dimension.

#### 1. Average vs. Ending Rates (The Accounting Principle)
The wizard asks if you want to use "Account Types" for conversion. This relies on standard accounting principles (FASB 52):
* **Average Rates (P&L):** Revenue and Expense accounts happen *over time* (e.g., across a whole month). Therefore, they must be converted using the Average Exchange Rate for that month. 
* **Ending Rates (Balance Sheet):** Asset, Liability, and Equity accounts represent a snapshot at a specific *point in time* (the end of the month). Therefore, they must be converted using the Ending Exchange Rate on the final day of the month.
* **Template Logic:** If you select "Yes", the template automatically writes an `IF` statement that checks the account type (e.g., `IF(@ISACCTYPE("Revenue") OR @ISACCTYPE("Expense")) Rate = "HSP_InputValue"->"Average";`).

#### 2. The HSP_Rates Dimension
In Oracle Planning multi-currency applications, exchange rates are stored in a hidden sparse dimension called `HSP_Rates` (or sometimes in a specific Account if the app is custom). 
* The wizard prompts you for "FX Average" and "FX Ending". This is where you point the template to the specific members holding those rates (e.g., `HSP_InputValue` for the local input, and the rate intersection).
* The script generates cross-dimensional mathematics: `Reporting_Currency = Local_Currency * (Rate_Account -> Rate_Type)`.

#### 3. Why the Template is Sometimes Hidden
The Oracle note mentions: *"If the Planning application is created with multi-currencies, the Currency Conversion template does not display."*
* **Why—** When you create a multi-currency Planning application, Oracle automatically generates hidden calculation scripts (often called `Calculate Currency` or `HSP_CRCY`) behind the scenes. When a user runs a rule, Planning injects this currency logic automatically.
* **When to use the Template:** You use this template if you built a *Standard* (single-currency) application but later decided to manually build a custom currency conversion process, or if you need to run a very specific, isolated currency translation on a custom cube.
