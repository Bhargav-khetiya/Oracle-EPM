## Introduction

The Calculation Manager **Graphical Designer** is a visual drag-and-drop interface for building business rules. Instead of writing raw Essbase calc scripts, you drag objects onto a canvas, connect them with arrows, and the system compiles them into optimized scripts.

This document covers **every object** in the Designer palette, **every property** on each object, and how connections/flow work.

---

```
Navigator → Calculation Manager → [Application] → [Plan Type] → Rules → 
[Right-click] → New → Business Rule → Designer Tab
```

# SECTION 3: FLOW CONNECTIONS & ARROWS

## How Arrows Work

| Connection Type | Meaning |
|----------------|---------|
| **Straight arrow (→)** | Sequential execution (this runs, then that runs) |
| **Green arrow from Condition** | TRUE branch — execute if condition is true |
| **Red arrow from Condition** | FALSE branch — execute if condition is false |
| **Arrow into Loop** | Execute inside the loop body |
| **Arrow into Member Range** | Execute within the FIX scope |

## Connection Rules
1. Every object must have at least ONE incoming arrow and ONE outgoing arrow
2. Begin can ONLY have outgoing arrows
3. End can ONLY have incoming arrows
4. Conditions MUST have both True and False arrows (even if one points directly to End)
5. Objects inside a Loop or Member Range automatically execute within that scope
6. Arrows cannot cross each other (reorganize canvas layout)

# SECTION 4: VALIDATION RULES

## Built-in Validation Checks

When you click **"Validate"** in the toolbar:

| Check | Error Level | Description |
|-------|------------|-------------|
| Missing ENDFIX | Error | A Member Range block is not properly closed |
| Unreachable objects | Warning | An object has no incoming arrows |
| Dead-end objects | Warning | An object has no outgoing arrows (except End) |
| Invalid member names | Error | A member referenced in a formula doesn't exist |
| Missing RTP values | Warning | An RTP is used but no default is provided |
| Syntax errors | Error | Invalid Essbase syntax in Script blocks |
| Circular references | Error | An arrow creates an infinite loop |

## View Script

Click **"View Script"** to see the compiled Essbase calc script. This is the exact script that Essbase will execute.

**Best Practice:** ALWAYS review the generated script before deploying to production. The graphical designer can sometimes generate inefficient code (e.g., unnecessary nested FIX blocks).

## Interview Questions

### Intermediate
**Q: In the graphical designer, what happens if a Condition block has no False branch connected—**
> A: Validation will show a warning. At compile time, if the condition is FALSE, execution skips to the next connected object after the Condition. If there is no connection, execution may terminate prematurely or produce unexpected results. Always connect both True and False branches — even if the False branch goes directly to End.

### Architect
**Q: Should you use the graphical designer or script mode for production rules—**
> A: Use the graphical designer for **simple to moderate rules** where the visual flow aids maintainability (especially for teams with mixed skill levels). Use script mode for **complex, performance-critical rules** where you need precise control over FIX nesting, SET command placement, and formula ordering. Many architects design in graphical mode initially, then click "View Script" and optimize the generated code manually.
