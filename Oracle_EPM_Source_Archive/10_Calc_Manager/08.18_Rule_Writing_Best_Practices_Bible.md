# SECTION 1: THE 10 COMMANDMENTS OF RULE WRITING

---

## Commandment 1: FIX Tight, FIX Sparse, FIX First

The `FIX` statement is the single most impactful performance tool. Every rule must begin with the tightest possible FIX.

### The Rules:
1. **Always FIX on Sparse dimensions** — Sparse dims define blocks. FIX on sparse = fewer blocks loaded from disk.
2. **Always include Scenario, Version, Year, Entity** — These are almost always sparse. Omitting any of them means Essbase processes ALL members of that dimension.
3. **FIX on Sparse before Dense** — Essbase reads the index file using sparse dim combinations. Dense dims are inside the block already.
4. **Never leave a FIX empty** — An empty FIX processes the entire database.

### Bad vs Good:
```essbase
/* BAD: No FIX — processes EVERYTHING */
"Tax" = "Revenue" * 0.25;

/* BAD: FIX on Dense only — no block filtering */
FIX("Jan")
    "Tax" = "Revenue" * 0.25;
ENDFIX

/* GOOD: Tight FIX on all Sparse dimensions */
FIX("Budget", "Working", "FY24", @RELATIVE("Total_Entity", 0))
    "Tax" = "Revenue" * 0.25;
ENDFIX
```

---

## Commandment 2: Replace IF with FIX Wherever Possible

`FIX` operates at **block level** (fast). `IF` operates at **cell level** (slow).

### Performance Comparison:
| Approach | What Essbase Does | Speed |
|----------|-------------------|-------|
| `FIX("US_Entity")` | Scans index, loads only US blocks | ⚡ Fast |
| `IF(@ISMBR("US_Entity"))` | Loads ALL blocks, opens each one, checks each cell | 🐌 Slow |

### When you MUST use IF (cannot use FIX):
1. Testing a **Dense dimension** member within a block (e.g., `IF(@ISMBR("Jan"))`)
2. Testing a **data value** (e.g., `IF("Revenue" > 0)`)
3. Testing an **account type** (e.g., `IF(@ISACCTYPE("Expense"))`)
4. The condition depends on a **calculation result** computed within the same block

### The Conversion Pattern:
```essbase
/* SLOW: IF on Sparse member */
FIX("Budget", "FY24")
    IF(@ISMBR("US_Entity"))
        "Tax" = "Revenue" * 0.21;
    ELSEIF(@ISMBR("UK_Entity"))
        "Tax" = "Revenue" * 0.20;
    ENDIF
ENDFIX

/* FAST: Separate FIX statements */
FIX("Budget", "FY24", "US_Entity")
    "Tax" = "Revenue" * 0.21;
ENDFIX
FIX("Budget", "FY24", "UK_Entity")
    "Tax" = "Revenue" * 0.20;
ENDFIX
```

## Commandment 3: Protect Every Division

Division by zero or `#Missing` corrupts data silently.

### The Standard Protection Pattern:
```essbase
"Margin_Pct"(
    IF("Revenue" <> 0 AND "Revenue" <> #Missing)
        "Margin_Pct" = ("Revenue" - "COGS") / "Revenue" * 100;
    ELSE
        "Margin_Pct" = #Missing;
    ENDIF
)
```

### Common Trap: `<> 0` vs `<> #Missing`
- `0` is a real number stored in the block
- `#Missing` means the cell is empty (no value)
- You must check for BOTH: `IF(x <> 0 AND x <> #Missing)`

---

## Commandment 4: Use Member Blocks for Conditional Formulas

When using IF/ELSE with a target member, always use the Member Block syntax.

```essbase
/* CORRECT: Member Block — anchors context */
"Tax"(
    IF(@ISACCTYPE("Revenue"))
        "Tax" = "Revenue" * 0.25;
    ELSE
        "Tax" = "Expenses" * 0.15;
    ENDIF
)

/* WRONG: Bare assignment — context may not anchor correctly */
IF(@ISACCTYPE("Revenue"))
    "Tax" = "Revenue" * 0.25;
ELSE
    "Tax" = "Expenses" * 0.15;
ENDIF
```

## Commandment 5: Control Block Creation

Blocks that don't exist cannot be calculated. But creating too many blocks ("Block Explosion") destroys performance.

### Block Creation Rules:

| Method | How | When to Use | Risk |
|--------|-----|-------------|------|
| `SET CREATEBLOCKONEQ ON` | Allows equations on sparse dims to create blocks | When target intersection has no data yet | ⚠️ HIGH — can create millions of empty blocks |
| `DATACOPY` | Physically copies blocks from source to target | Best way to create blocks in a controlled scope | ✅ LOW — only creates blocks where source has data |
| `SET CREATENONMISSINGBLK ON` | Creates blocks only if the formula result is non-#Missing | Safer alternative to CREATEBLOCKONEQ | ⚠️ MEDIUM |

### The DATACOPY Block Creation Trick:
```essbase
/* Step 1: Copy data to create blocks at target intersection */
FIX("Budget", "Working", "FY24")
    DATACOPY "Actual" TO "Budget";
ENDFIX

/* Step 2: Now calculate — blocks exist, formulas can write */
FIX("Budget", "Working", "FY24")
    "Tax" = "Revenue" * 0.25;
ENDFIX
```

### The Anti-Pattern: CREATEBLOCKONEQ Without Scope Control
```essbase
/* DANGEROUS: Creates blocks for EVERY possible sparse intersection */
SET CREATEBLOCKONEQ ON;
"Tax" = "Revenue" * 0.25;  /* No FIX! Block explosion! */

/* SAFE: Scoped CREATEBLOCKONEQ */
SET CREATEBLOCKONEQ ON;
FIX("Budget", "Working", "FY24", @RELATIVE("Total_Entity", 0))
    "Tax" = "Revenue" * 0.25;
ENDFIX
SET CREATEBLOCKONEQ OFF;  /* ALWAYS turn it off immediately after */
```

## Commandment 6: Understand Calculation Order

Essbase processes rules **top-to-bottom, left-to-right** within a block.

### Dense Dimension Calculation Order:
```
Period:  Jan → Feb → Mar → Q1 → Apr → May → Jun → Q2 → ...
Account: Revenue → COGS → Gross_Margin → OpEx → EBIT → Tax → Net_Income
```

### Why This Matters:
If `Net_Income` depends on `Tax`, and `Tax` depends on `EBIT`, your formulas must be ordered:
```essbase
/* CORRECT: Dependencies resolved top-to-bottom */
"EBIT" = "Gross_Margin" - "OpEx";
"Tax" = "EBIT" * 0.25;
"Net_Income" = "EBIT" - "Tax";

/* WRONG: Tax uses old EBIT value */
"Tax" = "EBIT" * 0.25;
"EBIT" = "Gross_Margin" - "OpEx";
"Net_Income" = "EBIT" - "Tax";
```

## Commandment 7: Use UDAs for Dynamic Rules

Hard-coded member names make rules brittle. UDAs make them dynamic.

```essbase
/* BRITTLE: Hard-coded member names */
FIX("Budget", "FY24", "Dept_100", "Dept_200", "Dept_300")
    "Tax" = "Revenue" * 0.25;
ENDFIX

/* DYNAMIC: UDA-based — auto-adapts to new departments */
FIX("Budget", "FY24", @UDA("Entity", "Tax_Applicable"))
    "Tax" = "Revenue" * 0.25;
ENDFIX
```

If a new department (Dept_400) is added and tagged with the "Tax_Applicable" UDA, it automatically enters the calculation scope without editing the rule.

---

## Commandment 8: Aggregate After Calculating, Not Before

### The Order: Clear → Calculate → Aggregate
```essbase
/* Step 1: Clear target data */
FIX("Budget", "Working", "FY24")
    CLEARDATA "Tax";
ENDFIX

/* Step 2: Calculate at Level 0 */
FIX("Budget", "Working", "FY24", @RELATIVE("Total_Entity", 0))
    "Tax" = "Revenue" * 0.25;
ENDFIX

/* Step 3: Aggregate up the hierarchy */
FIX("Budget", "Working", "FY24")
    AGG("Entity");
ENDFIX
```

### Why Not Aggregate First—
If you aggregate before calculating, the new Level 0 values won't be reflected in the upper levels until the next aggregation. Users will see stale totals.

---

## Commandment 9: Minimize Cross-Dimensional References

Each `->` operator is an additional block lookup.

```essbase
/* EXPENSIVE: 3 cross-dim lookups per cell */
"Allocated_Cost" = "Total_IT_Cost" -> "IT_Dept" * ("Revenue" / "Revenue" -> "Total_Company");

/* CHEAPER: Use FIX to pre-scope, reduce to 1 cross-dim */
FIX(@RELATIVE("Total_Entity", 0))
    "Allocated_Cost" = "Total_IT_Cost" -> "IT_Dept" * ("Revenue" / @PARENTVAL("Entity", "Revenue"));
ENDFIX
```

---

## Commandment 10: Always Validate and Test

Before deploying any rule:
1. **Validate** — Click the Validate button in Calc Manager (checks syntax)
2. **View Script** — Click "View Script" to see the compiled Essbase calc script
3. **Run on small scope** — Test with one entity, one period first
4. **Check the log** — Review Job Console for warnings and execution time
5. **Verify data** — Open a form and confirm the numbers are correct

# SECTION 2: EVERY SET COMMAND — EXHAUSTIVE REFERENCE

---

## Data Volume Commands

| Command | Values | Default | What It Does | When to Use |
|---------|--------|---------|-------------|-------------|
| `SET UPDATECALC OFF` | `ON` / `OFF` | `ON` | Disables Intelligent Calculation (forces full calc) | When running a full calc on a fresh dataset; always OFF for batch rules |
| `SET UPDATECALC ON` | `ON` / `OFF` | `ON` | Enables Intelligent Calculation (only calcs "dirty" blocks) | For incremental calculations during data entry |
| `SET CREATEBLOCKONEQ ON` | `ON` / `OFF` | `OFF` | Allows formulas to create new sparse blocks | When target intersection blocks don't exist yet |
| `SET CREATENONMISSINGBLK ON` | `ON` / `OFF` | `OFF` | Creates blocks only if result is non-#Missing | Safer alternative to CREATEBLOCKONEQ |

## Data Handling Commands

| Command | Values | Default | What It Does | When to Use |
|---------|--------|---------|-------------|-------------|
| `SET AGGMISSG ON` | `ON` / `OFF` | `OFF` | Aggregates #Missing values (treats as 0 during rollup) | When you need empty intersections to contribute to parents |
| `SET AGGMISSG OFF` | `ON` / `OFF` | `OFF` | Skips #Missing during aggregation | Default — prevents creation of empty upper-level blocks |
| `SET FRMLBOTTOMUP ON` | `ON` / `OFF` | `OFF` | Evaluates member formulas from bottom of hierarchy upward | When sparse dim member formulas depend on child calculations |
| `SET CLEARUPDATESTATUS AFTER` | `AFTER` / `OFF` | `OFF` | Marks all blocks as "clean" after the calc completes | Production rules that need Intelligent Calc to work properly on the next run |

## Memory Commands (BSO Only — NOT Available in Hybrid)

| Command | Values | Default | What It Does | When to Use |
|---------|--------|---------|-------------|-------------|
| `SET CACHE HIGH` | `HIGH` / `DEFAULT` / `LOW` | `DEFAULT` | Maximizes calculator RAM cache | Complex calcs on large databases |
| `SET CACHE LOW` | `HIGH` / `DEFAULT` / `LOW` | `DEFAULT` | Minimizes calculator RAM cache | When server memory is constrained |
| `SET LOCKBLOCK ON` | `ON` / `OFF` | `OFF` | Locks blocks in memory during calc (prevents disk swapping) | Complex multi-pass calculations |
| `SET LOCKBLOCK OFF` | `ON` / `OFF` | `OFF` | Releases blocks from memory after each formula | Default — saves memory |

## Threading Commands

| Command | Values | Default | What It Does | When to Use |
|---------|--------|---------|-------------|-------------|
| `SET CALCPARALLEL n` | `1` to `max_cores` | `1` | Enables parallel calculation with n threads | Large batch calculations; set to 4-8 for cloud |
| `SET CALCTASKDIMS n` | `1` to `max_dims` | `1` | Number of dimensions to parallelize | Usually paired with CALCPARALLEL; set to 2-3 |

## Logging Commands

| Command | Values | Default | What It Does | When to Use |
|---------|--------|---------|-------------|-------------|
| `SET MSG SUMMARY` | `SUMMARY` / `DETAIL` / `ERROR` / `NONE` | `SUMMARY` | Summary statistics in the log | Production rules |
| `SET MSG DETAIL` | — | — | Line-by-line execution detail in log | Debugging only (generates massive logs) |
| `SET MSG ERROR` | — | — | Only errors in the log | High-frequency rules (minimize log size) |
| `SET NOTICE LOW` | `LOW` / `HIGH` | `HIGH` | Reduces informational messages | Production rules |

## Standard SET Block for Production Rules

```essbase
/* === STANDARD PRODUCTION SETTINGS === */
SET UPDATECALC OFF;
SET AGGMISSG OFF;
SET CREATEBLOCKONEQ OFF;
SET MSG SUMMARY;
SET NOTICE LOW;
SET CALCPARALLEL 4;
SET CALCTASKDIMS 2;
/* =================================== */
```

# SECTION 3: PRODUCTION-READY RULE TEMPLATES

---

## Template 1: Revenue Calculation (Driver-Based)

```essbase
/* Revenue = Units × Price */
SET UPDATECALC OFF;
SET MSG SUMMARY;

FIX("Budget", "Working", &CurrYear, @RELATIVE("Total_Entity", 0), @RELATIVE("Total_Product", 0))
    "Revenue"(
        IF("Units" <> #Missing AND "Price_Per_Unit" <> #Missing)
            "Revenue" = "Units" * "Price_Per_Unit";
        ENDIF
    )
ENDFIX
```

---

## Template 2: Expense Allocation with Offset

```essbase
/* Allocate IT overhead to departments based on Headcount */
SET UPDATECALC OFF;
SET CREATEBLOCKONEQ ON;
SET MSG SUMMARY;

/* Step 1: Clear previous allocation */
FIX("Budget", "Working", &CurrYear, @RELATIVE("Total_Department", 0))
    CLEARDATA "Allocated_IT_Cost";
ENDFIX

/* Step 2: Allocate */
FIX("Budget", "Working", &CurrYear, @RELATIVE("Total_Department", 0))
    "Allocated_IT_Cost"(
        IF("Headcount" <> #Missing AND "Headcount" <> 0 AND "Headcount" -> "Total_Department" <> 0)
            "Allocated_IT_Cost" = "Total_IT_Cost" -> "IT_Dept" * ("Headcount" / "Headcount" -> "Total_Department");
        ENDIF
    )
ENDFIX

SET CREATEBLOCKONEQ OFF;

/* Step 3: Offset (negate source) */
FIX("Budget", "Working", &CurrYear, "IT_Dept")
    "Allocated_IT_Cost" = "Total_IT_Cost" * -1;
ENDFIX
```

## Template 3: Depreciation (Straight-Line)

```essbase
/* Monthly Depreciation = Asset Cost / Useful Life in Months */
SET UPDATECALC OFF;
SET MSG SUMMARY;

FIX("Budget", "Working", &CurrYear, @RELATIVE("Total_Entity", 0), @UDA("Account", "Depreciable_Asset"))
    "Depreciation_Expense"(
        IF("Asset_Cost" <> #Missing AND "Useful_Life_Months" <> #Missing AND "Useful_Life_Months" <> 0)
            "Depreciation_Expense" = "Asset_Cost" / "Useful_Life_Months";
        ELSE
            "Depreciation_Expense" = #Missing;
        ENDIF
    )
ENDFIX
```

## Template 4: Currency Conversion (Manual)

```essbase
/* Convert Local Currency to USD Reporting */
SET UPDATECALC OFF;
SET MSG SUMMARY;

/* P&L accounts: Use Average Rate */
FIX("Budget", "Working", &CurrYear, @RELATIVE("Total_Entity", 0), "USD_Reporting")
    FIX(@UDA("Account", "PL_Account"))
        @CHILDREN("Period")(
            IF("Local" <> #Missing AND "Avg_Rate" -> "FX_Rates" <> #Missing)
                "USD_Reporting" = "Local" * ("Avg_Rate" -> "FX_Rates");
            ENDIF
        )
    ENDFIX

    /* Balance Sheet accounts: Use Ending Rate */
    FIX(@UDA("Account", "BS_Account"))
        @CHILDREN("Period")(
            IF("Local" <> #Missing AND "End_Rate" -> "FX_Rates" <> #Missing)
                "USD_Reporting" = "Local" * ("End_Rate" -> "FX_Rates");
            ENDIF
        )
    ENDFIX
ENDFIX
```

## Template 5: Variance Calculations

```essbase
/* Calculate Actuals vs Budget Variance ($ and %) */
SET UPDATECALC OFF;
SET MSG SUMMARY;

FIX("Actual", "Working", &CurrYear, @RELATIVE("Total_Entity", 0))
    /* Variance $ */
    "Variance_Dollar"(
        IF(@ISACCTYPE("Expense"))
            "Variance_Dollar" = "Budget" -> "Actual" - "Actual";  /* Favorable = positive for expenses */
        ELSE
            "Variance_Dollar" = "Actual" - "Budget" -> "Actual";  /* Favorable = positive for revenue */
        ENDIF
    )

    /* Variance % */
    "Variance_Pct"(
        IF("Budget" -> "Actual" <> 0 AND "Budget" -> "Actual" <> #Missing)
            "Variance_Pct" = "Variance_Dollar" / @ABS("Budget" -> "Actual") * 100;
        ELSE
            "Variance_Pct" = #Missing;
        ENDIF
    )
ENDFIX
```

## Template 6: Rolling Forecast Seed

```essbase
/* Seed rolling forecast: Copy YTD Actuals + remaining months from prior forecast */
SET UPDATECALC OFF;
SET MSG SUMMARY;

/* Step 1: Clear target */
FIX("Forecast", "Working", &CurrYear)
    CLEARBLOCK ALL;
ENDFIX

/* Step 2: Copy YTD Actuals (Jan through current month) */
FIX(@RELATIVE("Total_Entity", 0), &CurrYear)
    DATACOPY "Actual" TO "Forecast";
ENDFIX

/* Step 3: Copy remaining months from prior forecast */
/* (Only if Actuals don't exist for future months) */
FIX("Forecast", "Working", &CurrYear, @RELATIVE("Total_Entity", 0))
    @CHILDREN("Period")(
        IF("Forecast" == #Missing)
            "Forecast" = "Forecast" -> "Prior_Forecast_Version";
        ENDIF
    )
ENDFIX
```

## Template 7: Headcount to Salary Calculation

```essbase
/* Salary = Headcount × Monthly Salary Rate */
SET UPDATECALC OFF;
SET MSG SUMMARY;

FIX("Budget", "Working", &CurrYear, @RELATIVE("Total_Entity", 0))
    "Salary_Expense"(
        IF("Headcount_FTE" <> #Missing AND "Monthly_Salary_Rate" <> #Missing)
            "Salary_Expense" = "Headcount_FTE" * "Monthly_Salary_Rate";
        ENDIF
    )

    /* Benefits = Salary × Benefits Rate */
    "Benefits_Expense"(
        IF("Salary_Expense" <> #Missing AND "Benefits_Rate" <> #Missing AND "Benefits_Rate" <> 0)
            "Benefits_Expense" = "Salary_Expense" * "Benefits_Rate";
        ENDIF
    )

    /* Total Compensation = Salary + Benefits */
    "Total_Compensation" = "Salary_Expense" + "Benefits_Expense";
ENDFIX
```

## Template 8: Cash Flow (Indirect Method)

```essbase
/* Cash from Operations = Net Income + Non-Cash Adjustments */
SET UPDATECALC OFF;
SET MSG SUMMARY;

FIX("Actual", "Working", &CurrYear, @RELATIVE("Total_Entity", 0))
    "Cash_From_Operations" = "Net_Income" + "Depreciation" + "Amortization"
        - "Change_In_AR" - "Change_In_Inventory" + "Change_In_AP";

    "Cash_From_Investing" = "CapEx" * -1 + "Asset_Disposals";

    "Cash_From_Financing" = "Debt_Issued" - "Debt_Repaid" - "Dividends_Paid";

    "Net_Change_In_Cash" = "Cash_From_Operations" + "Cash_From_Investing" + "Cash_From_Financing";

    /* Ending Cash = Beginning Cash + Net Change */
    "Ending_Cash"(
        IF(@ISMBR("Jan"))
            "Ending_Cash" = "Beginning_Cash_Balance" + "Net_Change_In_Cash";
        ELSE
            "Ending_Cash" = @PRIOR("Ending_Cash", 1) + "Net_Change_In_Cash";
        ENDIF
    )
ENDFIX
```

# SECTION 4: ANTI-PATTERNS — WHAT NEVER TO DO

---

| # | Anti-Pattern | Why It's Bad | Fix |
|---|-------------|-------------|-----|
| 1 | No FIX statement | Calculates entire database (all scenarios, years, entities) | Always add FIX with Scenario, Version, Year, Entity |
| 2 | `FIX` on Dense dimension only | Dense dims are inside the block — FIX doesn't filter blocks | FIX on Sparse dims to filter blocks |
| 3 | Nested IF (3+ levels) | Cell-level evaluation × 3 = extremely slow | Convert to multiple FIX statements |
| 4 | `SET CREATEBLOCKONEQ ON` at top, never turned OFF | Every formula in the script creates blocks | Turn OFF immediately after the formula that needs it |
| 5 | `SET MSG DETAIL` in production | Generates GB-sized log files | Use SUMMARY or ERROR in production |
| 6 | Hard-coded member names in FIX | Rule breaks when members are renamed/added | Use `@UDA`, `@RELATIVE`, or Variables |
| 7 | Division without zero-check | `#Missing` or `0` denominator corrupts data | Always protect: `IF(denom <> 0 AND denom <> #Missing)` |
| 8 | Calculating upper-level stored members | Aggregation handles this; manual calc causes double-counting | Only calculate at Level 0, then aggregate |
| 9 | `CALC ALL` in a Planning rule | Calculates the ENTIRE database including all scenarios/years | Never use in Planning — use targeted FIX instead |
| 10 | Not clearing target before DATACOPY | Stale data remains if source has gaps | Always clear target first |
| 11 | Aggregating before calculating | Parents show stale pre-calculation totals | Always: Clear → Calculate → Aggregate |
| 12 | Using `@XREF` inside a tight loop | Each @XREF is a cross-cube lookup (slow) | Cache the value in a variable or use Plan Type Map |
| 13 | Long-running rule on form save | User's browser freezes for minutes | Run heavy rules in background or restructure logic |
| 14 | `CALC DIM` on all dimensions | Unnecessary — only calc dims that changed | Target specific dimensions: `CALC DIM("Account")` |
| 15 | Forgetting `ENDFIX` | Syntax error, but can cause scope leakage if nested FIX | Match every FIX with ENDFIX; use graphical designer for safety |

## Summary

The difference between a 5-minute rule and a 5-hour rule is almost always in **FIX scope**, **IF elimination**, and **block creation control**. Master these three concepts and you can optimize any EPM calculation.

| Priority | Technique | Impact |
|----------|-----------|--------|
| 🥇 | Tight FIX on sparse dimensions | 10x–100x faster |
| 🥈 | Replace IF with additional FIX | 5x–20x faster |
| 🥉 | Control block creation (CREATEBLOCKONEQ) | Prevents block explosion |
| 4 | SET CALCPARALLEL (multi-threading) | 2x–4x faster |
| 5 | Clear → Calculate → Aggregate order | Correct results |
| 6 | Minimize cross-dim references (`->`) | 2x–5x faster per formula |
