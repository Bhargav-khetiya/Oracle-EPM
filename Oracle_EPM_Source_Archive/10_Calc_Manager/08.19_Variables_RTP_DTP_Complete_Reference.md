# 08.19 Variables, RTP, DTP — Complete Reference

> **Module:** 08_Calculation_Manager  
> **Topic:** 19 — Runtime Prompts, Design-Time Prompts, Substitution Variables & Global/Local Variables  
> **Target Audience:** Developer / Architect  

---

## Introduction

Variables in Oracle EPM Calculation Manager are the mechanism for creating **dynamic, reusable, parameterized** business rules. Instead of hard-coding `"FY24"` in a FIX statement, you use a variable that resolves to the correct year at runtime, design time, or from server configuration.

There are **4 types** of variables. Mastering all 4 — and knowing when to use each — is what separates a junior developer from an architect.

---

# PART 1: RUNTIME PROMPTS (RTP)

---

## 1. What is a Runtime Prompt—

An RTP is a pop-up dialog that appears when an **end user** runs a business rule. It collects input from the user (e.g., "Which entity do you want to calculate—) and passes that input into the calc script.

### Where to Create
**Calculation Manager → Variables → New Variable → Type: Runtime Prompt**

---

## 2. RTP Properties — Every Single Field

| Property | Description | Options / Values | Default | Required— |
|----------|-------------|------------------|---------|-----------|
| **Variable Name** | The internal name used in scripts (e.g., `RTP_Entity`) | Alphanumeric, underscores, no spaces | — | ✅ Yes |
| **Prompt Text** | The label the user sees in the pop-up dialog | Free text (e.g., "Select Entity to Calculate") | Variable Name | ✅ Yes |
| **Type** | The data type of the variable | `Member`, `Members` (multi-select), `String`, `Number`, `Date`, `SmartList` | `Member` | ✅ Yes |
| **Dimension** | Which dimension the member selector filters on (only for Member/Members type) | Dropdown of all dimensions | — | ✅ (for Member type) |
| **Default Value** | Pre-populated value when the prompt appears | A member name, string, number, date, or SmartList value | (empty) | ❌ No |
| **Required** | Whether the user must provide a value | `TRUE` / `FALSE` | `TRUE` | ❌ No |
| **Allow Multiple Selections** | Let the user pick multiple members (only for Member type) | `TRUE` / `FALSE` | `FALSE` | ❌ No |
| **Choice List** | Restrict the dropdown to specific members | `None`, `All Members`, `Level 0 Members`, `Custom List`, `@Function` | `None` | ❌ No |
| **Use Member Selector** | Show the full member tree or a simple dropdown | `TRUE` / `FALSE` | `TRUE` | ❌ No |
| **Hidden** | Hide the prompt from the user (used for passing context variables) | `TRUE` / `FALSE` | `FALSE` | ❌ No |
| **Use Global Variable** | Link to a Global Variable for default value | Variable selector | (none) | ❌ No |

---

## 3. RTP Type Deep Dive — All 6 Types

### Type 1: Member (Single Select)
The user selects exactly **one member** from a dimension.

**Properties specific to Member type:**
| Field | Description |
|-------|-------------|
| Dimension | Which dimension to show in the selector |
| Choice List | `None` = show all members; `Level 0` = only leaf members; `Custom` = specific list |
| Use Member Selector | TRUE = tree selector; FALSE = flat dropdown |

**Generated Script:**
```essbase
FIX({RTP_Entity})
    "Tax" = "Revenue" * 0.25;
ENDFIX
```

**Use Case:** "Select the Entity to calculate"

### Type 2: Members (Multi-Select)
The user selects **one or more members** from a dimension.

**Generated Script:**
```essbase
FIX({RTP_Entities})  /* Resolves to: "US", "UK", "Germany" */
    "Tax" = "Revenue" * 0.25;
ENDFIX
```

**Use Case:** "Select which departments to include in the allocation"

### Type 3: String
The user types a free-text string.

**Generated Script:**
```essbase
/* Used in IF conditions or as a label */
IF("{RTP_Comment}" == "Approved")
    /* logic */
ENDIF
```

**Use Case:** "Enter a justification for this budget override"

> **⚠️ Warning:** String RTPs should NOT be used in FIX statements. They are for comments, labels, or Groovy logic — not for Essbase member references.

### Type 4: Number
The user enters a numeric value.

**Generated Script:**
```essbase
FIX("Budget", "Working", {RTP_Entity})
    "Tax" = "Revenue" * {RTP_TaxRate} / 100;
ENDFIX
```

**Use Case:** "Enter the tax rate percentage to apply"

### Type 5: Date
The user selects a date from a calendar picker.

**Generated Script:** Used primarily in Groovy rules for date comparisons.

**Use Case:** "Enter the effective date for the rate change"

### Type 6: SmartList
The user selects from a predefined SmartList dropdown.

**Properties specific to SmartList type:**
| Field | Description |
|-------|-------------|
| SmartList Name | Which SmartList to use as the dropdown source |

**Generated Script:**
```essbase
/* SmartList values resolve to their numeric IDs or labels */
IF({RTP_Status} == 1)  /* 1 = "Approved" in the SmartList */
    /* logic */
ENDIF
```

**Use Case:** "Select the approval status"

---

## 4. Choice List Options — Restricting User Selections

The Choice List property controls what the user can select in the Member RTP dialog.

| Choice List | What It Shows | When to Use |
|------------|---------------|-------------|
| `None` | All members in the dimension (full tree) | When the user needs complete flexibility |
| `All Members` | Same as None | Same |
| `Level 0 Only` | Only leaf-level (input) members | When calculations should only target input data |
| `Level 0 Descendants of` | Level 0 descendants of a specific parent | Restrict to a branch of the hierarchy |
| `Children of` | Immediate children of a specific parent | One level only |
| `Descendants of` | All descendants of a specific parent | Entire sub-branch |
| `IDescendants of` | Descendants + the parent itself | Include parent in the list |
| `Siblings of` | Members sharing the same parent | Peer selection |
| `Custom` | Manually defined list of members | Maximum control over options |
| `@UDA` | Members with a specific UDA | Dynamic — auto-updates when UDAs change |

### Choice List Examples

```
/* Only show level-0 members under "North_America" */
Choice List: Level 0 Descendants of → "North_America"
Result: User sees only: US, Canada, Mexico

/* Only show members tagged with "Active" UDA */
Choice List: @UDA("Entity", "Active")
Result: User sees only active entities
```

## 5. RTP in Forms — Form-Level Prompt Configuration

When a Business Rule with RTPs is attached to a Form:

### Prompt Behavior Options (configured on the Form's Business Rules tab):

| Option | Description |
|--------|-------------|
| **Use Form Context** | Auto-populates the RTP with the form's current POV (e.g., if the form shows Entity=US, the RTP auto-fills with US) |
| **Prompt User** | Shows the standard RTP pop-up dialog |
| **Use Default Value** | Silently uses the variable's default value (no prompt) |
| **Hidden** | Passes a fixed value without showing anything to the user |

### Context Variables (Auto-Populated from Form):

| Variable | What It Returns |
|----------|----------------|
| `{$POV$}` | All dimensions in the form's Point of View |
| `{$ROW$}` | The member(s) on the current row |
| `{$COL$}` | The member(s) on the current column |
| `{$PAGE$}` | The member(s) on the current page axis |

# PART 2: DESIGN-TIME PROMPTS (DTP)

---

## 1. What is a Design-Time Prompt—

A DTP is a pop-up dialog that appears when a **developer** drags a Template into a Business Rule. It collects input from the developer during the design phase to customize the template's code.

**Key Difference from RTP:**
- **RTP:** User sees it when they CLICK "Run Rule"
- **DTP:** Developer sees it when they DRAG a template into a rule

---

## 2. DTP Properties — Every Field

| Property | Description | Options / Values | Default |
|----------|-------------|------------------|---------|
| **Variable Name** | Internal name | Alphanumeric, underscores | — |
| **Prompt Text** | Label shown to the developer | Free text | Variable Name |
| **Type** | Data type | `Member`, `String`, `Number` | `Member` |
| **Dimension** | For Member type — which dimension | Dropdown | — |
| **Default Value** | Pre-populated value | Any valid value | (empty) |

---

## 3. DTP Use Case — Universal Template Example

**Scenario:** You build a single "Calculate Tax" template. Different rules need different tax accounts.

**Template Code with DTP:**
```essbase
/* DTP_TaxAccount is asked when the developer drags this template */
FIX("Budget", "Working", &CurrYear)
    "{DTP_TaxAccount}" = "Revenue" * 0.25;
ENDFIX
```

**When Developer A drags it into the "Finance" rule:**
- DTP pop-up appears: "Enter the tax account:" → Developer types `"Corp_Tax"`
- Generated code: `"Corp_Tax" = "Revenue" * 0.25;`

**When Developer B drags it into the "Workforce" rule:**
- DTP pop-up appears: "Enter the tax account:" → Developer types `"Payroll_Tax"`
- Generated code: `"Payroll_Tax" = "Revenue" * 0.25;`

**Result:** One template, two customized outputs. The template is reusable without editing.

---

## 4. DTP to RTP Chaining (Advanced Architecture)

You can use a DTP value to dynamically configure an RTP.

**Example:** A template creates an RTP whose Choice List depends on what the developer enters as a DTP.

```
DTP: "Enter the parent entity for the user prompt:" → Developer enters "North_America"
Generated RTP: Choice List = @DESCENDANTS("North_America")
```

The end user then sees a prompt filtered to only North American entities. If another developer uses the same template but enters "Europe", the end user sees only European entities.

# PART 3: SUBSTITUTION VARIABLES

---

## 1. What is a Substitution Variable—

A Substitution Variable is a server-level or application-level named constant that resolves to a specific value when a script executes. Unlike RTPs (user input) and DTPs (developer input), Substitution Variables are set by **administrators** and apply globally.

### Where to Create
- **Application → Settings → Variables** (Application-level)
- **EPM Automate:** `setSubstVars` command (for automation)

---

## 2. Substitution Variable Properties

| Property | Description | Options |
|----------|-------------|---------|
| **Name** | Variable name (prefixed with `&` in scripts) | Alphanumeric (e.g., `CurrYear`) |
| **Value** | The resolved value | A member name, number, or string (e.g., `FY24`) |
| **Scope** | Where the variable applies | `Application` (all cubes) or specific Plan Type |

---

## 3. Common Substitution Variables

| Variable | Value | Use Case |
|----------|-------|----------|
| `&CurrYear` | `FY24` | Current planning year |
| `&CurrMonth` | `Mar` | Current month for actuals |
| `&PriorYear` | `FY23` | Prior year for variance calcs |
| `&CurrScenario` | `Budget` | Active planning scenario |
| `&ForecastVersion` | `V3` | Current forecast iteration |
| `&ActualMonth` | `Jun` | Last closed actuals month |
| `&BudgetYear` | `FY25` | Year being budgeted |

### Using in Scripts:
```essbase
FIX(&CurrScenario, "Working", &CurrYear, @RELATIVE("Total_Entity", 0))
    "Tax" = "Revenue" * 0.25;
ENDFIX
```

### Updating via EPM Automate:
```batch
epmautomate login admin password url
epmautomate setSubstVars Plan1 CurrYear=FY25
epmautomate setSubstVars Plan1 CurrMonth=Jul
epmautomate logout
```

# PART 4: GLOBAL AND LOCAL VARIABLES

---

## 1. Global Variables

Defined in Calculation Manager at the **application level**. Accessible by ALL business rules in the application.

| Property | Description |
|----------|-------------|
| **Name** | Variable name |
| **Type** | `Member`, `String`, `Number` |
| **Value** | Default value |
| **Scope** | Entire application |

**Use in Script:** `{GlobalVar_Name}`

### Use Case:
A Global Variable `GV_TaxRate = 0.21` is used across 50 business rules. When the tax law changes, the admin updates ONE variable and all 50 rules automatically use the new rate.

---

## 2. Local Variables

Defined within a **specific Business Rule or Template**. Only accessible within that rule.

| Property | Description |
|----------|-------------|
| **Name** | Variable name |
| **Type** | `Member`, `String`, `Number` |
| **Value** | Assigned within the rule |
| **Scope** | Single rule only |

**Use Case:** A calculation needs a temporary value (e.g., an intermediate tax amount) that shouldn't be exposed to other rules.

---

# PART 5: DECISION MATRIX — WHICH VARIABLE TO USE

| Question | Use This Variable Type |
|----------|----------------------|
| Does the end user need to provide input when running the rule— | **RTP** |
| Does the developer need to customize a template when building a rule— | **DTP** |
| Is the value the same for all users and all rules (e.g., current year)— | **Substitution Variable** |
| Is the value the same across all rules but might change (e.g., tax rate)— | **Global Variable** |
| Is the value used only within a single rule for intermediate calculations— | **Local Variable** |
| Should the value be updated automatically by a scheduled job— | **Substitution Variable** (via EPM Automate) |
| Should the value auto-populate from the form's current context— | **RTP with Form Context** |

## Interview Questions

### Intermediate
**Q: What is the difference between an RTP and a Substitution Variable—**
> A: An RTP prompts the end user for input at rule execution time — the user actively chooses a value. A Substitution Variable is a pre-configured value set by an administrator that resolves silently when the script runs — the user has no interaction with it.

### Architect
**Q: How would you architect a single "Calculate Tax" template that works for US, UK, and India entities — each with different tax rates — without hard-coding any member names—**
> A: Create a Template with two DTPs: `DTP_Entity_UDA` (e.g., "US_Taxable") and `DTP_TaxRate` (e.g., "0.21"). The template uses `FIX(@UDA("Entity", "{DTP_Entity_UDA}"))` and `"Tax" = "Revenue" * {DTP_TaxRate};`. When a developer drags the template into the US rule, they enter "US_Taxable" and "0.21". For UK, "UK_Taxable" and "0.20". For India, "India_Taxable" and "0.30". One template, three customized deployments, zero hard-coded member names.

### Trick Question
**Q: Can an RTP of type "Member" accept a member that doesn't exist in the selected dimension—**
> A: No. The RTP validates the member against the Essbase outline at runtime. If the member doesn't exist (or is misspelled), the rule will fail with a "Member not found" error. This is why it's best practice to use the Member Selector (tree view) instead of free-text entry for Member RTPs.

## Summary

| Variable Type | Set By | When Resolved | Scope | Use In Script |
|--------------|--------|---------------|-------|---------------|
| **RTP** | End User | Rule execution | Single rule run | `{RTP_Name}` |
| **DTP** | Developer | Rule design (drag template) | Template deployment | `{DTP_Name}` |
| **Substitution Variable** | Administrator | Script compilation | Application-wide | `&VarName` |
| **Global Variable** | Developer | Script compilation | All rules | `{GV_Name}` |
| **Local Variable** | Developer | Script execution | Single rule | `{LV_Name}` |
