## 🔬 Script Component — Deep Dive

### Calc Script Syntax (Complete)

```
/* Comments: Single line */
/* Multi-line comments
   span multiple lines */

/* Full calc script structure */
SET UPDATECALC OFF;
SET CREATEBLOCKONEQ ON;
SET AGGMISSG OFF;
SET MSG SUMMARY;

FIX("Budget", "Working", "FY27", @RELATIVE("Entity", 0))
    
    /* Simple assignment */
    "Revenue" = "Units" * "Price";
    
    /* Conditional logic */
    IF("Units" > 0)
        "Revenue" = "Units" * "Price";
    ELSE
        "Revenue" = 0;
    ENDIF
    
    /* Cross-dimensional reference */
    "Revenue" = "Revenue" -> "Actual" -> "Final" -> "FY26" * (1 + "Growth_Rate");
    
ENDFIX

/* Aggregation */
AGG("Entity");
AGG("Account");
```

### @Functions — Complete Reference

#### Member Functions

| Function | Purpose | Example |
|----------|---------|---------|
| `@RELATIVE(dim, level)` | Members at relative level | `@RELATIVE("Entity", 0)` → Level 0 |
| `@CHILDREN(member)` | Direct children | `@CHILDREN("Total_Revenue")` |
| `@ICHILDREN(member)` | Children + itself | `@ICHILDREN("Total_Revenue")` |
| `@DESCENDANTS(member)` | All descendants | `@DESCENDANTS("Entity")` |
| `@IDESCENDANTS(member)` | Descendants + itself | `@IDESCENDANTS("Entity")` |
| `@SIBLINGS(member)` | Same-level members | `@SIBLINGS("Jan")` |
| `@PARENT(member)` | Parent member | `@PARENT("Jan")` → Q1 |
| `@ANCESTORS(member)` | All ancestors | `@ANCESTORS("Mumbai")` |
| `@GEN(dim, gen)` | Members at generation | `@GEN("Entity", 2)` |
| `@LEV(dim, level)` | Members at level | `@LEV("Entity", 0)` |
| `@UDA(dim, tag)` | Members with UDA | `@UDA("Account", "Revenue")` |
| `@ATTRIBUTE(dim, attr, val)` | Members with attribute value | `@ATTRIBUTE("Account", "Type", "Revenue")` |
| `@RANGE(dim, m1, m2)` | Member range | `@RANGE("Period", "Jan", "Jun")` |
| `@LIST(m1, m2, m3)` | Explicit member list | `@LIST("Jan", "Feb", "Mar")` |

#### Math Functions

| Function | Purpose | Example |
|----------|---------|---------|
| `@ABS(x)` | Absolute value | `@ABS("Variance")` |
| `@ROUND(x, n)` | Round to n decimals | `@ROUND("Revenue", 2)` |
| `@MAX(x, y)` | Maximum | `@MAX("Actual", "Budget")` |
| `@MIN(x, y)` | Minimum | `@MIN("Actual", "Budget")` |
| `@MOD(x, y)` | Modulo | `@MOD("Row_Count", 2)` |
| `@INT(x)` | Integer part | `@INT("Monthly_Rate" * 12)` |
| `@AVG(range)` | Average of member range | `@AVG("Period", "Jan", "Dec")` |
| `@SUM(range)` | Sum of member range | `@SUM("Period", "Jan", "Jun")` |
| `@COUNT(range)` | Count of non-missing | `@COUNT("Period", "Jan", "Dec")` |

#### Data Functions

| Function | Purpose | Example |
|----------|---------|---------|
| `@ISMBR(member)` | Check if current is member | `IF(@ISMBR("Revenue"))` |
| `@ISANCEST(member)` | Check if ancestor | `IF(@ISANCEST("Total_Revenue"))` |
| `@ISLEV(dim, n)` | Check if at level n | `IF(@ISLEV("Entity", 0))` |
| `@ISGEN(dim, n)` | Check if at generation n | `IF(@ISGEN("Entity", 2))` |
| `@ISUDA(dim, tag)` | Check if has UDA | `IF(@ISUDA("Account", "Calculated"))` |
| `@PRIOR(member)` | Prior period value | `@PRIOR("Revenue")` → prior month |
| `@NEXT(member)` | Next period value | `@NEXT("Revenue")` |
| `@SHIFT(member, n)` | Shift by n periods | `@SHIFT("Revenue", -3)` → 3 months ago |
| `@CURRMBR(dim)` | Current member in loop | `@CURRMBR("Period")` |
| `@CONCATENATE(s1, s2)` | Combine strings | `@CONCATENATE("FY", "26")` |

### 💡 Logic & Purpose
Data functions like `@PRIOR` and `@NEXT` are the absolute bedrock of balance sheet logic, cash flow generation, and rolling forecasts. They allow the calculation engine to step outside the current cell's intersection and look backward or forward in time to retrieve opening balances or calculate trailing averages without hardcoding months.

### 🌀 Confusion Resolution
> **Misconception:** "I wrote `@PRIOR(Revenue)` in January, but it's returning `#MISSING` instead of pulling December's revenue from the previous year."
> **Reality:** By default, `@PRIOR` only looks backward within the *current* Year block! When it hits January, it looks for the period before January in the current year, finds nothing, and returns `#MISSING`. If you want `@PRIOR` to cross the Year boundary (Jan FY26 → Dec FY25), you MUST use the advanced syntax: `@PRIOR("Revenue", 1, @XRANGE("FY25"->"Jan", "FY26"->"Dec"))`.

### 😈 Twisted Interview Question
**Question:** A developer uses `@ISMBR("Actual")` inside a `FIX("Budget")` block to check if the scenario is actuals. What is wrong with this logic?
> **Answer:** It's mathematically impossible for `@ISMBR("Actual")` to evaluate to True. The `FIX` statement strictly limits the calc scope to the "Budget" scenario. Therefore, the engine will never process an "Actual" cell inside that block. `@ISMBR` should only be used to evaluate members of dimensions that are *not* locked down by the `FIX` statement.

## 📌 Rule Design Patterns — From Oracle Docs

### Pattern 1: Variance Calculation

```
SET CREATEBLOCKONEQ ON;
FIX("Variance", "Working", &CurrentYear, @RELATIVE("Entity", 0))
    FIX(@RANGE("Period", "Jan", &CurrentMonth))
        "Revenue"(
            @RELATIVE("Account", 0)
        ) = "Revenue" -> "Actual" -> "Final" - "Revenue" -> "Budget" -> "Working";
    ENDFIX
ENDFIX
```

### Pattern 2: Year-Over-Year Growth

```
FIX("Budget", "Working", &BudgetYear, @RELATIVE("Entity", 0))
    "Revenue"(
        @RELATIVE("Account", 0)
    ) = "Revenue" -> "Actual" -> "Final" -> &PriorYear * (1 + "Growth_Rate" -> "Saved Assumption");
ENDFIX
```

### Pattern 3: Seasonal Allocation

```
/* Distribute annual total to months based on seasonal weights */
FIX("Budget", "Working", &BudgetYear, @RELATIVE("Entity", 0))
    "Revenue"(
        @RANGE("Period", "Jan", "Dec")
    ) = "Revenue" -> "YearTotal" * "Seasonal_Weight" / "Seasonal_Weight" -> "YearTotal";
ENDFIX
```

### Pattern 4: Cascading Calculation (Waterfall P&L)

```
FIX("Budget", "Working", &BudgetYear, @RELATIVE("Entity", 0))
    /* Step 1: Calculate Gross Revenue */
    "Gross_Revenue" = "Room_Revenue" + "FnB_Revenue" + "Other_Revenue";
    
    /* Step 2: Calculate Net Revenue */
    "Net_Revenue" = "Gross_Revenue" - "Discounts";
    
    /* Step 3: Calculate Gross Profit */
    "Gross_Profit" = "Net_Revenue" - "COGS";
    
    /* Step 4: Calculate EBITDA */
    "EBITDA" = "Gross_Profit" - "Operating_Expenses";
    
    /* Step 5: Calculate Net Income */
    "Net_Income" = "EBITDA" - "Depreciation" - "Interest" - "Tax";
ENDFIX
```

### Pattern 5: Headcount-Based Allocation

```
/* Allocate corporate overhead based on headcount */
FIX("Budget", "Working", &BudgetYear)
    "Corporate_Overhead"(
        @RELATIVE("Entity", 0),
        @RELATIVE("Department", 0)
    ) = "Total_Corporate_Overhead" -> "Corporate" * 
        "Headcount" / "Headcount" -> "Total_Company";
ENDFIX
```

## 🎓 Interview Questions (Oracle Official)

**Q: List 5 @Functions and explain when to use each.**
> @RELATIVE(dim, 0) — get Level 0 members for FIX. @RANGE(Period, m1, m2) — select a period range. @ISMBR(member) — conditional logic per member. @PRIOR(member) — get prior period value. @UDA(dim, tag) — filter by User-Defined Attribute.

**Q: How do you design a Rule Set for a monthly close?**
> Group rules into phases: Prepare (clear/update) → Calculate (revenue, expenses) → Allocate (overhead distribution) → Translate (currency) → Aggregate → Report (variances). Use sequential for dependencies, parallel for independent rules. Share RTPs and enable Stop on Error.

**Q: What is the difference between @CHILDREN and @DESCENDANTS?**
> @CHILDREN returns only direct (immediate) children. @DESCENDANTS returns ALL children at every level below. For a 3-level hierarchy, @CHILDREN("Root") returns Gen 2 only, while @DESCENDANTS("Root") returns Gen 2 AND Gen 3.
