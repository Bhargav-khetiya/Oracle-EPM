# @INTERSECT

## Overview

`@INTERSECT` is a **native Essbase member array function** in Oracle EPM Cloud (PBCS/EPBCS). It acts as a set-theory operator, taking two discrete lists (arrays) of members and returning a new array containing **only the members that exist in BOTH lists**. (This is the mathematical equivalent of a Venn diagram overlap).

### Why Does This Function Exist?

In advanced allocations and targeted data pushes, you frequently need to combine multiple selection criteria. 
For example, you might need to allocate funds to all Cost Centers in the `"North_America"` branch. But you ALSO only want to allocate funds to Cost Centers that are tagged with the `"High_Risk"` UDA. 
If you just fix on `@DESCENDANTS("North_America")`, you hit low-risk centers. If you just fix on `@UDA("Entity", "High_Risk")`, you hit centers in Europe. 
`@INTERSECT` natively bridges these lists. By wrapping both selections in this function (`@INTERSECT(@DESCENDANTS("North_America"), @UDA("Entity", "High_Risk"))`), the Essbase compiler compares the two massive arrays in memory, strips out everything that doesn't overlap, and returns the perfect subset. This ensures hyper-optimized `FIX` statements that only visit the exact blocks required.

### When to Use It

- **Multi-Condition Filtering**: Targeting members that must meet two or more structural criteria simultaneously (e.g., Level 0 AND tagged with a specific attribute).
- **Security / Access Modeling**: Ensuring a dynamic allocation only runs on entities that the current user has access to, by intersecting the "All Entities" list with the user's "Security Access" list.
- **Array Pruning**: Passing a massive list of members returned by a custom Java function and intersecting it with `@LEVEL0` to instantly filter out any accidental parent members from the list.

## Syntax

```essbase
@INTERSECT(list1, list2)
```

---

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `list1` | Member List | ✅ Yes | The first array of members. This is usually generated by a function like `@DESCENDANTS`, `@UDA`, or `@GENMBRS`. |
| `list2` | Member List | ✅ Yes | The second array of members. |

---

## Return Value

**Return Type**: Member List (Array)

Returns a comma-separated array of members.
- **Strict Overlap**: It returns only members that are perfectly identical in both `list1` and `list2`.
- **Empty Intersections**: If the two lists share absolutely zero members (e.g., the intersection of `"North_America"` and `"Europe"`), the function returns an empty set. If this occurs inside a `FIX` statement, the `FIX` silently terminates (which is highly desirable, as it prevents calculating the wrong data).
- **Dimensionality**: Both lists **MUST** contain members from the exact same dimension. You cannot intersect a list of Entities with a list of Accounts. That makes no logical sense and will cause a compilation error.

---

## How It Works (Behind the Scenes)

1. **Parameter Evaluation**: The compiler generates `list1` (e.g., 500 North American entities). It then generates `list2` (e.g., 200 High-Risk entities).
2. **Memory Comparison**: The engine places both arrays in memory and executes a rapid Boolean AND join.
3. **Filtering**: Any member that is in `list1` but not `list2` is discarded. Any member in `list2` but not `list1` is discarded.
4. **Return**: The remaining members (the overlap) are concatenated into a final array and passed back to the `FIX` statement or calculation block.

## Syntax Variants & Scenarios

### Variant 1: UDA and Hierarchy Intersection

```essbase
/* 
   Returns only Level 0 descendants of USA that have the UDA "Taxable".
*/
@INTERSECT(@RELATIVE("USA", 0), @UDA("Entity", "Taxable"))
```

## Practical Examples

### Example 1: Multi-Attribute Filtering in a FIX

**Scenario**: A corporate tax script must allocate an overhead expense. However, it can ONLY allocate to Cost Centers that are both in the `"Sales"` division AND have the attribute `"Store_Format_Large"`. The script uses `@INTERSECT` to combine the structural hierarchy with the attribute dimension query.

```essbase
/* 
   1. list1 = All base stores under the "Sales_Division" parent.
   2. list2 = All entities tagged with the "Store_Format_Large" attribute.
   3. @INTERSECT guarantees we only calculate stores that meet BOTH rules.
*/
FIX("FY25", "Working", @INTERSECT(@RELATIVE("Sales_Division",0), @ATTRIBUTE("Store_Format_Large")))
    
    /* 
       4. Because of the optimized FIX, we do not need IF statements here.
       We can just execute the math directly, saving massive processing time.
    */
    "Allocated_Tax" = "Total_Corporate_Tax"->"No_Entity" * "Square_Footage_Ratio";
    
ENDFIX
```

### Example 2: Chaining Three Lists

**Scenario**: You need to intersect three different criteria: Under `"USA"`, Level 0, AND `UDA "Active"`. Because `@INTERSECT` only accepts two lists, you must nest them.

```essbase
/* 
   Inner Intersect: Gets Active USA members.
   Outer Intersect: Filters that result down to ONLY Level 0 members.
*/
FIX(
    @INTERSECT(
        @LEVEL0("Entity"), 
        @INTERSECT(@DESCENDANTS("USA"), @UDA("Entity", "Active"))
    )
)
    "Forecast" = "Actuals" * 1.05;
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Cross-Dimensional Intersections | `@INTERSECT(@DESC("USA"), @DESC("Revenue"))` | You cannot intersect an Entity with an Account. The lists must be from the exact same dimension. If you need to filter across multiple dimensions, simply put them side-by-side in the `FIX` statement (e.g., `FIX(@DESC("USA"), @DESC("Revenue"))`), which inherently creates a cross-dimensional grid intersection |
| Passing Single Strings | `@INTERSECT("USA", "Canada")` | This function expects arrays (lists) of members. While technically passing two single hardcoded members won't crash, it is useless because `"USA"` and `"Canada"` will never overlap, returning an empty set. If you are trying to combine lists (e.g., "Give me USA AND Canada"), you must use the `MERGE` function, or simply list them out: `"USA", "Canada"` |
| Using it inside IF statements | `IF(@INTERSECT(A, B) == "Store_1")` | This function returns an array of multiple members. You cannot use standard mathematical equality (`==`) to compare an array to a single string inside an `IF` statement. Use it exclusively inside `FIX` blocks or array aggregation functions |
