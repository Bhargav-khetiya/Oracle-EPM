# @CURRMBRRANGE

## Overview

`@CURRMBRRANGE` is a **range generation function** in Oracle EPM Cloud (PBCS/EPBCS) Calc Manager. It generates a dynamic list of members from a specified dimension, starting at a defined point and ending at the member currently being calculated.

### Why Does This Function Exist—

Many financial calculations require a "rolling" or "to-date" window that expands dynamically depending on which period is being calculated.
- **Year-To-Date (YTD)**: If calculating March, you need the range `Jan, Feb, Mar`.
- **Life-To-Date (LTD)**: Summing all capital expenditures since the inception of a project up to the current month.
- **Moving Averages**: Calculating an average over a specific time window that moves along with the current calculation context.

While `@PTD` or `@TODATE` handle standard time rollups, `@CURRMBRRANGE` is highly flexible, allowing you to generate ranges in *any* dimension, starting and stopping based on dynamic offsets.

### When to Use It

- To calculate custom Year-to-Date or Quarter-to-Date aggregates inside a formula.
- To create moving windows for statistical functions like `@STDEV` or `@TREND`.
- To generate a dynamic range inside a cross-dimensional aggregation function like `@SUMRANGE`.

## Category

**Range Generation / Time Series**

## Syntax

```essbase
@CURRMBRRANGE(dimName, genLevNum | genLevName, [startOffset], [endOffset])
```

### Formal Syntax

```
@CURRMBRRANGE(dimensionName, generationOrLevel, [startOffset], [endOffset])
```

Where:
- `dimensionName` — The dimension to generate the range for (usually `"Period"` or `"Years"`).
- `generationOrLevel` — The hierarchy level specifying the boundary of the list (e.g., `LEV, 0` or `"Quarter"`). The range will not cross this boundary (e.g., a YTD range won't cross into the prior year).
- `startOffset` — (Optional) How many positions relative to the current member to start the range. Default is the beginning of the level boundary.
- `endOffset` — (Optional) How many positions relative to the current member to end the range. Default is `0` (the current member).

---

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `dimName` | Dimension | ✅ Yes | The dimension to evaluate. |
| `genLevNum` | Keyword/Int| ✅ Yes | The boundary level. Typically `LEV, 0` for leaf members. |
| `startOffset` | Integer | ❌ No | e.g., `-2` starts 2 periods ago. `0` starts at the current member. If omitted, starts at the first member of the parent boundary (like Jan for a Year). |
| `endOffset` | Integer | ❌ No | e.g., `0` ends at the current member. `+2` ends 2 periods in the future. |

---

## Return Value

**Return Type**: Member Range (a list of members)

Returns a list of members that can be passed into functions like `@SUM`, `@AVG`, or `@SUMRANGE`.

---

## How It Works (Behind the Scenes)

1. **Context Check**: Essbase identifies the current member being calculated (e.g., `"Mar"`).
2. **Boundary Definition**: It looks at the `genLevNum` to determine the sandbox. If computing YTD, the boundary is the Year.
3. **List Construction**: 
   - If offsets are omitted, it lists everything from the start of the boundary up to the current member (e.g., `Jan, Feb, Mar`).
   - If offsets are provided (e.g., start `-2`, end `0`), it builds exactly that relative window (e.g., `Jan, Feb, Mar`).

## Syntax Variants & Scenarios

### Variant 1: Classic Year-To-Date (YTD)

```essbase
/* If current member is Mar, returns (Jan, Feb, Mar) */
@CURRMBRRANGE("Period", LEV, 0)
```

### Variant 2: Trailing 3-Period Window

```essbase
/* Start 2 periods ago, end at current period (Total 3 periods) */
@CURRMBRRANGE("Period", LEV, 0, -2, 0)
```

### Variant 3: Next 3-Period Forecast Window

```essbase
/* Start 1 period from now, end 3 periods from now */
@CURRMBRRANGE("Period", LEV, 0, 1, 3)
```

## Practical Examples

### Example 1: Custom YTD Calculation for a Specific Account

**Scenario**: You want to calculate the YTD sum of `Total_Expenses`, but only write it to a specific statistical metric, rather than using the standard Time dimension rollup logic.

```essbase
FIX("FY25", "Working", @DESCENDANTS("Total Entity"))
    FIX("Jan":"Dec")
        /* The @SUM function iterates over the list generated by @CURRMBRRANGE */
        "YTD_Metric" = @SUM("Total_Expenses", @CURRMBRRANGE("Period", LEV, 0));
    ENDFIX
ENDFIX
```

---

### Example 2: 3-Month Moving Average

**Scenario**: Calculate a 3-month trailing moving average for Sales to smooth out volatility.

```essbase
FIX("FY25", "Working", @DESCENDANTS("Products"))
    FIX("Mar":"Dec")
        /* Average the current month and the two prior months */
        "Moving_Avg_Sales" = @AVG(SKIPNONE, "Sales", @CURRMBRRANGE("Period", LEV, 0, -2, 0));
    ENDFIX
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Crossing year boundaries | `@CURRMBRRANGE` generally respects the outline hierarchy. A trailing 3-month average calculated in Jan will often fail to cross into Dec of the prior year | For true cross-year trailing calculations, use `@XRANGE` combined with `@PRIOR` instead of `@CURRMBRRANGE` |
| Using for assignments | `"YTD" = @CURRMBRRANGE(...)` | A cell holds a single number, not a list of members. You must wrap the range inside an aggregation function like `@SUM` or `@AVG` |
| Missing LEV/GEN keyword | `@CURRMBRRANGE("Period", 0)` is invalid | Always use the keyword `LEV` or `GEN` before the number: `@CURRMBRRANGE("Period", LEV, 0)` |
