# @COMPOUNDGROWTH

## Overview

`@COMPOUNDGROWTH` is a **native Essbase financial function** in Oracle EPM Cloud (PBCS/EPBCS). It calculates the pure **Compound Interest (Growth Amount)** generated from a principal amount over a specified period of time. Unlike `@COMPOUND` (which returns the Total Value: Principal + Interest), `@COMPOUNDGROWTH` strictly isolates and returns ONLY the mathematical growth/interest generated in that specific period.

### Why Does This Function Exist?

When building financial statements, Balance Sheets and Income Statements require different data. 
If you deposit `$100,000` into a treasury account at a `10%` annual rate:
- The **Balance Sheet** needs to know the Total Asset Value at the end of Year 1 (`$110,000`). You use `@COMPOUND` for this.
- The **Income Statement** needs to know the Interest Income earned *during* Year 1 (`$10,000`).
If you only had the `@COMPOUND` function, you would have to manually subtract the prior period's balance from the current period's balance to isolate the interest income. 
`@COMPOUNDGROWTH` automates this extraction. It calculates the full compounding curve under the hood, but explicitly returns only the delta (the growth) for each period, allowing you to instantly map interest income, inflation variance, or compounded liability growth directly to P&L accounts.

### When to Use It

- **Interest Income Projection**: Calculating the exact dollar amount of interest earned each month on a compounding cash reserve to map to the P&L.
- **Inflation Impact Isolation**: Calculating exactly how much *extra* money the company is spending purely due to inflation (excluding the base cost of the goods).
- **Accrued Liability Growth**: Calculating the incremental growth of an unfunded pension liability due to compounding discount rates.

## Syntax

```essbase
@COMPOUNDGROWTH(Principal, Rate, [XrangeList])
```

---

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `Principal` | Numeric / Member | ✅ Yes | The initial starting amount (e.g., `100000` or `"Cash_Reserve"`). |
| `Rate` | Numeric / Member | ✅ Yes | The interest rate per period, expressed as a decimal (e.g., `0.10` for 10%). |
| `XrangeList` | Member Range | ❌ No  | The specific time periods over which to compound. <br>If omitted, Essbase defaults to the `Time` dimension members in the current `FIX`. |

---

## Return Value

**Return Type**: Numeric (Block Vector)

Returns the pure growth amount (Interest Earned) for each period in the range.
- **Output Definition**: In Period 1, it returns $Principal \times Rate$. In Period 2, it returns $(Principal + Period1Growth) \times Rate$.
- **Missing Data**: If the Principal is `#MISSING`, it evaluates as `0`, resulting in a `$0` return.

---

## How It Works (Behind the Scenes)

1. **Parameter Evaluation**: Essbase locks onto the `Principal` value and the `Rate`.
2. **Time Series Traversal**: It identifies the `XrangeList` (e.g., `FY24:FY28`).
3. **Period 1 Calculation**: It calculates the interest for the first period: $Principal \times Rate$.
4. **Compounding Loop**: For Period 2, it adds the Period 1 Interest to the Principal, and multiplies that new total by the Rate to find the Period 2 Interest. 
5. **Data Write**: It returns the array of isolated Interest values into the target member block.

```essbase
/* 
   Calculates the interest generated by a $100,000 principal at a 10% rate.
*/
"Interest_Income" = @COMPOUNDGROWTH(100000, 0.10);
```

## Practical Examples

### Example 1: Modeling Interest Income on a Multi-Year CD

**Scenario**: A corporate treasury department purchases a `$10,000,000` Certificate of Deposit (CD) that pays `5%` annually, compounding yearly. The FP&A team needs to project the "Interest Income" for the Income Statement over the next 4 years.

```essbase
FIX("Working", "Treasury_Dept", "No_Product")
    
    /* 
       1. Calculate the pure Interest Income generated each year.
       - Principal: 10,000,000
       - Rate: 0.05 (5% Annual)
       - Range: FY25 to FY28
    */
    "Interest_Income" = @COMPOUNDGROWTH(10000000, 0.05, "FY25":"FY28");
    
    /*
       Mathematical Results:
       FY25 = $500,000       (10M * 5%)
       FY26 = $525,000       (10.5M * 5%)
       FY27 = $551,250       (11.025M * 5%)
       FY28 = $578,812.50    (11.576M * 5%)
    */
    
ENDFIX
```

### Example 2: Isolating the Cost of Inflation

**Scenario**: A supply chain model calculates the total cost of materials. The `Base_Cost` is `$500,000`. The company expects costs to inflate by `1%` per month. The CFO wants a specific line item on the P&L called `"Inflation_Variance"` that isolates exactly how much *extra* money they are paying purely because of inflation.

```essbase
FIX("FY25", "Working", "Raw_Materials")
    
    FIX(@CHILDREN("YearTotal"))
        
        /* 
           1. Calculate the pure inflationary growth each month.
           We point the Principal at the BegBalance of the Base_Cost.
           Rate is 1% (0.01).
        */
        "Inflation_Variance" = @COMPOUNDGROWTH("Base_Cost"->"BegBalance", 0.01);
        
        /* 
           2. Calculate the Total Cost by combining them.
        */
        "Total_Material_Cost" = "Base_Cost" + "Inflation_Variance";
        
    ENDFIX
    
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Rate vs Percentage | Passing `10` instead of `0.10` | Essbase mathematical functions expect rates to be expressed as pure decimals. If you pass `10` for 10%, Essbase interprets that as `1000%`. Always divide whole percentages by 100 before passing them to the function |
| Mismatched Time Horizons | Applying an Annual rate across Monthly periods | The `Rate` must match the frequency of the `XrangeList`. If your range is `Jan:Dec`, and you pass `0.05` (5% annual), Essbase will compound it by 5% *every single month*. If the range is months, you must divide the annual rate by 12: `@COMPOUNDGROWTH(Principal, (Rate/12), "Jan":"Dec")` |
| Using the Wrong Compound Function | Expecting the Total Balance | If you use `@COMPOUNDGROWTH`, it ONLY returns the interest. The $100,000 Principal is entirely missing from the result. If you are trying to calculate the Ending Balance of a bank account, you must use `@COMPOUND`. Use `GROWTH` only when projecting P&L variances or interest income |
