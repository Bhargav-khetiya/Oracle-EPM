# @DATEDIFF

## Overview

`@DATEDIFF` is a **native Essbase date mathematics function** in Oracle EPM Cloud (PBCS/EPBCS). It calculates the mathematical difference (in days) between two **native Essbase Date Integers** (which represent the number of seconds elapsed since January 1, 1970). 

### Why Does This Function Exist?

When EPM Cloud introduced Calc Manager, they introduced the powerful Java-based `@CalcMgrDaysBetween` and `@CalcMgrMonthsBetween` functions. However, before those existed, Essbase still needed a way to calculate date differences. 
Essbase does not natively understand `YYYYMMDD` integers (like `20240515`). It only natively understands Unix epoch timestamps (the total number of seconds since 1970). If you have two timestamps, you cannot simply subtract them, because subtracting two massive second-counts leaves you with a massive second-count, not a readable number of days.
`@DATEDIFF` takes two Unix epoch timestamps (usually generated by `@TODAY()` or converted via string-parsing), calculates the mathematical difference in seconds, and natively divides the result to return the precise integer number of elapsed days. 

*Note: While `@DATEDIFF` is highly optimized (as it runs in native C-code rather than invoking Java), most modern EPM developers prefer the `@CalcMgr` date functions because they are vastly easier to integrate with standard `YYYYMMDD` inputs. Use this only when working with native Unix timestamp accounts.*

### When to Use It

- **Legacy Unix Math**: Calculating the days elapsed between two Unix timestamps stored in an older Essbase application.
- **High-Performance Day Counts**: Calculating exactly how many days a project has been active without incurring the slight overhead of spinning up the Java JVM for `@CalcMgrDaysBetween`.
- **System Date Offsets**: Comparing a stored project date against `@TODAY()` (which natively returns a Unix timestamp) to see if the project is overdue.

## Syntax

```essbase
@DATEDIFF(date1, date2)
```

---

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `date1` | Numeric | ✅ Yes | The first Unix Epoch timestamp integer (e.g., `1715731200` for May 15, 2024). |
| `date2` | Numeric | ✅ Yes | The second Unix Epoch timestamp integer (e.g., `1716336000` for May 22, 2024). |

---

## Return Value

**Return Type**: Numeric (Integer)

Returns the exact number of days between the two dates.
- **Directionality (CRITICAL)**: This function calculates `date1 - date2`.
  - If `date1` is the NEWER date (e.g., May 22) and `date2` is the OLDER date (e.g., May 15), it returns a **positive** number (e.g., `7`).
  - If `date1` is the OLDER date, it returns a **negative** number (e.g., `-7`).
  - *(This is the exact opposite behavior of most `@CalcMgr` functions, which expect the older date first. Pay strict attention to parameter order).*

---

## How It Works (Behind the Scenes)

1. **Parameter Evaluation**: Essbase evaluates the two input integers (which it assumes represent seconds since Jan 1, 1970).
2. **Delta Calculation**: It performs a standard subtraction: `(date1 - date2)`. The result is the exact delta in seconds.
3. **Division**: It divides the delta by `86400` (the number of seconds in a standard 24-hour day).
4. **Rounding**: It rounds down to the nearest whole integer.
5. **Return**: It returns the final integer back to the calculation block.

## Syntax Variants & Scenarios

### Variant 1: Checking Days Overdue

```essbase
/* 
   Assumes "Target_Date" stores a Unix timestamp.
   @TODAY() generates the current Unix timestamp.
   By putting @TODAY() first, if today is PAST the Target Date, it returns a positive number of days overdue.
*/
VAR vDaysOverdue = @DATEDIFF(@TODAY(), "Target_Date");
```

## Practical Examples

### Example 1: High-Performance Project Aging

**Scenario**: A massive EPM application tracks 500,000 active projects. The `Start_Date` of every project is stored natively as a Unix timestamp to save space. The script must calculate exactly how many days the project has been running. To maximize performance, the administrator avoids Java functions entirely and uses native `@DATEDIFF`.

```essbase
FIX("FY25", "Working", @LEVEL0("Projects"))
    
    IF("Project_Start_Date" != #MISSING)
        
        /* 
           1. Calculate the difference between Today and the Start Date.
           We put @TODAY() (the newer date) first so the result is positive.
           E.g., Today - Jan 1st = 150 days.
        */
        "Total_Days_Active" = @DATEDIFF(@TODAY(), "Project_Start_Date");
        
        /* 
           2. Execute conditional logic based on the aging.
        */
        IF("Total_Days_Active" > 90)
            "Aging_Bucket" = 3; /* Over 90 Days */
        ELSEIF("Total_Days_Active" > 30)
            "Aging_Bucket" = 2; /* 30-90 Days */
        ELSE
            "Aging_Bucket" = 1; /* New Project */
        ENDIF
        
    ENDIF
    
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Passing YYYYMMDD Integers | `@DATEDIFF(20240522, 20240515)` | This is the most catastrophic mistake. `@DATEDIFF` DOES NOT understand `YYYYMMDD`. It assumes the number is seconds since 1970. If you pass `20240522`, Essbase thinks you mean a date in the year 1970. The calculation will output completely nonsensical integers. If your data is `YYYYMMDD`, you MUST use `@CalcMgrDaysBetween` instead |
| Inverting the Order | Passing `(OldDate, NewDate)` | Because this function runs basic `X - Y` math, if you put the Old Date first, it will return a negative number (e.g., `-10`). While mathematically accurate, this often ruins `IF(Days > 5)` logic blocks. Always put the newer date first to get a positive output, or wrap the result in `@ABS()` |
| Leap Second Inaccuracies | Extremely long horizons | This function uses strict 86,400-second division. It does not account for atomic leap seconds introduced by global time standards. While virtually irrelevant for financial models, if you need astronomical precision over a 50-year horizon, use Java Calendar classes |
