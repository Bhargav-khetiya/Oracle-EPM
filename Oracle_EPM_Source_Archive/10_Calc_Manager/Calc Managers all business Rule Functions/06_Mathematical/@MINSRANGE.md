# @MINSRANGE

## Overview

`@MINSRANGE` is a **native Essbase mathematical function** in Oracle EPM Cloud (PBCS/EPBCS). It evaluates a distinct, explicitly provided list of numeric values or cross-dimensional intersections and returns the absolute **lowest numeric value** found within that specific list. 

### Why Does This Function Exist—

The standard `@MIN` function is incredibly powerful, but it requires a structural *Member Range* (e.g., `"Jan":"Dec"` or `@CHILDREN("Vendors")`). If the data points you need to compare are entirely un-related and do not share a parent, `@MIN` cannot be used.
For example, what if you need to calculate an `"Approved_Price"` that must be the absolute *lowest* value among three completely different, disconnected sources: The `"Historical_Average"`, the `"Current_Vendor_Quote"`, and a hardcoded maximum cap of `$500`— 
You cannot use `@MIN` because `$500` is not an outline member, and the accounts are not siblings. You would have to write complex `IF` statements: `IF(A < B AND A < C) Then A`.
`@MINSRANGE` solves this. It accepts a raw, comma-separated list of individual numeric values, hardcoded numbers, formulas, or distinct account intersections. It sweeps through this arbitrary list, compares the math, and returns the lowest number. This completely breaks the requirement that array functions must operate on structural dimension ranges.

### When to Use It

- **Multi-Source Benchmarking**: Finding the lowest metric among multiple distinct cross-dimensional references (e.g., comparing `"Worst_Case_Scenario"`, `"Base_Scenario"`, and `"Prior_Year_Actuals"`).
- **Floor/Ceiling Math (Caps)**: Implementing a "Ceiling" where a calculated value cannot exceed a certain number. E.g., `@MINSRANGE(list, Calculated_Value, 500)` ensures the result never goes above 500.
- **Dynamic Array Injection**: Parsing custom text or numeric lists generated by complex Java CDFs directly into a minimum evaluation.

## Syntax

```essbase
@MINSRANGE(SKIPNONE | SKIPMISSING | SKIPZERO | SKIPBOTH, list_of_values)
```

---

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `Skip_Flag` | Keyword | ❌ No  | Determines how `#MISSING` or `0` values are handled:<br>- `SKIPNONE`: Evaluates everything (default).<br>- `SKIPMISSING`: Ignores `#MISSING` evaluations.<br>- `SKIPZERO`: Ignores evaluations resulting in `0`.<br>- `SKIPBOTH`: Ignores both `#MISSING` and `0`. |
| `list_of_values` | Numeric List| ✅ Yes | A comma-separated list of numeric inputs. These can be hardcoded numbers (`500`), account names (`"Price"`), full cross-dimensional pointers (`"Actual"->"FY23"`), or entire formulas (`"Cost" * 1.05`). |

---

## Return Value

**Return Type**: Numeric (Double)

Returns the absolute lowest number found in the list.
- **Negative Support**: If the list evaluates to `[-5, -10, 50]`, the function returns `-10`.
- **Missing Data Handling**: If every single item in the list evaluates to `#MISSING`, and `SKIPMISSING` is applied, it returns `#MISSING`. If `SKIPNONE` is used, `#MISSING` is evaluated as `0`.

---

## How It Works (Behind the Scenes)

1. **Argument Parsing**: The C-engine reads the `list_of_values` parameter and evaluates every single item separated by commas.
2. **Mathematical Resolution**: If an item is a formula (e.g., `"Cost" * 1.10`), it calculates the formula first and holds the resulting double in memory.
3. **Filtering**: It applies the `Skip_Flag`, deleting any elements from the temporary memory array that match the skip criteria.
4. **Comparison Sweep**: It compares all the remaining doubles in memory against each other.
5. **Return**: It outputs the single lowest numeric value.

## Syntax Variants & Scenarios

### Variant 1: Establishing a Mathematical Ceiling (Cap)

```essbase
/* 
   Calculates a Bonus amount. If the calculated bonus exceeds 10,000, 
   it forces the result to 10,000 (because 10,000 is less than the calculated overage).
*/
"Final_Bonus" = @MINSRANGE(SKIPNONE, ("Sales" * 0.10), 10000);
```

## Practical Examples

### Example 1: Enforcing Conservative Forecasting (Lowest of Three)

**Scenario**: To ensure conservative budgeting, the CFO dictates that the `"Base_Target"` for the upcoming year must be the absolute lowest performance recorded across three different historical metrics: The `"FY23_Actual"`, the `"FY24_Actual"`, or the `"FY24_Forecast"`. Because these are different Scenarios and Years, they cannot be bundled in a simple time-range. The administrator uses `@MINSRANGE`.

```essbase
FIX("FY25", "Working", @LEVEL0("Entity"))
    
    /* 
       1. We use MINSRANGE because we are comparing three distinct, 
       non-contiguous intersections.
       2. We MUST use SKIPMISSING so that if an entity didn't exist in FY23, 
       the missing block doesn't skew the comparison to 0.
    */
    "Base_Target" = @MINSRANGE(SKIPMISSING, 
        "Actual"->"FY23", 
        "Actual"->"FY24", 
        "Forecast"->"FY24"
    );
    
    /* 
       Results:
       If FY23 = 100k, FY24 = 120k, and Forecast = 115k.
       The function evaluates all three, finds the lowest, 
       and writes 100k to Base_Target.
    */
    
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Confusing `SKIPNONE` with Missing Data | `#MISSING` is Zero | This is the deadliest error with `@MINSRANGE`. If you are trying to find the lowest cost among three different options (`[50, 100, #MISSING]`), `SKIPNONE` will evaluate `#MISSING` as `0`, and return `0`. Your budget will be set to $0. You MUST almost always use `SKIPMISSING` or `SKIPBOTH` when comparing values to find a minimum |
| Using `@MINSRANGE` instead of `@MIN` | Poor Performance | If the members you want to evaluate *are* in a contiguous range (e.g., `"Jan":"Dec"`), DO NOT write `@MINSRANGE(SKIPMISSING, "Jan", "Feb", "Mar"...)`. `@MIN` is highly optimized to sweep dimensional arrays infinitely faster than `@MINSRANGE` can parse individual comma-separated strings. Only use `@MINSRANGE` when the inputs are disconnected or require inline math |
| Syntax Errors with Commas | `(A, B)` vs `@LIST(A, B)` | Unlike `@MIN`, `@MINSRANGE` is specifically designed to accept a raw comma-separated list of values directly in the parameter. You do NOT need to wrap the values in an `@LIST` function. Simply separate them with commas |
