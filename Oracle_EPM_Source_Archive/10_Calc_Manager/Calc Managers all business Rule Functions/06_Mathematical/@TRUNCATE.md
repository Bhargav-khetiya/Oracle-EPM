# @TRUNCATE

## Overview

`@TRUNCATE` is a **native Essbase mathematical rounding function** in Oracle EPM Cloud (PBCS/EPBCS). It evaluates a numeric value and completely slices off (truncates) the decimal portion, returning a clean, absolute whole number integer. It does NOT perform standard mathematical rounding (e.g., $10.9$ becomes $10$, not $11$).

### Why Does This Function Exist?

In corporate finance, headcount planning, and supply chain logistics, partial units are often mathematically impossible or legally invalid. 
If an algorithm calculates that a store needs $4.9$ `"Managers"` based on store square footage, the company cannot hire $0.9$ of a person. If you use a standard `@ROUND` function, it rounds $4.9$ up to $5$. But if the budget only allows for fully funded roles, rounding up causes an immediate budget overrun. The company can only afford $4$ managers. 
`@TRUNCATE` solves this by aggressively chopping off the remainder, acting as a strict floor for positive numbers. It forces the mathematical engine to discard fractions and return only the full, complete units that exist in the calculation.

### When to Use It

- **Headcount Planning**: Slicing off fractional employees generated by driver-based allocation formulas to ensure the headcount budget only reflects whole human beings.
- **Unit Manufacturing**: Calculating the exact number of full "Pallets" that can be built from raw materials, where a $0.99$ pallet cannot be shipped.
- **Accrual Indexing**: Converting precise decimal timestamps or date integers into flat period trackers by slicing off the time-of-day fractions.

## Syntax

```essbase
@TRUNCATE(Numeric_Expression)
```

---

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `Numeric_Expression` | Numeric | ✅ Yes | The number, formula, or member reference that you want to truncate (e.g., `10.99` or `"Calculated_Headcount"`). |

---

## Return Value

**Return Type**: Numeric (Double formatted as Integer)

Returns the absolute whole number portion of the input, completely discarding the fractional portion.
- **Positive Behavior**: Truncating `10.1`, `10.5`, and `10.99` all yield exactly `10`. It acts exactly like a mathematical `floor` for positive numbers.
- **Negative Behavior**: Truncating `-10.1`, `-10.5`, and `-10.99` all yield exactly `-10`. It simply removes the decimals. *(Note: This means it acts like a mathematical `ceiling` for negative numbers, pulling them closer to zero, unlike a true floor function which would push them to -11)*.
- **Missing Data**: If the input evaluates to `#MISSING`, the function returns `#MISSING`.

---

## How It Works (Behind the Scenes)

1. **Parameter Resolution**: The C-engine evaluates the mathematical expression to its final double-precision float value (e.g., `1045.789`).
2. **String/Bitwise Cast**: The engine performs an internal cast (similar to `(int)1045.789` in Java/C). 
3. **Decimal Drop**: This cast completely discards the memory bits representing the fractional decimals.
4. **Return**: The clean integer is cast back to a Double (`1045.0`) and returned to the Essbase data block.

### Variant 1: Basic Truncation

```essbase
/* 
   Regardless of how close the value is to the next whole number, 
   the decimal is sliced off. Both return 10.
*/
VAR vA = @TRUNCATE(10.01);
VAR vB = @TRUNCATE(10.99);
```

## Practical Examples

### Example 1: Enforcing Strict Headcount Caps

**Scenario**: A fast-food chain budgets `"Store_Managers"` based on `"Projected_Revenue"`. The formula is `$1,000,000` in revenue equals `1` Manager. If a store projects `$2,950,000`, the raw formula yields `2.95` managers. HR policy strictly dictates that they cannot hire the 3rd manager until the store actually crosses the $3M threshold. The admin uses `@TRUNCATE` to enforce the policy.

```essbase
FIX("FY25", "Working", @LEVEL0("Stores"))
    
    /* 
       1. The raw math evaluates to 2.95.
       2. If we used @ROUND, it would round up to 3 (Violating HR policy).
       3. We use @TRUNCATE to slice off the 0.95.
       4. The store is assigned 2 Managers.
    */
    "Store_Managers" = @TRUNCATE("Projected_Revenue" / 1000000);
    
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Expecting Standard Rounding | "Why didn't 10.9 become 11?" | The entire purpose of this function is to explicitly *prevent* rounding up. It is a guillotine for decimals. If your business logic dictates that $10.5$ or higher should round up to the next integer, you MUST use the `@ROUND` function instead |
| Confusing with `@INT` | Practically Identical | In modern Essbase, `@TRUNCATE(10.5)` and `@INT(10.5)` perform the exact same action (both return 10). They are functionally interchangeable for positive numbers. However, they can behave slightly differently on deeply negative numbers depending on the legacy C-engine patch. `@TRUNCATE` is generally preferred when you want to explicitly signal "chopping" in your code |
| Applying it to Small Decimals | Destroying Precision | Do not use `@TRUNCATE` to clean up floating point errors like `0.00000001`. If a rate account is supposed to hold `0.05` (5%), and you accidentally run `@TRUNCATE("Rate")`, it slices off the `.05` and leaves `0`. Your rate is now 0%, and all downstream multiplication fails. Use `@ROUND("Rate", 2)` to preserve precision |
