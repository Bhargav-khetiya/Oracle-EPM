# @INTEREST

## Overview

`@INTEREST` is a **native Essbase financial function** in Oracle EPM Cloud (PBCS/EPBCS). It calculates the total accumulated interest on a loan or savings balance over a specified range of periods, taking into account the principal balance, the interest rate, and a payment amount (for amortization).

### Why Does This Function Exist?

In corporate finance, calculating the interest expense on debt schedules is mathematically complex because the principal balance changes every period (as payments are made). To manually calculate interest over a 5-year monthly forecast (60 periods), an administrator would have to write a rigid, recursive `CALCMODE(CELL)` loop.
In Period 1, they would calculate `Interest = Principal * Rate`, then calculate the new `Ending Principal = Principal + Interest - Payment`. Then Period 2 would have to reference Period 1's Ending Principal. This is computationally expensive and highly prone to circular reference errors.
`@INTEREST` automates this entirely. It is a vector-based financial function that inherently understands time-series amortization. You pass it the Principal, the Rate, and the Payment, and it recursively iterates across the time range internally, outputting the exact Interest dollar amount for every single period into the database.

### When to Use It

- **Debt Schedules**: Projecting the monthly interest expense on a corporate term loan where fixed monthly payments are amortizing the principal balance over time.
- **Lease Accounting**: Calculating the implied interest portion of monthly capital lease payments.
- **Treasury Forecasting**: Projecting the interest income generated by a cash savings account where the business is making fixed monthly deposits (payments into the account).

## Syntax

```essbase
@INTEREST(Principal, Rate, Payment, [XrangeList])
```

---

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `Principal` | Numeric / Member | ✅ Yes | The initial starting balance of the loan or investment. |
| `Rate` | Numeric / Member | ✅ Yes | The interest rate per period, expressed as a decimal (e.g., `0.05` for 5%). <br>*Crucial: If the periods are Months, this must be a MONTHLY rate, not an Annual rate.* |
| `Payment` | Numeric / Member | ✅ Yes | The fixed payment amount applied every period. <br>*(For a loan, this reduces the principal. For savings, it increases the principal).* |
| `XrangeList` | Member Range | ❌ No  | The specific time periods over which the interest is calculated. If omitted, defaults to the `Time` dimension members in the current `FIX`. |

---

## Return Value

**Return Type**: Numeric (Block Vector)

Returns the calculated **Interest Amount** for each period in the specified time range.
- **Not the Principal**: It strictly returns the isolated interest dollars. If you want to return the remaining principal balance, you must use `@PTD` or `@AMORTIZ`.
- **Directionality**: In standard Essbase financial math, if `Principal` is positive (a loan you owe), the `Payment` should usually be a positive number representing money paid against the loan. Essbase subtracts the payment from the Principal + Interest internally. *(Always test sign behavior in your specific patch, as EPM financial functions are sensitive to signs).*

---

## How It Works (Behind the Scenes)

1. **Parameter Evaluation**: Essbase locks onto the `Principal`, `Rate`, and `Payment` inputs.
2. **Time Series Traversal**: It identifies the `XrangeList` (e.g., `Jan:Dec`).
3. **Period 1 Math**: It calculates `Interest_P1 = Principal * Rate`. It calculates the ending balance: `End_Balance_P1 = Principal + Interest_P1 - Payment`.
4. **Recursive Loop**: For Period 2, it uses `End_Balance_P1` as the new principal. It calculates `Interest_P2 = End_Balance_P1 * Rate`, and so on.
5. **Data Write**: It takes the array of isolated Interest values (`Interest_P1`, `Interest_P2`, etc.) and writes them back into the target account block for each respective month.

## Practical Examples

### Example 1: Full Debt Amortization Schedule

**Scenario**: Corporate Treasury has taken a `"Term_Loan"` of `$5,000,000`. The `"Annual_Rate"` is `6%` (which is `0.5%` monthly). The `"Monthly_Payment"` is fixed at `$50,000`. The script must calculate the `"Interest_Expense"` for the entire 12-month fiscal year.

```essbase
FIX("FY25", "Working", "No_Entity")
    
    /* 
       1. Calculate the Monthly Rate.
       We divide the Annual Rate by 12.
       (e.g., 0.06 / 12 = 0.005)
    */
    VAR vMonthlyRate = "Annual_Rate"->"BegBalance" / 12;
    
    /* 
       2. Use @INTEREST to calculate the expense curve across the year.
       - Principal: "Term_Loan"->"BegBalance"
       - Rate: vMonthlyRate (0.005)
       - Payment: "Monthly_Payment"->"BegBalance"
       - Range: Jan:Dec
    */
    "Interest_Expense" = @INTEREST(
        "Term_Loan"->"BegBalance", 
        vMonthlyRate, 
        "Monthly_Payment"->"BegBalance", 
        "Jan":"Dec"
    );
    
    /* 
       Results:
       Jan Interest = 5,000,000 * 0.005 = 25,000. (End Bal: 4,975,000)
       Feb Interest = 4,975,000 * 0.005 = 24,875. (End Bal: 4,949,875)
       Mar Interest = 4,949,875 * 0.005 = 24,749.
       ...
    */
    
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Mismatched Time Horizons | Passing Annual Rate for Monthly Periods | If your `XrangeList` is `Jan:Dec` (12 monthly periods), you MUST pass a monthly interest rate. If you pass a `6%` (`0.06`) annual rate into a monthly schedule, Essbase assumes the rate is `6%` PER MONTH (which is `72%` annually). Always divide annual rates by 12 before passing them to monthly ranges |
| Moving Base References | Pointing `Principal` to the current period | `Principal` should point to a static starting balance (like `"BegBalance"` or `"Prior_Year_End"`). If you point `Principal` to `"Current_Month_Balance"`, Essbase will try to calculate the interest off the current month, while simultaneously trying to calculate the current month off the interest, creating a circular `#MISSING` loop. Always anchor the principal |
| Rate vs Percentage | Passing `5` instead of `0.05` | EPM financial functions expect rates as decimals. `5` means 500% interest per period. Always divide whole percentages by 100 |
