# @ISMBR

## Overview

`@ISMBR` is a **logical evaluation function** in Oracle EPM Cloud (PBCS/EPBCS) Calc Manager. It evaluates whether the member currently being calculated matches a specified member or belongs to a specified list of members. It returns a Boolean value (`TRUE` or `FALSE`).

### Why Does This Function Exist—

While `FIX` statements restrict calculations at a macro level (the block level), there are many scenarios where you need cell-level conditional logic:
- Executing a different tax rate depending on which entity is currently calculating.
- Applying a calculation only to Level-0 members within a broader `FIX` that includes parents.
- Branching logic based on whether a member belongs to a specific subset of products.

`@ISMBR` is the primary way to ask Essbase: *"Am I currently calculating X—*

### When to Use It

- Inside `IF` statements to route conditional logic based on the current member context.
- When applying logic to specific members within a broad `FIX` block.
- When you need to check if the current member belongs to a dynamic list (e.g., `@CHILDREN("Parent")`).

---

## Category

**Logical / Boolean / Member Selection**

---

## Syntax

```essbase
@ISMBR(mbrName | rangeList)
```

### Formal Syntax

```
@ISMBR(memberExpression | rangeListExpression)
```

Where:
- `memberExpression` — A specific member name (e.g., `"New_York"`).
- `rangeListExpression` — A list of members generated by a function (e.g., `@CHILDREN("East_Region")`, `@UDA("Entity", "Active")`).

---

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `mbrName` | Member/List| ✅ Yes | The member, comma-separated list of members, or member set function to test the current context against. |

---

## Return Value

**Return Type**: Boolean (Returns `1` for TRUE, `0` for FALSE in standard Essbase terms).

| Condition | Returns |
|-----------|---------|
| Current member exactly matches `mbrName` | `TRUE` |
| Current member is found inside `rangeList` | `TRUE` |
| Current member does not match or is not in list | `FALSE` |

---

## How It Works (Behind the Scenes)

1. **Context Check**: During a calculation, Essbase evaluates cells one by one. `@ISMBR` checks the specific coordinate of the cell currently being calculated.
2. **Evaluation**: It compares the current member of the relevant dimension against the argument provided to `@ISMBR`.
3. **Implicit vs Explicit**: You do not have to tell `@ISMBR` which dimension to check. If you pass `@ISMBR("Jan")`, Essbase knows "Jan" belongs to the Time dimension and automatically checks the current Time member.

---

## Syntax Variants & Scenarios

### Variant 1: Single Member Check

```essbase
IF(@ISMBR("Actual"))
    /* Do something only for Actuals */
ENDIF
```

### Variant 2: Multiple Member Check (Comma Separated)

```essbase
IF(@ISMBR("Jan", "Feb", "Mar"))
    /* Do something only in Q1 */
ENDIF
```

### Variant 3: Range List Check

```essbase
IF(@ISMBR(@LEVEL0("Entity")))
    /* Do something only for base-level entities */
ENDIF
```

## Practical Examples

### Example 1: Differentiated Tax Rates

**Scenario**: You are calculating tax expense. Most regions have a 20% rate, but North America has a 25% rate.

```essbase
FIX("FY25", "Working", @DESCENDANTS("Global_Entities"))
    IF("PreTax_Income" > 0)
        /* Check if the current entity is anywhere under North_America */
        IF(@ISMBR(@DESCENDANTS("North_America")))
            "Tax_Expense" = "PreTax_Income" * 0.25;
        ELSE
            "Tax_Expense" = "PreTax_Income" * 0.20;
        ENDIF
    ENDIF
ENDFIX
```

---

### Example 2: Preventing Division by Zero on Parents

**Scenario**: You are calculating an average selling price (ASP), but you only want this to calculate at Level 0, allowing natural aggregation to roll up the parents (or because the parent calculation requires a different formula).

```essbase
FIX("FY25", "Working", @DESCENDANTS("Total Product"))
    /* Ensure we are only calculating at the lowest level */
    IF(@ISMBR(@LEVEL0("Product")))
        IF("Units" > 0)
            "ASP" = "Revenue" / "Units";
        ENDIF
    ENDIF
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Overusing `@ISMBR` instead of `FIX` | Writing a massive calculation where every line is wrapped in `IF(@ISMBR("Jan"))` is terribly inefficient | Use `FIX("Jan")` around the block. Only use `@ISMBR` when logic must branch *within* the block |
| Comparing against variables | `@ISMBR(vMyVar)` usually fails if the variable is numeric or a string | Use `@ISMBR(@MEMBER(vMyVar))` if the variable is a string holding a member name |
| Cross-Dimensional Checks | `@ISMBR("Actual"->"Jan")` is invalid. You cannot pass a cross-dimensional tuple into `@ISMBR` | Use `IF(@ISMBR("Actual") AND @ISMBR("Jan"))` |
