# @CalcMgrStringsToString

## Overview

`@CalcMgrStringsToString` is a **custom Calc Manager array processing function** in Oracle EPM Cloud (PBCS/EPBCS). It acts as a massive array compiler. It takes a **Java String Array** (a list of independent text items) and stitches them all back together into a **single, concatenated text string**, while automatically applying custom prefixes, suffixes, wrapper quotes, and delimiters to every item.

### Why Does This Function Exist—

When processing multi-select runtime prompts or flat-file loads, administrators often use `@CalcMgrSplit` to tear a comma-delimited string (e.g., `"101,102,103"`) into a Java String Array (`[101] [102] [103]`). 
However, you cannot pass a Java Array into an Essbase `FIX` statement or a MaxL script. It must be converted back into a single Essbase-readable string. If the outline expects Department members to be wrapped in quotes and prefixed with `"Dept_"` (e.g., `"Dept_101","Dept_102","Dept_103"`), achieving this using standard `@CONCATENATE` logic inside a custom loop is an absolute nightmare.
`@CalcMgrStringsToString` resolves this in a single line. You hand it the raw array, tell it to wrap every item in quotes (`"`), prepend `"Dept_"` to every item, and stitch the entire array back together using commas (`,`). The Java engine processes the entire array instantly, handing you a perfectly formatted Essbase list string ready for cross-dimensional calculation.

### When to Use It

- **Dynamic FIX Statements**: Converting a user's messy multi-select prompt into a perfectly formatted Essbase string so it can be passed dynamically into a data clear block.
- **MaxL Script Generation**: Taking an array of validated export filenames, wrapping them in single quotes, and joining them with spaces to pass as arguments to a command-line script.
- **SQL IN Clauses**: Converting an array of product IDs into a `('ID1', 'ID2', 'ID3')` format required for a SQL database query.

## Syntax

```essbase
@CalcMgrStringsToString(string_array, delimiter, quote_char, prefix, suffix)
```

---

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `string_array` | Array | ✅ Yes | The Java String Array containing the list of items (usually generated by `@CalcMgrSplit`). |
| `delimiter` | String | ✅ Yes | The character used to stitch the items back together (e.g., `","` for a comma-separated list). |
| `quote_char` | String | ✅ Yes | The character used to wrap *every* item (e.g., `"\""` for double quotes, or `"'"` for single quotes). Pass `""` if you don't want wrapping quotes. |
| `prefix` | String | ✅ Yes | The text to prepend inside the quote of every item (e.g., `"Dept_"`). Pass `""` if no prefix is needed. |
| `suffix` | String | ✅ Yes | The text to append inside the quote of every item (e.g., `"_Final"`). Pass `""` if no suffix is needed. |

---

## Return Value

**Return Type**: String

Returns a single, massive text string representing the compiled array.
- E.g., If Array = `[10] [20]`, Delimiter = `,`, Quote = `"`, Prefix = `D_`, Suffix = `_X`.
- The result is the literal string: `"D_10_X","D_20_X"`.

---

## How It Works (Behind the Scenes)

1. **Parameter Ingestion**: The Java engine receives the Array and formatting tokens.
2. **Loop Iteration**: It spins up a fast `StringBuilder` and loops through the array.
3. **Item Construction**: For each item, it constructs: `Quote` + `Prefix` + `ItemText` + `Suffix` + `Quote`.
4. **Delimiting**: It appends the `delimiter` between each constructed item (ensuring no trailing delimiter at the very end).
5. **Return**: It collapses the builder into a final string and passes it back to Essbase.

## Syntax Variants & Scenarios

### Variant 1: Basic Re-Stitching (No Quotes or Prefixes)

```essbase
/* 
   Assumes vArray = [Apples] [Oranges] [Bananas].
   Simply stitches them together with hyphens.
   Result: "Apples-Oranges-Bananas"
*/
VAR vString = @CalcMgrStringsToString(vArray, "-", "", "", "");
```

## Practical Examples

### Example 1: Formatting a User Prompt for a Dynamic FIX Statement

**Scenario**: A user selects multiple Target Departments in a runtime prompt. EPM passes them as a comma-separated string (`"101,102,103"`). To use this in an Essbase script dynamically, they must be formatted into exactly `"Dept_101","Dept_102","Dept_103"`. The script shreds the prompt, uses this function to recompile it perfectly, and uses the result.

```essbase
FIX("FY25", "Working", "No_Entity")
    
    /* 
       1. Shred the user prompt into a Java String Array.
       Array Result: [101] [102] [103]
    */
    VAR vDeptArray = @CalcMgrSplit({Target_Departments}, ",");
    
    /* 
       2. Use the StringsToString array macro to process the entire array.
       - Delimiter: ","
       - Quote: "\"" (Requires escaping the backslash in Essbase)
       - Prefix: "Dept_"
       - Suffix: "" (None)
    */
    VAR vFinalEssbaseList = @CalcMgrStringsToString(vDeptArray, ",", "\"", "Dept_", "");
    
    /* 
       Resulting String: "Dept_101","Dept_102","Dept_103" 
    */
    
    /* 
       3. Log the safe string for debugging.
    */
    VAR vLog = @CalcMgrLogStrings("Formatted List: ", vFinalEssbaseList);
    
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Passing a String instead of an Array | `@CalcMgrStringsToString("101,102", ...)` | The first parameter MUST be a Java String Array. You cannot pass a normal text string into this function. You must run the string through `@CalcMgrSplit` to convert it into an Array first, and then pass the Array variable into this function |
| Syntax Errors with Quotes | Passing `"""` | If you want to wrap your items in double quotes, you cannot just pass a double quote inside double quotes. Essbase will think you are prematurely ending the string and will fail to compile. You must escape the quote character using a backslash: `"\""` |
| Forgetting Empty Strings | `@CalcMgrStringsToString(Arr, ",")` | This function strictly requires all 5 parameters. If you don't need a Prefix, Suffix, or Quote, you cannot just leave them blank or omit the commas. You MUST explicitly pass empty strings (`""`) to satisfy the Java method signature |
