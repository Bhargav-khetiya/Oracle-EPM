# @CalcMgrDaysBetween

## Overview

`@CalcMgrDaysBetween` is a **custom Calc Manager date function** in Oracle EPM Cloud (PBCS/EPBCS). It calculates the mathematical difference, strictly in days, between two internal Java `Date` objects.

### Why Does This Function Exist?

There are two dominant date paradigms in Calc Manager:
1. **The Integer Paradigm**: Dates stored as `20241231`. To find the difference between two integers, you use `@CalcMgrDateDiff` or `@CalcMgrDaysDiff`.
2. **The Java Object Paradigm**: Dates generated dynamically in memory via `@CalcMgrGetCurrentDate()` or converted from text strings. 

If you have two Java Date objects sitting in memory (for instance, you just pulled two timestamps from a string attribute and converted them), you do not want to go through the painful process of converting them back into integers just to find the difference between them. 
`@CalcMgrDaysBetween` is natively built to accept Java Date objects directly. It executes lightning-fast chronological math to tell you exactly how many calendar days separate the two objects.

### When to Use It

- When calculating the difference between dynamically generated Java Dates without converting them back to Essbase integers.
- To determine the number of days elapsed since a specific Text Attribute timestamp.
- When generating complex SLA (Service Level Agreement) compliance metrics entirely inside memory variables.

## Syntax

```essbase
@CalcMgrDaysBetween(fromDate, toDate)
```

### Formal Syntax

```
@CalcMgrDaysBetween(javaDateExpression1, javaDateExpression2)
```

Where:
- `javaDateExpression1` — The starting Java Date object.
- `javaDateExpression2` — The ending Java Date object.

---

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `fromDate`| Java Date | ✅ Yes | The starting date object. Often generated by a previous `@CalcMgr` conversion function. |
| `toDate`  | Java Date | ✅ Yes | The ending date object. If this date is *before* the `fromDate`, the function will return a negative number. |

---

## Return Value

**Return Type**: Numeric (double-precision floating point)

Returns a numeric value representing the exact number of elapsed days between the two dates.
- If `toDate` is later than `fromDate`, the result is positive.
- If `toDate` is earlier than `fromDate`, the result is negative.
- If the dates are identical, the result is `0`.
*(Note: Despite calculating "days", the internal Java math operates on milliseconds. Because of daylight saving time shifts or precise hour discrepancies, the function occasionally returns a float like `5.999`. It is highly recommended to wrap this function in `@TRUNC` or `@ROUND` to ensure a clean integer).*

---

## How It Works (Behind the Scenes)

1. **Extraction**: The function receives both serialized Java Date objects (which actually represent milliseconds since the Unix epoch of Jan 1, 1970).
2. **Millisecond Math**: It performs a rapid subtraction: `(toDate_Milliseconds - fromDate_Milliseconds)`.
3. **Conversion to Days**: It divides the resulting millisecond difference by `86,400,000` (the number of milliseconds in a standard 24-hour day).
4. **Return**: It returns the resulting numeric value back to the Essbase engine.

## Practical Examples

### Example 1: Calculating Days Outstanding from a String Attribute

**Scenario**: A working capital model tracks open invoices. The invoice date is imported from the ERP as a literal text attribute (`"yyyy-MM-dd"`). You need to calculate how many days the invoice has been outstanding relative to the exact moment the script is run.

```essbase
FIX("FY25", "Actual", @LEVEL0("Invoice"))
    
    /* 1. Extract the raw string date from the cube attribute */
    VAR vInvoiceStr = @ATTRIBUTESVAL("Invoice_Date_Text");
    
    /* 2. Get the exact current system date as a Java Date object */
    VAR vTodayJava = @CalcMgrGetCurrentDate();
    
    /* 3. Ensure the invoice string exists */
    IF(vInvoiceStr != "")
        
        /* 4. Convert the string into a Java Date object */
        VAR vInvoiceJava = @CalcMgrConvertDateToJavaDate(vInvoiceStr, "yyyy-MM-dd");
        
        /* 5. Calculate the difference in days directly from the two Java objects.
           We use @ROUND to ensure daylight saving time millisecond shifts 
           don't leave us with 45.999 days instead of 46. */
           
        "Days_Outstanding" = @ROUND(@CalcMgrDaysBetween(vInvoiceJava, vTodayJava), 0);
        
    ENDIF
    
ENDFIX
```

---

### Example 2: Checking if a dynamically shifted date falls out of bounds

**Scenario**: You add 3 months to a project's start date in memory. You want to know exactly how many days are in that specific 3-month gap (since months have different lengths) so you can prorate a daily cost model.

```essbase
FIX("FY25", "Working", @LEVEL0("Project"))
    
    /* 1. Get the start date (Assume we converted it to Java Date 'vStartJava') */
    
    /* 2. Add exactly 3 months to it in memory */
    VAR vShiftedJava = @CalcMgrAddDatePart(vStartJava, 3, "month");
    
    /* 3. Find the exact number of days between the original and shifted date */
    "Proration_Days" = @ROUND(@CalcMgrDaysBetween(vStartJava, vShiftedJava), 0);
    
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Passing Essbase Integers | `@CalcMgrDaysBetween(20240101, 20241231)` | This function strictly expects Java Date objects. If you pass an Essbase `YYYYMMDD` integer, the function will fail. If you have integers, use `@CalcMgrDaysDiff` instead |
| Floating Point Imprecision | `Days_Between` evaluates to `14.9583` | Because Java Dates track time down to the millisecond, if one date was created at 12:00 PM, and the other at 1:00 PM, the math will yield a fractional day. **Always** wrap this function in `@ROUND(..., 0)` or `@TRUNC(...)` to ensure you get a clean whole day |
| Reversing the order | Putting the newer date first | `DaysBetween(Dec 31, Jan 1)` will yield a negative number (`-364`). Always put the older/starting date in parameter 1, and the newer/target date in parameter 2 |
