# @CalcMgrExcelMIRR

## Overview

`@CalcMgrExcelMIRR` is a **custom Calc Manager financial math function** in Oracle EPM Cloud (PBCS/EPBCS). It perfectly replicates the behavior of the Microsoft Excel `MIRR` function directly inside an Essbase calculation script. 
It calculates the **Modified Internal Rate of Return** for a series of periodic cash flows.

### Why Does This Function Exist?

Standard Internal Rate of Return (`IRR`) has a massive mathematical flaw: it assumes that all positive cash flows generated by a project are perfectly reinvested *at that exact same IRR rate*. If a highly lucrative project has a calculated IRR of 45%, standard IRR assumes you are taking all the profits from Year 1 and reinvesting them somewhere else that also yields 45%. In reality, you are likely putting those profits into a standard corporate bank account yielding 3%.
Because of this flaw, standard IRR often radically overstates the profitability of a project. **MIRR** fixes this by requiring two distinct interest rates:
1. **Finance Rate**: The cost of borrowing the initial investment money.
2. **Reinvestment Rate**: The realistic rate of return you earn when you reinvest the project's positive cash flows.
Calculating MIRR manually in Essbase requires isolating all negative cash flows, discounting them back to Year 0, isolating all positive cash flows, compounding them forward to the final year, and calculating the growth rate between those two massive sums. `@CalcMgrExcelMIRR` offloads this entire complex, array-splitting algorithm to the Java engine, returning the highly realistic Modified IRR instantly.

### When to Use It

- **CapEx Planning**: Providing a realistic, conservative return metric to the CFO when evaluating massive capital projects (instead of the overly optimistic standard IRR).
- **Private Equity**: Evaluating the true yield of an acquired company where the cost of leverage (debt) is significantly different from the expected cash-sweep reinvestment yield.
- Whenever you need to migrate an Excel spreadsheet containing the `MIRR` function directly into an Essbase calculation.

## Syntax

```essbase
@CalcMgrExcelMIRR(cashflows, finance_rate, reinvestment_rate)
```

*(Note: The parameters map 1-to-1 with the Excel function).*

---

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `cashflows` | Array/List | ✅ Yes | An array of cash flows (both positive and negative). Usually passed as a cross-dimensional range like `"Net_Cash_Flow"->@CHILDREN("All_Years")`. |
| `finance_rate`| Numeric | ✅ Yes | The interest rate you pay on the money borrowed to fund the negative cash flows (e.g., `0.05` for a 5% corporate loan). |
| `reinvest_rate`| Numeric | ✅ Yes | The interest rate you receive on the positive cash flows as you reinvest them (e.g., `0.03` for a 3% money market account). |

---

## Return Value

**Return Type**: Numeric (double-precision floating point)

Returns the Modified Internal Rate of Return as a decimal.
- E.g., `0.115` implies an 11.5% modified rate of return.
- If the array does not contain at least one positive and one negative number, it returns `#MISSING`.

---

## How It Works (Behind the Scenes)

1. **Parameter Validation**: The Java engine ingests the array and the two rates. It checks to ensure the array contains both signs (investment and return).
2. **Negative Discounting (PV)**: It isolates all negative numbers in the array. It calculates the Present Value of those negative numbers by discounting them back to Period 0 using the `finance_rate`.
3. **Positive Compounding (FV)**: It isolates all positive numbers. It calculates the Future Value of those numbers by compounding them forward to the final period using the `reinvest_rate`.
4. **Rate Calculation**: It calculates the geometric growth rate between the PV of costs and the FV of returns: `(FV / -PV) ^ (1 / (n - 1)) - 1`.
5. **Return**: Passes the final decimal rate back to Essbase.

## Practical Examples

### Example 1: Reality-Checking High-Yield Projects

**Scenario**: A software company is evaluating two projects. Project A has massive upfront costs but massive immediate returns. Project B has steady costs and steady returns. The standard IRR for Project A is 60%. The CFO knows this is unrealistic because they can't reinvest the profits at 60%—they can only reinvest at 4% (their standard treasury yield). They calculate both IRR and MIRR side-by-side to highlight the reality.

```essbase
FIX("FY25", "Working", @LEVEL0("Projects"))
    
    /* Calculate Standard IRR (Dangerously Optimistic) */
    "Standard_IRR" = @CalcMgrExcelIRR(
        "Net_Project_Cash_Flow"->@CHILDREN("Total_Project_Lifespan"), 
        0.1
    );
    
    /* Calculate Modified IRR (Realistic) */
    /* Assumes 6% cost of borrowing, 4% reinvestment yield */
    "Modified_IRR" = @CalcMgrExcelMIRR(
        "Net_Project_Cash_Flow"->@CHILDREN("Total_Project_Lifespan"), 
        0.06, 
        0.04
    );
    
    /* 
       If Standard IRR is 60%, but Modified IRR drops below the 15% hurdle rate, 
       flag the project for executive review.
    */
    IF("Standard_IRR" > 0.20 AND "Modified_IRR" < 0.15)
        "Review_Flag" = 1; 
    ENDIF
    
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Missing Negative Cash Flows | Array only contains positive profits | Like standard IRR, MIRR fundamentally requires an initial investment (cash *leaving* your pocket). If the array only contains positive numbers, the math is undefined, and the Java engine will fail |
| Array Ordering | Mixing up the Time dimension order | The MIRR algorithm compounds positive cash flows forward to the *end* of the array. If your `@CHILDREN` array is in reverse chronological order, the compounding math will be entirely backward. Always ensure your Time arrays pull sequentially from oldest to newest |
| Whole Number Rates | Passing `5` instead of `0.05` | The `finance_rate` and `reinvest_rate` explicitly expect decimals. If you pass `5`, the engine calculates a 500% compounding interest rate, destroying the calculation |
