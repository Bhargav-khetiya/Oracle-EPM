# @CalcMgrExcelYIELD

## Overview

`@CalcMgrExcelYIELD` is a **custom Calc Manager financial math function** in Oracle EPM Cloud (PBCS/EPBCS). It perfectly replicates the behavior of the Microsoft Excel `YIELD` function directly inside an Essbase calculation script. 
It calculates the **Yield to Maturity (YTM)** for a standard coupon-bearing bond based on its current market purchase price.

### Why Does This Function Exist—

When a company buys a 10-year bond in the secondary market, they almost never pay the exact face value ($100). If the bond pays a 5% coupon, but market interest rates have risen to 7%, the bond will be sold at a deep discount (e.g., $85). 
To determine if this $85 bond is actually a good investment, the Treasury department must reverse-engineer the *true* Yield to Maturity. This requires calculating exactly how many coupon payments remain, stripping out accrued interest, and running a complex recursive guess-and-check (Newton-Raphson) algorithm to find the exact discount rate that makes the present value of all those future coupons perfectly equal the $85 purchase price.
`@CalcMgrExcelYIELD` entirely offloads this massive iterative algorithm and calendar math to the Java engine. It ensures your EPM treasury dashboards report true, annualized portfolio yields that match legacy Excel and Bloomberg models flawlessly.

### When to Use It

- **Portfolio Performance Analysis**: Calculating the true return generated by existing bond holdings based on the historical cash price paid, rather than the stated coupon.
- **Fixed Income Strategy**: Reverse-engineering a broker's quoted return to verify it matches the mathematical reality of the cash price they are demanding.
- Whenever you need to migrate an Excel spreadsheet containing the `YIELD` function directly into an Essbase calculation.

## Syntax

```essbase
@CalcMgrExcelYIELD(settlement, maturity, rate, pr, redemption, frequency, basis)
```

*(Note: The parameters map 1-to-1 with the Excel function).*

---

## Parameters

All date parameters must be passed as `YYYYMMDD` integers, not Java Date objects.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `settlement` | Integer | ✅ Yes | The settlement date (`YYYYMMDD`). The date the bond is purchased. |
| `maturity` | Integer | ✅ Yes | The maturity date (`YYYYMMDD`). The date the bond expires. Must be > `settlement`. |
| `rate` | Numeric | ✅ Yes | The bond's stated annual coupon interest rate (e.g., `0.05` for 5%). |
| `pr` | Numeric | ✅ Yes | The clean price of the bond per $100 of face value (e.g., `85.50`). Must be > 0. |
| `redemption` | Numeric | ✅ Yes | The redemption value per $100 face value. (Almost always `100`). |
| `frequency` | Numeric | ✅ Yes | The number of coupon payments per year: Annual = `1`, Semi-annual = `2`, Quarterly = `4`. |
| `basis` | Numeric | ✅ Yes | The day count basis. `0` = US (NASD) 30/360, `1` = Actual/Actual, `2` = Actual/360, `3` = Actual/365, `4` = European 30/360. |

---

## Return Value

**Return Type**: Numeric (double-precision floating point)

Returns the Yield to Maturity as an annualized decimal.
- E.g., Returns `0.072` (representing a 7.2% true yield).

---

## How It Works (Behind the Scenes)

1. **Parameter Validation**: The Java engine ensures dates are valid integers, `pr` > 0, and the settlement date is chronologically before the maturity date.
2. **Accrued Interest Check**: It calculates if there is any accrued interest based on the calendar basis that must be stripped out of the yield calculation.
3. **Iterative Algorithm**: It executes a recursive algorithm, testing discount rates until the present value of the `redemption` + all remaining coupons (based on the `frequency`) perfectly equals the `pr` (purchase price).
4. **Return**: Passes the finalized yield decimal back to Essbase.

## Syntax Variants & Scenarios

### Variant 1: Valuing a Standard Corporate Bond

```essbase
/* 
   Settlement: Jan 1, 2024
   Maturity: Dec 31, 2028 (5 Years)
   Coupon: 5% (0.05)
   Price: 85.00 -> Price is lower than 100, so Yield will be HIGHER than coupon.
   Redemption: 100
   Freq: 2 (Semi-Annual)
   Basis: 0 (US 30/360)
   Result: ~ 0.088 (8.8% Yield)
*/
"True_Bond_Yield" = @CalcMgrExcelYIELD(20240101, 20281231, 0.05, 85, 100, 2, 0);
```

## Practical Examples

### Example 1: Reporting Portfolio Performance

**Scenario**: A corporate treasury dashboard lists its corporate bond holdings. They know exactly how much they paid for each bond (`"Purchase_Price_Per_100"`). The CFO wants a report showing the true annualized yield generated by these investments to evaluate the Treasury Manager's performance against the corporate hurdle rate of 6.0%.

```essbase
FIX("FY25", "Working", @LEVEL0("Debt_Investments"))
    
    IF("Purchase_Price_Per_100" > 0 AND "Purchase_Date" != #MISSING)
        
        /* 1. Calculate the true Yield to Maturity */
        "Calculated_True_Yield" = @CalcMgrExcelYIELD(
            "Purchase_Date", 
            "Maturity_Date", 
            "Coupon_Rate",
            "Purchase_Price_Per_100",
            100, /* Standard Redemption */
            "Payment_Frequency",
            0    /* Assuming US 30/360 */
        );
        
        /* 2. Flag under-performing investments */
        IF("Calculated_True_Yield" < "Corporate_Hurdle_Rate")
            "Under_Performance_Flag" = 1;
        ELSE
            "Under_Performance_Flag" = 0;
        ENDIF
        
    ENDIF
    
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Total Value Instead of Price | Passing `$10,000,000` | The `pr` parameter strictly expects the clean price *per $100 of face value* (e.g., `85.00`). If you pass the total cash value of your trade (`8,500,000`), the recursive algorithm will attempt to find a yield that justifies paying 8.5 million dollars for a bond that only returns $100 at maturity. It will fail or return `NaN` |
| Whole Number Rates | Passing `5` for Coupon | The `rate` parameter expects a decimal. If the coupon is 5%, you must pass `0.05`. Passing `5` will cause the formula to assume the bond pays 500% interest, returning a massively incorrect yield |
| Using for T-Bills | Using `YIELD` for a 90-day T-Bill | This function is strictly for bonds that pay periodic interest coupons (like corporate bonds). T-Bills are discounted securities and do not pay coupons. If you try to use `YIELD` on a T-Bill, it will fail. Use `@CalcMgrExcelTBILLYIELD` or `@CalcMgrExcelYIELDDISC` instead |
