# @CalcMgrExcelYIELDDISC

## Overview

`@CalcMgrExcelYIELDDISC` is a **custom Calc Manager financial math function** in Oracle EPM Cloud (PBCS/EPBCS). It perfectly replicates the behavior of the Microsoft Excel `YIELDDISC` function directly inside an Essbase calculation script. 
It calculates the **Annual Yield** of a discounted security (like a zero-coupon bond or commercial paper) based on its current market purchase price.

### Why Does This Function Exist—

Unlike standard corporate bonds that pay periodic interest coupons (`@CalcMgrExcelYIELD`), discounted securities pay absolutely no interest during their lifespan. They are sold at a deep discount (e.g., $95) and mature at their full face value ($100). 
When a corporate treasury buys commercial paper on the secondary market for $96.50, they need to know the *true annualized yield* they are earning to compare it against their corporate hurdle rate.
Calculating this manually requires calculating the exact number of days between settlement and maturity, determining the specific calendar basis (e.g., Actual/360), and running an inverse pricing fraction: `((Redemption - Price) / Price) * (YearBase / Days)`. 
`@CalcMgrExcelYIELDDISC` offloads this exact calculation and all calendar math to the Java engine. It returns the exact annualized yield instantly, ensuring your EPM models align perfectly with legacy Treasury Excel dashboards.

### When to Use It

- **Portfolio Performance**: Calculating the true return of zero-coupon bonds or short-term commercial paper based on historical purchase prices.
- **Yield Validation**: Verifying that a broker's quoted return matches the mathematical reality of the cash price they are demanding for a discount note.
- Whenever you need to migrate an Excel spreadsheet containing the `YIELDDISC` function directly into an Essbase calculation.

## Syntax

```essbase
@CalcMgrExcelYIELDDISC(settlement, maturity, pr, redemption, basis)
```

*(Note: The parameters map 1-to-1 with the Excel function).*

---

## Parameters

All date parameters must be passed as `YYYYMMDD` integers, not Java Date objects.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `settlement` | Integer | ✅ Yes | The settlement date (`YYYYMMDD`). The date the security is purchased. |
| `maturity` | Integer | ✅ Yes | The maturity date (`YYYYMMDD`). The date the security expires. Must be > `settlement`. |
| `pr` | Numeric | ✅ Yes | The price of the security per $100 of face value (e.g., `96.50`). Must be > 0. |
| `redemption` | Numeric | ✅ Yes | The redemption value per $100 face value. (Almost always `100`). |
| `basis` | Numeric | ✅ Yes | The day count basis. `0` = US (NASD) 30/360, `1` = Actual/Actual, `2` = Actual/360, `3` = Actual/365, `4` = European 30/360. |

---

## Return Value

**Return Type**: Numeric (double-precision floating point)

Returns the exact Annualized Yield as a decimal.
- E.g., Returns `0.065` (representing a 6.5% true yield).

---

## How It Works (Behind the Scenes)

1. **Parameter Validation**: The Java engine ensures dates are valid integers, `pr` > 0, and the settlement date is chronologically before the maturity date.
2. **Day-Count Math**: It calculates the exact number of days remaining (`DSM`) between the settlement and maturity dates using the specified calendar `basis`.
3. **Inverse Equation**: It executes the standard Treasury yield algorithm: `((redemption - pr) / pr) * (Year_Basis / DSM)`.
4. **Return**: Passes the finalized yield decimal back to Essbase.

## Syntax Variants & Scenarios

### Variant 1: Valuing Commercial Paper (Actual/360)

```essbase
/* 
   Settlement: Jan 1, 2024
   Maturity: Jun 30, 2024 (181 days remaining)
   Price: 96.50
   Redemption: 100
   Basis: 2 (Actual/360)
   Result: Calculates the true Yield. Returns ~ 0.0721 (7.21%)
*/
"Commercial_Paper_Yield" = @CalcMgrExcelYIELDDISC(20240101, 20240630, 96.50, 100, 2);
```

## Practical Examples

### Example 1: Reporting Portfolio Performance

**Scenario**: A corporate treasury dashboard lists its commercial paper holdings. They know exactly how much they paid for each note (`"Purchase_Price_Per_100"`). The CFO wants a report showing the true annualized yield generated by these investments to evaluate them against a corporate benchmark.

```essbase
FIX("FY25", "Working", @LEVEL0("Short_Term_Notes"))
    
    IF("Purchase_Price_Per_100" > 0 AND "Purchase_Date" != #MISSING)
        
        /* 1. Calculate the true Yield */
        "Calculated_True_Yield" = @CalcMgrExcelYIELDDISC(
            "Purchase_Date", 
            "Maturity_Date", 
            "Purchase_Price_Per_100",
            100, /* Standard Redemption */
            2    /* Actual/360 Basis */
        );
        
        /* 2. Flag under-performing investments */
        IF("Calculated_True_Yield" < "Corporate_Hurdle_Rate")
            "Under_Performance_Flag" = 1;
        ELSE
            "Under_Performance_Flag" = 0;
        ENDIF
        
    ENDIF
    
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Using for Coupon Bonds | Valuing a 10-year Treasury Note | `YIELDDISC` is exclusively for zero-coupon, discounted securities. If the security pays periodic interest coupons along the way, this function will completely ignore them and massively understate the yield. You must use `@CalcMgrExcelYIELD` instead |
| Total Value Instead of Price | Passing `$10,000,000` | The `pr` parameter strictly expects the clean price *per $100 of face value* (e.g., `96.50`). If you pass the total cash value of your trade (`9,650,000`), the function's internal algebra `(redemption - pr)` will become massively negative, and the function will fail |
| Whole Number Output | Expecting `5` instead of `0.05` | `YIELDDISC` strictly returns a decimal. If you want to display this on a report as `5.00%`, you must format the reporting cell as a percentage, or multiply the output by 100 within Essbase |
