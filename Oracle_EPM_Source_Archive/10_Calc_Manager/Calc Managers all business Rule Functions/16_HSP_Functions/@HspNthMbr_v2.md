# @HspNthMbr

## Overview

`@HspNthMbr` is a **Hyperion Planning (HSP) custom array extraction function** embedded within Oracle EPM Cloud (PBCS/EPBCS). It takes a list of members (or a relational list definition) and an integer index, and returns the **exact text string name of the member sitting at that specific position** in the list.

### Why Does This Function Exist—

When executing advanced cross-dimensional modeling or dynamic tiering, a script often generates or retrieves an array of data, such as a list of 10 priority products (`"Prod_A, Prod_B, Prod_C..."`). 
If the administrator needs to explicitly target the *first* product on that list to receive an allocation, they cannot use standard math. They need to extract the member name sitting at Index 1. 
`@HspNthMbr` acts as the extractor. You feed it the massive text array and tell it to look at position `1`. It natively parses the array, bypasses all the commas, isolates `"Prod_A"`, and returns that exact text string. This allows Essbase to perform complex, array-based parallel processing, mimicking the behavior of arrays in traditional programming languages like Python or JavaScript.

### When to Use It

- **Parallel Array Mapping**: Extracting the 3rd member from Array A, so you can execute logic against the 3rd member from Array B.
- **Tiered Selections**: Pulling the absolute #1 highest priority entity from a pre-sorted relational string list (e.g., retrieving Index 1).
- **Iterative Processing**: Nesting the function inside a `LOOP` where the loop counter (`1, 2, 3...`) is passed as the index, allowing the script to systematically pop members out of a list and calculate them one by one.

## Syntax

```essbase
@HspNthMbr(Index_Integer, "List_Name" | "Member1, Member2, ...")
```

---

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `Index_Integer` | Numeric | ✅ Yes | The mathematical position of the member you want to extract. (e.g., `1` for the first member, `3` for the third). |
| `List_Definition` | String | ✅ Yes | The array or comma-separated string of members. Can be a hardcoded string (`"Prod_A, Prod_B"`) or a dynamic variable generated by `@HspMbrList`. |

---

## Return Value

**Return Type**: String

Returns the exact text string name of the member residing at the requested position.
- **1-Indexed**: The first item in the list is `1`. Essbase arrays are rarely 0-indexed. 
- **Out of Bounds**: If you ask for Index `10`, but the list only has `3` items, the function will return an empty string `""` (or `#MISSING` depending on the environment patch). Always ensure your index requests are bounded by the total size of the list.
- **Storage Limitation**: Because the function returns a text string, it CANNOT be saved into a standard numeric account. It MUST be assigned to a `VAR` string variable.

---

## How It Works (Behind the Scenes)

1. **Parameter Ingestion**: The engine evaluates the target integer and the list definition.
2. **Parsing**: It parses the text list into an internal memory array, splitting it strictly by commas.
3. **Array Navigation**: It jumps directly to the specified index position in the memory array.
4. **Extraction**: It extracts the characters residing at that position.
5. **Return**: It passes that extracted text string back to the calculation block.

## Practical Examples

### Example 1: Systematic Array Iteration using a Loop

**Scenario**: An administrator has a variable containing a list of 5 high-risk Cost Centers (`"CC_100, CC_105, CC_201..."`). They need to apply a `$10,000` penalty strictly to those 5 Cost Centers. Instead of writing 5 `IF` statements, they use a `LOOP` set to 5. On every cycle of the loop, the loop counter increments, and `@HspNthMbr` extracts the next Cost Center in line, allowing `@MEMBER` to push the penalty amount.

```essbase
FIX("FY25", "Working", "No_Product")
    
    /* 1. Define the List */
    VAR vRiskList = "CC_100, CC_105, CC_201, CC_300, CC_405";
    
    /* 2. Establish a Loop Counter variable starting at 1 */
    VAR vLoopCounter = 1;
    
    /* 3. Execute the Loop exactly 5 times */
    LOOP(5)
        
        /* 
           4. Extract the Cost Center at the current Loop Counter position.
           Loop 1 extracts "CC_100". Loop 2 extracts "CC_105", etc.
        */
        VAR vTargetCCStr = @HspNthMbr(vLoopCounter, vRiskList);
        
        /* 
           5. Push the $10,000 penalty. 
           We use @MEMBER to convert the extracted string back into a real block target.
        */
        @MEMBER(vTargetCCStr)->"Penalty_Expense" = 10000;
        
        /* 
           6. Increment the loop counter manually so the next loop grabs the next item.
        */
        vLoopCounter = vLoopCounter + 1;
        
    ENDLOOP
    
ENDFIX
```

## Common Mistakes & Gotchas

| Mistake | Explanation | Fix |
|---------|-------------|-----|
| Attempting to Save to an Account | `"My_Target" = @HspNthMbr(...)` | **Essbase Data Cells CANNOT store text strings.** They only store numbers. If you try to assign the extracted string `"CC_100"` to a standard member, the block will reject it, writing `#MISSING`. The string must be kept in a `VAR` memory variable or wrapped in `@MEMBER()` to assign data to it |
| Array Out of Bounds Errors | Looping past the end of the list | In Example 1, we hardcoded the loop to `5` because we knew the list had 5 items. If we looped `10` times, loops 6 through 10 would ask `@HspNthMbr` for items that don't exist, causing blank string returns or fatal script crashes. If your list is dynamic, you MUST use a counting function to calculate the length of the list before initiating the loop limit |
| Passing Member Objects | `@HspNthMbr(2, @CHILDREN("Q1"))` | Native Essbase array generators (like `@CHILDREN`) return a native multidimensional object set, not a comma-separated text string. You cannot pipe standard Essbase relative functions directly into the second parameter of `@HspNthMbr`. It expects a literal string list |
