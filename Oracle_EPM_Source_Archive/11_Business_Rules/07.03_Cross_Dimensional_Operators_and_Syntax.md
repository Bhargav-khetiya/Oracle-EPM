# 07.03 — Cross-Dimensional Operators and Syntax: Complete Guide

> **Module:** 07_Business_Rules | **Topic:** Cross-Dim Operators, Member References, Syntax
> **Audience:** Service Administrator / Consultant

---

## 1. WHY — What Real-World Problem Does This Solve?

**The problem:** In a normal formula, `"Total" = "A" + "B"` assumes A and B are in the **same block** (same sparse member intersection). But what if you need Mumbai's Bonus to be based on Corporate's Salary? Or Budget to be Actual × 1.05? You need to reach **across** dimensions — from one block to another.

**The solution:** Cross-Dimensional Operators (`->`) let you reference data in a different member of any dimension within a formula.

---

## 2. WHAT — The Cross-Dimensional Operator

### Basic Syntax

```essbase
"Target" = "Source" -> "MemberName";

/* Read as: Target = Source "at" MemberName */
/* "->" means "look in the block for MemberName" */
```

### Simple Example

```essbase
/* Hotel Pvt Ltd: Copy Actual revenue to Budget as starting point */
"Budget" = "Revenue" -> "Actual";

/* Read as: Budget Revenue = Revenue value at Actual scenario */
/* This reaches from the Budget block to the Actual block */
```

---

## 3. ALL CROSS-DIMENSIONAL PATTERNS

### Pattern 1: Cross Scenario

```essbase
/* Budget = Actual × growth rate */
FIX("Budget", "Working", &CurrYear)
  FIX(@RELATIVE("All_Hotels", 0))
    "Total_Revenue" = "Total_Revenue" -> "Actual" * 1.05;
  ENDFIX
ENDFIX

/* Budget Revenue = Actual Revenue × 105% */
```

### Pattern 2: Cross Entity

```essbase
/* Each hotel's bonus based on Corporate headquarters salary */
FIX("Budget", "Working", &CurrYear)
  FIX(@RELATIVE("All_Hotels", 0))
    "Bonus_Allocation" = "Total_Salary" -> "Corporate_HQ" * 0.02;
  ENDFIX
ENDFIX

/* ⚠️ WARNING: Cross-dim on sparse Entity forces Top-Down calculation */
/* Better approach: Use two-pass pattern (see Section 6) */
```

### Pattern 3: Cross Year (Prior Year Reference)

```essbase
/* YoY variance = This Year - Prior Year */
FIX("Actual", "Final", "FY2026")
  FIX(@RELATIVE("All_Hotels", 0))
    "YoY_Variance" = "Revenue" - "Revenue" -> "FY2025";
    IF("Revenue" -> "FY2025" <> 0)
      "YoY_Variance_Pct" = "YoY_Variance" / "Revenue" -> "FY2025" * 100;
    ENDIF
  ENDFIX
ENDFIX
```

### Pattern 4: Cross Period

```essbase
/* Month-over-month change */
FIX("Actual", "Final", &CurrYear)
  FIX(@RELATIVE("All_Hotels", 0))
    "MoM_Change" = "Revenue" - "Revenue" -> @PRIOR("Period");
  ENDFIX
ENDFIX

/* @PRIOR returns the previous member in the hierarchy */
/* Jan → (no prior), Feb → Jan, Mar → Feb, etc. */
```

### Pattern 5: Cross Account

```essbase
/* Profit Margin = Net Income / Revenue */
FIX("Budget", "Working", &CurrYear)
  FIX(@RELATIVE("All_Hotels", 0))
    IF("Total_Revenue" <> 0)
      "Profit_Margin" = "Net_Income" / "Total_Revenue" * 100;
    ENDIF
  ENDFIX
ENDFIX

/* Note: If Account is Dense, this is NOT a cross-dim — it's within-block */
/* Cross-dim only applies when referencing different SPARSE members */
```

### Pattern 6: Multi-Dimension Cross Reference

```essbase
/* Budget FY2026 = Actual FY2025 × growth × inflation */
FIX("Budget", "Working", "FY2026")
  FIX(@RELATIVE("All_Hotels", 0))
    "Revenue" = "Revenue" -> "Actual" -> "FY2025" * 1.05;
  ENDFIX
ENDFIX

/* Chains cross-dim operators: reach to Actual AND FY2025 */
```

## 4. SYNTAX REFERENCE

### Operators

| Operator | Name | Description |
|----------|------|-------------|
| `->` | Cross-Dim | Reference data at a different member |
| `=>` | Implied Cross-Dim | Same as `->` (legacy syntax) |
| `@MEMBER()` | Dynamic Member Ref | Construct member name dynamically |
| `@CONCATENATE()` | String Builder | Build member names from pieces |

### Member Functions Used with Cross-Dim

| Function | Description | Example |
|----------|-------------|---------|
| `@PRIOR(dim)` | Previous member in hierarchy | `"Revenue" -> @PRIOR("Period")` |
| `@NEXT(dim)` | Next member in hierarchy | `"Revenue" -> @NEXT("Period")` |
| `@PARENT(dim)` | Parent member | `"Revenue" -> @PARENT("Entity")` |
| `@CURRMBRRANGE()` | Current member range | Loop reference |
| `@MEMBER()` | Dynamic member reference | `"Revenue" -> @MEMBER(@CONCATENATE("FY", "2025"))` |

## 5. PERFORMANCE IMPACT

```
WITHIN-BLOCK (Dense members):
  "Total" = "A" + "B";
  Account A and B are in the same block (Dense dim)
  → FAST: No cross-block I/O

CROSS-BLOCK on Dense:
  "Revenue" -> "Q1_Total"  (Period is Dense)
  → Still within the same block — Dense-to-Dense
  → FAST: No additional I/O

CROSS-BLOCK on Sparse:
  "Revenue" -> "Corporate_HQ"  (Entity is Sparse)
  → Different block! Must read Corporate_HQ's block
  → If inside a loop: N reads × N blocks = SLOW
  → May trigger Top-Down calculation

MULTI-CROSS on Sparse:
  "Revenue" -> "Actual" -> "FY2025" -> "Corporate"
  → 3 sparse crosses = VERY SLOW
  → Avoid at all costs
```

## 6. SAFE ALTERNATIVES TO CROSS-DIM

### Alternative 1: Two-Pass Pattern

```essbase
/* Instead of: "Bonus" = "Salary" -> "Corporate_HQ" * 0.02; */

/* Step 1: Store Corporate salary in a temporary member */
FIX("Corporate_HQ", "Budget", "Working", &CurrYear)
  "Temp_Corp_Salary" = "Total_Salary";
ENDFIX

/* Step 2: Use the temp member (no cross-dim needed) */
FIX(@RELATIVE("All_Hotels", 0), "Budget", "Working", &CurrYear)
  "Bonus_Allocation" = "Temp_Corp_Salary" * 0.02;
ENDFIX
```

### Alternative 2: DATACOPY Instead of Cross-Dim

```essbase
/* Instead of: "Budget" = "Revenue" -> "Actual" * 1.05; */

/* Step 1: Copy Actual to Budget */
DATACOPY "Actual" TO "Budget";

/* Step 2: Apply growth factor */
FIX("Budget", "Working", &CurrYear)
  "Revenue" = "Revenue" * 1.05;
ENDFIX
```

### Alternative 3: Smart Push (No Calc Script)

```
For cross-CUBE references:
  Instead of XREF/cross-dim to another cube
  → Use Data Map + Smart Push to bring data into the same cube
  → Then reference locally (no cross-dim needed)
```

## 7. SHOW ME — Hotel Pvt Ltd Cross-Dim Examples

```essbase
/* ====== Example 1: Seed Budget from Actual ====== */
FIX("Budget", "Working", "FY2026")
  FIX(@RELATIVE("All_Hotels", 0))
    /* Revenue grows 5% over prior year actual */
    "Room_Revenue" = "Room_Revenue" -> "Actual" -> "FY2025" * 1.05;
    "F&B_Revenue" = "F&B_Revenue" -> "Actual" -> "FY2025" * 1.08;
    "Spa_Revenue" = "Spa_Revenue" -> "Actual" -> "FY2025" * 1.10;
  ENDFIX
ENDFIX

/* ====== Example 2: YoY Variance ====== */
FIX("Actual", "Final", "FY2026")
  FIX(@RELATIVE("All_Hotels", 0))
    "YoY_Revenue_Change" = "Total_Revenue" - "Total_Revenue" -> "FY2025";
    IF("Total_Revenue" -> "FY2025" <> 0)
      "YoY_Revenue_Pct" = "YoY_Revenue_Change" / 
                           "Total_Revenue" -> "FY2025" * 100;
    ELSE
      "YoY_Revenue_Pct" = 0;
    ENDIF
  ENDFIX
ENDFIX

/* ====== Example 3: Corporate Allocation ====== */
/* SAFE pattern — avoids cross-dim on sparse Entity */
VAR v_TotalCorpCost;

/* Pass 1: Get corporate overhead total */
FIX("Corporate_HQ", "Budget", "Working", &CurrYear, "YearTotal")
  v_TotalCorpCost = "Total_Corporate_Overhead";
ENDFIX

/* Pass 2: Allocate to each hotel based on their revenue share */
FIX(@RELATIVE("All_Hotels", 0), "Budget", "Working", &CurrYear)
  IF("Total_Revenue" -> "All_Hotels" <> 0)
    "Allocated_Corp_Cost" = v_TotalCorpCost * 
      ("Total_Revenue" / "Total_Revenue" -> "All_Hotels");
  ENDIF
ENDFIX
```

## 8. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Cross-dim on sparse inside a loop | Exponentially slow | Use two-pass pattern |
| No divide-by-zero protection | Rule crashes with error | Always `IF(denom <> 0)` |
| Chain of 3+ cross-dims | Minutes per execution | Break into multiple passes |
| `->` vs `;` confusion | Syntax error | `->` is cross-dim; `;` ends statement |
| Cross-dim to non-existent member | Rule fails | Validate member names before deployment |
| Forgetting FIX on cross-dim | Processes entire cube | Always FIX both source and target scope |

## 9. INTERVIEW QUESTIONS

### Beginner
**Q: What does the `->` operator do in a calc script?**
> The `->` (cross-dimensional) operator references data at a different member of a dimension. For example, `"Budget_Revenue" = "Revenue" -> "Actual"` means "set Budget Revenue equal to Revenue in the Actual scenario." It lets you read data from a different block (different sparse member) within the same formula.

### Intermediate
**Q: Why is `"Bonus" = "Salary" -> "Corporate_HQ" * 0.02` potentially slow?**
> Because Entity is a Sparse dimension, and `-> "Corporate_HQ"` is a cross-dimensional reference on a sparse member. This can force Essbase into Top-Down calculation mode, where it evaluates every possible entity combination instead of only processing existing blocks. The fix is to use a two-pass pattern: first store Corporate_HQ's salary in a variable or temp member, then use that stored value in the second pass without a cross-dim reference.
