# 07.05 — Allocation Patterns and Spreading: Complete Guide

> **Module:** 07_Business_Rules | **Topic:** Cost Allocation, Data Spreading, Distribution
> **Audience:** Architect / Senior Consultant

---

## 1. WHY — What Real-World Problem Does This Solve—

**The problem:** Hotel Pvt Ltd's Corporate HQ incurs ₹1,20,00,000 in overhead costs (IT, Legal, HR). These costs must be **allocated** to the 5 hotels based on their revenue share. Similarly, a user enters an annual budget of ₹12,00,000 and wants it **spread** evenly across 12 months. Both require mathematical distribution logic.

---

## 2. ALLOCATION vs SPREADING

| Concept | Allocation | Spreading |
|---------|-----------|-----------|
| **What** | Distribute a total across MEMBERS | Distribute a total across PERIODS |
| **Direction** | Parent → Children (Entity, Department) | Annual → Monthly (Time) |
| **Driver** | Revenue share, headcount, square footage | Even, seasonal, historical pattern |
| **Example** | ₹1.2Cr corp cost → 5 hotels by revenue % | ₹12L annual → ₹1L per month |

## 3. ALLOCATION PATTERNS

### Pattern 1: Revenue-Based Allocation

```essbase
/* Allocate Corporate Overhead to hotels based on revenue share */

VAR v_TotalRevenue;
VAR v_CorpOverhead;

/* Step 1: Get the total values */
FIX("All_Hotels", "Budget", "Working", &CurrYear, "YearTotal")
  v_TotalRevenue = "Total_Revenue";
ENDFIX

FIX("Corporate_HQ", "Budget", "Working", &CurrYear, "YearTotal")
  v_CorpOverhead = "Total_Corp_Overhead";
ENDFIX

/* Step 2: Allocate to each hotel */
FIX("Budget", "Working", &CurrYear)
  FIX(@RELATIVE("All_Hotels", 0))
    IF(v_TotalRevenue <> 0)
      "Allocated_Corp_Cost" = v_CorpOverhead * 
        ("Total_Revenue" / v_TotalRevenue);
    ELSE
      "Allocated_Corp_Cost" = 0;
    ENDIF
  ENDFIX
ENDFIX

/* Result:
   Mumbai Revenue = ₹4.5Cr (37.5%) → Allocation = ₹45,00,000
   Delhi Revenue = ₹3.0Cr (25.0%) → Allocation = ₹30,00,000
   Bangalore = ₹2.4Cr (20.0%) → Allocation = ₹24,00,000
   Kolkata = ₹1.2Cr (10.0%) → Allocation = ₹12,00,000
   Chennai = ₹0.9Cr (7.5%) → Allocation = ₹9,00,000
   Total = ₹1,20,00,000 (100%) ✅
*/
```

### Pattern 2: Headcount-Based Allocation

```essbase
/* Allocate training budget based on headcount */
VAR v_TotalHC;
VAR v_TrainingBudget;

FIX("All_Hotels", "Budget", "Working", &CurrYear, "YearTotal")
  v_TotalHC = "Total_Headcount";      /* 500 total employees */
  v_TrainingBudget = "Training_Budget"; /* ₹50,00,000 */
ENDFIX

FIX("Budget", "Working", &CurrYear)
  FIX(@RELATIVE("All_Hotels", 0))
    IF(v_TotalHC <> 0)
      "Allocated_Training" = v_TrainingBudget * 
        ("Total_Headcount" / v_TotalHC);
    ENDIF
  ENDFIX
ENDFIX

/* Mumbai: 150 HC / 500 = 30% → ₹15,00,000
   Delhi: 120 HC / 500 = 24% → ₹12,00,000
   ... */
```

### Pattern 3: Equal Allocation

```essbase
/* Split cost equally across all hotels */
VAR v_HotelCount = 5;
VAR v_SharedCost;

FIX("Corporate_HQ", "Budget", "Working", &CurrYear, "YearTotal")
  v_SharedCost = "Shared_Services_Cost";
ENDFIX

FIX("Budget", "Working", &CurrYear)
  FIX(@RELATIVE("All_Hotels", 0))
    "Allocated_Shared" = v_SharedCost / v_HotelCount;
  ENDFIX
ENDFIX
```

### Pattern 4: Multi-Driver Weighted Allocation

```essbase
/* IT costs: 50% by revenue, 30% by headcount, 20% equal */
VAR v_TotalRev;
VAR v_TotalHC;
VAR v_ITCost;
VAR v_HotelCount = 5;

FIX("All_Hotels", "Budget", "Working", &CurrYear, "YearTotal")
  v_TotalRev = "Total_Revenue";
  v_TotalHC = "Total_Headcount";
ENDFIX

FIX("Corporate_HQ", "Budget", "Working", &CurrYear, "YearTotal")
  v_ITCost = "IT_Cost";
ENDFIX

FIX("Budget", "Working", &CurrYear)
  FIX(@RELATIVE("All_Hotels", 0))
    "Allocated_IT" = 
      (v_ITCost * 0.50 * ("Total_Revenue" / v_TotalRev)) +
      (v_ITCost * 0.30 * ("Total_Headcount" / v_TotalHC)) +
      (v_ITCost * 0.20 / v_HotelCount);
  ENDFIX
ENDFIX
```

## 4. SPREADING PATTERNS

### Pattern 1: Even Spread (Annual → Monthly)

```essbase
/* User enters YearTotal = ₹12,00,000
   Spread evenly: each month = ₹1,00,000 */

FIX("Budget", "Working", "FY2026")
  FIX(@RELATIVE("All_Hotels", 0))
    FIX(@CHILDREN("YearTotal"))  /* Jan through Dec */
      "Expense" = "Expense" -> "YearTotal" / 12;
    ENDFIX
  ENDFIX
ENDFIX
```

### Pattern 2: Seasonal Spread (Weighted by Pattern)

```essbase
/* Hotel revenue is seasonal — more in winter/holidays */
/* Seasonal weights stored in a separate Account member */

FIX("Budget", "Working", "FY2026")
  FIX(@RELATIVE("All_Hotels", 0))
    FIX(@CHILDREN("YearTotal"))
      "Room_Revenue" = "Room_Revenue" -> "YearTotal" * "Seasonal_Weight";
    ENDFIX
  ENDFIX
ENDFIX

/* Seasonal weights (pre-loaded):
   Jan=0.10, Feb=0.08, Mar=0.07, Apr=0.06, May=0.05, Jun=0.05
   Jul=0.06, Aug=0.07, Sep=0.08, Oct=0.10, Nov=0.12, Dec=0.16
   Total = 1.00 (100%)
   
   If Annual = ₹12,00,000:
   Jan = ₹1,20,000, Dec = ₹1,92,000 (peak season)
*/
```

### Pattern 3: Prior Year Pattern Spread

```essbase
/* Spread using prior year's actual monthly pattern */
VAR v_PYAnnual;

FIX("Budget", "Working", "FY2027")
  FIX(@RELATIVE("All_Hotels", 0))
    
    /* Get prior year annual total */
    v_PYAnnual = "Room_Revenue" -> "Actual" -> "FY2026" -> "YearTotal";
    
    IF(v_PYAnnual <> 0)
      FIX(@CHILDREN("YearTotal"))
        /* Monthly = Annual Budget × (PY Month / PY Annual) */
        "Room_Revenue" = "Room_Revenue" -> "YearTotal" * 
          ("Room_Revenue" -> "Actual" -> "FY2026" / v_PYAnnual);
      ENDFIX
    ENDIF
    
  ENDFIX
ENDFIX
```

## 5. GRID SPREADING (USER-INITIATED)

Grid spreading is a form-level feature where users spread data directly in the form:

```
User enters ₹12,00,000 in YearTotal cell
Right-clicks → Adjust Data → Spread

Spread Options:
  ○ Proportional Spread  → Based on existing monthly values
  ○ Even Spread          → Equal across all months (₹1L each)
  ○ Fill                 → Same value in all months (₹12L each!)
  
  Direction:
  ○ Down (parent → children)
  ○ Across (left → right)

Result: Monthly cells auto-populate without running a rule
```

### Grid Spread Options on Form

```
Form Designer → Grid Properties:
  ☑ Enable Grid Spread

Form Designer → Display Properties:
  ☐ Allow Grid Spread on read-only cells

Spread types available to users:
  Proportional Spread, Even Spread, Fill
```

## 7. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Allocation doesn't sum to total | Rounding errors, missing entity | Use rounding adjustment on the largest entity |
| Spreading weights don't sum to 1.0 | Over/under-distribution | Validate weights sum to exactly 1.0 |
| Cross-dim on sparse for total | Top-Down = slow | Use VAR to store total first |
| Even spread puts same value (not divided) | Fill instead of spread | Divide by member count |
| Grid spread on calculated members | Overwrites dynamic calc | Disable spread on calculated rows |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: What is the difference between allocation and spreading—**
> **Allocation** distributes a total across dimension members (e.g., corporate cost across 5 hotels based on revenue share). **Spreading** distributes a total across time periods (e.g., annual budget across 12 months). Allocation uses a driver (revenue, headcount) to determine each member's share. Spreading uses a pattern (even, seasonal, prior year) to determine each period's share.

### Architect
**Q: Design the corporate cost allocation for Hotel Pvt Ltd with multiple drivers.**
> Use a multi-driver weighted allocation: IT costs at 50% by revenue + 30% by headcount + 20% equal. Steps: (1) Store totals (Total Revenue, Total Headcount) in variables to avoid cross-dim on sparse dimensions. (2) Calculate each hotel's allocation in a single FIX block with the weighted formula. (3) Validate that the sum of allocations equals the corporate total (rounding check). (4) For monthly allocation, apply the hotel's seasonal spread pattern to the annual allocated amount. (5) Run as part of the Monthly Close Ruleset after the aggregation step. Key performance consideration: NEVER use cross-dim `-> "All_Hotels"` inside the hotel FIX — use variables instead.
