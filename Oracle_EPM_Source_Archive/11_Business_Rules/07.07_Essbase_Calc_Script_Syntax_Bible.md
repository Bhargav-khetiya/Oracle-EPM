# SECTION 1: CONTROL FLOW COMMANDS

---

## 1.1 FIX / ENDFIX

**Purpose:** Restricts the calculation scope to specific members.

**Syntax:**
```essbase
FIX(member1, member2, ..., @function("parent"))
    /* calculations */
ENDFIX
```

**Parameters:**
| Parameter | Type | Description |
|-----------|------|-------------|
| Member list | Members | One or more member names (quoted), separated by commas |
| @Function | Function | Member selection functions (@CHILDREN, @DESCENDANTS, etc.) |
| Variables | Variable | RTPs ({RTP_Name}), Substitution Vars (&Name), Global Vars ({GV_Name}) |

**Rules:**
- FIX operates at **block level** on sparse dimensions (filters which blocks to load)
- FIX on dense dimensions narrows scope within the block but does NOT reduce I/O
- Every FIX must have a matching ENDFIX
- FIX can be nested (inner FIX further restricts outer FIX scope)
- Maximum nesting: Unlimited (but performance degrades beyond 3–4 levels)
- Members from the SAME dimension are OR'd: `FIX("Jan", "Feb")` = Jan OR Feb
- Members from DIFFERENT dimensions are AND'd: `FIX("Jan", "Budget")` = Jan AND Budget

**Performance:**
```
FIX on Sparse dim: ⚡ Block filtering — excellent performance
FIX on Dense dim:  ⚠️ No block filtering — cell filtering only
No FIX:            ❌ Processes entire database — worst performance
```

## 1.2 IF / ELSEIF / ELSE / ENDIF

**Purpose:** Conditional execution based on Boolean expressions.

**Syntax:**
```essbase
IF(condition)
    /* true branch */
ELSEIF(condition2)
    /* else-if branch */
ELSE
    /* false branch */
ENDIF
```

**Condition Operators:**

| Operator | Meaning | Example |
|----------|---------|---------|
| `==` | Equal to | `IF("Revenue" == 0)` |
| `<>` or `!=` | Not equal to | `IF("Revenue" <> #Missing)` |
| `<` | Less than | `IF("Revenue" < 1000)` |
| `>` | Greater than | `IF("Revenue" > 0)` |
| `<=` | Less than or equal | `IF("Revenue" <= 100000)` |
| `>=` | Greater than or equal | `IF("Revenue" >= 50000)` |
| `AND` | Logical AND | `IF("Revenue" > 0 AND "Revenue" <> #Missing)` |
| `OR` | Logical OR | `IF(@ISMBR("US") OR @ISMBR("UK"))` |
| `NOT` | Logical NOT | `IF(NOT(@ISMBR("US")))` |

**Special Values:**

| Value | Meaning | Usage |
|-------|---------|-------|
| `#Missing` | Cell has no data (empty) | `IF("Revenue" <> #Missing)` |
| `#MI` | Alias for #Missing | Same as above |
| `0` | Numeric zero (a real value — NOT the same as #Missing) | `IF("Revenue" <> 0)` |

**Performance Warning:** IF evaluates at cell level. Use FIX instead when testing sparse dimension membership.

---

## 1.3 Member Formula Blocks

**Purpose:** Execute formulas anchored to a specific member's context.

**Syntax:**
```essbase
"MemberName"(
    /* formulas execute in context of MemberName */
    IF(condition)
        "MemberName" = expression;
    ENDIF
)
```

**Rules:**
- The member name must be in quotes
- Parentheses `( )` wrap the formula block
- Inside the block, the calculation context is anchored to that member
- Required when using IF/ELSE with a target member
- Can nest: `"Tax"( IF... "SubTax"( IF... ENDIF ) ENDIF )`

---

## 1.4 Comments

**Syntax:**
```essbase
/* This is a single-line comment */

/* This is a
   multi-line
   comment */
```

**Rules:**
- Only `/* */` style comments are supported
- `//` is NOT supported in Essbase calc scripts
- Comments are stripped during compilation — zero performance impact

# SECTION 2: DATA COMMANDS

---

## 2.1 CLEARBLOCK

**Purpose:** Physically removes data blocks from the database.

**Syntax:**
```essbase
CLEARBLOCK blockOption;
```

**Block Options:**

| Option | What It Clears | When to Use |
|--------|---------------|-------------|
| `ALL` | All data blocks in the current FIX scope | Before a full data copy or reload |
| `UPPER` | Only consolidated (non-Level-0) blocks | Reset aggregations without losing input data |
| `DYNAMIC` | Blocks for Dynamic Calc & Store members | Force recalculation of cached dynamic values |
| `NONINPUT` | Blocks created entirely by calculations (no loaded data) | Remove allocation results while keeping user inputs |

**Example:**
```essbase
FIX("Budget", "Working", "FY24")
    CLEARBLOCK ALL;
ENDFIX
```

**Performance:** Extremely fast — drops block file pointers. Reduces database size.

---

## 2.2 CLEARDATA

**Purpose:** Sets all values in the current scope to `#Missing` without deleting the physical block.

**Syntax:**
```essbase
CLEARDATA "MemberName";
```

**Example:**
```essbase
FIX("Budget", "Working", "FY24")
    CLEARDATA "Tax";
ENDFIX
```

**Key Difference from CLEARBLOCK:**
| Feature | CLEARBLOCK | CLEARDATA |
|---------|-----------|-----------|
| Physical block | Deleted from disk | Remains on disk |
| Targets | Sparse dimension intersections (blocks) | Any member (dense or sparse) |
| Speed | ⚡ Very fast | ⚠️ Slower (reads/writes each block) |
| Use for Dense member | ❌ Cannot target dense member | ✅ Can target dense member |

---

## 2.3 DATACOPY

**Purpose:** Physically copies data blocks from one sparse member to another.

**Syntax:**
```essbase
DATACOPY "SourceMember" TO "TargetMember";
```

**Example:**
```essbase
FIX("Working", "FY24", @RELATIVE("Total_Entity", 0))
    DATACOPY "Actual" TO "Budget";
ENDFIX
```

**Rules:**
- Source and Target must be from the SAME sparse dimension
- Creates blocks at the target if they don't exist
- Does NOT delete target data that doesn't exist in the source (clear first!)
- Operates at block level — extremely fast for bulk copies

**Common Pattern (Seed Budget from Actuals):**
```essbase
/* Step 1: Clear target */
FIX("Budget", "Working", "FY24")
    CLEARBLOCK ALL;
ENDFIX

/* Step 2: Copy */
FIX("Working", "FY24", @RELATIVE("Total_Entity", 0))
    DATACOPY "Actual" TO "Budget";
ENDFIX
```

## 2.4 CALC DIM

**Purpose:** Calculates (aggregates + applies member formulas) an entire dimension.

**Syntax:**
```essbase
CALC DIM("DimensionName");
CALC DIM("Dim1", "Dim2");  /* Multiple dimensions */
```

**Behavior:**
| For Dense Dimensions | For Sparse Dimensions |
|---------------------|----------------------|
| Executes formulas + sums within blocks in memory | Creates/updates upper-level blocks on disk |
| Very fast | Slower (block creation I/O) |
| No new blocks created | Creates new blocks for parent intersections |

**When to Use:**
- After modifying Level 0 data and needing to aggregate up
- When member formulas need to be triggered

---

## 2.5 AGG

**Purpose:** Aggregates (sums) a dimension WITHOUT executing member formulas.

**Syntax:**
```essbase
AGG("DimensionName");
AGG("Dim1", "Dim2");
```

**CALC DIM vs AGG:**

| Feature | CALC DIM | AGG |
|---------|----------|-----|
| Aggregates (sums up)? | ✅ Yes | ✅ Yes |
| Executes member formulas? | ✅ Yes | ❌ No |
| Speed | Slower (formulas + aggregation) | Faster (aggregation only) |
| When to use | When dimension has member formulas | When dimension has no formulas (pure hierarchy) |

---

## 2.6 CALC ALL

**Purpose:** Calculates the ENTIRE database — all dimensions, all members.

**Syntax:**
```essbase
CALC ALL;
```

> **⚠️ NEVER use in Oracle Planning.** CALC ALL processes every scenario, every version, every year. In a Planning application with 5 scenarios × 3 versions × 10 years × 500 entities, this would attempt to calculate 75,000 different block combinations. It will take hours and potentially crash the server.

---

## 2.7 CALC TWOPASS

**Purpose:** Forces recalculation of members tagged as "Two-Pass" in the outline.

**Syntax:**
```essbase
CALC TWOPASS;
```

**Use Case:** After calculating Revenue and COGS, recalculate `Margin %` (which is tagged Two-Pass) so it uses the freshly calculated Q1 Revenue total instead of the stale pre-calc value.

# SECTION 3: ALL SET COMMANDS — EXHAUSTIVE

---

## Data Volume

| Command | Syntax | Values | Effect |
|---------|--------|--------|--------|
| Update Calc | `SET UPDATECALC OFF;` | `ON` / `OFF` | ON = only calc dirty blocks (Intelligent Calc). OFF = calc everything. |
| Create Block on Eq | `SET CREATEBLOCKONEQ ON;` | `ON` / `OFF` | ON = formulas can create new blocks. OFF = formulas only write to existing blocks. |
| Create Non-Missing | `SET CREATENONMISSINGBLK ON;` | `ON` / `OFF` | ON = create blocks only if formula result ≠ #Missing. Safer than CREATEBLOCKONEQ. |

## Data Handling

| Command | Syntax | Values | Effect |
|---------|--------|--------|--------|
| Agg Missing | `SET AGGMISSG ON;` | `ON` / `OFF` | ON = treat #Missing as 0 during aggregation. OFF = skip #Missing. |
| Formula Bottom-Up | `SET FRMLBOTTOMUP ON;` | `ON` / `OFF` | ON = evaluate member formulas from Level 0 up. OFF = top-down. |
| Clear Update Status | `SET CLEARUPDATESTATUS AFTER;` | `AFTER` / `OFF` | AFTER = mark all blocks as "clean" after calc completes. |

## Memory (BSO Only)

| Command | Syntax | Values | Effect |
|---------|--------|--------|--------|
| Cache | `SET CACHE HIGH;` | `HIGH` / `DEFAULT` / `LOW` | HIGH = maximize RAM for calculator. |
| Lock Block | `SET LOCKBLOCK ON;` | `ON` / `OFF` | ON = keep blocks in RAM during calc (no disk swapping). |

## Threading

| Command | Syntax | Values | Effect |
|---------|--------|--------|--------|
| Parallel Calc | `SET CALCPARALLEL 4;` | `1` to `n` | Number of CPU threads for the calculation. |
| Parallel Tasks | `SET CALCTASKDIMS 2;` | `1` to `n` | Number of dimensions to split for parallelization. |

## Logging

| Command | Syntax | Values | Effect |
|---------|--------|--------|--------|
| Message Level | `SET MSG SUMMARY;` | `SUMMARY` / `DETAIL` / `ERROR` / `NONE` | Controls log verbosity. |
| Notice Level | `SET NOTICE LOW;` | `LOW` / `HIGH` | LOW = fewer informational messages. |

## Boolean / Data Type

| Command | Syntax | Values | Effect |
|---------|--------|--------|--------|
| Missing Value | `SET MISSINGVALUE "text";` | Text string | Replace #Missing display with custom text. |
| Suppress Missing | `SET SUPPMISSG ON;` | `ON` / `OFF` | ON = suppress #Missing from calc output. |

## Summary

This syntax bible covers **every command, operator, and function** available in Essbase calc scripts within Oracle EPM Cloud. Use it as your go-to reference when writing or debugging business rules.

**Quick Reference — Most Used:**
| Need | Use |
|------|-----|
| Restrict scope | `FIX / ENDFIX` |
| Conditional logic | `IF / ELSEIF / ELSE / ENDIF` |
| Clear data | `CLEARBLOCK` (sparse) or `CLEARDATA` (dense) |
| Copy data | `DATACOPY` |
| Aggregate | `AGG` (no formulas) or `CALC DIM` (with formulas) |

| Performance tuning | `SET CALCPARALLEL`, `SET UPDATECALC OFF` |
