# 09.07 — Groovy vs Calc Script Decision Guide: Complete Guide

> **Module:** 09_Groovy | **Topic:** When to Use Groovy vs Calc Script
> **Audience:** Architect / Rule Developer

---

## 1. WHY — Making the Right Choice

**The problem:** Both Groovy and Calc Scripts can calculate data in EPBCS. Choosing the wrong one wastes development time, creates performance issues, or limits functionality. Most teams default to calc scripts because they're familiar — missing Groovy's power for complex scenarios.

---

## 2. THE DECISION MATRIX

| Requirement | Calc Script | Groovy | Winner |
|-------------|------------|--------|--------|
| Simple math (A + B = C) | ✅ Native | ✅ Possible | **Calc Script** |
| Aggregation (AGG) | ✅ Native command | ❌ Must use embedded calc | **Calc Script** |
| DATACOPY | ✅ Native command | ❌ Must use embedded calc | **Calc Script** |
| SET commands (LOCKBLOCK, PARALLEL) | ✅ Native | ❌ Not available | **Calc Script** |
| Cross-dimensional formulas | ✅ `->` operator | ✅ `crossDimCell()` | **Calc Script** |
| Complex conditional logic | ⚠️ Limited IF/ELSE | ✅ Full if/else/switch | **Groovy** |
| String manipulation | ❌ Very limited | ✅ Full Java strings | **Groovy** |
| Smart List text comparison | ❌ Numeric IDs only | ✅ `getSmartListValue()` | **Groovy** |
| Send email | ❌ Impossible | ✅ Built-in email service | **Groovy** |
| REST API calls | ❌ Impossible | ✅ HttpURLConnection | **Groovy** |
| Data validation with user message | ❌ Rule fails silently | ✅ `throwVetoException()` | **Groovy** |
| Cross-cube data access | ❌ Separate rules | ✅ DataMap + crossDimCell | **Groovy** |
| Runtime context (which form, user) | ❌ No access | ✅ `operation` object | **Groovy** |
| Performance (pure math) | ⚡ 2× faster | 🐌 Slower (JVM overhead) | **Calc Script** |
| Performance (complex logic) | 🐌 Many IF/ELSE = slow | ⚡ JVM optimized | **Groovy** |

## 3. THE DECISION TREE

```
What do you need to do—
│
├── Pure math/aggregation—
│   → CALC SCRIPT ✅
│   (A + B = C, AGG, DATACOPY, CLEARDATA)
│
├── Send email or call REST API—
│   → GROOVY ✅
│   (Only Groovy can reach external systems)
│
├── Complex validation with user messages—
│   → GROOVY ✅
│   (throwVetoException shows message to user)
│
├── Smart List text comparison—
│   → GROOVY ✅
│   (getSmartListValue() returns "Approved" not 3)
│
├── String manipulation—
│   → GROOVY ✅
│   (Substring, replace, concatenate, regex)
│
├── Math + external integration—
│   → BOTH ✅
│   (Groovy rule calls embedded calc script for math)
│
└── Not sure—
    → Start with CALC SCRIPT
    → If you hit a limitation → switch to GROOVY
```

## 4. HYBRID APPROACH — BEST OF BOTH

```groovy
/* Use Groovy for logic + Calc Script for math */

/* Step 1: Groovy validates input */
def errors = []
operation.grid.dataCellIterator("Account#Room_Revenue").each { cell ->
    if (cell.data < 0) {
        errors << "Negative revenue: ${cell.getMemberName('Entity')}"
    }
}

if (errors.size() > 0) {
    throwVetoException("Validation failed:\n${errors.join('\n')}")
}

/* Step 2: Groovy calls embedded calc script for math */
def calcScript = """
SET LOCKBLOCK ON;
SET CALCPARALLEL 4;
FIX("Budget", "Working", "FY2026")
  FIX(@RELATIVE("All_Hotels", 0))
    "Total_Revenue" = "Room_Revenue" + "F&B_Revenue" + "Spa_Revenue";
    "Net_Income" = "Total_Revenue" - "Total_Expenses";
    IF("Total_Revenue" <> 0)
      "Profit_Margin" = "Net_Income" / "Total_Revenue" * 100;
    ENDIF
  ENDFIX
  AGG("Entity");
ENDFIX
SET LOCKBLOCK OFF;
"""

operation.application.getEssbaseServer()
    .getApplication("HotelApp")
    .getCube("OEP_FS")
    .executeCalcScript(calcScript)

/* Step 3: Groovy sends notification */
try {
    def emailService = operation.application.getEmailService()
    emailService.sendMail("cfo@hotelpvtltd.com",
        "P&L Calculated", "Monthly P&L calculation complete.")
} catch (Exception e) {
    println "Email failed: ${e.message}"
}
```

## 5. PERFORMANCE COMPARISON

```
Scenario: Calculate P&L for 5 hotels × 12 months

Calc Script:
  FIX("Budget", "Working", "FY2026", @RELATIVE("All_Hotels", 0))
    "Net_Income" = "Total_Revenue" - "Total_Expenses";
  ENDFIX
  → Time: 0.8 seconds ⚡

Groovy (cell iteration):
  operation.grid.dataCellIterator("Account#Net_Income").each { cell ->
    double rev = cell.crossDimCell("Account#Total_Revenue").data
    double exp = cell.crossDimCell("Account#Total_Expenses").data
    cell.data = rev - exp
  }
  → Time: 3.2 seconds 🐌 (4× slower for pure math)

Groovy (embedded calc):
  operation.application...executeCalcScript(calcScript)
  → Time: 1.0 seconds ⚡ (same as native calc script)

Rule: For pure math → use Calc Script or embedded calc.
      For logic → use Groovy iteration.
```

## 7. COMMON MISTAKES

| Mistake | Impact | Fix |
|---------|--------|-----|
| Using Groovy for simple math | 4× slower than needed | Use Calc Script for A+B=C |
| Using Calc Script for validation | No user error message | Use Groovy + throwVetoException |
| Writing AGG in Groovy | Impossible — no AGG in Groovy | Embed calc script inside Groovy |
| Ignoring hybrid approach | Miss optimal performance | Use Groovy for logic + embedded calc for math |
| Defaulting to one language | Sub-optimal for many cases | Match language to requirement |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: When should you use Groovy vs Calc Script—**
> **Calc Script:** Pure math (A+B=C), aggregation (AGG), data copy (DATACOPY), performance-critical calculations, SET commands (LOCKBLOCK, CALCPARALLEL). **Groovy:** Email notifications, REST API calls, complex validation with user messages (throwVetoException), Smart List text comparisons, string manipulation, cross-cube data access via DataMaps. **Hybrid:** Use Groovy for logic and validation, then call an embedded calc script for the heavy math.

### Architect
**Q: Design the rule architecture for Hotel Pvt Ltd's budget approval process.**
> **Phase 1 (Groovy):** Validate all input — no negative revenues, occupancy ≤ 100%, mandatory fields filled. If validation fails → throwVetoException with detailed error message. **Phase 2 (Embedded Calc Script):** Calculate totals, P&L, KPIs using SET LOCKBLOCK ON + CALCPARALLEL 4 for maximum performance. AGG Entity dimension. **Phase 3 (Groovy):** Check Smart List "Budget_Status". If status = "In Review" and variance < 5% → auto-approve (set to 3). **Phase 4 (Groovy):** Send summary email to CFO with hotel-by-hotel results. Log completion message. This hybrid approach gets the best of both: Groovy's flexibility for logic/integration and Calc Script's speed for math.
