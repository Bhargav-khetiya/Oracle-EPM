## 📌 Data Reading — Complete Patterns

### Pattern 1: Read Single Cell

```groovy
Cube cube = operation.application.getCube("FinPlan")
DataGridDefinitionBuilder builder = cube.dataGridDefinitionBuilder()
builder.addPov(["Year":"FY26", "Scenario":"Actual", "Version":"Final",
                "Entity":"E10001", "Currency":"Local"])
builder.addColumn(["Period":["Jan"]])
builder.addRow(["Account":"Revenue"])
builder.setSuppressMissing(true)

DataGridDefinition dgd = builder.build()
DataGrid grid = cube.loadGrid(dgd, false)

grid.dataCellIterator().each { DataCell cell ->
    println "Revenue Jan = ${cell.data}"
}
```

### Pattern 2: Read Multiple Members

```groovy
Cube cube = operation.application.getCube("FinPlan")
DataGridDefinitionBuilder builder = cube.dataGridDefinitionBuilder()
builder.addPov(["Year":"FY26", "Scenario":"Actual", "Version":"Final",
                "Currency":"Local"])
builder.addColumn(["Period":["Jan","Feb","Mar","Apr","May","Jun",
                             "Jul","Aug","Sep","Oct","Nov","Dec"]])
builder.addRow(["Account":["Revenue","Expenses","Net_Profit"],
                "Entity":["E10001","E10002"]])
builder.setSuppressMissing(true)

DataGrid grid = cube.loadGrid(builder.build(), false)
grid.dataCellIterator().each { DataCell cell ->
    String acct = cell.getMemberName("Account")
    String entity = cell.getMemberName("Entity")
    String period = cell.getMemberName("Period")
    double value = cell.data
    println "${entity} | ${acct} | ${period} = ${value}"
}
```

### Pattern 3: Navigate to Related Cells

```groovy
grid.dataCellIterator("Account":"Revenue").each { DataCell cell ->
    // Get current cell value
    double revenue = cell.data
    
    // Navigate to a different member in same block
    DataCell expenseCell = cell.crossDimCell("Account":"Expenses")
    double expenses = expenseCell.data
    
    // Navigate to prior period
    DataCell priorCell = cell.crossDimCell("Period":"Jan") // explicit
    
    // Calculate
    double profit = revenue - expenses
    println "Profit = ${profit}"
}
```

### 💡 Logic & Purpose
The `DataGridDefinitionBuilder` (Reading) and `DataGridBuilder` (Writing) APIs act exactly like invisible Smart View sheets running in the server's memory. Instead of forcing Essbase to calculate an entire block, you define the exact intersection you want, "pull" it into memory, manipulate the Java object, and "submit" it back. This is hyper-efficient for targeted user-driven actions (like saving data on a web form).

### 🌀 Confusion Resolution
> **Misconception:** "I used `DataGridDefinitionBuilder` to pull all my revenue data. I then modified the `cell.data` property directly in the iterator. Why isn't it saving to Essbase?"
> **Reality:** The `DataGridDefinitionBuilder` creates a strictly **read-only** snapshot of the data. Modifying the `cell.data` property in memory does absolutely nothing to the database. To write data back, you MUST use `DataGridBuilder` to construct a brand new grid containing the modified values, and explicitly execute `cube.saveGrid(builder.build())`.

### 😈 Twisted Interview Question
**Question:** A developer writes a Groovy script using `DataGridDefinitionBuilder`. They set the POV, Columns, and Rows perfectly. However, when they iterate through the `dataCellIterator()`, the loop doesn't execute even once, even though they *know* there is data in the cube at that intersection. What property did they forget?
> **Answer:** They likely forgot to manage `#MISSING` data, or they explicitly set `builder.setSuppressMissing(true)` on a grid that consisted mostly of missing data at the parent level before aggregation. If the grid evaluation returns entirely missing rows, the builder suppresses them, and the iterator receives an empty object (zero rows). Always verify whether missing suppression is helping or hurting the specific query!

## 📌 Data Writing — Complete Patterns

### Pattern 4: Write to Cube

```groovy
Cube cube = operation.application.getCube("FinPlan")
DataGridBuilder builder = cube.dataGridBuilder("USD")

builder.addPov(["Year":"FY27", "Scenario":"Budget", "Version":"Working",
                "Currency":"Local"])
builder.addColumn(["Period":["Jan","Feb","Mar"]])

// Each addRow: member map + array of values (one per column)
builder.addRow(["Account":"Revenue", "Entity":"E10001"], [1000000, 1100000, 1200000])
builder.addRow(["Account":"Revenue", "Entity":"E10002"], [500000, 550000, 600000])
builder.addRow(["Account":"Expenses", "Entity":"E10001"], [400000, 420000, 440000])
builder.addRow(["Account":"Expenses", "Entity":"E10002"], [200000, 210000, 220000])

cube.saveGrid(builder.build())
println "Data saved successfully: 4 rows × 3 columns = 12 cells"
```

### Pattern 5: Read-Transform-Write (ETL)

```groovy
Cube cube = operation.application.getCube("FinPlan")

// STEP 1: READ actuals
DataGridDefinitionBuilder reader = cube.dataGridDefinitionBuilder()
reader.addPov(["Year":"FY26", "Scenario":"Actual", "Version":"Final", "Currency":"Local"])
reader.addColumn(["Period":["Jan","Feb","Mar","Apr","May","Jun",
                            "Jul","Aug","Sep","Oct","Nov","Dec"]])
reader.addRow(["Account":["Revenue","Expenses"], 
               "Entity":["E10001","E10002"]])
reader.setSuppressMissing(true)

DataGrid sourceGrid = cube.loadGrid(reader.build(), false)

// STEP 2: TRANSFORM — apply 10% growth
DataGridBuilder writer = cube.dataGridBuilder("USD")
writer.addPov(["Year":"FY27", "Scenario":"Budget", "Version":"Working", "Currency":"Local"])
writer.addColumn(["Period":["Jan","Feb","Mar","Apr","May","Jun",
                            "Jul","Aug","Sep","Oct","Nov","Dec"]])

Map<String, List<Double>> entityAccountData = [:]

sourceGrid.dataCellIterator().each { DataCell cell ->
    String key = "${cell.getMemberName('Entity')}|${cell.getMemberName('Account')}"
    if (!entityAccountData.containsKey(key)) {
        entityAccountData[key] = []
    }
    entityAccountData[key] << (cell.data * 1.10)  // 10% growth
}

// STEP 3: WRITE budget
entityAccountData.each { key, values ->
    def parts = key.split("\\|")
    writer.addRow(["Account":parts[1], "Entity":parts[0]], values as double[])
}

cube.saveGrid(writer.build())
println "Budget FY27 = Actual FY26 × 1.10 — ${entityAccountData.size()} rows saved"
```

## 📌 Error Handling — Production Quality

```groovy
try {
    Cube cube = operation.application.getCube("FinPlan")
    
    // Your logic here
    DataGridBuilder builder = cube.dataGridBuilder("USD")
    // ... build grid ...
    cube.saveGrid(builder.build())
    
    println "SUCCESS: Data saved"
    
} catch (Exception e) {
    println "ERROR: ${e.message}"
    println "Stack trace: ${e.stackTrace.take(5).join('\n')}"
    
    // Send error email
    def mail = operation.application.getMailDefinition()
    mail.setTo("epm-admin@company.com")
    mail.setSubject("EPM Groovy Rule FAILED")
    mail.setBody("Error: ${e.message}\nRule: GR_Copy_Budget\nTime: ${new Date()}")
    operation.application.sendMail(mail)
    
    // Re-throw to mark rule as failed in Job Console
    throw e
}
```

## 🎓 Interview Questions

**Q: When would you use Groovy instead of Calc Scripts?**
> Groovy for: REST API calls, email notifications, complex conditional logic, string manipulation, metadata iteration, cross-cube ETL with transformations. Calc Scripts for: simple math, aggregation, DATACOPY — they're faster for standard calculations.

**Q: Explain DataGridDefinitionBuilder vs DataGridBuilder.**
> DataGridDefinitionBuilder is for READING data (define what to retrieve, call loadGrid, iterate cells). DataGridBuilder is for WRITING data (define POV, columns, add rows with values, call saveGrid). Read = Definition, Write = Builder.

**Q: How do you handle errors in production Groovy rules?**
> try/catch/finally blocks. Log errors with println (Job Console). Send email alert on failure. Re-throw exception to mark the rule as failed. Always validate inputs before processing. Test with small data sets first.
