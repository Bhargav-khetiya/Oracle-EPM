# 11.01 — Data Management vs Data Integration: Complete Guide

> **Module:** 11_Data_Integration | **Topic:** FDMEE vs Data Integration, Import/Export Pipelines
> **Audience:** Service Administrator / Consultant

---

## 1. WHY — What Real-World Problem Does This Solve—

**The problem:** EPBCS doesn't exist in isolation. Hotel Pvt Ltd's actual revenue comes from the PMS (Property Management System), salary data from HRMS, and GL balances from the ERP. How do you get external data INTO EPBCS and EPBCS data OUT to downstream systems—

**The solution:** Oracle provides two data loading frameworks: **Data Management** (the legacy FDMEE-based tool) and **Data Integration** (the newer, simplified approach). Understanding when to use which is critical.

---

## 2. DATA MANAGEMENT vs DATA INTEGRATION

```
┌── Data Management (Legacy/Classic) ─────────────────────────┐
│                                                               │
│  • Full FDMEE engine under the hood                         │
│  • Complex mapping rules with drill-through                 │
│  • Multi-step workflows: Import → Validate → Export → Check │
│  • Supports: ERP, flat files, databases                     │
│  • Best for: Complex transformations, large enterprise      │
│  • Navigation: Navigator → Data Exchange → Data Management  │
│                                                               │
└───────────────────────────────────────────────────────────────┘

┌── Data Integration (Modern/Simplified) ─────────────────────┐
│                                                               │
│  • Simplified UI on top of Data Management                  │
│  • Drag-and-drop mapping                                    │
│  • Direct connections to ERP Cloud, files                   │
│  • Automated workflows with minimal configuration           │
│  • Best for: Simple loads, cloud-to-cloud integrations      │
│  • Navigation: Navigator → Data Exchange → Data Integration │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

### Comparison Table

| Feature | Data Management | Data Integration |
|---------|----------------|-----------------|
| **Complexity** | High — full FDMEE power | Low — simplified UI |
| **Mapping** | Explicit mapping rules per dimension | Auto-mapping with overrides |
| **Transformation** | Script-based (Jython/SQL) | Visual mapping |
| **Source types** | Files, ERP, databases, on-prem | Files, ERP Cloud, REST APIs |
| **Drill-back** | ✅ Full drill-through to source | ✅ Limited drill-back |
| **Validation** | Multi-step with data staging | Inline validation |
| **On-Premise sources** | Via EPM Integration Agent | Via EPM Integration Agent |
| **Best for** | Complex, regulated industries | Standard cloud integrations |

| Method | Complexity | Speed | Best For |

## 4. FLAT FILE IMPORT — STEP BY STEP

### File Format

```csv
Account,Entity,Scenario,Version,Year,Period,Amount
Room_Revenue,Mumbai_Hotel,Actual,Final,FY2026,Aug,8500000
F&B_Revenue,Mumbai_Hotel,Actual,Final,FY2026,Aug,2200000
Spa_Revenue,Mumbai_Hotel,Actual,Final,FY2026,Aug,500000
Room_Revenue,Delhi_Hotel,Actual,Final,FY2026,Aug,7200000
F&B_Revenue,Delhi_Hotel,Actual,Final,FY2026,Aug,1800000
```

### Import Process

```
Step 1: Upload file to EPBCS
  Navigator → Data Exchange → Upload file
  Select: Aug_Actuals.csv

Step 2: Create Import Rule (first time only)
  Data Management → Import Format:
    Delimiter: Comma
    Header Row: 1
    Column Mapping:
      Column 1 → Account
      Column 2 → Entity
      Column 3 → Scenario
      Column 4 → Version
      Column 5 → Year
      Column 6 → Period
      Column 7 → Data (Amount)

Step 3: Create Data Load Rule
  Source: Import Format (created above)
  Target: OEP_FS cube
  Mapping: Direct (member names match) or Mapped (need translation)

Step 4: Run the load
  Execute Data Load Rule → Monitor in Jobs Console

Step 5: Verify
  Open form → Refresh → Verify data appears correctly
```

## 5. DATA INTEGRATION — MODERN APPROACH

### Creating an Integration

```
Navigator → Data Exchange → Data Integration → Create

Step 1: Source
  Type: [File ▾]
  File: Aug_Actuals.csv (uploaded)

Step 2: Target
  Application: HotelApp
  Cube: OEP_FS

Step 3: Mapping
  ┌── Dimension Mapping ─────────────────────────────────────┐
  │ Source Column  →  Target Dimension  →  Mapping Type     │
  │ Account       →  Account           →  Direct            │
  │ Entity        →  Entity            →  Direct            │
  │ Scenario      →  Scenario          →  Direct            │
  │ Version       →  Version           →  Direct            │
  │ Year          →  Year              →  Direct            │
  │ Period        →  Period            →  Direct            │
  │ Amount        →  Data              →  (auto)            │
  └──────────────────────────────────────────────────────────┘

Step 4: Options
  Import Mode: [Replace ▾]  (Replace existing data— or Merge/Accumulate—)
  
Step 5: Execute
  Run → Monitor status
```

### Import Modes

| Mode | Behavior | Use When |
|------|----------|----------|
| **Replace** | Clears existing data at intersection, loads new | Monthly actuals (full refresh) |
| **Merge (Accumulate)** | Adds to existing values | Journal entries, adjustments |
| **Replace (All Data)** | Clears ALL data in scope, then loads | Full reload scenarios |

## 6. EPM INTEGRATION AGENT (On-Premise Data)

```
For on-premise databases (SQL Server, Oracle DB, SAP):
  
  ┌── On-Premise ──────────┐     ┌── Oracle Cloud ──────────┐
  │                         │     │                           │
  │  SQL Server / Oracle DB │     │  EPM Cloud (EPBCS)       │
  │          │              │     │          ▲                │
  │          ▼              │     │          │                │
  │  EPM Integration Agent  │────────────────                │
  │  (installed on-prem)    │ HTTPS (443)  │                │
  │                         │     │         Data Integration │
  └─────────────────────────┘     └──────────────────────────┘

Agent runs as a Windows service on-premise.
Connects to the local database.
Pushes data to EPM Cloud over HTTPS.
No inbound ports needed (outbound only).
```

## 8. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Member name mismatch | "Member not found" errors | Create mapping rules or fix source data |
| Wrong import mode (Replace vs Merge) | Data overwritten or doubled | Choose correct mode for use case |
| No header row in CSV | First data row treated as header | Add header row or configure skip |
| Special characters in data | Import fails | Clean data: remove commas in numbers |
| Not validating before loading to production | Bad data in cube | Always load to DEV first, verify, then PROD |

## 9. INTERVIEW QUESTIONS

### Beginner
**Q: What is the difference between Data Management and Data Integration in EPBCS—**
> **Data Management** is the full-power FDMEE engine with complex mapping, transformation scripts, and multi-step workflows. Best for complex enterprise integrations with drill-back requirements. **Data Integration** is a simplified, modern UI built on top of Data Management — drag-and-drop mapping, quick setup, ideal for standard file loads and cloud-to-cloud connections. For most new implementations, start with Data Integration; escalate to Data Management only when you need advanced transformations.

### Architect
**Q: Design the data integration architecture for Hotel Pvt Ltd with data from PMS (on-prem), HRMS (cloud), and ERP (Fusion Cloud).**
> (1) **PMS (on-prem):** Install EPM Integration Agent on-premise. Agent connects to PMS database, extracts daily revenue/occupancy data, pushes to EPM Cloud via HTTPS. Schedule: daily at 2 AM. (2) **HRMS (Oracle Cloud):** Use Data Integration direct cloud connector — pre-built mapping for headcount/salary data. Schedule: weekly. (3) **ERP (Fusion Cloud):** Direct Cloud connector with GL account mapping. Use Data Management for complex GL → Planning account translation with drill-back. (4) **Validation:** Member mapping validation before each load; email alerts on failure. (5) **Environment strategy:** Load to DEV first, verify, promote to PROD.
