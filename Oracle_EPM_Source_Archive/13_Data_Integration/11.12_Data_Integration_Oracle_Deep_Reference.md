## 🏢 Overview

Data flows INTO EPM via two main tools:
1. **Data Management (FDMEE)** — Traditional ETL with mapping, transformation, and drill-through
2. **Data Integration** — Modern cloud-native integration with direct connections

## 📌 Data Management (FDMEE) — Complete Workflow

### The 4-Step Process

```
Step 1: IMPORT → Load source data into Data Management staging table
Step 2: VALIDATE → Check data quality, apply mappings
Step 3: EXPORT → Push mapped data to target Essbase cube
Step 4: VERIFY → Confirm data landed correctly
```

### Components

| Component | Purpose | Where to Configure |
|-----------|---------|-------------------|
| **Source System** | Define where data comes from | Data Management → Setup → Source System |
| **Import Format** | Define file structure (columns, delimiters) | Data Management → Setup → Import Format |
| **Location** | Link source to target + mapping | Data Management → Setup → Location |
| **Data Load Rule** | Execution definition | Data Management → Setup → Data Load Rule |
| **Data Load Mapping** | Source member → Target member | Data Management → Setup → Mapping |
| **Period Mapping** | Source period format → EPM periods | Data Management → Setup → Period Mapping |

### Setting Up a Data Load — Step by Step

#### Step 1: Define Source System

```
Navigation: Data Management → Setup → Source System → Add
```

| Property | Value |
|----------|-------|

#### Step 2: Create Import Format

```
Navigation: Data Management → Setup → Import Format → Add
```

Import Format defines your source file structure:

```csv

Account,Entity,Department,Period,Amount
100110,E10001,ROOMS,Jul-26,500000
100120,E10001,FNB,Jul-26,200000

```

| Column | Maps To | Format |
|--------|---------|--------|
| Column 1 | Account | Text |
| Column 2 | Entity | Text |
| Column 3 | Department | Text (custom dimension) |
| Column 4 | Period | Date (MMM-YY) |
| Column 5 | Amount | Number |

Properties:
| Property | Value |
|----------|-------|
| File Type | Delimited |
| Delimiter | Comma |
| Header Rows | 1 |
| Source Type | File |

#### Step 3: Create Location

```
Navigation: Data Management → Setup → Location → Add
```

| Property | Value |
|----------|-------|
| Name | Load_Actuals |
| Import Format | (from Step 2) |
| Target Application | FinPlan |
| Target Plan Type | FinPlan (BSO) |
| Functional Currency | INR |

#### Step 4: Create Mappings

```
Navigation: Data Management → Setup → Mapping → [Select Location]
```

### 💡 Logic & Purpose
Data Management (FDMEE) exists because source systems speak a different language than EPM. The ERP might use a 12-digit GL string (`01.4000.999.00`), while Planning uses 5 separate dimensions (Entity, Account, Dept, Sub, Proj). The mappings translate the ERP string into the 5 EPM dimensions row by row, ensuring data lands in the exact correct block in Essbase.

### 🌀 Confusion Resolution
> **Misconception:** "I created an 'Explicit' mapping for Account 4000 to map to 'Revenue', and a 'Like' mapping for `4*` to map to 'Other_Revenue'. Why is Account 4000 going to 'Other_Revenue'?"
> **Reality:** You violated the strict Mapping Priority order! Data Management evaluates mappings in a very specific sequence: **Explicit → Between → In → Like → Multi-Dimensional**. If 4000 mapped to 'Other_Revenue', your 'Like' mapping was likely evaluated first because of a corrupted rule order, or your 'Explicit' mapping was built on the wrong location/dimension. Always check the rule priority sequence!

### 😈 Twisted Interview Question
**Question:** An admin configures a Data Load Rule. The source file has 10,000 rows. The admin creates a Multi-Dimensional mapping: `If Account = 5000 AND Entity = NewYork, map to 'Local_Travel'`. The data loads, but thousands of rows are rejected with "Unmapped Data" errors, even though all other dimensions had wildcard (`*`) mappings. Why?
> **Answer:** Multi-Dimensional mappings are evaluated LAST in the priority sequence! If the admin had a generic `*` to `*` "Like" mapping on the Account dimension, Data Management would apply the wildcard mapping and skip the Multi-Dimensional mapping entirely. To fix it, the admin must ensure the "Like" mapping doesn't swallow the rows before the Multi-Dimensional mapping gets a chance to evaluate them, or explicitly define the processing order.


##### Account Mapping

| Source | Target | Type |
|--------|--------|------|
| 100110 | 100110 | Explicit (1-to-1) |
| 100120 | 100120 | Explicit |
| 100* | Ignore | Wildcard (catch unmapped) |
| 200110 | 200110 | Explicit |
| 200* | 200999_Other_Expense | Wildcard (map unknown to catch-all) |

##### Entity Mapping

| Source | Target | Type |
|--------|--------|------|
| E10001 | E10001 | Explicit |
| E10002 | E10002 | Explicit |
| * | Ignore | Default (catch unmapped) |

##### Period Mapping

| Source | Target |
|--------|--------|
| Jul-26 | Jul, FY26 |
| Aug-26 | Aug, FY26 |

## 📌 Data Load Workbench

```
Navigation: Data Management → Monitor → Process Details
```

| Column | What to Check |
|--------|---------------|
| **Process ID** | Unique load identifier |
| **Status** | Success / Error |
| **Rows Loaded** | Number of records successfully imported |
| **Rows Rejected** | Number of records that failed |
| **Error Log** | Click for detailed error messages |

### Common Load Errors

| Error | Cause | Fix |
|-------|-------|-----|
| "Target member not found for [ACCT]" | Account not mapped | Add mapping in Data Management |
| "Invalid number" | Non-numeric in Amount column | Clean source file |
| "No data loaded" | All rows rejected | Check ALL dimension mappings |
| "Duplicate key violation" | Same intersection loaded twice | Use Replace mode instead of Append |
| "Import format mismatch" | File structure changed | Update import format columns |

## 📌 Data Maps & Smart Push

### Data Maps (Cube-to-Cube)

Data Maps move data BETWEEN cubes within the same application.

```
Navigation: Application → Data Maps → Create
```

| Property | Description |
|----------|-------------|
| Source Cube | FinPlan (BSO) |
| Target Cube | OEP_REP (ASO Reporting) |
| Dimension Mapping | Map each dimension from source to target |
| Member Mapping | Which members to include |
| Data Option | Add / Replace / Subtract |

### Smart Push (Automatic Data Maps)

Smart Push triggers a Data Map automatically when a user saves a form.

```
Navigation: Form → Edit → Smart Push tab → Add Data Map
```

| Setting | Description |
|---------|-------------|
| Data Map | Select which Data Map to use |
| After Save | Automatically push after form save |
| Members | Which members to push |

## 🔌 EPM Integration Agent (On-Premise Sources)

For connecting to on-premise databases (Oracle DB, SQL Server, etc.):

```
Architecture:
On-Premise Database → EPM Integration Agent (installed on-prem) → EPM Cloud

Agent runs as a Windows Service or Linux daemon
Communicates outbound via HTTPS (no inbound ports needed)
```

### Setup

```
1. Download agent from EPM Cloud → Navigator → Downloads
2. Install on a server with access to source database
3. Configure connection in EPM Cloud → Data Integration → Connections
4. Create data integration using agent as source
```

### 🎯 Hands-On: Understanding Agent Architecture

```
Exercise 5: Architecture Diagram
1. Draw the data flow:
   Oracle DB (on-prem) → EPM Agent (on-prem) → HTTPS → EPM Cloud → Essbase
2. List the benefits of the agent approach:

   - Runs on schedule via EPM Automate

   - Agent: Real-time or scheduled automated loads from databases
   - File: One-time loads, manual loads, or when source is a spreadsheet
```

## 🎓 Interview Questions (Oracle Official Level)

**Q: What is the difference between Data Management and Data Integration?**
> Data Management (FDMEE) is the traditional ETL tool with detailed mapping, transformation, and drill-through capabilities. Data Integration is the modern cloud-native tool with direct connections to ERP systems and simplified setup. Data Management is more powerful for complex transformations; Data Integration is simpler for standard loads.

**Q: Walk me through a complete data load process.**
> (1) Define source system in Data Management. (2) Create Import Format defining file structure. (3) Create Location linking source to target cube. (4) Set up dimension mappings (source → target members). (5) Upload file to inbox. (6) Execute: Import → Validate → Export. (7) Verify in form or Smart View.

**Q: What is the EPM Integration Agent and when do you need it?**
> The agent is installed on-premise to connect EPM Cloud to on-premise databases. It initiates outbound HTTPS connections (no inbound ports needed). You need it when the source data is in an on-premise Oracle DB, SQL Server, or other database that can't expose APIs to the cloud.

**Q: A data load shows "50 rows loaded, 10 rejected." How do you investigate?**
> Check the Data Management Process Details log. The error log will show exactly which rows failed and why — typically "Target member not found" (unmapped member), "Invalid number" (bad data), or "Duplicate key" (same intersection twice). Fix mappings or source data and reload.

**Q: What is Smart Push and how does it differ from a Data Map?**
> A Data Map defines HOW data moves between cubes (mapping, members, options). Smart Push is the TRIGGER that automatically executes a Data Map when a user saves a form. Without Smart Push, Data Maps must be run manually or via scripts.
