# 10.02 — Smart View Ad Hoc Analysis: Complete Guide

> **Module:** 10_Smart_View | **Topic:** Ad Hoc Analysis, Drill-Down, Pivoting
> **Audience:** Power User / Consultant

---

## 1. WHY — What Real-World Problem Does This Solve?

**The problem:** A form shows Mumbai's P&L for Q1 2026. The CFO asks: "Why is March revenue 15% below February?" The form doesn't show that level of detail — it only shows the total. The CFO needs to drill into room types, departments, and individual categories. Standard forms are too rigid for exploratory analysis.

**The solution:** Ad Hoc Analysis in Smart View connects directly to the Essbase cube — no form definition constraints. Users can zoom in, zoom out, pivot dimensions, and explore data freely.

## 3. AD HOC OPERATIONS — COMPLETE REFERENCE

### Zoom In (Drill Down)

```
Double-click "Total_Revenue" to see its children:

BEFORE:                          AFTER:
Total_Revenue  8,500,000    →    Room_Revenue     5,200,000
                                  F&B_Revenue      2,100,000
                                  Spa_Revenue        800,000
                                  Other_Revenue      400,000
```

### Zoom Out (Roll Up)

```
Select "Room_Revenue" → Smart View → Zoom Out

BEFORE:                          AFTER:
Room_Revenue     5,200,000  →    Total_Revenue    8,500,000
F&B_Revenue      2,100,000
Spa_Revenue        800,000
```

### Zoom In Options

```
Smart View → Options → Member Options:

Zoom In Level:
  ○ Next Level (children only)         ← Default
  ○ All Levels (descendants to leaf)
  ○ Bottom Level (leaf members only)
  ○ Sibling Level (same-level peers)
```

### Pivot (Move Dimension)

```
Move Entity from POV to Rows:
  Select "Entity" header → Smart View → Pivot

BEFORE (Entity in POV):
  POV: [Mumbai_Hotel]
  
         Jan        Feb        Mar
  Rev    8,500      9,000      7,600

AFTER (Entity in Rows):
         Jan        Feb        Mar
  Mumbai 8,500      9,000      7,600
  Delhi  7,200      7,800      6,900
  B'lore 4,800      5,100      4,500
```

### Keep Only / Remove Only

```
Right-click a member → Keep Only
  → Hides all sibling members, keeps only the selected

Right-click a member → Remove Only
  → Hides only the selected member, keeps siblings
```

### Member Selection Dialog

```
Smart View → Member Selection (button)

Opens a dialog:
  Dimension: Entity
  
  Available Members:         Selected Members:
  ┌────────────────────┐     ┌────────────────┐
  │ All_Hotels         │     │ Mumbai_Hotel    │
  │  ├── Mumbai_Hotel  │ ──► │ Delhi_Hotel     │
  │  ├── Delhi_Hotel   │     │ Chennai_Hotel   │
  │  ├── Bangalore     │     └────────────────┘
  │  ├── Kolkata       │
  │  └── Chennai       │
  └────────────────────┘
  
  Functions:
  @CHILDREN("All_Hotels")
  @DESCENDANTS("All_Hotels")
  @ICHILDREN("All_Hotels")
```

## 5. AD HOC OPTIONS THAT MATTER

| Option | Location | What It Does |
|--------|----------|-------------|
| **Suppress #NoData Rows** | Data Options | Hide rows with all missing data |
| **Suppress Zero Rows** | Data Options | Hide rows with all zeros |
| **Member Name vs Alias** | Member Options | Show technical names or display labels |
| **Preserve Formatting** | Formatting | Keep Excel formatting after refresh |
| **Cell Styles** | Advanced | Color dirty (changed) cells |
| **Zoom In Level** | Member Options | Next Level / All Levels / Bottom / Sibling |
| **Ancestor Position** | Member Options | Where parent appears after zoom |

## 6. AD HOC vs FORMS — WHEN TO USE WHICH

| Feature | Forms | Ad Hoc |
|---------|-------|--------|
| **Structure** | Fixed by admin | User-defined (free exploration) |
| **Drill-down** | Limited | Full zoom in/out |
| **Pivoting** | Not possible | Any dimension, any axis |
| **Business Rules** | On Load/On Save | Not triggered |
| **Formatting** | Server-defined | Excel formatting |
| **Security** | Form-level + dimension | Dimension security only |
| **Best for** | Standard data entry | Exploration, root cause analysis |
| **Speed** | Optimized | Can be slow on large cubes |

## 7. SHOW ME — Hotel Pvt Ltd CFO Analysis Session

```
CFO Question: "Why is March revenue 15% below February?"

  → Default view: All_Hotels, Total_Revenue, FY2026

  → Jan: ₹1,12,00,000
```

## 8. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Zoom in on all dimensions at once | Grid has millions of cells → Excel crashes | Zoom in one dimension at a time |
| Submit from ad hoc without checking | Overwrites data in unexpected intersections | Review changed cells before Submit |
| Not suppressing #NoData | Grid filled with blanks | Enable Suppress Missing Data |
| Ad hoc on wrong cube | Wrong data or "member not found" | Verify cube name (OEP_FS vs OEP_WFP) |
| Pivoting too many dims to rows | Cross-join explosion → timeout | Keep max 2 dims on rows |

## 9. INTERVIEW QUESTIONS

### Beginner
**Q: What is Ad Hoc Analysis in Smart View?**
> Ad Hoc connects directly to the Essbase cube without any form definition. Users can freely: Zoom In (drill to children), Zoom Out (roll to parent), Pivot (move dimensions between axes), Keep/Remove members, and explore any data intersection. It's the tool for root cause analysis, exploratory data investigation, and building custom Excel reports. Unlike forms, ad hoc has no On Save rules — data is submitted directly to the cube.

### Intermediate
**Q: Walk through how a CFO would investigate a revenue drop using Smart View Ad Hoc.**
> Start ad hoc on the FinPlan cube. Zoom in on Period to see monthly breakdown — identify which month dropped. Pivot Entity to rows to see which hotel is responsible. Zoom in on the worst hotel to see revenue by category (Room, F&B, Spa). Compare against prior month and prior year. Finding: Room Revenue in Mumbai dropped 33% due to off-season. Total investigation time: 3-5 minutes. Key skills: Zoom In, Pivot, Keep Only, and reading the grid. This is exactly the kind of analysis forms can't do — forms are structured, ad hoc is free-form.
