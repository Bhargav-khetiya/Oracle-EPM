# 14.01 — EPM Automate Best Practices: Complete Guide

> **Module:** 14_EPM_Automate | **Topic:** Script Patterns, Error Handling, Scheduling
> **Audience:** Service Administrator / DevOps

---

## 1. WHY — Beyond Basic Commands

EPM Automate runs commands fine. But production scripts need: error handling, logging, retry logic, conditional execution, and scheduling. This guide covers the patterns that separate a dev script from a production-grade automation.

## 2. SCRIPT STRUCTURE — THE TEMPLATE

```bash
#!/bin/bash
# ═══════════════════════════════════════════════
# EPM Automate Production Script Template
# Purpose: [describe what this script does]
# Schedule: [when it runs]
# Author: Admin
# Last Updated: 2026-08-13
# ═══════════════════════════════════════════════

# ── Configuration ──
EPM_URL="https://instance.oraclecloud.com"
EPM_DOMAIN="idDomain"
EPM_USER="admin@hotelpvtltd.com"
EPM_PASS="password.epw"  # Encrypted password file
LOG_DIR="/logs/epm"
DATE=$(date +%Y%m%d_%H%M%S)
LOG_FILE="${LOG_DIR}/script_${DATE}.log"
EMAIL_TO="admin@hotelpvtltd.com"
MAX_RETRIES=3

# ── Functions ──
log() { echo "[$(date '+%Y-%m-%d %H:%M:%S')] $1" | tee -a "$LOG_FILE"; }
send_alert() { echo "$1" | mail -s "EPM Alert: $2" "$EMAIL_TO"; }

run_epm() {
    local cmd="$1"
    local attempt=1
    while [ $attempt -le $MAX_RETRIES ]; do
        log "Running: epmautomate $cmd (attempt $attempt)"
        epmautomate $cmd >> "$LOG_FILE" 2>&1
        local rc=$?
        if [ $rc -eq 0 ]; then
            log "✅ Success: $cmd"
            return 0
        fi
        log "⚠️ Failed (rc=$rc), retrying in 30s..."
        sleep 30
        ((attempt++))
    done
    log "❌ FAILED after $MAX_RETRIES attempts: $cmd"
    return 1
}

# ── Main Script ──
log "═══ Script Started ═══"

# Step 1: Login
run_epm "login $EPM_USER $EPM_PASS $EPM_URL $EPM_DOMAIN" || {
    send_alert "Login failed" "CRITICAL"
    exit 1
}

# Step 2: [Your operations here]
run_epm "setsubstvars ALL CurrMonth=Oct" || {
    send_alert "SubVar update failed" "HIGH"
    epmautomate logout
    exit 2
}

# Step 3: Logout
run_epm "logout"

log "═══ Script Completed ═══"
```

## 3. COMMON PATTERNS

### Pattern 1: Monthly Close Automation

```bash
# Step 1: Update SubVars
run_epm "setsubstvars ALL CurrMonth=Oct PriorMonth=Sep ForecastStart=Nov"

# Step 2: Upload and load data
run_epm "uploadfile /data/actuals_oct.csv"
run_epm "importdata DL_Revenue actuals_oct.csv"

# Step 3: Run monthly close ruleset
run_epm "runbusinessrule RS_Monthly_Close RTP_Scenario=Actual RTP_Year=FY2026"

# Step 4: Backup
run_epm "exportsnapshot Post_Close_Oct_2026"
```

### Pattern 2: Daily Data Load

```bash
# Run at 6 AM daily
run_epm "login $USER $PASS $URL $DOMAIN"
run_epm "uploadfile /data/daily_revenue.csv"
run_epm "importdata DL_Daily_Revenue daily_revenue.csv"
run_epm "runbusinessrule CALC_Revenue_Totals"

# Validate: download and check
run_epm "exportdata DE_Validation"
run_epm "downloadfile Validation.csv"

# Check if load was successful
RECORDS=$(wc -l < Validation.csv)
if [ "$RECORDS" -lt 10 ]; then
    send_alert "Only $RECORDS records loaded — check data" "WARNING"
fi

run_epm "logout"
```

### Pattern 3: LCM Migration (DEV → PROD)

```bash
# Export from DEV
epmautomate login dev_admin@hotel.com $PASS $DEV_URL $DOMAIN
epmautomate exportsnapshot "Release_v2.3"
epmautomate downloadfile "Release_v2.3.zip"
epmautomate logout

# Import to PROD
epmautomate login prod_admin@hotel.com $PASS $PROD_URL $DOMAIN
epmautomate uploadfile "Release_v2.3.zip"
epmautomate importsnapshot "Release_v2.3"
epmautomate logout
```

### Pattern 4: User Provisioning Bulk

```bash
# Bulk add users from CSV
while IFS=, read -r email role; do
    run_epm "assignrole $email $role"
    log "Provisioned: $email as $role"
done < /data/new_users.csv
```

## 4. ERROR CODES

| Exit Code | Meaning | Action |
|-----------|---------|--------|
| 0 | Success | Continue |
| 1 | General error | Check log details |
| 2 | Authentication failed | Check credentials |
| 3 | Command not found | Check command syntax |
| 4 | Timeout | Retry or check maintenance |
| 5 | Service unavailable | Instance down — try later |

## 5. SCHEDULING

### Linux (cron)

```bash
# Monthly close — 1st of every month at 3 AM
0 3 1 * * /scripts/epm/monthly_close.sh >> /logs/cron_monthly.log 2>&1

# Daily data load — every day at 6 AM
0 6 * * * /scripts/epm/daily_load.sh >> /logs/cron_daily.log 2>&1

# Weekly backup — every Sunday at 11 PM
0 23 * * 0 /scripts/epm/weekly_backup.sh >> /logs/cron_backup.log 2>&1
```

### Windows (Task Scheduler)

```powershell
# Create scheduled task
$action = New-ScheduledTaskAction -Execute "powershell.exe" `
  -Argument "-File C:\scripts\epm\monthly_close.ps1"
$trigger = New-ScheduledTaskTrigger -Monthly -DaysOfMonth 1 -At 3:00AM
Register-ScheduledTask -TaskName "EPM_Monthly_Close" `
  -Action $action -Trigger $trigger -User "SYSTEM"
```
