## 🏢 Overview

**EPM Automate** is a command-line utility provided by Oracle for automating routine Oracle EPM Cloud tasks — data loading, rule execution, backups, environment refresh, user provisioning, and scheduling. It's the admin's Swiss Army knife for EPM Cloud operations.

---

## 📌 Installation

```
Download: EPM Cloud → Navigator → Downloads → EPM Automate
Install: Unzip to a directory (e.g., C:\EPMAutomate)
Add to PATH: Add C:\EPMAutomate\bin to system PATH
Java: Requires Java 8+ (JRE)
```

## 📌 Authentication — Login/Logout

```bash
# Login
epmautomate login admin@company.com Password123 https://mycompany.pbcs.us2.oraclecloud.com

# Login with encrypted password file
epmautomate encrypt Password123 EncKey123 C:\EPM\password.epw
epmautomate login admin@company.com C:\EPM\password.epw https://mycompany.pbcs.us2.oraclecloud.com EncKey123

# Logout
epmautomate logout
```

### 💡 Logic & Purpose
EPM Automate is a local client utility that speaks REST API to the Oracle Cloud. Because it is designed for unattended batch scripts, it requires a mechanism to pass credentials securely without a human typing them in. Oracle provides the `encrypt` command to convert your plain-text password into a `.epw` (Encrypted Password) file, secured by a custom encryption key, so that scheduled tasks can authenticate safely.

### 🌀 Confusion Resolution
> **Misconception:** "I wrote a batch script using my plain text password: `epmautomate login admin@co.com MyPass123 url`. It works perfectly on my laptop. I'll just deploy this script to the production server."
> **Reality:** NEVER put plain-text passwords in production batch scripts! If anyone gains read-access to that server folder, your EPM Cloud Service Administrator password is exposed. You MUST use the `epmautomate encrypt` command to generate a `.epw` file, and reference that file in your production script.

### 😈 Twisted Interview Question
**Question:** An administrator successfully creates an encrypted password file (`pwd.epw`) on their local laptop using the key `Key123`. They copy both the batch script and the `pwd.epw` file to the production Windows server. When the Windows Task Scheduler runs the script using `Key123`, the login fails with an "Invalid credentials" error. Why?
> **Answer:** The `epmautomate encrypt` algorithm generates the encryption hash based on the **specific machine's hardware profile** (MAC address/CPU ID). An encrypted password file generated on Laptop A cannot be decrypted by Server B, even if you know the key! The administrator must physically run the `epmautomate encrypt` command ON the production server to generate a valid `.epw` file for that specific machine.

## 📌 Common Automation Scripts

### Script 1: Daily Actuals Load (Windows Batch)

```batch
@echo off
SET EPM_URL=https://mycompany.pbcs.us2.oraclecloud.com
SET EPM_USER=admin@company.com
SET EPM_PWD=C:\EPM\password.epw
SET EPM_KEY=EncKey123

echo [%DATE% %TIME%] Starting Daily Actuals Load >> C:\EPM\logs\daily_load.log

:: Login
epmautomate login %EPM_USER% %EPM_PWD% %EPM_URL% %EPM_KEY%
IF ERRORLEVEL 1 (echo LOGIN FAILED >> C:\EPM\logs\daily_load.log & exit /b 1)

:: Upload file
epmautomate uploadFile C:\Data\actuals_export.csv
IF ERRORLEVEL 1 (echo UPLOAD FAILED >> C:\EPM\logs\daily_load.log & goto :LOGOUT)

:: Import data
epmautomate importData LoadActuals
IF ERRORLEVEL 1 (echo IMPORT FAILED >> C:\EPM\logs\daily_load.log & goto :LOGOUT)

:: Run calculation
epmautomate runBusinessRule "Aggregate_Actuals"
IF ERRORLEVEL 1 (echo CALC FAILED >> C:\EPM\logs\daily_load.log & goto :LOGOUT)

echo [%DATE% %TIME%] Daily Load COMPLETED SUCCESSFULLY >> C:\EPM\logs\daily_load.log

:LOGOUT
epmautomate logout
```

### Script 2: Monthly Close Process

```batch
@echo off
echo === Monthly Close Process: %DATE% ===

epmautomate login %EPM_USER% %EPM_PWD% %EPM_URL% %EPM_KEY%

:: Step 1: Update substitution variable
epmautomate setSubstVars ALL CurrentMonth=Jul

:: Step 2: Load exchange rates
epmautomate uploadFile rates_jul.csv
epmautomate importData LoadRates

:: Step 3: Run monthly close rule set
epmautomate runRuleSet "Monthly_Close_Process"

:: Step 4: Export reports
epmautomate exportData ExportPL
epmautomate downloadFile PL_Report.csv

:: Step 5: Create backup
epmautomate exportSnapshot "Backup_Jul_2026"

epmautomate logout
echo === Monthly Close COMPLETE ===
```

### Script 3: Environment Refresh (DEV from PROD)

```batch
@echo off
echo === Environment Refresh: PROD → DEV ===

:: Login to PROD
epmautomate login admin@co.com prod_pwd.epw https://prod.pbcs.oraclecloud.com EncKey

:: Export snapshot from PROD  
epmautomate exportSnapshot "PROD_Snapshot_%DATE%"

:: Logout from PROD
epmautomate logout

:: Login to DEV
epmautomate login admin@co.com dev_pwd.epw https://dev.pbcs.oraclecloud.com EncKey

:: Copy snapshot from PROD to DEV
epmautomate copySnapshotFromInstance "PROD_Snapshot_%DATE%" admin@co.com prod_pwd.epw https://prod.pbcs.oraclecloud.com EncKey

:: Recreate DEV environment
epmautomate recreate -f

:: Import snapshot
epmautomate importSnapshot "PROD_Snapshot_%DATE%" userPassword=Welcome1

epmautomate logout
echo === Refresh COMPLETE ===
```

## 📌 Scheduling with Windows Task Scheduler

```
1. Open Task Scheduler
2. Create Basic Task → "Daily EPM Load"
3. Trigger: Daily at 6:00 AM
4. Action: Start a Program
   - Program: C:\EPM\scripts\daily_load.bat
   - Start in: C:\EPM\scripts\
5. Conditions: Start only if network available
6. Settings: Allow task to run on demand
```

## ⭐ Best Practices

| Practice | Reason |
|----------|--------|
| Use encrypted password files | Security — no plain text |
| Log all operations with timestamps | Audit trail and debugging |
| Check ERRORLEVEL after each command | Catch failures early |
| Schedule during off-peak hours | Minimize user impact |
| Test scripts in DEV first | Avoid production issues |
| Create backups before destructive operations | Recovery safety net |
| Use service accounts, not personal accounts | Continuity when staff changes |

## 🎓 Interview Questions

**Q: What is EPM Automate and when do you use it?**
> A: EPM Automate is a command-line utility for automating EPM Cloud tasks. Use it for scheduled data loads, monthly close processes, environment refresh, backups, and any repetitive administration task.

**Q: How do you secure passwords in EPM Automate scripts?**
> A: Use the `encrypt` command to create an encrypted password file (.epw), then reference the file in the login command instead of plain-text passwords.

**Q: How would you automate a daily data load?**
> A: Create a batch script that: (1) logs in, (2) uploads the data file, (3) runs importData, (4) runs a calculation rule, (5) logs out. Schedule it with Windows Task Scheduler or cron.

**Q: How do you refresh DEV from PROD?**
> A: Export snapshot from PROD → Copy snapshot to DEV → Recreate DEV environment → Import snapshot. The `copySnapshotFromInstance` command handles cross-environment transfers.
