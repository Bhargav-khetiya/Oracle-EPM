## 📌 Every EPM Automate Command — Categorized

### Authentication Commands

| Command | Syntax | Description |
|---------|--------|-------------|
| `login` | `epmautomate login user@co.com password_file URL key` | Start session |
| `logout` | `epmautomate logout` | End session |
| `encrypt` | `epmautomate encrypt "Password" KEY_NAME filepath` | Create encrypted password |

### Setup: Create Encrypted Password

```batch
REM One-time setup
epmautomate encrypt "MyP@ssw0rd" MY_KEY "C:\epm\pwd.epw"

REM From now on, use:
epmautomate login user@company.com "C:\epm\pwd.epw" "https://company.pbcs.us2.oraclecloud.com" MY_KEY
```

| Command | Syntax | Description |
|---------|--------|-------------|
| `importData` | `epmautomate importData "RuleName" "FileName"` | Load data into cube |
| `exportData` | `epmautomate exportData "RuleName" "FileName"` | Export data from cube |
| `importMetadata` | `epmautomate importMetadata "RuleName"` | Load dimension members |

| `clearData` | `epmautomate clearData CubeName` | Clear all data in cube |

### 💡 Logic & Purpose
Data Operations in EPM Automate are essentially wrappers around the Data Management backend. When you run `importData`, EPM Automate doesn't parse the file itself; it uploads the file to the cloud inbox and tells the Cloud server to trigger the predefined Data Load Rule.

### 🌀 Confusion Resolution
> **Misconception:** "I want to clear data for just the 'Budget' scenario before I run my import. I'll use `epmautomate clearData FinPlan`."
> **Reality:** DO NOT run `clearData` unless you intend to wipe the ENTIRE cube! The EPM Automate `clearData` command is the equivalent of a nuclear bomb—it clears every single intersection in the specified cube. If you want to clear a specific slice (like 'Budget' -> 'FY26'), you must write a Business Rule with a `CLEARDATA` command inside a `FIX` statement, and use `epmautomate runBusinessRule` instead!

### 😈 Twisted Interview Question
**Question:** A batch script is scheduled to run every night. It executes `epmautomate uploadFile actuals.csv` and then `epmautomate importData LoadActuals`. A user complains that Friday's data wasn't loaded. The admin checks the server inbox and sees `actuals.csv` has a modified date of Friday. However, the EPM Automate log shows the `uploadFile` command failed on Friday night. How could the file be there if the upload failed—
> **Answer:** The file in the inbox is from *Thursday*! The `importData` command does not inherently know *which* file to use—it just uses whatever file name is defined inside the "LoadActuals" rule on the server. Because the Friday upload failed, the rule ran anyway on Friday night, but it re-processed the stale Thursday file that was still sitting in the inbox. Admins must handle EPM Automate exit codes (`IF ERRORLEVEL 1`) and abort the script if the upload fails!

## 📌 Complete Automation Scripts

### Script 1: Daily Actuals Load

```batch
@echo off
REM ============================================
REM  Daily Actuals Load Script
REM  Schedule: Daily at 6:00 AM via Task Scheduler
REM ============================================

SET EPM_URL=https://company.pbcs.us2.oraclecloud.com
SET EPM_USER=epm_admin@company.com
SET EPM_PWD=C:\epm\pwd.epw
SET EPM_KEY=MY_KEY
SET LOG_FILE=C:\epm\logs\daily_load_%date:~-4%%date:~4,2%%date:~7,2%.log

echo [%time%] Starting Daily Actuals Load >> %LOG_FILE%

REM Step 1: Login
epmautomate login %EPM_USER% %EPM_PWD% %EPM_URL% %EPM_KEY%
IF ERRORLEVEL 1 (
    echo [%time%] ERROR: Login failed >> %LOG_FILE%
    exit /b 1
)

REM Step 2: Upload data file
epmautomate uploadFile "C:\data\actuals_daily.csv"
IF ERRORLEVEL 1 (
    echo [%time%] ERROR: Upload failed >> %LOG_FILE%
    epmautomate logout
    exit /b 2
)

REM Step 3: Import data
epmautomate importData "Load_Actuals" "actuals_daily.csv"
IF ERRORLEVEL 1 (
    echo [%time%] ERROR: Import failed >> %LOG_FILE%
    epmautomate logout
    exit /b 3
)

REM Step 4: Run aggregation
epmautomate runBusinessRule "BR_Aggregate_All"
IF ERRORLEVEL 1 (
    echo [%time%] WARNING: Aggregation had issues >> %LOG_FILE%
)

REM Step 5: Run variance calculation
epmautomate runBusinessRule "BR_Calculate_Variance"

REM Step 6: Logout
epmautomate logout

echo [%time%] Daily Actuals Load COMPLETED successfully >> %LOG_FILE%
exit /b 0
```

### Script 2: Monthly Close Automation

```batch
@echo off
REM ============================================
REM  Monthly Close Script
REM  Schedule: 1st of each month at 11:00 PM
REM ============================================

SET EPM_URL=https://company.pbcs.us2.oraclecloud.com
SET EPM_USER=epm_admin@company.com
SET EPM_PWD=C:\epm\pwd.epw
SET EPM_KEY=MY_KEY
SET LOG_FILE=C:\epm\logs\monthly_close_%date:~-4%%date:~4,2%.log

echo [%time%] Starting Monthly Close >> %LOG_FILE%

epmautomate login %EPM_USER% %EPM_PWD% %EPM_URL% %EPM_KEY%
IF ERRORLEVEL 1 (echo LOGIN FAILED >> %LOG_FILE% & exit /b 1)

REM Step 1: Backup before close
echo [%time%] Creating backup... >> %LOG_FILE%
epmautomate exportSnapshot "PreClose_%date:~-4%%date:~4,2%"

REM Step 2: Update substitution variables
echo [%time%] Updating variables... >> %LOG_FILE%
epmautomate setSubstVars ALL "PriorMonth=Jun"
epmautomate setSubstVars ALL "CurrentMonth=Jul"
epmautomate setSubstVars ALL "CurrentQuarter=Q3"

REM Step 3: Load final actuals
echo [%time%] Loading actuals... >> %LOG_FILE%
epmautomate uploadFile "C:\data\actuals_final.csv"
epmautomate importData "Load_Actuals_Final" "actuals_final.csv"

REM Step 4: Load exchange rates
echo [%time%] Loading rates... >> %LOG_FILE%
epmautomate uploadFile "C:\data\exchange_rates.csv"
epmautomate importData "Load_Exchange_Rates" "exchange_rates.csv"

REM Step 5: Run monthly close rule set
echo [%time%] Running close calculations... >> %LOG_FILE%
epmautomate runRuleSet "RS_Monthly_Close"
IF ERRORLEVEL 1 (
    echo [%time%] ERROR: Monthly close rules failed >> %LOG_FILE%
    epmautomate sendMail "epm_team@company.com" "EPM Monthly Close FAILED" "Check logs"
    epmautomate logout
    exit /b 5
)

REM Step 6: Export reports
echo [%time%] Exporting reports... >> %LOG_FILE%
epmautomate exportData "Export_PnL_Summary" "pnl_summary.csv"
epmautomate downloadFile "pnl_summary.csv" "C:\reports\"

REM Step 7: Send success notification
epmautomate sendMail "finance@company.com" "Monthly Close Complete" "All calculations completed successfully"

epmautomate logout
echo [%time%] Monthly Close COMPLETED >> %LOG_FILE%
exit /b 0
```

### Script 3: Environment Refresh (DEV from PROD)

```batch
@echo off
REM ============================================
REM  Refresh DEV from PROD
REM ============================================

SET PROD_URL=https://company.pbcs.us2.oraclecloud.com
SET DEV_URL=https://company-test.pbcs.us2.oraclecloud.com
SET USER=epm_admin@company.com
SET PWD=C:\epm\pwd.epw
SET KEY=MY_KEY

REM Step 1: Export PROD snapshot
epmautomate login %USER% %PWD% %PROD_URL% %KEY%
epmautomate exportSnapshot "Refresh_Source"
epmautomate logout

REM Step 2: Copy snapshot to DEV
epmautomate login %USER% %PWD% %DEV_URL% %KEY%
epmautomate copySnapshotFromInstance "Refresh_Source" %USER% %PWD% %PROD_URL% %KEY%

REM Step 3: Recreate DEV and import
epmautomate recreate -f
epmautomate importSnapshot "Refresh_Source"

epmautomate logout
echo DEV refresh complete!
```

## 📌 Windows Task Scheduler Setup

```
1. Open Task Scheduler → Create Task
2. General tab: Name = "EPM_Daily_Load", Run whether user is logged on or not
3. Triggers tab: Daily, 6:00 AM
4. Actions tab:
   Program: C:\epm\scripts\daily_load.bat
   Start in: C:\epm\scripts\
5. Settings: Allow task to be run on demand, stop if runs longer than 2 hours
```

### 🎯 Hands-On: Complete Automation

```
Exercise 1: Setup EPM Automate
1. Download epmautomate from EPM Cloud → Navigator → Downloads
2. Install (extract zip, add to PATH)
3. Create encrypted password: epmautomate encrypt "password" MY_KEY "C:\epm\pwd.epw"
4. Test login: epmautomate login user@co.com "C:\epm\pwd.epw" URL MY_KEY
5. Run: epmautomate listFiles → verify connection works
6. Logout: epmautomate logout

Exercise 2: Build Daily Load Script
1. Create the daily load script from Script 1 above
2. Test manually by running from command prompt
3. Verify in Job Console → data load should appear
4. Schedule via Task Scheduler → daily at 6 AM

Exercise 3: Build Monthly Close Script
1. Adapt Script 2 for your application
2. Test each step individually first
3. Run the complete script
4. Verify all calculations ran correctly

Exercise 4: Error Handling Test
1. Intentionally break the script (wrong file name)
2. Run → verify it fails gracefully with error logging
3. Check the log file → verify error is recorded
4. Fix the error → re-run → verify success

Exercise 5: Environment Refresh
1. Export a snapshot from your application
2. List snapshots: epmautomate listSnapshots
3. Download the snapshot
4. If you have a test environment: import and verify
```

## 🎓 Interview Questions

**Q: Write a complete EPM Automate script for a daily data load.**
> Login (with encrypted password) → Upload CSV → Import Data (run load rule) → Run Business Rule (aggregation) → Logout. Include ERRORLEVEL checks after each step, logging to a file, and email notification on failure.

**Q: How do you schedule EPM Automate scripts—**
> On Windows: Windows Task Scheduler. On Linux: cron jobs. The script runs as a batch file (.bat) or shell script (.sh). Set "Run whether user is logged on or not" in Task Scheduler.

**Q: How do you refresh a DEV environment from PROD—**
> Export PROD snapshot → Copy snapshot to DEV using copySnapshotFromInstance → Recreate DEV → Import snapshot. This gives DEV an exact copy of PROD data, metadata, and configuration.
