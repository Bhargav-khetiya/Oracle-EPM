## 📌 Authentication

### Basic Auth (Base64)

```
Username: admin@company.com
Password: MyP@ssword
Identity Domain: mycompany

Header:
Authorization: Basic base64("admin@company.com:MyP@ssword")
```

### 💡 Logic & Purpose
Authentication in the EPM REST API relies on stateless HTTP verification. The `Authorization` header must be sent with every single request because the server does not store session cookies for API clients. The `Basic` scheme wraps the username and password in a Base64 string. Note: Base64 is an *encoding* format, not encryption. Anyone intercepting the HTTP request can easily decode it back to plain text, which is why HTTPS (TLS) is absolutely mandatory.

### 🌀 Confusion Resolution
> **Misconception:** "My company uses SSO (Single Sign-On). When I try to run my Python REST script with my corporate username and password, it returns a 401 Unauthorized error. I'll just encode my SSO token instead."
> **Reality:** The standard EPM REST API `Basic` authentication DOES NOT natively understand corporate SSO passwords unless your company's Identity Provider explicitly allows basic auth pass-through (which most disable for security). If your environment is federated via SSO, you must use a specialized **OAuth 2.0 Token** (generated via OCI Identity / IDCS) or an **App Password**, rather than your raw corporate password in the Base64 string.

### 😈 Twisted Interview Question
**Question:** A consultant writes an automation script that successfully creates a Base64 string from their username (`admin`) and password (`Pass123`). However, when they send the POST request to EPM Cloud, the server rejects it. The consultant confirms the URL and password are correct. What crucial component is missing from their Base64 string structure?
> **Answer:** In Oracle EPM Cloud (unlike on-premises Hyperion), the username string MUST include the **Identity Domain** if the environment is older (classic architecture), or it must be fully qualified. In many cases, if you don't prefix the username with the identity domain (`IdentityDomain.username:password`), the IDCS router cannot resolve which tenant the user belongs to and rejects the authentication outright.

### PowerShell Auth Setup

```powershell
$user = "admin@company.com"
$pass = "MyP@ssword"
$pair = "${user}:${pass}"
$bytes = [System.Text.Encoding]::ASCII.GetBytes($pair)
$base64 = [System.Convert]::ToBase64String($bytes)
$headers = @{
    "Authorization" = "Basic $base64"
    "Content-Type" = "application/json"
}
$baseUrl = "https://company.pbcs.us2.oraclecloud.com"
```

## 📊 Practical Scripts — Complete Working Examples

### PowerShell: Run a Business Rule

```powershell
# Setup
$user = "admin@company.com"
$pass = "MyP@ssword"
$base64 = [System.Convert]::ToBase64String([System.Text.Encoding]::ASCII.GetBytes("${user}:${pass}"))
$headers = @{ "Authorization" = "Basic $base64"; "Content-Type" = "application/json" }
$baseUrl = "https://company.pbcs.us2.oraclecloud.com"

# Run business rule
$body = @{
    jobType = "RULES"
    jobName = "BR_Calculate_Revenue"
    parameters = @{
        "Entity" = "E10001"
    }
} | ConvertTo-Json

$response = Invoke-RestMethod -Uri "$baseUrl/HyperionPlanning/rest/v3/applications/MyApp/jobs" `
    -Method POST -Headers $headers -Body $body

$jobId = $response.jobId
Write-Host "Job started: $jobId"

# Poll for completion
do {
    Start-Sleep -Seconds 5
    $status = Invoke-RestMethod -Uri "$baseUrl/HyperionPlanning/rest/v3/applications/MyApp/jobs/$jobId" `
        -Method GET -Headers $headers
    Write-Host "Status: $($status.status)"
} while ($status.status -eq "Processing")

Write-Host "Final status: $($status.status)"
```

### PowerShell: Import Data

```powershell
# Step 1: Upload file
$filePath = "C:\data\actuals.csv"
$fileName = "actuals.csv"

$uploadUrl = "$baseUrl/interop/rest/v3/files/$fileName"
$fileBytes = [System.IO.File]::ReadAllBytes($filePath)

Invoke-RestMethod -Uri $uploadUrl -Method POST -Headers $headers `
    -Body $fileBytes -ContentType "application/octet-stream"

# Step 2: Run import
$importBody = @{
    jobType = "IMPORT_DATA"
    jobName = "Load_Actuals"
    parameters = @{
        importFileName = $fileName
    }
} | ConvertTo-Json

$response = Invoke-RestMethod -Uri "$baseUrl/HyperionPlanning/rest/v3/applications/MyApp/jobs" `
    -Method POST -Headers $headers -Body $importBody

Write-Host "Import job: $($response.jobId), Status: $($response.status)"
```

### Python: Complete Automation

```python
import requests
import time
import json

# Setup
base_url = "https://company.pbcs.us2.oraclecloud.com"
app = "MyApp"
session = requests.Session()
session.auth = ("admin@company.com", "MyP@ssword")
session.headers.update({"Content-Type": "application/json"})

def run_job(job_type, job_name, params=None):
    """Run any EPM job and wait for completion"""
    body = {"jobType": job_type, "jobName": job_name}
    if params:
        body["parameters"] = params
    
    # Start job
    r = session.post(f"{base_url}/HyperionPlanning/rest/v3/applications/{app}/jobs", 
                      json=body)
    job_id = r.json()["jobId"]
    print(f"Started {job_name} (Job ID: {job_id})")
    
    # Wait for completion
    while True:
        time.sleep(5)
        status = session.get(
            f"{base_url}/HyperionPlanning/rest/v3/applications/{app}/jobs/{job_id}"
        ).json()
        if status["status"] != "Processing":
            break
    
    print(f"Completed: {status['status']}")
    return status

# Example usage
run_job("RULES", "BR_Calculate_Revenue", {"Entity": "E10001"})
run_job("CUBE_REFRESH", "Refresh")
run_job("IMPORT_DATA", "Load_Actuals", {"importFileName": "actuals.csv"})
```

## 🎓 Interview Questions

**Q: How do you authenticate to EPM Cloud REST API?**
> Basic Authentication with Base64-encoded credentials in the Authorization header. The format is `Basic base64(username:password)`. All requests must go over HTTPS.

**Q: How do you run a business rule via REST API?**
> POST to `/HyperionPlanning/rest/v3/applications/{app}/jobs` with body `{"jobType": "RULES", "jobName": "RuleName"}`. The response includes a jobId. Poll GET `/jobs/{jobId}` until status != "Processing".

**Q: What are the advantages of REST API over EPM Automate?**
> REST API: Can be called from ANY programming language, embedded in web apps, integrated with CI/CD pipelines, supports webhooks. EPM Automate: Simpler for batch scripts, no coding required, built-in error handling. Choose REST for integration, EPM Automate for standalone automation.
