# 15.02 — Daily Maintenance and Audit: Complete Guide

> **Module:** 15_Administration | **Topic:** Daily Maintenance Window, Audit Trail, Activity Monitoring
> **Audience:** Service Administrator

---

## 1. WHY — What Real-World Problem Does This Solve—

**The problem:** Oracle Cloud takes the application offline every night for a 1-hour maintenance window. During this time, users can't access the system. If critical batch jobs overlap with maintenance, they fail. Without understanding the maintenance window, admins schedule jobs that conflict and users file complaints.

**The solution:** Understand the daily maintenance window, schedule around it, and use audit/activity reporting to monitor system health.

---

## 2. DAILY MAINTENANCE WINDOW

### What Happens During Maintenance

```
Oracle EPM Cloud performs automatic daily maintenance:

┌─ Daily Maintenance (1 hour window) ──────────────────────────────┐
│                                                                   │
│  Step 1: Application backup (automatic)                          │
│  Step 2: Index optimization                                      │
│  Step 3: Essbase cube optimization                               │
│  Step 4: Security cache refresh                                  │
│  Step 5: Temporary file cleanup                                  │
│  Step 6: Essbase restructure (if pending outline changes)        │
│                                                                   │
│  Duration: ~30-60 minutes                                        │
│  Impact: Application UNAVAILABLE during maintenance              │
│  Schedule: Set by admin (default: 6:00 AM local time)            │
└───────────────────────────────────────────────────────────────────┘
```

### Setting the Maintenance Time

```
Navigator → Application → Settings → Maintenance

Maintenance Start Time: [2:00 AM ▾]  (choose a time when users are offline)

For Hotel Pvt Ltd (India):
  Users work 9 AM - 9 PM IST
  Set maintenance: 2:00 AM IST (midnight UTC)
  Users never experience downtime
```

### Skip or Manage Maintenance

```bash
# Skip today's maintenance (emergency — use sparingly)
epmautomate skipdailymaintenance

# Replay changes made during maintenance
epmautomate replay "2026-08-13T02:00:00"

# Run maintenance now (during off-hours)
epmautomate runDailyMaintenance
```

## 3. ACTIVITY REPORTS

### What They Show

```
Navigator → Monitor and Explore → Activity Reports

Reports available:
  ├── Access Log         → Who logged in, when, from where
  ├── Invalid Login      → Failed login attempts
  ├── Provisioning       → Role assignments and changes
  ├── Task List Status   → Task completion tracking
  ├── Data Load          → Import/export history
  └── Form Usage         → Which forms are opened most/least
```

### Activity Report Columns

| Report | Key Columns | Use Case |
|--------|------------|----------|
| **Access Log** | User, Login Time, Duration, IP Address | Track user sessions |
| **Invalid Login** | User, Attempt Time, IP, Reason | Detect brute force |
| **Provisioning** | User, Role, Action (Add/Remove), Date | Audit trail for compliance |
| **Data Load** | File, Status, Records, Errors | Data quality monitoring |
| **Form Usage** | Form Name, User, Open Count, Duration | Identify unused forms |

## 4. AUDIT TRAIL

### What Gets Audited

```
Auditable events:
  ├── User login/logout
  ├── Form data saves
  ├── Business rule execution
  ├── Dimension member changes (add/rename/delete)
  ├── Security changes (access grants/revokes)
  ├── Variable changes (SubVar updates)
  ├── LCM operations (export/import)
```

## 5. ADMIN DAILY CHECKLIST

```
Morning Routine (9:00 AM):
  ☐ Check maintenance completed successfully (Activity Reports)
  ☐ Check Jobs Console for overnight job failures
  ☐ Verify substitution variables are correct
  ☐ Check disk usage / application size
  ☐ Review any user-reported issues

Weekly Routine (Monday):
  ☐ Review Activity Reports for unusual access patterns
  ☐ Check form usage — identify unused forms for cleanup
  ☐ Review failed login attempts
  ☐ Verify backup snapshots exist for the past 7 days
  ☐ Check Application Statistics (block count, fragmentation)

Monthly Routine (1st of month):
  ☐ Update substitution variables (CurrMonth, PriorMonth, etc.)
  ☐ Run CLEARBLOCK ALL (clean up empty blocks)
  ☐ Review and optimize slow-performing rules
  ☐ Remove unused forms/rules/dashboards
  ☐ Verify security assignments (new hires, departures)
  ☐ Archive old snapshots (keep 12-month rolling)
```

## 7. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Scheduling batch jobs during maintenance | Jobs fail with timeout | Schedule 2 hours before or after maintenance |
| Not checking jobs after maintenance | Failed jobs go unnoticed | Morning checklist includes job review |
| Maintenance during business hours | Users can't access system | Set maintenance to 2-4 AM local time |
| Audit not enabled | No trail for compliance | Enable audit on Day 1 |
| Never cleaning up old snapshots | Storage fills up | Delete snapshots older than 90 days |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: What is the daily maintenance window and why does it matter—**
> Oracle EPM Cloud automatically takes the application offline for ~1 hour daily for backup, optimization, and cleanup. During this time, users cannot access the system. Admins must schedule it during off-hours (typically 2-4 AM). Any batch jobs or data loads running during maintenance will fail. Key admin responsibility: set the maintenance time correctly and never schedule overlapping operations.

### Intermediate
**Q: Design the admin monitoring routine for Hotel Pvt Ltd's EPBCS production environment.**
> **Daily (9 AM):** Check maintenance completion, review Jobs Console for overnight failures, verify SubVars are correct. **Weekly (Monday):** Review Activity Reports for unusual access, check form usage metrics, review failed logins, verify weekly backups exist. **Monthly (1st):** Update SubVars, run CLEARBLOCK ALL, review Application Statistics, clean up unused artifacts, verify security for personnel changes, archive old snapshots. **Automation:** Create an EPM Automate script that emails the admin daily with: maintenance status, job failures, block count, and fragmentation percentage.
