# 15.04 — Dynamic Smart Lists and Action Context: Complete Guide

> **Module:** 15_Administration | **Topic:** Smart Lists + Action Menu Integration
> **Audience:** Service Administrator

---

## 1. WHY — What Real-World Problem Does This Solve—

**The problem:** A planner enters data and needs to tag rows with a status — "Draft", "Reviewed", "Approved". Using free-text comments leads to inconsistency: "approved", "Approved", "APPROVED", "Aprvd". And what if the status should trigger an action — like automatically notifying the manager when status changes to "Reviewed"—

**The solution:** Smart Lists provide **dropdown selections** with fixed values in form cells. When combined with Action Menus and conditional formatting, they create interactive, workflow-driven forms.

## 2. SMART LISTS — COMPLETE MECHANICS

### Creating a Smart List

```
Navigator → Create and Manage → Smart Lists → Create

Smart List Name: BudgetStatus
Labels and Values:
  ID: 1  →  Label: "Draft"
  ID: 2  →  Label: "In Review"
  ID: 3  →  Label: "Approved"
  ID: 4  →  Label: "Rejected"
  ID: -1 →  Label: "#MISSING" (default for empty cells)

```
Dimension Editor → Select Account member → Properties:

Data Type: Smart List ▾

## 3. SMART LISTS IN BUSINESS RULES

### Reading Smart List Values

```essbase
/* Smart Lists are stored as numbers (IDs) in Essbase */
/* Draft=1, In Review=2, Approved=3, Rejected=4 */

FIX("Budget", "Working", &CurrYear)
  FIX(@RELATIVE("All_Hotels", 0))
    IF("Budget_Status" == 3)  /* 3 = Approved */
      "Locked" = 1;  /* Lock the budget */
    ENDIF
  ENDFIX
ENDFIX
```

### Reading Smart Lists in Groovy

```groovy
operation.grid.dataCellIterator({DataCell cell ->
    if (cell.getMemberName("Account") == "Budget_Status") {
        def statusId = cell.data as int
        def statusLabel = cell.getSmartListValue()  // "Approved"
        
        if (statusLabel == "Approved") {
            // Trigger approval workflow
            println "Budget approved for ${cell.getMemberName('Entity')}"
        }
    }
})
```

## 4. ACTION MENUS — COMPLETE MECHANICS

### What They Are
Action Menus (Context Menus) are right-click menus on forms that provide quick access to:
- Other forms (drill-through)
- Business rules (launch with context)
- URLs (open external links)
- Supporting details (cell documents)

### Creating an Action Menu

```
Navigator → Create and Manage → Action Menus → Create

Action Menu Name: Revenue_Actions
Menu Items:
  1. "View Room Details" → Type: Form → Target: Room_Revenue_Detail
  2. "Run Revenue Forecast" → Type: Business Rule → Target: Calculate_Forecast
  3. "Open Booking System" → Type: URL → Target: https://booking.hotelpvtltd.com
  4. ─── (separator) ───
  5. "View Supporting Details" → Type: Supporting Details
```

### Associating with a Form

```
Form Designer → Other Options → Context Menu: [Revenue_Actions ▾]

User right-clicks a cell on the form:
  ┌──────────────────────────────┐
  │ View Room Details        →   │  (opens another form)
  │ Run Revenue Forecast     →   │  (launches rule with form context)
  │ Open Booking System      →   │  (opens URL in new tab)
  │ ──────────────────────────── │
  │ View Supporting Details  →   │  (shows cell documents)
  └──────────────────────────────┘
```

## 5. CONDITIONAL ACTION MENUS

You can make menu items context-sensitive — show different options based on the cell's dimension context:

```
Menu Item: "View Department P&L"
  Show when: Account dimension = any member
  Hide when: Entity dimension = "All_Hotels" (only for specific hotels)

Menu Item: "Approve Budget"
  Show when: Smart List value = "In Review" (show only when ready for approval)
  Hide when: Smart List value = "Approved" or "Draft"
```

## 7. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Smart List ID = 0 | Displays as blank, confused with #MISSING | Start IDs at 1 |
| Forgot to link Smart List to member | Member shows numbers (1,2,3) not labels | Set Data Type = Smart List in member properties |
| Hard-coded IDs in rules | Rule breaks if Smart List order changes | Use @CalcMgrIsValidSLMember for validation |
| Action Menu not associated with form | Right-click shows default menu | Set Context Menu in Other Options |
| Smart List member not on form | Users can't see the status | Add the Smart List member to form rows |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: What is a Smart List and how is it stored in Essbase—**
> A Smart List is a dropdown selector in form cells that displays text labels (like "Draft", "Approved") but stores **numeric IDs** in Essbase (1, 2, 3, 4). To use it, you create the Smart List, then assign it to an Account member by setting the member's Data Type to "Smart List." In business rules, you compare against the numeric ID: `IF("Status" == 3)` for "Approved."

### Intermediate
**Q: Design a budget approval workflow using Smart Lists and Action Menus for Hotel Pvt Ltd.**
> (1) Create Smart List: BudgetStatus with Draft(1), In Review(2), Approved(3), Rejected(4). (2) Create Account member "Budget_Status" with Data Type = Smart List. (3) Add format rules: color-code rows by status (Green=Approved, Yellow=Review, Red=Rejected). (4) Create Action Menu with items: "Submit for Review", "Approve", "Reject" — each linked to a rule that sets the status ID. (5) Associate the Action Menu with the budget entry form. Result: Planners enter data, right-click → "Submit for Review." GM reviews, right-click → "Approve." The row turns green. No separate approval system needed.
