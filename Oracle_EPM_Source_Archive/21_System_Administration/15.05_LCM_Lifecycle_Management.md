# 15.05 — LCM Lifecycle Management: Complete Guide

> **Module:** 15_Administration | **Topic:** LCM Export/Import, Migration, Backup/Restore
> **Audience:** Service Administrator

---

## 1. WHY — What Real-World Problem Does This Solve—

**The problem:** You've built a perfect app in DEV — 200 forms, 50 rules, 20 dashboards. Now you need to move it to TEST, then to PROD. Without LCM, you'd recreate everything manually — 3 environments × 270 artifacts = 810 manual operations. One typo = broken production.

**The solution:** Lifecycle Management (LCM) exports the **entire application** (or selected parts) as a snapshot file, which can be imported into another environment.

### Via EPM Automate (Automation)

```bash
# Export snapshot
epmautomate exportsnapshot "Backup_Aug2026"

# List available snapshots
epmautomate listsnapshots

# Import snapshot
epmautomate importsnapshot "Backup_Aug2026"

# Copy to another environment (migration)
epmautomate copysnapshot "Backup_Aug2026" \
  https://target.oraclecloud.com \
  admin@company.com \
  targetpassword.epw

# Delete old snapshot
epmautomate deletesnapshot "OldBackup"
```

## 4. WHAT'S IN A SNAPSHOT

| Artifact Category | Included | Details |
|------------------|----------|---------|
| **Dimensions** | ☑ | All dimension hierarchies, member properties |
| **Forms** | ☑ | Form definitions, layouts, rules, formatting |
| **Business Rules** | ☑ | All rules and rulesets |
| **Calc Manager** | ☑ | Components, templates, variables |
| **Smart Lists** | ☑ | Definitions and values |
| **Substitution Variables** | ☑ | Names and current values |
| **User Variables** | ☑ | Definitions (not user-specific values) |
| **Action Menus** | ☑ | Menu definitions |
| **Navigation Flows** | ☑ | Flow definitions |
| **Dashboards** | ☑ | Dashboard layouts and components |
| **Infolets** | ☑ | Home page cards |
| **Data Maps** | ☑ | Cross-cube mapping definitions |
| **Data** | Optional | Actual cell values (can be very large) |
| **Security** | Optional | User provisioning and access rules |
| **Audit Trail** | ❌ | Not included in snapshots |

## 5. MIGRATION PATTERNS

### Pattern 1: Full Migration (DEV → TEST → PROD)

```
Step 1: Export from DEV (full snapshot with data)
Step 2: Copy snapshot to TEST
Step 3: Import to TEST (Replace mode)
Step 4: UAT testing in TEST
Step 5: Export from TEST (no data — artifacts only)
Step 6: Copy snapshot to PROD
Step 7: Import to PROD (Merge mode — preserve PROD data)
Step 8: Verify in PROD
```

### Pattern 2: Selective Migration (Only Rules)

```
Step 1: Export from DEV (select only Business Rules + Calc Manager)
Step 2: Copy to PROD
Step 3: Import to PROD (Merge mode)
Step 4: Deploy rules in PROD Calc Manager
Step 5: Test rules with sample data
```

### Pattern 3: Daily Backup

```bash
# Automated daily backup script
#!/bin/bash
DATE=$(date +%Y%m%d)
EPM="./epmautomate.sh"

$EPM login admin@hotelpvtltd.com pass.epw https://instance.oraclecloud.com domain
$EPM exportsnapshot "Daily_Backup_${DATE}"

# Keep only last 7 days of backups
for i in $(seq 8 14); do
  OLD_DATE=$(date -d "-${i} days" +%Y%m%d)
  $EPM deletesnapshot "Daily_Backup_${OLD_DATE}" 2>/dev/null
done

$EPM logout
```

## 6. SHOW ME — Hotel Pvt Ltd LCM Strategy

```
Environment Strategy:
  DEV:  https://hoteldev.oraclecloud.com    → Development
  TEST: https://hoteltest.oraclecloud.com   → UAT/Testing
  PROD: https://hotel.oraclecloud.com       → Production

Backup Schedule:
  Daily:    Artifact snapshot (no data) → kept for 7 days
  Weekly:   Full snapshot (with data) → kept for 4 weeks
  Monthly:  Full snapshot → kept for 12 months

Migration Process:
  Developer makes changes in DEV
  → Exports snapshot
  → Imports to TEST
  → Business users do UAT (3-5 days)
  → If approved → Copy snapshot to PROD
  → Import to PROD (Merge mode — don't overwrite data)
  → Verify and sign off

Naming Convention:
  Backup_YYYYMMDD           → Daily backup
  Migration_vX.Y_YYYYMMDD   → Migration package
  Rollback_YYYYMMDD         → Pre-migration safety backup
```

## 7. COMMON MISTAKES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Import with Replace mode in PROD | All PROD data deleted | Use Merge mode in PROD — never Replace |
| Forgot to backup before import | Can't rollback after bad import | Always `exportsnapshot "Pre_Migration"` first |
| Including data in migration snapshot | Import takes hours, overwrites prod data | Exclude data for artifact-only migrations |
| Not deploying rules after import | Imported rules don't execute | Deploy all imported rules in Calc Manager |
| Snapshot name too long | EPM Automate errors | Keep names under 50 characters |
| Not refreshing database after import | New dimensions not visible | Run Refresh Database after metadata import |

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: What is LCM and why is it important—**
> Lifecycle Management (LCM) exports EPBCS application artifacts (forms, rules, dimensions, dashboards) as a snapshot file that can be imported into another environment. It's essential for: (1) **Migration** — moving changes from DEV to TEST to PROD. (2) **Backup** — creating recoverable snapshots before major changes. (3) **Disaster Recovery** — restoring the application if something breaks. Without LCM, you'd manually recreate every artifact in every environment.

### Architect
**Q: Design the LCM strategy for Hotel Pvt Ltd with 3 environments.**
> **Environments:** DEV (development), TEST (UAT), PROD (production). **Backup:** Daily artifact snapshot (no data) in PROD — 7-day retention. Weekly full snapshot (with data) — 4-week retention. Monthly archive — 12-month retention. **Migration workflow:** Developer changes DEV → exports artifact-only snapshot → copies to TEST → business users test for 3-5 days → if approved, export TEST snapshot → backup PROD first → import to PROD in Merge mode → refresh database → deploy rules → verify. **Key rules:** Never use Replace mode in PROD. Always backup before import. Exclude data from migration packages. Deploy rules after import. Name snapshots with version and date.
