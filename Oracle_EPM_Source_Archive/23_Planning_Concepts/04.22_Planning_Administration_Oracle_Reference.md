## 🔬 Application Creation — Deep Dive

### Creating a Planning Application (Step-by-Step)

```
Navigation: Home → Application → Create
```

| Step | Setting | Options |
|------|---------|---------|
| 1 | Application Name | 3-8 chars, no spaces, no special chars |
| 2 | Description | Free text |
| 3 | Application Type | Standard, Freeform, Enterprise (OOTB modules) |
| 4 | Enable Features | Planning, Modules (Financials, Workforce, Capital, Projects) |
| 5 | Default Currency | INR, USD, EUR, etc. |
| 6 | Multiple Currencies | Enable/Disable |
| 7 | Start Year / End Year | FY range (e.g., FY24-FY30) |
| 8 | Fiscal Start Month | Jan (calendar) or Apr (India fiscal) |
| 9 | Weekly Distribution | Even, 445, 454, 544 |

### 💡 Logic & Purpose
The Application Creation wizard is the most critical phase of a project because **Start Year, End Year, and Weekly Distribution cannot be easily changed later**. The Weekly Distribution (e.g., 4-4-5) dictates how quarterly data is mathematically spread down to months if a user types a value directly into a Quarter parent on a form.

### 🌀 Confusion Resolution
> **Misconception:** "We messed up the Start Year during application creation. We'll just go into Settings and change it."
> **Reality:** You **cannot** change the Start Year or the Base Time Period (Weekly Distribution) after the application is created. If you create an application starting in FY26 and later realize you need to load FY25 historical data, you must completely delete the application, recreate it from scratch, and rebuild all dimensions.

### 😈 Twisted Interview Question
**Question:** An administrator creates an EPBCS application with a Fiscal Start Month of April. They load data into the system, but when they look at the Q1 rollup, it contains January, February, and March data. They expected Q1 to be April, May, and June. What did they do wrong?
> **Answer:** They selected a Fiscal Start Month of April, but they failed to update the underlying Period hierarchy in the Outline to reflect the fiscal mapping. By default, Oracle builds the Period dimension calendar-style (Q1 = Jan, Feb, Mar). The administrator must manually restructure the Period dimension hierarchy so that Q1's children are Apr, May, Jun, or use the "Fiscal Calendar" automation feature during setup.

### Application Settings (After Creation)

```
Navigation: Application → Settings
```

| Setting | Description | Default |
|---------|-------------|---------|
| **Enable for Sandboxes** | Allow private what-if analysis | Off |
| **Enable Data Audit** | Track who changed what data | Off |
| **Enable Cell-Level Security** | Control access at individual cells | Off |

| **Enable Approvals** | Enable budget approval workflow | Off |
| **Currency Setting** | Simplified / Standard | Standard |

### 🎯 Hands-On: Create Your First Application

```
Step 1: Login → Navigate to "Application" on Springboard
Step 2: Click "Create"
Step 3: Choose "Standard" type
Step 4: Settings:
   - Name: HotelPlan
   - Currency: INR
   - Multi-Currency: Enable
   - Start Year: FY25, End Year: FY30
   - Fiscal Start: April (Indian fiscal year)
   - Period: Monthly

Step 6: Click "Create"
Step 7: Navigate to Application → Overview → verify cubes were created

VERIFY: You should see FinPlan (BSO), OEP_WFP (BSO), and OEP_REP (ASO) cubes
```

## 📌 Dimension Management — Oracle Official Details

### Standard Dimensions (Mandatory in Every Application)

| Dimension | Type | Dense/Sparse | Purpose | Oracle Notes |
|-----------|------|-------------|---------|-------------|
| **Account** | Standard | Dense | Financial accounts (Revenue, Expense, Asset) | Account Type, Variance Reporting, Time Balance properties |
| **Period** | Standard | Dense | Time periods (Jan-Dec, Q1-Q4, YearTotal) | Period type (Base/Rollup), calendar type |
| **Entity** | Standard | Sparse | Organization units (companies, divisions, departments) | Base currency assignment |
| **Scenario** | Standard | Sparse | Data categories (Actual, Budget, Forecast) | Start/End period, Exchange Rate Table |
| **Version** | Standard | Sparse | Draft status (Working, Approved, Final) | Target/Bottom-Up, Access Control |
| **Year** | Standard | Sparse | Fiscal years (FY25, FY26, FY27) | Auto-created based on Start/End Year |
| **Currency** | Standard | Sparse | Currencies (Local, INR, USD, EUR) | Only if Multi-Currency enabled |

### Adding Members — Complete Properties

```
Navigation: Application → Dimensions → [Select Dimension] → Add Member
```

#### Account Member Properties (Every Single Property)

| Property | Values | Description |
|----------|--------|-------------|
| **Name** | String | Unique member code (e.g., `100110`) |
| **Alias (Default)** | String | Display name (e.g., `Rooms Revenue`) |
| **Description** | String | Free-text description |
| **Account Type** | Revenue, Expense, Asset, Liability, Equity, Saved Assumption | Controls variance and aggregation behavior |
| **Variance Reporting** | Non-Expense, Expense | Controls variance sign convention |
| **Time Balance** | Flow, First, Balance, Average, Fill | How months aggregate to quarters/years |
| **Skip Value** | None, Missing, Zeros, Missing and Zeros | Controls Time Balance with empty periods |
| **Exchange Rate Type** | None, Average, Ending, Historical | For currency translation |
| **Data Storage** | Store, Dynamic Calc, Dynamic Calc & Store, Label Only, Shared, Never Share | How data is stored |
| **Two-Pass** | Yes/No | Recalculate after aggregation |
| **Data Type** | Currency, Non-Currency, Percentage, Smart List, Date, Text | Controls cell formatting |
| **Source Plan Type** | FinPlan, Manpower, Capital | Which cube the data lives in |
| **Plan Type (Member)** | Enable/disable per cube | Which cubes this member belongs to |
| **Consolidation (+, -, ~, ^)** | Addition, Subtraction, Ignore, Never Consolidate | How it rolls up to parent |
| **UDA** | Text tags | User-Defined Attributes for calc scripts |
| **Smart List** | Dropdown reference | Only when Data Type = Smart List |
| **Formula** | MDX/Calc expression | Member formula for Dynamic Calc members |

### 🎯 Hands-On: Build a Complete Account Hierarchy

```
Create this structure in your application:

Total P&L (Label Only, ~)
├── Total Revenue (+)
│   ├── 100110 — Rooms Revenue (Revenue, Flow, Store)
│   ├── 100120 — F&B Revenue (Revenue, Flow, Store)
│   ├── 100130 — Other Revenue (Revenue, Flow, Store)
│   └── 100100 — Total Revenue (Dynamic Calc)
├── Total Expenses (~)
│   ├── 200110 — Salaries (Expense, Flow, Store)
│   ├── 200120 — Rent (Expense, Flow, Store)
│   ├── 200130 — Utilities (Expense, Flow, Store)
│   ├── 200140 — Marketing (Expense, Flow, Store)
│   └── 200100 — Total Expenses (Dynamic Calc)
├── EBITDA (Dynamic Calc: Total Revenue - Total Expenses)
├── 300110 — Depreciation (Expense, Flow, Store)
├── EBIT (Dynamic Calc: EBITDA - Depreciation)
├── 400110 — Interest (Expense, Flow, Store)
├── EBT (Dynamic Calc: EBIT - Interest)
├── 500110 — Tax (Expense, Flow, Store)
├── Net Profit (Dynamic Calc: EBT - Tax)
└── Profit Margin % (Dynamic Calc, Two-Pass, Never Share, %: Net Profit / Total Revenue * 100)

VERIFY: 
1. Enter data for Jan/Feb/Mar in a form
2. Check: Do quarters sum correctly? (Time Balance = Flow)
3. Check: Does EBITDA calculate automatically? (Dynamic Calc)
4. Check: Does Profit Margin % show correctly at parent entity? (Two-Pass)
```

### 🎯 Hands-On: Configure Scenario Properties

```
Set up these scenarios:

Actual:
  - Start: FY25/Jan, End: FY26/Dec
  - Exchange Rate Table: "Actual_Rates"
  - Process Management: No (actuals are loaded, not approved)

Budget:
  - Start: FY27/Jan, End: FY27/Dec
  - Exchange Rate Table: "Budget_Rates"
  - Process Management: Yes (needs approval)

  - Start: FY26/Jul, End: FY27/Jun (rolling 12 months)
  - Exchange Rate Table: "Forecast_Rates"
  - Process Management: No

VERIFY: Open each scenario in a form — data entry should only be allowed within Start/End range
```

### 🎯 Hands-On: Build 5 Production-Quality Forms

```
Form 1: "Revenue Planning" (Driver-Based)
  POV: Scenario, Version, Year, Currency
  Rows: Account (100110-100130), with sub-rows for Units, Price, Revenue
  Columns: Period (Jan-Dec)
  Pages: Entity
  Rules on Save: "Calculate_Revenue" (Revenue = Units × Price)
  Suppress: Missing=On, Zero=Off

Form 2: "Expense Budget"
  POV: Scenario=Budget, Version=Working, Year
  Rows: Account (200110-200140)
  Columns: Period (Jan-Dec)
  Pages: Entity, Department
  Rules on Save: "Aggregate_Expenses"

Form 3: "P&L Summary" (Read-Only)
  POV: Version, Year, Currency
  Rows: Account (full P&L hierarchy with indentation)
  Columns: Period (Jan-Dec, Q1-Q4, YearTotal)
  Pages: Entity, Scenario
  Cell colors: Revenue=green, Expense=red, Profit=bold

Form 4: "Variance Analysis"
  POV: Version, Year, Currency
  Rows: Account (P&L)
  Columns: Scenario (Actual | Budget | Variance | Variance %)
  Pages: Entity, Period
  Rules on Load: "Calculate_Variance" 

Form 5: "Executive Dashboard" (Composite)
  Sub-form 1: Revenue Summary (top)
  Sub-form 2: Expense Summary (middle)
  Sub-form 3: KPI Metrics (bottom — Profit %, Revenue Growth)
```

## 📌 Valid Intersections (Oracle Official)

Valid Intersections prevent users from entering data at invalid combinations.

```
Navigation: Application → Valid Intersections → Create
```

| Example | Rule |
|---------|------|
| "Rooms Revenue" only for Hotel entities | Account=100110 → Entity must be E10001 or children |
| "Manufacturing Cost" only for Manufacturing | Account=200150 → Entity must be E10002 or children |
| Budget only for future periods | Scenario=Budget → Period must be after &CurrentMonth |

### 🎯 Hands-On: Set Up Valid Intersections

```
1. Navigate to Application → Valid Intersections
2. Create Rule: "Revenue_by_Entity"
   - Anchor: Account dimension
   - Include: 100110 (Rooms Revenue)
   - Valid with: Entity = IDescendants(E10001) only
3. Test: Open a form → try entering Rooms Revenue for E10002 → should be read-only
4. Create Rule: "Budget_Future_Only"
   - Anchor: Scenario = Budget
   - Valid with: Year/Period combinations after current month
```

## 📌 Substitution Variables — Oracle Official

```
Navigation: Administration → Manage → Substitution Variables
```

### Standard Variables Every Application Needs

| Variable | Value | Usage |
|----------|-------|-------|
| `&CurrentMonth` | Jul | Forms, rules — filter current period |
| `&CurrentYear` | FY26 | Forms, rules — filter current year |
| `&BudgetYear` | FY27 | Budget forms — target year |
| `&PriorYear` | FY25 | Prior year comparisons |
| `&ForecastStart` | Jul | Rolling forecast start |
| `&CurrentQuarter` | Q3 | Quarterly reporting |

### Using in Forms
```
Form POV: Year = &BudgetYear
Form Column: @RANGE(Period, &ForecastStart, Dec)
```

### Using in Business Rules
```
FIX(&BudgetYear, "Budget", "Working")
    DATACOPY "Actual"->"Final"->&PriorYear TO "Budget"->"Working"->&BudgetYear;
ENDFIX
```

### 🎯 Hands-On: Create and Use Substitution Variables

```
1. Navigate to Administration → Manage → Substitution Variables
2. Create all 6 variables from the table above
3. Edit a form → use &BudgetYear in Year POV
4. Write a rule using &CurrentMonth:
   FIX("Forecast", "Working", &CurrentYear)
       FIX(@RANGE(Period, Jan, &CurrentMonth))
           DATACOPY "Actual"->"Final" TO "Forecast"->"Working";
       ENDFIX
   ENDFIX
5. Update &CurrentMonth to Aug → verify form and rule behavior changes
```

## 📌 Approval Workflow — Oracle Official Process

```
Navigation: Tools → Approvals
```

### Approval Process Components

| Component | Description |
|-----------|-------------|
| **Planning Unit** | Entity + Scenario + Version combination |
| **Approval Unit** | The hierarchy level for approval (can be per entity or group) |
| **Owner** | Who is responsible for the planning unit |
| **Status** | Not Started → First Pass → Under Review → Approved → Published |

### Status Flow

```
Not Started → User begins entering data
First Pass → User completes initial entry
Under Review → User submits for review
Approved → Reviewer approves
Published → Data is final and locked
Rejected → Reviewer sends back to user (returns to First Pass)
```

### 🎯 Hands-On: Set Up Approval Workflow

```
1. Application → Settings → Enable Approvals
2. Set Scenario = Budget, Version = Working for approval
3. Define approval hierarchy:
   - E10001 (Mumbai) → Preparer: user1@co.com
   - E10001 (Delhi) → Preparer: user2@co.com
   - Hotel Division → Reviewer: manager@co.com
   - Total Company → Approver: cfo@co.com
4. Test: Login as user1 → enter data → submit → login as manager → approve
5. Verify: After approval, data becomes read-only for user1
```

## 🎓 Interview Questions from Oracle Docs

**Q: What are the 3 application types in EPBCS?**
> Standard (pre-built modules), Enterprise (all OOTB modules), Freeform (maximum flexibility). Standard is the most common for new implementations.

**Q: What is the maximum number of dimensions in a Planning application?**
> 32 dimensions for Standard/Enterprise, 29 for Freeform. This includes the 7 mandatory standard dimensions.

**Q: What properties are unique to the Scenario dimension?**
> Start/End Year+Period (controls data entry range), Exchange Rate Table (for currency translation), and Process Management flag (enables approval workflow).

**Q: What is a Valid Intersection?**
> A rule that restricts which dimension member combinations allow data entry. It prevents users from entering data at meaningless intersections (e.g., "Rooms Revenue" for the IT department).

**Q: What is the difference between Suppress Missing Data vs Suppress Missing Blocks?**
> Suppress Missing Data hides individual rows where all cells are #Missing. Suppress Missing Blocks hides entire chunks where no Essbase block exists — it's more aggressive and significantly improves form load time.

**Q: How does the approval workflow prevent unauthorized changes?**
> Once a Planning Unit is submitted/approved, the data becomes read-only for the preparer. Only the reviewer/approver can reject it back to "First Pass" status, which re-enables editing.
