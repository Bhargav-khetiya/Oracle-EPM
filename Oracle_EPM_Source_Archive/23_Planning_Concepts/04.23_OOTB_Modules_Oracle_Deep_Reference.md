## 🏢 OOTB Planning Modules Overview

When you create a **Standard** or **Enterprise** application, Oracle provides pre-built modules:

```
EPM Cloud Application
├── Financials (FinPlan) ← Always included
├── Workforce (OEP_WFP) ← Enable as needed
├── Capital (OEP_CAP) ← Enable as needed
└── Projects (OEP_PRJ) ← Enable as needed
```

### 💡 Logic & Purpose
Oracle provides these out-of-the-box (OOTB) modules to drastically reduce implementation time. Instead of spending 3 months designing a calculation engine to spread depreciation across 12 periods, you just enable the Capital module, and Oracle provides the rules, forms, and dimensions instantly. All modules seamlessly share data (e.g., Workforce Salary automatically flows into the Financials P&L).

### 🌀 Confusion Resolution
> **Misconception:** "We enabled the Workforce module, but we don't like the way Oracle calculates taxes. We should just delete their business rule and write our own from scratch."
> **Reality:** Never delete or directly modify an OOTB business rule or dimension member! When Oracle pushes a monthly cloud update, it will overwrite or break your customizations if you modified the core artifacts. If you need custom logic, you must create *new* custom members or use the designated "Custom Calc" insertion points provided within the OOTB rules.

### 😈 Twisted Interview Question
**Question:** A client wants to implement the Financials, Workforce, and Capital modules. They plan to enable Financials today, go live in 4 months, and then enable Workforce and Capital next year. Is this a safe strategy—
> **Answer:** Yes, but with a massive caveat! When you enable Workforce and Capital later, they will aggressively push new dimension members (like Employees or Asset Classes) and restructure the cubes. If you haven't meticulously planned your custom dimensions to align with the future OOTB requirements, enabling a new module a year later can corrupt or overwrite your Financials metadata mappings. You must design the architecture for *all* modules on Day 1, even if you only enable them incrementally.

## 🔬 Module 2: Workforce Planning — Deep Dive

### What It Does

Workforce Planning manages **headcount, compensation, and workforce costs**. It connects people data to financial planning.

### Pre-Built Components

| Component | Contents |
|-----------|----------|
| **Cube** | OEP_WFP (BSO) |
| **Dimensions** | Employee, Job, Union, Pay Type, Component |
| **Accounts** | Salary, Benefits, Bonus, Tax, Total Compensation |
| **Forms** | Headcount planning, Compensation planning, New hire, Termination |
| **Rules** | Calculate compensation, Spread salary, Calculate benefits |

### Workforce Dimension Structure

```
Employee Dimension
├── Existing Employees
│   ├── EMP001 — John Smith (Manager, Mumbai)
│   ├── EMP002 — Priya Patel (Analyst, Delhi)
│   └── EMP003 — Raj Kumar (Director, Mumbai)
├── New Hires (template members)
│   ├── NH_001 (placeholder for future hires)
│   ├── NH_002
│   └── NH_003
└── Terminated
    └── (Employees moved here on exit)

Job Dimension
├── Executive
│   ├── CEO
│   ├── CFO
│   └── CTO
├── Management
│   ├── Director
│   └── Manager
└── Individual Contributor
    ├── Senior Analyst
    ├── Analyst
    └── Associate
```

### Workforce Calculation Logic

```
Per Employee:
  Annual Salary → entered or loaded from HR
  Monthly Salary = Annual Salary / 12
  Benefits = Annual Salary × Benefits Rate (e.g., 25%)
  Bonus = Annual Salary × Bonus Rate (e.g., 10%)
  Tax = (Salary + Benefits + Bonus) × Tax Rate
  Total Compensation = Salary + Benefits + Bonus + Tax

Per Entity/Department:
  Total Headcount = COUNT of active employees
  Total Salary = SUM of all employee salaries
  Average Salary = Total Salary / Total Headcount
  Total Compensation = SUM of all employee total comp
```

## 🔬 Module 3: Capital Planning — Deep Dive

### What It Does

Capital Planning manages **fixed assets, capital expenditures, and depreciation**. It tracks physical assets and their financial impact.

### Pre-Built Components

| Component | Contents |
|-----------|----------|
| **Cube** | OEP_CAP (BSO) |
| **Dimensions** | Asset Class, Asset Detail |
| **Accounts** | Purchase Price, Useful Life, Residual Value, Depreciation, NBV |
| **Forms** | New asset entry, Asset register, Depreciation schedule |
| **Rules** | Calculate depreciation, Calculate NBV, Aggregate by class |

### Depreciation Methods

| Method | Formula | Use Case |
|--------|---------|----------|
| **Straight Line** | (Cost - Residual) / Useful Life | Most common — equal annual charge |
| **Declining Balance** | NBV × Rate | Higher charge in early years |
| **Sum of Years** | Cost × (Remaining Life / Sum of Years) | Accelerated |
| **Units of Production** | Cost × (Units This Year / Total Units) | Manufacturing equipment |

### Capital Planning Calculation

```
Per Asset:
  Purchase Price: ₹10,000,000
  Residual Value: ₹1,000,000
  Useful Life: 10 years
  Depreciation Method: Straight Line

  Annual Depreciation = (10,000,000 - 1,000,000) / 10 = ₹900,000
  Monthly Depreciation = 900,000 / 12 = ₹75,000

  Year 1 NBV = 10,000,000 - 900,000 = ₹9,100,000
  Year 2 NBV = 9,100,000 - 900,000 = ₹8,200,000
  ...
  Year 10 NBV = ₹1,000,000 (= Residual Value)
```

## 📌 Module 4: Projects Planning

### What It Does

Projects Planning tracks **project budgets, timelines, and resource allocation**. Links project costs to financial planning.

### Key Concepts

| Concept | Description |
|---------|-------------|
| **Project** | A defined initiative with start/end date and budget |
| **Task** | Sub-component of a project |
| **Resource** | People or equipment assigned to tasks |
| **Budget** | Planned cost for the project |
| **Actual** | Actual spend to date |
| **EAC** | Estimate at Completion |
| **Variance** | Budget - Actual |

### 🎯 Hands-On: Projects Module

```

```

## 📌 Inter-Module Data Flow

```
Workforce Module (OEP_WFP)
├── Total Compensation per Entity → Smart Push → FinPlan "Salary Expense"
│
Capital Module (OEP_CAP)  
├── Depreciation per Entity → Smart Push → FinPlan "Depreciation Expense"
│
Projects Module (OEP_PRJ)
├── Project Costs per Entity → Smart Push → FinPlan "Project Expense"
│
Financials Module (FinPlan)
├── Receives all module outputs
├── Calculates complete P&L
└── Pushes to Reporting cube (ASO) for analysis
```

## 🎓 Interview Questions

**Q: What OOTB modules does EPBCS provide—**
> Financials (P&L/BS planning), Workforce (headcount/compensation), Capital (assets/depreciation), and Projects (project budgets). Each runs in its own BSO cube and pushes results to FinPlan and the ASO Reporting cube via Smart Push.

**Q: How does workforce data flow into the P&L—**
> Workforce module calculates total compensation (salary + benefits + bonus + tax) per employee per entity. This data is pushed to the FinPlan cube via Smart Push, landing in the "Salary & Benefits" expense line. The P&L business rule then includes it in EBITDA calculation.

**Q: What depreciation methods does Capital module support—**
> Straight Line (most common — equal annual charge), Declining Balance (accelerated — higher early), Sum of Years' Digits (accelerated), and Units of Production (usage-based). The method is set per Asset Class.

**Q: Should a client use OOTB modules or build custom—**
> OOTB if requirements match 70%+ of the pre-built content — faster deployment, Oracle support, automatic updates. Custom if requirements are highly specialized or the OOTB structure doesn't fit their business model. Many implementations use OOTB as a starting point and customize.
