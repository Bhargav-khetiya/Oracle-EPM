# 17.01 — Debugging Methodology and Log Analysis: Complete Guide

> **Module:** 17_Debugging | **Topic:** Systematic Debugging, Log Reading, Error Resolution
> **Audience:** Service Administrator / Consultant

---

## 1. WHY — Why Master Debugging—

**The problem:** It's 11 PM on month-end close. The aggregation rule failed. The data load rejected 500 records. The form shows wrong numbers. Users are panicking. Without a systematic debugging approach, you'll spend 3 hours chasing symptoms instead of fixing root causes.

**The solution:** A **5-step debugging methodology** that works for every EPBCS issue — from rule failures to data discrepancies to form errors.

---

## 2. THE 5-STEP DEBUGGING METHOD

```
Step 1: REPRODUCE — Can you see the problem yourself—
  → Open the same form as the user
  → Run the same rule with the same parameters
  → Confirm the issue exists (not a browser cache issue)

Step 2: ISOLATE — Narrow the scope
  → Which cube— Which entity— Which period—
  → Which rule component fails—
  → Does it fail for all users or just one—

Step 3: EXAMINE — Read the logs and data
  → Jobs Console → job details → full log
  → Essbase calc log for rule errors
  → Data audit trail for data discrepancies

Step 4: HYPOTHESIZE — Form a theory
  → Based on error messages and data patterns
  → "The member was renamed" / "The rule divides by zero" / etc.

Step 5: FIX & VERIFY — Apply fix, confirm resolution
  → Fix the root cause (not the symptom)
  → Re-run the operation
  → Verify with the original user
```

---

## 3. WHERE TO FIND LOGS

| Log Type | Location | Contains |
|----------|----------|----------|
| **Job Log** | Jobs Console → click job → View Details | Rule execution trace, errors, timing |
| **Activity Report** | Navigator → Monitor and Explore → Activity Reports | User actions, form opens, rule launches |
| **Essbase Server Log** | Calc Manager → Essbase → Server Log | Low-level database errors |
| **EPM Automate Log** | Local machine → EPM Automate output | CLI command results |
| **Browser Console** | F12 → Console tab | JavaScript errors, network failures |
| **Data Load Log** | Data Management → Process Details | Import/export errors, rejected records |

## 4. READING A JOB LOG — STEP BY STEP

```
Jobs Console → Click "Calculate_PnL" (Status: Error)

Log output:
───────────────────────────────────────────────────────────
[2026-08-12 14:30:01] INFO: Starting rule execution
[2026-08-12 14:30:01] INFO: Plan Type: OEP_FS
[2026-08-12 14:30:01] INFO: User: admin
[2026-08-12 14:30:01] INFO: RTPs: Scenario=Budget, Year=FY2026
[2026-08-12 14:30:02] INFO: Parsing calc script...
[2026-08-12 14:30:02] INFO: FIX("Budget", "Working", "FY2026")
[2026-08-12 14:30:02] INFO: Processing block [Mumbai_Hotel]
[2026-08-12 14:30:02] INFO: Processing block [Delhi_Hotel]
[2026-08-12 14:30:03] ERROR: Unknown member name [Maintainence]  ← THE BUG
[2026-08-12 14:30:03] ERROR: Error in formula at line 15
[2026-08-12 14:30:03] INFO: Rule execution failed
[2026-08-12 14:30:03] INFO: Duration: 2.1 seconds
───────────────────────────────────────────────────────────

Reading strategy:
  1. Scroll to first ERROR line
  2. Read the error message: "Unknown member name [Maintainence]"
  3. Note the line number: "line 15"
  4. Note which block was last processed: Delhi_Hotel
  5. Fix: Correct spelling to "Maintenance"
```

## 5. COMMON ISSUE CATEGORIES

### Category 1: Rule Failures

| Symptom | Common Cause | Debug Steps |
|---------|-------------|-------------|
| "Unknown member name" | Typo or member renamed/deleted | Search rule for the member name |
| "Syntax error" | Missing semicolon/bracket | Check FIX/ENDFIX, IF/ENDIF pairs |
| "Divide by zero" | Denominator is 0 or #MISSING | Add IF(denom <> 0) check |
| "Timeout" | Rule too slow | Check FIX scope, algorithm type |
| "Insufficient access" | User lacks permissions | Check user's dimension security |
| Rule runs but wrong results | Logic error | Add @CalcMgrLogMessageTrace messages |

### Category 2: Data Discrepancies

| Symptom | Common Cause | Debug Steps |
|---------|-------------|-------------|
| Form shows #MISSING | Data not loaded or wrong intersection | Check with ad hoc on exact intersection |
| Numbers don't add up | Aggregation not run | Run AGG or check Dynamic Calc members |
| Old data showing | Cache or stale substitution variable | Refresh database, check SubVars |
| Doubled values | Data loaded twice (no clear before load) | Check import mode (Replace vs Accumulate) |
| Values in wrong period | SubVar not updated | Check &CurrMonth value |

### Category 3: Form Issues

| Symptom | Common Cause | Debug Steps |
|---------|-------------|-------------|
| Form won't open | Security: user has None on form | Check form permissions |
| Form opens but empty | Dimension security: None on entity | Check user's entity access |
| Form shows wrong entity | User Variable not set | Check User Preferences |
| Form takes 30+ seconds | Performance issue | See Performance Monitoring guide |
| Can't save data | Read-only form or read-only member | Check form property + member data storage |

## 6. DEBUGGING TOOLS IN CALC MANAGER

### Tool 1: Trace Messages

```essbase
/* Add breadcrumb messages throughout the rule */
@CalcMgrLogMessageTrace("=== START: Hotel P&L ===");
@CalcMgrLogMessageTrace("Step 1: Revenue calculation");
/* ... revenue formulas ... */
@CalcMgrLogMessageTrace("Step 2: Expense calculation");
/* ... expense formulas ... */
@CalcMgrLogMessageTrace("Step 3: P&L ratios");
/* ... ratio formulas ... */
@CalcMgrLogMessageTrace("=== END: Hotel P&L ===");

/* If the rule fails, the last trace message shows WHERE */
```

### Tool 2: Validate Button

```
Before deploying → Click Validate
Catches:
  ✅ Missing semicolons
  ✅ Unmatched FIX/ENDFIX
  ✅ Unknown member names
  ✅ Invalid function calls
Does NOT catch:
  ❌ Logic errors (wrong formula)
  ❌ Performance issues
  ❌ Security problems
```

### Tool 3: Disable Components

```
In Graphical Designer:
  Right-click component → Disable (turns grey)
  
Use to isolate which component fails:
  Disable all → Enable one → Run → Pass—
  Enable next → Run → Pass—
  Enable next → Run → FAIL → Found the culprit!
```

## 7. SHOW ME — Hotel Pvt Ltd Debugging Walkthrough

### The Problem
CFO opens P&L form → Mumbai Net Income shows ₹0 but revenue is ₹1.12 Cr.

```
Step 1: REPRODUCE
  Open P&L form as admin → confirm: Mumbai Net Income = ₹0
  Other hotels show correct Net Income ✓
  
Step 2: ISOLATE
  → Only Mumbai is affected
  → Revenue and Expenses are correct
  → Net Income = 0 specifically for Mumbai
  
Step 3: EXAMINE
  → Jobs Console: Last rule execution "Calculate_PnL" = Success ✅
  → Open ad hoc on exact intersection:
    Entity=Mumbai_Hotel, Account=Net_Income, Scenario=Actual, Period=Aug
    → Value = #MISSING (not 0!)
  → The form displays #MISSING as 0 (Display Missing as Blank setting)
  
  → Check: Is Net_Income a Dynamic Calc member—
    → YES! Net_Income has formula: "Total_Revenue" - "Total_Expenses"
  → Check: Does Total_Expenses exist for Mumbai—
    → Total_Expenses = #MISSING! (not calculated)
  
Step 4: HYPOTHESIZE
  → The expense sub-accounts have data
  → But Total_Expenses is not aggregating
  → Check if aggregation rule ran after expense entry
  → Jobs Console: Last AGG ran for Delhi_Hotel only (RTP was wrong)
  
Step 5: FIX
  → Re-run aggregation for Mumbai_Hotel
  → Net Income now shows ₹47,00,000 ✅
  → Root cause: User ran AGG with wrong entity RTP
  → Prevention: Remove entity RTP — let rule process all entities
```

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: A business rule shows "Error" in the Jobs Console. How do you debug it—**
> (1) Click the job in Jobs Console → View Details → read the full log. (2) Find the first ERROR line — it contains the error message and often the line number. (3) Common errors: "Unknown member name" = typo or deleted member, "Syntax error" = missing semicolon or bracket, "Divide by zero" = missing IF check. (4) Fix the rule in Calc Manager → Validate → Deploy → Re-run. (5) Verify the job now shows Success.

### Architect
**Q: Design a debugging runbook for Hotel Pvt Ltd's support team.**
> **Tier 1 (Self-service):** Users check their own User Variables and POV. Clear browser cache. Refresh the form. **Tier 2 (Admin):** Check Jobs Console for failed jobs. Read job logs for error messages. Verify substitution variables are current. Re-run failed rules. Check dimension security if user reports missing data. **Tier 3 (Developer):** Open Calc Manager, add trace messages, validate rules, check for algorithm issues (Top-Down). Review Application Statistics for block explosion. Optimize rules and forms. **Documentation:** Maintain a Known Issues log with error → cause → fix mappings. Track recurring issues for proactive fixes.
