# 18.01 — Production Support Tickets: Complete Guide

> **Module:** 18_Production_Support | **Topic:** Common Tickets, Triage, Resolution Playbook
> **Audience:** L2/L3 Support / Service Administrator

---

## 1. WHY — The Support Landscape

In a production EPBCS environment with 50+ users, you'll see **5-15 tickets per week**. 80% are the same 10 issues. This playbook covers every common ticket with exact resolution steps, so you can resolve most issues in under 10 minutes.

---

## 2. TICKET CATEGORIES

```
Ticket Volume Distribution (typical):
  35% — Form/Data Issues ("form is blank", "wrong numbers")
  25% — Smart View Issues ("can't connect", "refresh fails")
  15% — Rule Failures ("monthly close failed")
  10% — Access/Security Issues ("can't see form", "can't edit")
  10% — Performance Issues ("form is slow")
   5% — Admin/Misc ("SubVar not updated", "maintenance")
```

## 3. TOP 10 TICKETS — PLAYBOOK

### Ticket #1: "My form is blank / showing all zeros"

```
Priority: Medium | SLA: 2 hours
Frequency: 3-5 per week

Triage:
  Q1: Which form— Which entity— Which scenario/version/year—
  Q2: Other users affected— (one user vs all users)
  Q3: Was it working before— When did it stop—

Resolution:
  ☐ Check User Variable: Is UserEntity set correctly—
     → Navigator → Preferences → Variables → verify
  ☐ Check Dimension Security: Does user have Read/Write on that entity—
     → Access Control → check user's group → entity access
  ☐ Check SubVars: Is &CurrYear and &CurrMonth correct—
     → Admin → Variables → verify values
  ☐ Check if data exists: Open ad hoc → navigate to exact intersection
     → If #MISSING everywhere → data hasn't been loaded or AGG hasn't run
  ☐ Check if AGG ran: Jobs Console → last AGG job → status
     → If AGG not run → run AGG → form should populate

Most common fix: User Variable not set (50% of cases)
```

### Ticket #2: "Smart View won't connect"

```
Priority: Medium | SLA: 4 hours
Frequency: 2-3 per week

Resolution:
  ☐ VPN connected— (if required by company)
  ☐ URL correct— Test in browser:
     https://instance.oraclecloud.com/HyperionPlanning/SmartView
     → Should show XML, not error page
  ☐ Credentials correct— Try browser login to EPBCS
  ☐ Clear saved credentials: Control Panel → Credential Manager
  ☐ Excel COM Add-in enabled— File → Options → Add-ins → COM → ☑
  ☐ Reinstall Smart View if above fails

Most common fix: VPN not connected (40%) or stale credentials (30%)
```

### Ticket #3: "Monthly close rule failed"

```
Priority: HIGH | SLA: 1 hour
Frequency: 1 per month (critical when it happens)

Resolution:
  ☐ Jobs Console → find the failed job → View Details
  ☐ Read the FIRST error line in the log:
     "Unknown member" → fix member name in rule
     "Timeout" → optimize rule (add FIX, CALCPARALLEL)
     "Divide by zero" → add IF check
     "Lock conflict" → wait for other job to finish
  ☐ Fix the root cause
  ☐ Re-run the rule
  ☐ Verify data on key forms
  ☐ Notify stakeholders of delay + resolution

Most common fix: Member renamed without rule update (40%)
```

### Ticket #4: "I can see the form but can't edit"

```
Priority: Low | SLA: 8 hours

Resolution:
  ☐ Check form permission: Form Designer → Permissions → user's group
     → If Read → change to Write (or add user to correct group)
  ☐ Check dimension security:
     Entity: Write— Scenario: Write— Version: Working = Write—
  ☐ Check if Final version: Final = Read for planners (by design)
  ☐ Check if Actual scenario: Actual = Read for planners (by design)

Most common fix: User trying to edit Final version (35%)
```

### Ticket #5: "Numbers are wrong / doubled"

```
Priority: HIGH | SLA: 2 hours

Resolution:
  ☐ Is this after a data load— Check import mode:
     Accumulate → values added to existing (doubled!)
     Fix: Change to Replace mode, clear bad data, reload
  ☐ Is this after a rule— Check if rule is idempotent:
     "Revenue = Revenue * 1.05" run twice = 10.25% growth!
     Fix: Make rule idempotent (reference source, not target)
  ☐ Is aggregation stale— Run AGG → check if parents correct
  ☐ Is SubVar wrong— Check &CurrMonth → processing wrong period

Most common fix: Data load mode = Accumulate instead of Replace (45%)
```

### Ticket #6: "Form is extremely slow (>15 seconds)"

```
Priority: Medium | SLA: 1 day

Resolution:
  ☐ Count cells on form (rows × columns). > 5,000— Reduce.
  ☐ Suppress Missing Data enabled— If not → enable.
  ☐ Two sparse dims on rows— Move one to Page.
  ☐ Heavy On Load rule— Move to On Save or batch.
  ☐ Check block count in App Statistics → if exploded, CLEARBLOCK ALL.

Most common fix: Suppress Missing not enabled (40%)
```

### Ticket #7: "New user can't access EPBCS"

```
Priority: Low | SLA: 1 day

Resolution:
  ☐ User exists in Identity Domain— → If not, create account
  ☐ Application role assigned— → Assign Planner/Viewer/etc.
  ☐ User Variable set— → Set UserEntity to their hotel
  ☐ Dimension security set— → Add to appropriate group
  ☐ Share login URL and Smart View connection string
  ☐ Schedule 30-min training call
```

### Ticket #8: "Data load failed"

```
Priority: HIGH | SLA: 2 hours

Resolution:
  ☐ Jobs Console → Process Details → view error log
  ☐ "Member not found" → fix source file or add mapping
  ☐ "Invalid data value" → clean source (remove N/A, symbols)
  ☐ "File not found" → re-upload file
  ☐ "Column mismatch" → check delimiter and format
  ☐ Re-run after fix → verify on form
```

### Ticket #9: "SubVar not updated — wrong month showing"

```
Priority: HIGH | SLA: 30 minutes

Resolution:
  ☐ Navigator → Admin → Variables → update all SubVars:
     CurrMonth, PriorMonth, ForecastStart, CurrQtr
  ☐ OR: epmautomate setsubstvars "ALL" "CurrMonth=Oct" "PriorMonth=Sep"
  ☐ Prevention: Automate with scheduled script

Most common fix: Admin forgot monthly update (100%)
```

### Ticket #10: "Groovy rule shows VetoException"

```
Priority: Low | SLA: 8 hours

Resolution:
  This is EXPECTED behavior — the rule is blocking the save because:
  ☐ Read the error message shown to user
  ☐ "Negative revenue" → user entered a negative number → fix the data
  ☐ "Occupancy > 100%" → user entered invalid value → fix
  ☐ "Budget incomplete" → not all months filled → complete entry

  This is NOT a bug — it's validation working correctly!
```

## 4. INCIDENT SEVERITY MATRIX

| Severity | Definition | SLA | Examples |
|----------|-----------|-----|---------|
| **P1 — Critical** | System down, all users affected | 1 hour | Instance unreachable, maintenance overrun |
| **P2 — High** | Major function broken | 2 hours | Monthly close failed, data doubled, data load failed |
| **P3 — Medium** | Single user impacted | 8 hours | User can't connect, form slow, can't edit |
| **P4 — Low** | Minor issue, workaround exists | 24 hours | Formatting issue, new user setup, feature request |
