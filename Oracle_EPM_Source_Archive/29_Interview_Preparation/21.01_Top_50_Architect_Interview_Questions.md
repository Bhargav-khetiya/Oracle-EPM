## 7. The Gauntlet: Architectural Questions

### Q1: The Block Explosion
**Scenario:** A client has a 3-minute Business Rule. A junior developer adds one line of code to calculate a 5% commission on sales. The rule now takes 4 hours and crashes the server. Why?
> **Architect Answer:** The developer likely targeted a Sparse dimension on the left side of the equation (e.g., `"Commission" -> "No_Entity" = "Sales" * 0.05;`), or wrapped an `IF` statement around a sparse evaluation. This forces the Essbase engine to abandon fast, Bottom-Up block execution and switch to Top-Down mode. Essbase evaluated every possible sparse intersection in the outline, generating millions of empty blocks in RAM, causing a block explosion and a memory crash.

### Q2: Hybrid BSO Constraints
**Scenario:** Oracle says Hybrid BSO is the future. Should I just set all parent members in all 10 sparse dimensions to `Dynamic Calc` and delete all my aggregation scripts?
> **Architect Answer:** Absolutely not. While Hybrid calculates sparse parents in RAM on the fly, it is still bound by physical memory limits. If a user queries the absolute top of a 10-dimension cube (e.g., Total Year, Total Product, Total Geography), the Hybrid engine must dynamically calculate billions of leaf intersections simultaneously. This will cause a memory spike and a query timeout. You must selectively `Store` intermediate parents (Anchors) to pre-aggregate the data on disk, reducing the dynamic load on the Hybrid RAM engine.

### Q3: Security Matrix Conflicts
**Scenario:** You put a user in Group A (Read access to North America). You put the user in Group B (Deny/None access to North America). You make the user a "Service Administrator" in IDCS. Can the user see the data for North America?
> **Architect Answer:** Yes. The "Service Administrator" IDCS role acts as a "God Mode" override, bypassing standard Access Control data grants. Even though Group B explicitly denied access, the foundational Service Administrator role ignores the Deny filter. If the user was a "Power User", the Deny from Group B would override the Read from Group A, and they would see nothing.

### Q4: OOTB Modules vs Custom
**Scenario:** A client is an Airline. They want to plan "Fuel Cost per Flight Mile". They ask you to enable the OOTB Financials module. What do you advise?
> **Architect Answer:** I advise against it. The OOTB Financials module is built for standard corporate GL accounting (Account, Entity, Product). An Airline's driver model (Flight Miles, Routes, Aircraft Type) requires highly custom dimensionality. If we try to force "Aircraft Type" into the standard "Product" dimension, we will spend more time fighting Oracle's pre-built Groovy scripts than we would have spent building a clean, Custom Planning cube perfectly tailored to their business model.

### Q5: Smart Push Performance
**Scenario:** You configure a Web Form with Smart Push set to "Run After Save". When the user clicks Save, their browser freezes for 2 minutes before the data saves. How do you fix the user experience?
> **Architect Answer:** The standard Smart Push runs synchronously; the browser hangs until the data successfully transfers to the ASO reporting cube. To fix this, I would disable the standard Form Smart Push. Instead, I would write a Groovy Rule attached to the "Run After Save" trigger. In the Groovy script, I would invoke the Data Map using the asynchronous flag (`dataMap.execute(false)`). This fires the push into a background job and immediately returns control of the browser back to the user in 1 second.

### Q6: Data Integration Repository Bloat
**Scenario:** EPM Automate data loads start taking 3 hours instead of 5 minutes. The staging tables are timing out. The Essbase cube size is normal. Where is the bottleneck?
> **Architect Answer:** The bottleneck is in the relational repository, specifically the Audit Logs or the Data Management staging tables. If the system is set to heavily audit Data changes or Task flows, the relational tables bloat to millions of rows. Or, if Data Management is not purged, the `TDATASEG` staging tables are massive. The Architect must implement a monthly EPM Automate maintenance script using `clearAudit` and `maintainDataManagement` to truncate these relational tables and restore SQL query performance.
