# Planning — Interview Questions

> **Module:** 20_Interview | **Topic:** Planning  
> **Last Updated:** 2026-07-23  
> **Oracle Cloud Version:** 24.10+  
> **Questions:** 20 | **Difficulty:** Mixed

---

**Q1: What is the difference between PBCS and EPBCS—**
> PBCS (Planning and Budgeting Cloud Service) is the basic cloud planning tool. EPBCS (Enterprise PBCS) includes everything in PBCS plus pre-built modules: FinPlan, Workforce, Capital, Projects, and Strategic Modeling. EPBCS is the current standard; PBCS is effectively merged into it.

**Q2: What is a Freeform application vs an OOTB application—**
> OOTB (Out of the Box) applications come with pre-built dimensions, members, forms, and rules (e.g., FinPlan has pre-built P&L accounts). Freeform gives maximum flexibility — you design everything from scratch with no Oracle-provided structure. Use OOTB for standard financial planning; Freeform for custom solutions.

**Q3: What is a substitution variable and why is it important—**
> A substitution variable is a global placeholder (e.g., `&CurrentMonth = Jul`) that can be changed once and affects all forms, rules, and reports that reference it. Without it, you'd need to manually update dozens of forms every month.

**Q4: What cubes does a standard EPBCS application have—**
> FinPlan (financial planning — BSO), Manpower/Workforce (headcount planning — BSO), Capital (asset planning — BSO), and optionally a Reporting cube (ASO for fast aggregation). Each cube has its own dimension structure.

**Q5: What is a Task List—**
> A Task List is an ordered list of steps assigned to users that guides them through a business process: "1. Enter Revenue Assumptions → 2. Enter Expense Budget → 3. Run Calculation → 4. Submit for Approval." Each step links to a form, rule, URL, or another task list.

**Q6: What is the Approval/Workflow process in EPBCS—**
> The approval workflow routes budget submissions through stages: Preparer enters data → submits → Reviewer checks and approves or rejects → Approver gives final sign-off. Once approved, data becomes read-only. This is controlled by Planning Units (Entity + Scenario + Version).

**Q7: What is a Planning Unit—**
> A Planning Unit is the slice of data that flows through the approval process. It's typically defined by Entity + Scenario + Version (e.g., "Hotel Pvt Ltd + Budget + Working"). Each planning unit has its own approval status (Not Started, First Pass, Under Review, Approved).

**Q8: What is Sandbox in EPBCS—**
> Sandbox is a private workspace where users can test what-if scenarios without affecting the public data. Users can modify data, run calculations, and compare results. Only when satisfied, they "publish" the sandbox data to the live database. Up to 4 sandboxes are available.

**Q9: What is the difference between a Driver-Based plan and a traditional budget—**
> Traditional: Enter absolute numbers directly (Revenue = ₹10,00,000). Driver-Based: Enter assumptions/drivers (Occupancy Rate = 80%, Room Rate = ₹5,000, Rooms = 100) and EPM calculates: Revenue = 80% × ₹5,000 × 100 × 365 = ₹14.6 Cr. Driver-based is more flexible — change one assumption and everything recalculates.

**Q10: What is a Rolling Forecast—**
> A Rolling Forecast continuously looks 12-18 months ahead. When January ends, you drop Jan and add a new future month. Unlike a static annual budget, it always shows the next 12 months. EPM implements this using substitution variables and calc rules.

**Q11: What is Valid Intersections—**
> Valid Intersections restrict which dimension member combinations allow data entry. Example: Prevent entering "Rooms Revenue" for the "Corporate IT" department (rooms revenue only applies to Hotel operations). Invalid combinations show as read-only or hidden.

**Q12: What is Data Map and Smart Push—**
> Data Map defines how data moves between cubes (e.g., FinPlan → Manpower). Smart Push is a form-level feature that automatically pushes data via a Data Map when the user saves the form. It enables real-time cross-cube data synchronization.

**Q13: How would you design a budget process for a company with 50 entities—**
> (1) Create task lists for each entity group. (2) Assign preparers per entity. (3) Use substitution variables for budget year. (4) Build data-entry forms for revenue, expenses, headcount. (5) Create business rules for calculations. (6) Set up approval workflow: Entity Preparer → Regional Reviewer → CFO Approver. (7) Schedule reports for variance analysis.

**Q14: What are the key differences between Planning and FCCS—**
> Planning (EPBCS) is for CREATING future data (budgets, forecasts). FCCS is for COMBINING historical data (consolidation). Planning = forward-looking, write-heavy. FCCS = backward-looking, read-heavy with complex consolidation rules (currency translation, intercompany eliminations, minority interest).

**Q15: What is the role of the Period dimension—**
> Period dimension holds time members: Jan-Dec (monthly), Q1-Q4 (quarterly), YearTotal (annual), and optionally BegBalance. It's typically Dense (every entity has all periods). Time Balance properties on Account dimension control how months aggregate to quarters and years.

**Q16: How do you handle scenario comparison (Budget vs Actual vs Forecast)—**
> Create reports/forms that show multiple scenarios side-by-side with variance columns. Use business rules to calculate variances: Variance = Actual - Budget (for revenue, positive = favorable). Use the Variance Reporting property on Account dimension to handle sign convention automatically.

**Q17: What is the Currency dimension—**
> Currency dimension enables multi-currency planning. Members include Local (input currency), and reporting currencies (USD, EUR, etc.). Data is entered in Local currency, then translated to reporting currencies using exchange rates and translation rules.

**Q18: What modules are available in EPBCS—**
> FinPlan (Financial Planning), Workforce (headcount and compensation), Capital (asset planning and depreciation), Projects (project financial planning), Strategic Modeling (long-range planning with financial models). Each module comes with pre-built dimensions, forms, and rules.

**Q19: When would you use a Custom application type vs OOTB—**
> Custom/Freeform when: requirements don't match any OOTB module, need full control over dimension design, or planning non-financial data. OOTB when: standard P&L/Balance Sheet planning, workforce planning, or capital asset planning where Oracle's pre-built structure saves significant development time.

**Q20: What is the difference between a Version and a Scenario—**
> Scenario defines the TYPE of data (Actual, Budget, Forecast). Version defines the DRAFT STATUS (Working, Approved). You can have Budget-Working (draft budget) and Budget-Approved (finalized budget). Actual-Final (loaded actuals). Forecast-Working (in-progress forecast).

### 😈 Twisted Interview Question
**Question:** A company wants to lock the "Budget" scenario so no one can change the final numbers, but they want users to start working on "Forecast". If they change the Access permission on the "Budget" member to `Read`, will this work perfectly—
> **Answer:** It will lock Budget, but it's architecturally flawed! You should almost NEVER put security directly on the Scenario dimension. Instead, EPM uses **Approval Units** (Planning Units) that combine Scenario + Version + Entity. You should change the Approval Status of the `Budget -> Final` combination to "Approved" (which auto-locks it), leaving the overarching Scenario security alone. Hardcoding `Read` on the dimension member breaks flexibility.
