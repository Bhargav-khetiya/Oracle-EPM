## 📌 Smart View (Q1-Q10)

**Q1: What is Smart View—**
> Oracle's Excel add-in that connects to EPM Cloud. Users can enter data, run ad-hoc queries, build reports, and submit budgets — all within familiar Excel.

**Q2: What is the difference between Forms and Ad-Hoc in Smart View—**
> Forms are pre-designed structured layouts (fixed dimensions). Ad-Hoc lets users freely explore data — zoom in/out, pivot, keep/remove members on the fly. Forms for data entry; Ad-Hoc for analysis.

**Q3: What is HsGetValue—**
> An Excel function that retrieves a single data value from EPM: `=HsGetValue("Cube","Account#Revenue","Period#Jan",...)`. All dimensions must be specified. Used for building custom dashboards.

**Q4: What is a Flex Form—**
> A Flex Form combines EPM form structure with Excel flexibility — users can sort, filter, and add Excel formulas while still being able to submit data back to EPM.

**Q5: What do the cell colors mean in Smart View—**
> White = writable, Yellow = changed but not submitted, Light Blue = read-only (Dynamic Calc), Gray = not editable.

**Q6: How do you troubleshoot "Unable to connect" in Smart View—**
> Check: (1) URL format, (2) VPN/proxy, (3) clear Smart View cache, (4) verify SSO credentials, (5) check if instance is up, (6) Office/SV version compatibility.

**Q7: What are Member Selection functions—**
> IChildren, IDescendants, ILvl0Descendants, Siblings, IParent, Ancestors. Used in ad-hoc to programmatically select members rather than picking individually.

**Q8: How does Smart View connect to EPM Cloud—**
> Via HTTPS connection to the Smart View provider URL. Uses the same SSO authentication as web interface. Each open connection consumes a server session.

**Q9: What is the difference between Refresh and Submit—**
> Refresh pulls latest data FROM the server. Submit pushes your changes TO the server. Always refresh before editing to get latest data.

**Q10: Why might HsGetValue return #NoData—**
> Missing a dimension in the function (ALL dimensions required), data doesn't exist at that intersection, or the connection name is wrong.

## 🔌 Data Integration (Q11-Q20)

**Q11: What are the methods to load data into EPBCS—**
> (1) Data Management (FDMEE) — mapping and transformation, (2) Data Exchange — file-based, (3) REST API, (4) EPM Automate, (5) Smart View submit, (6) Manual form entry, (7) Groovy DataGridBuilder.

**Q12: What is Data Management (FDMEE)—**
> Data Management is the built-in ETL tool for loading data from external sources. It provides mapping rules, transformations, validations, and audit trails. Handles source-to-target member mapping.

**Q13: What is a Data Map—**
> A Data Map defines how data moves between cubes within the same application. It maps dimensions from source cube to target cube, including member transformations.

**Q14: What is Smart Push—**
> Smart Push is a form-level feature that automatically triggers a Data Map when the user saves the form. It enables real-time cross-cube data synchronization without manual intervention.

**Q15: How does data flow from ERP to EPM—**
> ERP exports data (CSV/flat file) → Upload to EPM inbox → Data Management maps source accounts to EPM members → Import loads data into the cube → Business rules aggregate and calculate.

**Q16: What happens when a source account doesn't have a mapping—**
> It goes to the "Unmapped" bucket and is typically ignored. This is a common cause of "EPM doesn't tie to ERP" complaints. Always review unmapped members after each load.

**Q17: What is Import Format in Data Management—**
> Import Format defines the structure of the incoming data file — which column maps to which dimension, delimiters, header rows. It's the bridge between the file format and EPM's dimension structure.

**Q18: What is a Location in Data Management—**
> A Location links an Import Format to a specific target application/cube. It defines the source system, file format, and target cube for a specific data flow.

**Q19: What are the common data load errors—**
> "Target member not found" (unmapped account), "Invalid data value" (non-numeric), "Duplicate records" (same intersection loaded twice), "Load rule not found" (name mismatch).

**Q20: How do you verify a data load was successful—**
> (1) Check Data Management process log for rejected records. (2) Open a form or Smart View ad-hoc to verify key totals. (3) Compare EPM total with source system total. (4) Check Job Console for any errors.

## 🔒 Security (Q21-Q30)

**Q21: What are the 3 layers of EPM security—**
> (1) Identity Domain — authentication/SSO, (2) Application Roles — feature access (Admin, Power User, User, Viewer), (3) Data Access — member-level Read/Write/None permissions.

**Q22: What are the pre-defined roles—**
> Service Administrator (full control), Power User (create forms/rules), User (data entry), Viewer (read-only).

**Q23: Why use groups instead of individual user assignments—**
> Scalability. Add/remove users from groups instead of managing individual permissions. One group change affects all members instantly.

**Q24: How do you prevent users from editing Actuals—**
> Set Actual scenario to Read access for all user groups. Only data integration (system loads) should write to Actuals.

**Q25: What is the approval workflow—**
> Preparer → Reviewer → Approver. Each role has different permissions. Approved data becomes read-only for preparers.

**Q26: What is form-level security—**
> You can restrict which users/groups can see specific forms. Assign users in form properties → Access Control tab.

**Q27: What does "None" permission mean—**
> The user cannot see the member at all — it's as if it doesn't exist. No data, no member name, completely hidden.

**Q28: How do you audit who changed what data—**
> Tools → Audit shows data changes (who, when, old value, new value), security changes, and rule executions.

**Q29: What is provisioning—**
> Assigning application roles to users via Access Control or Identity Console. A user without provisioning cannot access the application at all.

**Q30: How does cross-dimensional security work—**
> Set permissions on individual dimension members. The effective access is the INTERSECTION of all dimension permissions. If Entity=Write but Scenario=Read, the user can only Read data for that entity's actual scenario.

### 😈 Twisted Interview Question
**Question:** A user has `Read` access to the 'Actual' scenario and `Write` access to the 'Budget' scenario. You create a Cell-Level Security rule that sets `None` (deny) for the 'Total Revenue' account. What happens when the user tries to view 'Budget -> Total Revenue'—
> **Answer:** They see `#NoAccess` (None). Cell-Level Security is a secondary security layer evaluated *after* standard dimension security. Even if standard security grants `Write` to Budget, a conflicting Cell-Level Security rule that enforces `None` will completely override and block the data. Cell-Level Security always wins.

## 📌 Administration (Q31-Q40)

**Q31: What is the Job Console—**
> The central dashboard showing all executed jobs — data loads, business rules, metadata imports, snapshots. Shows status, duration, and error details.

**Q32: What are substitution variables used for—**
> Dynamic placeholders that change value without editing forms/rules. Examples: `&CurrentMonth`, `&BudgetYear`, `&CurrentYear`. Updated monthly or as needed.

**Q33: What is a Navigation Flow—**
> A customized user interface that shows/hides cards and menus based on user roles. Power Users see admin tools; regular users see only their data entry forms.

**Q34: What is the difference between Refresh Cube and Restructure—**
> Refresh Cube applies metadata changes without restructuring. Restructure physically reorganizes the Essbase database (needed when Dense/Sparse changes). Both are triggered from Application → Overview.

**Q35: How do you backup an EPM application—**
> `epmautomate exportSnapshot "BackupName"`. This creates a full snapshot of metadata, data, security, forms, rules — everything needed to restore.

**Q36: How do you refresh DEV from PROD—**
> Export PROD snapshot → Copy to DEV → Recreate DEV → Import snapshot. Use `epmautomate copySnapshotFromInstance` for cross-environment transfer.

**Q37: What are Activity Reports—**
> Daily system reports showing: slowest forms, slowest rules, user login activity, data load times, and resource utilization. Essential for performance monitoring.

**Q38: How do Oracle's monthly updates work—**
> Oracle updates non-prod environments first (1 week early), then production. Updates are mandatory — you cannot skip them. Review Release Readiness documents before each update.

**Q39: What is LCM (Lifecycle Management)—**
> LCM is the tool for migrating artifacts (forms, rules, metadata) between environments. It creates export packages that can be imported into another instance. Used for DEV → TEST → PROD promotions.

**Q40: What should a daily admin routine include—**
> Check Job Console for overnight failures, review Activity Reports, verify data load completions, check user issues, monitor disk/database size, address support tickets.
