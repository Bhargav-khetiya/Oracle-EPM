## 📌 Data Issues

**Q1: Users report that Q1 totals don't match the sum of Jan+Feb+Mar. What do you investigate—**
> (1) Check Time Balance property — is it set to "Balance" instead of "Flow"— Balance takes last period, not sum. (2) Check if account has Skip Value set — it might be skipping zeros/missing. (3) Verify consolidation operators on children. (4) Check for Dynamic Calc formula on Q1 that might override aggregation.

**Q2: After a data load, EPM total is ₹10 lakhs less than ERP. How do you debug—**
> (1) Check Data Management log for rejected records. (2) Check for unmapped source accounts going to "Ignore." (3) Compare at the account level — find which specific account has the variance. (4) Verify load rule mappings. (5) Check if data was loaded to wrong intersection (wrong entity/period/scenario).

**Q3: A user's form shows all zeros, but you can see data in Smart View ad-hoc. What's wrong—**
> (1) Form POV might be pointing to wrong intersection (different scenario/version/year). (2) Check member selection on rows/columns — might be filtering out the members with data. (3) Check if form has a Business Rule on Load that's clearing data. (4) Verify user has Read access to the dimension members.

**Q4: Budget data was accidentally overwritten. How do you recover—**
> (1) Check if a snapshot backup exists from before the overwrite. (2) If yes, restore to a DEV environment and extract the needed data. (3) If no backup, check if the data was also loaded via Data Management — re-run the import. (4) If it was user-entered, check audit trail for original values.

## 📌 Calculation Issues

**Q5: A revenue calculation rule takes 45 minutes. The client wants it under 5 minutes. How—**
> (1) Check FIX scope — narrow it to only Level 0 entities, specific scenario/version. (2) Check for CALC ALL — replace with targeted AGG. (3) Add SET UPDATECALC ON. (4) Check for unnecessary cross-dimensional references. (5) Split into multiple smaller rules. (6) Check if block size is too large.

**Q6: A rate member shows 90% at Total Entity instead of 30%. What happened—**
> The rate (30%) is being summed across 3 entities: 30+30+30=90. Fix: Set the rate member to Never Share with Ignore (~) consolidation. Or: Use Dynamic Calc with a formula that divides at the parent level.

**Q7: After running a currency translation rule, some entities show zero in USD. Others are fine.**
> (1) Check if exchange rates are loaded for all entities/periods. (2) Check if the rule FIX scope includes all entities. (3) Verify SET CREATEBLOCKONEQ ON is set — blocks might not exist for new currency intersections. (4) Check account-level Exchange Rate Type property.

**Q8: A user runs a rule from a form, but nothing changes. No error either.**
> (1) Verify the rule is deployed (not just validated). (2) Check if the FIX scope matches the form's POV. (3) Check SET CREATEBLOCKONEQ — data might be assigned but blocks don't exist. (4) Verify the rule is actually attached to the form (Business Rules tab).

## 📌 Form & UI Issues

**Q9: A form takes 30 seconds to load. Users are complaining. How do you fix it—**
> (1) Enable Suppress Missing Data and Suppress Missing Blocks. (2) Reduce the number of members on rows/columns. (3) Remove Business Rules on Load unless essential. (4) Move rarely-changed dimensions to POV. (5) Check if Dynamic Calc members are causing slow retrieval. (6) Break large forms into smaller ones.

**Q10: Users say they can see data they shouldn't be able to see. How do you fix it—**
> (1) Check entity-level security — is the user's group granted Read/Write on the wrong entities— (2) Check if "None" permission is set on restricted members. (3) Verify inheritance settings — parent access might cascade to children. (4) Check if user has Service Admin role (bypasses data security).

**Q11: A Composite Form shows different data than the individual forms it's composed of.**
> (1) Check if each sub-form has different POV settings. (2) Verify substitution variables resolve the same way in all sub-forms. (3) Check if one form has a Business Rule on Load that's modifying data. (4) Refresh all components.

## 🔌 Integration Issues

**Q12: An automated nightly data load failed. What's your troubleshooting approach—**
> (1) Check EPM Automate log for error messages. (2) Check if the source file was generated and uploaded successfully. (3) Verify the file format hasn't changed (new columns, different delimiter). (4) Check if the EPM instance was under maintenance. (5) Verify credentials haven't expired.

**Q13: Smart View users report "Session Expired" frequently. What do you recommend—**
> (1) Check idle timeout settings in Identity Cloud. (2) Advise users to refresh periodically to keep session alive. (3) Check if too many concurrent connections are hitting the session limit. (4) Verify network stability — dropped connections cause timeouts.

**Q14: After migrating forms from DEV to PROD using LCM, some forms show errors.**
> (1) Check if all dimension members referenced in forms exist in PROD. (2) Verify substitution variables are set in PROD. (3) Check if business rules attached to forms are deployed in PROD. (4) Verify Smart Lists referenced in forms exist. (5) Check form-level security assignments.

## 🏗️ Architecture & Design

**Q15: A client has 500 cost centers. Should Cost Center be a separate dimension or part of Entity—**
> Separate dimension. Reasons: (1) Reduces Entity dimension complexity. (2) Allows different security models for entity vs cost center. (3) Enables cross-entity cost center analysis. (4) But consider data density — if 500 cost centers × 100 entities creates too many sparse combinations, consider using it as a Dense dimension or attribute.

**Q16: A client wants to plan at both monthly and weekly levels. How do you design this—**
> Option 1: Use Period dimension with both monthly and weekly members (increases Dense dim size significantly). Option 2: Use a separate "Weekly" cube with its own Period dimension. Option 3: Use monthly in EPM and manage weekly detail in a separate system. Recommend Option 2 — separate cubes prevent block size explosion.

**Q17: A manufacturing company needs to track 10,000 SKUs in planning. Is this feasible—**
> 10,000 SKUs as a dimension would create massive block counts. Instead: (1) Use product categories (100-200 groups) as the planning dimension. (2) Load SKU-level actuals aggregated to category level. (3) Use an attribute dimension for SKU-level analysis if needed. (4) Keep detailed SKU data in ERP.

**Q18: How do you handle a scenario where Budget needs 5 more custom dimensions than Forecast—**
> Create multiple cubes: Budget cube (with all custom dimensions) and Forecast cube (simpler structure). Use Data Maps to push common data between cubes. Each cube optimized for its use case.

## 📌 Production & Operations

**Q19: Oracle releases a monthly update that deprecates a feature you're using. What do you do—**
> (1) Review Release Readiness doc immediately. (2) Test in non-prod environment (it updates first). (3) Identify the deprecated feature's replacement. (4) Modify the application before PROD update. (5) Communicate impact to users. (6) Raise an Oracle SR if no reasonable workaround exists.

**Q20: A P1 incident: EPM Cloud is completely unreachable for all users.**
> (1) Check Oracle Cloud Status page first. (2) If Oracle infrastructure issue → raise Oracle SR with P1 severity. (3) Communicate to stakeholders immediately. (4) If NOT Oracle issue → check VPN/network, DNS, SSO provider status. (5) Document timeline for post-incident RCA.

**Q21: Month-end is tomorrow and the monthly close rule set is failing. What's your approach—**
> (1) Check Job Console for specific error. (2) Identify which rule in the set is failing. (3) Check if it's a data issue (missing data) or a script issue. (4) Fix the specific rule, test in isolation. (5) Re-run the rule set. (6) If unfixable, manually run the individual rules that succeeded, skip the failed one, document the gap.

### 😈 Twisted Interview Question
**Question:** You isolate the failure to "Rule 3: Allocate Corporate Overhead". The rule crashes on a divide-by-zero error. You have exactly 10 minutes to fix it before the CFO logs in to run reports. How do you patch the calculation instantly without rewriting the logic—
> **Answer:** You wrap the division logic in an `IF` statement to check the denominator! A pro consultant always writes defensive code. Example: `IF("Headcount" > 0) "Overhead" = "Total_Corp_Cost" / "Headcount"; ENDIF;`. This instantly stops the rule from crashing when a department has zero headcount.

**Q22: How do you ensure zero downtime during budget season—**
> (1) Schedule all maintenance outside business hours. (2) Run data loads and heavy calculations overnight. (3) Monitor performance proactively via Activity Reports. (4) Pre-test Oracle monthly updates. (5) Keep DEV environment synchronized for emergency fixes. (6) Have rollback snapshots ready.

## 📌 Consultant Wisdom

**Q23: What is the biggest mistake you've seen in EPM implementations—**
> Lifting and shifting broken Excel processes into EPM without re-engineering. The result is a ₹1 Cr tool that operates exactly like the broken spreadsheets it replaced. Always re-engineer business processes first, THEN implement in EPM.

**Q24: How do you handle scope creep from clients during implementation—**
> (1) Document all requirements in BRD with sign-off. (2) For new requests, assess impact on timeline and budget. (3) Create a Change Request (CR) with effort estimate. (4) Let the client prioritize: include in current phase or defer to Phase 2. (5) Never say "no" — say "yes, here's what it costs."

**Q25: What makes a great EPM consultant vs a mediocre one—**
> Great consultant: Understands BOTH the business process AND the technology. Can explain to a CFO why a design decision matters. Thinks about performance from Day 1. Documents everything. Tests thoroughly. Mediocre consultant: Only knows which buttons to click. Doesn't understand why.
