## 📌 Beginner Labs (1-10)

### Lab 1: Create Your First Application
**Objective:** Create a Freeform application with a single BSO cube
1. Login to EPM Cloud → Application → Create
2. Choose "Freeform" type
3. Name: "Lab_Practice"
4. Create 1 BSO cube: "FinPlan"
5. **Expected:** Application appears on home page

### Lab 2: Build a Basic Dimension
**Objective:** Add members to the Account dimension
1. Navigate to Dimensions → Account
2. Add members: Revenue (parent), Rooms Revenue, F&B Revenue, Other Revenue
3. Add: Expenses (parent), Salaries, Rent, Utilities
4. Add: Net Profit (Dynamic Calc formula: Revenue - Expenses)
5. Refresh cube
6. **Expected:** Full P&L structure visible

### Lab 3: Create Entity Hierarchy
**Objective:** Build entity structure
1. Dimensions → Entity
2. Create: Total Company (parent)
3. Add: Hotel Division, Manufacturing Division
4. Under Hotel: Mumbai Branch, Delhi Branch
5. Set consolidation operators: all (+)
6. **Expected:** 2-level entity hierarchy

### Lab 4: Create a Simple Form
**Objective:** Build a data entry form
1. Navigate → Forms → Create
2. Name: "Revenue Input"
3. POV: Scenario=Budget, Version=Working, Year=FY26
4. Rows: Account (Revenue children)
5. Columns: Period (Jan-Dec)
6. Pages: Entity
7. **Expected:** Form opens with empty cells ready for input

### Lab 5: Enter Data and Verify Aggregation
**Objective:** Enter data and see it aggregate
1. Open "Revenue Input" form
2. Enter monthly values for Mumbai Branch
3. Switch to Delhi Branch (Pages), enter values
4. Click Save
5. Switch to Hotel Division — verify totals aggregate
6. **Expected:** Parent = sum of children

### Lab 6: Set Up Substitution Variables
**Objective:** Create and use substitution variables
1. Navigate → Administration → Variables
2. Create: CurrentMonth = Jul, BudgetYear = FY27
3. Edit your form → use &BudgetYear in Year POV
4. **Expected:** Form automatically uses FY27

### Lab 7: Create a Smart List
**Objective:** Build a dropdown for forms
1. Navigate → Dimensions → Smart Lists
2. Create: "ApprovalStatus" with values: Pending=1, Approved=2, Rejected=3
3. Create an Account member "Status" with Data Type = Smart List
4. Add "Status" to your form
5. **Expected:** Dropdown appears in form cells

### Lab 8: Configure Suppress Missing Data
**Objective:** See the impact of suppression
1. Enter data for only Jan-Mar (leave Apr-Dec empty)
2. Open form WITHOUT suppression → see empty rows
3. Edit form → enable Suppress Missing Data
4. Reopen form → empty rows disappear
5. **Expected:** Understand suppression behavior

### Lab 10: Create a Task List
**Objective:** Build a guided workflow
1. Navigate → Task Lists → Create
2. Add steps: Open Revenue Form → Enter Data → Run Calc → Submit
3. Assign to a user
4. **Expected:** User sees step-by-step task list

### 💡 Logic & Purpose
Task lists are the functional wrapper around technical components. A user doesn't know *what* "Revenue Form" or "Aggregate Rule" is; they just know they need to "Do Monthly Close". Task lists enforce sequential execution so users can't run the aggregation rule before entering the data.

### 🌀 Confusion Resolution
> **Misconception:** "I can use a Task List to secure forms. If a form isn't in a user's Task List, they can't access it."
> **Reality:** Task Lists DO NOT provide security! They are merely shortcuts (bookmarks). If a user has `Read/Write` access to a form, they can still navigate to `Data -> Forms` and open it directly, bypassing the Task List entirely. To truly lock a form, you must assign explicit form-level security in the Access Control tab.

### 😈 Twisted Interview Question
**Question:** You create a 5-step Task List. Step 3 runs a Business Rule. A user complains that the Business Rule fails every time they click it from the Task List, but if they open the related Form and run the rule from the Form's Action menu, it works perfectly. Why—
> **Answer:** Context! When you run a rule from a Form, the rule automatically inherits the exact Page and POV members the user is currently viewing. When you run a rule directly from a Task List, it has NO form context. If the rule uses Run-Time Prompts (RTPs) but relies on hidden form context to populate them, running it "naked" from the Task List will cause a validation failure because the prompts are empty.

## 📌 Intermediate Labs (11-20)

### Lab 11: Write Your First Business Rule
**Objective:** Create a simple calculation
```
SET CREATEBLOCKONEQ ON;
FIX("Budget","Working","FY26")
    "Net Profit" = "Revenue" - "Expenses";
ENDFIX
```
Validate → Deploy → Launch from form

### Lab 12: Data Copy — Seed Budget from Actuals
**Objective:** Copy last year's actuals to next year's budget
```
SET CREATEBLOCKONEQ ON;
FIX(@RELATIVE("Entity",0))
    DATACOPY "Actual"->"Final"->"FY26" TO "Budget"->"Working"->"FY27";
ENDFIX
```

### Lab 13: Create a Runtime Prompt

1. In Calc Manager → Create variable RTP_Entity (Member, Entity dimension)
2. Use in rule: `FIX({RTP_Entity}, "Budget") ... ENDFIX`
3. Deploy and launch → verify prompt appears

### Lab 14: Set Up Smart View Connection

3. Open a form in Smart View
4. Enter data → Submit

### Lab 16: Configure Security

1. Create a test user (Viewer role)
2. Set Entity E10001 → Read for test user
3. Set Entity E10002 → None for test user
4. Login as test user → verify they only see E10001

### Lab 17: Load Data via File
**Objective:** Import data from CSV
1. Create CSV: Account, Entity, Period, Scenario, Version, Year, Data
2. Upload to inbox
3. Configure Data Management import format
4. Run import
5. Verify data in form

### Lab 18: Create an Allocation Rule
**Objective:** Distribute cost across departments
```
FIX("Budget","Working","FY26")
    "Rent"(@RELATIVE("Department",0)) = 
        "Rent"->"Total Company" * 
        "Headcount" / "Headcount"->"Total Company";
ENDFIX
```

### Lab 19: Build a Rule Set
**Objective:** Chain multiple rules

2. Create Rule 2: Copy Actuals to Budget
3. Create Rule 3: Apply Growth Rate
4. Create Rule Set: "Budget_Process" (sequential)

### Lab 20: Performance Comparison
**Objective:** See FIX impact on performance
1. Create a rule WITHOUT FIX → time it
2. Create the same rule WITH FIX → time it
3. Compare execution times in Job Console
