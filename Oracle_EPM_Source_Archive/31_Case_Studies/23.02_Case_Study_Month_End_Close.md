# 23.02 — Case Study: Month-End Close Optimization

> **Module:** 23_Case_Studies | **Topic:** Reducing Close from 5 Days to 1 Day
> **Audience:** Consultant / Architect

---

## 1. THE PROBLEM

```
Hotel Pvt Ltd — Month-End Close (BEFORE optimization):

Day 1: Finance team downloads PMS data, cleans in Excel, uploads manually
Day 2: Admin runs data load, fixes errors, re-runs
Day 3: Admin manually runs 9 business rules one by one
Day 4: Controllers review data on forms, find errors, request re-runs
Day 5: Admin runs currency conversion, AGG, generates reports

Total: 5 business days, 3 people involved, ~120 person-hours/month
Pain: CFO gets consolidated numbers 7 calendar days after month-end
```

---

## 2. THE SOLUTION

### Automation Design

```
Automated Close Sequence (EPM Automate):

#!/bin/bash
# Monthly Close — runs at 2:00 AM on the 1st of each month
DATE=$(date +%Y%m%d)
LOG="monthly_close_${DATE}.log"

echo "=== Monthly Close Started: $(date) ===" >> $LOG

# Step 1: Update substitution variables (30 seconds)
epmautomate setsubstvars "ALL" "CurrMonth=Oct" "PriorMonth=Sep" "ForecastStart=Nov"

# Step 2: Upload and load data (2 minutes)
epmautomate uploadfile "/data/Oct_Revenue.csv"
epmautomate importdata "DL_Revenue_Actuals" "Oct_Revenue.csv"
epmautomate uploadfile "/data/Oct_Expenses.csv"
epmautomate importdata "DL_Expense_Actuals" "Oct_Expenses.csv"

# Step 3: Run Monthly Close Ruleset (30 seconds)
epmautomate runbusinessrule "RS_Monthly_Close" "RTP_Scenario=Actual" "RTP_Year=FY2026"

# Step 4: Smart Push to Reporting Cube (15 seconds)
epmautomate runbusinessrule "PUSH_to_Reporting"

# Step 5: Export validation data (30 seconds)
epmautomate exportdata "DE_Validation_Report"
epmautomate downloadfile "Validation_Report.csv"

# Step 6: Backup (2 minutes)
epmautomate exportsnapshot "Post_Close_${DATE}"

echo "=== Monthly Close Completed: $(date) ===" >> $LOG

# Step 7: Send email notification
python3 send_notification.py --status "SUCCESS" --log $LOG
```

### Ruleset: RS_Monthly_Close (runs as one unit)

```
Rules in sequence:
  1. CALC_Revenue_Totals     (0.5s)
  2. CALC_Expense_Totals     (0.5s)
  3. CALC_PnL_Complete       (1.2s)
  4. CALC_KPIs               (0.8s)
  5. CALC_Currency_Conversion (0.6s)
  6. ALLOC_Corporate_Cost    (1.0s)
  7. AGG_Entity              (2.0s)
  8. COPY_Rolling_Forecast   (1.5s)
  
  Total: ~8 seconds (vs 3 hours manual)
```

## 3. THE RESULTS

```
BEFORE                              AFTER
─────────────────────────────────────────────────────
5 business days                 →   6 minutes (automated)
3 people, 120 person-hrs/month  →   0 people (fully automated)
9 rules run manually            →   1 Ruleset (8 rules, auto)
Manual data upload              →   Auto upload + load
Manual SubVar update            →   Script updates vars
No validation                  →   Auto validation report
CFO sees data: Day 7            →   CFO sees data: Day 1 at 6 AM
Errors caught: Day 3-4          →   Errors caught: 2:10 AM (auto-email)
No backup after close          →   Auto snapshot created

ROI:
  120 person-hours/month saved × ₹500/hr = ₹60,000/month
  Annual savings: ₹7,20,000
  Implementation cost: ₹2,00,000 (one-time)
  Payback: 3.3 months
```

---

## 4. LESSONS LEARNED

```
✅ Key Success Factors:
  1. Standardize the PMS export format FIRST (before automation)
  2. Test the close script in DEV for 3 months before production
  3. "Stop on Error" in the Ruleset catches failures early
  4. Auto-email on failure is critical — someone must be notified
  5. Daily maintenance window at 2 AM → schedule close at 3 AM

⚠️ Gotchas:
  1. EPM Automate session timeout (60 min) — keep script under 50 min
  2. If data file is late → schedule a retry at 4 AM
  3. CLEARBLOCK ALL should run monthly (not during close — takes 5 min)
```
