## 🏢 1. What is IPM in Oracle EPM Cloud?

Oracle Intelligent Performance Management (IPM) is the native **Machine Learning and Artificial Intelligence suite** embedded directly within EPBCS / Planning Enterprise Cloud. It replaces manual human guesswork with statistical time-series forecasting.

### The Three Pillars of IPM
1. **Auto-Predict:** Runs automated ML forecasting jobs in the background and writes predicted values directly into target Essbase data intersections (e.g., seeding next year's baseline budget using 3 years of historical actuals).
2. **IPM Insights:** Proactively scans historical and forecast data across millions of intersections to detect **Forecast Biases**, **Hidden Anomalies**, and **Prediction Variances** without requiring users to run manual reports.
3. **Predictive Planning (Smart View / Web):** On-demand, real-time statistical simulation run by individual planners directly inside web forms or Excel Smart View grids (`Predictive Planning -> Predict`).

## 🏗️ 2. Auto-Predict Architecture & Mathematical Algorithms

When an interviewer asks: *"What statistical algorithms does Auto-Predict run under the hood when forecasting P&L?"*, an elite architect explains the exact multi-model evaluation engine:

```
┌────────────────────────────────────────────────────────────────────────┐
│                   AUTO-PREDICT ENGINE EVALUATION LOOP                  │
├────────────────────────────────────────────────────────────────────────┤
│ 1. Historical Data Extraction (Minimum 24-36 periods of Actuals)       │
│ 2. Parallel Algorithm Tournament (Runs all 5 models simultaneously)    │
│    ├── ARIMA (Auto-Regressive Integrated Moving Average)               │
│    ├── ETS (Error, Trend, Seasonal exponential smoothing)              │
│    ├── Damped Trend (Prevents infinite exponential explosion)          │
│    ├── Seasonal Additive / Multiplicative                              │
│    └── Holt-Winters Exponential Smoothing                              │
│ 3. Best-Fit Selection (Picks model with lowest RMSE / MAPE error)      │
│ 4. Target Write (Writes winning prediction to Target Scenario/Version) │
└────────────────────────────────────────────────────────────────────────┘
```

### The Best-Fit Evaluation Metrics
Oracle EPM automatically ranks the competing models for *every single individual intersection* using two statistical error formulas:
- **RMSE (Root Mean Squared Error):** Penalizes large outlier forecasting errors heavily.
- **MAPE (Mean Absolute Percentage Error):** Measures the average percentage deviation from historical actuals. The model with the lowest MAPE is crowned the winner and written to the cube.

## 🛠 3. Designing & Automating an Auto-Predict Job

Elite architects do not let financial analysts spend 3 weeks copying last year's actuals plus 5%. We design automated **Auto-Predict Jobs** that seed baseline budgets overnight before planning cycles begin.

### Step-by-Step Architect Configuration (`Application -> Overview -> Auto-Predict`)
1. **Define Source Slice (Historical Data):**
   - Cube: `FinPlan`
   - Scenario: `Actual`, Version: `Final`
   - Periods: `FY23 to FY25 (Jan - Dec)` *(Architect Rule: Always provide at least 3 full years of monthly data so the engine can detect quarterly seasonal spikes).*
2. **Define Target Slice (Where AI Writes Data):**
   - Scenario: `Baseline_AI`, Version: `Working`
   - Periods: `FY26 (Jan - Dec)`
3. **Define Prediction Scope & Filters:**
   - Account: `@RELATIVE("Total_Revenue", 0), @RELATIVE("Total_Opex", 0)`
   - Entity: `@RELATIVE("Total_Company", 0)`
4. **Execution & Automation:**
   - Schedule via EPM Automate after monthly close:
     ```bash
     # Run Auto-Predict Job from command line / overnight batch
     epmautomate runAutoPredict "Seed_FY26_AI_Baseline_Budget"
     ```

### 💡 Logic & Purpose
Auto-Predict handles the heavy statistical lifting so planners can focus on qualitative adjustments. By executing an overnight EPM Automate job, the system scans 3 years of actuals, runs ARIMA/Holt-Winters across 50,000 cost centers, and populates the `Baseline_AI` scenario before planners even log in the next morning.

### 🌀 Confusion Resolution
> **Misconception:** "The AI will automatically adjust for COVID-19 anomalies or one-time massive asset sales."
> **Reality:** The mathematical models are purely quantitative; they do not read the news. If a massive one-time asset sale spiked revenue by 900% in March 2024, the ML model will treat that as a legitimate data point and likely forecast another massive spike in March 2025. Architects MUST pre-clean the historical data (or use data mapping to exclude one-off accounts) before feeding it into the Auto-Predict engine.

### 😈 Twisted Interview Question
**Question:** You run an Auto-Predict job using 3 years of actuals. For a specific Account `Travel_Expense`, the historical data was `$1,000` every single month for 36 months, with zero variation. When you check the prediction for the next 12 months, the AI wrote `$0` (or `#Missing`). Why?
> **Answer:** Lack of variance triggers flatline rejection! The time-series ML algorithms (like ARIMA) require volatility to calculate a standard deviation and trend. If a data series is mathematically perfectly flat (variance = 0), the statistical models fail to converge, classify the series as non-statistical noise, and bypass predicting it entirely.

## ️ 4. IPM Insights: Anomaly & Bias Detection Algorithms

IPM Insights runs as a background data-mining engine (`Application -> IPM Insights`) that scans data blocks and generates actionable insight cards on the user's dashboard.

### The Three Insight Types
| Insight Card Type | What the AI Detects | Mathematical Trigger Condition |
| :--- | :--- | :--- |
| **Forecast Bias** | Detects if a department manager habitually over-forecasts or under-forecasts expenses year after year (`Sandbagging` or `Optimism bias`). | Historical forecast vs. actual variance exhibits a consistent directional bias ($> 5\%$ variance across at least 4 out of 6 consecutive historical periods). |
| **Anomaly Detection** | Detects unusual data spikes or dips in historical actuals or submitted forecasts that deviate wildly from established seasonal norms. | Data point falls outside the **95% Prediction Interval Band** ($2 \times \text{Standard Deviation}$ above or below historical best-fit trendline). |
| **Prediction Check** | Compares the user's manually entered forecast against the AI's statistical prediction to highlight massive discrepancies before executive review. | Manual user submission (`Working`) differs by $> 15\%$ from the AI prediction (`Auto-Predict`) across any future period. |

## 🔌 5. Elite Groovy Integration: Reading IPM Predictions in Rules

An elite architect knows how to bridge IPM Machine Learning with Groovy rules. If a user submits a budget that violates the AI's 95% confidence interval, we can use Groovy to **intercept the form save and force the user to enter a mandatory explanation note!**

```groovy
/* ELITE ARCHITECTURE: GROOVY + IPM AI VARIANCE INTERCEPTOR */
Cube cube = operation.application.getCube("FinPlan")

operation.grid.dataCellIterator().each { DataCell userCell ->
    if (userCell.isEdited() && userCell.data != null) {
        // Retrieve the corresponding AI Prediction value from the 'Baseline_AI' scenario
        double aiPrediction = userCell.crossDim("Baseline_AI", "Final").data
        
        if (aiPrediction > 0) {
            double variancePct = Math.abs(userCell.data - aiPrediction) / aiPrediction
            
            // If the user's entry deviates by more than 25% from what the AI predicted
            if (variancePct > 0.25) {
                String entity = userCell.getMemberName("Entity")
                String account = userCell.getMemberName("Account")
                
                println("⚠️ AI Variance Alert: ${account} for ${entity} deviates by ${Math.round(variancePct*100)}% from AI baseline.")
                
                // Add a permanent cell note flagging the variance for executive review
                userCell.addNote("SYSTEM AI ALERT: Submitted value ($${userCell.data}) deviates by ${Math.round(variancePct*100)}% from statistical ML prediction ($${Math.round(aiPrediction)}). Please justify.")
            }
        }
    }
}
```

## 🔧 6. Interview Scenarios: IPM & Machine Learning Troubleshooting

### Q: An Auto-Predict job runs successfully, but 40% of the target intersections show `#Missing`. Why did the AI skip them?
> **Architect Answer:** The ML engine requires a minimum volume of historical data to achieve statistical significance (`Minimum 12 non-zero historical data points across 24 months`). If a specific cost center or product intersection had all `#Missing` or zeros for 18 out of 24 historical periods (`Sparse data series`), the engine marks the series as **Unpredictable** and bypasses target calculation to prevent outputting statistical noise.

### Q: Why does Auto-Predict run fast on BSO (`2 minutes`) but takes `35 minutes` when writing predictions directly to an ASO cube?
> **Architect Answer:** When Auto-Predict writes to a BSO cube, it writes directly into high-speed physical dense block arrays (`.pag`). When writing directly to an ASO cube, every single predicted tuple must be passed through the ASO incremental slice buffer and committed via relational transaction pipes. **Best Practice:** Always run Auto-Predict jobs against your **BSO input cube (`FinPlan`)**, and then run a high-speed **Data Map (`Smart Push`)** to push the completed AI predictions across to the ASO reporting cube in seconds.
