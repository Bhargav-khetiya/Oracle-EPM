# 🏗️ 28.13 — Dimension Editor Screen: Complete Encyclopedia

> **Source:** Oracle® Fusion Cloud EPM Administering Planning (Aug 2026), Chapters 13 & 25
> **Navigation:** Home → Application → Overview → Dimensions → [click dimension name]
> **Audience:** Service Administrator / Technical Consultant

---

## 1. WHY — What Problem Does the Dimension Editor Solve—

**The problem:** EPBCS stores all of its data organized around dimensions (Account, Entity, Period, etc.). To add new accounts, change how values aggregate, set storage properties, or build the hierarchical structure — you need a way to edit these dimension members visually.

**The solution:** The Dimension Editor (now called the Simplified Dimension Editor) is a spreadsheet-like interface that lets you see ALL members of a dimension and edit their properties directly in-line, in bulk, with drag-and-drop support.

**Consultant importance:** You will use this screen daily. Adding new cost centers, changing an account type, fixing a storage property, moving a member to a new parent — all happens here.

---

## 2. WHAT — Plain English Definition

The Simplified Dimension Editor is a **grid-based interface** that shows all members of a dimension as rows, with their properties as columns. You can:
- Add, edit, delete members
- Change properties for multiple members at once (drag-and-drop property values)
- View and edit member formulas
- Move members up/down or to different parent
- Search/filter to find specific members
- Zoom in/out of hierarchies
- Copy member names from Excel

There are **TWO versions** of the dimension editor:
1. **Simplified Dimension Editor** (current default) — grid-based, in-line editing
2. **Classic Dimension Editor** (legacy) — tree-based, slower, via Navigator → Dimensions

---

## 3. TWO NAVIGATION PATHS

### Path 1: Simplified Dimension Editor (Recommended)
```
Home → Application → Overview → Dimensions tab → Click dimension name
```
Result: Opens the Simplified Dimension Editor (grid format)

### Path 2: Classic Dimension Editor (Legacy)
```
Home → Navigator (≡) → Create and Manage → Dimensions → Select dimension
```
Result: Opens the Classic Dimension Editor (tree format)

> ⚠️ **Note:** Oracle recommends using the Simplified Dimension Editor. The Classic editor is still available for backward compatibility but is older technology.

## 5. TOOLBAR — EVERY BUTTON DOCUMENTED

### Actions Menu (dropdown)
| Action | Description |
|--------|-------------|
| **Add Child** | Adds a new member as a child of selected member |
| **Add Sibling** | Adds a new member at same level as selected |
| **Delete** | Deletes selected member AND all its descendants and shared members |
| **Show Ancestors** | Shows the chain of parent → grandparent → root for selected member |
| **Show Usage** | Shows ALL places this member is used (forms, approval units, exchange rates, etc.) |
| **Select Columns** | Opens column selector to add/remove/reorder property columns |
| **Sort Ascending/Descending** | Sorts children or descendants of selected member |

### Zoom Controls
| Button | What It Does |
|--------|-------------|
| **Zoom In Next Level** | Shows all members one level BELOW the selected member |
| **Zoom In All Levels** | Shows ALL descendants below the selected member |
| **Zoom In Bottom Level** | Shows only leaf-level (no children) descendants |
| **Zoom Out** | Shows the member one level ABOVE selected |
| **Keep Selected** | Shows ONLY the selected row/column (hides everything else) |
| **Remove Selected** | Removes the selected row/column from view (doesn't delete from database) |
| **Freeze** | Locks selected column and all columns to the left (columns to right can scroll) |

### Search Bar
| Option | Description |
|--------|-------------|
| **Name** | Search by member name |
| **Alias** | Search by alias |
| **Both** | Search by both name and alias |
| **Search Up (▲)** | Searches upward from current position |
| **Search Down (▼)** | Searches downward from current position |
| **Filter Search (≡)** | Returns ALL matching members as a filtered list |
| **Clear Filter** | Removes filter, shows full hierarchy |

### Sort Options
| Option | Description |
|--------|-------------|
| **Children** | Sorts ONLY the immediate children of selected member |
| **Descendants** | Sorts ALL descendants of selected member |
| **Ascending (↑)** | A → Z order |
| **Descending (↓)** | Z → A order |

> ⚠️ **Cannot sort:** Dense dimensions, "Plan Element" in Financials, "Project Element" in Projects

### Formula Bar
Located above the grid. When you click on a member's formula cell:
- **Formula bar** appears showing the current formula
- **Member Formula button (✏)** — opens a full formula editor with Validate option
- **Tip:** Press `Ctrl + click` on another member name while in formula bar to insert that member name into the formula

### Move Up / Move Down
- Moves the selected member up or down ONE position in the hierarchy
- Affects the Essbase outline order

## 7. COMPLETE MEMBER PROPERTIES — FULL REFERENCE TABLE

### Data Storage Options Explained

| Option | Symbol | When to Use |
|--------|--------|-------------|
| **Store** | (none) | Level-0 members where users enter data |
| **Dynamic Calc** | D | Upper-level members calculated from children (formula or aggregation). Values NOT stored |
| **Dynamic Calc and Store** | DS | Members with complex formulas that are frequently retrieved. Values ARE stored |
| **Never Share** | NS | Default for custom dimension members. Use for members that should never inherit another member's data |
| **Shared** | S | Second instance of a member pointing to the base member's data (alternate rollups) |
| **Label Only** | LO | Navigation-only members with no associated data storage. Value shown = first child's value |

**Oracle Best Practices for Data Storage:**
```
Dense dimensions upper levels  → Dynamic Calc (NEVER Dynamic Calc and Store)
Sparse dimensions upper levels → Dynamic Calc
Dense dimensions leaf levels   → Store (for data entry)
Sparse dimensions with complex formulas → Dynamic Calc and Store
Members with multiple users accessing simultaneously → Dynamic Calc
```

### Time Balance Options Explained

| Time Balance | How Q1 is Calculated | Use Case |
|--------------|---------------------|----------|
| **Flow** | Jan + Feb + Mar | Revenue, Expenses (accumulate) |
| **First** | Jan value only | Beginning balance (e.g., opening stock) |
| **Balance** | Mar value only | Ending balance (e.g., closing stock, headcount) |
| **Average** | (Jan+Feb+Mar)/3 | Average rates |
| **Fill** | Q1 = child value; fills all children | Assumption-style members |
| **Weighted Avg - Actual_Actual** | Weighted by actual days (leap year aware) | Interest rates, etc. |
| **Weighted Avg - Actual_365** | Weighted assuming 365 days always | Interest rates (non-leap-year model) |
| **Custom** | Spreading disabled — admin writes custom Groovy rule | Complex custom scenarios |
| **Disable** | Spreading disabled — parent is read-only | Prevent entry at summary levels |

### Account Types Summary

| Account Type | Time Balance | Variance = (Actual - Budget) | Sign |
|--------------|-------------|------------------------------|------|
| **Revenue** | Flow | Positive = favorable | Credits |
| **Expense** | Flow | Negative = favorable (Budget - Actual) | Debits |
| **Asset** | Balance | Positive = favorable | Debits |
| **Liability** | Balance | Negative = favorable | Credits |
| **Equity** | Balance | Per formula | Credits |
| **Saved Assumption** | User-defined | User-defined | User-defined |

## 10. KEY OPERATIONS — STEP BY STEP

### Adding a New Member (Child)
```
1. Select the parent member (e.g., "Total Revenue")
2. Actions → Add Child
3. New row appears below — type the member name
4. Set properties in each column (Account Type, Data Storage, etc.)
5. Click Save
6. Go to Application → Overview → Actions → Refresh Database
```

### Moving a Member to a New Parent
```
Method 1 (Grid): 
   - Click the "Parent Member" cell for the member
   - Type the new parent name
   - Click Save

Method 2 (Move Up/Down):
   - Only moves within the same parent's children
   - Click Move Up or Move Down buttons
```

### Deleting a Member
> ⚠️ DANGER: Deleting a member deletes ALL data for that member AND all descendants.

```
1. First check where it's used: Actions → Show Usage
2. Remove member from any forms, approval units, exchange rates
3. Select the member
4. Right-click → Delete (OR Actions → Delete)
5. Confirm deletion
6. Refresh database
```

### Adding a Member Formula
```
1. Add "Default Formula" column if not visible
   (Right-click column header → Select Columns → Member Formula → Default Formula)
2. Click the formula cell for the member
3. Formula bar appears above the grid
4. Type formula OR click ✏ (Member Formula) for full editor
5. In full editor: click Validate to check syntax
6. Click Save
```

### Copying Member Names from Excel
```
1. In Excel: Select the cells with member names → Ctrl+C
2. In Dimension Editor: Select target cells → Ctrl+V
3. Clipboard Helper dialog appears
4. Press Ctrl+V again in the dialog
5. Click Paste
```

## 11. HOTEL PVT LTD EXAMPLE

### Scenario: Adding a New Revenue Category

**Business Need:** Hotel Pvt Ltd wants to add "Spa Revenue" as a new revenue line under "Total Revenue".

**Step-by-Step:**
```
1. Navigate: Home → Application → Overview → Dimensions tab
2. Click "Account" dimension
3. In grid, find "Total Revenue" member
4. Right-click "Total Revenue" → Add Child
5. New row appears:
   - Member Name: [Spa_Revenue]
   - Parent Member: [Total Revenue]
   - Account Type: [Revenue]
   - Time Balance: [Flow]
   - Data Storage: [Store]
   - Consol Op (OEP_FS cube): [+]
   - Consol Op (OEP_REP cube): [+]
6. Click Save
7. Application → Overview → Actions → Refresh Database
8. Verification: Open Hotel Revenue Form → Spa_Revenue appears as new row
```

### Key Properties Set:
```
Account Type = Revenue   → System knows it flows upward, variance = favorable if positive
Time Balance = Flow      → Q1 Revenue = Jan + Feb + Mar (sum of all months)
Data Storage = Store     → Users can enter data into this cell
Consol Op = +            → Adds to Total Revenue parent
```

## 12. TOP 10 DIMENSION DESIGN BEST PRACTICES (from Oracle)

1. **Dimension order = modified hourglass** — Dense first, then less dense, then sparse (most dense sparse first, least dense sparse last). For Hybrid BSO: non-dynamic sparse before dynamic sparse.

2. **Block size critical** — Optimal block size = 8KB to 500KB. Max 3 dense dimensions. Level 1+ members in dense dims should be Label Only or Dynamic Calc.

3. **Text/SmartList/Date accounts → Never consolidation** — Set Cube Consol Op to Never for these types. Aggregating them creates useless data and bloats the cube.

4. **Generation 2 members → Ignore** — Can't assign security to Gen 1 (root). No point aggregating Gen 2 to root. Use Ignore.

5. **Avoid flat/long dimensions** — If >200 members under a parent, add intermediate parents. Long flat hierarchies degrade aggregation performance.

6. **HSP_NOLINK UDA for multi-cube members** — Enabling members for multiple cubes creates dynamic X-Refs. Add HSP_NOLINK UDA to avoid them; use Smart Push/Data Maps instead.

7. **Simple calcs → outline math** — Don't write formulas for Account C = Account A - Account B. Use consolidation operators (-) instead.

8. **Avoid single-child parents** — Single children create implied shares or duplicate blocks. Design to have at least 2 children under each parent.

9. **Large dims → ASO, not BSO** — Aggregate dimensions with many members in ASO for better performance.

10. **Historical data >2 years → ASO** — Keep BSO light (only what's needed for calculations). Move historical data to ASO.

## 13. INTERVIEW QUESTIONS

### Beginner
**Q: You added a new Entity member "Pune_Hotel" to the Entity dimension and saved. But when users open a form, Pune_Hotel doesn't appear. What happened—**
> **A:** You saved to the relational database but forgot to run "Refresh Database." Navigate to Home → Application → Overview → Actions → Refresh Database. This pushes the metadata changes from the relational layer into the Essbase physical outline file (.otl). Until this is done, the new member doesn't exist in Essbase and won't appear in forms.

### Intermediate
**Q: What is the difference between Dynamic Calc and Dynamic Calc and Store— When do you use each—**
> **A:** Both calculate values on-the-fly using formulas or aggregation. The difference is storage: Dynamic Calc discards the calculated value immediately — the value is recalculated every time it's requested. Dynamic Calc and Store calculates AND saves the result to disk.
> Use Dynamic Calc for: (1) all dense dimension upper-level members, (2) members accessed concurrently by many users, (3) when disk space is a concern.
> Use Dynamic Calc and Store for: sparse dimension members with complex formulas that many users retrieve frequently — because storing the result avoids re-calculating a complex formula repeatedly.

### Architect
**Q: A client has an Account dimension with 1,200 leaf members. The Essbase cube is getting very slow during aggregation. Looking at the dimension, all members are set to "Store". What are the three things you would fix and why—**
> **A:** (1) **Set upper-level Account members to Dynamic Calc** — parent accounts like "Total Revenue" don't need stored values if their children are all Store. Dynamic Calc parents are calculated on-the-fly, reducing block size dramatically.
> (2) **Set non-aggregating accounts (Text, Smart List, Date type) to Consolidation = Never** — these should never roll up. Aggregating them creates meaningless data blocks and inflates cube size.
> (3) **Add intermediate parents** to any parent with >200 children — long flat hierarchies force Essbase to process too many members at once during aggregation. Breaking them up with intermediate groupings (e.g., "Room Revenue Group", "F&B Revenue Group") improves aggregation performance.
> Additionally: Review whether Label Only can replace some intermediate parents that don't need data.
