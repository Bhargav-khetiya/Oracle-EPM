## 1. WHY — What Problem Do Substitution Variables Solve?

**The problem:** Business rules, forms, and member selections often need to reference "the current month," "the current year," or "the budget scenario" — values that change over time. Hardcoding these creates maintenance nightmares: you'd have to edit every rule/form each month.

**The solution:** Substitution Variables are **named placeholders** stored at the cube/application level that resolve to a specific member name at runtime. Change the variable once → every rule and form that references it automatically uses the new value.

**Hotel Pvt Ltd use case:** `&CurrMonth` = "Mar" — all forms and rules reference `&CurrMonth`. When April starts, admin changes it to "Apr" → everything updates automatically.

---

## 2. WHAT — Plain English Definition

A Substitution Variable is a **global name=value pair** that:
- Is prefixed with `&` when used in formulas/scripts (e.g., `&CurrMonth`)
- Resolves to a **text string** (typically a member name)
- Can be scoped at **Application** level or **Cube** level
- Changes are **immediate** — no refresh/deploy needed

**Three types of variables in EPBCS:**
| Variable Type | Created Where | Scope | Used By |
|--------------|---------------|-------|---------|
| **Substitution Variables** | Navigator → Variables | App/Cube | Rules, forms, member selections |
| **User Variables** | Navigator → Variables | Per-user | Forms (Page/POV — each user sees their own entity) |
| **Smart Lists** | Application → Smart Lists | Members | Data cells (dropdown selections) |

## 5. COMMON SUBSTITUTION VARIABLES IN EPBCS

| Variable | Typical Value | Usage |
|----------|--------------|-------|
| `&CurrMonth` | "Aug" | Current reporting month |
| `&CurrYear` | "FY2026" | Current fiscal year |
| `&BudgetYear` | "FY2027" | Year being budgeted |
| `&PriorYear` | "FY2025" | Previous year (for variance) |
| `&ForecastStart` | "Sep" | Month from which forecast begins |
| `&ForecastEnd` | "Dec" | Last forecast month |
| `&CurrScenario` | "Actual" | Active scenario |
| `&ActualVersion` | "V_Actual" | Version for actual data |
| `&BudgetVersion` | "Working" | Version for budget data |

### How They're Used in Rules (Calc Scripts):

```
FIX(&CurrScenario, &BudgetVersion, &CurrYear)
  "Total Revenue" = "Room Revenue" + "F&B Revenue";
ENDFIX

/* When CurrScenario=Budget, BudgetVersion=Working, CurrYear=FY2026
   Essbase resolves this to:
   FIX("Budget", "Working", "FY2026")
     "Total Revenue" = "Room Revenue" + "F&B Revenue";
   ENDFIX
*/
```

### How They're Used in Forms:

In the form designer, when selecting members for a dimension:
```
Row dimension Account: Select "Variables" tab → "Substitution Variables"
Select &CurrMonth as a member selection

Result: The form shows data for whatever month &CurrMonth resolves to.
When admin changes &CurrMonth from "Aug" to "Sep", the form
automatically shows September data next time it's opened.
```

### How User Variables Work

1. Admin creates a User Variable (e.g., "UserEntity" linked to Entity dimension)
2. Admin uses "UserEntity" in a form's Page or POV axis as a member selection
3. Each user sets their own value via **Tools → User Preferences → User Variables**
4. When user opens the form, their personal entity value is pre-selected

```
Admin creates: UserEntity (Dimension = Entity)

User A sets: UserEntity = Mumbai_Hotel
User B sets: UserEntity = Delhi_Hotel

When both open the same form:
  User A sees Mumbai_Hotel data
  User B sees Delhi_Hotel data
```

## 7. KEY DIFFERENCES: SUBSTITUTION vs USER VARIABLES

| Feature | Substitution Variable | User Variable |
|---------|----------------------|---------------|
| **Scope** | Global (all users get same value) | Per-user (each user has own value) |
| **Who sets it** | Admin only | Each user (via User Preferences) |
| **Prefix** | `&` (in calc scripts) | No prefix (form designer selection) |
| **Used in** | Rules, forms, member selections | Forms only (Page, POV, Row, Column) |
| **Dimension link** | Not linked to specific dimension | Linked to a specific dimension |
| **Change frequency** | Monthly (admin updates) | Per-user, anytime |
| **Typical use** | Current month, current year | User's entity, user's department |

## 9. DO's AND DON'Ts

### ✅ DO
- **DO** use substitution variables for anything that changes on a schedule (month, year, forecast start)
- **DO** use user variables for entity/department personalization on forms
- **DO** document all substitution variables and their update schedule
- **DO** verify the value is a valid member name before saving
- **DO** use meaningful names: `CurrMonth` not `Var1`

### ❌ DON'T
- **DON'T** hardcode months/years in business rules — always use substitution variables
- **DON'T** forget to update substitution variables at the start of each month/cycle
- **DON'T** delete a substitution variable without checking usage (rules and forms will break)
- **DON'T** use spaces in substitution variable names
- **DON'T** use substitution variables where user variables are appropriate (and vice versa)

## 10. INTERVIEW QUESTIONS

### Beginner
**Q: What happens if the admin doesn't update the &CurrMonth substitution variable at the start of the new month?**
> **A:** All forms and rules that reference &CurrMonth will continue showing/calculating for the old month. Users will see stale data — forms will show July data when it's August. Rules will aggregate/calculate for July instead of August. This is a common operational mistake. Best practice: Create a Task List or calendar reminder for the admin to update substitution variables on the 1st of each month.

### Intermediate
**Q: You have a form where 5 different department heads need to see their own department's data, but you want to use only ONE form definition. How do you set this up?**
> **A:** Use a User Variable. (1) Create a User Variable named "UserDept" linked to the Department dimension (Navigator → Variables → User Variables → Create). (2) In the form designer, on the Page axis for the Department dimension, select the "UserDept" user variable as the member selection. (3) Each department head goes to Tools → User Preferences → User Variables → sets UserDept to their department (e.g., F&B, Rooms, Maintenance). (4) When each user opens the form, they see their own department's data. Optionally, enable "Dynamic User Variables" on the form so users can switch departments directly from the page dropdown without going to User Preferences.

### Architect
**Q: A client wants a rolling 18-month forecast. The current month is August 2026 — the forecast covers Sep 2026 through Feb 2028. What substitution variables would you create, and how do you handle the year boundary?**
> **A:** Create these substitution variables:
> - `&CurrMonth` = "Aug" (current actual month)
> - `&ForecastStartMonth` = "Sep" (first forecast month)
> - `&ForecastStartYear` = "FY2026" (year of forecast start)
> - `&ForecastEndMonth` = "Feb" (last forecast month — 18 months ahead)
> - `&ForecastEndYear` = "FY2028" (year of forecast end)
> - `&CurrYear` = "FY2026"
> 
> The year boundary challenge: Since the forecast spans FY2026 (Sep-Dec) and FY2027 (Jan-Dec) and FY2028 (Jan-Feb), the business rule needs TWO FIX blocks:
> ```
> FIX("Forecast", "Working")
>   FIX(&ForecastStartYear, &ForecastStartMonth:@MEMBER("Dec"))
>     /* Sep-Dec 2026 calculations */
>   ENDFIX
>   FIX("FY2027")
>     /* Jan-Dec 2027 calculations */
>   ENDFIX
>   FIX(&ForecastEndYear, @MEMBER("Jan"):&ForecastEndMonth)
>     /* Jan-Feb 2028 calculations */
>   ENDFIX
> ENDFIX
> ```
> Alternatively, use a Groovy rule to dynamically generate the calc script based on the substitution variable values, handling the year boundary programmatically.
