## 1. WHY — What Problem Does the Currency System Solve—

**The problem:** Hotel Pvt Ltd operates in India (INR) but reports to international investors in USD. Each hotel enters budgets in local currency, but consolidated reports need to be in a single reporting currency. Exchange rates fluctuate, and different accounts need different rate types (revenue uses average rate, balance sheet uses closing rate).

**The solution:** EPBCS provides a built-in multicurrency framework that:
- Defines available currencies (INR, USD, EUR, etc.)
- Stores exchange rates per period
- Converts data automatically using business rules
- Supports different rate types per account (Average, Ending, Historical)

## 2. TWO MULTICURRENCY MODES

| Mode | Description | When to Use |
|------|-------------|-------------|
| **Simplified Multicurrency** | Single exchange rate table, simpler setup | Small apps, one base currency, limited FX needs |
| **Standard Multicurrency** | Full Currency dimension with multiple rate tables, triangulation | Enterprise apps with multiple base currencies and complex FX requirements |

### Rate Types Explained

| Rate Type | Used For | When Applied |
|-----------|----------|-------------|
| **Average** | Revenue, Expense (P&L items) | Uses the average rate for the period — reflects exchange rate over the entire period |
| **Ending** | Balance Sheet items (Assets, Liabilities) | Uses the rate at the end of the period — closing rate |
| **Historical** | Equity items, historical transactions | Uses a fixed rate — same rate regardless of period |

### Account → Rate Type Mapping

The **Exchange Rate Type** property on each Account member controls which rate is used:

```
Account Member       → Exchange Rate Type  → Rate Used
────────────────────────────────────────────────────────
Room_Revenue         → Average             → Average rate for the period
F&B_Revenue          → Average             → Average rate for the period
Total_Revenue        → Average             → Average rate (derived)
Cash                 → Ending              → End-of-period closing rate
Accounts_Receivable  → Ending              → End-of-period closing rate
Retained_Earnings    → Historical          → Fixed historical rate
Common_Stock         → Historical          → Fixed historical rate
```

## 6. HOW CURRENCY CONVERSION WORKS

### Step-by-Step Flow

```
1. Entity Mumbai_Hotel has Base Currency = INR
2. User enters data in INR:
   Room_Revenue Jan = ₹10,00,000

3. Admin enters exchange rate:
   INR → USD Average Jan = 0.01198

4. Admin runs Currency Conversion business rule:
   (Built-in rule: "Calculate Currencies" or custom rule)

5. EPBCS calculates:
   Room_Revenue Jan USD = ₹10,00,000 × 0.01198 = $11,980

6. Users switching Reporting Currency to USD see:
   Room_Revenue Jan = $11,980
```

### The Currency Dimension

In Standard Multicurrency apps, a **Currency dimension** is automatically created:

```
Currency (dimension)
├── Local           → Data in entity's base currency (INR for Mumbai)
├── INR             → Data converted to INR
├── USD             → Data converted to USD
├── EUR             → Data converted to EUR (if reporting currency)
└── HSP_InputCurrency → Tracks which currency data was entered in
```

## 7. HOTEL PVT LTD EXAMPLE

### Currency Setup

```
Currencies:
  INR (₹) — Base currency for all 5 Indian hotels
  USD ($) — Reporting currency for investors

Exchange Rates (FY2026):
  INR → USD (Multiply method)
  Jan: Avg=0.01198, End=0.01195
  Feb: Avg=0.01201, End=0.01203
  ...
  Dec: Avg=0.01180, End=0.01175

Entity Base Currencies:
  Mumbai_Hotel → INR
  Delhi_Hotel → INR
  Bangalore_Hotel → INR
  All_Hotels → USD (reporting level)

Account Rate Types:
  Revenue accounts → Average
  Expense accounts → Average
  Balance sheet accounts → Ending
  Equity accounts → Historical
```

### Monthly Currency Process

```
1. Hotels enter budgets in INR (their local currency)
2. Admin updates exchange rates monthly:
   Navigator → Administration → Currency
   Enter latest rates for each period
3. Admin runs Currency Conversion rule:
   Navigator → Rules → "Calculate Currencies" → Launch
   RTPs: Scenario=Budget, Version=Working, Year=FY2027
4. Finance team views reports in USD:
   Form POV → Currency = USD → sees converted values
5. Variance analysis:
   Budget in INR vs Actual in INR → operational variance
   Budget in USD vs Actual in USD → includes FX impact
```

## 8. DO's AND DON'Ts

### ✅ DO
- **DO** set Account Exchange Rate Type correctly — Revenue=Average, BS=Ending
- **DO** enter rates BEFORE running currency conversion rules
- **DO** use the import feature for bulk rate updates (CSV file)
- **DO** verify converted values after running conversion
- **DO** run conversion rules after every data update if accuracy is critical

### ❌ DON'T
- **DON'T** enter data directly in a non-local currency — always enter in local, convert
- **DON'T** forget to run the conversion rule after changing rates — stale conversions
- **DON'T** use Multiply vs Divide incorrectly — check the direction (INR→USD = multiply by 0.012)
- **DON'T** leave Exchange Rate Type as "None" on accounts that need conversion

## 9. INTERVIEW QUESTIONS

### Beginner
**Q: Mumbai Hotel enters revenue in INR. How does the CFO see it in USD—**
> **A:** (1) Mumbai_Hotel's base currency is set to INR. (2) The admin enters exchange rates in the rate table (INR → USD, Average rate per month). (3) The admin runs the Currency Conversion business rule. (4) EPBCS calculates: INR amount × exchange rate = USD amount. (5) The CFO changes the Currency POV on the form to USD and sees the converted values. All P&L items use the Average rate; Balance Sheet items use the Ending rate.

### Intermediate
**Q: Revenue in January was ₹10,00,000 with an average rate of 0.01198. In February, revenue was also ₹10,00,000 but the average rate was 0.01201. What does Q1 show in USD, and why is it different from simply multiplying Q1 INR by one rate—**
> **A:** Jan USD = ₹10,00,000 × 0.01198 = $11,980. Feb USD = ₹10,00,000 × 0.01201 = $12,010. Assuming Mar USD is similarly calculated, Q1 USD = $11,980 + $12,010 + Mar USD (sum of monthly converted values). This is DIFFERENT from taking Q1 INR (₹30,00,000) × Q1 Average Rate because Q1's average rate would be the weighted average across the quarter. EPBCS correctly handles this by converting each period individually and then summing — this avoids the "cross-product" rate error.
