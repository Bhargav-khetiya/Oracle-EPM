## 1. WHY — What Problem Do Application Settings Solve—

**The problem:** EPBCS applications have dozens of global behaviors — how missing values display, which Essbase features are enabled, what the default alias table is, whether sandboxes are active, etc. These need to be configured once and applied everywhere.

**The solution:** Application Settings is a single, centralized configuration page that controls global behavior across the entire application — forms, rules, data loading, and UI.

## 4. CRITICAL SETTINGS EXPLAINED

### Hybrid Mode
```
What: Enables Hybrid BSO (Block Storage with ASO-like dynamic calc)
Why: Major performance improvement — reduces block creation, enables larger dims
Impact: Once enabled, CANNOT be easily reverted
Recommendation: ✅ Always enable for new applications

Before Hybrid:
  Every parent member stores data → blocks created → slow
  
After Hybrid:
  Parent members are dynamically calculated → no blocks → fast
  Level 0 members still store data normally
```

### Sandboxes
```
What: Isolated testing environments within the application
Why: Test metadata changes, rule modifications without affecting production
Impact: Creates HSP_View dimension with Base and SandboxN members
Recommendation: ✅ Enable for development; consider performance impact
```

### Audit
```
What: Tracks all data and metadata changes
Why: Compliance, troubleshooting, accountability
Impact: Slight performance overhead for data writes
Recommendation: ✅ Enable for production environments
```

## 6. DO's AND DON'Ts

### ✅ DO
- **DO** enable Audit before going live — you can't track changes retroactively
- **DO** enable Hybrid Mode for new applications — major performance benefit
- **DO** enable Valid Intersections if you have structural restrictions
- **DO** review settings before migrating to production

### ❌ DON'T
- **DON'T** enable Enhanced Calc in Forms unless users specifically need it — adds processing
- **DON'T** disable Hybrid Mode after enabling it — complex reversal process
- **DON'T** enable Cell-Level Security unless absolutely required — adds overhead to every cell check
- **DON'T** change the Thousands/Decimal separator after users have entered data — causes display confusion

## 7. INTERVIEW QUESTIONS

### Beginner
**Q: Where do you enable auditing in EPBCS—**
> **A:** Application → Settings → Enable Audit = ☑, then also check "Audit Data Changes" and/or "Audit Metadata Changes" depending on what you need to track. Changes are viewable at Navigator → Administration → Audit.

### Intermediate
**Q: What is Hybrid Mode, and should you enable it—**
> **A:** Hybrid Mode enables Hybrid BSO in Essbase — it combines BSO (block storage for data entry) with ASO-like dynamic calculation for parent members. This drastically reduces the number of blocks created, improving performance for large applications. You should ALWAYS enable it for new applications. In Hybrid Mode, parent members default to Dynamic Calc, so they don't create blocks — only level 0 (leaf) members store data. The trade-off: some legacy Essbase functions (like certain SET commands) don't work in Hybrid Mode.
