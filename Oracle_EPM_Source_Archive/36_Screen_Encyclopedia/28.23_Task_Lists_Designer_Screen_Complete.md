## 1. WHY — What Problem Do Task Lists Solve?

**The problem:** A budgeting process has many steps: enter revenue, enter expenses, run rules, review P&L, submit for approval. Users forget steps, do them out of order, or miss deadlines. Administrators have no visibility into who has completed what.

**The solution:** Task Lists are **guided checklists** that define the step-by-step workflow for a business process. Each task can open a specific form, run a rule, link to a URL, or provide instructions. Admins can track completion.

**Hotel Pvt Ltd use case:** "Monthly Budget Entry" task list with 8 steps — from entering revenue data to submitting for approval.

> ⚠️ **Note:** Task Lists (this doc) are a simpler, form-level workflow tool. For enterprise-grade process management with dependencies, due dates, and automated integrations, use **Task Manager** (Chapter 14 — a separate, more powerful tool).

---

## 2. WHAT — Plain English Definition

A Task List is a **hierarchical checklist** of tasks that:
- Can contain **sub-task lists** (nested)
- Each task has a **type** (Form, URL, Business Rule, or Descriptive)
- Users mark tasks as **Complete** as they finish each step
- Administrators can view **completion status** across all users
- Can include **due dates** and **instructions**

```
Task List: "Monthly Budget Entry"
├── 1. Read Budget Instructions (Descriptive)
├── 2. Enter Room Revenue (Form: Room_Revenue_Entry)
├── 3. Enter F&B Revenue (Form: F&B_Revenue_Entry)
├── 4. Enter Operating Expenses (Form: OpEx_Entry)
├── 5. Run P&L Calculation (Rule: Calculate_PnL)
├── 6. Review P&L Dashboard (URL: Dashboard link)
├── 7. Submit Task List (Sub-task list: "Approval Steps")
│   ├── 7a. Review and validate
│   └── 7b. Submit for approval
└── 8. Confirm Submission (Descriptive)
```

## 5. TASK TYPES — COMPLETE REFERENCE

| Type | Icon | Description | What Happens When User Clicks |
|------|------|-------------|-------------------------------|
| **Form** | 📋 | Opens a data entry form | Form opens in the main area; task marked "In Progress" |
| **URL** | 🔗 | Opens a web link | Browser navigates to URL (dashboard, documentation, etc.) |
| **Business Rule** | ⚙ | Launches a business rule | Rule execution dialog opens with runtime prompts |
| **Descriptive** | 📝 | Instructions only — no action | User reads and manually marks complete |
| **Sub-Task List** | 📁 | Nested task list | Expands to show sub-tasks |

---

## 6. TASK STATUS LIFECYCLE

```
☐ Pending → ▶ In Progress → ✅ Complete
                              ↕
                          ↩ Reopen

Status definitions:
  ☐ Pending: User hasn't started this task yet
  ▶ In Progress: User has opened the task (auto-detected for Forms)
  ✅ Complete: User manually marked as complete
  ↩ Reopen: Admin or user can reopen a completed task
```

## 7. ACCESS PERMISSIONS FOR TASK LISTS

| Permission | What User Can Do |

## 9. TASK LISTS vs TASK MANAGER

| Feature | Task Lists | Task Manager |
|---------|-----------|-------------|
| **Complexity** | Simple checklists | Full workflow engine |
| **Dependencies** | No (sequential by order) | Yes (predecessors, successors) |
| **Due dates** | Basic (per task) | Advanced (with schedules, calendars, holidays) |
| **Automation** | Manual completion | Automated task execution |
| **Reporting** | Basic completion status | Dashboards, Gantt charts, reports |
| **User assignment** | By access permission | Per-task assignees, owners, reviewers |
| **Integration** | Forms, rules, URLs | EPM Cloud services, ERP, custom integrations |
| **Best for** | Simple user guidance | Enterprise close/budget process management |

## 10. DO's AND DON'Ts

### ✅ DO
- **DO** use descriptive task names that tell users exactly what to do
- **DO** add instructions to every task — users need context
- **DO** set due dates and alert dates for time-sensitive tasks
- **DO** order tasks logically (data entry → calculation → review → submit)
- **DO** use nested sub-task lists for complex processes

### ❌ DON'T
- **DON'T** create task lists with more than 20 tasks — break into sub-lists
- **DON'T** skip access permissions — users won't see the task list
- **DON'T** use task lists when you need dependency management — use Task Manager
- **DON'T** forget to assign the task list to users after creating it

## 11. INTERVIEW QUESTIONS

### Beginner
**Q: What is the difference between a Task List and Task Manager?**
> **A:** A Task List is a simple guided checklist built into Planning — it has sequential steps that users mark complete. It's good for simple workflows like "enter revenue → run rule → submit." Task Manager is a full-fledged enterprise workflow engine (separate module) with dependencies, due dates, automated execution, Gantt charts, and detailed reporting. Use Task Lists for simple user guidance; use Task Manager for complex close/budget processes with multiple teams and deadlines.

### Intermediate
**Q: A user opens a Task List and sees 8 tasks. They complete tasks 1-5 but then log out. When they log back in, tasks 1-5 are back to "Pending." What went wrong?**
> **A:** The user likely didn't explicitly mark the tasks as "Complete." For Form-type tasks, opening the form changes the status to "In Progress," but it does NOT auto-complete. Users must manually click the checkbox to mark each task as "Complete." The completion status is stored server-side, so it persists across sessions — but only if the user clicked the complete button. Also check: the task list might have been cleared by an admin (Task Lists → Clear Task Lists) or the user might have a different user variable setting that shows a different task list instance.
