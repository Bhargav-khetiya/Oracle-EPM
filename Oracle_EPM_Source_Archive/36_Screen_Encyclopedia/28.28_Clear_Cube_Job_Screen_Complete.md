## 1. WHY — What Problem Does Clear Cube Solve—

**The problem:** During development, testing, or annual rollover, admins need to remove data from Essbase cubes — either all data (full clear) or selective data (filtered clear). Without a structured clear job, admins would have to manually set cells to #MISSING or use complex calc scripts.

**The solution:** Clear Cube creates a **reusable job definition** that clears data from a cube based on member selections. You define which intersections to clear, save the definition, and run it when needed.

## 4. HOW CLEAR CUBE WORKS

### What Gets Cleared

```
Clear Cube sets ALL data at the selected intersections to #MISSING.

Example: Clear_Working_Forecast
  Scenario = Forecast
  Version = Working
  Year = FY2026
  All other dimensions = All members

Result: EVERY cell at Forecast/Working/FY2026 becomes #MISSING
        Other scenarios (Budget, Actual) are NOT affected
        Other versions (Final) are NOT affected
        Other years (FY2025, FY2027) are NOT affected
```

### Clear Options

| Option | Description |
|--------|-------------|
| **Selective Clear** | Choose specific members per dimension → only those intersections cleared |
| **Full Cube Clear** | Select "All" for every dimension → entire cube emptied |
| **Clear #MISSING Blocks** | Physically removes empty blocks from Essbase → reduces database size |

> ⚠️ **CRITICAL: Clear Cube is DESTRUCTIVE and IRREVERSIBLE.** Always create a snapshot before running a clear cube job. There is NO undo.

| Use Case | What to Clear | When |
|----------|--------------|------|
| **New Budget Cycle** | Scenario=Budget, Version=Working, Year=FY2028 | Start of new budget year — remove prior cycle's working data |
| **Reset Forecast** | Scenario=Forecast, Version=Working | Monthly — clear old forecast before new one |
| **Development Cleanup** | All data in test cube | After testing — clean up test data |
| **Post-Migration** | Scenario=Actual, incorrect periods | After fixing a bad data load |
| **Storage Optimization** | Clear #MISSING blocks only | Monthly — reduce cube bloat |

## 6. HOTEL PVT LTD EXAMPLE

### Monthly Forecast Reset

```
Scenario: Each month, Hotel Pvt Ltd clears the working forecast
          and re-enters based on latest actuals.

Clear Cube Job: "Clear_Working_Forecast"
  Cube: OEP_FS (FinPlan)
  Scenario: Forecast
  Version: Working
  Year: FY2026
  Period: Sep, Oct, Nov, Dec (future months only)
  Entity: All Hotels
  Account: All Accounts

Steps:
  1. Admin creates snapshot: "Pre_Clear_Aug_FC"
  2. Admin runs Clear Cube job
  3. 4 months of forecast data → #MISSING
  4. Planners re-enter forecast for Sep-Dec
  5. If something goes wrong → restore snapshot
```

## 7. DO's AND DON'Ts

### ✅ DO
- **DO** always create a snapshot before running Clear Cube
- **DO** be specific with dimension selections — don't clear more than needed
- **DO** verify selections twice before clicking "Run"
- **DO** use "Clear #MISSING Blocks" periodically to optimize cube size
- **DO** schedule Clear Cube jobs for off-hours (to avoid impacting users)

### ❌ DON'T
- **DON'T** run a full cube clear on production without a backup
- **DON'T** clear Actual data unless you're fixing a load error (and have backup)
- **DON'T** forget to re-aggregate after clearing data — parent values may be stale
- **DON'T** give Clear Cube access to non-admin users

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: What is the difference between "Clear Cube" and deleting data in a form—**
> **A:** Deleting data in a form (pressing Delete key) sets individual cells to #MISSING one at a time. Clear Cube is a **bulk operation** that clears thousands or millions of cells at once based on dimension selections. Clear Cube also has the option to physically remove empty blocks from Essbase (reducing database size), which deleting in forms does not do. Clear Cube is an admin-only operation; deleting in forms is a planner action.

### Intermediate
**Q: After running Clear Cube, parent member values still show old aggregated data. Why, and how do you fix it—**
> **A:** If parent members are "Dynamic Calc" (which they should be in Hybrid Mode), they should automatically recalculate and show #MISSING or updated totals. However, if parents are "Store" type, they retain their old aggregated values because Clear Cube only clears the specific intersections selected — if the parent member wasn't in the member selection, its stored value persists. Fix: (1) Run an aggregation rule to recalculate parents from children. (2) Better long-term: change parent members to Dynamic Calc so they always reflect current child data.
