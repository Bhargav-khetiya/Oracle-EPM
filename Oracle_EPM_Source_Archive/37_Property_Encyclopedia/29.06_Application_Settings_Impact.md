# Application Settings Impact

Application settings in Oracle EPM govern the global behavior of the cube. Changing these settings can have massive implications on performance, usability, and data integrity.

## 1. Multiple Alias Tables

By default, an application comes with a "Default" alias table. 

### Why Enable Multiple Alias Tables—
*   **Localization:** If you have global users, you can create alias tables for "French", "Spanish", "Japanese", etc. Users can select their preferred alias table in Smart View, and the member names will translate automatically.
*   **Reporting vs. Input:** Sometimes planners need descriptive names ("10100 - Base Salary Input"), while board reporting requires cleaner names ("Salaries"). Different alias tables solve this.
*   **Impact:** Enabling multiple alias tables increases the memory footprint of the outline. Ensure you only create tables you actually use.

## 2. Smart View Formatting Settings

Application settings control how formatting flows from the web to Smart View.

*   **Use Cell Styles:** If enabled, the application forces specific background colors onto Smart View based on cell status (e.g., Read-only = Grey, Dirty = Yellow, Calculated = Green). 
*   **Impact:** If a user complains that their custom Excel formatting keeps getting overwritten every time they click "Refresh", it is because this application-level or form-level setting is overriding their Excel styles.

## 3. Dynamic Time Series (DTS)

DTS is a global application setting that must be explicitly enabled for the Time dimension. 

### Deep Dive: How DTS Works
Instead of creating static members like "Q1_YTD", DTS allows the system to calculate Year-To-Date (YTD), Quarter-To-Date (QTD), or Month-To-Date (MTD) dynamically based on the current period selection.

*   **Setup:** You enable the DTS member (e.g., H-T-D for Half-to-Date, Y-T-D for Year-to-Date) and associate it with a generation in the Time hierarchy.
*   **Usage:** In Smart View or a form, a user selects `Y-T-D(Mar)`. Essbase dynamically sums Jan + Feb + Mar.
*   **Performance Impact:** DTS is heavily optimized in the Essbase engine and is vastly superior to writing custom formulas or `SUMRANGE` functions to calculate YTD balances.

## 4. Evaluation Order (Solve Order)

We covered Solve Order in the Planning Formulas guide, but there is a global Application Evaluation Order that dictates the absolute precedence when multiple dimensions have conflicting solve orders.

*   **The Default Order:** Typically, Account is evaluated first, then Time, then custom sparse dimensions. 
*   **The Impact of Changing It:** If you change the global evaluation order so that Time evaluates *before* Account, every single ratio and percentage calculation in your application will break (they will sum the percentages instead of recalculating them at the parent level). **Do not change global evaluation order unless absolutely necessary.** Use member-level solve order instead.
