# Standard vs. Attribute Dimensions Deep Dive

Based on Oracle Essbase (21c) and EPM Cloud (Planning/FreeForm) documentation, understanding the distinction between standard and attribute dimensions is critical for optimal cube design.

## 1. Standard Dimensions

Standard dimensions represent the core components of a business plan and define the structural hierarchy of the database. 

### Characteristics
*   **Hierarchical Structure:** They define consolidation (rollups) using tree structures (e.g., Qtr1 -> Jan, Feb, Mar).
*   **Data Storage:** Data is stored directly at the intersections of standard dimensions.
*   **Typical Dimensions:** Time, Accounts, Scenario, Version, Entity, Product.
*   **Volatility:** They generally change less frequently than members within them, though modern EPM apps support dynamic metadata updates.
*   **Types:** Standard dimensions can be categorized further (e.g., Dense vs. Sparse). The Time and Account dimensions are typically Dense, while Entity and Product are typically Sparse.

### 1.1 The "Required" Standard Dimensions (PeopleSoft/Planning Context)
In most Planning/FreeForm applications, the system requires a baseline set of standard dimensions:
*   **Account:** Measures what is being tracked (Revenue, Expense, Headcount). It dictates the calculation logic (Time Balance, Two-Pass).
*   **Period (Time):** Defines the time interval (Jan, Feb, Q1, YearTotal).
*   **Scenario:** Represents different data sets (Actual, Budget, Forecast).
*   **Version:** Allows for what-if modeling within a Scenario (Working, Final, Draft 1).
*   **Entity:** Defines the organizational structure (Cost Centers, Departments, Regions).

## 2. Attribute Dimensions

Attribute dimensions are associated with standard sparse dimensions. They group and analyze members of standard dimensions based on characteristics (attributes) without increasing the database sparsity or block count.

### Characteristics
*   **Association:** An attribute dimension must be tied to a standard sparse "Base" dimension. 
*   **Data Storage:** Data is **not** stored against an attribute dimension. It is calculated dynamically based on the base dimension's data. 
*   **Use Case:** Profitability analysis. For example, if "Product" is the base dimension, "Packaging_Type" (Glass, Can, Plastic) can be an attribute dimension. You can query Profitability by "Glass" without creating a massive sparse matrix.

### Deep Dive: Attributes vs. UDAs (User Defined Attributes)

| Feature | Attribute Dimension | UDA (User Defined Attribute) |
| :--- | :--- | :--- |
| **Type** | Actual dimension in the outline | Text tag applied to a member |
| **Reporting** | Can be pivoted on rows/columns in Smart View | Cannot be pivoted; only used as a filter or in calc scripts (`@ISUDA`) |
| **Data Types** | Text, Numeric, Boolean, Date | Text only |
| **Calculation** | Supports dynamic rollups (e.g., Sum of all "Glass" products) | Requires explicit calc script logic |
| **Performance** | Slower retrieval (dynamic aggregation) but saves block space | Very fast, no aggregation overhead |

### 2.1 Implementing Attribute Dimensions
1.  **Base Dimension Requirement:** Only Sparse dimensions can have attributes (e.g., Entity, Product).
2.  **One-to-One Rule:** A base member can only be assigned *one* attribute from a specific attribute dimension. For example, Product A can only have one "Packaging_Type". It cannot be both "Glass" and "Can". If it is, you must split the base member or use alternate hierarchies instead of attributes.

## 3. Cubes and Dimensionality (AAI & EPM Context)
A "Cube" (or Database in Essbase terminology) is the multidimensional engine where these dimensions intersect. 
*   **BSO (Block Storage Option):** Optimized for complex allocations and calculations. Dense/Sparse configuration is paramount.
*   **ASO (Aggregate Storage Option):** Optimized for massive reporting and read-heavy operations. There is no Dense/Sparse concept; all dimensions are essentially sparse, and data is aggregated on the fly using hierarchies. 

*Sources: Oracle Essbase 21c Database Administrator's Guide, Oracle Enterprise Performance Management Workspace User's Guide.*
