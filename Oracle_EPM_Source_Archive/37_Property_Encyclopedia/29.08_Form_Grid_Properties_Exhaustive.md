# 📐 29.08 — Form Grid Properties: Exhaustive Reference

> **Source:** Oracle® Fusion Cloud EPM Administering Planning (Aug 2026), Chapter 25, Tables 25-14 through 25-18
> **Navigation:** Form Designer → Layout tab → Grid Properties / Segment Properties / Display Properties
> **Audience:** Service Administrator / Power User

---

## 1. WHY — Why Do Form Properties Matter—

Form properties control **everything** about how a form looks, behaves, and performs. The difference between a fast, clean form and a slow, confusing one is entirely in the properties. Knowing every property is essential for techno-functional consultants.

---

## 2. PROPERTY CATEGORIES

Forms have **five** categories of properties, each on the Layout tab:

```
Form Designer → Layout tab
├── Grid Properties          → Global form behavior
├── Segment Properties       → Per-row/per-column settings
├── Dimension Properties     → Per-dimension settings on each axis
├── Display Properties       → Visual and functional display options
├── Smart View Options       → Settings for Smart View rendering
└── Prediction Options       → Predictive Planning settings
```

## 3. GRID PROPERTIES — EVERY OPTION

| Property | Options | Default | What It Does | Performance Impact |
|----------|---------|---------|-------------|-------------------|
| **Suppress Missing Data** | ☑/☐ | ☐ | Hides rows/columns with all #MISSING values | ✅ Improves (less data rendered) |
| **Suppress Missing Blocks** | ☑/☐ | ☐ | Suppresses at Essbase block level — more aggressive | ✅ Major improvement for sparse grids |
| **Suppress Invalid Data** | ☑/☐ | ☐ | Hides rows/columns with invalid intersection data | ✅ Cleaner forms with Valid Intersections |
| **Use Database Suppression** | ☑/☐ | ☐ | Applies suppression at Essbase level (not app level) | ✅ Major improvement; ⚠️ formula columns may disappear |
| **Suppress Invalid Scenario/Time Periods** | ☑/☐ | ☐ | Hides periods outside scenario's start/end period range | Neutral |
| **Suppress Missing Also Suppresses Zero** | ☑/☐ | ☐ | When suppress missing is on, also hide zero-value rows | ✅ Cleaner form |
| **Default Row Height** | Medium, Size-to-Fit, Custom | Medium | Row height in pixels | Neutral |
| **Default Column Width** | Small(50px), Medium(100px), Large(300px), Size-to-Fit, Custom | Medium | Column width in pixels | Neutral |
| **Global Assumptions Form** | ☑/☐ | ☐ | Marks form as storing global assumptions (transferable) | Neutral |
| **Enable Autosave** | ☑/☐ | ☐ | Auto-saves when navigating between cells; enables Ctrl+Z | ⚠️ Can impact performance for large forms |
| **Run Form Calc on Autosave** | ☑/☐ | ☐ | Recalculates dynamic calc cells after each auto-save | ⚠️ Significant impact — use only with dense dims on rows/cols |
| **Enable Calc On the Fly** | ☑/☐ | ☐ | Shows member formula and calculates without saving | ⚠️ Performance impact |
| **Remove Form Suppressions in Ad Hoc** | ☑/☐ | ☐ | Lets Smart View users do ad hoc on suppressed forms | Neutral |
| **Pivot Rows and Columns after Load** | ☑/☐ | ☐ | Transposes grid after data loads | Neutral |

### Suppression Decision Matrix

| Scenario | Use This Setting |
|----------|-----------------|
| Large form with many empty rows | ☑ Suppress Missing Data |
| Very large form with 1000+ rows | ☑ Suppress Missing Blocks + Use Database Suppression |
| Form with Valid Intersections | ☑ Suppress Invalid Data |
| Budget form (Scenario=Budget, periods Jan-Dec) | ☑ Suppress Invalid Scenario/Time |
| Form has formula columns that depend on missing data | ☐ Do NOT use Database Suppression |

## 4. SEGMENT PROPERTIES — PER-ROW / PER-COLUMN

Access: Click the row number (1, 2, 3...) or column letter (A, B, C...) in the Layout tab.

| Property | Options | Default | What It Does |
|----------|---------|---------|-------------|
| **Apply to All Rows/Columns** | ☑/☐ | ☑ | Apply same properties to all rows or columns |
| **Hide** | ☑/☐ | ☐ | Hides the row/column entirely (still exists, just invisible) |
| **Read-Only** | ☑/☐ | ☐ | Makes the row/column non-editable |
| **Show Separator** | ☑/☐ | ☐ | Adds a bold border before this segment (visual grouping) |
| **Suppress Hierarchy** | ☑/☐ | ☐ | Removes indentation for hierarchical members |
| **Suppress Missing Data** | ☑/☐ | ☐ | Row/column-level missing data suppression (overrides grid) |
| **Suppress Invalid Scenario/Time** | ☑/☐ | ☐ | Row/column-level scenario period suppression |
| **Column Width** | Default, Small, Medium, Large, Size-to-Fit, Custom | Default | Override grid-level width for this column |
| **Row Height** | Default, Medium, Size-to-Fit, Custom | Default | Override grid-level height for this row |
| **Enable Dropdown for Dimensions** | ☑/☐ | ☐ | Shows dropdown member selector on row dimensions |

### Segment Design Patterns

```
Pattern: Revenue vs Expense with visual separation
  Row 1 (Segment): Revenue members → no separator
  Row 2 (Segment): Expense members → Show Separator = ☑ (bold line)
  Row 3 (Segment): P&L total → Read-Only = ☑ (calculated)

Pattern: Actual vs Budget comparison
  Column A (Segment): Actual data → Read-Only = ☑
  Column B (Segment): Budget data → editable
  Column C (Segment): Variance → Read-Only = ☑, formula column
```

## 9. COMMON MISTAKES AND FIXES

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Suppress Missing Blocks + formula columns | Formula column rows disappear | Disable Use Database Suppression; use regular Suppress Missing |
| Autosave on form with sparse dims on rows | Extremely slow — saves on every cell move | Disable Autosave; or move sparse dims to Page/POV |
| All rows collapse (nothing visible) | Suppress Missing too aggressive | Check if data exists; disable suppression temporarily to see all rows |
| Smart View shows different layout | Flex form or formatting options inconsistent | Check Smart View Options on form definition |
| Users can edit read-only form | Read-only set at segment level but not for all segments | Set "Make Form Read-Only" at Display Properties level |

## 10. INTERVIEW QUESTIONS

### Beginner
**Q: What does "Suppress Missing Data" do, and when should you use it—**
> **A:** It hides entire rows or columns where ALL cells contain #MISSING (no data). Use it when forms have many members that might not have data for every intersection — it prevents users from seeing hundreds of empty rows. Without it, users would see "#MISSING" in every cell of empty rows, making the form unusable.

### Intermediate
**Q: A form has 2000 rows with a formula column. The form takes 45 seconds to load. What property changes would improve performance—**
> **A:** (1) Enable "Suppress Missing Data" — hide empty rows. (2) Enable "Suppress Missing Blocks" — more aggressive server-side suppression. (3) Do NOT enable "Use Database Suppression" because the form has a formula column (formula column results may be suppressed before evaluation). (4) Consider reducing the member selection — do users really need 2000 rows— (5) If the formula column is simple, consider replacing it with a Dynamic Calc member formula in Essbase (server-side calculation). (6) Move sparse dimensions from rows to Page axis to reduce the cross-join.

### Architect
**Q: Design a form for 500 room-level revenue entries (500 rooms × 12 months). How would you structure the form properties for optimal performance—**
> **A:** 500 × 12 = 6,000 cells — large but manageable. Structure:
> (1) **Layout:** Rooms on rows (sparse), Months on columns (dense = Period). This aligns with Essbase block structure.
> (2) **Grid Properties:** Suppress Missing Data ☑, Suppress Missing Blocks ☑, Use Database Suppression ☑ (no formula columns). Enable Autosave ☐ (sparse on rows = bad for autosave).
> (3) **Segment Properties:** Enable Dropdown for Dimensions ☑ on the Room dimension (so users can filter to their floor/wing).
> (4) **Display Properties:** Display Missing as Blank ☑. Enable Grid Spread ☑ (for quick data entry by filling months).
> (5) **Alternative:** If 6,000 cells is too slow, split into multiple forms by hotel floor (50 rooms each) and use a Page dropdown for floor selection.
