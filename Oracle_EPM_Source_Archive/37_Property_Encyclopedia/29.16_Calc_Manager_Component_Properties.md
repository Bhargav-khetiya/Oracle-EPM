# 🧩 29.16 — Calc Manager Component Properties: Complete Reference

> **Source:** Oracle® Fusion Cloud EPM Designing with Calculation Manager (Aug 2026), Chapters 5-9

> **Audience:** Service Administrator / Rule Developers

## 1. WHY — Why Know Component Properties—

Calculation Manager uses a **component-based architecture** — rules are built from reusable building blocks (components). Each component type has specific properties that control its behavior. Mastering these properties is essential for building efficient, maintainable business rules.

---

## 2. COMPONENT TYPES — COMPLETE LIST

| Component | Icon | Purpose | Script Equivalent |
|-----------|------|---------|-------------------|
| **Formula** | fx | Write calculation formulas | Direct member formulas |
| **Script** | {} | Write free-form calc scripts | FIX...ENDFIX, IF...ENDIF blocks |
| **Condition** | ◇ | IF/THEN/ELSE branching | IF...ELSEIF...ELSE...ENDIF |
| **Member Block** | □ | FIX statement (member selection) | FIX(members)...ENDFIX |
| **Member Range** | ↔ | Loop through members | @LOOPRANGE / FIX on range |
| **Fixed Loop** | ⟳ | Loop N times | For i = 1 to N |
| **Metadata Loop** | ⟳M | Loop through dimension members | @LOOPRANGE on dim members |
| **DTP Assignment** | ← | Set design-time prompt values | Variable assignment |
| **System Template** | 📋 | Pre-built Oracle templates | Clear, Copy, Aggregate, etc. |
| **Custom Template** | 📋c | User-created reusable templates | Parameterized calc snippets |

## 6. MEMBER BLOCK COMPONENT — PROPERTIES

| Property | Description |
|----------|-------------|
| **Dimensions** | Which dimensions to FIX on |
| **Members** | Specific members per dimension |
| **Children Components** | Sub-components that execute inside the FIX |

Generates: `FIX(member1, member2, ...) ... ENDFIX`

### Member Block = FIX Statement

```
Member Block: "Fix on Budget Entities"
  Scenario: Budget
  Entity: @CHILDREN("All_Hotels")
  Version: Working
  
Generates:
  FIX("Budget", @CHILDREN("All_Hotels"), "Working")
    [child components execute here]
  ENDFIX
```

## 9. DEPLOYMENT AND VALIDATION

### Validation
```
Before deployment, Calculation Manager checks:
  ✅ Syntax: All calc script syntax is valid
  ✅ Members: All referenced members exist in the cube
  ✅ Functions: All @functions are valid for BSO/ASO
  ✅ Variables: All runtime prompts have valid definitions
  ❌ Logic: Does NOT validate business logic (wrong results are possible)
```

### Deployment Status

| Status | Meaning |
|--------|---------|
| **Not Deployable** | Rule cannot be deployed (default for new rules) |
| **Deployable** | Rule is ready to deploy but not yet deployed |
| **Deployed** | Rule is active — visible in Planning |
| **Modified** | Rule was changed after deployment — needs re-deploy |

```
Deployment Flow:
  1. Create rule → Status: Not Deployable
  2. Validate → Fix errors
  3. Mark as Deployable → Status: Deployable
  4. Deploy → Status: Deployed (visible in Planning)
  5. Edit rule → Status: Modified (old version still active)
  6. Re-deploy → Status: Deployed (new version active)
```

## 10. HOTEL PVT LTD EXAMPLE

### Complete Rule: Hotel P&L Calculation

```
Rule: "Hotel_FinPlan_Rollup"
Cube: OEP_FS

Components (Flow):
  ├── Member Block: FIX on Budget/Working/FY2026
  │   ├── Member Block: FIX on @CHILDREN(All_Hotels)
  │   │   ├── Formula: Total_Revenue = Room_Rev + F&B_Rev + Spa_Rev
  │   │   ├── Formula: Total_Expenses = Labor + Maint + Utilities
  │   │   ├── Formula: Net_Income = Total_Revenue - Total_Expenses
  │   │   └── Condition: IF Total_Revenue > 0
  │   │       ├── THEN: Profit_Margin = Net_Income / Total_Revenue * 100
  │   │       └── ELSE: Profit_Margin = 0
  │   └── Aggregation Template: Aggregate Entity dimension
  └── END

Runtime Prompts:
  Scenario: [Member selector] → Default: Budget
  Version: [Member selector] → Default: Working
  Year: [Member selector] → Default: FY2026

Generated Script:
  FIX({RTP_Scenario}, {RTP_Version}, {RTP_Year})
    FIX(@CHILDREN("All_Hotels"))
      "Total_Revenue" = "Room_Revenue" + "F&B_Revenue" + "Spa_Revenue";
      "Total_Expenses" = "Labor_Expense" + "Maintenance" + "Utilities";
      "Net_Income" = "Total_Revenue" - "Total_Expenses";
      IF("Total_Revenue" > 0)
        "Profit_Margin" = "Net_Income" / "Total_Revenue" * 100;
      ELSE
        "Profit_Margin" = 0;
      ENDIF
    ENDFIX
    AGG("Entity");
  ENDFIX
```

## 11. INTERVIEW QUESTIONS

### Beginner
**Q: What is the difference between a Formula Component and a Script Component—**
> **A:** A **Formula Component** is a visual, guided interface for building single calculation formulas — you pick members from dropdowns and build the formula step by step. A **Script Component** is a free-text editor where you write raw Essbase calc script code directly. The Formula Component is easier for simple calculations; the Script Component provides full flexibility for complex logic. In practice, experienced consultants often prefer Script Components because they're faster to write and offer full control.

### Intermediate
**Q: A rule has 5 Formula Components in sequence. After deployment, only the first 3 execute and the last 2 seem ignored. What could be wrong—**
> **A:** Several possibilities: (1) The last 2 Formula Components might be inside a Condition Component whose condition is FALSE — so they never execute. (2) The Member Block (FIX statement) wrapping the components might not include the members that the last 2 formulas target. (3) The last 2 components might be "disabled" — right-click and check if "Disable" is checked. (4) There might be an error in component 4 that causes the rule to stop (though normally Essbase continues past errors). Check the execution log for error messages.
