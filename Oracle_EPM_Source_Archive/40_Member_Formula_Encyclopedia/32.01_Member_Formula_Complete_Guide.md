# 31.01 Member Formula Complete Guide

> **Module:** 31_Member_Formula_Encyclopedia  
> **Topic:** 01 — Everything About Member Formulas  
> **Target Audience:** Developer / Architect  

---

## Introduction

A **Member Formula** is a calculation expression attached directly to a member in the dimension outline (metadata). Unlike Business Rules (which run on-demand), member formulas are intrinsic to the member — they execute automatically during aggregation (`CALC DIM`, `AGG`), or calculate in real-time if the member is tagged as `Dynamic Calc`.

This guide covers **everything**: what they are, where to write them, when they fire, every syntax rule, every option, every edge case.

---

# SECTION 1: FUNDAMENTALS

---

## 1.1 What Is a Member Formula?

A member formula is an Essbase calculation expression that is stored as part of the member's metadata in the dimension outline.

**Example:** The member `Gross_Margin_Pct` in the Account dimension has this formula:
```essbase
IF("Revenue" <> 0 AND "Revenue" <> #Missing)
    "Gross_Margin_Pct" = ("Revenue" - "COGS") / "Revenue" * 100;
ELSE
    "Gross_Margin_Pct" = #Missing;
ENDIF;
```

Every time a user queries `Gross_Margin_Pct`, this formula fires (if Dynamic Calc) or was pre-calculated during the last aggregation (if Stored).

---

## 1.2 Member Formula vs Business Rule Formula

| Feature | Member Formula | Business Rule Formula |
|---------|---------------|----------------------|
| **Where Defined** | Dimension Editor → Member → Formula field | Calc Manager → Business Rule/Script |
| **When Executes** | During `CALC DIM`, `AGG`, or real-time (Dynamic Calc) | On-demand (user clicks Run, or form Save triggers it) |
| **Scope** | Applies to that ONE member across ALL intersections | Can target any intersection via FIX statements |
| **Maintenance** | Embedded in metadata — requires outline refresh | Separate artifact — can be versioned/updated independently |
| **FIX Statement** | ❌ Cannot use FIX inside a member formula | ✅ Full FIX support |
| **Runtime Prompts** | ❌ Not available | ✅ Full RTP support |
| **Cross-Dim (`->`)** | ✅ Supported (but performance-critical) | ✅ Supported |
| **IF/ELSE** | ✅ Supported | ✅ Supported |
| **Performance** | Runs EVERY time the member is queried (if Dynamic Calc) | Runs only when explicitly triggered |

**Rule of Thumb:** Use member formulas for **inherent mathematical relationships** (e.g., Margin % = Margin / Revenue). Use business rules for **batch processes** (e.g., Copy Actuals to Budget, Run Allocation).

---

## 1.3 Where to Write a Member Formula

### Path in Oracle EPM Cloud:
```
Navigator → Dimensions → [Select Dimension] → [Select Member] → 
  Member Properties → Formula
```

### In the Dimension Editor:
1. Navigate to the dimension (e.g., Account)
2. Find or search for the member (e.g., `Gross_Margin_Pct`)
3. Click the member to open its properties
4. Scroll to the **Formula** field
5. Type or paste the formula
6. Click **Save**
7. **Refresh the database** (the formula is stored in the outline and requires a refresh to take effect)

### Formula Field Properties:

| Property | Description |
|----------|-------------|
| **Formula** | Free-text field for the Essbase formula expression |
| **Validate** | Button to check syntax before saving |
| **Formula Length Limit** | ~64KB per member formula (rarely a constraint) |

---

## 1.4 When Do Member Formulas Execute?

| Trigger | Behavior | Example |
|---------|----------|---------|
| `CALC DIM("Account")` | Executes ALL member formulas on the Account dimension, plus aggregation | After loading data, run CALC DIM to calculate derived accounts |
| `AGG("Account")` | Does NOT execute member formulas — only aggregates | Use when accounts have no formulas |
| `Dynamic Calc` member queried | Formula executes in real-time in RAM when a user opens a form or report | User opens a form showing Margin % — formula fires immediately |
| `CALC ALL` | Executes ALL member formulas on ALL dimensions | ❌ Never use in Planning |
| Manual `"MemberName";` in calc script | Triggers only that member's formula | `"Gross_Margin_Pct";` in a business rule |

### Execution Order Within a Dimension:
Essbase processes member formulas in **outline order** (top to bottom in the dimension hierarchy). If `Net_Income` depends on `Tax`, and `Tax` is below `Net_Income` in the outline, `Net_Income` will calculate FIRST with the OLD Tax value.

**Fix:** Reorder members in the outline so dependencies are resolved top-down, OR use **Two-Pass** tagging on the dependent member.

# SECTION 2: SYNTAX RULES

---

## 2.1 Basic Syntax

```essbase
/* Every formula must end with a semicolon */
"Gross_Margin" = "Revenue" - "COGS";
```

### Rules:
1. **Semicolons are mandatory** at the end of every statement
2. **Member names must be in double quotes** if they contain spaces or special characters
3. **The formula's "self" member** is the member the formula is attached to. You can reference it by name or omit it:
   ```essbase
   /* Both are identical: */
   "Margin_Pct" = "Margin" / "Revenue" * 100;
   /* OR just: */
   "Margin" / "Revenue" * 100;
   ```
4. **Multi-line formulas** are supported — use semicolons to separate statements
5. **Comments** use `/* */` syntax

---

## 2.2 IF / ELSEIF / ELSE / ENDIF

```essbase
IF(condition)
    expression1;
ELSEIF(condition2)
    expression2;
ELSE
    expression3;
ENDIF;
```

### Critical Syntax Rule: ENDIF Must End with Semicolon in Member Formulas
```essbase
/* CORRECT in member formula */
IF("Revenue" > 0)
    "Margin_Pct" = "Margin" / "Revenue" * 100;
ELSE
    "Margin_Pct" = #Missing;
ENDIF;  /* ← Semicolon after ENDIF */

/* NOTE: In calc scripts, ENDIF does NOT need a semicolon */
/* In member formulas, ENDIF DOES need a semicolon */
```

---

## 2.3 Cross-Dimensional References (`->`)

```essbase
/* Pull value from a different dimension intersection */
"Variance" = "Revenue" - "Revenue" -> "Budget";

/* Chain multiple cross-dim references */
"Prior_Year_Budget_Rev" = "Revenue" -> "Budget" -> "FY23";
```

### Performance Impact:
| # of `->` in formula | Impact on Dynamic Calc retrieval |
|----------------------|----------------------------------|
| 0 | ⚡ Fastest — value computed within the block |
| 1 | ⚠️ +1 block lookup per cell |
| 2 | ⚠️⚠️ +2 block lookups per cell |
| 3+ | ❌ Noticeably slow — form load times degrade |

**Best Practice:** Limit cross-dim references in Dynamic Calc member formulas to 2 or fewer. If you need 3+, consider storing the value via a business rule instead.

---

## 2.4 @Functions in Member Formulas

All `@` functions available in calc scripts are also available in member formulas. The most commonly used:

### Hierarchy Functions:
```essbase
/* Sum of all children */
@SUM("Product", @CHILDREN("All_Products"));

/* Parent value reference */
@PARENTVAL("Entity", "Revenue");
```

### Boolean Functions:
```essbase
IF(@ISMBR("Jan"))
    "Opening_Balance" = "Prior_Year_Ending";
ELSE
    "Opening_Balance" = @PRIOR("Closing_Balance", 1);
ENDIF;
```

### Time Functions:
```essbase
/* Prior period */
"Growth_Rate" = ("Revenue" - @PRIOR("Revenue", 1)) / @PRIOR("Revenue", 1) * 100;

/* Year-to-Date */
"YTD_Revenue" = @TODATE("Period", "YearTotal", "Revenue");
```

# SECTION 3: SOLVE ORDER

---

## 3.1 What is Solve Order?

Solve Order is a numeric property (0–127) assigned to a member that determines the **priority of formula evaluation** when two or more Dynamic Calc members' formulas conflict at the same intersection.

### The Problem:
Imagine a form with `Margin %` on the rows (Dynamic Calc with formula) and `Q1` on the columns (also Dynamic Calc, sums Jan+Feb+Mar). When the user queries the intersection `(Margin %, Q1)`:
- Should Essbase calculate Q1 first (sum the months), then apply the Margin % formula?
- OR should Essbase calculate Margin % for each month first, then sum them to Q1?

These give **different answers**. Summing percentages is mathematically wrong.

### The Solution: Solve Order

| Solve Order | Calculates... | Rule |
|------------|---------------|------|
| **Lower number** | **First** | Simple aggregations (sums) should have LOW solve order |
| **Higher number** | **Last** (wins) | Ratios and percentages should have HIGH solve order |

### Example:
| Member | Solve Order | Formula |
|--------|-------------|---------|
| Q1 (Period parent) | 0 (default) | Sum of Jan+Feb+Mar |
| Margin % (Account) | 50 | Revenue - COGS / Revenue |

**Result:** Essbase first sums Q1 Revenue and Q1 COGS, THEN applies the Margin % formula to the Q1 totals. This is mathematically correct.

### Setting Solve Order:
```
Dimension Editor → [Member] → Properties → Solve Order → Enter number (0-127)
```

### Best Practice Guidelines:
| Member Type | Recommended Solve Order |
|------------|------------------------|
| Standard aggregation (sums) | 0 (default) |
| Custom aggregation (weighted avg) | 10–20 |
| Variance calculations ($ and %) | 30–40 |
| Ratios and percentages | 50–60 |
| KPIs and derived metrics | 70–80 |
| Exception handling formulas | 90+ |

# SECTION 4: TWO-PASS CALCULATION

---

## 4.1 What is Two-Pass?

Two-Pass is a member property that forces Essbase to recalculate the member a **second time** after the initial aggregation pass is complete.

### The Problem:
`Margin %` is calculated as `Margin / Revenue * 100`. During a `CALC DIM("Account")`:
1. Essbase processes the outline top-to-bottom
2. It calculates `Margin %` for each entity using the entity's local Revenue
3. Then it aggregates entities up: `Total_Company_Margin%` = sum of all entity margin percentages
4. **This is wrong** — you cannot sum percentages

### The Solution: Tag `Margin %` as Two-Pass
1. **Pass 1:** Essbase calculates everything normally (sums Margin and Revenue up the Entity hierarchy)
2. **Pass 2:** Essbase goes back and recalculates `Margin %` using the newly aggregated `Total_Company_Revenue`

### Setting Two-Pass:
```
Dimension Editor → [Member] → Properties → Two-Pass Calculation → ☑ Enable
```

### Critical Requirement:
Two-Pass **only works** on members tagged as **Dynamic Calc**. If the member is `Store`, the Two-Pass flag is silently ignored during `CALC DIM`.

### When to Use Two-Pass:
| Scenario | Use Two-Pass? |
|----------|---------------|
| Percentages (Margin %, Growth %) | ✅ Yes |
| Ratios (Revenue per Employee) | ✅ Yes |
| Weighted averages (Avg Price) | ✅ Yes |
| Simple sums | ❌ No |
| Balance sheet accounts | ❌ No |

# SECTION 5: DATA STORAGE INTERACTION

---

## 5.1 How Data Storage Affects Member Formulas

| Data Storage | Formula Behavior |
|-------------|-----------------|
| **Store** | Formula executes during `CALC DIM` / `AGG`. Result is saved to disk. Fast retrieval. |
| **Dynamic Calc** | Formula executes in real-time when queried. Never saved to disk. May be slow for complex formulas. |
| **Dynamic Calc & Store** | First query: calculates and saves. Subsequent queries: reads from disk. Must clear to recalculate. |
| **Shared** | No formula allowed (inherits from original member). |
| **Label Only** | No formula allowed (holds no data). |
| **Never Share** | Formula executes normally, but Implied Sharing is disabled. |

### Decision Matrix: Store vs Dynamic Calc for Members with Formulas

| Factor | Use Store | Use Dynamic Calc |
|--------|----------|-----------------|
| Formula is simple (A + B) | Either | ✅ Preferred |
| Formula has 3+ cross-dim refs | ✅ Preferred (pre-calculate) | ⚠️ Slow retrieval |
| Data changes frequently | ⚠️ Needs recalc after every change | ✅ Always current |
| Queried very frequently | ✅ Instant retrieval | ⚠️ Calculates every query |
| Disk space is a concern | ⚠️ Uses disk | ✅ No disk usage |
| Aggregation required above | ✅ Can aggregate normally | ✅ Aggregates dynamically |

# SECTION 6: COMMON FORMULA PATTERNS

---

## Pattern 1: Safe Division (The Universal Pattern)
```essbase
IF("Revenue" <> 0 AND "Revenue" <> #Missing)
    ("Revenue" - "COGS") / "Revenue" * 100;
ELSE
    #Missing;
ENDIF;
```

## Pattern 2: Variance $ (Favorable = Positive)
```essbase
IF(@ISACCTYPE("Expense"))
    "Budget" - "Actual";  /* Under-budget is favorable */
ELSE
    "Actual" - "Budget";  /* Over-revenue is favorable */
ENDIF;
```

## Pattern 3: Variance %
```essbase
IF("Budget" <> 0 AND "Budget" <> #Missing)
    IF(@ISACCTYPE("Expense"))
        ("Budget" - "Actual") / @ABS("Budget") * 100;
    ELSE
        ("Actual" - "Budget") / @ABS("Budget") * 100;
    ENDIF;
ELSE
    #Missing;
ENDIF;
```

## Pattern 4: Year-over-Year Growth
```essbase
IF("Revenue" -> @PRIOR("Year", 1) <> 0 AND "Revenue" -> @PRIOR("Year", 1) <> #Missing)
    ("Revenue" - "Revenue" -> @PRIOR("Year", 1)) / @ABS("Revenue" -> @PRIOR("Year", 1)) * 100;
ELSE
    #Missing;
ENDIF;
```

## Pattern 5: Cumulative YTD (Running Total)
```essbase
IF(@ISMBR("Jan"))
    "Revenue";
ELSE
    @PRIOR("YTD_Revenue", 1) + "Revenue";
ENDIF;
```

## Pattern 6: Balance Sheet Carryforward
```essbase
IF(@ISMBR("Jan") AND @ISMBR(&CurrYear))
    "Ending_Balance" -> "Dec" -> &PriorYear;
ELSE
    @PRIOR("Ending_Balance", 1) + "Net_Change";
ENDIF;
```

## Pattern 7: Price per Unit (with Protection)
```essbase
IF("Units" <> 0 AND "Units" <> #Missing)
    "Revenue" / "Units";
ELSE
    #Missing;
ENDIF;
```

## Pattern 8: Weighted Average
```essbase
IF(@SUM("Product", @CHILDREN("All_Products"), "Units") <> 0)
    @SUM("Product", @CHILDREN("All_Products"), "Revenue") / 
    @SUM("Product", @CHILDREN("All_Products"), "Units");
ELSE
    #Missing;
ENDIF;
```

## Pattern 9: Headcount FTE from Hours
```essbase
IF("Standard_Hours_Per_Month" <> 0 AND "Standard_Hours_Per_Month" <> #Missing)
    "Actual_Hours_Worked" / "Standard_Hours_Per_Month";
ELSE
    #Missing;
ENDIF;
```

## Pattern 10: Conditional Account Type Logic
```essbase
IF(@ISACCTYPE("Revenue"))
    "Local_Amount" * "Avg_FX_Rate" -> "FX_Rates";
ELSEIF(@ISACCTYPE("Expense"))
    "Local_Amount" * "Avg_FX_Rate" -> "FX_Rates";
ELSEIF(@ISACCTYPE("Asset") OR @ISACCTYPE("Liability") OR @ISACCTYPE("Equity"))
    "Local_Amount" * "End_FX_Rate" -> "FX_Rates";
ELSE
    "Local_Amount";
ENDIF;
```

## Interview Questions

### Intermediate
**Q: Where do you write a member formula and when does it execute?**
> A: A member formula is written in the Dimension Editor on the member's Formula property. It executes either during `CALC DIM` (for Stored members) or in real-time when a user queries the member (for Dynamic Calc members). Unlike business rules, it is intrinsic to the member and does not require a manual trigger.

### Architect
**Q: A user reports that `Margin %` shows 15% for Entity US and 20% for Entity UK on a form, but the `Total Company` row shows 35%. What is wrong?**
> A: The Total Company is summing the percentages (15% + 20% = 35%), which is mathematically incorrect. The `Margin %` member is either (1) not tagged as `Dynamic Calc`, (2) missing the Two-Pass property, or (3) has the wrong Solve Order. The fix: tag `Margin %` as Dynamic Calc with Two-Pass enabled and set its Solve Order higher than the Entity aggregation (e.g., Solve Order = 50). This forces Essbase to first aggregate the raw Margin and Revenue numbers to Total Company, then recalculate the percentage at the Total Company level using the correct aggregated values.

### Trick Question
**Q: Can a member formula use the `FIX` statement?**
> A: No. `FIX/ENDFIX` is a calc script command that defines block-level scope. Member formulas execute in the context of a single member — they don't have "scope" in the calc script sense. If you need scope control, move the logic to a business rule. Member formulas can use `IF/@ISMBR` for conditional logic, but not `FIX`.

## Summary

| Aspect | Key Point |
|--------|-----------|
| **Location** | Dimension Editor → Member → Formula property |
| **Execution** | CALC DIM (stored) or real-time (Dynamic Calc) |
| **Syntax** | Same as calc scripts, but every ENDIF needs a semicolon |
| **Solve Order** | Higher number = calculates last (wins at conflict intersections) |
| **Two-Pass** | Required for ratios/percentages; only works on Dynamic Calc members |
| **Performance** | Minimize cross-dim references (`->`) in Dynamic Calc formulas |
| **Golden Rule** | Always protect divisions with `IF(denom <> 0 AND denom <> #Missing)` |
