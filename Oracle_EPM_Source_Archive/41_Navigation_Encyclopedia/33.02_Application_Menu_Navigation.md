# 📱 33.02 — Application Menu: Complete Navigation Encyclopedia

> **Source:** Oracle® Fusion Cloud EPM Administering Planning (Aug 2026)
> **Navigation:** Home Page → Application card
> **Who sees it:** Service Administrators only
> **What it is:** The central hub for managing the entire EPBCS application structure

---

## 1. WHY — What Problem Does the Application Menu Solve—

**The problem:** EPBCS needs a single control center where administrators can manage everything about the application's structure — its cubes, dimensions, settings, and the ability to refresh/rebuild.

**The solution:** The Application card on the Home page opens a structured menu of admin screens. Everything that is "structural" about the application (not data, not forms, not rules — the underlying cube structure) is accessed through the Application card.

## 3. TAB 1: OVERVIEW

**Navigation:** Application → Overview (default tab)

### Screen Elements

| Element | Description |
|---------|-------------|
| **Application Name** | The name of the EPBCS application |
| **Application Type** | EPBCS, Financials, Workforce, Capital, or custom |
| **Start Year** | First year available in the application |
| **End Year** | Last year available in the application |
| **Base Time Period** | 12 Months, Quarters, or Custom |
| **Cubes Section** | List of all cubes (BSO and ASO) with their Essbase type |
| **Reporting Currency** | The default reporting currency |

### Actions Menu (Critical Operations)

| Action | What It Does | When to Use |
|--------|-------------|-------------|
| **Refresh Database** | Pushes all metadata changes (dimensions, members) from relational DB → Essbase physical database | After EVERY structural change (new members, changed properties) |
| **Clear Database** | Wipes ALL data from the Essbase cube | Only during implementation/reset — IRREVERSIBLE |
| **Create Audit Report** | Generates a report showing who changed what and when | Compliance, SOX audit trail |
| **Create Database Outline Report** | Exports the full Essbase outline in text format | Documentation, analysis, comparing environments |

> ⚠️ **CRITICAL:** Refresh Database ≠ Clear Database. Refresh pushes structure changes. Clear deletes ALL data. Never confuse these two!

### Dimensions Tab (within Overview)
Clicking the "Dimensions" link in the Overview tab shows a list of all dimensions. From here you can:
- Filter dimensions by cube (dropdown)
- Click any dimension name to open the Simplified Dimension Editor

### Cube Types

| Type | Full Name | Characteristics |
|------|-----------|-----------------|
| **BSO** | Block Storage Option | Supports write-back, member formulas, business rules |
| **ASO** | Aggregate Storage Option | Read-only (no write-back), faster aggregation, better for reporting |
| **Hybrid** | Hybrid BSO | BSO cube with ASO-like aggregation for some dimensions |

### Actions on Cubes

| Action | Description |
|--------|-------------|
| **Refresh** | Refresh a specific cube (not all cubes) |
| **Clear** | Clear data from a specific cube only |
| **Enable** | Enable a cube module (e.g., enable Workforce) |
| **Disable** | Disable a cube module (data preserved but cube inactive) |
| **Compress** | Run Essbase compression on the cube to reclaim disk space |

## 7. APPLICATION ACTIONS — COMPLETE GUIDE

All accessible via Application → Overview → Actions menu:

### Refresh Database

**What it does:** Reads all metadata from the relational Planning database and rebuilds/updates the Essbase database outline (.otl). Makes all new/changed members visible to users.

**When you MUST run this:**
```
✅ After adding new dimensions
✅ After adding/editing/deleting dimension members
✅ After enabling dynamic children on a parent
✅ After changing member properties (storage, account type, etc.)
✅ After changing cube settings
✅ After changing valid intersections
✅ After importing a metadata file
```

**When NOT needed:**
```
❌ Adding new forms (UI change only, no outline change)
❌ Adding new business rules
❌ Changing user permissions
❌ Modifying navigation flows
```

**Duration:** 30 seconds to 30+ minutes depending on application size.

**Impact during refresh:**
- Users cannot save data or run rules
- Forms are read-only
- Do during off-peak hours for large applications

### Clear Database

**What it does:** Permanently deletes ALL data from ALL cells in the specified cube.

> ⚠️ **EXTREME CAUTION:** This cannot be undone. Always take a snapshot (backup via Migration) before clearing.

**Valid use cases:**
- Start of a new planning cycle (clear working version)
- During initial implementation testing
- Clear a specific sandbox version

**Safe procedure:**
```
1. Application → Migration → Create snapshot (backup)
2. Verify backup completed successfully
3. Application → Overview → Actions → Clear Database
4. Select which cube to clear
5. Confirm action
```

### Audit Report

**What it shows:**
- User login/logout activity
- Administrative changes (who changed what member, when)
- Data entry changes (who entered what value, when)
- Business rule launches

**Export format:** Excel or CSV

**Use cases:** SOX compliance, troubleshooting, security review

### Database Outline Report

**What it shows:**
- Complete Essbase outline structure
- All members with all their properties
- Member formula text
- Consolidation operators

**Export format:** Text file

**Use cases:** Documentation, comparing TEST vs PROD, technical review

## 9. DO's AND DON'Ts

### ✅ DO
- **DO** always Refresh Database after any metadata change
- **DO** take a Migration snapshot before Clear Database
- **DO** run Refresh Database during off-peak hours for large applications
- **DO** use the Audit Report before pointing fingers — verify who actually changed something
- **DO** filter Dimensions view by cube to reduce noise

### ❌ DON'T
- **DON'T** confuse Refresh Database (safe) with Clear Database (deletes data!)
- **DON'T** do Clear Database without a verified backup
- **DON'T** change Attribute Dimension Date Format after date attributes have data — fix all values first
- **DON'T** modify dimension settings during active planning cycles without user communication

## 10. INTERVIEW QUESTIONS

### Beginner
**Q: You added 5 new Cost Center entities to the Entity dimension. What is the next mandatory step before users can see them in forms—**
> **A:** Run Refresh Database. Go to Application → Overview → Actions → Refresh Database. Saving in the dimension editor writes to the relational database but does NOT push to the Essbase outline. Users see dimensions from Essbase, not directly from the relational DB. Without Refresh, the new entities simply don't exist in the physical outline.

### Intermediate
**Q: A client wants all Hindi aliases for dimension members to appear in forms instead of the technical member names. How do you configure this—**
> **A:** First, create an "Hindi" alias table in Application → Dimensions → [select any dim] → Alias Tables (or via Navigator → Alias Tables). Then, for each member in the Simplified Dimension Editor, add the Hindi name in the "Hindi" alias column. Finally, go to Application → Settings → Alias Tables → set Default Alias Table to "Hindi" and set "Display Member Label as" to "Alias". Users will now see Hindi names in all forms, dashboards, and member selectors.

### Architect
**Q: You are implementing Hotel Pvt Ltd EPBCS. The application has 7 cubes (BSO + ASO). After adding 200 new Account members from a load file, how long should you estimate for Refresh Database, and what should you communicate to users—**
> **A:** For 200 members across 7 cubes, expect 15-45 minutes depending on server load, cube size, and existing member count. The refresh touches each cube's outline. During this time: all users will be unable to save data (forms become read-only), no business rules can launch, and running rules may fail. Communication best practice: (1) Send email to all users 1 day before announcing the maintenance window. (2) Send reminder 1 hour before. (3) Schedule during off-peak hours (early morning, weekend). (4) Test the load file in a copy environment first. (5) Take a Migration snapshot before the refresh as a rollback point. (6) After the refresh, spot-check 5-10 members in Smart View to confirm they are visible in the outline.
