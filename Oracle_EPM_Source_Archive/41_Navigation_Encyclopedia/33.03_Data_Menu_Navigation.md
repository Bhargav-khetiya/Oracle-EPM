# 📊 33.03 — Data Menu: Complete Navigation Encyclopedia

> **Source:** Oracle® Fusion Cloud EPM Administering Planning (Aug 2026)
> **Navigation:** Home Page → Data card (or via Navigation Flow tabs)
> **Who sees it:** All users (with appropriate form access)
> **What it is:** The primary interface for data entry, form browsing, and ad hoc analysis

---

## 1. WHY — What Problem Does the Data Menu Solve—

**The problem:** EPBCS has hundreds of forms organized in folders. Users need a single place to find, open, and interact with their data entry forms, composite forms, and ad hoc grids.

**The solution:** The Data card (or Data tab in Navigation Flows) is the **centralized form browser**. It shows a folder tree of all forms the user has access to, plus quick-access features like Recent Forms and Favorites.

## 4. FORM TOOLBAR — EVERY BUTTON

When a form is open, the toolbar appears:

| Button | Icon | Description |
|--------|------|-------------|
| **Save** | 💾 | Saves all data entered + runs "On Save" business rules |
| **Refresh** | 🔄 | Reloads form data from Essbase (discards unsaved changes) |
| **Instructions** | ℹ | Shows admin-defined instructions for the form |
| **Actions ▾** | ☰ | Dropdown with additional operations |
| **Grid POV** | POV bar | Fixed context — Scenario, Version, Currency |
| **Page Selector** | Page dropdown | Entity, Year, or other page dimension selectors |

### Actions Menu (dropdown)

| Action | Description |
|--------|-------------|
| **Rules** | Launch business rules manually (if any are attached to form) |
| **Adjust** | Adjust selected cell value by +/- amount or percentage |
| **Grid Spread** | Spread a parent value to children (proportional, even, fill) |
| **Mass Allocate** | Spread values using allocation rules |
| **Lock / Unlock** | Lock cell for spreading protection |
| **Supporting Details** | Add line-item detail behind a cell (builds up to the total) |
| **Cell History / Audit** | View who changed a cell value and when |
| **Attachments** | Add documents/files to a cell |
| **Comments** | Add text comments to a cell |
| **Copy Version** | Copy data from one version to another |
| **Export to Excel** | Exports form grid to Excel file |
| **Open in Smart View** | Opens form directly in Smart View (if enabled) |
| **Edit** | Toggle between Read and Edit mode |
| **Pivot** | Swap rows and columns |
| **Print** | Print the form |

## 5. DATA ENTRY — KEY BEHAVIORS

### Cell Colors and Their Meaning

| Color | Meaning |
|-------|---------|
| **White** | Editable data cell — user can enter data |
| **Light Yellow** | Changed but unsaved data |
| **Light Gray** | Read-only cell (calculated, or no write access) |
| **Light Blue** | Dynamic Calc member — calculated on-the-fly |
| **Green** | Autosave — recently auto-saved cell |
| **Red border** | Validation error — data violates a validation rule |
| **Strikethrough** | Locked cell — protected from spreading |
| **#MISSING** | No data exists at this intersection |

### Data Spreading (How Values Flow)

| Method | What Happens | When to Use |
|--------|-------------|-------------|
| **Default Spread** | Enter at parent → proportionally spreads to children based on existing ratios | Most common — preserves existing distribution |
| **Even Spread** | Enter at parent → equal value to all children | New data with no existing ratios |
| **Fill** | Enter at parent → same value to all children | Assumptions (e.g., exchange rate same every month) |
| **Percentage Adjustment** | Right-click → Adjust → +10% | Raise all children by a percentage |
| **Grid Spread** | Actions → Grid Spread → choose method | When you need control over how values spread |

### Keyboard Shortcuts

| Shortcut | Action |
|----------|--------|
| **Tab** | Move to next cell |
| **Shift+Tab** | Move to previous cell |
| **Enter** | Confirm entry, move down |
| **Ctrl+S** | Save form |
| **Ctrl+Z** | Undo (if Autosave enabled) |
| **Ctrl+C / Ctrl+V** | Copy / Paste data |
| **F5** | Refresh |
| **Delete** | Clear cell (set to #MISSING) |

## 6. POV AND PAGE — HOW CONTEXT WORKS

### Point of View (POV)
```
Fixed at top of form. User selects values but they stay persistent.
Usually: Scenario, Version, Currency

POV: [Budget ▾]  [Working ▾]  [Local ▾]

Changing POV = changes ALL data shown in the grid.
```

### Page Axis
```
Dropdown above the grid. Changing page = changes visible data slice.
Usually: Entity, Year

Page: [Mumbai_Hotel ▾]  [FY2026 ▾]

User selects entity from dropdown → grid shows that entity's data.
```

### How POV and Page differ:
| Aspect | POV | Page |
|--------|-----|------|
| **Position** | Top bar | Between POV and grid |
| **Typical dims** | Scenario, Version, Currency | Entity, Year |
| **User interaction** | Click to change from dropdown | Click to change from dropdown |
| **Persistence** | Stays until user changes | Stays until user changes |
| **Multiple values** | One value per dimension | One value per dimension (but dropdown shows multiple) |

## 7. COMPOSITE FORMS (multiple grids on one page)

A Composite Form displays **multiple form grids** on a single page — each grid can show different cubes, dimensions, or member selections.

```
┌──────────────────────────────────────────────────────────────┐
│  Composite Form: Hotel Monthly Review                        │
│  Global POV: [Budget] [Working] [FY2026] [Mumbai_Hotel]     │
│                                                              │
│  ┌── Grid 1: Revenue Summary ─────────────────────────────┐ │
│  │  Room Rev │ F&B Rev │ Spa Rev │ Total Rev              │ │
│  │  120      │  40     │  15     │  175                   │ │
│  └────────────────────────────────────────────────────────┘ │
│                                                              │
│  ┌── Grid 2: Expense Summary ─────────────────────────────┐ │
│  │  Labor    │ Maint   │ Utilities│ Total Exp             │ │
│  │  80       │  12     │   8     │  100                   │ │
│  └────────────────────────────────────────────────────────┘ │
│                                                              │
│  ┌── Grid 3: P&L ─────────────────────────────────────────┐ │
│  │  Total Rev │ Total Exp │ Net Income                    │ │
│  │  175       │  100      │   75                          │ │
│  └────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

**Key Rules for Composite Forms:**
- Each grid can use a different cube
- Grids share the Global POV dimensions
- Cannot add Groovy rules to composite forms
- Cannot use drag-and-drop between grids
- Maximum recommended: 4 grids per composite form

## 9. DO's AND DON'Ts

### ✅ DO
- **DO** organize forms into logical folder hierarchies (Revenue/Expense/P&L/Admin)
- **DO** use Favorites for frequently accessed forms
- **DO** save frequently — unsaved data is lost if the session times out
- **DO** check the Page selector when values look wrong — you may be on the wrong entity
- **DO** use Supporting Details for bottom-up line-item detail

### ❌ DON'T
- **DON'T** enter data into gray (read-only) cells — they're calculated or locked
- **DON'T** close a form without saving — there is no auto-save by default
- **DON'T** spread to a parent if children have important existing values — spreading overwrites
- **DON'T** use Ctrl+Z without Autosave enabled — it won't work

## 10. INTERVIEW QUESTIONS

### Beginner
**Q: A user opens a form and all cells show "#MISSING". What are three possible causes—**
> **A:** (1) No data has been entered at the selected intersection (Scenario=Budget, Version=Working, Entity=Mumbai for FY2026). This is normal for a new planning cycle. (2) The user is looking at the wrong POV — check if Scenario is "Actual" when data only exists in "Budget". (3) The dimension members on the form don't have "Store" data storage — they might be "Label Only" or "Dynamic Calc" parents with no children having data.

### Intermediate
**Q: A user enters 1000 in a parent cell (Total Revenue) and saves. After saving, the children (Room Revenue, F&B Revenue) show values, but they're not what the user expected. What happened—**
> **A:** The form has "Enable Grid Spread" turned on. When the user entered 1000 at the parent level, EPBCS spread the value to children using the default spreading method (proportional). If children had existing values of 600 and 400 (60%/40% ratio), the new 1000 was spread as 600 and 400 proportionally. If the user wanted specific values, they should enter directly in child cells, not at the parent. If there were no existing values, the spread would be even (500/500). The spreading method can be controlled via Actions → Grid Spread.
