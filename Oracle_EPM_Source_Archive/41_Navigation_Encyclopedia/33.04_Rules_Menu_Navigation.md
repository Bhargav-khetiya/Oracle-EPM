# ⚙️ 33.04 — Rules Menu: Complete Navigation Encyclopedia

> **Source:** Oracle® Fusion Cloud EPM Administering & Designing with Calculation Manager (Aug 2026)
> **Navigation:** Home Page → Rules card (or Navigator → Create and Manage → Rules)
> **Who sees it:** All users for launching; Service Administrators for creating/editing
> **What it is:** The interface for launching, managing, and monitoring business rules

---

## 1. WHY — What Problem Does the Rules Menu Solve—

**The problem:** After an administrator creates business rules in Calculation Manager, end users need a simple way to launch those rules — and administrators need to manage them without always opening the full Calculation Manager.

**The solution:** The Rules page provides a simplified, user-friendly interface for browsing deployed rules, launching them (with runtime prompts), and viewing their execution status.

---

## 2. TWO DIFFERENT "RULES" SCREENS

### Screen 1: Rules Page (for All Users)
```
Navigation: Home → Rules card
             Or: Navigation Flow → Rules tab

Purpose: Launch business rules, view run status
Access: All users with Launch permission on the rule
```

### Screen 2: Calculation Manager (for Admins)
```
Navigation: Home → Navigator (≡) → Create and Manage → Rules

Purpose: Create, edit, validate, deploy rules
Access: Service Administrators only
```

> See [28.16 Business Rules Screen](../28_Screen_Encyclopedia/28.16_Business_Rules_Screen_Complete.md) for the full Calculation Manager encyclopedia.

## 4. RULE LAUNCH FLOW

```
1. User opens Rules page
2. Browses folder tree → finds the rule
3. Clicks the rule name
4. Runtime Prompt dialog opens (if rule has prompts)
5. User fills in member selections:
   - Scenario: Budget
   - Version: Working
   - Year: FY2026
   - Entity: Mumbai_Hotel
6. Clicks [Launch]
7. Rule executes against Essbase
8. Status shows:
   ✅ "Rule completed successfully" (green)
   ❌ "Rule failed" (red) with error details
9. User can view the execution log
```

### Runtime Prompt Types

| Type | User Sees | Example |
|------|-----------|---------|
| **Member** | Member Selector (dropdown/tree) | Select Entity: Mumbai_Hotel |
| **Members** | Multi-select member selector | Select Entities: Mumbai, Delhi |
| **String** | Text input | Enter comment: "Q1 adjustment" |
| **Numeric** | Number input | Enter adjustment amount: 50000 |
| **Date** | Date picker | Select date: 2026-08-15 |
| **Smart List** | Dropdown from Smart List | Select status: Approved |
| **Boolean** | Yes/No toggle | Skip aggregation: No |

**Job Statuses:**
| Status | Icon | Meaning |
|--------|------|---------|
| **Completed** | ✅ | Rule finished successfully |
| **Failed** | ❌ | Rule encountered an error — click to see log |
| **Running** | ⏳ | Rule is still executing |
| **Pending** | 🔲 | Rule is queued, waiting to start |
| **Cancelled** | 🚫 | User or admin cancelled the rule |

## 9. INTERVIEW QUESTIONS

### Beginner
**Q: What is the difference between the "Rules" card and Calculation Manager—**
> **A:** The Rules card (Home → Rules) is the end-user interface for LAUNCHING deployed rules with runtime prompts. Any user with Launch permission sees it. Calculation Manager (Navigator → Create and Manage → Rules) is the admin-only interface for CREATING, EDITING, validating, and deploying rules. End users never access Calculation Manager; they only use the Rules card.

### Intermediate
**Q: A rule runs successfully but the data doesn't change. What could be wrong—**
> **A:** Several possibilities: (1) The FIX statement targets the wrong members (e.g., FIX on "Actual" but user selected "Budget" in the runtime prompt — check if the runtime prompt is actually connected to the FIX). (2) The rule has IF conditions that are not met (e.g., IF "Revenue" <> 0 but all revenue is #MISSING). (3) The rule runs on a different cube than where the form reads data (rule on OEP_FS but form shows OEP_REP). (4) The rule calculation produces the same values already stored (no visible change). Check the execution log in Jobs Console for details.
