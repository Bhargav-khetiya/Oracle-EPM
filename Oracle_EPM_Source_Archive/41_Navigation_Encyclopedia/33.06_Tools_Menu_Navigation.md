# 🛠️ 33.06 — Tools Menu: Complete Navigation Encyclopedia

> **Source:** Oracle® Fusion Cloud EPM Administering Planning (Aug 2026), Chapters 7, 21, 22, 24
> **Navigation:** Home → Navigator (≡) → Tools section (or Home Page toolbar)
> **Who sees it:** All users see some tools; Service Admins see all
> **What it is:** Utility functions for daily operations, preferences, and background job management

---

## 1. WHY — What Problem Does the Tools Menu Solve?

**The problem:** Users need quick access to operational functions — checking job status, setting preferences, managing their profile, viewing sandbox status — without navigating deep into admin menus.

**The solution:** The Tools menu aggregates frequently-used utilities available from the Navigator or the Settings gear icon.

## 6. SANDBOX MANAGEMENT

### Navigation
```
Settings Gear (⚙) → Sandbox Management
Or: Sandbox icon in top toolbar (if sandboxes enabled)
```

### What is a Sandbox?

A Sandbox is a **private workspace** where admins/users can make changes (metadata, data, rules) without affecting the production application. Think of it as a "draft mode."

```
Sandbox Lifecycle:
  1. Create Sandbox → isolated workspace created
  2. Make changes → edit dimensions, forms, rules, data
  3. Test changes → verify everything works
  4. Publish Sandbox → merge changes to production
  OR
  4. Delete Sandbox → discard changes
```

### Sandbox Screen

| Action | Description |
|--------|-------------|
| **Create** | Create a new sandbox (named, with description) |
| **Enter** | Switch to sandbox context — all changes go to sandbox |
| **Exit** | Return to production context |
| **Publish** | Merge sandbox changes to production |
| **Compare** | View differences between sandbox and production |
| **Delete** | Discard sandbox and all its changes |

## 7. HOTEL PVT LTD EXAMPLE

### Monthly Tools Workflow for Admin

```
Before making changes:
  1. ⚙ Settings → Sandbox → Create "Aug_Changes"
  2. Enter sandbox
  3. Make dimension changes, add new members
  4. Test in forms
  5. Compare sandbox vs production
  6. If good → Publish sandbox
  7. If bad → Delete sandbox

After monthly data load:
  8. Navigator → Tools → Jobs
  9. Check Import_Actuals job status
  10. If failed → Click job → View error log → Fix and re-run
  11. If success → Verify data in forms

Weekly backup:
  12. Navigator → Tools → Migration
  13. Create Snapshot → "Weekly_Aug12"
  14. Export to Object Storage (for offsite backup)
```

## 8. INTERVIEW QUESTIONS

### Beginner
**Q: Where does a user change their personal entity setting so forms show their hotel?**
> **A:** Settings Gear (⚙) → User Preferences → User Variables tab. Find the "UserEntity" variable and click the member selector to choose their hotel (e.g., Mumbai_Hotel). After saving, all forms that use the UserEntity variable will show data for that hotel.

### Intermediate
**Q: A business rule has been running for 30 minutes and appears stuck. How do you check and fix it?**
> **A:** (1) Go to Navigator → Tools → Jobs. (2) Find the rule in the job list — check if status is "Running" or "Error." (3) If stuck as "Running," click the job and select "Cancel" to kill it. (4) Check the execution log for errors. (5) Common causes: rule is processing too many blocks (missing FIX statement), infinite loop, or database lock contention. (6) If the rule can't be cancelled, wait for the session timeout (typically 30-60 minutes). (7) Optimize the rule before re-running.

### Architect
**Q: A Hotel Pvt Ltd client wants to automate nightly processing: import actuals, run aggregation, convert currencies, create a backup. How would you set this up?**
> **A:** Create a Business Ruleset with sequential execution:
> (1) Rule 1: Import_Actuals (or use EPM Automate `importData` command)
> (2) Rule 2: Refresh_Database
> (3) Rule 3: Full_Aggregation (AGG rule for all sparse dims)
> (4) Rule 4: Currency_Conversion (uses exchange rate table)
> (5) Rule 5: Create_Snapshot (backup via EPM Automate `exportSnapshot`)
>
> Schedule via: Navigator → Tools → Jobs → Schedule → set daily at 2:00 AM IST. Alternatively, use EPM Automate scripting with OS scheduler (crontab/Windows Task Scheduler) for more control, error handling, and email notifications. The EPM Automate approach is preferred because it can chain different job types (data loads + rules + snapshots) and handle errors with exit codes.
